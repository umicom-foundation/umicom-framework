Use the local help example

This small C application demonstrates one shared help policy. A policy is a reviewed connection between a product topic and a guide. The button and F1 both request this guide; they do not construct a URL from private application data.

Try the complete journey

  1. Start the example and choose Help before loading this pack. The catalogue explains that the matching local pack is missing. It keeps your existing document.
  2. Enter the absolute path of the pack directory generated beside the example's build files, then choose the catalogue's load action.
  3. Wait until loading completes. Choose Help for this example. This guide should appear. Put keyboard focus in the catalogue and press F1: the same route should select the same guide.
  4. Read the source with the example source link. That action displays declared, verified source; it does not compile or run it. Press F1 to return to the guide.
  5. Close the window. Accepted file jobs retain the application until their completion cleanup, so normal window closing cannot strand their ownership.

Follow the real source

Activate creates a catalogue and a containing context. It fills a UmiLearningHelpRoute with literal, reviewed identities and passes it to UmiLearningHelpGtk4Bind. The binding copies that policy and keeps a weak reference to its catalogue. A weak reference can report that the target has gone; it does not keep a closed destination alive.

The Help callback calls UmiLearningHelpGtk4Open with its own button. The service walks through that button's parent widgets to find the nearest binding. A missing nearest topic never silently selects a broader ancestor's guide. The keyboard controller uses the same copied route.

UmiStatus status = UmiLearningHelpGtk4Open(GTK_WIDGET(button));
if (status != UMI_STATUS_OK)
    fprintf(stderr, "Help admission: %s\n", umi_status_text(status));

OK means a read was accepted. The catalogue's busy flag and final status describe completion. Neither acceptance nor a displayed title proves that arbitrary content is trustworthy: the admitted pack and resource digest must still match the bytes that were read.

If something fails

For a missing pack, choose the generated pack directory rather than the source directory containing this HTML. For a changed-content refusal, regenerate the pack through CMake so its manifest hashes describe its staged files. For a busy reader, wait for completion and choose Help again. A closed or retired catalogue must be recreated by its host; a retained button cannot revive it.

This example reads local files and has no automatic network navigation, script execution, credential storage or default settings file. Its structured reader supports a bounded subset of HTML; it is not a full web browser.

Open a guide without changing F1

The second button, Open guide without changing F1, uses UmiLearningHelpGtk4OpenRoute. It constructs a temporary product route and passes it to the shared catalogue. The service validates and copies the accepted selection before returning; the stack route is not borrowed by the later worker.

This example deliberately targets the same guide from a different topic key so you can compare the two entry points. A product can supply a different declared guide identity. The surrounding F1 binding and its attempt receipt stay separate. Both entry points require the pack to be loaded, keep reading local and refuse a busy or retired catalogue.
