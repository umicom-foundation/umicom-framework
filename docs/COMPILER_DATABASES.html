Use compiler settings with Studio source tools

A C source file often depends on include folders, preprocessor definitions and a language standard chosen by its build system. A compiler database records those choices in compile_commands.json. Framework reads the records for inspection; the source tools can then pass the database folder to clangd, a local language server.

Prepare the project

  1. Open your project in Studio and open Project Build Settings.
  2. Check the project, build folder and configure preset. When a preset chooses another build directory, make the displayed build folder match it.
  3. Choose Enable compiler database export. This prepares -DCMAKE_EXPORT_COMPILE_COMMANDS:BOOL=ON in the CMake definitions field. An existing definition of that name is replaced; other definitions remain.
  4. Review the draft, choose Apply Settings, then run Configure. Configure can execute the project's build scripts, so use a project you trust.
  5. Use a Ninja or Makefile generator. CMake does not provide this export for every generator. After successful configuration, the build directory should contain compile_commands.json.

Inspect the recorded settings

  1. In Build Settings, expand Inspect compiler database. The folder begins with the profile's build directory when the form opens. Edit it if you configured another build tree.
  2. Choose Read compiler database. Reading runs in the background and does not compile or execute any recorded command.
  3. Change Command row to inspect another entry. The preview shows its source path, working folder, optional output, and recorded arguments or command.
  4. To find a source, enter its absolute path in Find source file and read again. The inspector selects the first matching record. Several rows may compile the same source with different settings; those rows are retained.
  5. If inputs change or the panel is hidden during a read, read again. Cancel stops publication of the pending result; an operating-system file read may finish before cancellation is observed.

Use the folder in clangd

  1. Open a C-family source operation, such as completion, source diagnostics or definition lookup. Review the language server executable and use your installed clangd.
  2. Expand Compiler database (clangd). Enter the absolute folder containing the database and choose Read compiler database.
  3. Inspect the rows, then choose Use this folder for clangd. This prepares one --compile-commands-dir= argument in the current source-operation form. Existing ordinary server arguments remain.
  4. Review the executable and arguments, then explicitly request the source operation. Preparing the arguments does not start a server, approve an edit or save settings.
  5. The existing Save server for this language control can save the argument draft. That setting is language-wide in the selected application settings store, not tied to one project. Recheck the database folder when changing projects.

The helper is specifically for clangd. Other language servers may use different options. Existing response-file arguments, duplicate database options and an end-of-options marker are refused by the helper; inspect those settings manually. It does not enable clangd's compiler-query permission or start a compiler to discover system headers.

Understand the limits

InputLimit
Database file64 MiB; 65,536 command rows
Arguments in one row4,096
Each argument or recorded command65,535 UTF-8 bytes
JSON parsing2,097,152 nodes and 128 nested containers
Visible command previewFirst 256 arguments and approximately 128 KiB; omitted text is labelled

The complete file is validated before any rows are offered. Malformed JSON, duplicate known fields, invalid paths and exceeded bounds reject the snapshot. A final symlink or device is refused by the regular-file reader; parent directory aliases may still be followed. Choose a folder you control.

A successful read proves only that this file was readable and structurally supported. It does not prove the database is current, the compiler exists, all headers are available or the source will compile. Configure again after changing build settings. Headers may not have their own records; clangd can infer their settings from source files. This inspector does not select which variant clangd will use.

Troubleshooting

  1. No database: check the export definition, selected generator and actual preset build folder, then configure again.
  2. Source is not recorded: verify its absolute path and whether it belongs to a configured target. A header or generated file may be absent.
  3. Includes still cannot be found: inspect the command for the expected include folders, select the correct build database and check that the SDK exists locally.
  4. Database read rejected: regenerate it with the project's build tool. Do not edit a truncated file or assume a partially displayed list is complete; the inspector publishes no partial database.
