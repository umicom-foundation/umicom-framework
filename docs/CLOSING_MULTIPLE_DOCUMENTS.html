Closing several source documents

A project often leaves several source files open. In Umicom Notes, you might have notes.c, notes.h and a test file on separate tabs. When you finish a task, you can close those documents together without losing the chance to review each unsaved draft.

Choose which documents to close

File-menu commandPurpose
Close All Source DocumentsVisit every source document that was open when you chose the command.
Close Other Source DocumentsKeep the selected source document and visit the other open sources. The retained document is remembered by its identity, even if selection later changes.
Cancel Closing DocumentsStop a running sequence before it processes more documents.

Documents are visited in the order they were opened, not in most-recently-used order. A source opened after the sequence starts is not added to that sequence. Other tools and panels, such as Output or Problems, are not source documents and are not closed by these commands.

A clean document closes without a question. For each unsaved draft, choose Save and Close, Discard and Close or Cancel. Cancel has the initial focus and is the default choice. The question shows how many documents have already closed and how many remain.

Pinned documents: these explicit File-menu group commands include pinned source documents. Pinning still protects the individual tab-close button. Keep the selected source with Close Other Source Documents when it should remain open.

Try the workflow with Umicom Notes

Use a practice project. Save a notes.c file containing a small function, then edit its return value without saving. Create a second, untitled header draft containing its declaration.

/* notes.c: save this version, then change 2 to 3 in the editor. */
int CountSavedNotes(void)
{
    return 2;
}

/* Untitled header draft */
int CountSavedNotes(void);

Choose File → Close All Source Documents. At the question for notes.c, choose Save and Close. At the question for the header, choose Cancel. The source has been saved and closed; the header remains open and unsaved.

Open the saved source independently and check that it now returns 3. The header must still contain your declaration. Open the source again, select the header and choose Close Other Source Documents. The source closes, while the header stays open. This is useful when you want to keep one file in view and clear the surrounding tabs.

Repeat with Discard and Close on a practice draft. Check that the saved file keeps its previous contents. Repeat with an untitled Save and cancel the filename chooser: its draft and the later documents must remain open.

What cancellation and failure mean

Closing several files is a sequence of separate operations. Cancel stops the remaining work. It does not reopen files that already closed, and it does not reverse a successful save. There is no automatic “undo everything” operation across the whole sequence.

When a filename chooser is open, use its Cancel button. When a close question is open, use Cancel in that question. Between questions, the File-menu cancellation command stops later work. A single file write is synchronous: the interface returns to its event loop between documents, but a slow write can still delay the current operation.

A failed save never becomes permission to discard. A read-only draft, an external-file conflict or an unavailable destination stops the sequence and leaves the unsuccessful document available for review. A successful write followed by a later close or display failure can leave a saved document open. Read the result before retrying.

Closing releases that document’s Undo history. Save another copy before closing when you need to keep both versions. This workflow does not provide crash recovery, an application-exit wizard or automatic workspace shutdown.

A question must describe the current draft

The Framework prepares a close plan when a pending document reaches its turn. A plan is a record of the document and draft the user is being asked to review. If that draft changes after the question opens, the old answer is rejected. Saving or renaming the target separately also invalidates the question.

An edit made before the document reaches its turn is included in the new question. Moving the caret or changing an unrelated tab does not approve or discard anything. A document closed separately before its turn is counted as already closed. A newly opened replacement with a different identity is not silently substituted.

Avoid competing operations

The shared editing binding permits one group-close sequence at a time. Finish or cancel Save All and allow a pending clipboard Paste to complete before starting it. An outstanding close question also prevents those operations from starting through that binding.

Studio checks its build-service state before beginning the group close. Its command routes reject a new build or workspace change while the group is active. These checks coordinate the application’s own actions; they are not filesystem locks against another editor or an external process.

Use the public C contract

A session remembers which documents belong to the operation and how far it has progressed. It does not own their text or write files itself. The existing document coordinator remains responsible for saving and closing.

#include "umicom/document/close_session.h"

UmiDocumentCloseSession *session = NULL;
UmiStatus status = UmiDocumentCloseSessionCreate(
    documents, UMI_DOCUMENT_CLOSE_ALL, 0U, &session);

Here, documents is the application’s existing coordinator. For Close Others, pass UMI_DOCUMENT_CLOSE_OTHERS and the identity of the document to keep. Do not create a second coordinator just to run this operation.

The complete programme below demonstrates these calls and their error checks together.

Read the phase, not only the return code

An OK result from Step means that the requested step completed. It does not mean every document closed. Read the copied phase:

PhaseHost action
READYSchedule one more Step. A graphical host should return to its event loop between steps.
DECISIONAsk the user to save, discard or cancel the current draft.
PATHAn untitled Save needs an approved absolute filename. Respond again with Save and that filename.
COMPLETEShow the result and release the session.
FAILED or CANCELLEDShow the reason and remaining count. Release the session; use a fresh one for a later retry.

For an untitled draft, responding with Save and a null path requests a filename without writing. Empty, relative or overlong paths are rejected. A supplied replacement filename is not accepted for an already named document: use the separate Save As workflow instead.

The counters always divide the original total into closed, already_closed and remaining. They describe document closure, not a count of files written. A failure or unanswered question remains in the remaining count.

Ownership and callbacks

The caller owns the session and must destroy it. The coordinator is borrowed and must remain alive during operations. Use these functions on its owner thread. Do not destroy or reentrantly change the coordinator from a provider callback. The session holds at most one full reviewed draft at a time, within the existing document-size limit.

For GTK applications, use UmiGtk4AdapterCloseDocuments() on the existing bound adapter. It schedules the sequence and reuses the same Save/Discard/Cancel form as single-document Close. Its completion callback receives a borrowed progress pointer for that call; copy the structure when it must be kept. UmiGtk4AdapterCloseDocumentsProgress() copies current progress, and UmiGtk4AdapterCancelCloseDocuments() stops remaining work. The busy queries distinguish a group sequence from any close question.

Remove the editing binding before releasing the application callback context. Queued work and late filename replies must not access a detached host. These rules allow future Umicom applications to use the same component without duplicating its document or lifetime logic.

Complete Notes example

This programme uses the actual local provider, document store, workbench and coordinator. It creates only its own temporary practice files. First it saves and closes the source, cancels at the header, and reads the saved source back. It then keeps the header and closes the reopened source through Close Others.

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/editor_workflow/close_documents.c
 * PURPOSE:
 *   Close an Umicom Notes source and header in stages, cancel without discarding
 *   the header, then keep that header while closing another source document.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "umicom/document/close_session.h"
#include "umicom/document/local_provider.h"
#include "umicom/platform/filesystem.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#ifdef _WIN32
#include <process.h>
#define PROCESS_ID _getpid
#else
#include <unistd.h>
#define PROCESS_ID getpid
#endif
#define REQUIRE(x) do { if (!(x)) { fprintf(stderr,"Line %d: %s\n",__LINE__,#x); result=1; goto cleanup; } } while(0)

int main(void)
{
    int result=0,madeRoot=0;
    UmiCommandRegistry *commands=NULL;
    UmiUiWorkbench *workbench=NULL;
    UmiDocumentStore *store=NULL;
    UmiDocumentCoordinator *documents=NULL;
    UmiDocumentCloseSession *session=NULL;
    char temp[UMI_PATH_CAPACITY],root[UMI_PATH_CAPACITY],path[UMI_PATH_CAPACITY],leaf[96];
    char sourceView[UMI_UI_ID_CAPACITY],headerView[UMI_UI_ID_CAPACITY];
    char *text=NULL;size_t bytes=0U;
    const char *savedSource="int CountSavedNotes(void) { return 2; }\n";
    const char *headerText="int CountSavedNotes(void);\n";
    REQUIRE(umi_fs_temp_directory(temp,sizeof(temp))==UMI_STATUS_OK);
    REQUIRE(snprintf(leaf,sizeof(leaf),"umicom-notes-close-documents-%ld",(long)PROCESS_ID())>0);
    REQUIRE(umi_fs_join(root,sizeof(root),temp,leaf)==UMI_STATUS_OK);
    REQUIRE(!umi_fs_exists(root));
    REQUIRE(umi_fs_make_directories(root)==UMI_STATUS_OK);madeRoot=1;
    REQUIRE(umi_fs_join(path,sizeof(path),root,"notes.c")==UMI_STATUS_OK);
    REQUIRE(umi_fs_write_text(path,"int CountSavedNotes(void) { return 1; }\n")==UMI_STATUS_OK);
    REQUIRE(umi_command_registry_create(&commands)==UMI_STATUS_OK);
    REQUIRE(umi_ui_workbench_create("example.notes.close",commands,&workbench)==UMI_STATUS_OK);
    REQUIRE(umi_document_store_create(&store)==UMI_STATUS_OK);
    UmiDocumentProvider provider=umi_document_local_provider();
    REQUIRE(umi_document_coordinator_create(store,workbench,&provider,&documents)==UMI_STATUS_OK);
    REQUIRE(umi_document_coordinator_open(documents,path,sourceView,sizeof(sourceView))==UMI_STATUS_OK);
    UmiUiDocumentViewSnapshot view;
    REQUIRE(umi_ui_document_view_model_find(umi_ui_workbench_documents(workbench),sourceView,&view)==UMI_STATUS_OK);
    view.dirty=1;
    REQUIRE(UmiUiDocumentViewModelUpsertText(umi_ui_workbench_documents(workbench),&view,savedSource,strlen(savedSource))==UMI_STATUS_OK);
    REQUIRE(umi_document_coordinator_new(documents,"notes.h",headerView,sizeof(headerView))==UMI_STATUS_OK);
    REQUIRE(umi_ui_document_view_model_find(umi_ui_workbench_documents(workbench),headerView,&view)==UMI_STATUS_OK);
    view.dirty=1;
    REQUIRE(UmiUiDocumentViewModelUpsertText(umi_ui_workbench_documents(workbench),&view,headerText,strlen(headerText))==UMI_STATUS_OK);
    UmiDocumentWorkingCopySnapshot header;
    REQUIRE(umi_document_coordinator_active_snapshot(documents,&header)==UMI_STATUS_OK);

    /* The first question belongs to notes.c even though notes.h is active. */
    REQUIRE(UmiDocumentCloseSessionCreate(documents,UMI_DOCUMENT_CLOSE_ALL,0U,&session)==UMI_STATUS_OK);
    REQUIRE(UmiDocumentCloseSessionStep(session)==UMI_STATUS_OK);
    UmiDocumentCloseProgress progress;
    REQUIRE(UmiDocumentCloseSessionProgress(session,&progress)==UMI_STATUS_OK);
    REQUIRE(progress.phase==UMI_DOCUMENT_CLOSE_DECISION);
    REQUIRE(strcmp(progress.current.display_name,"notes.c")==0);
    REQUIRE(UmiDocumentCloseSessionRespond(session,UMI_DOCUMENT_CLOSE_SAVE,NULL)==UMI_STATUS_OK);
    REQUIRE(umi_fs_read_text(path,&text,&bytes)==UMI_STATUS_OK);
    REQUIRE(bytes==strlen(savedSource) && memcmp(text,savedSource,bytes)==0);
    free(text);text=NULL;

    /* Stop at the header. The source remains saved/closed; no header is lost. */
    REQUIRE(UmiDocumentCloseSessionStep(session)==UMI_STATUS_OK);
    REQUIRE(UmiDocumentCloseSessionRespond(session,UMI_DOCUMENT_CLOSE_CANCEL,NULL)==UMI_STATUS_CANCELLED);
    REQUIRE(UmiDocumentCloseSessionProgress(session,&progress)==UMI_STATUS_OK);
    REQUIRE(progress.closed==1U && progress.remaining==1U && progress.phase==UMI_DOCUMENT_CLOSE_CANCELLED);
    char message[1024];
    REQUIRE(UmiDocumentCloseProgressFormat(&progress,message,sizeof(message))==UMI_STATUS_OK);
    puts(message);
    REQUIRE(UmiUiDocumentViewModelCopyText(umi_ui_workbench_documents(workbench),headerView,&text,&bytes)==UMI_STATUS_OK);
    REQUIRE(bytes==strlen(headerText) && memcmp(text,headerText,bytes)==0);
    UmiUiDocumentViewModelFreeText(text);text=NULL;
    UmiDocumentCloseSessionDestroy(session);session=NULL;

    /* A fresh Close Others remembers the header's ID, not later tab changes. */
    REQUIRE(umi_document_coordinator_open(documents,path,sourceView,sizeof(sourceView))==UMI_STATUS_OK);
    REQUIRE(UmiDocumentCloseSessionCreate(documents,UMI_DOCUMENT_CLOSE_OTHERS,header.document_id,&session)==UMI_STATUS_OK);
    REQUIRE(UmiDocumentCloseSessionStep(session)==UMI_STATUS_OK);
    REQUIRE(UmiDocumentCloseSessionProgress(session,&progress)==UMI_STATUS_OK);
    REQUIRE(progress.phase==UMI_DOCUMENT_CLOSE_COMPLETE && progress.closed==1U);
    REQUIRE(umi_document_coordinator_count(documents)==1U);
    REQUIRE(umi_document_coordinator_active_snapshot(documents,&header)==UMI_STATUS_OK && header.dirty);
    puts("The source was saved and closed. The unsaved Notes header is still open.");
cleanup:
    free(text);
    UmiDocumentCloseSessionDestroy(session);
    umi_document_coordinator_destroy(documents);
    umi_document_store_destroy(store);
    umi_ui_workbench_destroy(workbench);
    umi_command_registry_destroy(commands);
    if(madeRoot)(void)umi_fs_remove_tree(root);
    return result;
}

Build and run it

From the Applications repository in Windows PowerShell, after configuration:

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& "C:\msys64\ucrt64\bin\cmake.exe" --build --preset windows-ucrt64-all-debug --target umicom-document-close-session-example --parallel 2
& ".\build\windows-ucrt64-all-debug\bin\umicom-document-close-session-example.exe"

On Linux, the same example can run without a graphical desktop:

cmake --preset headless-debug -DCMAKE_C_COMPILER=gcc
cmake --build --preset headless-debug --target umicom-document-close-session-example --parallel 2
./build/headless-debug/bin/umicom-document-close-session-example

When using an installed SDK, configure examples/editor_workflow with CMAKE_PREFIX_PATH pointing to that SDK. Its umicom-notes-close-documents target compiles the same programme against the installed Umicom::document library.

Test the outcome

A close button responding is not enough. Check which document disappeared, which drafts remain, what the saved file contains and what the progress report says. After the last source closes, the workbench must not continue naming its absent view as active.

For an automated regression, first make the outcome deliberately wrong in an isolated fixture and confirm that the assertion detects it. Keep native input checks separate from core service tests: a successful core test does not operate a GTK window.

Continue the exercise

Add a third practice source and close it separately before its turn. Check that the report counts it as already closed. Then open a new source after creating a session and confirm that it remains open. Finally, change the current draft after its question is prepared and verify that the old discard is rejected.
