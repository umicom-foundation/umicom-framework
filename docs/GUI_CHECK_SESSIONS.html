Running repeatable GUI checks

When you test an application, it helps to follow the same steps each time. In Umicom Notes, you might save a document, read the saved file and check that a second document still has its unsaved changes. A scenario describes that sequence. A session is one attempt to run it.

The session keeps the whole plan, including steps that have not run. This matters when a check fails or someone cancels: the report should show where work stopped, rather than making unfinished checks disappear.

Begin with one Notes document

The supplied example uses a temporary Notes file. It does not open or modify your project files. Its driver handles three targets: notes.save, notes.saved-file and notes.other-draft. A driver is the small adapter that knows how to perform an action or read a result.

StepWhat happensWhy it matters
Request SaveCall the Notes save handler.A handler can return successfully without writing anything; this is only the request.
Verify the fileRead the temporary file and compare its bytes with the expected note.This checks the saved result independently.
Verify the other draftRead the separate unsaved draft.Saving one document must not change another document by mistake.

Build the example on Windows

Open PowerShell in your Applications checkout. The small test build compiles the real Framework session sources without building every application. Run each command separately and read its result before continuing.

$env:Path = "C:\msys64\ucrt64\bin;$env:Path"

& "C:\msys64\ucrt64\bin\cmake.exe" --build build/gui-check-runs --parallel 2
& "C:\msys64\ucrt64\bin\ctest.exe" --test-dir build/gui-check-runs --output-on-failure --no-tests=error

Run the normal example. Its JSON output should show "accepted":true, three attempted steps and no failed or unrun steps.

& ".\build\gui-check-runs\umicom-check-session-example.exe"
$LASTEXITCODE

Try a Save handler that does nothing

The --fail-save option deliberately skips the write. The save request returns, but the next check reads an empty file. The process returns 1, the session stops, and the third step remains not-run.

& ".\build\gui-check-runs\umicom-check-session-example.exe" --fail-save
$LASTEXITCODE

Cancel between steps

The --cancel option requests cancellation after Save returns. No later check runs. The file operation has already happened; cancellation does not undo it. The exit code is 1 because this sequence has not been accepted.

& ".\build\gui-check-runs\umicom-check-session-example.exe" --cancel
$LASTEXITCODE

Keep a report

Create an empty directory for this run. The example refuses to overwrite existing report files. A successful export writes checks.html, checks.json and junit.xml.

$Report = Join-Path $env:TEMP ("umicom-notes-check-" + (Get-Date -Format "yyyyMMdd-HHmmss-fff"))
New-Item -ItemType Directory -Path $Report
& ".\build\gui-check-runs\umicom-check-session-example.exe" --output $Report
Start-Process (Join-Path $Report "checks.html")

HTML is the easiest format to read. JSON is useful for another programme that needs the results. JUnit XML can be read by build and test-reporting tools. The JUnit report includes one extra run-completion check. It fails when a run was cancelled, stopped early or is still running, so a report containing only skipped actions cannot appear successful.

The example returns 0 for accepted checks, 1 for a failed or cancelled run, and 2 for a setup or export problem. A disk-write failure is not evidence that the deliberately broken Save handler was detected.

Read the state before the totals

StateMeaning
ReadyThe plan has been copied, but no action has run.
RunningThe run has started. More actions remain, or a driver callback is executing.
CompletedAll planned actions were attempted. Inspect the failed count before deciding whether the application passed.
StoppedA failed step stopped the sequence. Later steps remain in the report as not run.
CancelledA cancellation request prevented further actions. Completed actions and their results remain recorded.

Share only what is needed

Reports omit titles, step values, driver messages and observed text by default. A developer can include them explicitly when needed. Identifiers remain in the report, so do not use account numbers, passwords or private document contents as control or scenario IDs.

Screenshots and interaction recordings remain separate evidence. A recording describes what a person tried. A repeatable check also needs known starting data and a clear expected result. Review those details before turning a recording into an automated scenario.

Use the session in a graphical application

Framework already defines UmiUiAutomationDriver for toolkit and test adapters. The new session accepts that same driver. It does not add a second command system or a second set of assertion rules.

Call UmiUiAutomationSessionAdvance from the application's owning thread to perform one step. Return to the event loop before requesting the next step. This leaves an opportunity to update progress and handle Cancel between actions. A driver callback can still block: cancellation cannot interrupt that callback, and a test launcher should enforce an overall process timeout.

The session API does not add a new Run button to the existing Report problem panel. A host connects its own selected scenario, progress display and cancellation action to these shared functions. There is no automatic conversion of recorded clicks into a replay script.

Understand the contract

Function or typePurpose and ownershipWhere to see it used
UmiUiAutomationSessionCreateCopy a nonempty scenario and driver interface. The driver context is borrowed and must remain alive while steps can run.Example: create the Notes session, then destroy the original scenario.
UmiUiAutomationSessionAdvanceAttempt one step. An OK return means its result was recorded, not that the check passed.Example: the owner-thread loop requests each Notes action.
UmiUiAutomationSessionCancelPrevent further actions; an active callback finishes first.Example: the cancellation exercise stops after Save.
UmiUiAutomationSessionDestroyRelease the session and report. It returns Busy during its driver callback.Example: the cleanup block releases the session.
UmiUiAutomationSessionReportBorrow the report until session destruction. Do not destroy this borrowed pointer separately.Example: use the same report for progress, exports and acceptance.
UmiUiAutomationReportSnapshotCopy metadata and progress counters without executing an action.Example: decide whether another step may run.
UmiUiAutomationReportStepCopy a planned row and its state. A not-run row has no driver outcome.Tests: inspect the last unrun row after stopping at the first failure.
UmiUiAutomationReportWriteJson / WriteHtml / WriteJUnitCopy the report before writing it through the supplied output callback. The caller owns and closes the file.Example: export the same result to three files.
UmiUiAutomationReportRequireSuccessRequire a nonempty completed plan, matching expected count and no failures.Example: choose process exit code 0 or 1.
UmiUiAutomationSessionSnapshotA copied view of the run. Planned equals attempted plus notRun; attempted equals passed plus failed.Example: inspect the state. Tests verify these relationships throughout cancellation/failure combinations.

Complete Notes example

Read the main function first to see the sequence, then follow PerformNotesStep to see how the saved result is checked. The output callback writes bytes; it does not decide whether the application passed.

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/gui_recording/check_sessions.c
 *
 * PURPOSE:
 *   Teach repeatable acceptance runs using a Notes save request followed by
 *   independent file and draft checks. Export reports without hiding a stop.
 *
 * AUTHOR AND ORGANISATION:
 * Sammy Hegab
 * Umicom Foundation
 *
 * LICENCE:
 * MIT
 *---------------------------------------------------------------------------*/
#include "umicom/ui/automation_session.h"
#include <stdio.h>
#include <string.h>

static const char SAVED_NOTE[] = "Umicom Notes: release checklist\nSaved: yes\n";
static const char OTHER_DRAFT[] = "Keep this second note unsaved.";

typedef struct NotesFixture {
    FILE *savedFile;
    int failSave;
    char otherDraft[UMI_UI_DESCRIPTION_CAPACITY];
} NotesFixture;

/* This fixture is deliberately independent of GTK and Studio. A graphical
 * host can pass its existing UmiUiAutomationDriver to the same session API. */
static UmiStatus PerformNotesStep(void *context, const UmiUiAutomationStep *step,
    UmiUiAutomationObservation *out, char *message, size_t messageCapacity)
{
    NotesFixture *notes = context;
    (void)snprintf(out->target_id, sizeof(out->target_id), "%s", step->target_id);
    (void)snprintf(out->role_name, sizeof(out->role_name), "notes-file-fixture");
    if (strcmp(step->target_id, "notes.save") == 0) {
        /* --fail-save models a handler that says OK but does no useful work. */
        if (!notes->failSave) {
            if (fwrite(SAVED_NOTE, 1U, strlen(SAVED_NOTE), notes->savedFile) != strlen(SAVED_NOTE) ||
                fflush(notes->savedFile) != 0) return UMI_STATUS_IO_ERROR;
        }
        (void)snprintf(message, messageCapacity, "Save handler returned.");
    } else if (strcmp(step->target_id, "notes.saved-file") == 0) {
        size_t bytes;
        if (fseek(notes->savedFile, 0L, SEEK_SET) != 0) return UMI_STATUS_IO_ERROR;
        bytes = fread(out->text, 1U, sizeof(out->text) - 1U, notes->savedFile);
        if (ferror(notes->savedFile)) return UMI_STATUS_IO_ERROR;
        out->text[bytes] = '\0';
        (void)snprintf(message, messageCapacity, "Read the actual saved bytes.");
    } else if (strcmp(step->target_id, "notes.other-draft") == 0) {
        (void)snprintf(out->text, sizeof(out->text), "%s", notes->otherDraft);
        (void)snprintf(message, messageCapacity, "Read the separate draft.");
    } else return UMI_STATUS_NOT_FOUND;
    return UMI_STATUS_OK;
}

/* Adapt a caller-owned FILE to the Framework output callback. */
static UmiStatus WriteBytes(void *context, const char *bytes, size_t length)
{
    return fwrite(bytes, 1U, length, context) == length ? UMI_STATUS_OK : UMI_STATUS_IO_ERROR;
}
/* Keep each scenario step small and explicitly identify its intended target. */
static UmiStatus Add(UmiUiAutomationScenario *scenario, const char *id,
    const char *target, UmiUiAutomationOperation operation, const char *value)
{
    UmiUiAutomationStep step = {0};
    /* These are fixed teaching strings within the public field capacities. */
    (void)snprintf(step.step_id, sizeof(step.step_id), "%s", id);
    (void)snprintf(step.target_id, sizeof(step.target_id), "%s", target);
    (void)snprintf(step.value, sizeof(step.value), "%s", value);
    step.operation = operation;
    return umi_ui_automation_scenario_add(scenario, &step);
}

typedef UmiStatus (*ExportFn)(const UmiUiAutomationReport *, int, UmiUiRecordingWriteFn, void *);
/* Export to a new file beside the other reports, preserving earlier runs. */
static UmiStatus SaveReport(const UmiUiAutomationReport *report,
    const char *directory, const char *filename, ExportFn exportReport)
{
    char path[2048];
    FILE *file;
    UmiStatus status;
    int length = snprintf(path, sizeof(path), "%s/%s", directory, filename);
    if (length < 0 || (size_t)length >= sizeof(path)) return UMI_STATUS_CAPACITY_EXCEEDED;
    /* Never overwrite earlier evidence. Choose an empty output directory. */
    file = fopen(path, "wx");
    if (file == NULL) return UMI_STATUS_IO_ERROR;
    status = exportReport(report, 0, WriteBytes, file);
    if (fclose(file) != 0 && status == UMI_STATUS_OK) status = UMI_STATUS_IO_ERROR;
    return status;
}

/* Exit 0: accepted. Exit 1: failed or cancelled checks. Exit 2: setup/export
 * failure. Keeping these outcomes separate lets automated tests detect errors
 * in the test setup rather than treating every nonzero exit as useful evidence. */
int main(int argc, char **argv)
{
    NotesFixture notes = {0};
    UmiUiAutomationDriver driver = {0};
    UmiUiAutomationScenario *scenario = NULL;
    UmiUiAutomationSession *session = NULL;
    UmiUiAutomationSessionSnapshot info;
    const UmiUiAutomationReport *report;
    const char *directory = NULL;
    int cancel = 0, exitCode = 2, i;
    UmiStatus status;
    for (i = 1; i < argc; ++i) {
        if (strcmp(argv[i], "--fail-save") == 0) notes.failSave = 1;
        else if (strcmp(argv[i], "--cancel") == 0) cancel = 1;
        else if (strcmp(argv[i], "--output") == 0 && i + 1 < argc) directory = argv[++i];
        else { fprintf(stderr, "Usage: %s [--fail-save | --cancel] [--output EMPTY_DIRECTORY]\n", argv[0]); return 2; }
    }
    if (directory != NULL && directory[0] == '\0') { fprintf(stderr, "Choose an existing empty output directory.\n"); return 2; }
    if (notes.failSave && cancel) { fprintf(stderr, "Choose one failure exercise at a time.\n"); return 2; }
    notes.savedFile = tmpfile();
    if (notes.savedFile == NULL) { fprintf(stderr, "Cannot create the temporary Notes file.\n"); return 2; }
    (void)snprintf(notes.otherDraft, sizeof(notes.otherDraft), "%s", OTHER_DRAFT);
    driver.structure_size = (uint32_t)sizeof(driver);
    driver.api_version = UMI_UI_AUTOMATION_API_VERSION;
    (void)snprintf(driver.driver_id, sizeof(driver.driver_id), "notes.file-fixture");
    driver.context = &notes;
    driver.perform = PerformNotesStep;
    status = umi_ui_automation_scenario_create("notes.save-checks", "Save a Notes document", &scenario);
    if (status == UMI_STATUS_OK) status = Add(scenario, "request-save", "notes.save", UMI_UI_AUTOMATION_INVOKE_COMMAND, "");
    if (status == UMI_STATUS_OK) status = Add(scenario, "verify-file", "notes.saved-file", UMI_UI_AUTOMATION_ASSERT_TEXT, SAVED_NOTE);
    if (status == UMI_STATUS_OK) status = Add(scenario, "verify-other-draft", "notes.other-draft", UMI_UI_AUTOMATION_ASSERT_TEXT, OTHER_DRAFT);
    if (status == UMI_STATUS_OK) status = UmiUiAutomationSessionCreate(&driver, scenario,
        cancel ? "notes-cancelled" : (notes.failSave ? "notes-failed" : "notes-passed"), &session);
    /* The session owns its plan now; it does not borrow scenario storage. */
    umi_ui_automation_scenario_destroy(scenario);
    if (status != UMI_STATUS_OK) goto cleanup;
    report = UmiUiAutomationSessionReport(session);
    while (1) {
        status = UmiUiAutomationReportSnapshot(report, &info);
        if (status != UMI_STATUS_OK) goto cleanup;
        if (info.state != UMI_UI_AUTOMATION_SESSION_READY && info.state != UMI_UI_AUTOMATION_SESSION_RUNNING) break;
        /* A graphical host would return to its event loop between these calls.
         * Cancellation is cooperative; it cannot interrupt an active driver. */
        status = UmiUiAutomationSessionAdvance(session);
        if (status != UMI_STATUS_OK) goto cleanup;
        if (cancel) {
            status = UmiUiAutomationSessionCancel(session);
            if (status != UMI_STATUS_OK) goto cleanup;
        }
    }
    if (directory != NULL) {
        status = SaveReport(report, directory, "checks.json", UmiUiAutomationReportWriteJson);
        if (status == UMI_STATUS_OK) status = SaveReport(report, directory, "checks.html", UmiUiAutomationReportWriteHtml);
        if (status == UMI_STATUS_OK) status = SaveReport(report, directory, "junit.xml", UmiUiAutomationReportWriteJUnit);
        if (status != UMI_STATUS_OK) goto cleanup;
    }
    status = UmiUiAutomationReportWriteJson(report, 0, WriteBytes, stdout);
    if (fflush(stdout) != 0 && status == UMI_STATUS_OK) status = UMI_STATUS_IO_ERROR;
    if (status != UMI_STATUS_OK) goto cleanup;
    exitCode = UmiUiAutomationReportRequireSuccess(report, 3U) == UMI_STATUS_OK ? 0 : 1;
cleanup:
    if (status != UMI_STATUS_OK) fprintf(stderr, "Notes check setup/export failed: %s\n", umi_status_text(status));
    (void)UmiUiAutomationSessionDestroy(session);
    if (fclose(notes.savedFile) != 0) exitCode = 2;
    return exitCode;
}
