Changing a Test Explorer query

A query contains the search text, suite, label and outcome filters. A projection is the set of rows prepared for display, including its order, selection and expanded groups. Applications should publish a query together with the rows it describes.

Use the shared session

  1. Create a Framework test-platform service and its workspace. Bind an Explorer session to that same service and workspace. A workspace from another service is rejected.
  2. Initialize a UmiTestPlatformFilter with umi_test_platform_filter_init. Its default outcome of -1 means any outcome. Fill only complete strings that fit the public fields.
  3. Call UmiTestExplorerSessionApplyFilter on the owning thread. Keep the session, workspace, registries and any application presentation fields serialized during the call.
  4. Update your controls only when the call returns UMI_STATUS_OK. On refusal, retain the previous visible query and report the returned status. Retry the complete query after addressing the cause.
UmiTestPlatformFilter filter;
UmiTestPlatformFilterSummary summary;
umi_test_platform_filter_init(&filter);
/* Example fixed text fits the public buffer, including its terminator. */
memcpy(filter.text, "parser", sizeof "parser");
UmiStatus status = UmiTestExplorerSessionApplyFilter(session, &filter, &summary);
if (status == UMI_STATUS_OK) {
    /* summary.matched_count counts direct matches across the catalogue. */
}

The session prepares independent row storage first. Only then does it apply the workspace filter and transfer the completed rows. Failure preserves the previous workspace query and selected item, model query and rows, retained row selection and expansion, revisions and caller summary. Successful filtering advances the workspace, model and session revisions once each. The model object's address remains stable.

Sorting and grouping

umi_test_explorer_session_set_sort and umi_test_explorer_session_set_group prepare their new projection before changing the visible ordering. A failure preserves the previous ordering and session revision. These operations leave the workspace filter unchanged.

A host that owns a model directly can call UmiTestExplorerModelApplyQuery to apply filter, sort and group together. This changes only that model. The older model setters remain available for callers that deliberately configure a model separately from rebuilding it.

Studio integration

Studio's centre uses UmiStudioTestServiceApplyExplorerFilter so its presentation fields change only after Framework accepts both the workspace query and projection. The session must belong to that Studio service. The active suite remains part of the query. Overlong search or label strings are refused rather than silently shortened.

Exact outcome filtering and the failed-only shortcut are different operations. An exact Failed query matches failed results; the shortcut also includes timed-out results. Hidden row selection is retained so it can reappear when the filter is cleared. It is separate from the workspace's currently actionable item and from a bounded execution plan.

Build and check the affected targets

In an already integrated Applications checkout with the UCRT64 toolchain installed, run these commands in PowerShell. Stop if a command fails. These are qualification instructions, not a statement that a particular checkout has passed.

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake --preset windows-ucrt64-all-debug -DBUILD_TESTING=ON
cmake --build --preset windows-ucrt64-all-debug --parallel 2 --target umicom-test-explorer-query umicom-test-explorer-query-failure umicom-studio-explorer-filter-test
ctest --preset windows-ucrt64-all-debug -R "^(framework[.]test[.]explorer_query|studio[.]explorer_filter_transaction)" --output-on-failure --no-tests=error

The regression fixtures use synthetic in-memory test catalogues. They exercise refused allocations, invalid fields, mismatched bindings, revisions, selection retention and Studio composition without launching external test processes. Running them does not replace the existing Explorer, workspace, installed-SDK or native UI qualification suites.

Limits

Owner-thread serialization is required; these functions do not make registries thread-safe. General session refresh also computes coverage, history, rerun and benchmark views; it is a separate operation and is not covered by the query transaction guarantee. Studio's centre snapshot reads the full hierarchy count directly; exporting hierarchy rows and creating an execution selection retain their own caller-buffer limits.
