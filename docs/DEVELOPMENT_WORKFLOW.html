From a new project to a tested application

A project is more than the file open in the editor. It also has build instructions, tests and a description of the programme you intend to run. Studio brings those parts together so that you can move from an idea to an executable and then to a package that another person can install.

This chapter follows Umicom Notes. You will create a C project, change its source, compile it, inspect a failure, run tests, use a debugger and create a ZIP package. The compiler and debugger are installed tools. Studio asks Framework to run them and display their results; Studio does not replace GCC, Clang, GDB or LLDB with its own compiler.

1. Prepare the tools

Use the same toolchain for a project’s compiler, libraries and debugger. On Windows, the examples use MSYS2 UCRT64. Start PowerShell and make its programmes visible for this session:

$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake --version
ninja --version
gcc --version
ctest --version
cpack --version

Every command should print information about the tool. A “not recognised” message means that the programme is missing or is not on PATH. Do not work around that message by changing the project’s source code.

Prepare a debugger

On Windows, GDB must include its Python-based Debug Adapter Protocol support. In the MSYS2 UCRT64 terminal, install the UCRT64 package:

pacman -S --needed mingw-w64-ucrt-x86_64-gdb

Return to PowerShell and check the executable:

& "C:\msys64\ucrt64\bin\gdb.exe" --interpreter=dap --version

Alternatively, use an installed lldb-dap executable and its matching runtime dependencies. A programme that exists on disk can still fail to start because one of its libraries is missing. Run its version command first. On Linux, select your distribution’s GDB with DAP support or LLDB DAP package. Studio does not download a debugger or silently replace a failed debugger with a simulation.

Further reading: GDB interpreters, LLDB DAP and the MSYS2 UCRT64 GDB package.

2. Create an Umicom Notes project

Open Studio and use New Project. Choose the C23 console template. Use Umicom Notes as the application name, org.umicom.notes as its application ID and umicom_notes as the executable target. Select a new, empty folder for this exercise. Keep your Framework checkout and existing projects separate from it.

The generator creates the source, tests and CMake files as a coherent project. It refuses to create another project over an existing destination. Once the new project is adopted, review Build → Project Settings: source folder, build folder, configuration, executable and installation folder. The paths must belong to this Notes project, not to the Studio programme that is editing it.

A trusted workspace is one in which you deliberately allow tools to execute project instructions. Read an unfamiliar project’s build files before granting that trust. Compiling, testing and debugging all execute code or commands.

Make one useful change

Open src/main.c. Use this small programme to represent three notes and count those already saved:

#include <stddef.h>
#include <stdio.h>

static unsigned CountSavedNotes(const int *saved, size_t count)
{
    unsigned total = 0U;
    for (size_t index = 0U; index < count; ++index) {
        if (saved[index] != 0) ++total;
    }
    return total;
}

int main(void)
{
    const int saved[] = {1, 0, 1};
    unsigned savedNotes = CountSavedNotes(saved, 3U);
    printf("Umicom Notes: %u saved\n", savedNotes);
    return 0;
}

Save the source. Two notes have a saved flag, so the expected output is Umicom Notes: 2 saved. The array, function and loop are small enough to inspect in a debugger, but they represent a real application question: which notes still need saving?

3. Configure, build and test

Configure reads the project’s CMake files and prepares the build. Build asks the compiler and linker to create the executable. Test Project runs the tests registered by the project. Keep the Output and Problems views open so that you can see which phase is running and why it stops.

Use Build → Build, then run the programme. The existing background build worker performs the compiler work. A failed build must be corrected before the programme is run or debugged; the existence of yesterday’s executable is not evidence that today’s source compiled.

To practise diagnosing an error, remove the semicolon from the printf statement and build again. Read the compiler’s filename and line. Restore the semicolon, save and rebuild. Do not accept a successful run of an older executable as a successful correction.

Rebuild now performs Configure → Clean → Build. It removes generated build products through the build system, not source files. Ordinary Build remains the quicker choice for most edits.

Enable testing in Project Settings before using Package or Deploy. These operations require the project’s registered tests to succeed. An empty test selection is reported as an error, not as a successful test run. The build phase includes the test targets rather than compiling only a selected programme target and hoping that its tests already exist.

4. Follow the programme with a debugger

A debugger starts the compiled programme under supervision. A breakpoint pauses it at a selected source line. Stepping runs a small amount of code before pausing again. Variables and the call stack explain what the programme is doing at that point.

Open the Run and Debug panel. Select GDB (DAP) or LLDB DAP. Enter the adapter executable’s full path, or leave that field empty to use PATH. Choose Use adapter. Configuration is copied into the current service; it is not a new saved preference profile.

Add a breakpoint on the printf line, after savedNotes has been assigned. Save the file and choose Start in Run and Debug. Studio first requests a build. Only the matching successful build operation can start the captured executable. Changing the project settings while it waits invalidates that old request.

The native launch initially stops at the programme entry. Use Continue to reach the breakpoint. Select the stopped thread and frame. Inspect the available scopes and variables, or explicitly add a watch for savedNotes. Its value should be 2. Use Step Over to execute the print statement without entering the C library. Continue lets the programme finish. Choose Stop before starting another debugging run.

Step In enters a called function when source and symbols are available. Step Out returns to its caller. Pause requests a stop in a running programme; the debugger must acknowledge it. Selecting a thread, frame or scope requests the corresponding data from the connected adapter rather than inventing a displayed value.

Watch expressions are deliberate debugger requests. Some expressions can call functions or otherwise affect the programme being debugged. Prefer simple variable names while learning. Studio does not automatically evaluate every saved expression after each stop.

The initial adapter handshake and stopped-state inspection have time limits, but currently wait synchronously on Studio’s owner thread. A slow or unresponsive debugger can briefly delay the interface. This is separate from the background compiler worker. Missing adapter dependencies, denied process access and unsupported debugger capabilities must be resolved before the session can work.

5. Create a package

Choose Build → Package. Framework runs these four phases in order:

Configure → Build → Test → CPack ZIP

A failure stops the sequence. For example, if a test fails, CPack is not started. Successful packaging writes a ZIP and its SHA-256 checksum under <build-folder>/packages. The project’s CPackConfig.cmake and install rules determine which files enter the archive.

A checksum helps detect changed bytes; it is not a digital signature or proof of who published a package. Compare the archive hash before sharing it:

Get-FileHash -LiteralPath "C:\path\to\notes-package.zip" -Algorithm SHA256

On Linux, use sha256sum /path/to/notes-package.zip. Extract the package to a new test folder and start the executable from that extracted folder. This catches mistakes that running the build-tree copy would miss.

The ZIP is a portable archive, not automatically a Windows Setup executable, MSIX package or self-contained runtime. Projects using GTK or other shared libraries still need correct runtime files and resources. Test the package on a clean supported machine before describing it as ready for end users.

6. Install and deploy locally

Install applies the project’s existing CMake installation rules. The new Deploy command is a checked local sequence:

Configure → Build → Test → Install to the selected prefix

Choose a fresh development installation folder in Project Settings. Do not point this exercise at a working production installation. Run the installed executable, not its copy inside the build folder. Deployment here does not upload to a server, publish a release or activate a remote service. Those operations need their own destination, credentials, approval and rollback design.

A completed installation is not rolled back automatically if a later manual check fails. Preserve a known working installation and use a separate candidate folder. Package and Deploy require testing through the project-session route; calling a low-level provider directly does not add that complete sequence automatically.

7. How applications reuse this workflow

Framework owns project generation, process execution, build sequences, debugger protocols and their models. Studio connects the selected project, menus and panels to those contracts. Another Umicom application can reuse the same services without copying Studio’s private widgets.

Contract or filePurpose and use
developer_project/new_project.h
UmiDeveloperProjectCreateNew()		Create a project from an existing template. Supply a new destination and receive its model and build profile. The complete example below checks that a second creation attempt is refused.
build/project_session.h
umi_build_project_session_submit()		Copy a reviewed profile into the existing worker and request Build, Rebuild, Package or Deploy. Poll snapshots and phase results; do not execute the compiler on a GUI callback. The caller owns the session and destroys it after work has stopped.
build/cpack_provider.h
UmiBuildCPackProvider()		Create a provider value that prepares an owned CPack argument list. It returns a real process command, not shell text. src/build/cpack_provider.c preserves spaces inside paths and rebinds pointers after copying its argument storage. The contract tests inspect each argument.
build/types.h
Package, Rebuild and Deploy phases		Represent three different requests. Existing phase values are retained. src/build/project_session.c chooses their phase order; src/build/task.c no longer treats all three as Install.
debug_runtime/platform.h
UmiDebugRuntimePlatformLaunchNative()		Start the existing process-backed adapter using an installed executable, captured programme, working folder and arguments. Framework copies the launch description, performs the protocol handshake, synchronises breakpoints and checks the replies.
UmiDebugRuntimePlatformInspectStopped()Request threads, frames, scopes and ordinary variables after a confirmed stop. It does not run user watch expressions implicitly. Results belong to the existing debug service registries; request copied snapshots rather than retain registry internals.
debug_runtime/platform.c, adapter.c, deadline.hCoordinate process startup and bounded waits. A launch reply can arrive before or after configuration is completed. The shared deadline consumes one waiting budget instead of restarting the whole timeout for each event.
decoders/stack_trace.c, service_bridge.c, request_support.cDecode and request source locations. Frame identifier zero is a valid frame; a missing identifier is not silently converted into it. The frame-zero and watch-frame-zero tests exercise these paths.
applications/studio/include/umicom/studio/debugger.hStudio’s composition contract exposes adapter selection, a queued build-before-debug request and owner-thread polling. QueueNative() captures the next build-operation ID before submission; PollNative() requires that exact successful result.
applications/studio/src/app/commands.cRoute approved commands to the existing build worker and debugger service. The new Studio integration tests call these actual registered commands.
applications/studio/src/gui/workbench/runtime/Connect menu aliases, project guards, polling and Run and Debug controls. The adapter chooser and buttons use the existing weak-owner action binding so a retained button does not keep using a released host.

Ownership and failure handling

Keep a session’s owner alive while an operation is using it. Do not retain pointers to a stack-local profile or temporary argument array. Framework’s build session and native launcher copy what they need; their public headers state the remaining lifetime requirements. Results such as Busy, Permission denied, Not found and Timeout describe different problems and must not be changed into success just to keep a button enabled.

The debugger service has one authoritative model. Its older in-memory protocol interface remains available to explicit clients and tests, but Studio’s Start command uses the process-backed runtime. The memory interface is not a fallback when an installed debugger fails.

8. Run the complete Framework example

The source below creates its own temporary Notes project. It compiles the source, runs the tests, produces a package, independently verifies the checksum, extracts and runs the package, installs it to its own folder and rebuilds. It uses only a directory that it creates itself. On success it removes that private directory; on failure it prints the location so that you can inspect it.

From the Applications checkout, after building the example:

& ".\build\windows-ucrt64-all-debug\bin\umicom-development-workflow-example.exe"

The test modes deliberately introduce a compiler error, a failing test, an empty test suite or missing CPack configuration. A failed prerequisite must stop later work. The separate debugger tests use either an installed debugger or an explicitly labelled protocol fixture; this example does not pretend that packaging is a debugger test.

Complete example: framework/examples/development_workflow/main.c
/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/development_workflow/main.c
 * PURPOSE:
 *   Generate a real Notes project, compile and test it, package it, verify its
 *   checksum, run the extracted executable, and install it to a private folder.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "umicom/developer_project/new_project.h"
#include "umicom/build/project_session.h"
#include "umicom/platform/directory.h"
#include "umicom/platform/filesystem.h"
#include "umicom/platform/process.h"
#include "umicom/platform/threading.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#define CHECK(value) do { if (!(value)) { fprintf(stderr,"%s:%d: %s\n",__FILE__,__LINE__,#value); return EXIT_FAILURE; } } while (0)

/* This helper uses the production worker. Polling copies completed results;
 * it does not execute compiler work on a graphical owner's thread. */
static int Run(UmiBuildProjectSession *session, const UmiBuildProfile *profile,
    UmiBuildPhase phase, int expectSuccess, size_t *completed)
{
    CHECK(umi_build_project_session_submit(session, profile, phase, true) == UMI_STATUS_OK);
    UmiBuildResult *result = NULL; CHECK(umi_build_result_create(&result) == UMI_STATUS_OK);
    size_t shown = 0U;
    UmiBuildProjectSessionSnapshot snapshot = {0};
    for (unsigned attempt = 0U; attempt < 20000U; ++attempt) {
        CHECK(umi_build_project_session_snapshot(session, &snapshot) == UMI_STATUS_OK);
        while (shown < snapshot.completed_phase_count) {
            CHECK(umi_build_project_session_result_at(session, shown++, result) == UMI_STATUS_OK);
            printf("%s: %s (exit %d)\n%s\n", umi_build_phase_text(result->phase),
                umi_status_text(result->status), result->exit_code, result->output);
        }
        if (!snapshot.active) break;
        umi_thread_sleep_ms(10U);
    }
    umi_build_result_destroy(result);
    CHECK(!snapshot.active);
    CHECK((snapshot.status == UMI_STATUS_OK) == expectSuccess);
    *completed = snapshot.completed_phase_count;
    return EXIT_SUCCESS;
}

/* argv is passed to the platform runner directly, never through a shell. */
static int Execute(const char *program, const char *const *args, size_t count,
    const char *directory, const char *expectedPrefix)
{
    UmiProcessRequest request = {0};
    UmiProcessResult *result = calloc(1U, sizeof(*result)); CHECK(result != NULL);
    request.program = program; request.arguments = args; request.argument_count = count;
    request.working_directory = directory; request.capture_stdout = 1; request.capture_stderr = 1;
    request.timeout_ms = 30000U; request.window_mode = UMI_PROCESS_WINDOW_HIDDEN;
    UmiStatus status = umi_process_execute(&request, result);
    printf("%s: %s\n%s\n", program, umi_status_text(status), result->output);
    int passed = status == UMI_STATUS_OK && result->exit_code == 0 &&
        (expectedPrefix == NULL || strncmp(result->output, expectedPrefix, strlen(expectedPrefix)) == 0);
    free(result); CHECK(passed); return EXIT_SUCCESS;
}

typedef struct Found { char zip[UMI_PATH_CAPACITY]; char program[UMI_PATH_CAPACITY]; size_t zips; } Found;
static UmiStatus Find(const UmiFileInfo *info, void *context)
{
    Found *found = context;
    if (info->kind != UMI_FILE_KIND_REGULAR) return UMI_STATUS_OK;
    size_t n = strlen(info->name);
    if (n > 4U && strcmp(info->name + n - 4U, ".zip") == 0) {
        ++found->zips; (void)snprintf(found->zip, sizeof(found->zip), "%s", info->path);
    }
    if (strcmp(info->name, "umicom_notes") == 0 || strcmp(info->name, "umicom_notes.exe") == 0)
        (void)snprintf(found->program, sizeof(found->program), "%s", info->path);
    return UMI_STATUS_OK;
}

int main(int argc, char **argv)
{
    const char *mode = argc == 2 ? argv[1] : "complete";
    int compileFailure = strcmp(mode,"compile-failure") == 0;
    int testFailure = strcmp(mode,"test-failure") == 0;
    int noTests = strcmp(mode,"no-tests") == 0;
    int noCPack = strcmp(mode,"no-cpack") == 0;
    int deployFailure = strcmp(mode,"deploy-test-failure") == 0;
    CHECK(argc <= 2 && (strcmp(mode,"complete") == 0 || compileFailure || testFailure || noTests || noCPack || deployFailure));
    UmiDeveloperProjectService *projects = NULL;
    UmiDeveloperProjectGenerationRequest request;
    UmiDeveloperProjectGeneratorReport report;
    UmiDeveloperProjectModel model;
    UmiBuildProfile profile;
    UmiBuildProjectSession *session = NULL;
    UmiBuildProjectSessionConfig config = {0};
    char temporary[UMI_PATH_CAPACITY], root[UMI_PATH_CAPACITY], name[160], path[UMI_PATH_CAPACITY];
    struct timespec now; CHECK(timespec_get(&now, TIME_UTC) == TIME_UTC);
    (void)snprintf(name,sizeof(name),"Umicom Notes-%lld-%ld-%s",(long long)now.tv_sec,now.tv_nsec,mode);
    CHECK(umi_fs_temp_directory(temporary,sizeof(temporary)) == UMI_STATUS_OK);
    CHECK(umi_fs_join(root,sizeof(root),temporary,name) == UMI_STATUS_OK);
    CHECK(!umi_fs_exists(root));
    printf("Private generated project: %s\n",root);
    CHECK(umi_developer_project_service_create(&projects) == UMI_STATUS_OK);
    umi_developer_project_generation_request_init(&request);
    strcpy(request.template_id,"developer.template.c23-console");
    strcpy(request.application_name,"Umicom Notes"); strcpy(request.application_id,"org.umicom.notes");
    strcpy(request.repository_name,"umicom-notes"); strcpy(request.target_name,"umicom_notes");
    strcpy(request.project_root,root);
    CHECK(UmiDeveloperProjectCreateNew(projects,&request,&report,&model,&profile) == UMI_STATUS_OK);
    CHECK(report.files_created >= 6U);
    CHECK(UmiDeveloperProjectCreateNew(projects,&request,&report,&model,&profile) == UMI_STATUS_ALREADY_EXISTS);
    CHECK(umi_fs_join(path,sizeof(path),root,"src/main.c") == UMI_STATUS_OK);
    const char *source = compileFailure ? "int main(void) { syntax error }\n" :
        "#include <stdio.h>\nint main(void) { unsigned savedNotes = 2U; printf(\"Umicom Notes: %u saved\\n\", savedNotes); return 0; }\n";
    CHECK(umi_fs_write_text(path,source) == UMI_STATUS_OK);
    CHECK(umi_fs_join(path,sizeof(path),root,"tests/test_main.c") == UMI_STATUS_OK);
    CHECK(umi_fs_write_text(path,(testFailure || deployFailure) ? "int main(void) { return 7; }\n" :
        "int main(void) { unsigned count = 2U; return count == 2U ? 0 : 1; }\n") == UMI_STATUS_OK);
    if (noTests || noCPack) {
        CHECK(umi_fs_join(path,sizeof(path),root,"CMakeLists.txt") == UMI_STATUS_OK);
        char *cmake = NULL; CHECK(umi_fs_read_text(path,&cmake,NULL) == UMI_STATUS_OK);
        char *line = strstr(cmake,noTests ? "    add_test(" : "include(CPack)"); CHECK(line != NULL);
        char *end = strchr(line,'\n'); CHECK(end != NULL);
        memset(line,' ',(size_t)(end-line));
        CHECK(umi_fs_write_text(path,cmake) == UMI_STATUS_OK); umi_fs_free_text(cmake);
    }
    /* Generated profiles may use paths relative to their source root. Convert
     * this example's paths for independent filesystem verification below. */
    if (!umi_fs_is_absolute(profile.build_directory)) {
        CHECK(umi_fs_join(path,sizeof(path),root,profile.build_directory) == UMI_STATUS_OK);
        strcpy(profile.build_directory,path);
    }
    if (!umi_fs_is_absolute(profile.install_directory)) {
        CHECK(umi_fs_join(path,sizeof(path),root,profile.install_directory) == UMI_STATUS_OK);
        strcpy(profile.install_directory,path);
    }
    profile.timeout_ms = 30000U; profile.parallel_jobs = 2U;
    CHECK(umi_build_project_session_create(&config,&session) == UMI_STATUS_OK);
    CHECK(umi_build_project_session_submit(session,&profile,UMI_BUILD_PHASE_PACKAGE,false) == UMI_STATUS_PERMISSION_DENIED);
    size_t phases = 0U;
    if (compileFailure || testFailure || noTests || noCPack || deployFailure) {
        CHECK(Run(session,&profile,deployFailure ? UMI_BUILD_PHASE_DEPLOY : UMI_BUILD_PHASE_PACKAGE,0,&phases) == EXIT_SUCCESS);
        CHECK(phases == (compileFailure ? 2U : noCPack ? 4U : 3U));
        CHECK(!umi_fs_is_directory(profile.install_directory));
    } else {
        CHECK(Run(session,&profile,UMI_BUILD_PHASE_PACKAGE,1,&phases) == EXIT_SUCCESS && phases == 4U);
        CHECK(umi_fs_join(path,sizeof(path),profile.build_directory,"packages") == UMI_STATUS_OK);
        UmiDirectoryWalkOptions options = umi_directory_walk_options_default(); options.recursive = 0;
        Found found = {0}; CHECK(umi_directory_walk(path,&options,Find,&found) == UMI_STATUS_OK);
        CHECK(found.zips == 1U);
        char checksumPath[UMI_PATH_CAPACITY], *checksum = NULL;
        CHECK(snprintf(checksumPath,sizeof(checksumPath),"%s.sha256",found.zip) < (int)sizeof(checksumPath));
        CHECK(umi_fs_read_text(checksumPath,&checksum,NULL) == UMI_STATUS_OK && strlen(checksum) >= 64U);
        char hash[65]; memcpy(hash,checksum,64U); hash[64] = '\0'; umi_fs_free_text(checksum);
        const char *hashArgs[] = {"-E","sha256sum",found.zip};
        CHECK(Execute("cmake",hashArgs,3U,root,hash) == EXIT_SUCCESS);
        char extracted[UMI_PATH_CAPACITY]; CHECK(umi_fs_join(extracted,sizeof(extracted),root,"extracted") == UMI_STATUS_OK);
        CHECK(umi_fs_make_directories(extracted) == UMI_STATUS_OK);
        const char *extractArgs[] = {"-E","tar","xvf",found.zip};
        CHECK(Execute("cmake",extractArgs,4U,extracted,NULL) == EXIT_SUCCESS);
        options.recursive = 1; memset(&found,0,sizeof(found));
        CHECK(umi_directory_walk(extracted,&options,Find,&found) == UMI_STATUS_OK && found.program[0] != '\0');
        CHECK(Execute(found.program,NULL,0U,extracted,"Umicom Notes: 2 saved") == EXIT_SUCCESS);
        CHECK(Run(session,&profile,UMI_BUILD_PHASE_DEPLOY,1,&phases) == EXIT_SUCCESS && phases == 4U);
        memset(&found,0,sizeof(found));
        CHECK(umi_directory_walk(profile.install_directory,&options,Find,&found) == UMI_STATUS_OK && found.program[0] != '\0');
        CHECK(Execute(found.program,NULL,0U,profile.install_directory,"Umicom Notes: 2 saved") == EXIT_SUCCESS);
        CHECK(Run(session,&profile,UMI_BUILD_PHASE_REBUILD,1,&phases) == EXIT_SUCCESS && phases == 3U);
    }
    umi_build_project_session_destroy(session); umi_developer_project_service_destroy(projects);
    /* This path was created above by this process; no caller-selected folder is removed. */
    CHECK(umi_fs_remove_tree(root) == UMI_STATUS_OK);
    puts("Notes workflow checks passed."); return EXIT_SUCCESS;
}

9. When a workflow stops

What you seeWhat to inspect
Compiler or linker errorRead the first relevant diagnostic in Output. Check the selected project, source path and toolchain before changing code. Correct the source and request a new build.
Tests unavailable or no tests foundEnable the project’s testing option and register meaningful CTest tests. Do not disable the test gate to publish an untested package.
CPack cannot read its configurationCheck that the project includes CPack and has useful install rules. The Notes generator supplies these; an imported project may not.
Debugger cannot startRun the chosen adapter’s version command. Check DAP support, runtime dependencies, programme path, permissions and Debug symbols. A compiler success cannot fix a missing debugger library.
Project changed while Debug was waitingStop that request, review the new profile, save the intended sources and start again. Do not use an old build result as approval for a different executable.
Interface appears delayed during debuggingWait for the bounded adapter request to finish or time out. Record the operation and adapter output. The present debugger handshake is synchronous, unlike the compiler worker.

For a reproducible GUI problem, use Report problem, repeat the smallest sequence, add what you expected and what actually happened, and export the local report. Review screenshots and logs before sharing: they may contain source code and paths. A screenshot of a button is not enough to prove that its file, build or debugger operation succeeded.

10. Continue towards a daily-use IDE

A dependable IDE also needs responsive language intelligence, fully qualified native debugging, interactive terminals, workspace recovery, reliable Git workflows and clean-machine installation. Keep testing the complete Notes journey rather than judging a feature by whether its menu item is present. Each confirmed problem should name the failing operation, the affected project and the observed result.
