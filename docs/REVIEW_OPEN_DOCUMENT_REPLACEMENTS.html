Review replacements across open documents

A draft is the text currently held by an editor, including changes that have not been saved. The document service can capture the set of open documents and ask the user to review a replacement in each draft. The service owns the sequence; applications supply the search text and present the decisions.

What the review includes

The starting set includes pinned tabs and untitled documents. Documents opened afterwards are excluded. The search is literal: punctuation is ordinary text, and replacement text has no template syntax. An ASCII uppercase letter in the search makes it case-sensitive; otherwise ASCII letters match without case. Non-ASCII text is matched exactly. An empty replacement removes matches; an empty search is rejected.

Each question contains the complete draft and proposed text. Changes made before a document's turn appear in that question. Changes made after capture invalidate Apply, even if the text is later changed back.

Connect a native editor

  1. Bind the document coordinator with UmiGtk4AdapterBindDocumentEditing, using a completion callback that refreshes your application.
  2. Collect Find and Replace with fields. Call UmiGtk4AdapterReviewOpenReplacements(adapter, needle, replacement) on the GTK thread.
  3. Handle an immediate error using its returned status. A successful call opens the shared review window; no draft has yet been accepted.
  4. Let the shared window present Apply to this document, Skip this document and Stop. It prepares one document per idle dispatch.
  5. When the window closes, the existing edit callback reports completion, cancellation or failure and the document view is refreshed.
  6. Unbind editing before destroying the coordinator. This cancels pending work and disconnects controls retained by another owner.

Use UmiGtk4AdapterReplacementReviewProgress to inspect a live review and UmiGtk4AdapterCancelReplacementReview to stop and close it programmatically. The progress API returns UMI_STATUS_NOT_FOUND after the form closes. Native saving, closing and delayed paste cannot start another decision while the review is open.

Use the sequence without GTK

  1. Include umicom/document/replacement_session.h and create a session with the coordinator and two UTF-8 strings. The session copies both strings.
  2. Read progress. In READY, call UmiDocumentReplacementSessionStep once and inspect progress again. An OK return does not imply the whole sequence is complete.
  3. In REVIEW, call UmiDocumentReplacementSessionTexts and display both full buffers. They are borrowed until the next decision, cancellation or destruction; copy them for longer-lived widgets.
  4. Call UmiDocumentReplacementSessionRespond only after an explicit Apply, Skip or Stop decision. Apply repeats freshness checks against the captured document identity.
  5. At COMPLETE, CANCELLED or FAILED, display the counters and last status. Destroy the session when its progress is no longer needed.

Keep the coordinator, store and workbench alive while preparing, checking or applying. These are owner-thread operations. Cancellation, progress inspection and destruction use owned state and do not need to access the former coordinator. The implementation retains one complete text plan at a time; the existing document text limit still applies.

Understand the result

OutcomeMeaning
AppliedThe reviewed draft changed. It has its own Undo entry.
SkippedThe user left this draft alone.
UnchangedNo match or the replacement produced the same text.
Read-onlyThe draft could not be edited when its turn started.
ClosedThe captured document no longer exists. A new tab with the same name is a different document.
RemainingDocuments still awaiting a completed outcome, including a stopped or failed current question.

These document counts add up to the original total. The separate replacement count includes only accepted drafts.

Recover from a stopped review

If a draft changes, becomes read-only during its question, is saved under a different path, or cannot be prepared, the sequence stops. Inspect the explanation and start a new review of the current state. A stale proposal is never silently refreshed and applied.

Stop keeps earlier accepted edits. Use Undo in each changed document to reverse its edit. This is not one transaction spanning all documents. No file is saved by replacement. Use the ordinary Save workflow afterwards. This feature does not search unopened files or rewrite the project on disk.
