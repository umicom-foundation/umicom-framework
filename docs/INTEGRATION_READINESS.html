Checking application readiness

A process can be running before it is ready to accept work. The integration readiness gate lets a supervising application record a confirmation from the particular process instance it started. It shares the existing suite runtime; it does not start processes or provide an authentication service.

Connect a supervisor to the gate

  1. Prepare a suite runtime using the application registry and suite definition. Keep the runtime alive for as long as the gate uses it. Link your application to the public Umicom::integration target and include umicom/integration/readiness_gate.h.
  2. Create a gate with UmiIntegrationReadinessGateCreate. Keep gate calls and ordinary runtime changes on one owning thread, or arrange equivalent serialization in your supervisor.
  3. After starting a member, confirm its current process token and generation against the supervisor's process records. Generate a fresh 32-byte challenge using a cryptographically secure operating-system random source.
  4. Arm that member with its token, generation, challenge, monotonic clock time and a bounded wait. Send the challenge through the transport you already own.
  5. Verify the responding transport peer's identity and access rights before confirming the response. Matching challenge bytes alone do not authenticate a process. An unverified peer, stale process instance or expired response must not make the application ready.
  6. Use UmiIntegrationReadinessGateIsReady when this policy is required. A registry entry marked running is a different observation and does not replace the gate's confirmation.
  7. Pass accepted process exits to UmiIntegrationReadinessGateExit. Destroy the gate before freeing the runtime. Recreate it after preparing a new runtime or changing suite membership.
A fixed challenge is useful in an isolated test, but is not suitable for a real supervisor. Do not store challenge bytes in logs, snapshots or project configuration.

Inspect readiness without exposing a challenge

UmiIntegrationReadinessGateSnapshot copies the member identity, process token, generation, deadline and pending or confirmed flags. It deliberately omits the challenge. This is local state supplied by the supervisor; it is not independent evidence that a remote service authenticated or that a process ran.

Understand library and linker checks

The seven UmiIntegrationReadinessGate functions are implemented in src/integration/suite_runtime.c and belong to umicom_integration. Their declarations in the public header do not provide executable definitions. Consumers need the matching library.

The integration archive symbol check includes all seven definitions. On supported GNU and Clang builds, a focused build of the suite runtime test or the readiness consumer also runs this check before linking. Its report is written under the build directory's link-reports folder. The check reads the archive; it does not alter it or substitute implementations.

  1. If a linker reports an undefined readiness function, check that the consumer links Umicom::integration from the same configured Framework checkout as its headers.
  2. Read the first archive or linker error. An archive report naming a missing symbol identifies an incomplete or mismatched library; adding another header include cannot repair it.
  3. Reconfigure the intended build tree after integrating source changes, then rebuild that consumer and its dependencies. Do not copy individual object files or libraries from a different checkout to make a link succeed.
  4. After the link succeeds, run framework.integration.readiness.consumer and framework.integration.suite_runtime. A successful symbol check confirms definitions, while these runtime cases exercise lifecycle behaviour.

Extend the workflow

Add process supervision and peer verification in their existing owners. Keep the gate focused on binding a readiness response to a member and process generation. Tests can inject a known challenge and peer decision, but production code must obtain both from trusted operating-system or authenticated transport facilities.
