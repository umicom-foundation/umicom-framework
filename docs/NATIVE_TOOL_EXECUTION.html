Use Umicom Framework to launch tools, capture diagnostics and stop owned helper processes.

1. What happens when a tool starts

When Studio builds a C project, it starts a program such as CMake or Ninja. That program may start a compiler, an assembler and a linker. A test runner can also start test executables, and those executables may start helpers. These are separate operating-system processes, even though the developer sees one Build or Test action.

Studio command→Framework build/test service→Native process service→Tool and helpers

A process lifetime specifies how long those processes belong to an operation. An owned tool operation should not leave a compiler or test helper running after Stop. An application that deliberately hands work to a separately managed service needs a different lifetime. Framework exposes that choice explicitly rather than guessing from an executable’s name.

The implementation is in src/platform/process.c. Its public contracts are umicom/platform/process.h and umicom/platform/process_supervisor.h. Applications call these contracts; they do not need to build Windows command lines, create process groups or manage operating-system job handles themselves.

2. Describe a request in C

UmiProcessRequest describes the executable, an array of literal arguments, an optional working directory, environment overrides, output capture and a timeout. An argument is one string in that array, not part of a shell command. Spaces in a filename therefore remain part of the filename.

const char *arguments[] = {"--build", "C:/Projects/Umicom Notes/build", "--parallel", "2"};
UmiProcessRequest request = {0};
request.program = "C:/msys64/ucrt64/bin/cmake.exe";
request.arguments = arguments;
request.argument_count = sizeof(arguments) / sizeof(arguments[0]);
request.capture_stdout = 1;
request.capture_stderr = 1;
request.timeout_ms = 120000U;
request.window_mode = UMI_PROCESS_WINDOW_HIDDEN;

Initialising the structure to zero gives unused options a known value. The program path selects the tool. The argument array above contains four entries: --build, the complete build-directory name, --parallel, and 2. Do not add shell quotes inside a path string; the Windows adapter encodes the argument when it constructs the native command line.

working_directory affects only the child. Environment entries override the child’s copy of the environment. Neither operation changes Studio’s current directory or its process-wide environment. Prefer absolute tool paths from the configured toolchain, especially when several compiler installations exist.

3. Choose the appropriate lifetime

ChoiceBehaviourTypical use
UMI_PROCESS_LIFETIME_TREEOwn the root process and ordinary helpers in its job or process group. Clean up remaining members on cancellation, timeout or root completion.Compilers, CMake, CTest and bounded development tools.
UMI_PROCESS_LIFETIME_CHILDWait for or cancel only the direct child. Separately managed descendants can continue.A deliberate hand-off to a service with another lifecycle owner.

Call UmiProcessExecuteWithLifetime for synchronous execution with an explicit choice. Optional observers receive either a copied-result view or raw output chunks on the executing thread. The function returns only after the selected request has finished. A GUI should call it from a worker, not directly from a button callback.

UmiStatus status = UmiProcessExecuteWithLifetime(
    &request, UMI_PROCESS_LIFETIME_TREE,
    NULL, NULL, NULL, result);

The existing umi_process_execute, UmiProcessExecuteObserved and UmiProcessExecuteStreamed entry points retain child-only lifetime behaviour. The request and result structures retain their layouts. Framework’s build runner and verified CTest execution adapter explicitly choose the owned-tree lifetime.

A process group or Windows job is a lifecycle boundary, not a security sandbox. A POSIX program can deliberately create a new session or change groups. Remote work and independently created service processes have their own owners. Use the security and isolation services for untrusted code.

4. Run a tool without blocking the interface

The process supervisor owns an asynchronous job and copies its request before submission returns. A job ID is the stable number used to request Stop, read progress and release a completed job. It is not a native process ID.

The complete example below is provided in examples/development/native_tool/main.c. It starts a CMake version probe through the shared supervisor, waits in a console application, and checks both the final state and the exit code.

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/development/native_tool/main.c
 * PURPOSE: Submit a compiler-tool probe to the shared asynchronous supervisor.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "umicom/platform/process_supervisor.h"
#include <stdio.h>

int main(void)
{
    UmiProcessSupervisor *supervisor = NULL;
    UmiProcessJobId job = 0U;
    UmiProcessRequest request = {0};
    UmiProcessJobSnapshot snapshot = {0};
    const char *arguments[] = {"--version"};
    /* A configured tool catalogue should provide an absolute executable path.
     * The example uses CMake from the prepared development environment. */
    request.program = "cmake";
    request.arguments = arguments;
    request.argument_count = sizeof(arguments) / sizeof(arguments[0]);
    request.capture_stdout = 1;
    request.capture_stderr = 1;
    request.timeout_ms = 10000U;
    request.window_mode = UMI_PROCESS_WINDOW_HIDDEN;
    UmiStatus status = umi_process_supervisor_create(NULL, &supervisor);
    if (status == UMI_STATUS_OK)
        status = UmiProcessSupervisorSubmitWithLifetime(supervisor,
            "CMake tool information", &request, UMI_PROCESS_LIFETIME_TREE, &job);
    /* This console example waits. A GTK frontend polls snapshot() from its
     * refresh loop and calls cancel() from its Stop action instead. */
    if (status == UMI_STATUS_OK) status = umi_process_supervisor_wait(supervisor, job, 15000U);
    if (status == UMI_STATUS_OK) status = umi_process_supervisor_snapshot(supervisor, job, &snapshot);
    if (status == UMI_STATUS_OK) {
        fputs(snapshot.output, stdout);
        if (snapshot.output_truncated) fputs("[The compact view is truncated.]\n", stderr);
        if (snapshot.state != UMI_PROCESS_JOB_SUCCEEDED || snapshot.exit_code != 0)
            status = UMI_STATUS_INTERNAL_ERROR;
    }
    if (status != UMI_STATUS_OK) fprintf(stderr, "Tool request failed: %d\n", (int)status);
    umi_process_supervisor_destroy(supervisor);
    return status == UMI_STATUS_OK ? 0 : 1;
}

In a graphical frontend, replace the blocking wait with periodic umi_process_supervisor_snapshot calls from the normal refresh loop. A Stop action calls umi_process_supervisor_cancel(supervisor, job). It requests cancellation; the job can still be running until a later snapshot reports a terminal state. Keep the supervisor alive until its workers have finished.

UmiProcessSupervisorSubmitWithLifetime accepts the lifetime parameter. The original umi_process_supervisor_submit keeps child-only semantics for existing callers. Studio’s trusted process submission chooses the tree lifetime explicitly. Completed jobs remain available until their owner calls UmiProcessSupervisorReleaseJob or destroys the supervisor.

5. Read results and preserve the useful diagnostic

Field or resultMeaning
launchedThe executable was started successfully. An invalid request or a missing executable can leave this false.
exit_codeThe child’s exit status. A nonzero code must not be treated as successful compilation.
cancelled / timed_outCancellation and expiry are distinct outcomes; neither means that the tool completed successfully.
output_truncatedThe fixed display buffer omitted earlier bytes. The newest diagnostic text is retained.
Raw output observerReceives every captured chunk before the diagnostic tail rotates. Copy or write the bytes during the callback and impose a suitable storage limit.

The process result has a 64-KiB output array, including its terminator. Compact supervisor snapshots have a 4-KiB array and retain the final part of that output. This is particularly useful for a compiler that prints a long command trace before reporting its actual error. A raw observer is appropriate when a parser needs the complete output instead of a compact display.

Captured data is bytes. Framework does not guess the child’s text encoding. When both output streams are captured, their bytes share the same native pipe and do not carry a separate stdout/stderr label. A JSON consumer must reject an invalid or contaminated document rather than silently skip diagnostic text.

Stop can leave partial files created by the tool. Reconfigure or rebuild as needed, inspect diagnostics, and regenerate a package before using it. Stopping a process does not roll back filesystem changes made earlier in the operation.

6. Understand Windows and POSIX requirements

Windows

Request strings are UTF-8. The Windows adapter validates them, converts them to UTF-16 and uses CreateProcessW. This covers the executable, arguments, working directory and explicit environment values. The child still needs to support the characters in any files it opens itself.

Owned jobs are created suspended, assigned to a Windows job and then resumed. If job assignment fails, the executable is not allowed to continue without its requested ownership. Captured launches use an explicit inheritable-handle list. Missing console handles are represented by NUL endpoints instead of requiring a console window.

Nested job restrictions can apply in a CI agent or other host. An assignment error is a configuration or host-policy problem to investigate; it is not a reason to silently launch an unowned process.

POSIX

The owner prepares its environment and executable candidates before forking. The child performs the native setup and executes the selected program. An owned invocation creates a private process group. Framework retains the direct child’s waitable identity until group cleanup is complete, then reaps that child.

Leave reaping of these children to Framework. Do not use SIGCHLD auto-reaping, SA_NOCLDWAIT, or another thread that waits for the same child. Coordinate any process-wide environment changes with process launch preparation. These rules matter in a multithreaded application, not just in a standalone test.

7. Build the examples and checks

Use a checkout containing Framework’s headers and sources. On Windows, open PowerShell and prepare the UCRT64 toolchain. The checks compile the same process implementation used by the applications.

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake -S ".\framework\tests\native_process" -B ".\build\native-process-checks" -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build ".\build\native-process-checks" --parallel 2
ctest --test-dir ".\build\native-process-checks" --parallel 2 --no-tests=error --output-on-failure
& ".\build\native-process-checks\umicom-native-tool-example.exe"

Run each command separately and inspect errors before continuing. Configuration creates build rules; the build compiles the programs; CTest executes the checks. The version-probe example prints the CMake information returned by its child process. Linux uses the same source and build directories with forward slashes and an executable without the .exe suffix.

The process-tree fixture uses ordinary native helper executables. The CTest integration check puts CTest above that helper tree. The Notes workflow check builds a C/Assembly project, runs its tests, installs to an isolated prefix, creates a ZIP and verifies its checksum. Fixture directories are created beneath the chosen build directory.

8. API and platform references

The public declarations are in include/umicom/platform/process.h and include/umicom/platform/process_supervisor.h. The operating-system contracts are documented by Microsoft’s CreateProcessW reference, Windows Job Objects, process attribute lists and the POSIX process-group interface.
