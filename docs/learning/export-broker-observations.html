Export received broker observations

Trader's Broker Connections window can write the selected account's received values and positions to a new local CSV file. CSV is a plain-text table that you can inspect in a text editor or import into a spreadsheet. Exporting formats captured data; it does not ask the broker for new data.

Create a report

  1. Open Paper / Live broker connections, check your intended provider login and connect through the existing read-only workflow.
  2. Select an authorised account and choose Read selected account once. Wait for summary and positions to complete when you want a complete received response. A partial response can also be exported, but its completeness flags remain false.
  3. Find Export received account observations. Enter a new absolute CSV path in a private folder outside your source repositories.
  4. Choose Write new account report. Framework freezes the current observations into an owned document and writes it on a worker. Reconnecting while the write is pending does not change the captured account.
  5. Check the completion message for the account and destination. Open the file and read the metadata row before interpreting its values. Closing the window does not undo a write that has already started.

Read the report correctly

Every row includes the selected account, requested Paper/Live environment, connection state, stale flag, completeness flags and receipt information. environment_attested remains false because the framed connection does not independently attest the provider login's environment.

The header is followed by one metadata row and zero or more account_value and position rows. An empty response therefore still has an identifiable report. Summary and positions are separate captured responses; this report is not an atomic portfolio, a booked bank balance, a broker statement or evidence that an order executed.

Fields ending in monotonic_ms use the exporting process's monotonic clock. They support elapsed-time comparisons within that observation; they are not UTC dates and should not be compared across unrelated process runs. A completion time is blank while its response is incomplete.

Provider quantities, prices, currencies and identifiers remain text. No exchange-rate conversion, total valuation or decimal rounding is performed. Import provider columns as text to preserve leading zeros and decimal spelling. The shared CSV writer quotes fields and prefixes possible spreadsheet formulas with an apostrophe; negative provider text may therefore include that prefix. Do not interpret the export as a numerical reconciliation without reviewing its import settings.

Recovery and privacy

An existing destination is refused. A failed or cancelled write can leave a partial new file for inspection; it is never silently deleted. Choose a different new path to retry. A malformed or uninitialised snapshot produces no report. Reports contain account identifiers and financial observations, so keep them in the private folder you selected. They contain no API keys or stored login credentials and are not uploaded by this workflow.

Reuse Framework's exporter

Include umicom/broker_connectivity/observation_export.h. Copy the connection snapshot on its owning thread, then call UmiIbkrObservationsExportCsv. Its CSV document owns its text independently of the connection. Pass it to UmiIbkrObservationsWriteNew on a worker, or present its bytes in another frontend. Keep the document alive and unchanged until the write returns, then destroy it with UmiCsvDocumentDestroy.
