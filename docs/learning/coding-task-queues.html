Queue coding drafts without partial scheduling

A coding assistant can collect several tasks before a worker is ready to run them. Framework owns the queue and copies each request by value. This lets Studio or a headless client release its input buffers after a successful enqueue operation.

1. Separate safe storage from readiness to execute

UmiAiCodingRequestValidateText checks that each fixed text array has a zero terminator within its declared capacity. Empty arrays are allowed. An initialized request can therefore be stored while its session, runtime and instruction are still being selected.

The full umi_ai_coding_request_validate operation also checks ABI metadata, task and privacy domains, required identifiers, paths and budgets. Queue acceptance does not imply that this later validation will succeed. Neither operation gives permission to contact a provider or modify files.

UmiAiCodingRequest draft;
umi_ai_coding_request_init(&draft, UMI_AI_CODING_TASK_CHAT);
/* Text storage succeeds; execution validation refuses missing fields. */
UmiStatus storage = UmiAiCodingRequestValidateText(&draft);
UmiStatus readiness = umi_ai_coding_request_validate(&draft);

The text-only operation does not interpret UTF-8, paths or enumeration values. Call the validator for the operation you actually intend to perform. A valid terminator proves a bounded string, not a valid model request.

2. Submit a complete group in one operation

UmiAiCodingTaskQueuePushBatch checks capacity, remaining sequence values and every task before changing the queue. If one task is refused, none of the group is added. Existing queued tasks remain intact.

#include "umicom/ai_coding_runtime/task_queue.h"
#include <string.h>

int main(void)
{
    UmiAiCodingTaskQueue *queue = NULL;
    UmiAiCodingQueuedTask tasks[2] = {0}, result;
    int exit_status = 1;
    strcpy(tasks[0].task_id, "explain-buffer");
    strcpy(tasks[1].task_id, "review-lifetime");
    umi_ai_coding_request_init(&tasks[0].request, UMI_AI_CODING_TASK_EXPLAIN);
    umi_ai_coding_request_init(&tasks[1].request, UMI_AI_CODING_TASK_CHAT);
    if (umi_ai_coding_task_queue_create(&queue) != UMI_STATUS_OK) return 1;
    if (UmiAiCodingTaskQueuePushBatch(queue, tasks, 2U) != UMI_STATUS_OK) goto done;
    memset(tasks, 0, sizeof tasks); /* The queue owns complete copies. */
    if (umi_ai_coding_task_queue_pop(queue, &result) != UMI_STATUS_OK) goto done;
    if (result.sequence != 1U || strcmp(result.task_id, "explain-buffer") != 0) goto done;
    if (umi_ai_coding_task_queue_pop(queue, &result) != UMI_STATUS_OK) goto done;
    if (result.sequence != 2U || strcmp(result.task_id, "review-lifetime") != 0) goto done;
    exit_status = 0;
done:
    umi_ai_coding_task_queue_destroy(queue);
    return exit_status;
}

Build this C23 example against the installed Framework SDK and its Umicom::developer target. Expected exit status is zero. It stores and removes drafts only; it does not run a model or start a background worker.

3. Understand queue identities and ownership

  • The bounded queue holds up to UMI_AI_CODING_TASK_QUEUE_CAPACITY tasks.
  • First in, first out (FIFO) means tasks are removed in their insertion order.
  • The queue assigns each accepted task a sequence value. Input sequence values are ignored.
  • Duplicate task labels remain allowed. A sequence distinguishes individual entries within this queue's lifetime.
  • Clearing drops queued tasks but retains the counter. The next accepted task receives the next identity.
  • At the largest representable identity, further nonempty submissions return CAPACITY_EXCEEDED instead of wrapping to zero.
  • A zero-length batch is a no-op and may use a null task pointer, including when the queue is full or its counter is exhausted.

Sequence values are local ordering evidence, not globally unique identifiers or permissions. Destroying a queue ends its identity lifetime. A newly created queue starts a new lifetime.

Keep each input record complete and stable for the call. Input arrays must be separate from the queue's owned storage. Serialize all operations through the owning thread or an external lock. Atomic batch admission means all-or-none state change under that serialization; it does not make concurrent calls safe.

4. Recover from refusal without losing existing work

ResultMeaning and recovery
INVALID_ARGUMENTCheck required pointers, empty task labels and missing terminators. Correct the whole batch before retrying.
CAPACITY_EXCEEDEDReduce or postpone the group if queue space is unavailable. An exhausted identity counter needs a deliberately new queue lifetime; clearing cannot reuse old identities.
INVALID_STATEThe opaque queue's ring bounds are inconsistent. Stop using that owner and investigate its lifetime or memory ownership; repeatedly retrying is not a repair.
NOT_FOUNDA pop or peek found an empty queue. The caller's prior output remains unchanged.

Capacity and identity checks run before traversing batch records. When these checks refuse an oversized batch, that result does not certify that its records are otherwise valid. Never increase a count unless the input really contains that many readable records.

6. Construct input before resetting an owner

Fixed arrays need a terminator before a formatter can safely treat them as strings. A destination capacity in snprintf limits output, but its %s conversion still expects a valid input string. Validating the request after formatting it is too late. A second hazard appears when an input points into the owner that the operation is about to reset.

UmiAiCodingQueuedTaskPrepare solves the value-construction part once in Framework. It bounds the task ID, rejects empty or overlong labels without truncating them, invokes the existing request-text validator, and publishes a complete copied draft only after admission. It initializes the draft sequence to zero; insertion still assigns the actual queue sequence.

UmiAiCodingRequest request;
UmiAiCodingQueuedTask task;
umi_ai_coding_request_init(&request, UMI_AI_CODING_TASK_EXPLAIN);
UmiStatus status = UmiAiCodingQueuedTaskPrepare(
    "explain-buffer", &request, &task);
if (status != UMI_STATUS_OK) return status;
/* The incomplete request is a stored draft, not permission to run a model. */
status = umi_ai_coding_task_queue_push(queue, &task);

The example assumes the host already created the queue. For a variable task label, provide readable bytes through its terminator or the complete maximum prefix. If no terminator occurs before UMI_AI_CODING_RUNTIME_ID_CAPACITY, construction returns CAPACITY_EXCEEDED. A shorter string is inspected only through its terminator. The request must be a complete readable record, stable for the call.

Input fields may alias the constructor's output because it stages its complete candidate first. The agent uses the same constructor before clearing the prior task, so borrowed task and request data survive that reset. Platform enqueue delegates to it as well. This does not change the queue's rule that batch inputs remain separate from its internal ring storage, or make concurrent access safe.

  1. Prepare a draft with an ordinary label and confirm the copied label and request fields.
  2. Fill one request text array without a terminator and retry. The destination, previous agent task or queue must remain unchanged.
  3. Try a label at the accepted maximum and then one character longer. The longer label must fail rather than become the same truncated identity.
  4. Use the destination's own task and request fields as constructor inputs. Confirm that staging preserves the values and resets only the draft sequence.
