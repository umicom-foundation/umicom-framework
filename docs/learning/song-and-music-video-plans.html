Plan a song and its music video

The Song and video plan page is a local writing and timing tool shared by Umicom Media and Umicom Music. It turns your timed lyrics and chosen tempo into a shot list, and exports captions for a video editor. It does not generate music, analyse an audio file, animate a character or render a movie.

Create a plan

  1. Open the creative workspace and choose Song and video plan.
  2. Enter a title and describe the visual style or mood. These fields become part of the saved plan.
  3. Enter the song duration in milliseconds. One second is 1,000 milliseconds. Enter the tempo in beats per minute and choose how many beats each shot should last. At 120 beats per minute, four beats produce a two-second shot.
  4. If the first beat starts after a short introduction, enter its offset in milliseconds. The introduction becomes its own shot. The final shot ends at the song duration.
  5. Write each lyric with its start time. The example below starts two lines at zero and two-and-a-half seconds. Each line remains visible until the next one begins; the last ends with the song. Leave the field empty for an instrumental plan.
[00:00.000]The morning light arrives
[00:02.500]We begin another day
  1. Choose Prepare song plan. Review the displayed shot intervals and the lyric lines that overlap them. Nothing is uploaded.
  2. Enter a full path to a new .json file, then choose Save new plan file. Choose a location outside your source repository for personal lyrics and project plans.
  3. To export captions, change the path to a new .srt file and choose Save new SRT captions. SRT is a common text format for timed subtitles. Import it into an editor that supports SRT.

Reopen and revise

  1. Save any draft you want to keep.
  2. Enter the full path to an existing song-plan JSON file, select the replace approval, then choose Open plan from path.
  3. The form is replaced only after a complete valid plan is read. Shot intervals are recomputed from the saved timing; edited or stale derived shot data is not trusted.
  4. Change lyrics, tempo or duration and prepare again. Save to a new filename to keep the earlier draft.

Understand the limits

The plan supports up to ten minutes, 256 lyric cues and 512 shots. Use 30–300 beats per minute and 1–32 beats per shot. Very long songs with very short shots can exceed the shot limit; increase beats per shot. Times must increase strictly and be earlier than the song end. Each timestamp uses exactly two minute digits, two second digits and three fractional digits. Blank lines and Windows line endings are accepted. HTML-style angle brackets are refused in captions so players cannot silently interpret lyrics as formatting.

The plan contains text and timing, not the underlying audio or video. Keep source recordings separately. Visual style is descriptive text; it does not invoke an AI service. A selected shot can inform a separately reviewed PixVerse prompt, but plans are not automatically submitted or joined into a movie.

Recover from problems

  • If preparation fails, check the title, timestamps, duration and cue/shot limits. The form remains available for correction.
  • If saving reports an existing file, choose a new name. The writer does not replace files or create missing parent folders.
  • If an open operation fails, the previous form and plan remain intact.
  • Stopping a write may leave a partial new file. The message identifies a created file; inspect it before deciding what to keep. Closing the page loses unsaved edits.

Extend the shared owner

Applications can call UmiSongPlanCreate, inspect cues and shots, then export an owned UmiCreativeAsset. Use the shared asset writer on a worker for disk access. Keep AI suggestions separate until the user accepts them into a new draft. New frontends can reuse the C API without GTK; they need their own input controls and file adapters.
