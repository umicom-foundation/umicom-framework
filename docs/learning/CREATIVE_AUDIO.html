Edit a sound without changing its original

From a short musical phrase to an exact frame selection, a waveform and a new PCM-WAVE file.

1. Make a short sound, then keep a smaller part

You may need a brief tune for a lesson, a sound effect for a game, or a short audio excerpt for a film. Rather than change the only copy, open the sound into memory, choose the part you need and write a new file.

This guide follows one small Umicom tune. The first exercise needs only the native console tool. The graphical exercise uses the same Framework service through Music Studio or Media Studio.

Keep your original. Loading reads the selected file; editing changes an in-memory preview; exporting creates a different file. The Audio clip tab does not attach audio to a saved project. Closing it discards its clip and preview. No playback starts automatically.

Use your existing built Umicom checkout, or the focused SDK steps near the end. Build with GTK4 for the graphical page. Choose a practice folder containing no irreplaceable recordings.

The short clip below was produced by the native C lesson. Press Play only when ready, with your volume low.

2. Understand samples, frames and seconds

A sample is one channel’s amplitude at one moment. A frame contains the samples for all channels at that moment. Mono has one sample per frame; stereo has two. Two channels do not make a recording twice as long.

The sample rate says how many frames make one second. At 48,000 Hz, 48,000 frames make one second. The tool keeps the input rate; it does not resample.

At 48,000 HzFrame count
0.05 seconds2,400
0.25 seconds12,000
1 second48,000
1.5 seconds72,000

A range is written [begin, end). It includes begin and excludes end. Its length is end − begin. This makes neighbouring edits fit together without using their shared boundary twice.

Discard
0–12,000Keep [12,000, 60,000)
48,000 frames = 1 secondDiscard
60,000–72,000

The editor supports signed 16-bit PCM: values from −32,768 to 32,767. PCM is an uncompressed representation. A .wav extension alone does not guarantee that the file uses this supported encoding.

3. Run the memory-only lesson

Open PowerShell in your Umicom Applications folder. Run this after the application build succeeds:

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
$Audio = ".\build\windows-ucrt64-all-debug\bin\umicom-audio-clip.exe"
& $Audio --self-test
if ($LASTEXITCODE -ne 0) { throw "The audio lesson failed." }

The lesson makes four musical notes, uses the existing WAVE synthesiser, imports those bytes, and renders an excerpt. It does not create a file or send sound to your speakers.

Four notes: 96000 frames at 48000 Hz (2 seconds).
Kept frames [12000, 84000): 72000 frames (1.5 seconds).
Gain 700/1000; each fade spans 2400 frames. The source remains unchanged.
Practice complete. Memory only; no file, database or audio device was opened.

4. Export the practice clip and inspect it

The next commands create the practice folder and write the lesson’s finished 1.5-second excerpt. The output file must not already exist. Choose a different name when repeating the exercise; the tool does not delete or overwrite the first result.

Set-Location "C:\umicom\Umicom-Applications"

New-Item -ItemType Directory -Force -Path "C:\umicom\Practice\Audio" | Out-Null

& $Audio demo "C:\umicom\Practice\Audio\Workshop-Trim.wav"
if ($LASTEXITCODE -ne 0) { throw "The demonstration export failed. Choose a new filename." }

& $Audio inspect "C:\umicom\Practice\Audio\Workshop-Trim.wav"
if ($LASTEXITCODE -ne 0) { throw "Audio inspection failed." }

The inspection should report 48,000 Hz, one channel, 72,000 frames and 1.500000 seconds. The peak and RMS values describe linear sample amplitudes; they are not an assessment of perceived loudness or listening safety.

Inspection counts optional metadata chunks that will not survive a new export. Keep the original when cue points, broadcast metadata, loop markers or other annotations matter.

5. Edit the clip in Music Studio or Media Studio

Open Umicom Music Studio or Umicom Media Studio. Select Creative workbench, then its new Audio clip tab. Project, Objects, Motion, Notes and Export keep their earlier positions. Other creative profiles keep their existing pages.

Paste C:\umicom\Practice\Audio\Workshop-Trim.wav into Absolute source WAVE path. Choose Load WAVE. The loaded-file description—not just the editable path field—identifies the clip now held in memory.

Set these values:

Choose Preview range. The waveform shows the rendered selection, after the gain and fades—not the entire original clip. Stereo has two lanes. Each vertical stroke spans the minimum and maximum sample in a small contiguous group of frames. A zero-height stroke is not missing data; it may be silence or one constant sample.

Changing any range or gain setting clears that preview and disables Write new WAVE until you preview again. The display is a waveform preview, not playback.

Enter C:\umicom\Practice\Audio\Workshop-Selection.wav in New absolute destination WAVE path, then choose Write new WAVE. Use a separate audio player to listen at a low volume. Reopen the original to confirm it is still 1.5 seconds.

A failed load leaves the previous clip available. Editing the source-path field alone does not reload it. The Audio clip page is independent of the saved notes and drawing; it does not create or change a Data Server project.

6. Make the same edit from PowerShell

The console and graphical page call the same Framework functions. The numeric arguments are begin frame, end frame, gain, fade-in frames, fade-out frames, in that order:

& $Audio trim `
    "C:\umicom\Practice\Audio\Workshop-Trim.wav" `
    "C:\umicom\Practice\Audio\Workshop-Selection.wav" `
    12000 60000 700 2400 2400

if ($LASTEXITCODE -ne 0) { throw "Trim export failed. Inspect the reported error." }

& $Audio inspect "C:\umicom\Practice\Audio\Workshop-Selection.wav"
if ($LASTEXITCODE -ne 0) { throw "Selection inspection failed." }

The new file contains 48,000 frames and lasts one second. The rate and channel order are unchanged. Quoting both paths preserves spaces in folder names.

For an unchanged copy of the supported audio samples, use the complete frame range, gain 1000 and zero fades. This preserves sample bytes, but the output is a new minimal WAVE file without optional source metadata.

7. What the fades do

Gain 1000 leaves amplitude unchanged; 500 halves it; 0 produces silence. Values above 1000 are rejected, so this editor does not amplify the samples or introduce additional saturation. It cannot repair clipping already present in the source.

A fade-in of more than one frame starts at zero and reaches full gain on its last frame. A fade-out follows the reverse progression, ending at zero. A one-frame fade silences that endpoint. A zero-frame fade does nothing. Both fade lengths must fit within the retained range. When they overlap, both reductions apply.

For reproducible integer PCM results, the renderer applies attenuation first, then the fade-in, then the fade-out. Each signed division rounds towards zero. This is a deliberately simple editing profile, not a dithered mastering engine.

Waveform overviews are also exact about their coverage: all selected frames occur in one bin, and no bin is empty. Requesting more bins than there are frames produces one bin per frame.

8. Read the complete C example

The example is a normal source file at framework\examples\creative_audio\lesson.c. It uses the existing creative project and export APIs, followed by the new audio API.

Musical notes→Existing WAVE export→Owned audio clip→Trim and fade→New WAVE bytes

Read the cleanup near the end before changing the code. A project is caller-owned, each export owns its allocated bytes, and each clip owns copied PCM. Freeing the first exported buffer cannot invalidate an already imported clip.

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/creative_audio/lesson.c
 * PURPOSE: Compose notes, render sound, retain a range and release every owner.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "lesson.h"
#include <stdio.h>
#include <stdlib.h>

UmiStatus UmiCreativeAudioLesson(UmiCreativeExport *optionalOutput)
{
    UmiStatus status;
    UmiCreativeProject *project = calloc(1U, sizeof(*project));
    UmiCreativeExport source = {0}, trimmed = {0};
    UmiCreativeAudioClip *clip = NULL, *result = NULL;
    UmiCreativeAudioInfo info;
    if (optionalOutput != NULL && (optionalOutput->bytes != NULL || optionalOutput->size != 0U)) {
        free(project); return UMI_STATUS_INVALID_STATE;
    }
    if (project == NULL) return UMI_STATUS_OUT_OF_MEMORY;
    UmiCreativeSettings settings = {"Workshop sound", UMI_CREATIVE_PIXELS, 640, 360, 2000U, 120U};
    status = UmiCreativeProjectInit(project, "workshop-sound", &settings);
    const unsigned char pitches[] = {60U, 62U, 64U, 67U};
    for (unsigned i = 0U; status == UMI_STATUS_OK && i < 4U; ++i) {
        UmiCreativeNote note = {0};
        (void)snprintf(note.id, sizeof(note.id), "note-%u", i + 1U);
        note.startTick = i * 480U; note.durationTicks = 480U;
        note.pitch = pitches[i]; note.velocity = 60U;
        status = UmiCreativeProjectPutNote(project, &note, false);
    }
    if (status == UMI_STATUS_OK) status = UmiCreativeExportBuild(project, UMI_CREATIVE_EXPORT_WAVE, 0U, &source);
    if (status == UMI_STATUS_OK) status = UmiCreativeAudioDecode(source.bytes, source.size, &clip);
    /* The imported clip owns a copy. It does not borrow the exported buffer. */
    UmiCreativeExportFree(&source);
    if (status == UMI_STATUS_OK) status = UmiCreativeAudioGetInfo(clip, &info);
    if (status == UMI_STATUS_OK && info.frames != 96000U) status = UMI_STATUS_INTERNAL_ERROR;
    UmiCreativeAudioEdit edit = {12000U, 84000U, 700U, 2400U, 2400U};
    if (status == UMI_STATUS_OK) status = UmiCreativeAudioRender(clip, &edit, &trimmed);
    if (status == UMI_STATUS_OK) status = UmiCreativeAudioDecode(trimmed.bytes, trimmed.size, &result);
    if (status == UMI_STATUS_OK) status = UmiCreativeAudioGetInfo(result, &info);
    if (status == UMI_STATUS_OK && info.frames != 72000U) status = UMI_STATUS_INTERNAL_ERROR;
    if (status == UMI_STATUS_OK) {
        puts("Four notes: 96000 frames at 48000 Hz (2 seconds).");
        puts("Kept frames [12000, 84000): 72000 frames (1.5 seconds).");
        puts("Gain 700/1000; each fade spans 2400 frames. The source remains unchanged.");
        if (optionalOutput != NULL) { *optionalOutput = trimmed; trimmed = (UmiCreativeExport){0}; }
        else puts("Practice complete. Memory only; no file, database or audio device was opened.");
    }
    UmiCreativeAudioDestroy(result); UmiCreativeAudioDestroy(clip);
    UmiCreativeExportFree(&trimmed); free(project);
    return status;
}

optionalOutput transfers the finished buffer to a caller only after all checks pass. With no output argument the lesson releases the result itself. Every failure follows the same cleanup path. The public service rejects reuse of a live output, rather than overwriting its pointer and leaking the allocation.

The clip is immutable, so callers may read it concurrently while they guarantee its lifetime. Destruction must never race a reader. Keep window callbacks on the GTK owner thread; the model does not store any GTK widget pointer.

9. Know which files this profile accepts

The supported input is RIFF/WAVE with format tag 1, signed little-endian 16-bit PCM, one or two channels, and a rate from 8,000 through 192,000 Hz. Files are limited to 4 MiB and 256 chunks. Every data block must contain whole sample frames.

The parser checks the declared RIFF length, chunk boundaries, byte rate, block alignment and odd-length padding. Exactly one format chunk and one data chunk are required. Bounded optional chunks may be skipped and counted.

MP3, FLAC, floating-point WAVE, 24-bit audio, WAVEFORMATEXTENSIBLE, RIFX and RF64 are outside this profile. Renaming a file cannot convert its encoding. Preserve the original and use an appropriate separately chosen converter where needed.

Export uses the established new-file writer. It refuses an existing destination. A disk or flush failure may leave a partial new file for inspection; it does not delete the original, remove the partial output, or claim power-loss-atomic publication.

Import refuses final symlinks, final Windows reparse points and non-regular files. Parent directory links, mapped drives and network-mounted filesystems are not a security sandbox. Choose a trusted practice directory and do not treat these checks as authentication of an audio file.

The file is refusedConfirm PCM16, mono/stereo and the size limit. A .wav suffix is not enough.
Preview range failsBegin must be smaller than end; end must not exceed the loaded frame count. Each fade must fit within the selected length.
Write new WAVE is disabledLoad a clip and preview the current settings again.
Export reports an existing fileChoose a new destination name. No overwrite switch is provided.
The picture changed but there is no soundThe page does not play audio. Export, then open the new file in your chosen player.
The old clip remains after a load errorThis is deliberate. Check the Loaded description before exporting.
The new tab is missingRebuild a GTK-enabled Music or Media application and open Creative workbench. The headless SDK does not build a graphical product.

11. Build the focused laboratory and its client

These commands build the shared native services and tests without starting an entire application. They do not replace your normal complete Applications build.

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"

& "C:\msys64\ucrt64\bin\cmake.exe" `
    -S ".\framework\examples\creative_audio" `
    -B ".\build\creative-audio" -G Ninja `
    -DCMAKE_BUILD_TYPE=Release
if ($LASTEXITCODE -ne 0) { throw "Audio SDK configuration failed." }

& "C:\msys64\ucrt64\bin\cmake.exe" --build ".\build\creative-audio" --parallel 2
if ($LASTEXITCODE -ne 0) { throw "Audio SDK build failed." }

& "C:\msys64\ucrt64\bin\ctest.exe" --test-dir ".\build\creative-audio" `
    --parallel 2 --no-tests=error --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "Audio SDK tests failed." }

& ".\build\creative-audio\bin\umicom-audio-clip.exe" --self-test
if ($LASTEXITCODE -ne 0) { throw "The lesson failed." }

Install this focused SDK into a new practice directory. Then compile the separate client, which includes only public headers:

$Sdk = "C:\umicom\Practice\AudioSdk"
& "C:\msys64\ucrt64\bin\cmake.exe" --install ".\build\creative-audio" --prefix $Sdk
if ($LASTEXITCODE -ne 0) { throw "SDK installation failed." }

& "C:\msys64\ucrt64\bin\cmake.exe" `
    -S ".\framework\examples\creative_audio\client" `
    -B ".\build\creative-audio-client" -G Ninja `
    -DCMAKE_BUILD_TYPE=Release "-DCMAKE_PREFIX_PATH=$Sdk"
if ($LASTEXITCODE -ne 0) { throw "Client configuration failed." }

& "C:\msys64\ucrt64\bin\cmake.exe" --build ".\build\creative-audio-client" --parallel 2
if ($LASTEXITCODE -ne 0) { throw "Client build failed." }

& "C:\msys64\ucrt64\bin\ctest.exe" --test-dir ".\build\creative-audio-client" `

A Linux or WSL shell can use the separate OS host-tool entry. It builds host tools only, not an OS guest:

set -eu
OS="/mnt/c/umicom/umicomOS"
FW="/mnt/c/umicom/Umicom-Applications/framework"
BUILD="$HOME/umicom-builds/audio-clip"

cmake -S "$OS/tools/audio-clip" -B "$BUILD" -G Ninja \
    -DCMAKE_BUILD_TYPE=Release \
    -DUMICOM_OS_FRAMEWORK_SOURCE="$FW"
cmake --build "$BUILD" --parallel 2
ctest --test-dir "$BUILD" --parallel 2 --no-tests=error --output-on-failure
"$BUILD/bin/umicom-audio-clip" --self-test

Use -DUMICOM_AUDIO_SQLITE=OFF to test the memory Data Server without SQLite. Its five retained SQLite tests explicitly skip. The old independent-export Python check remains an alternative; the new clip implementation and its primary tests do not require Python.

12. Try three changes and explain the result

Exercise A. Starting with a 48,000 Hz file, keep frames 24,000 through 48,000. How long is the output?

Exercise B. Import a stereo file, then keep its first 100 frames at unity gain with no fades. How many samples are in the output, and what should change?

Exercise C. Preview a range, then change the gain. Why must export be disabled until another preview?

Answers

A: 24,000 frames, or half a second. B: 200 samples in 100 frames. Sample bytes, rate and channel order stay the same; optional metadata need not remain. C: The old preview contains different processed samples from the current form. Requiring a fresh preview prevents exporting stale settings.

Further experiment. Apply two long overlapping fades to a short range. Compare the result with two non-overlapping fades. Read the integer rounding rule and predict the first and last samples before you inspect them.

Reference notes

The native implementation uses the existing Umicom::creative_workspace owner. It introduces no new project schema, database or player service. The earlier SVG, storyboard, HTML and note-WAVE exporters remain available.

This is the audio-editing part of the creative-applications programme. Video decoding, audio-device playback, large-recording streaming, project attachment persistence, CAD constraints and mobile packaging are separate work.

Engineering references: Microsoft: RIFF structure and chunk padding; GTK: drawing callback and ownership. The supported format limits and rounding rules above are Umicom’s deliberately narrower profile.
