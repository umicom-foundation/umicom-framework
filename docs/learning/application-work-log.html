Write an activity report for Umicom Notes

A useful first program can tell us what happened in an application. We will write an activity report for Umicom Notes. It will show how many notes were saved and how many still need attention. You will create a source file, build it and run it. The same routine will be used for larger applications later.

Start with a project folder

In Studio, choose File → New Project. Select C23 Console Application. Use Umicom Notes for the display name, org.umicom.notes for the application identifier and umicom_notes for the target name. A target is the name by which the build system knows your program. Choose a new destination such as C:\umicom\projects\UmicomNotes; it must not already exist.

The generated project includes src/main.c, a CMake build description and a preset file. Open src/main.c. Replace its contents with the activity-report example below. Save the file before asking CMake to build it. These are ordinary text files: Studio helps you work with them, but it does not turn them into an executable until the compiler runs.

Read the program before running it

#include <stdio.h> makes the standard input/output declarations available. Our program needs the declarations for puts and printf. An include line is handled before the compiler translates the C statements.

int main(void) names the function where this program starts. The braces enclose its body. int savedNotes = 3; creates an integer variable and gives it its first value. Its name explains what that value means. The semicolon finishes the statement.

puts writes a line of text. printf can insert values into a message. In "Saved notes: %d\n", %d asks for an integer and \n ends the line. The next argument supplies the integer. return 0; tells the operating system that the program finished successfully.

Configure, build and run

Open Build → Project Settings and check that the source directory is your new project, not the Applications repository. Review the code, then explicitly mark this project as trusted. A CMake file can run commands, so opening an unfamiliar folder must not automatically authorise a build.

Choose Build. Studio first configures the project and then compiles it. Watch the Build panel and open Output to read the completed phase. Choose Run after a successful build. The run profile must name your generated program, not Studio itself.

Umicom Notes — activity report
Saved notes: 3
Notes waiting to be saved: 1

Make one controlled change

Change savedNotes from 3 to 4. Save, build and run again. Only the saved count should change. This small experiment checks that you are editing the source used by the active build, rather than running an older executable elsewhere.

Now remove one semicolon and build again. Read the compiler message and find the reported source line. Restore the semicolon, save and rebuild. A failed build should produce an error, not quietly run a previously compiled program.

Check your understanding

Explain the difference between the source file and the executable. Which action writes your editor changes to disk? Which action translates those changes? Why is savedNotes a clearer name than x in this report?

Build and run the supplied example

Configure the learning targets once using the course setup. Run the commands below one at a time. Stop when a command reports a failure; do not continue to run an older executable.

Windows · PowerShell

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake --build --preset windows-ucrt64-all-debug --target umicom-learning-work-log --parallel 2
& ".\build\windows-ucrt64-all-debug\bin\umicom-learning-work-log.exe"

Linux · terminal

cd "$HOME/umicom/Umicom-Applications"
cmake --build --preset linux-gcc-all-headless-debug --target umicom-learning-work-log --parallel 2
./build/linux-gcc-all-headless-debug/bin/umicom-learning-work-log

Source to study and edit

These are the supplied files for this lesson. Open them in Studio to follow the code. The Notes model is shared by the terminal example and the window; keep one implementation while trying different frontends.

work_log.c

framework/examples/learning/projects/work_log.c

/*-----------------------------------------------------------------------------
 * Umicom Framework — application development lessons
 * File: examples/learning/projects/work_log.c
 * PURPOSE: Write a small activity report for a Umicom application.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/

#include <stdio.h>

int main(void)
{
    int savedNotes = 3;
    int pendingNotes = 1;

    puts("Umicom Notes — activity report");
    printf("Saved notes: %d\n", savedNotes);
    printf("Notes waiting to be saved: %d\n", pendingNotes);
    return 0;
}
Your practical task

Change the saved and pending counts, rebuild and check the new report.
