Detect stale AI context previews

A preview can become outdated while a person reviews it. A policy may change, a source may be removed, or a runtime entry may point to a different model. The old plan can remain a valid C structure while no longer describing the current decision. This lesson builds on context budgeting and privacy and uses the public AuthorEngine service contract.

1. Identify each owner

An owner is the service responsible for maintaining a particular collection or setting. The coordinating service owns its policy and budget. Its context broker owns source metadata. Its runtime catalogue owns runtime descriptions. Editing a child directly does not necessarily advance the coordinating service revision, so one counter cannot represent all three.

Observed fieldWhat makes it stale
service_revisionAny accepted service-owned mutation, including a policy update. This deliberately also rejects some previews after unrelated service actions.
context_revisionAn accepted broker upsert, removal or clear, including direct child access.
runtime_id and runtime_revisionA replacement, health update or disappearance of the selected runtime record.

A direct update to another runtime row does not invalidate the selected row. Rejected updates leave identities unchanged. Revision values belong to one live service and its children; identical numbers from a different service do not establish any relationship.

2. Prepare a complete preview

UmiAiAuthorEnginePlanContextObserved calls the existing policy-aware planner. It returns the same metadata plan plus an observation containing the three relevant identities. Both output objects must exist and must not overlap. On any error both retain their previous contents.

UmiAiContextPlan *plan = malloc(sizeof *plan);
UmiAiContextPlanObservation observed;
if (plan == NULL) return UMI_STATUS_OUT_OF_MEMORY;
UmiStatus status = UmiAiAuthorEnginePlanContextObserved(
    service, selected_runtime_id, sensitive_approved, plan, &observed);
if (status != UMI_STATUS_OK) {
    free(plan);
    return status;
}
/* Retain service lifetime and the initiating request alongside these values. */

The service does not open source URIs or invoke a model. Planning can succeed for an unavailable model because metadata planning and transport readiness are separate responsibilities. An approval flag is an input to the current planning decision; the returned observation does not preserve or grant approval for later execution.

3. Recheck after review

UmiStatus status = UmiAiAuthorEngineCheckContextObservation(service, &observed);
if (status == UMI_STATUS_BUSY) {
    /* Keep the action stopped. Prepare and review a fresh preview. */
    return status;
}
if (status != UMI_STATUS_OK) return status;
/* Recheck the initiating request, source text, final prompt budget,
 * current execution policy and selected transport before a separate action. */

BUSY means an observed owner changed or the runtime disappeared. A malformed observation returns INVALID_ARGUMENT. Invalid owner state is a separate error. An OK result only means the recorded identities still match: it does not authenticate an endpoint, prove file freshness, compare a final prompt with the plan, or authorize network access.

4. Keep checks and actions on the correct owner

These APIs provide no mutex and do not make concurrent access safe. Serialize operations on the service and its child owners. A worker can prepare external data, but its completion should return to the owning thread and check that the same workspace and request still exist. Never retain a service pointer after destruction.

The existing API that returns only a context plan remains available. Use the observed variant when a preview is retained across user interaction. A caller can pass the previous observation's runtime ID back into the planner because the ID is copied before the output observation is replaced.

5. Reproduce a stale preview offline

  1. Create a runtime description and register a public source. Prepare an observed plan.
  2. Replace that source's label through the broker. Check the observation and expect BUSY; the old plan remains unchanged.
  3. Prepare another observed plan. Change the service budget through umi_ai_authorengine_service_set_policy. Expect BUSY again.
  4. Refresh the preview. Update only an unrelated runtime through the catalogue. The selected runtime identity should still match.
  5. Attempt an invalid source update, such as a zero token estimate. Expect refusal and an unchanged valid observation.

Run the native cases from a configured Framework checkout, stopping on errors:

cmake --preset windows-ucrt64-debug
cmake --build --preset windows-ucrt64-debug --target umicom-ai-context-observation-test
ctest --test-dir build/windows-ucrt64-debug -R '^framework[.]ai[.]context[.]observation[.]' --output-on-failure --no-tests=error

The regression source covers malformed observations, policy and child edits, unavailable metadata, read-only exhausted service revisions, failure preservation and successful re-preview. The SDK consumer exercises the exported symbols without a model or network connection. Registered tests still require compiler and runtime qualification; no GUI interaction is established by these API cases.
