Function signatures and parameter help

A function signature describes the arguments a function accepts. Some languages allow several functions with the same name and different arguments; these alternatives are called overloads. Framework can ask a chosen local language server for the overloads available at the current caret, then show their parameter descriptions without changing the source document.

Read help in Studio

  1. Open a source document and place the caret inside a function call. The document may contain unsaved changes or be read-only.
  2. Choose Parameters… in the editor toolbar. This captures the document text and caret. Opening the form does not launch a language server.
  3. Enter an absolute path to a language-server executable that you have installed, its ordinary command-line arguments, and the absolute project folder. You can use Load saved server to reuse settings previously saved for this language. Loading settings also does not launch the server.
  4. Choose Request parameter help. The selected program receives the captured draft and project location. It may inspect other files in that project. The temporary connection initializes, requests help, closes the document and shuts down before a result is published.
  5. Choose an overload from the searchable selector. The form shows its complete signature, documentation and numbered parameters. The active parameter is marked in the list and, when the server supplied an exact label span, highlighted in the signature.
  6. Choose Close when finished. This workflow does not edit or save the document. If you change the document or caret, close the form and open it again to capture the new location.

Documentation and highlighting

Descriptions are displayed as literal text. Markdown markers and HTML remain visible text; they do not execute code or open links. A parameter may be described by a substring or by offsets into the signature. Protocol offsets count UTF-16 code units; Framework converts them to UTF-8 byte spans before GTK highlights characters. A supplementary character such as an emoji occupies two UTF-16 units but four UTF-8 bytes, so a span that splits its surrogate pair is rejected.

When a string label occurs more than once, Framework lists the parameter without guessing which occurrence to highlight. The signature's own active-parameter value takes precedence over a top-level value. An omitted or out-of-range active index defaults to the first available choice. Empty results mean the server supplied no help at that location.

Use the shared service

  1. Include umicom/language_runtime/signature_query.h and link the Framework developer target.
  2. Fill UmiLanguageSignatureRequest with the root URI, source URI, language identifier, complete UTF-8 source, its byte count, a caret byte offset and a read timeout. Keep these inputs alive until the call returns.
  3. Run UmiLanguageSignatureQueryNative on a worker. The profile and working directory identify an explicitly chosen local program. Do not pass widget pointers or a mutable editor buffer to that worker.
  4. On success, use UmiLanguageSignatureCatalogueCount, UmiLanguageSignatureCatalogueActive, UmiLanguageSignatureCatalogueAt and UmiLanguageSignatureCatalogueParameter to inspect borrowed views. The strings belong to the catalogue.
  5. Before presenting the result, verify that its captured document is still current. Release the catalogue with UmiLanguageSignatureCatalogueDestroy, including when its result is no longer needed.

Applications that already receive protocol replies can use UmiLanguageSignatureCatalogueReadResponse with the expected request ID. The standalone reader accepts up to 1 MiB of JSON, 256 overloads, 256 parameters per overload and 4096 parameters overall. Labels allow 65536 UTF-8 bytes, each description allows 262144 bytes, and all retained labels and descriptions together allow 4 MiB. A failure returns no partial catalogue.

Limits and recovery

  • No provider: the server must advertise signature-help options, document open/close synchronization and UTF-16 source positions. Check that it supports the document language.
  • No useful result: check the caret location and the project's language-server configuration. Framework does not install servers, generate compilation databases or add initialization options in this form.
  • Timeout: Studio allows five seconds for initialization and reply reads. Cleanup has a separate 250 ms budget. A large project may require more startup time than this temporary workflow provides.
  • Capacity error: the native message limit is 65536 bytes including JSON escaping and its envelope, with the existing native parser's token limit. These limits can be smaller than the standalone catalogue limits; shorten the draft or use a different supported workflow.
  • Stale result: changing settings clears the displayed result. Editing the document or caret invalidates its captured identity. Reopen the form and request again.
  • Cancellation: closing the form retires it and requests cooperative cancellation. Native launch and synchronous writes are not interruptible by that token. The process owner manages the direct child, not descendants started by the server.

This is an explicit temporary query. It does not provide automatic typing popups, a persistent editor language session or trigger-character handling. Server settings are local preferences, not encrypted credential storage; do not put credentials in executable arguments.
