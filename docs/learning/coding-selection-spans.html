Select source lines from a bounded byte span

A source adapter often knows both the address and the length of its buffer. It should not need to append a temporary zero byte just to select a line range. Framework provides UmiAiCodingExtractSelectionSpan for this case and retains the existing terminated-string interface.

1. Supply the extent explicitly

#include "umicom/ai_coding_runtime/selection.h"
#include <string.h>

int main(void)
{
    const char source[] = {'o', 'n', 'e', '\n', 't', 'w', 'o'};
    char selected[16];
    size_t selected_length = 0U;
    UmiStatus status = UmiAiCodingExtractSelectionSpan(
        source, sizeof source, 2U, 2U,
        selected, sizeof selected, &selected_length);
    return status == UMI_STATUS_OK && selected_length == 3U &&
        strcmp(selected, "two") == 0 ? 0 : 1;
}

Build the example as C23 against the Framework SDK and its Umicom::developer target. Expected exit status is zero. The input array intentionally has no terminator. The supplied extent must describe actual readable storage; a length value cannot make an invalid pointer safe.

The span form accepts a null pointer only for an empty span. It rejects embedded zero bytes within a nonempty span. The original umi_ai_coding_extract_selection still requires a non-null terminated C string and delegates to the shared selection implementation after finding its length.

2. Understand the line coordinates

  • Line numbers begin at one, and both endpoints are inclusive.
  • A line-ending newline belongs to the selected line.
  • An end line beyond the available text selects through the end of the input.
  • A starting line beyond the available text returns NOT_FOUND.
  • An empty input has an empty first line. A trailing newline creates a final empty line.
  • LF separates lines. CRLF is preserved byte for byte, and a lone CR remains part of its line.

The operation uses line coordinates rather than display columns or grapheme counts. It preserves the selected bytes and performs no normalization or transcoding. Prompt construction applies its separate UTF-8 policy before publishing provider text.

3. Allow overlap only after inspection is complete

memcpy requires source and destination regions not to overlap. memmove defines the result even when they overlap. The extractor now finds and validates the complete selected range first, then uses memmove to publish its bytes.

char text[64] = "one\ntwo\nthree\n";
size_t length = 0U;
UmiStatus status = umi_ai_coding_extract_selection(
    text, 2U, 3U, text, sizeof text, &length);
/* On success, text contains "two\nthree\n". */

The character buffers may overlap in either direction when the destination has enough real writable space. The length-result object must be separate storage and must not overlap either character buffer. Keep all objects alive and serialize access during the call.

4. Preserve both results when refusing a request

The destination needs the selected byte count plus one byte for its terminator. If that space is unavailable, the function returns CAPACITY_EXCEEDED without changing either the destination bytes or the reported length. Invalid coordinates, malformed spans and missing lines also preserve both outputs.

ResultWhat to correct
INVALID_ARGUMENTRequired pointers, output capacity, line zero or reversed endpoints.
PARSE_ERRORAn embedded zero inside the explicit source span.
NOT_FOUNDThe requested starting line does not occur in the supplied extent.
CAPACITY_EXCEEDEDThe destination cannot hold content plus terminator, or the span uses the reserved SIZE_MAX extent.

Do not retry a capacity error with a larger numeric capacity unless the actual destination allocation is larger. Preserve the previous selection until a complete replacement succeeds.

5. Qualify the string and span interfaces together

# From the Framework source root after configuration with testing enabled:
cmake --build build/windows-ucrt64-debug --target umicom-ai-coding-selection-spans-test
ctest --test-dir build/windows-ucrt64-debug -R '^framework\.ai\.coding-selection-span\.' --output-on-failure

The 32 scenarios cover line ranges, EOF behavior, CRLF, Unicode byte preservation, nonterminated spans, empty spans, malformed arguments, exact capacity and overlap in both directions. Expected result: all selected cases pass. These native scenarios must be executed before a pass is claimed; authored source and CMake registration alone are insufficient.
