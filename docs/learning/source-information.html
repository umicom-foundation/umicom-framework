Read source information

A language server can explain a symbol under the caret, such as a function's type or documentation. Framework captures the current draft and requests this information on a worker. The result is read-only and does not change the document.

Use Source info in Studio

  1. Open a source document and place the caret immediately before the symbol you want to inspect. Writable and read-only drafts are supported. A selection does not change the request position: it uses the start of the selection.
  2. Choose Source info… in the editor command bar. Scroll the bar horizontally if the control is outside the visible area. The form captures the draft at this point. Opening it does not launch a program.
  3. Enter a trusted language server's absolute executable path, arguments and project folder, or choose Load saved server. Settings are shared with completion and formatting for this document's language. Loading fills the form without launching the server.
  4. Choose Request source information. The selected local program receives the captured source and can inspect the project folder. Framework closes the document and temporary connection before showing a result.
  5. Read or select the returned text. Markdown, HTML and code examples are displayed literally. No link or script is executed and no edit is staged. Choose Close when finished.

If information is unavailable

SituationWhat to do
No information at this caretMove the caret before another symbol and open a new form. A null reply is valid and means the server provided no content.
The capture became staleClose the form and capture again after changing the document, caret, selection, permissions or saved state. Changing server settings clears the displayed result and cancels a pending request.
The server is unsupportedThe server must advertise hover support, document open/close synchronization and UTF-16 positions. A temporary connection may not have the indexing state a persistent editor connection would provide.
Timeout or capacity exceededThe native form uses a five-second read budget. Each message must fit 65536 bytes, including escaped source and the JSON envelope, and 4096 parser tokens. Use a smaller draft or a supported server configuration. Synchronous launch and writes may finish before cancellation.

How the pieces fit together

UmiDocumentSourceRequestCreateInspection owns captured UTF-8 bytes and metadata without granting editing permission. Stage and Apply are always refused for an inspection request, even when its document is writable. Check compares source bytes, revisions, paths, permissions and caret against the original capture. No file is read or saved by this capture.

UmiLanguageHoverQueryNative owns initialization, document open/close, request correlation and child-process cleanup. Its optional returned range is checked against the captured source so UTF-16 coordinates cannot point outside the draft or split a Unicode character. Only the direct child is owned; programs that start their own descendants need additional supervision.

UmiLanguageHoverDocument independently reads up to 1 MiB of JSON, with at most 256 text/code blocks and 127 UTF-8 bytes in a code-language label. It owns all decoded text, supports plain text, markdown and legacy code-block arrays, and exposes a joined literal text representation. The native transport has the smaller limits described above. Rich rendering would require a separate sanitized renderer and explicit actions for opening links; this reader never evaluates returned content.

The GTK form keeps document access on its owning thread and gives workers copied source and settings. Closing or unbinding the editor cancels publication. Completion, formatting and source information share one source-review slot. This workflow does not provide automatic mouse hover, persistent indexing, server installation or arbitrary server-to-client configuration callbacks.
