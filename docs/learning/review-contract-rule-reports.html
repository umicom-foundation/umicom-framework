Review saved IBKR contract rules

A route-rule report records advertised order types and time-in-force settings for one stock contract and one Buy or Sell side. A time-in-force setting describes how long, or under which execution conditions, an order may remain active. This workflow reads a saved JSON report; it does not authenticate with IBKR or submit an order.

Open and inspect a report

  1. Obtain the JSON report from your contract-rule checker. Keep the original file so you can compare its timestamp, contract ID, currency, side and requested routes. A raw authentication response or raw contract-rules response is not this report format.
  2. In Umicom Trader, open Paper / Live broker connections. Expand Full-quantity policy and local liquidity watch, then Saved contract and route rules.
  3. Choose the report with Browse, then press Import rule report. The file is read on a worker so the inspector can continue responding. The path must be absolute and its final component must be a regular file. Use a trusted local directory.
  4. Select a requested route. Read the original TIF and order-type entries alongside the derived finding. The timestamp is supplied by the file; the importer does not establish that the information is fresh or authentic.
  5. To compare with a policy, select the intended quote contract and route in the inspector, choose Buy or Sell, enter valid policy fields and press Review policy. A usable quote is required to capture its identity. Contract, side and route must all match exactly. Editing policy or quote fields clears that comparison.
  6. Press Clear imported report when finished. Importing, clearing or comparing a report makes no broker request and changes no order.

Interpret the findings

FindingMeaning
FOK advertisedThe original TIF list contains a FOK entry. This is a candidate for further broker-side validation, not proof of acceptance or enforcement.
FOK not advertisedThe returned list does not name FOK. It does not describe every possible IBKR service.
InconclusiveThe checker reported an unsuccessful lookup, or a necessary rule list was missing or empty. This must not be reported as unsupported.

The reader separately reports whether LIMIT or LMT is explicitly listed after FOK and whether a limit order appears in the order-type list. Unexplained flags such as o,a are preserved without interpretation. Summary booleans from the file are ignored: the original lists determine the finding.

A matching report does not prove account permission, price units, exchange enforcement, commission treatment or support through the TWS API. FOK can produce several execution records while filling the full quantity. AON and minimum execution size remain unconfirmed; ordinary order-size increments are not minimum-fill guarantees. Neither this importer nor the existing local liquidity watch substitutes IOC or an ordinary limit order for FOK.

Format and troubleshooting

The report requires generated_utc in UTC ISO form, side equal to BUY or SELL, a contract object containing an integer conid and instrument_type: STK, and a nonempty routes array. Each route has requested_route, status (metadata_received or inconclusive), and optional time_in_force_entries and order_types arrays. The report is limited to 4 MiB, 100 distinct routes, 64 entries per list and 4096 UTF-8 bytes per entry. Duplicated supported fields, malformed data and oversized values are rejected without truncation.

If import fails, the prior report is cleared. Check the file format and limits, then import again. A relative path, directory, final symbolic link or device is rejected. Changing the selected path while a read is pending discards that result. Wait for that read to finish before importing again. Closing the window discards late results. If the optional complete JSON service is not built, the report panel is unavailable and the existing policy review remains available.

Only selected metadata is retained in memory. Account IDs, authentication responses and arbitrary commentary fields are discarded. The importer neither reads nor stores IBKR passwords or authenticator codes. The Client Portal Gateway used to collect these reports is a different interface from a TWS socket connection.

For contributors

Umicom::ibkr_rule_report owns bounded JSON import, copied values, exact identity comparison and plain-text presentation. The native panel owns file selection and publication. Extend the portable reader first, give each new field explicit bounds and semantics, then add regression coverage before exposing it in an application. Do not turn metadata into order-submission authority.
