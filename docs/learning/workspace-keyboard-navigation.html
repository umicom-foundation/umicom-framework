Navigate a workspace with the keyboard

Keyboard focus is the control that receives your next key press. A workspace region groups related controls, such as project files, an editor, a preview or an inspector. Framework provides a shared way to move between live regions while each product retains its own layout and commands.

Use the controls

  1. Open a workspace and click an editable field or use Tab to reach one.
  2. Press F6 to move to the next available region. The navigation wraps at the end.
  3. Press Shift+F6 to move backwards. Use Tab and Shift+Tab for controls within the selected region.
  4. Hide a supporting panel using the product's layout controls, then repeat navigation. Hidden panels and inactive notebook pages are skipped.
  5. Show the panel again. Its unsaved values should remain when the host retains content. Check values before applying a command.

The active region must contain a focusable control. A region containing only labels may be skipped. A single already-focused region stays put. Floating native windows remain separate: use your operating system's window switching to reach them. Navigation follows the current widget tree; it is not a configurable visual reading order. A focused child that handles F6 keeps that shortcut.

Integrate a custom workspace

Include the public header and link the existing Umicom::ui_gtk4 target. Call these functions on the GTK thread after creating the relevant widgets:

#include "umicom/ui/gtk4/workstation/focus_cycle.h"

UmiGtk4FocusCycleMarkRegion(library, TRUE);
UmiGtk4FocusCycleMarkRegion(preview, TRUE);
UmiGtk4FocusCycleMarkRegion(inspector, TRUE);
UmiGtk4FocusCycleInstall(workspace);

Each argument identifies an existing widget. Mark a panel body or a notebook, rather than every button. A marked parent owns one region; marked descendants do not add stops. An unmarked nested workspace manages its own children. The workspace must be a stable container; installing twice does not add duplicate controllers. GTK owns the controller for the lifetime of that widget. No additional teardown call is needed.

The shared native layout host marks panel content mounts automatically. Enable content retention on an empty host before adding panels if those bodies hold drafts. The Media sequence editor marks its library, preview, inspector and timeline separately. Applications using other renderers must provide their own supported navigation or adopt this service deliberately; this does not change every unrelated window automatically.

GTK split panes have their own F6 action. Install connects layout panes outside marked bodies to the shared cycle so their default traversal does not consume the key first. Call Install again after replacing layout containers. It binds new panes without duplicating controllers; specialised panes inside a marked body retain their own behaviour. Divider resize and handle-focus keys are unchanged.

Keep commands and navigation separate

UmiGtk4FocusCycleAdvance(workspace, FALSE) invokes the same operation from a product command. A TRUE result means focus ended inside another eligible region. It does not mean a document was saved, an order sent or a build started. Control, Alt, Super, Hyper and Meta combinations are left for application commands. Existing labels, visibility, ownership and document state are unchanged by marking a region.

GTK focus changes can notify observers immediately. An observer may hide a panel, select another control or close the window. Framework holds temporary widget references, rejects reentrant navigation within the native root and rechecks the final focus and ownership. It stops after a target is retired or focus is redirected, without restoring an obsolete selection. New integrations should retain that distinction between a focus request and an accepted final focus.

Check a product integration

  1. Record the source revision, GTK version, desktop scaling and selected product layout.
  2. Type a draft value without applying it. Move forward, reverse and wrap between regions.
  3. Hide and restore a region; maximise and restore a shared-host panel. Verify that the original controls and draft values remain.
  4. Repeat with the keyboard and inspect the visible focus indicator. Automated signal emission alone does not verify physical keyboard delivery or screen-reader output.
  5. Capture genuine screenshots only from the running application, with private values removed. Record failures and skips separately from passes.

Native regression coverage is registered under framework.ui_workstation.focus_cycle.*, framework.ui_workstation.workspace.focus.gtk4 and the Media workspace keyboard cases. These cover hidden pages, modifiers, nested containers, reentrant focus callbacks, detachment and retirement. A return code of 77 means the native display was unavailable; that is skipped coverage, not a pass.

If navigation does not move

Check that the workspace is mapped in a native window, contains another visible sensitive marked region, and that the destination has a focusable control. If a child owns F6, use the product's navigation command or leave that child first. Do not rebuild all panel contents merely to move focus; doing so can discard drafts. Inspect retained content and focus notifications before changing layout persistence.
