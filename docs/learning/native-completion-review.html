Review suggestions from a local language server

A language server is a separate program that understands a programming language. Framework can send it a captured source draft, request completion suggestions and prepare a complete replacement for review. Umicom Studio exposes this workflow through the editor's Complete… action.

Use the native review

  1. Open a writable source document. To replace a typed word, select that word within one line. With no selection, the fallback inserts at the caret. A server may return its own replacement range, which takes precedence.
  2. Select Complete… in Studio's editor command bar. Scroll the bar horizontally if necessary. The form captures the current draft and selection. Opening it does not launch a program or send source.
  3. Enter the absolute path to a trusted language-server executable, its arguments and the absolute project folder. These fields are drafts for this review; they are not saved automatically. The selected program can inspect that folder.
  4. Select Request suggestions. A worker starts a temporary connection, initializes it, sends the captured draft and asks for completion at the end of the selection, or at the caret. The connection closes before the suggestions become available. Closing the form requests cancellation.
  5. Select a suggestion from the searchable list, then select Preview complete draft. Review both texts, including any imports added by the server. A different suggestion or changed connection field invalidates the preview.
  6. Select I approve the displayed result, then Apply to captured draft. Framework rechecks the document and applies the reviewed result through its existing history. Undo restores the earlier draft. Save is a separate action. Cancel leaves the document unchanged.

Remember a server for each language

  1. Enter the server path and ordinary command-line arguments, then select Save server for this language. The form reports the local file location. Saving creates the application settings folder if needed.
  2. On a later visit, select Load saved server. The saved path and arguments fill the form. The project folder still comes from this workspace; it is not stored with the language settings.
  3. Review the loaded values before selecting Request suggestions. Neither saving nor loading starts a process or changes the document.

These are user-local JSON preferences, not an encrypted secret store. Keep API keys and passwords out of server arguments. Files are separate for each language, and the reader rejects a file labelled for a different language. A missing or invalid file leaves the current fields in place. If you edit while a load is pending, its result is discarded. A synchronous control observer interrupting publication stops further updates; review any field already loaded.

An explicit save writes the values captured when Save was selected. It may finish after the form closes. If you edit during a save, save again to keep the newer values. Saving uses atomic file replacement but does not promise a cross-process settings lock or power-loss durability on every filesystem.

What the review supports

Plain-text completions can supply a primary replacement, insert/replace ranges, list-level defaults and additional non-overlapping edits such as imports. The preview adjusts the caret for edits before the primary replacement. It does not execute server commands or treat snippets as ordinary text. Unsupported choices report a reason and leave the draft unchanged.

This is an explicit temporary request. It does not provide an automatic popup on every keystroke, a persistent indexing session, background diagnostics, tool installation or completion-item resolution. The Outline connection check remains a separate handshake that sends no source text.

Limits and recovery

SituationNext step
The source, caret, selection or saved state changedClose the review and capture the current source again. Do not reuse the old approval.
The server path or project folder is invalidUse absolute paths and check the server's required arguments. Request suggestions again.
No suggestionsCheck the source language and project setup. An empty list is a valid server response. An incomplete list is labelled.
A choice cannot be previewedTry another choice. Snippets, indentation adjustment, commands, intersecting edits and edits beyond the planner's limits are refused.
The response exceeds capacityThe native transport accepts less than 65536 bytes per JSON message and at most 4096 parser tokens. JSON escaping can make a draft larger on the wire. This form refuses drafts of 65536 bytes or more before launching. It never truncates the draft or a choice.
The query times out or cannot initializeCheck the server's diagnostics and project setup. The form uses a five-second read budget; a large project may require a future persistent-session workflow. Servers must support UTF-16 positions, completion and document open/close synchronization.

Each planned replacement and expected span is limited to 511 UTF-8 bytes, with at most 64 additional edits. The reusable preview service separately permits complete source and result text up to 16 MiB; the native form has the smaller transport limit above. A server-to-client request that this isolated workflow cannot service stops the query explicitly.

Cancellation is checked between native reads. Starting the child and writing to its input are synchronous and may finish first. Cleanup owns the direct child, not every descendant it might start. The form reports query, document close and shutdown outcomes separately.

Extend the integration

Keep reusable protocol work in UmiLanguageCompletionQueryNative, result construction in UmiLanguageCompletionPreviewCreate, and live editing in UmiDocumentSourceRequestApply. The worker receives copied source and settings. Only the GTK thread follows the editing lifetime token and accesses the document coordinator. A retired binding makes retained controls inert and suppresses worker publication.

Hosts that want settings controls use UmiGtk4AdapterReviewCompletionWithSettings with their application namespace. The original UmiGtk4AdapterReviewCompletion remains a transient form. Portable hosts and tests can supply an absolute settings root. No settings file is stored in the project checkout by default.

For a persistent editor session, use one owning worker, synchronize each document revision, negotiate only implemented capabilities and handle server requests. Preserve the explicit review and document-history boundary when adding those services.
