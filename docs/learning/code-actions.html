Review code actions

Use Resolve missing text edits to prepare deferred actions in their original server session before review.

Use action families to request quick fixes, refactoring, organize-imports or fix-all proposals while retaining complete review.

Choose how diagnostic context arrives

Some fixes need the server's diagnostic data. Select Include fresh diagnostics for fixes to obtain that data within the action request's own connection. The default waits for a notification. Select Use pull diagnostics for fixes as well when the server offers explicit diagnostic requests.

  1. Choose the source scope and both diagnostic options before requesting actions. The pull option has no effect while diagnostic context is unchecked.
  2. Choose Request code actions. All selected drafts are sent first. Framework requests a complete diagnostic report for the primary draft, validates its ranges and includes the relevant original diagnostic objects in the action context.
  3. Select a returned edit-only action and use the normal complete comparison and approval workflow. Diagnostics themselves do not grant permission to edit.

Missing providers, refused or unchanged reports, invalid ranges and unsupported related-document reports stop the action request. Studio does not replace a failed diagnostic capture with an empty context. Changing either diagnostic option retires pending choices and approvals, even if changed back afterward. Captures shown in a separate Problems window are not reused across server connections.

SDK hosts can use UmiLanguageCodeActionQueryNativeWithContext or UmiLanguageCodeActionQueryOnServerWithContext with optional additional sources. Select UMI_LANGUAGE_ACTION_DIAGNOSTICS_NONE, UMI_LANGUAGE_ACTION_DIAGNOSTICS_NOTIFICATION or UMI_LANGUAGE_ACTION_DIAGNOSTICS_PULL. Existing APIs keep their previous contracts. Pull context requires both diagnostic and code-action capabilities, shares one read budget, and preserves opaque diagnostic data only within that connection.

A code action is a change suggested by a language server for the caret or selected source range. Depending on the server and project, choices might include a quick fix, extracting a variable or arranging imports. Studio can review a complete text edit for the current document. The server supplies the proposal; Framework controls its scope, review and application.

Use Actions in Studio

  1. Open a writable source document. Place the caret where help is needed, or select the expression or statements you want to change. A selection can span several lines.
  2. Choose Actions… in the editor toolbar. This captures the current draft and selection without starting a server.
  3. Enter the absolute path to an installed language server, its arguments, and the absolute project folder. Load saved server can reuse preferences for this language.
  4. Choose Request code actions. The selected program receives the captured draft and range. It may read the project folder. The temporary connection closes before Studio displays the result.
  5. Select an action from the searchable list. Read its title, kind and availability. A preferred label records the server's preference; it does not approve the action. Unavailable choices show the server's reason. Choices that require a command or a later resolution request cannot be applied here.
  6. For an available text edit, choose Preview selected action. Review the whole proposed document and its changed ranges. Numbered explanations connect edits to their reasons; read every explanation marked Confirmation required.
  7. Approve the displayed action and all listed confirmation requests, then choose Apply to captured draft. The update has one Undo step. Saving is separate.

Selecting another action or changing server settings retires the previous approval. If the draft, permissions, caret or selection changes, close the form and open it again. A retained Apply control cannot apply an action that was not previewed and approved for this source.

Why some actions remain unavailable

Action formWhat the review does
Complete text edit for the captured documentChecks exact coordinates, required source revision and overlapping changes, then offers a full-text comparison.
Disabled actionShows its reason and refuses edit extraction.
Command, or an edit followed by a commandShows the choice without running it. Applying just the edit would omit part of the requested operation.
Title or opaque data without an edit Needs the explicit Resolve missing text edits option. The default query leaves it unavailable; successful resolution still needs complete review.
Other documents or file create/rename/delete operationsRefuses the complete proposal. It does not apply the current document's portion alone.

Descriptions, titles and explanations are literal text. HTML and Markdown do not execute, and returned command identifiers are not shell commands. Other open unsaved drafts are not synchronized by this request. By default, the outgoing context contains an empty diagnostics list. Select Include fresh diagnostics for fixes to capture and validate a matching publication in the same server session before requesting actions. Diagnostics from a previous connection are never replayed.

Use the Framework service in another host

  1. Capture a document through its owner and copy the complete source before dispatching a worker. Record both selection endpoints as UTF-8 byte offsets.
  2. Call UmiLanguageCodeActionQueryNative. It validates the ordered range, converts both endpoints to UTF-16 and returns an owned catalogue after connection cleanup.
  3. Read metadata with UmiLanguageCodeActionCatalogueAt. Borrowed strings live until catalogue destruction. The original item JSON remains available for inspection, including diagnostics, command arguments and opaque data; retaining those fields does not authorize their execution.
  4. When the user selects an action, call UmiLanguageCodeActionCatalogueReadEdits. This creates a separate workspace-edit catalogue only for a supported, enabled edit-only action. The original catalogue remains immutable.
  5. Use UmiLanguageWorkspaceEditCataloguePreviewSingleDocument when the host owns only one captured draft. Reject the whole proposal if another document is present. Retain and show the annotation requirements.
  6. On the document owner's thread, check the capture again, stage the complete proposed text and apply only its explicitly approved review revision. Destroy both catalogues and the text preview when finished. Do not save as a side effect.

Decoding selected edits on demand avoids reserving a large workspace-edit buffer for every unselected choice. The action catalogue accepts up to 512 choices in a 1 MiB JSON document; title and disabled-reason fields allow 65,536 UTF-8 bytes, while kinds and command identifiers allow 4,096 bytes. Native transport messages have a smaller 65,536-byte envelope limit including escaped source. Studio uses a five-second total read budget with a short extra cleanup allowance.

Troubleshooting

  1. If there are no actions, select a meaningful source range and check the server's project setup. An empty response does not prove that every refactor is supported.
  2. If a proposal is stale, cancel and capture the current source again. Do not transfer approval between different results.
  3. Use the explicit resolution option for deferred text edits and the open-draft scope for supported cross-file proposals. If a command or unsupported operation is still required, use a tool that can complete the whole operation. Never apply a partial proposal as though it were complete.
  4. If startup or response reading times out, inspect the local server configuration and project workload. This action does not create a persistent project index.

Inspect source diagnostics

Include diagnostics for fixes

  1. In Actions, select Include fresh diagnostics for fixes before requesting actions.
  2. The server must publish diagnostics after the captured document opens. Framework checks the source and sends relevant original diagnostic objects back through that same connection.
  3. Review and approve the returned edit as usual. Changing the option retires older results and approval.

This option shares the request timeout and fails if no matching publication arrives. It does not silently fall back to range-only actions. An empty publication is allowed; it does not establish a successful project build.
