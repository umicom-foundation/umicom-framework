Find a configured target or captured position

A filtered list shows part of a captured collection. It keeps the identity of each original item, even when two items have the same label or the visible order changes. Filtering does not change build settings or request market data.

Choose a build target in Studio

  1. Open Build Settings and choose the project, build folder and configuration. If target metadata is missing, use Request target data in this build folder, apply settings, complete Configure, then reopen the form.
  2. Choose Read configured targets. The list comes from that folder's CMake reply.
  3. Type part of a target name or type, such as EXECUTABLE. Choose Original order, Text A-Z or Text Z-A, and optionally Match case.
  4. Choose Apply filter and order. The count describes the applied query. Typing another query does not change the active list until you apply it.
  5. Select a visible target. Inspect its program path, then choose Use selected build target or Use selected program. Review the resulting field and apply settings separately.

If filtering hides the selected item, selection is cleared. No other target takes its place automatically. Clear the query and apply it to restore the whole list. Changing build inputs invalidates the captured metadata; read the targets again before copying a value.

Inspect received positions in Trader

  1. Open Paper / Live broker connections. Confirm the actual login in TWS or IB Gateway and connect using the read-only controls.
  2. Select an authorised account and choose Read selected account once. The account and position responses arrive separately.
  3. Choose Capture received positions for review. This copies observations already received; it sends no broker request. An incomplete or disconnected capture is explicitly labelled.
  4. Filter by symbol, security type, currency, exchange, local symbol, contract ID or expiry. Apply the filter, select a row and read its contract details, quantity and average cost.
  5. For a complete capture that still agrees with the same ready connection, choose Copy selected contract to quote inspector. Check its ID and exchange against TWS Contract Description, then choose Subscribe to quote separately.

Some position responses do not include an exchange. In that case, use TWS Contract Description to fill the quote inspector manually. Combination contracts cannot be copied by this chooser. Copying fields does not validate market-data permissions or place an order. Reconnecting retires the old position review; capture again on the new connection.

What the list means

Matching is literal, not a regular expression. Ignoring case folds ASCII letters only; accented characters are matched by their exact UTF-8 spelling. Sorting compares text rather than financial values. Duplicate labels retain their source order. The filter is limited to 255 UTF-8 bytes, and the shared model accepts up to 32,768 rows, 8,192 bytes per row including its terminator and 16 MiB of text in total.

Provider quantity and cost text is preserved without conversion to floating-point numbers. Captures are historical observations, not a continuously refreshed portfolio. Times are local monotonic milliseconds used to compare observations, not calendar times. Filtering the chooser does not filter the full account report or CSV export.

Recovery and availability

If no rows match, clear the query and apply it. An invalid or oversized input leaves the previous capture active. A failed contract copy leaves quote fields unchanged. If a connection, account or position changes, capture the received positions again. Position controls require Framework's GTK frontend; the smaller standalone broker inspector remains available without them.

Extend the shared component

UmiUiTextProjection owns copied labels and a mapping to original source indices. UmiGtk4FilteredChoicesSelectedSource resolves a visible selection before the application asks its catalogue for data. A source index belongs only to that capture. Keep domain freshness checks in the service that owns the original data, and keep all GTK operations on the UI thread.
