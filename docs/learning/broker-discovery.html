Find instruments with scanners and option chains

A scanner asks the broker for a ranked list of contracts matching a chosen market and filter. An option chain describes available expiries and strikes for an underlying instrument. Neither response is a quote or an order.

Look up scanner parameters

  1. Connect to your local TWS or IB Gateway, then expand Scanner parameter catalogue.
  2. Select Read scanner catalogue. The application requests the broker's current XML parameter document once on this connection.
  3. Enter a scan, location or filter name and select Find next. Search ignores letter case and wraps to the beginning. You can select and copy text from the viewer.
  4. Review the matching entries, then enter the appropriate values in Market scanner. The viewer does not automatically construct a valid subscription.

The catalogue is plain text. It is not executed, and external XML resources are never loaded. A complete document is retained after disconnect and marked stale. Reconnect to request another catalogue after completion, failure or a 60-second timeout. Documents larger than 4 MiB are refused rather than truncated. This viewer does not validate the XML schema or prove that a scan is available for your account.

Before you start

  1. Sign in to your TWS or IB Gateway application and enable its socket API. Review the account mode and permissions in that application.
  2. Open Umicom Trader's broker connection window. Choose the intended Paper or Live profile, confirm the port and connect.
  3. Wait for the connection to report that its read-only API is ready. A profile choice records your intent; it does not attest the account environment.
The connection window observes the broker. Its discovery, chart and report controls do not submit, modify or cancel trading orders.

Run a market scanner

  1. Expand Market scanner. Enter the instrument, location code and scan code you have checked in TWS. The initial stock scan values are an editable example, not a recommendation.
  2. Choose a maximum of 1 to 50 results. Leave optional thresholds blank when you do not want to constrain them. Prices, market capitalisation and coupon thresholds use a dot for the decimal separator; volume thresholds use whole numbers.
  3. For generic filters, enter pairs such as usdMarketCapAbove=10000. Separate multiple pairs with semicolons. Duplicate tags, empty values and separator characters inside values are rejected.
  4. Select Start scanner. A complete refresh replaces the previous ranking together, so rows from two refreshes are never mixed.
  5. Select a ranked result to inspect its broker description. Stop any existing quote stream, then choose Use selected contract ID.
  6. Review the contract details and choose the quote route explicitly. Start a separate quote subscription when you want prices.
  7. Choose Cancel scanner before replacing the panel's scan. Previously received rows remain visible with stale status.

Scan filters and availability depend on the broker and your subscriptions. Umicom does not download the scanner-parameter XML catalogue yet. Check the desired scan in TWS. A fresh local receipt indicates when Umicom received the result, not the age of an exchange price.

Inspect and resolve an option

  1. Use contract discovery to identify the underlying instrument. Put its resolved contract ID in the connection window's Contract ID field.
  2. Expand Option chains. Enter the underlying symbol and security type. Use STK for a stock, IND for an index or FUT for a future when selecting an option to resolve.
  3. Optionally enter a chain exchange filter, then select Request option chains. Wait for the broker's completion marker.
  4. Choose an exchange and trading class from the returned definitions. Choose one expiry, one strike, and Call or Put. Enter the option currency and review the connection window's quote Exchange field; this is the route used for contract resolution.
  5. Select Resolve selected option. The lists describe candidate values: some expiry and strike combinations do not form a valid contract.
  6. Wait for exactly one completed contract match. Inspect its symbol, expiry, strike, right, currency and contract ID. If no match or several matches are returned, review the selection instead of guessing an identity.
  7. Stop an existing quote stream before selecting Use resolved option ID. Explicitly request market data for the resolved option.

Abandon local lookup stops accepting replies locally. The negotiated API has no option-chain cancellation message. Starting another lookup uses a new request ID. A disconnected or incomplete chain is not eligible for contract resolution.

Save discovery records

  1. Enter a new absolute CSV path in the relevant panel, for example C:\Users\YourName\Documents\scanner-review.csv.
  2. Select Write scanner report or Write option definition report.
  3. Wait for the saved status. Existing files are not overwritten; choose another name if the destination already exists.
  4. Import provider text columns as text in your spreadsheet to preserve exact spelling and identifiers. Check the stale, failed, complete and environment-attested columns before interpreting the records.

Scanner reports include query properties, generic filters, ranks and contract descriptions. Option reports contain separate chain, expiry and strike records. They deliberately do not imply that every possible combination is valid. The report owns a frozen copy before the file worker starts; later scanner refreshes cannot alter that copy. If writing fails after a new file has been opened, inspect that partial file and choose another path to retry.

Current bounds and recovery

AreaSupported bound and recovery
TransportThe legacy field protocol is negotiated in the existing supported range. Protobuf sessions are not supported by this connection.
ScannersFramework supports ten subscriptions of up to fifty rows each; the native panel controls one. Local requests are separated by at least one second. Other clients and account-wide broker limits are outside this local pacing rule.
FiltersUp to sixteen generic filters and 511 serialized bytes. Internal-use subscription options stay empty. Numeric thresholds must be exactly representable by the shared decimal owner; an unsupported precision is rejected, never rounded.
Option definitionsOne pending lookup, at most 32 exchange/class/multiplier definitions, 128 expiries and 512 strikes per definition. A response beyond these bounds fails explicitly instead of pretending a truncated chain is complete. Use an exchange filter to reduce large responses.
Timeouts and stale resultsOption discovery waits up to 60 seconds. Scanner results are marked stale in the native panel after 60 seconds without a complete refresh. A malformed result fails the session; retained evidence remains available. Correct the request and reconnect explicitly.
ExportsScanner documents are bounded to 2 MiB; option documents use the shared 4 MiB limit. An oversized export returns a capacity error without exposing a partial document. Narrow the discovery scope and retry.

Extend the shared implementation

Use scanner.h, option_chain.h, option_contract.h and discovery_report.h from the Framework broker-connectivity module. Serialize access on the connection's owning event loop. Request and copy APIs retain their data in Framework; native controls only collect inputs and display copies. When adding another consumer, retain the request ID and scanner generation alongside the selected row.

Add a protocol decoder only after checking the official field order and server-version boundary. Validate complete messages before changing public state. Keep large temporary records on the heap, preserve output values on failed requests, and add injected-transport cases for late replies and queue failures. The current controls do not provide option Greeks, volatility models, multi-leg order construction or a complete OptionTrader replacement.
