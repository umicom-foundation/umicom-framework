Chat about selected code

Studio can copy text you select in the editor into a new chat request. You choose a saved connection and inspect the complete request before sending it. The copied text comes from your current draft, including unsaved edits. Other open files, filenames, paths and conversation history are not added by this workflow.

Prepare a connection

Open AI Coding → Connections and save an enabled connection with a model. The current chat adapters support the official OpenAI Responses or chat-completion destination and a compatible local chat service at its configured numeric loopback address. Follow Chat with saved connections for credentials, request limits, provider policies and transport requirements. Saving a connection does not start a local model or grant provider access.

Choose exactly what to send

  1. Open a source document and select the code you want to discuss. Select at most 8,192 UTF-8 bytes. A byte is a unit of storage; some characters use several bytes, so the character count can be smaller.
  2. Open the AI Coding panel and choose Chat about selected code…. This action captures the active document's selection. Opening AI Coding alone does not capture text.
  3. Inspect Captured context in the Connections window. It is a copy of the selection, not a live link to the editor. Use Clear captured context if you picked the wrong text.
  4. Select the saved connection you intend to use. Save or discard any pending settings draft, then choose Chat with selected saved connection….
  5. The new chat window contains your selection in Optional context. The Connections window clears its copy after a successful handoff. A second chat starts with empty context unless you explicitly capture or supply more text.
  6. Enter a prompt, such as “Explain the ownership of this allocation.” You can edit or remove the context before continuing.
  7. Choose Review request. Read the exact message, destination, model and output limit. For a remote connection, enter your local profile password, then approve the displayed request.
  8. Choose Send reviewed request once. The reply is displayed as text. It does not execute tools or apply edits to your document.

Changing the editor after capture does not refresh the copied context. To discuss newer code, capture a new selection. Changing the context in the chat window invalidates the previous review, approval and password. Review the changed request before sending.

Recover from common problems

  • No selection: return to the active editor, highlight text and choose the action again. A caret position alone does not export the complete file.
  • Selection too large: select a smaller function or explain the surrounding behaviour in your prompt. Text is rejected rather than silently cut off.
  • Invalid text: select complete characters. Unsupported control bytes and malformed UTF-8 cannot be placed in the context field.
  • Chat did not open: the captured context remains visible in Connections. Correct the settings or clear the context before retrying.
  • Saved settings changed: reload the connection and review a new request. The existing approval cannot authorize a different saved configuration.
  • Need to stop: use Cancel. A request already transmitted may still finish remotely. The application does not retry it automatically.

Where the copied text lives

Captured context stays in the local window's memory. It is not stored in the connections database. The panel clears its copy on successful handoff, explicit clearing or retirement. The chat owns its own draft until you clear or close it. Clearing local text cannot erase content already received by a provider. This workflow does not save a local conversation transcript.

The local selection action does not contact a provider, read the clipboard or read a saved source file. A later approved Send transmits the exact reviewed message using the selected adapter. Provider charges and retention policies described in the chat guide still apply.

Extend the shared implementation

UmiUiDocumentViewModelCopySelection captures the selected bytes and source identity while holding the document model's lock. It checks the expected model revision, selection bounds and destination capacity before changing either output. It reads the complete draft owned by the model, so a selection beyond the short display preview remains available.

Thin native applications call UmiProviderConnectionsGtkPresentSelection with an explicitly chosen active view on their document owner's thread. The function borrows that model only while making the copy. It does not keep the editor alive. Direct context producers can use UmiProviderConnectionsGtkSetChatContext or UmiProviderChatGtkSetContext; both validate the copied text before changing the draft. Calling the chat setter while a worker is active returns Busy.

Studio binds the action through its existing weak window owner, so a retained button cannot access a retired workbench. Keep new provider work in Framework, keep source selection explicit, and keep code application behind a separate review step. The existing AI command and agent routes remain available with their existing policies.

Continue with selected earlier text

The chat window can keep up to eight completed exchanges in memory. Select an excerpt from an earlier request or reply to replace the next request's context, then review and approve it again. Follow Choose context for a chat follow-up for history limits, forgetting entries and clearing local copies.
