Compare immutable JSON values

JSON objects can describe the same value using different member order or string escapes. Comparing their raw source text can reject a harmless serialization change. Framework provides an owned-tree comparison for consumers that need to preserve protocol metadata without treating it as executable instructions.

  1. Parse both byte spans with UmiJsonTreeCreate and explicit size, node and depth limits appropriate to your protocol.
  2. Select node zero for the entire value, or obtain a member handle with UmiJsonTreeMember.
  3. Call UmiJsonTreeValuesEqual with both tree owners and node handles. Keep the owners and optional cancellation token alive until return.
  4. Check the status before reading the equality result. Success returns zero or one; failure leaves your output unchanged.
  5. Release each tree after all borrowed views and comparisons are finished.

Objects are compared by decoded member names, independent of order. Arrays keep their original element order. Strings compare decoded UTF-8 bytes without Unicode normalization. Numbers use exact JSON spelling, so 1 and 1.0 differ even though they can represent the same mathematical value. This avoids losing precision when metadata contains large identifiers.

Duplicate names in compared objects return an error. Comparison can stop at an earlier difference, so it is not a whole-document duplicate-key validator. Validate any stronger protocol-wide constraints separately.

Private sorted key tables prevent repeated full-object searches. Temporary memory follows the visited values; recursion follows the parser's bounded container depth. Cancellation is checked between values and key decodes. Sorting and an individual string decode are not interrupted.
