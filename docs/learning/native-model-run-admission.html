Admit a local model before launching

A native application should refuse an unsuitable file before it starts an expensive model process. This lesson follows Umicom's C implementation from a user's selection to a process submission. It also explains why choosing C does not, by itself, make every operation faster or prevent memory errors.

First complete GGUF roles, model lifetimes and bounded memory. A process is a running program. An owner is the part of our program responsible for releasing a resource. Admission means checking whether an operation is allowed to proceed; it is not a claim that the operation has already succeeded.

1. Follow the checks in order

  1. Keep the current session owner intact. If the owner slot is already occupied, a replacement start returns BUSY. Stopping a session is a separate, deliberate operation.
  2. Validate the captured run plan, execution approval, inherited environment profile and selected executable. Do not construct a shell command from model labels.
  3. Acquire the existing cooperative file lease. A lease here is an operating-system handle that cooperating callers use to avoid conflicting model sessions. It does not prevent unrelated programs from editing a file.
  4. Read the selected file through the shared checked reader. Calculate its complete digest and parse its bounded role metadata in that same pass.
  5. Require the reviewed digest to match. Refuse impossible basic counts and any role other than a model candidate.
  6. Only then create the process supervisor and submit its owned process tree. A supervisor tracks the child and provides a controlled stop and cleanup path.
  7. Observe startup and request readiness separately. A submitted process may still fail because of unsupported tensors, incompatible engine behavior, insufficient memory or another runtime error.
Selected path + reviewed digest

Every refusal before submission must release resources acquired by that attempt. It must not overwrite the previous successful observation or discard a usable session.

2. Use the shared C contract

The function is declared in umicom/local_models/manager.h. Applications link Umicom::local_models; they do not implement their own metadata parser. The Framework build must enable UMICOM_BUILD_MODEL_FORMATS for role admission. A selective build without it keeps the older discovery and download APIs but refuses model launch with NOT_IMPLEMENTED.

This fragment assumes that selected_path and reviewed_digest already refer to the user's reviewed selection. It performs no launch:

#include "umicom/local_models/manager.h"

UmiModelInspection candidate = {0};
if (!UmiModelRunInspectionAvailable()) {
    /* Explain that the installed SDK lacks role inspection. */
} else {
    UmiStatus status = UmiModelInspectForRun(
        selected_path, reviewed_digest, NULL, &candidate);
    if (status == UMI_STATUS_OK) {
        /* Publish this complete observation for review.
           This is not proof that an engine can run the model. */
    } else {
        /* Keep the earlier UI observation and show this refusal. */
    }
}

NULL means no optional cancellation token was supplied. A GUI should instead use its existing worker and cancellation service so the interface remains responsive. The operation is blocking: it does not return until the checked read has completed or failed. Keep borrowed input strings and the token alive until the worker has returned.

The expected digest is mandatory and must contain 64 lowercase hexadecimal digits. It can come from reviewed publisher metadata or an explicitly reviewed earlier file observation. Calculating a digest is not proof of a trusted publisher. A byte-identical malicious or incompatible file remains malicious or incompatible.

The function writes its output only on success. It first captures the expected digest, so using previous.sha256 as the input and &previous as the output is supported. Do not free or modify that object concurrently.

An architecture name that is unfamiliar to the engine can still be a metadata candidate. This service does not maintain a universal engine support list. It also cannot freeze a file permanently: the owner must keep the model and executable stable and trusted throughout use.

4. Inspect a file before trying a runtime

  1. Build the current native Framework executable with role inspection enabled. Source edits do not update an older binary automatically.
  2. Use the role-inspection commands on your exact local file. They read the file but do not start an engine.
  3. Compare the role and digest with the model you intended to use. A control-vector file belongs to a separate auxiliary workflow.
  4. Follow the existing local-model lifecycle guide to review a run plan. Current session submission performs admission again so an earlier UI observation cannot replace the launch-time check.
  5. Record the engine version, model identity, context size, thread count and runtime output when you qualify a real launch. A successful inspection alone is not a successful generation.

5. Learn from the regression cases

The following commands run only synthetic fixtures after the owner builds the matching source. Run each line separately from the Framework checkout and stop on error:

Set-Location "C:\umicom\Umicom-Applications\framework"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake --preset windows-ucrt64-debug
cmake --build .\build\windows-ucrt64-debug --target umicom-model-run-inspection-test umicom-model-run-inspection-unavailable-test umicom-model-session-admission-test umicom-model-session-test
ctest --test-dir .\build\windows-ucrt64-debug --no-tests=error --output-on-failure -R "^framework[.]local_models[.](run_inspection|session_admission|session)[.]"

With the default model-format component enabled, this selects 40 cases. A component-disabled build has a different selection: it explicitly verifies that submission is unavailable. A test listing or successful configuration is not an executed pass.

Read tests/local_models/test_session_admission.c. It reads real temporary metadata fixtures and checks real digests, but substitutes inert process and lease boundaries. Its auxiliary-file case must create zero supervisors and submit zero processes. Its candidate case proves only the submission boundary. The existing session fixture separately checks a real finite child process; that child does not perform inference.

  1. Predict which resource exists when role admission fails.
  2. Find the assertion that proves a refused attempt never creates a supervisor.
  3. Explain why the fixture for a missing file expects NOT_FOUND rather than an arbitrary generic error.
  4. Find the test that reuses the digest stored in the output object. Explain why clearing the output first would break it.
  5. Record actual pass, failure and skip counts from your run. Keep them separate from real model qualification.

6. Measure the benefit of native code

C lets the service retain fixed parser state, skip unused metadata directly in input chunks and avoid a second whole-file read. Those are specific design choices. Rewriting orchestration in C without those choices could still copy large buffers, retain models unnecessarily or leak resources. Assembly is useful when a measured operation needs a hardware-specific implementation; it is not required for this metadata policy.

Many Python AI tools already use native libraries for numerical inference. Compare equivalent workloads before attributing a slowdown to Python: use the same model bytes, backend, context size, prompt and hardware. Record idle memory, peak process memory, device memory where relevant, first-result latency and throughput. Repeat load, request, cancel and unload cycles, then inspect retained processes, threads and handles. A high peak is not automatically a leak; memory retained unexpectedly across completed cycles needs investigation.

Continue with bounded allocation ownership and the native AI course. Keep requested buffer limits separate from whole-process or GPU memory limits. This admission service does not impose either of those global limits.
