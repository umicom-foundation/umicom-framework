Read bounded audit history honestly

A coding agent records approvals, provider work, file changes and validation outcomes. Keeping every record forever in memory is not practical. Framework's coding audit log retains the newest 128 records. When a reader is slow, some earlier evidence may already have been evicted.

A sequence cursor identifies the last record the reader accepted. Unlike an array offset, it still has meaning after older entries are removed. UmiAiCodingAuditLogReadSince returns records after that sequence and explicitly counts records that were lost before the reader caught up.

1. Admit a whole group before evicting anything

UmiAiCodingAuditLogAppendBatch accepts at most 128 records. It validates all fixed text fields and checks sequence headroom before moving any retained record. A failure in the second input must not cause the first input to replace old evidence.

#include <umicom/ai_coding_runtime/audit.h>
#include <string.h>

UmiAiCodingAuditRecord records[2] = {0};
strcpy(records[0].task_id, "task.7");
strcpy(records[0].summary, "Approval recorded by the host");
strcpy(records[1].task_id, "task.7");
strcpy(records[1].summary, "Validation requested by the host");
UmiStatus status = UmiAiCodingAuditLogAppendBatch(log, records, 2U);
if (status != UMI_STATUS_OK) {
    /* Existing retention and sequence values are unchanged. */
    return status;
}

The snippet assumes the application already owns log. It stores illustrative observations; it does not approve a patch or run validation. Keep summaries short and exclude prompts, source text, credentials and personal data. Empty task IDs and summaries remain representable for compatibility.

The log assigns sequence numbers. Caller-provided sequence values are replaced. At the maximum 64-bit sequence, further nonempty appends return CAPACITY_EXCEEDED; they do not wrap to zero or evict an existing record. A zero-length batch is a no-op.

2. Read a bounded page

uint64_t cursor = 0U; /* Belongs to this one live log instance. */
UmiAiCodingAuditRecord page[16];
UmiAiCodingAuditRead read;
UmiStatus status = UmiAiCodingAuditLogReadSince(
    log, cursor, page, 16U, &read);
if (status != UMI_STATUS_OK) return status;

/* First show read.missed_records when it is nonzero.
 * Then accept page[0 .. read.count-1] into the consumer's own view. */
cursor = read.next_sequence;

Only advance the cursor after your consumer has accepted the records. If display or export fails, keep the previous cursor and retry. The read is nonconsuming: another reader can maintain its own cursor. The log, page buffer and report must occupy separate storage.

Report fieldMeaning
countNumber of copied records, at most the supplied capacity.
oldest_sequence / newest_sequenceThe retained interval at the time of this serialized call; both are zero for an empty log.
next_sequenceThe last copied sequence, or the supplied cursor when no record was copied.
missed_recordsRecords after your cursor that were already evicted. It is not a failed-operation count.
has_moreMore retained records remain after this page. A later append may add further records even after it becomes false.

3. Work through a retention gap

  1. Append records 1 through 128. The retained interval is 1–128.
  2. Append records 129 through 131. The retained interval becomes 4–131.
  3. Read after cursor 0 with capacity 2. The page contains 4 and 5, missed_records is 3, and next_sequence is 5.
  4. Report that records 1–3 are missing. Do not draw a continuous history line through them or invent their outcomes.
  5. After accepting the page, read after cursor 5. The next page starts at 6, and its missing-record count is zero unless further eviction happened.

A zero-capacity read permits a null record buffer and reports metadata without advancing the cursor. This can preview a gap, but it does not acknowledge or consume that gap. Repeating the same cursor can therefore report it again.

4. Handle invalid cursors and data

A cursor newer than this log's newest sequence returns INVALID_STATE. This often means the application mixed cursors from different logs or reused one after recreating a log. Do not silently reset it and imply the combined histories are complete. End the previous view and explicitly begin a new log instance.

Unterminated input text is refused before eviction. Reads validate the selected retained records before writing the page or report; a refused read leaves both outputs untouched. Historical status, event kind, state, hash and numeric evidence are preserved rather than reinterpreted as permission to perform a new operation.

5. Know what retention does not provide

This service is a bounded memory log. It does not persist records, authenticate a writer, prove that a reported action happened, or make records tamper-evident. Serialize append, read and destruction. Do not access a destroyed log or share its cursor with another instance. Durable audit export and transaction-level guarantees require additional services and qualification.

6. Execute the native regression cases

From the Framework repository in PowerShell, run these commands separately and stop on an error. They use a separate UCRT64 build directory.

$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake -S . -B build/audit-cursors -G Ninja -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe -DBUILD_TESTING=ON
cmake --build build/audit-cursors --target umicom-ai-coding-audit-cursors-test
ctest --test-dir build/audit-cursors -R '^framework.ai.coding-audit-cursors.' --output-on-failure

The 33 authored cases cover cursor gaps, continuation, replacement, unchanged outputs, bounded text, invalid private state and sequence exhaustion. They require no model, network or file mutation. Registration during configuration does not establish that they compile or pass.
