Discover folding regions without changing a draft

Framework separates language discovery from editor presentation. The language runtime owns a checked list of complete source ranges. The document coordinator validates the captured draft before navigation. The GTK folding service hides an explicit selection without editing its bytes.

  1. Include umicom/language_runtime/navigation_query.h and link Umicom::developer. Capture the URI, language, full UTF-8 source and caret before dispatching a worker.
  2. Set the request kind to UMI_LANGUAGE_NAVIGATION_FOLDING_RANGES. Call UmiLanguageNavigationQueryNative with the selected trusted server profile, working folder, timeout and cancellation token. Inputs must remain valid until the call returns.
  3. On success, inspect the owned location catalogue. Every range belongs to the captured URI. Its start is column zero, and its exclusive end is the next line start or the end of source. Input order and duplicates are retained. Destroy the catalogue when finished.
  4. Before selecting a row, recheck the document source request against its live coordinator. Use UmiDocumentCoordinatorOpenSourceRange only after that check. The shared GTK review form already owns this lifetime and stale-result boundary.
  5. Collapse only after an explicit user action. Call UmiGtk4AdapterFoldSelectedCode in a Framework editor host, or UmiGtk4TextFoldSelection with a live native text view. The first selected line stays visible. Reveal behavior remains with the native buffer owner.

Validation and limits

The isolated query advertises complete-line folding and requires the folding capability. It sends document-only folding parameters, closes the captured draft and stops its owned child before publishing a result. It shares the existing native 65,536-byte message bound and parser budget; escaped text can reach the limit before raw source does.

UmiLanguageLocationCatalogueReadFoldingResponse is available to other protocol owners. It validates a correlated response, at most 4,096 regions, 1 MiB of JSON and 16 MiB of UTF-8 source. Negative, fractional, reversed or out-of-source lines fail the complete operation. Optional character positions are validated as protocol integers but ignored for line presentation. Kind and custom label fields must be strings; this API does not publish them. Null and empty-array responses produce an empty owner.

Source coordinates follow the shared editor service, including LF, CRLF and CR line endings. Returned locations own their URIs and metadata. They do not borrow source storage or confer permission to execute a program or open a file. Single-line regions remain visible to reviewers even though the manual presentation service cannot collapse them. Blank final lines contribute no hidden source bytes.

Extending this workflow

Keep future categories, fold-all commands and persistence outside the JSON reader. They need their own selection, document-revision and capacity rules. Do not make a partial response appear complete or reuse a catalogue after its draft changes. The older bounded folding-list decoder remains available for its existing clients; the checked Studio path uses this owned reader.
