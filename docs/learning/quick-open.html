Connect an indexed file picker to a document owner

The GTK Quick Open service presents complete entries from an existing Framework file index. The application keeps ownership of its workspace and documents. The legacy developer search API remains available for bounded display results; this picker does not use display labels as file identities.

  1. Link Umicom::ui_gtk4 and Umicom::developer. Include umicom/ui/gtk4/quick_open.h and umicom/developer_workbench/quick_open_selection.h.
  2. Create host data that records a weak application-window identity, the requested workspace root and revision, and the identity of its existing file index. Do not keep an application controller alive merely because a picker exists.
  3. Implement the read callback. Resolve the current host, reject a replaced workspace or index, then call UmiFileIndexReadPage with the query, offset, expected revision and capacity supplied by the picker. Use case-insensitive matching and copy a coherent page. Do not start filesystem enumeration from this callback.
  4. Implement the open callback. Recheck the host and workspace, call UmiQuickOpenCheckSelection with the exact captured query, page, position and entry, then open the complete path through the existing document owner. The check returns BUSY if the captured index revision or selected record changed. It is not a filesystem lock; handle a later file-open failure normally.
  5. Call UmiGtk4QuickOpenCreate with the parent, callbacks, host data, a destroy function and an output window. Success transfers the host data to the picker. Failure leaves it with you. Present the returned window, destroy it when finished, and release its caller-owned reference.
  6. Keep callback data valid until its destroy function runs. The picker may close during a callback; copied arguments remain valid for that call. Do not free the data inside the callback. Window removal retires pending actions even when a test or accessibility client retains a control.

Selection and lifetime

Typing invalidates previous choices immediately. Repeated typing is coalesced into one idle read, held by a weak window reference. A page is published only if the window and query generation still match. Opening is always explicit. Closed or retained old controls cannot dispatch to a new host.

There are up to 64 complete entries per page and 256 Unicode characters / 1,024 UTF-8 bytes per query. Page validation rejects malformed counts, paths and revisions. Filename labels use plain text. The index folds only ASCII letters for case-insensitive matching so the process locale cannot transform UTF-8 continuation bytes.

Open a source location

Applications can opt into source coordinates with UmiGtk4QuickOpenCreateAt. The original constructor still treats the complete query as a literal filename filter.

  1. Provide an UmiGtk4QuickOpenOpenAt callback. It receives the same checked page and entry as ordinary opening, plus an optional UmiDocumentLocation. Both read and open callbacks receive the filename filter with the coordinate suffix removed.
  2. Keep the workspace and selection checks described above. If the location is non-null, call UmiDocumentCoordinatorOpenAtPosition with the complete selected path, line and column. That operation reads an already-open document’s current draft and records one navigation jump.
  3. Resolve the live application owner again after opening, then reveal and focus the selected editor. A failed line lookup keeps existing drafts and restores the previous active document when it remains available; the opened target tab can remain available for inspection.

For example, main.c:42:5 filters for main.c and requests line 42, UTF-8 byte column 5. main.c:42 uses column 1. Both numbers start at 1. A long column is clamped to the line end; a column inside a multibyte character moves to the character’s first byte. Quote a filter containing a literal colon: "notes:12":4. Absolute Windows drive prefixes are retained. Incomplete or invalid coordinates disable opening until the input is corrected. Parsing never opens a file and is also available without GTK through UmiQuickOpenQueryParse.

Extending the workflow

Add ranking or different matching through an explicit index/query contract, preserving the captured query and complete path identity. Keep file loading and draft preservation in the document owner. A background filtering design would need its own index lifetime and cancellation contract; the current picker filters the existing in-memory index on the UI thread.
