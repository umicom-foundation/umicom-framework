Sources, drafts and responsible checking

Keep the sources behind an AI draft

Inspect the passages, preserve the selection and return to the exact text a draft was given.

Build a small Umicom Notes knowledge collection and learn the difference between a reference that exists and a statement that is supported.

Start with a question you can check

You have asked an assistant how to save a note. Its answer looks sensible and ends with [S1]. What does that mark actually prove? It tells you which supplied passage to inspect. It does not prove that the sentence before it is correct.

In this lesson you will supply two short pages from a fictional Umicom Notes handbook. You will inspect the search results, keep that exact selection for a draft, and then follow each source reference back to its saved text. Finally, you will amend one passage and see why an old answer must not silently acquire a new source.

Three different jobs. Retrieval chooses useful passages. A provider produces a draft. A person checks whether the draft is supported. Umicom records these stages separately.

The first exercise runs entirely in memory with the labelled Extractive preview (not an LLM). It copies from the supplied references; it is not a learned language model. An optional later exercise uses your separately prepared local model server. Nothing is downloaded or started automatically.

You need the matching Framework source and a working native build. Windows and the graphical steps are local acceptance exercises: the delivery’s headless checks do not establish that your installed GUI or model works.

Learn the five names used in the window

NameWhat it means here
CollectionA named group of source passages, such as the Notes handbook.
PassageA selected piece of text, with its own stable ID, title, original line label and revision.
JobA saved request: provider, model label, prompt, supplied passages and review state.
Frozen evidenceThe exact passage copies supplied to that job. Editing the current handbook does not replace them.
InspectionA read-only snapshot of a job, its literal references and comparisons with currently loaded sources.

A revision is a counter describing a saved state. The corpus revision changes when its collection of sources changes. A source has its own revision too. These numbers help detect stale work; they are not signatures or authenticated user identities.

The current source is the passage now loaded in the workspace. The original file is a different thing. This lesson pastes text; the program neither opens that original file nor proves that your line labels match it.

1. Run the complete memory lesson

After merging the batch, build your Applications workspace using the accompanying Build-and-Git instructions. Open PowerShell in the repository and run:

PowerShell
Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
$Tool = ".\build\windows-ucrt64-all-debug\bin\umicom-ai-evidence.exe"
& $Tool --self-test
if ($LASTEXITCODE -ne 0) { throw "The memory lesson failed." }

The expected output is:

Expected output
Selected passages: 2. Reference targets exist; prose still needs checking.
One source changed. The saved citation still resolves to the frozen passage.
Practice complete. Extractive preview, not model inference; no network, files or tools were used.

This is a real native workflow through Framework’s memory Data Server, source search, saved job, approval, extractive provider and evidence inspection. It is not a test of a neural model. The program closes the source services before copying a line from the retained inspection, which also checks its memory ownership.

Run & $Tool demo to print the inspection as well. The command writes to the console, not to a report file. Do not confuse a successful demonstration with a successful full application test suite.

2. Give the graphical exercise its own workspace

Use fictional text, not customer records, passwords or private trading data. Close any existing RAG instance, then launch a new one with a practice database path:

PowerShell
$env:UMICOM_AI_WORKSPACE_DB = Join-Path $env:LOCALAPPDATA "umicom\ai-workspace\evidence-practice.sqlite"
& ".\build\windows-ucrt64-all-debug\bin\umicom-rag.exe"
if ($LASTEXITCODE -ne 0) { throw "RAG exited with an error." }

The application creates its parent directory when needed and reuses an existing database at that location. It does not erase an earlier practice session. Inside the application choose AI workspace and check the displayed path before entering text. Existing layouts remains available beside it.

The same shared AI workspace adapter serves LLM and AI Creator. This lesson uses RAG because its Sources page is the natural starting point. Changing the product does not create a second implementation of retrieval or evidence inspection.

After closing the practice application, remove the temporary setting from this PowerShell session:

PowerShell
Remove-Item Env:UMICOM_AI_WORKSPACE_DB -ErrorAction SilentlyContinue

That command removes only the environment setting. It does not delete the database.

3. Add two short handbook passages

Open Sources. Set Collection ID to notes and Collection name to Umicom Notes handbook. Choose Save collection.

For the first passage, enter save as its ID, Saving a note as its title, and 10 as its first source line. Paste the following text and choose Save passage:

Passage: save
Save checkpoint commits the current note.
Closing without saving discards the draft.

For the second passage, use ID review, title Checking a draft, and first source line 30:

Passage: review
Read the source passage before using a draft.
A citation alone does not prove the answer is correct.

Choose Save passage again. The catalogue should show two sources in the Notes collection. Last-line labels are calculated from the pasted text. There is no need to pad a passage with blank lines merely because it originally began at line 30.

Saving the same ID later replaces its current version, rather than creating a second ID. Historical jobs retain their original copies. Keep IDs stable when you are deliberately editing the same source.

4. Inspect retrieval, then preserve its order

In Search question, enter saving draft and choose Inspect retrieval. This uses the existing lexical search and contacts no model. Read both displayed passages, not merely their ranking scores.

The result text explains how many of the first displayed passages will be retained. The graphical selection is bounded to the first four, or fewer when fewer are found. It is not a new per-row checkbox selector.

Go to Drafts and review, choose New job, select Grounded draft, and keep Extractive preview (not an LLM) with model ID extractive-preview. Use the question:

Drafting instruction
Explain how to save and check a note. Cite the supplied sources.

Choose the new Prepare inspected results button. This freezes the copied results in their inspected order; it does not run another search using the differently worded drafting instruction. The first supplied passage becomes [S1], the second becomes [S2].

The earlier route remains. Prepare for review still performs the existing automatic lexical selection. Choose that button when you deliberately want that behaviour. The new button is the explicit route for keeping the inspected result set.

Do not edit a source between inspection and preparation and expect the old results to be accepted as current. A changed corpus revision is refused. Inspect again and review the new text. The same public C interface can accept canonical hybrid or reranked results, but the GUI search in this lesson remains lexical.

5. Review, approve and run the saved request

Read the Frozen request, source references and returned draft area. Check its prompt, provider, model label and passages. Editing a form after a job has been prepared does not silently rewrite that saved job. Use a new job for changed inputs.

Choose Approve selected job, then Run approved job. The writer and reviewer labels are local records of a decision, not authenticated accounts. Opening a page or inspecting a result is not approval.

The extractive response is deliberately limited. It shows the evidence path without suggesting that an LLM was invoked. Check that the saved state says the operation succeeded; a failed, cancelled or unfinished job is not an answer merely because a text box contains earlier content.

The existing running-job controls remain: source edits are paused while the worker runs, cancellation is explicit, and the owner joins that worker before releasing its services. This batch does not introduce an unattended agent or a new background writer.

6. Follow references to their frozen passages

Open the new Evidence inspection page and choose Inspect selected job evidence. The selected job is the one prepared or loaded on the Drafts page. Inspection does not approve, run or alter it.

The report shows the saved prompt, requested provider/model, loaded workspace revision, prepared and current corpus revisions, returned-output state, reference counts, source status, frozen text and literal reference locations. A length-limited response stays labelled as length-limited.

Read a claim in the returned draft, find its [S1] or [S2] marker, and compare the claim with that passage. Ask: does the passage actually say this? Has the draft added an assumption? Is important context missing?

Report resultInterpretation
Known referenceThe numbered source exists in this job. Its statement still needs checking.
Unknown sourceThe marker names a source that was not supplied.
Malformed referenceA literal marker is incomplete or outside the supported syntax.
Not citedA supplied passage has no recognised reference in the response. That alone does not prove the answer is wrong.
No response presentThere is no successful retained draft to inspect. A pending job can still show its supplied sources.

Offsets count UTF-8 bytes from zero, not visual columns. A non-ASCII character can occupy several bytes. The scanner reads literal markers even inside quotes or code blocks; it does not claim to understand Markdown or sentence meaning. Legacy [S01] remains resolvable but is flagged as noncanonical.

7. Change a source without rewriting history

Return to Sources and save passage save with this replacement text:

Replacement passage
The current handbook has been amended; inspect the saved source version.

Keep its ID and first line, then inspect the earlier completed job again. The report now labels that source Changed since preparation. Its old text remains under the frozen citation. The replacement appears separately as Current comparison only (NOT the cited passage).

Removing the current passage instead marks it removed from the loaded workspace. The saved source copy remains in the earlier job. That is useful history, not permission to keep using an outdated answer.

The inspection is itself a snapshot. Press the inspection button again for newer loaded state. When another application changes the shared database, use Reload shared workspace first. Inspection does not silently reload a database or repair corruption.

A job that has not run may be refused after any corpus change. Create and review a new job against the new source state rather than bypassing that check.

8. Make a separate, explicit local-model request

This optional exercise needs a compatible inference server and model that you have already obtained and reviewed. This delivery includes neither. Check that your Umicom build reports Local HTTP transport compiled. AUTO leaves it unavailable when the development dependencies are absent; ON makes them an explicit configure requirement.

The existing provider sends a bounded, non-streaming request to /v1/chat/completions on 127.0.0.1. The upstream llama.cpp server documents that endpoint and served model naming; use the model identifier actually returned by your selected server, or its configured alias. Consult the official server reference for your version.

With your reviewed server already listening on port 8080 and serving the identifier local-model, run:

PowerShell
& $Tool local --port 8080 --model local-model --acknowledge-local
if ($LASTEXITCODE -ne 0) {
    throw "The local model request failed or was unavailable. No automatic retry."
}

This sends only the example’s built-in fictional passages and prompt. It does not scan your repository, launch a server, download a model or submit a tool request. The CLI uses a ten-second deadline; a cold or slow model may time out. Wait for your server to be ready before testing. Exit 77 means unavailable, not a pass.

For the graphical route, the existing UMICOM_AI_WORKSPACE_PORT environment setting selects the port before the application starts. Choose Configured local model, set its actual model ID, prepare a new job, review and run it. The existing graphical provider uses a thirty-second timeout.

Inspect what comes back. A valid response and existing citation targets do not demonstrate that a learned model followed its evidence. No real model was run in the delivery tests. The native local HTTP tests use an inert C peer and establish transport/error handling only.

9. Read the complete C lesson

The file framework/examples/ai_evidence/lesson.c is the complete implementation used by the tool. It allocates the runtime and bounded results, creates sources, searches, prepares the exact selection, approves, runs and inspects. A single cleanup path releases the owned objects.

Notice the order near the end: the workspace and Data Server close before a line is copied from the review. That works because the inspection owns its text. A borrowed pointer into the closed workspace would not have that lifetime.

C23 · complete lesson.c
/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/ai_evidence/lesson.c
 * PURPOSE: Follow selected Notes passages through review, generation and source change.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "lesson.h"
#include "umicom/ai_workspace/providers.h"
#include <stdlib.h>
#include <string.h>

UmiStatus UmiAiEvidenceLesson(FILE *output, bool verbose, bool local, uint16_t port, const char *model)
{
    UmiDataServer *data = NULL; UmiAiWorkspace *workspace = NULL;
    UmiAiWorkspaceCancellation *cancellation = NULL; UmiAiEvidenceReview *review = NULL;
    UmiAiRuntime *runtime = calloc(1U, sizeof *runtime);
    UmiAiWorkspaceEvidence *selected = calloc(UMI_AI_WORKSPACE_MAX_EVIDENCE, sizeof *selected);
    char *report = calloc(UMI_AI_EVIDENCE_REPORT_CAPACITY, 1U);
    UmiStatus status = UMI_STATUS_OUT_OF_MEMORY;
    if (runtime == NULL || selected == NULL || report == NULL) goto cleanup;
    umi_ai_runtime_init(runtime);
#define STEP(expression) do { status = (expression); if (status != UMI_STATUS_OK) goto cleanup; } while (0)
    STEP(umi_data_server_create_memory(&data));
    STEP(UmiAiWorkspaceCancellationCreate(&cancellation));
    UmiAiProvider provider = {0};
    STEP(local ? UmiAiWorkspaceLocalProviderCreate(port, 10000U, cancellation, &provider) :
        UmiAiWorkspaceExtractiveProviderCreate(&provider));
    status = umi_ai_provider_registry_add(&runtime->providers, &provider);
    if (status != UMI_STATUS_OK) {
        if (provider.destroy != NULL) provider.destroy(provider.instance);
        goto cleanup;
    }
    STEP(UmiAiWorkspaceCreate(data, runtime, "notes.lesson", &workspace));
    STEP(UmiAiWorkspacePutCollection(workspace, "notes", "Umicom Notes handbook"));
    STEP(UmiAiWorkspacePutSource(workspace, "save", "notes", "Saving a note",
        "Save checkpoint commits the current note.\nClosing without saving discards the draft.\n", 10U));
    STEP(UmiAiWorkspacePutSource(workspace, "review", "notes", "Checking a draft",
        "Read the source passage before using a draft.\nA citation alone does not prove the answer is correct.\n", 30U));
    UmiAiWorkspaceSnapshot snapshot;
    STEP(UmiAiWorkspaceSnapshotRead(workspace, &snapshot));
    size_t count = 0U;
    STEP(UmiAiWorkspaceSearch(workspace, "notes", "saving draft", NULL, NULL, NULL,
        selected, UMI_AI_WORKSPACE_MAX_EVIDENCE, &count));
    if (count != 2U) { status = UMI_STATUS_INTERNAL_ERROR; goto cleanup; }
    const char *providerId = local ? "umicom.local-chat" : "umicom.extractive-preview";
    const char *modelId = local ? model : "extractive-preview";
    STEP(UmiAiWorkspacePrepareEvidence(workspace, "lesson", providerId, modelId,
        "notes", "Explain how to save and check a note. Cite the supplied sources.", "writer",
        256U, snapshot.corpusRevision, selected, count));
    STEP(UmiAiWorkspaceReview(workspace, "lesson", "reviewer", true));
    STEP(UmiAiWorkspaceRun(workspace, "lesson", cancellation));
    STEP(UmiAiEvidenceCapture(workspace, "lesson", &review));
    UmiAiEvidenceSummary summary;
    STEP(UmiAiEvidenceSummaryRead(review, &summary));
    if (!summary.hasResponse || !summary.referenceBindingsValid) { status = UMI_STATUS_INTERNAL_ERROR; goto cleanup; }
    if (verbose) { STEP(UmiAiEvidenceFormat(review, report, UMI_AI_EVIDENCE_REPORT_CAPACITY, NULL)); fputs(report, output); }
    fprintf(output, "Selected passages: %zu. Reference targets exist; prose still needs checking.\n", summary.sourceCount);
    UmiAiEvidenceDestroy(review); review = NULL;
    STEP(UmiAiWorkspacePutSource(workspace, "save", "notes", "Saving a note",
        "The current handbook has been amended; inspect the saved source version.\n", 10U));
    STEP(UmiAiEvidenceCapture(workspace, "lesson", &review));
    STEP(UmiAiEvidenceSummaryRead(review, &summary));
    if (summary.changedSources != 1U) { status = UMI_STATUS_INTERNAL_ERROR; goto cleanup; }
    /* Reports own their copies. Close all services before demonstrating that
     * an old citation still resolves to its original text. */
    UmiAiWorkspaceDestroy(workspace); workspace = NULL;
    umi_data_server_destroy(data); data = NULL;
    for (size_t i = 0U; i < summary.sourceCount; ++i) {
        UmiAiEvidenceSourceCheck source;
        STEP(UmiAiEvidenceSourceAt(review, i, &source));
        if (strcmp(source.frozen.id, "save") == 0) {
            char line[160]; STEP(UmiAiEvidenceCopyLines(review, i, 10U, 10U, line, sizeof line, NULL));
            if (strcmp(line, "Save checkpoint commits the current note.\n") != 0) { status = UMI_STATUS_INTERNAL_ERROR; goto cleanup; }
        }
    }
    fputs("One source changed. The saved citation still resolves to the frozen passage.\n", output);
    fputs(local ? "Practice complete. One explicitly requested local model call; no tools or source files were executed.\n" :
        "Practice complete. Extractive preview, not model inference; no network, files or tools were used.\n", output);
cleanup:
    UmiAiEvidenceDestroy(review); UmiAiWorkspaceDestroy(workspace);
    umi_data_server_destroy(data);
    if (runtime != NULL) { umi_ai_runtime_destroy(runtime); free(runtime); }
    UmiAiWorkspaceCancellationDestroy(cancellation); free(selected); free(report);
    return status;
#undef STEP
}

The public header documents each ownership and error rule. Request construction now uses a private candidate: an invalid later passage leaves the caller’s previous request untouched instead of publishing a half-built request. This is a general C programming technique for failure-atomic output.

The installed-client project is another small complete example. It links Umicom::ai_workspace through find_package(UmicomFramework CONFIG REQUIRED) and uses public headers only. Its result says that two reference targets exist; it deliberately makes no claim about the truth of those statements.

When the result is not what you expected

ObservationNext check
No inspected passagesSave the correct collection and sources, check Collection ID, then run Inspect retrieval. Stop-word-only questions are not useful lexical searches.
State changed or busyA source or corpus changed. Reload when another window wrote the database, inspect again and prepare a new job.
The job ID already existsUse New job for changed prompt, model or selection. An existing ID is not a mutable draft slot.
HTTP transport unavailableCheck configure output and curl/json-c development availability. The offline preview remains a separately labelled option.
Model mismatch or malformed responseCheck the actual server identifier and compatible non-streaming response. Do not treat a fixture or substituted response as inference.
Capacity exceededReduce the passage/response/selection size. No apparently successful truncated inspection is substituted.
Old text in the evidence pageIt is a captured report. Inspect again for current loaded state; reload first when another application changed storage.

Keep personal details out of shared logs. Reports can contain every supplied passage and the whole retained draft. This feature does not add automatic redaction, encryption or telemetry.

Exercises and answers

  1. Change the drafting question after inspecting retrieval. Prepare with the new button. Which passages are retained?
  2. Change a passage before preparation. Should the old inspection still be accepted as current?
  3. Inspect a pending job. What can the report show without a successful response?
  4. Inspect a completed job after source removal. Should the citation silently point to another source?
  5. Consider “The notebook is encrypted [S1]”. Does a known marker establish encryption?
  6. Read the cleanup code. Which object owns the saved passage after the workspace closes?
Compare your answers

1. The inspected ordered copies, not results from another lexical search. The changed prompt is independently saved and reviewed.

2. No. The corpus/source checks reject a stale selection; inspect and review again.

3. The frozen request, supplied passages, revisions and current-source comparisons. There is no successful returned draft yet.

4. No. The frozen original remains available and its current source is marked removed.

5. No. Read the source. A numbered target can exist while the claim is unsupported.

6. The immutable evidence review owns its copied text. Destroy it only after all readers finish.

The boundaries of this lesson

The current workspace supports 16 collections, 64 sources, 32 jobs and four passages per grounded job. A passage or prompt is limited to 1,535 UTF-8 bytes, a returned draft to 2,047 bytes, and an inspection to 128 literal references. The formatted report reserves 32,768 bytes including its terminator. These are explicit capacities, not an invitation to truncate inputs silently.

The existing C provider, Data Server and job lifecycle are reused. There is no new model downloader, learned embedding engine, persistent vector index, large-file importer, autonomous editor or generation of images/audio in this update. Earlier scripts and examples remain alternatives; the new feature and primary fixtures are native C.

The available automated evidence covers native execution, real local HTTP transport against an inert fixture, ownership, failure atomicity and SQLite reload. Windows, GTK and a genuine neural-model run need their own acceptance results. Build the whole Applications tree and exercise installed products before treating a focused test as release qualification.

For developer contracts read docs/development/ai-evidence.md. For residual risks read docs/development/ai-evidence-risk-review.md. The separate Build-and-Git document contains the full build, test and publication sequence.
