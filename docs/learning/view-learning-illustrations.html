View learning illustrations

A learning pack can contain a diagram as well as its written explanation. The native learning catalogue opens explicitly selected PNG resources through Framework's shared Media decoder. The catalogue verifies the file against its manifest before decoding it. This detects a changed file; it does not authenticate its author.

Open an image

  1. Open the local learning catalogue in your application. Choose the absolute folder containing the pack's learning-pack.json and select Load learning pack.
  2. Search for the illustration's title or topic, choose its result and select Open selected. Alternatively, open a guide and explicitly follow its local link to the declared image.
  3. Wait until the request completes. A supported PNG appears in a bounded viewing area. A message identifies a format, size or decoder limitation when pixels cannot be shown.
  4. Use Back and Forward to move between previously opened resources. Reading an image does not copy, edit, execute or upload it.

Inline HTML images still appear as alternative-text descriptions in structured reading. An HTML img element does not start a second file read. Add a visible link such as <a href="diagram.png">Open the diagram</a> when readers should be able to inspect the pixels separately.

Prepare a diagram for a pack

  1. Export a static, noninterlaced PNG. Put it inside the pack folder. Use an ordinary relative name such as diagram.png; avoid parent-directory components and encoded addresses.
  2. Give it an accurate title and a written explanation. The resource title supplies the native image's accessible description. Explain important relationships in the accompanying guide as well; a short title alone cannot describe a complex diagram.
  3. Compute the file's SHA-256 digest after its final edit. For example, PowerShell's Get-FileHash -Algorithm SHA256 .\diagram.png reads the bytes and prints a digest. Store the 64 hexadecimal characters in lowercase in the resource's sha256 field.
  4. Declare the file as a resource with kind set to image. Its path is relative to the pack root. Keep the existing pack identity, supported Framework range and other required manifest fields.
  5. After changing the diagram, publish a new pack revision with matching file digests. Readers who already hold an older admitted revision keep that revision until they explicitly choose the new one.
{
  "id": "reader-ownership-diagram",
  "title": "Verified source becomes an owned reading view",
  "topic": "ownership",
  "kind": "image",
  "path": "diagram.png",
  "sha256": "REPLACE_WITH_THE_ACTUAL_64_CHARACTER_LOWERCASE_DIGEST"
}

This is a resource fragment, not a complete manifest. The digest placeholder is deliberately invalid: replace it with the value calculated from your own file. The existing examples/learning_pack_inspector project demonstrates a complete generated pack.

Know the limits

BoundaryCurrent behavior
Source resourceThe native reader admits at most 1 MiB for one file.
Decoded imageAt most 2,048 pixels on either side and 1,048,576 pixels in total. Both limits apply before pixel allocation.
FormatStatic, noninterlaced PNG when the optional decoder is available. Palette, grayscale and transparency are expanded to RGBA. Sixteen-bit channels are reduced to their high eight bits.
Colour and metadataSource sample values are displayed without ICC or gamma conversion. EXIF rotation and animation are not applied. This is a learning illustration viewer, not a colour-critical proofing tool.
Unsupported resourcesJPEG, SVG and other formats receive a limitation notice. They are not sent to an external application automatically.
LifetimeDecoded pixels cross the worker boundary as immutable owned bytes. The native texture retains them after the worker job ends.

Understand a refusal

  • Verification failed: the bytes no longer match the admitted manifest. The previous verified reader remains available. Review the file and pack revision; do not change a digest merely to suppress an unexplained error.
  • Optional decoder unavailable: the catalogue was built without the Media PNG service or without its required native decoder features. Ask the application builder to include that capability. Reopening the file cannot install it.
  • Image too large: export a smaller diagram. A 2,048 by 2,048 image exceeds the total-pixel limit even though each side meets the individual limit.
  • PNG could not be decoded: a valid manifest hash does not imply a valid image format. Export a fresh static PNG from the original diagram and review a new pack revision.
  • Memory allocation failed: the candidate is not published. The previous reader and navigation history are retained; close other work before deciding whether to retry.

Connect the shared service

Applications link the existing Umicom::learning_catalogue_gtk4 target. When both native learning and Umicom::png_image are composed, Framework connects them through cmake/UmicomLearningPngGtk4.cmake. The application does not implement another PNG decoder.

UmiLearningCatalogueGtk4PngAvailable() reports the included capability. After a completed read, UmiLearningCatalogueGtk4CopyIllustration() copies the selected image's status and dimensions. Its successful return means metadata was copied; inspect status and has_pixels before claiming pixels were rendered. Calling it for a text selection returns UMI_STATUS_NOT_FOUND without changing caller output.

Decoding happens on the reader's worker. Widget and texture publication happens on the GTK thread. Closing the catalogue retires it, so late work cannot populate a disposed panel. A synchronous notification can inspect the current image metadata; a new mutating operation remains busy until publication ends.

Open an illustration described by a guide

A structured guide can contain an HTML image reference such as <img src="diagram.png" alt="Record ownership flow">. Its description stays in the reading text. The image bytes are not fetched automatically.

  1. Open the guide and expand Reading controls.
  2. Choose an entry under Illustrations described in this guide. The row shows the description and its source reference. Merely selecting a row does not navigate.
  3. Choose Open selected illustration. The source must resolve to an image resource in this reader's admitted manifest. Its verified bytes then use the existing bounded PNG decoder when available.
  4. Use Back to return to the guide. The guide's illustration list returns with its own reading model.

A missing, empty, duplicated or oversized source attribute leaves the description readable but has no usable target. A remote address, an undeclared file, parent traversal, a fragment or a target declared as a guide/example is refused before a read starts. There is no automatic choice between two conflicting source attributes.

These controls do not place image pixels inside each paragraph. They open one explicitly chosen image in the bounded illustration viewport. Inline SVG, scripts, remote images and general page layout remain unsupported. An absent PNG decoder still produces the verified-image notice; it must not be reported as a rendered picture.

Source and SDK entry points

UmiBrowserReadingDocumentImageAt copies an image's inert source, alternative-text range and source status. The number of entries is summary.image_descriptions, bounded by the existing 512 semantic ranges. Native applications use UmiLearningCatalogueGtk4ReadingImageAt for inspection and UmiLearningCatalogueGtk4OpenReadingImage only after an explicit action. The latter resolves against the displayed reader's owned pack, so a newer catalogue entry cannot silently change the image policy for an older open guide.
