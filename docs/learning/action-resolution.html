Resolve complete action proposals in their original session

A deferred code action carries provider-owned identity before it carries an edit. That identity may depend on the live language-server process and synchronized drafts. Framework therefore resolves explicit requests before closing their original source query, rather than replaying data into a new connection.

  1. Prepare the normal UmiLanguageCodeActionRequest and UmiLanguageCodeActionQueryOptions. Options compose the action family, diagnostic context and additional captured sources.
  2. Call UmiLanguageCodeActionQueryNativeWithResolution, or the corresponding OnServerWithResolution entry point for an exclusively owned starting server. Supply a maximum action count between 1 and 32.
  3. The query advertises edit resolution and data preservation, requires codeActionProvider.resolveProvider, opens the captured sources and obtains the original action list.
  4. All actions are validated, then filtered. Count enabled actions without an edit or required command before sending any resolve requests. If that count exceeds the selected limit, the request fails completely.
  5. Send each complete original eligible action through codeAction/resolve. A reply may add only its edit object. Every other field must retain its value, including diagnostics, data and unknown extensions.
  6. Publish the complete catalogue only after every required resolution, document close and shutdown succeeds. The total read deadline is shared with initialization, diagnostics and action discovery.
  7. Decode the explicitly selected edit and use the document source-review owner for exact ranges, revision checks, complete comparisons, confirmations and approval. Resolution itself performs no edit or save.

Standalone response ownership

UmiLanguageCodeActionCatalogueWithResolvedResponse creates an independent replacement catalogue. It validates the response identifier and immutable metadata without launching a process. The original catalogue and its borrowed views remain unchanged. The result owns complete selected and unselected rows. Failure clears the output.

Identity comparison accepts reordered object fields and equivalent escaped Unicode strings. Arrays remain ordered, and number spelling must remain exact: opaque identifiers are never compared through floating-point conversion. Duplicate keys in compared objects are refused. Resolution bounds action fields to 256, field names to 4096 UTF-8 bytes and the complete catalogue to one MiB. Native message limits may be smaller.

Extend without bypassing review

Compatibility query functions do not advertise resolution. Keep future resolved properties behind explicit capabilities and validate their full meaning before adding them. Do not extract an edit from an edit-and-command action as though the operation were complete. Do not cache process-owned data across shutdown or accept source coordinates as evidence of a current revision.
