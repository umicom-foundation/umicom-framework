Review changes to your source library

A source library contains the text passages used to answer grounded questions. When a notice changes or a document becomes outdated, update the passages used by future searches while keeping the evidence behind earlier answers. Umicom RAG, LLM and Creator use the same Framework service for this work.

Replace saved passages

  1. Open the application’s AI workspace and select Review source changes.
  2. Choose Refresh saved passages. This shows the current workspace’s passage IDs, collection, title and source line ranges. If another application changed the database, first use Reload shared workspace.
  3. Select exactly the passages you want to replace. Use Ctrl to select individual rows or Shift for a range. A matching title or ID prefix does not automatically select a whole document. Unselected passages remain in the library.
  4. Choose Replace selected passages. To start from saved text, select Copy selected text to editor. It joins the selected texts in displayed order without adding separators. Check that this order matches the document; individual sources may need separating line breaks.
  5. Enter the destination collection ID and name, replacement document ID and title. An existing collection needs its exact saved name. For a new collection, both fields are saved with the replacement. The replacement ID creates passages such as notice.part.1. You may reuse IDs of selected passages. An ID belonging to an unselected passage causes an error.
  6. Edit or paste the complete replacement text. This is a document replacement, so its line numbers start at 1. UTF-8 validation, byte limits, line-ending normalization and passage splitting follow the document import rules.
  7. Select Preview complete source change. Read every BEFORE passage and every AFTER passage, including their IDs, collection, title and line ranges. The preview is complete; it does not replace storage yet.
  8. Select I approve exactly the source changes shown above, then Apply reviewed source change. All selected removals, replacement passages and any new collection commit together.
  9. Refresh the list and run a new search from Sources. Future searches use the new text. Refresh and preview again before making another change.

For example, an imported notice may occupy notice.part.1 and notice.part.2. Select both when replacing the whole notice. If the new text fits one passage, only the reviewed replacement notice.part.1 remains. Selecting only the first passage leaves the second untouched and can cause an ID collision if the replacement also needs notice.part.2.

Remove sources from future searches

  1. Refresh the list and select exactly the passages to remove.
  2. Choose Remove selected passages from search. Replacement fields and editor text are ignored for this operation.
  3. Preview the complete change. The preview lists the affected BEFORE passages and has no AFTER passages.
  4. Approve and apply. Refresh the list to confirm the selected passages are absent. Empty collections are retained.

What happens to earlier answers?

Saved jobs retain their copied source text, source revisions, original request and response. Updating or removing a live source does not rewrite those citations. Use Evidence inspection to compare a saved job’s sources with the current library. It can distinguish a changed source from one that has been removed.

Removal from search is not secure erasure: the old text can remain in saved jobs, database history or backups. The source-review controls follow Framework’s private recording policy, but this is not database encryption. No file is overwritten, no provider is contacted and no model is run by these source changes.

When a change cannot be applied

  • Workspace changed or busy: a job, passage, collection or external writer changed the saved revision, or work is running. Wait for the work to finish, reload if necessary, refresh the list and review again. The old preview is never applied to a different revision.
  • Identifier collision: inspect which unselected passage owns the proposed ID. Select it only if you also intend to replace its content, or choose a different replacement document ID. Do not assume all similar IDs belong together.
  • Capacity reached: the shared workspace supports 64 saved passages. Selected passages release their places within the same transaction, so replacement can succeed even when the library is full. The remaining passages plus the replacement must fit. The complete change is refused if it does not fit.
  • No approval: read the preview and select the approval checkbox. Editing any selection, operation or replacement field revokes the old approval.
  • Storage failure: the transaction rolls back rather than publishing part of a replacement. Resolve the storage problem, reload and inspect the library before retrying. If the window closed after the change committed, inspect saved sources before repeating the operation.
  • Identical replacement: the reviewed operation succeeds without creating a new revision or discarding cached embeddings. The persisted workspace is still checked for an intervening writer.

Extend the shared service

Include umicom/ai_workspace/source_change.h. Prepare a replacement with UmiAiWorkspaceSourceReplacementCreate or a removal with UmiAiWorkspaceSourceRemovalCreate, supplying explicit source IDs. The service copies the selected sources and complete replacement. Inspect its summary and every before/after record, then call UmiAiWorkspaceSourceChangeApply only after approval.

Keep the borrowed workspace alive and use its owner thread. Destroy unused captures with UmiAiWorkspaceSourceChangeDestroy. A successful capture is consumed and cannot be applied twice. The existing Data Server owns persistence and stale-writer checks; new interfaces should reuse that boundary. Existing single-passage APIs remain available for callers that already use them.

The examples/ai_source_change_main.c source demonstrates selection, preview and explicit application using an in-memory workspace. Production applications use their existing local database connection. File watching, PDF/Word extraction, automatic document grouping and model-generated embeddings remain separate capabilities.
