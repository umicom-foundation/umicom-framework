Format a context summary without treating it as verified source

A context summary is an inspection view. It prints selected metadata such as paths, byte counts and hashes without copying the source text. That distinction matters: a summary can describe an archived or diagnostic record even when its source bytes are unavailable.

1. Validate the fields the formatter reads

The formatter first checks that the file count fits the fixed array. It checks path and language terminators through Framework's shared bounded-field validator, then applies the existing relative-path rule. It rejects malformed UTF-8 and ASCII control bytes in labels so a label cannot create an extra summary line or inject a terminal control byte.

These checks protect the formatter's traversal and readable line structure. They do not compare the displayed hash with source text or require per-file token estimates to add up to the displayed total. Use UmiAiCodingMaterializedContextValidate when you need the complete owned-content contract instead of a metadata projection.

2. Keep the existing report format

Context files: 1, skipped: 0, estimated tokens: 12
* src/main.c [c] 10 bytes hash=000000000000002a

The asterisk identifies an active-file marker. A nonzero truncated flag adds the existing truncated label to the first line. These are values reported by the supplied metadata; they are not independent verification of a workspace or a model execution.

3. Stage the text before replacing the caller's buffer

The formatter allocates a bounded temporary buffer using the admitted file count and fixed label capacities. It runs the existing formatting logic there. Only a successful result that fits the caller's destination is copied out.

This prevents a small destination from containing a new header and only part of the first file after CAPACITY_EXCEEDED. It also allows the destination to overlap an input label when the caller supplies enough actual writable storage: all metadata reads finish before publication.

char summary[4096];
strcpy(summary, "Previous summary");
UmiStatus status = umi_ai_coding_context_summary(
    context, summary, sizeof summary);
if (status == UMI_STATUS_CAPACITY_EXCEEDED) {
    /* summary remains unchanged. Choose a larger buffer and retry. */
}

Include <string.h> and umicom/ai_coding_runtime/context_summary.h. The context pointer in this fragment refers to live, serialized metadata. A summary requires one extra byte for the C string terminator, so a buffer equal to the visible byte count is still too small.

4. Recover from a refused summary

ResultRecovery
INVALID_ARGUMENTSupply a context, writable output and a nonzero capacity.
INVALID_STATEInspect the file count, path/label termination, relative paths and ASCII control bytes.
PARSE_ERRORCorrect the label encoding to valid UTF-8 before retrying.
CAPACITY_EXCEEDEDRetain the previous text, allocate enough destination space and retry.
OUT_OF_MEMORYTemporary storage could not be allocated; no replacement text was published.

Do not weaken the metadata checks just to print a damaged record. Keep raw diagnostic evidence separately. If the application displays the summary as HTML or another markup format, that presentation layer must still escape the text appropriately.

5. Qualify metadata-only compatibility and failure behavior

# From the Framework source root after configuration with testing enabled:
cmake --build build/windows-ucrt64-debug --target umicom-ai-coding-context-summary-admission-test
ctest --test-dir build/windows-ucrt64-debug -R '^framework\.ai\.coding-context-summary-admission\.' --output-on-failure

The 23 scenarios cover malformed counts and labels, UTF-8 and line controls, exact and insufficient output capacities, aliased output, empty contexts, maximum numeric metadata, maximum label sizes and a record whose source bytes are deliberately unavailable. Expected result: all selected cases pass. These are authored native checks; configuration or registration alone does not establish their results.
