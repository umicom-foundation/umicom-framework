Arrange a workspace from shared components

A useful application window gives each activity a clear place: a list for finding work, an editor for changing it, a table for checking details, and a panel that explains what happened.

In this lesson you will arrange those parts without losing the text inside them. You will also read the C code that calculates their positions. The same layout description is used by the graphical example and the command-line lesson; they do not maintain competing copies of the layout rules.

Use practice information. Component Workbench is development software with temporary, in-memory data. It has no Save operation. Closing a practice window discards its notes and comments. The GTK and Windows paths in this source edition still require target-platform validation; do not treat this lesson as a qualification of installed applications.

1. Build the example before opening it

The full application checkout is assumed to be C:\umicom\Umicom-Applications. Merge the supplied full files into their matching locations first. The delivery’s Build-and-Git.md contains the complete configure, build, test and publication sequence. Do not move or delete your previous application folders.

After the full build succeeds, run this memory-only lesson from PowerShell:

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& ".\build\windows-ucrt64-all-debug\bin\umicom-layout-example.exe"
if ($LASTEXITCODE -ne 0) { throw "The layout lesson failed." }

Its output describes a 1,000 by 600 logical-pixel workspace. No window or database is opened:

navigation: x=0 y=0 width=248 height=600
notes: x=256 y=32 width=744 height=412
status: x=256 y=452 width=744 height=148
Practice complete. One canonical layout; no files, widgets or databases were opened.

In a GUI-enabled Applications build, the added executable is umicom-component-workbench.exe in the same bin directory. Double-click it. This is a separate learning window, not a replacement for Desk, Bank or Studio.

A smaller, focused build

The native lesson and its tests can be built without the rest of the application suite. Use a new build directory:

& "C:\msys64\ucrt64\bin\cmake.exe" `
    -S ".\framework\examples\workbench_viewport" `
    -B ".\build\workbench-viewport" -G Ninja `
    -DCMAKE_BUILD_TYPE=Debug
& "C:\msys64\ucrt64\bin\cmake.exe" `
    --build ".\build\workbench-viewport" --parallel 2
& "C:\msys64\ucrt64\bin\ctest.exe" `
    --test-dir ".\build\workbench-viewport" `
    --parallel 2 --no-tests=error --output-on-failure

Stop after any failed command and read its first error. Add -DUMICOM_VIEWPORT_GTK4=ON to the configure command only when GTK4 development files, version 4.10 or newer, are installed. That option requires the real library. Without it, this focused build deliberately provides the native lesson and tests only.

2. Try the components one at a time

Find a notebook title

In the Notebook panel, type work in the search field. The list should keep Workshop plan visible. Clear the field to restore all four fictional titles. This search is limited to that practice list: it does not search your computer, and selecting a title does not replace your draft.

Write a note and leave it temporarily

In the Notes tab, add Check the window layout before the workshop. Watch the character count change. Open Account browser, then return to Notes. Your new sentence should still be present because switching tabs changes visibility, not ownership of the editor.

Filter the account table

The account browser contains three fictional rows. Choose EUR from its currency control: only the Travel practice row should remain. Choose GBP to show the two workshop accounts, then All currencies to restore all rows. Enter a temporary review comment. No balance, payment or account service is involved; these are fixed labels used to practise a native table and choice control.

Make room for the editor

Move Sidebar width (%) towards 40. The notebook and editor areas should resize, without recreating the editor. Clear Show notebook: the remaining content should use the available width, with no abandoned separator gap. Select the checkbox again to bring the notebook back.

The requested percentage is a preference, not permission to make another panel unusably small. When there is enough space, the shared projection respects both sides’ minimum sizes. At a small window size, surrounding scrollbars keep content reachable. Check this behaviour on your own display, including its normal scaling setting.

Check an event and a second window

Choose Check this panel in the lower area. Its status label changes, but the note does not. Press F6 to move between visible panels; use Shift+F6 for the reverse direction and ordinary Tab within a panel.

Choose Open another workspace. Write a different sentence in that new window. Each window owns its own widgets and preview copy; editing the first must not change the second. Close the second window and confirm that the first still responds. These are useful lifecycle checks, not simply cosmetic checks.

3. Understand what a layout describes

A semantic layout records relationships such as “these two panels share a horizontal split” or “only one child in this tab group is active”. It does not store widget pointers, screen addresses or database connections.

Canonical document→Checked C projection→GTK allocation→Existing panel widgets

The sample is defined in examples/workbench_viewport/practice_layout.c. Its root window contains horizontal columns. The first column is the notebook. The second contains a vertical split: a tab group above and the status panel below. Notes and Account browser are alternative children of that tab group.

ConceptWhat it means here
Node identifierA stable name such as navigation or documents, not a widget address.
Child indexA reference to a node in the canonical document’s bounded node array.
Active childA position in the tab group’s child list. Position zero selects Notes, even though Notes is node five.
Logical pixelA layout unit used before the toolkit applies display scaling. Do not multiply all coordinates by a DPI factor a second time.
Minimum sizeThe space required by a panel or its descendants before a feasible split can honour both sides.
ProjectionA derived plan of rectangles and visibility. It is not a replacement persistence format.

For a 1,000-pixel-wide workspace, the default gap is eight pixels. The split therefore divides 992 pixels. A 25% request gives the notebook 248 pixels, and the next panel begins at x = 248 + 8 = 256. The tab strip uses the top 32 pixels of its area. The command-line example prints those calculations so you can check them without starting GTK.

4. Read the C boundary

The public interface lives in include/umicom/workbench_layout/viewport.h. Begin with the complete main.c and practice_layout.c beside it, rather than copying an isolated fragment into an unrelated application.

UmiWorkbenchViewportOptions options = UmiWorkbenchViewportDefaults();
UmiWorkbenchViewportDiagnostic diagnostic;
UmiStatus status = UmiWorkbenchViewportBuild(
    document,
    (UmiWorkbenchLayoutRect){0, 0, 1000, 600},
    &options,
    plan,
    &diagnostic);

document points to the existing canonical document type. plan points to separate caller-owned output storage. The function checks the entire graph before publishing a plan: every child must exist, parent links must agree, identifiers must be unique and all nodes must be reachable. Hidden branches are checked too; hiding an invalid branch does not make it valid.

A split ratio must be a finite number between 0.05 and 0.95. NaN, meaning “not a number”, is refused explicitly. Coordinate and minimum-size calculations use checked wider intermediate values. If the available space is smaller than the combined minimum, the result reports that limitation while keeping its rectangles non-negative and inside the supplied viewport.

The function is allocation-free and does not modify the document. On failure, the output plan is cleared and the diagnostic identifies the rejected node or request. Keep inputs stable during the call and do not overlap the input and output objects.

5. Keep widgets and application data separate

The GTK adapter asks a factory for a new, unparented widget for each component leaf. That factory gives ownership of the widget to the viewport. A failure during construction releases widgets already created. The factory’s context is borrowed only while construction is running.

Each leaf is constructed once. Changing the split, switching a tab or hiding the notebook changes the adapter’s private preview state; it does not create another editor or clear the existing buffer. Tab callbacks hold weak references to their viewport so a retained button cannot keep an otherwise closed window alive or call into its destroyed owner.

All GTK calls belong on the GTK thread. The pure C projection can be used elsewhere with separate output objects, but that does not permit a worker to manipulate widgets. A real application should send a command to its owning controller when a user requests a saved layout. This example deliberately has no persistence, so it cannot overwrite your previous layouts.

Supported shape: up to 256 canonical nodes, 16 children per node and depth 64. The projection handles a single root window or content tree, binary splits, tab groups and leaves. Project separate top-level windows separately. Drag-and-drop docking, monitor placement, preferred-size negotiation and global theme editing are not implemented by this example.

6. Understand the SQLite target warning

The warning about SQLite::SQLite3 concerns the name used by CMake to link the library. It does not say that the database is damaged. Your pasted output reached both “Configuring done” and “Generating done”; that establishes successful generation, not a later compiler or test result.

The delivered Framework helper prefers SQLite3::SQLite3. When an older CMake only defines SQLite::SQLite3, it creates an alias to that same target. It does not select a second SQLite copy or change application transactions. The original link statements remain in explained inactive blocks for review.

The helper is called after dependency discovery in each relevant directory. That matters when two sibling projects have their own imported targets. The Data Safety test project and its standalone installed SDK both use the helper; this is not a claim that every older dependency reference in the complete repository has been migrated.

The regression project tests old and new names, both names together, repeated resolution, sibling directories, missing targets and an available real SQLite library. Developer warnings remain enabled. See the official CMake FindSQLite3 documentation for the new spelling and older-version alias pattern.

7. Practise, predict, then check

Exercise 1 — Where does the second column begin?

With width 1,000, an eight-pixel gap and a 25% split, available width is 992. The first width is 248, so the second begins at 256. Its width is 744.

Exercise 2 — Why not reconstruct the Notes tab every time?

The existing text buffer owns the draft. Reconstructing its widget can lose text, selection and callbacks. Keep the component alive and change which rectangle is visible.

Exercise 3 — What happens when the chosen tab is hidden?

The projection chooses the first visible child without changing the canonical document. If every tab is hidden, no child is displayed. There is no invalid child-array access.

Exercise 4 — Does the new SQLite name upgrade the database?

No. This change selects the supported CMake target spelling and preserves the older spelling through an alias when necessary. Database-format or transaction changes are separate engineering decisions.

Exercise 5 — Can the layout command prove that Windows GTK works?

No. It checks native geometry and the canonical document. The graphical source must also compile, run and pass its own lifecycle, scaling and interaction checks on the target platform.

When something does not work

The graphical executable is absent: check that your build enables the actual GTK application path. In the focused project, GTK is off by default. Do not rename the command-line lesson to pretend it is the GUI.

A note vanished after closing: this is a temporary example, not the persistent Desk workspace. Use fictional notes and expect closing to discard them.

A split stops following the requested percentage: inspect each side’s minimum width. A percentage request cannot override a feasible minimum. A deliberately undersized pure projection reports its minimum violations.

The SQLite warning remains at the same file and line: compare your local tests/data_safety/CMakeLists.txt and the new helper with the supplied full files, then configure again. Do not hide the warning with a global suppression option. A warning from a different source file should be investigated at that actual location.

A GUI test reports skipped: read its reason. A missing display is not a graphical pass. The delivery’s validation record separately lists tested native paths and untested target-platform work.
