Native AI application learning path

Streamlit state and native Umicom forms

This four-lesson course uses Streamlit to study interactive state, then maps the design to native Umicom services. Python appears here because it is Streamlit's teaching language; the Framework implementation remains C23. Allow about two hours. Prerequisites are basic variables, functions and a working Python environment for the optional comparison lab.

Lesson 1: identify state and actions

A widget has an identity and a current value. Use stable keys for controls whose meaning persists, and separate editable values from accepted application settings. Streamlit documents widget identity and lifecycle rules; those details can vary by release, so record the installed version. See widget behavior.

For this lab, a model selection is a value, not a command to download or run a model. Draw three boxes: draft selection, accepted selection and active job. Changing the first box should not silently change a running job.

Lesson 2: submit a complete draft

Streamlit forms batch input changes for submission. The submit event is the point at which this exercise accepts a selection. See the forms guide. Save the following original example as lesson.py. Place the approved Umicom light-surface SVG logo in assets/umicom-logo.svg beside it, preserving the asset bytes.

# Umicom learning example
# File: lesson.py
# PURPOSE: Compare draft and accepted model selection without provider actions.
# AUTHOR AND ORGANISATION: Sammy Hegab / Umicom Foundation
# LICENCE: MIT
from pathlib import Path
import streamlit as st

st.image(str(Path(__file__).parent / "assets/umicom-logo.svg"), width=212)
st.title("Model selection lesson")
if "accepted_model" not in st.session_state:
    st.session_state.accepted_model = "example:small"

with st.form("model_settings"):
    selected = st.selectbox("Model", ["example:small", "example:large"],
                            key="draft_model")
    submitted = st.form_submit_button("Accept selection")
if submitted:
    st.session_state.accepted_model = selected
st.write("Accepted model:", st.session_state.accepted_model)
st.caption("Synthetic model names. No network or model operation occurs.")

Streamlit's image API supports local image paths. The logo is existing Umicom artwork, not a generated replacement. The browser's rendered font still needs visual checking; use the approved Segoe UI text and Cascadia Code/Consolas code roles in any product adaptation.

  1. In an isolated learning environment, install Streamlit according to its official installation guide and record python -m pip show streamlit.
  2. Run python -m streamlit run lesson.py.
  3. Change the draft selection without submitting. The accepted value should remain unchanged.
  4. Submit, then observe the accepted value. Refreshing or opening another browser session is a separate persistence experiment; do not assume a session variable is a database record.

Lesson 3: cache data separately from resource owners

Streamlit distinguishes st.cache_data, which returns copies of cached data, from st.cache_resource, which shares resource objects. Shared mutable objects need deliberate lifetime and concurrency handling. Read the caching guide for the selected version and scope.

In a native model browser, an immutable discovery snapshot is data. A database connection, process session or HTTP worker is a resource with an owner. Do not reuse a resource merely because two views display the same model label. Scope lookup data by provider endpoint, profile and connection revision. Set an explicit age policy and make stale observations visible. These are Umicom application design rules, not a claim that Framework provides Streamlit's decorators.

Lesson 4: implement the native boundary

Framework already exposes typed form changesets in umicom/application/experience/form_changeset.h. After building and validating your before/after models with the existing form APIs, create a changeset and apply it through the shared contract:

UmiApplicationExperienceFormChangeset change;
UmiStatus status = umi_application_experience_form_changeset_create(
    &before, &draft, &change);
if (status == UMI_STATUS_OK) {
    status = umi_application_experience_form_changeset_apply(&current, &change, 0);
}

This fragment assumes initialized form models and matching schemas. It is not a standalone program or a Streamlit binding. The native service checks every captured old value and field constraint before publication. A stale revision or mismatched field leaves the current model unchanged. Required-field completeness belongs at submission. After acceptance, a separate reviewed command can start provider work.

Lesson 5 — Apply a form to an immutable model list

Connect the draft-versus-submitted distinction to the native SDK. A form can collect search text, family, quantization, a reported-size limit and sort order. On submission, copy those values into UmiAiDiscoveryFilter, call UmiAiDiscoverySelect, and replace the displayed snapshot only after success. Keep the prior result available when validation or cancellation refuses a new query.

Lesson 6: own a native draft until explicit submission

Streamlit forms collect widget edits and submit them together; session state retains values across reruns within a session. Read the official forms and session-state guides. Umicom uses an explicit C object instead of rerunning a Python script. The object owns copied values and borrows an immutable schema.

The new umicom/application/experience/form_draft.h service reuses existing typed setters, validation and changesets. A draft belongs to one live model address. Give each window or profile its own model and draft; do not place a draft in a shared global cache. Keep the live model and every schema string, field and option alive until the draft is destroyed.

UmiApplicationExperienceFormDraft *draft = NULL;
UmiStatus status = umi_application_experience_form_draft_create(&model, &draft);
if (status == UMI_STATUS_OK)
    status = umi_application_experience_form_draft_set(draft, "query", &value);
/* Draw from a separate snapshot. Only the explicit Submit action commits. */
if (status == UMI_STATUS_OK)
    status = umi_application_experience_form_draft_commit(draft, &model);
umi_application_experience_form_draft_destroy(draft);

This fragment assumes initialized typed values and a matching schema. Use examples/form_draft/main.c for the complete program. Editing, taking a snapshot and validating perform no I/O or provider work. A successful commit consumes that draft, even when no values changed; another commit returns INVALID_STATE. A changed form advances the live revision once regardless of the number of draft edits.

Lesson 7: refuse stale or incomplete submission

  1. Create two drafts from one model. Edit and submit the first. The second must refuse with BUSY because its reviewed base is stale.
  2. Change an unedited live field without changing its revision in a test fixture. Submission still refuses: all captured live values are compared, not just changed fields.
  3. Unset a required value with no default. Inspect the validation report and confirm that committing leaves the live form unchanged. Repair the draft and submit again.
  4. Unset an optional value or a value with a schema default. Explain the distinction between absence and an explicit stored value; complete validation uses the schema default for absent fields.
  5. Take a copied snapshot and alter that copy. The draft and live model must remain unchanged. Never pass the live model as the snapshot destination.

The service requires serialized owner-thread access. It does not synchronize competing threads or detect changes to schema memory that the caller promised to keep immutable. It also does not execute the schema's command identifier, write a database, launch a model or deduplicate a paid request across restarts. Compose accepted form data with the separate reviewed command and durable task services when those effects are required.

Lesson 9: distinguish a retained draft from current application state

Streamlit forms batch input until submission, while Session State retains values within a user session across reruns. Review the official forms guide and Session State guide. In native Umicom code, the host explicitly owns live values and an isolated draft. The refresh policy below is an Umicom service, not a claim that Streamlit automatically merges concurrent forms.

Suppose a user edits a search query while another application action updates the selected catalogue. Keeping the old draft unchanged protects the user's typing, but committing it directly would use a stale base. The existing commit operation refuses with BUSY. A host can now request an explicit refresh without submitting the form.

Captured baseLocal draftCurrent live valueRefresh result
AABAdopt B into the draft.
ABAKeep the local B.
ABBAccept the convergent B.
ABCReport a conflict; preserve the whole draft.

The comparison uses stored presence and typed values. An absent field and a field explicitly storing its schema default are different representations. Revision numbers provide context, but the service also compares every captured field, so it can detect a live change that failed to advance its revision.

Lesson 10: refresh explicitly and review conflicts

#include "umicom/application/experience/form_reconcile.h"

UmiApplicationExperienceFormReconcileReport report;
UmiStatus status = umi_application_experience_form_draft_reconcile(
    draft, model, &report);
if (status == UMI_STATUS_BUSY) {
    /* Show report.conflict_fields[0..conflict_count) through the host's UI.
     * The live model and the entire draft are unchanged. */
} else if (status == UMI_STATUS_OK) {
    /* Refresh the displayed draft snapshot, then let the user review it.
     * This call has not submitted the form or executed its command. */
}

This fragment assumes that draft belongs to model and both remain alive. All access must be serialized on the owner thread, and the borrowed schema must remain immutable. Do not overlap report storage with the draft or live model. Only OK and conflict BUSY produce a new report; other errors preserve its previous bytes.

  1. Create a draft and edit the query field.
  2. Change a different live field. Confirm that an ordinary commit refuses the stale draft.
  3. Call reconcile. Inspect the copied report and take a new snapshot. The local query remains, and the unrelated live change is visible.
  4. Submit explicitly. Normal complete-form validation still applies; a required value left absent can be repaired after refresh.
  5. Repeat with different edits to the same field on both sides. Confirm that refresh returns BUSY, reports that field and preserves every draft field, including unrelated ones.

To accept the current live value for a conflict, deliberately set that value in the draft and request refresh again. To keep a conflicting local value, first retain a copied snapshot, create a fresh draft from the current model and explicitly reapply only the edits the user chose to retain. Do not silently overwrite all current values. A schema change requires a new draft and deliberate mapping to the new fields.

A real refresh copies the current base and saved marker, then advances the draft snapshot revision beyond both its previous revision and the live revision. Revision exhaustion refuses rather than wrapping. Refreshing unchanged live state is a no-op. The live model remains untouched until a separate successful commit. A consumed draft cannot be refreshed or edited.

Lesson 12: choose exact integers or approximate numeric settings

A numeric control needs a value representation as well as a minimum and maximum. Streamlit's number-input reference documents bounds, defaults and steps, and warns about exact integer limits when values cross its Python/JavaScript serialization boundary. ComfyUI's datatype reference distinguishes INT and FLOAT input descriptions. Review those primary references for the installed releases. The native exercise below uses Umicom's own C APIs; it does not execute either framework.

Use a floating-point value for an approximate parameter such as guidance. Keep a seed or exact counter as an integer, or retain its original text when it exceeds the chosen integer range. For example, 9007199254740993 fits in a signed 64-bit integer but cannot be represented exactly as a binary64 floating-point value. Converting it to a double and back can silently change its identity. Money needs its appropriate exact decimal or fixed-unit representation rather than this approximate reader.

#include "umicom/language_runtime/json_tree.h"

/* tree is an owned, validated JSON object, kept alive for these calls. */
int node = -1;
double guidance = 0.0;
UmiStatus status = UmiJsonTreeMember(tree, 0, "guidance", &node);
if (status == UMI_STATUS_OK)
    status = UmiJsonTreeDouble(tree, node, &guidance);
/* Validate the application's allowed range before accepting guidance. */

UmiJsonTreeDouble reuses the shared ASCII converter and its isolated C locale. JSON always uses a dot in decimal spelling, regardless of the desktop's regional settings. The service does not change the process locale. It accepts integer or decimal number spelling and finite nonzero subnormal values. It refuses overflow, nonzero underflow rounded to zero, and a numeric spelling longer than 511 bytes. A wrong JSON kind, including a string containing a number, is a parse error. Every error leaves the caller's previous output unchanged. Platforms lacking the isolated-locale implementation can report NOT_IMPLEMENTED.

The existing integer reader still requires exact integer spelling and signed 64-bit range. It refuses 20.0 for an integer field instead of coercing it. Exact JSON value comparison still distinguishes 1 from 1.0. Reading either as a double does not rewrite the document or alter its comparison rules.

Lesson 15: distinguish interface defaults from observed settings

Streamlit provides st.text_area for multiline text and st.checkbox for Boolean input. A stable key identifies widget state across reruns. Their initial values belong to the interface; a provider's missing default is a separate fact. A native observer should preserve that distinction even when the interface chooses an empty field or unchecked control.

Run this small subject-language exercise in a separate Streamlit learning environment using streamlit run app.py. It is an original teaching example, not an Umicom runtime dependency or a native implementation.

Lesson 17: display one captured native report

Use the ComfyUI course's installed SDK browser to save a successful node page as node-page.json. Confirm the native command exited successfully before using its output. This original Python exercise teaches Streamlit's table presentation; Framework's reader, filtering and serialization remain C23.

Continue the earlier lesson's project and approved assets/umicom-logo.svg. Keep its supplied branding resources unchanged. Save the following as node_table.py. Run streamlit run node_table.py in your teaching environment.

import json
from pathlib import Path
import streamlit as st

folder = Path(__file__).parent
st.image(str(folder / "assets/umicom-logo.svg"), width=212)
st.title("Umicom captured node review")
try:
    envelope = json.loads((folder / "node-page.json").read_text(encoding="utf-8-sig"))
    report = envelope["report"]
    if envelope["origin"] != "offline-files":
        raise ValueError("Expected a captured-file report")
    if report["schema_version"] != 1 or report["scope"] != "node-selection-observations":
        raise ValueError("Unsupported report schema")
    if not isinstance(report["connection_revision"], str):
        raise ValueError("Keep the revision as an exact string")
    rows = []
    for node in report["nodes"]:
        flag = node["deprecated"]
        rows.append({
            "Class": node["class_type"],
            "Display": node["display_name"],
            "Category": node["category"],
            "Deprecated": "Unknown" if flag is None else str(flag),
        })
    st.dataframe(rows, hide_index=True)
    st.caption(f"Captured selection: {report['selection_sha256']}")
    st.caption(f"More rows in this selection: {report['remaining_count']}")
except (OSError, ValueError, KeyError, TypeError) as error:
    st.error(f"Cannot display this captured page: {error}")

Streamlit's dataframe reference describes its interactive table. Table sorting changes this displayed page; it does not change the native selection or ask a provider to load anything. The teaching loader performs only basic shape checks and is not a replacement for the native admission contract or a general hostile-file parser. Preserve missing flags as Unknown rather than converting them to false.

Lesson 18: extend the table without mixing observations

  1. Compare the four identity fields from two pages: connection revision, connection fingerprint, response digest and selection digest. Reject a join when any differs.
  2. Require the second page's offset to equal the first page's next offset. Display duplicate or missing rows as an error rather than silently deduplicating them.
  3. Change --order class to --order source on a fixture whose order differs. Explain why the original response digest stays equal while the selection digest changes.
  4. Filter for an explicitly false deprecated flag. Explain why unknown entries disappear without being labelled deprecated.
