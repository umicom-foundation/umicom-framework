Build real applications with Umicom

You will learn C by building useful parts of an application. We begin with an activity report, calculate a training account balance, manage note text in memory and save it safely. Then we attach a window, panels and menus to the same Notes model.

Work through one change at a time. Before running a program, write down what you expect it to do. After running it, compare the output, the saved file or the visible behaviour with that expectation. When something differs, investigate the difference before moving on.

Prepare the learning build

Use your existing Umicom Applications checkout. Keep Framework and the application submodules at the revisions recorded by the parent. These learning targets use the actual Framework libraries; they do not download or embed another copy.

Windows

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake --preset windows-ucrt64-all-debug -DUMICOM_BUILD_NATIVE_TOOL=ON -DUMICOM_BUILD_LEARNING_EXAMPLES=ON -DUMICOM_LEARNING_BUILD_GUI=ON

Linux without a desktop

cd "$HOME/umicom/Umicom-Applications"
cmake --preset linux-gcc-all-headless-debug -DUMICOM_BUILD_LEARNING_EXAMPLES=ON

Linux with the graphical development dependencies installed

cd "$HOME/umicom/Umicom-Applications"
cmake --preset linux-all-gtk4-debug -DUMICOM_BUILD_LEARNING_EXAMPLES=ON -DUMICOM_LEARNING_BUILD_GUI=ON

Use the headless configuration for terminal and model exercises. Use the graphical configuration for the Notes window. In each lesson, build just the target you need. In Studio, use Help → AI Teacher to open Guided Learning and select the lesson by its title.

The application journey

LessonWhat you will practise
1. Write an activity report for Umicom NotesCreate a C source file, build it and explain how named values become useful output.
2. Calculate a training account balanceUse integers, structures, arrays and checked Framework money operations for GBP amounts.
3. Read binary settings in a real applicationRepresent independent Notes display options with bit masks and inspect each operation.
4. Understand who owns a note in memoryFollow copied and borrowed data, pointer lifetime and cleanup in a Framework document.
5. Save a note without overwriting someone else’s workUse paths, error results and the Framework document saver to preserve user files.
6. Connect actions through a command registryGive New, Save and Undo stable command names and route them to the existing document owner.
7. Build a document workflow with Model, View and ControllerFollow one note through a store, view model, coordinator and undo history.
8. Create the Umicom Notes window and panelsUse Framework component specifications to arrange a window, split panels and a text editor.
9. Add menus, actions and clear error feedbackConnect File and Edit menus to the same Notes commands as buttons and terminal clients.
10. Create and build another application with FrameworkGenerate a project, inspect its build profile and understand background build sequencing.
11. Test, install and publish your applicationDistinguish a successful compile, a passing test, an installation and a published source revision.

Save and create from a terminal

Choose fresh paths. The example refuses an existing project directory or an unrelated existing destination file. Replace the paths below with locations you own.

Windows

New-Item -ItemType Directory -Path "C:\umicom\practice-notes"
& ".\build\windows-ucrt64-all-debug\bin\umicom-learning-notes-session.exe" "C:\umicom\practice-notes\review.txt"
& ".\build\windows-ucrt64-all-debug\bin\umicom-learning-project-creator.exe" "C:\umicom\projects\UmicomNotes"

Linux

mkdir -p "$HOME/umicom/practice-notes"
./build/linux-gcc-all-headless-debug/bin/umicom-learning-notes-session "$HOME/umicom/practice-notes/review.txt"
./build/linux-gcc-all-headless-debug/bin/umicom-learning-project-creator "$HOME/umicom/projects/UmicomNotes"

Develop your knowledge further

The existing programming lessons provide additional practice for each stage. Use this map when you meet an unfamiliar concept, then return to the application you are building.

StageStudy and application exercise
C foundationsTypes and formatting. Values, expressions, selection, loops, functions, arrays, structures and enumerations. Extend the activity report and account totals.
Safe memoryDynamic memory. Pointer contracts, allocation, resizing, ownership, strings, cleanup, integer bounds and non-finite input. Explain the lifetime of every note buffer.
Algorithms and dataSearch and sorting. Search note titles, sort account rows, compare algorithm costs and study bounded queues, recursion and binary records.
Architecture and patternsController architecture. Master Controller / Slave Controllers, MVC, view models, Command, Adapter, Strategy, Factory, Observer, dependency injection and state machines. Keep the model independent from GTK.
Systems and AssemblyAssembly loops. Binary, byte order, instruction execution, registers, stack, calling conventions, C/Assembly boundaries and profiling before optimisation.
Concurrent workAtomic basics. Study shared state and cancellation before adding threads. The next application milestone is background search with progress and safe shutdown.
Quality and deliveryTest design. Negative tests, sanitizers, compiler diagnostics, release checks, Git snapshots, installation and clean-machine packaging.

Later project work will add persistent note collections through the Data Server, database transactions, networking, authenticated APIs, accessibility checks, richer widget models, debugger integration and performance measurement. Those activities should extend the same applications and shared Framework services rather than introduce disconnected examples.
