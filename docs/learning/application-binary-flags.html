Read binary settings in a real application

Umicom Notes can show line numbers, wrap long lines and display a preview. Each setting has two states: on or off. A bit mask lets one integer represent several independent settings. We will inspect the binary value rather than treating it as a mysterious number.

Give each option its own bit

Our constants have values 1, 2 and 4. In three-bit binary notation these are 001, 010 and 100. Each value occupies a different bit position. Combining options therefore preserves the identity of every selected option.

Bit position:     2 1 0
Line numbers:     0 0 1
Word wrap:        0 1 0
Preview:          1 0 0

Combine, test and clear

The bitwise OR operator | turns on every bit present in either operand. Line numbers OR word wrap produces 011. The AND operator & can test whether a selected bit is present. A result of zero means that the tested bit is off.

To turn off word wrap without changing the other options, use settings &= ~NOTES_WORD_WRAP;. The complement ~ creates a mask with that bit cleared and the other bits set. AND then preserves those other positions.

Do not confuse bitwise & with logical &&. Logical operators answer true-or-false questions; bitwise operators work on the separate bits in integer values. This difference matters when reading conditions.

Read the printing loop

PrintBinary starts at the highest of our three display positions and works downwards. The shift expression moves a single set bit to the position being examined. We use an unsigned value and keep every shift within its valid range. Shifting by the width of a type or more is not a safe way to request another digit.

Umicom Notes settings: 011
Preview on, wrapping off: 101

Connect bits to system architecture

The variable is stored in the program’s memory. The processor loads integer values into registers when performing operations. A compiler can turn these expressions into machine instructions that manipulate those bits. The C expression describes the operation; the instruction encoding depends on the processor architecture.

Open the existing Assembly lessons after this exercise and compare the compiler’s output with the source. Keep the display-setting behaviour as the reference. A shorter Assembly listing is useful only when it still produces the correct result.

Use masks for the right job

Display settings are a good place to learn this representation. A local integer is not, by itself, a secure permission system. An application must still ask the Framework security service whether a protected operation is allowed. Changing a visible checkbox must not bypass that decision.

binary_flags.c

framework/examples/learning/projects/binary_flags.c

/*-----------------------------------------------------------------------------
 * Umicom Framework — application development lessons
 * File: examples/learning/projects/binary_flags.c
 * PURPOSE: Inspect independent display settings as binary flags.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/

#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

#define NOTES_SHOW_LINE_NUMBERS UINT32_C(1)
#define NOTES_WORD_WRAP UINT32_C(2)
#define NOTES_SHOW_PREVIEW UINT32_C(4)

static void PrintBinary(uint32_t value)
{
    for (unsigned position = 3U; position > 0U; --position)
        putchar((value & (UINT32_C(1) << (position - 1U))) != 0U ? '1' : '0');
    putchar('\n');
}

int main(void)
{
    uint32_t settings = NOTES_SHOW_LINE_NUMBERS | NOTES_WORD_WRAP;
    fputs("Umicom Notes settings: ", stdout);
    PrintBinary(settings);
    settings |= NOTES_SHOW_PREVIEW;
    settings &= ~NOTES_WORD_WRAP;
    fputs("Preview on, wrapping off: ", stdout);
    PrintBinary(settings);
    return settings == UINT32_C(5) ? EXIT_SUCCESS : EXIT_FAILURE;
}
