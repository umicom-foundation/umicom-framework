Listen to an audio edit before exporting

Media and Music share Framework's Audio clip page. You can trim a supported WAVE recording, reduce its gain, add fades, inspect its waveform and listen before creating a new file.

Preview and listen

  1. Open Creative workbench → Audio clip. Enter the full path of a PCM16 mono or stereo WAVE file and choose Load WAVE. The clip reader accepts 8,000–192,000 Hz and at most 4 MiB. Compressed and floating-point audio are refused without conversion.
  2. Choose the first included frame and excluded end frame, gain and fade lengths. Choose Preview range to render the edit and see its waveform. Rendering alone produces no sound.
  3. Choose Load preview for listening. A separate player copies the edited samples and prepares them through the installed GTK media backend. Wait for preparation or an explanatory backend error.
  4. Press the player's Play control when ready. Playback begins at 20 percent volume. Use pause, volume and the position control where the backend supports seeking. Loading, replacing or showing a preview never starts playback automatically.
  5. Change the edit if needed. Changing its range, gain or fades retires the listening preview, so you must render and load it again. Moving away from the page or hiding its window pauses it. Returning leaves it paused.
  6. When satisfied, choose a new absolute destination path and Write new WAVE. Existing files are never overwritten. The playback volume affects listening only; the exported samples use the edit's gain and fades.

If sound is unavailable

The player reports errors supplied by GTK's media backend. Check that your GTK installation has a media backend capable of reading PCM WAVE streams and that an output device is available. A loaded preview proves ownership of the sample data, not successful audible playback. Waveform inspection and WAVE export remain available when playback is unavailable. You can listen to the exported file in another local player.

Privacy and reuse

The player receives an owned in-memory copy containing only PCM format and sample chunks. It writes no temporary file, opens no URL and starts no external program. Clip and audition state remain separate from the saved scene project. Closing the application discards them unless you explicitly export the edit.

Other GTK frontends can use UmiCreativeAuditionGtkCreate, UmiCreativeAuditionGtkLoadWave and UmiCreativeAuditionGtkClear from umicom/ui/gtk4/creative_audition.h. Calls belong to the GTK thread. Load a preview only after an explicit user action and clear it whenever its source edit changes. This control shares the existing bounded PCM reader; it does not play compressed music, provider video results or larger audio arrangements.

GTK documents its input-stream media source and playback state interface.

If playback components are missing

The audio player checks its GStreamer components before creating the native GTK media player. A missing playbin3, WAVE decoder, stream source or audio sink produces an explanatory message instead of entering a backend constructor that can terminate the process. Editing, rendering and WAVE export remain available.

  1. Read the component name in the preview message.
  2. Install the matching GStreamer runtime plugins for the same architecture and toolchain as the application. Do not mix DLLs from unrelated installations.
  3. Restart the application and load the preview again. Press Play only when ready; passing the component check does not prove an audio device works.

This preview adapter currently preflights the GTK GStreamer backend. An explicit GTK_MEDIA setting for another backend, or a build without GStreamer development support, reports preview unavailable. Backend-dependent tests report a skip when prerequisites are absent; that is not a playback pass.
