Create and build another application with Framework

Studio’s New Project window is a frontend to a Framework service. We can call that same service from a small native program. This is useful for learning the API and for proving that project generation is not hidden inside a button callback.

Supply a generation request

Open project_creator.c. It supplies a template ID, display name, application ID, repository name, target name and destination. These fields have different roles: the display name is for readers, the target name is for CMake, and the application ID provides a stable identity.

The request uses fixed-capacity fields. The example checks the destination length before copying it. Framework validates the complete request before generating files. Names that would inject quotes or new commands into generated C, CMake or YAML are rejected instead of being inserted as executable syntax.

Plan before writing

The existing Framework template service renders a file plan, and the generator applies it. UmiDeveloperProjectCreateNew adds the specific rule for creating a new project: the destination must be absolute and must not already exist. It does not overwrite an established project.

An I/O failure can leave part of a newly created directory. Read the error and inspect that directory before retrying. Do not repeatedly delete folders from a helper script. The report tells the caller what generation completed; it is not a substitute for checking the filesystem.

Read the build profile

After creation, the returned profile names the source, build directory, preset, executable and installation directory. The Linux model uses a Linux preset and an executable without a Windows suffix. The Windows model uses the UCRT64 preset.

An imported folder is different from a generated project. Framework can set its source directory, but must not guess that its executable is umicom-studio-ide. Select the actual target and program in Project Settings. A profile is a description of one build, not permission to run arbitrary code.

Understand the background sequence

A build runs Configure followed by Build. Run adds the selected program after those phases succeed. Test and Install configure and build the project before their final operation. If compilation fails, later phases stop. This prevents Run from silently executing an old binary after a failed build.

The worker receives a copy of the profile. The UI reads completed results on its own thread rather than sharing mutable GTK objects with the worker. Cancellation is a request to stop the operation; it is not the same thing as freeing the worker’s memory immediately. Shutdown waits for the owned work to finish before releasing its inputs.

Try both entry points

Run the native creator with a new absolute directory. Read its printed preset and launch path. Open the resulting folder in Studio, inspect Project Settings and build it. Compare this with using File → New Project. Both should generate through Framework, not through separate file-writing implementations.

Build and run the supplied example

Configure the learning targets once using the course setup. Run the commands below one at a time. Stop when a command reports a failure; do not continue to run an older executable.

Windows · PowerShell

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake --build --preset windows-ucrt64-all-debug --target umicom-learning-project-creator --parallel 2
& ".\build\windows-ucrt64-all-debug\bin\umicom-learning-project-creator.exe" --help

Linux · terminal

cd "$HOME/umicom/Umicom-Applications"
cmake --build --preset linux-gcc-all-headless-debug --target umicom-learning-project-creator --parallel 2
./build/linux-gcc-all-headless-debug/bin/umicom-learning-project-creator --help

Source to study and edit

These are the supplied files for this lesson. Open them in Studio to follow the code. The Notes model is shared by the terminal example and the window; keep one implementation while trying different frontends.

project_creator.c

framework/examples/learning/projects/project_creator.c

/*-----------------------------------------------------------------------------
 * Umicom Framework — application development lessons
 * File: examples/learning/projects/project_creator.c
 * PURPOSE: Create a fresh CMake project through the same Framework service as Studio.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/

#include "umicom/developer_project/new_project.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv)
{
    UmiDeveloperProjectService *service = NULL;
    UmiDeveloperProjectGenerationRequest request;
    UmiDeveloperProjectGeneratorReport report;
    UmiDeveloperProjectModel model;
    UmiBuildProfile profile;
    if (argc != 2 || strcmp(argv[1], "--help") == 0) {
        puts("Usage: umicom-learning-project-creator <absolute-new-directory>");
        puts("Creates a C23 project named Umicom Notes. Existing directories are refused.");
        return argc == 2 ? EXIT_SUCCESS : EXIT_FAILURE;
    }
    if (strlen(argv[1]) >= sizeof(request.project_root)) return EXIT_FAILURE;
    umi_developer_project_generation_request_init(&request);
    strcpy(request.application_name, "Umicom Notes");
    strcpy(request.application_id, "org.umicom.notes");
    strcpy(request.repository_name, "umicom-notes");
    strcpy(request.target_name, "umicom_notes");
    strcpy(request.template_id, "developer.template.c23-console");
    strcpy(request.project_root, argv[1]);
    UmiStatus status = umi_developer_project_service_create(&service);
    if (status == UMI_STATUS_OK)
        status = UmiDeveloperProjectCreateNew(service, &request, &report, &model, &profile);
    if (status == UMI_STATUS_OK)
        printf("Created %zu files in %s\nConfigure preset: %s\nRun program: %s\n",
            report.files_created, model.root, profile.preset, profile.run_program);
    else fprintf(stderr, "Project was not created: %s\n", umi_status_text(status));
    umi_developer_project_service_destroy(service);
    return status == UMI_STATUS_OK ? EXIT_SUCCESS : EXIT_FAILURE;
}
