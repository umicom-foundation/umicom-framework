Edit a local video sequence

The Video editing workspace in Media, and the Video editing view in Music, join selected parts of local video files. A recipe records the order, trim ranges and output size. Editing a recipe leaves the source files unchanged. The shared Framework service supplies the same editing rules to both applications.

This editor supports six clips and a total of ten minutes. Export produces silent H.264 video in a fragmented MP4 container at 30 frames per second. Audio is attached in a separate export described below. Transitions, caption burn-in and multi-track video composition are not included in the sequence renderer. The separate audio and caption tools remain available.

Find your way around

Media opens its Video editing view. Clips and project settings are on the left, the preview is in the centre, the Inspector and Export pages are on the right, and the clip strip is below. Drag the separators to resize these regions. Choose Design and generators for the other creative tools, or Workspace layouts for the product's existing layouts. Music starts in its creative workbench; select its Video editing view for this editor.

Choose clips and make edits

  1. In Clips, enter a unique clip ID, such as intro, then browse to a local video. A clip is a named section of one source file. Use an ordinary absolute file path; web addresses and network shares are not accepted.
  2. In Inspector, set Source start and Source end in milliseconds. One second is 1000 milliseconds. For example, 2000 to 6000 selects four seconds beginning two seconds into the file. The end is excluded.
  3. Choose Add clip on the left. A button appears below the preview with the clip ID and its place in the assembled sequence. To add another clip, enter a different ID, choose its file, set its source range, and choose Add clip again.
  4. Select a clip using its button below the preview or the clip list on the left. Selection loads its fields; it does not change the recipe, start playback or consume an Undo step.
  5. Change the source range and choose Apply trim. Typing into a field alone does not edit the recipe.
  6. To split a clip, enter a source time inside its current range, give the right part a new ID, and choose Split clip. To change its order, enter a New position starting at 1 and choose Move clip.
  7. Use Undo and Redo to review the last sixteen changes. A fresh edit after Undo replaces the redo path. The clip strip updates after each accepted edit.
  8. Open Project on the left to apply a title and even output dimensions. The supported dimensions run from 16 by 16 to 1920 by 1080 pixels.

The clip strip is an ordered sequence, not a multi-track editor. Its buttons are not scaled to duration, and clips are reordered with Move clip rather than drag and drop. Expand Sequence details for exact timing and source paths.

Preview a stored trim

Select an added clip and press Preview selected clip. Preview is muted to match the silent export. Playback depends on the installed GTK GStreamer backend and suitable codecs. The editor checks whether the backend can seek and whether the selected end is within its reported duration. Press Stop preview before moving on. This is a single-clip preview, not a preview of the entire assembled timeline. Backend timing is not a frame-accurate editing guarantee.

Save and reopen your recipe

  1. Open Project, choose a new JSON filename in a directory you control, then press Save new recipe. Existing files are preserved, so use a new filename for each saved revision.
  2. To reopen a recipe, enter or choose its existing path and press Open recipe. If you have unsaved edits, save them first or tick the replacement confirmation.
  3. An invalid or missing recipe leaves the current edits intact. Successful opening starts a fresh undo history. Source media is referenced by its absolute path and is not copied into the recipe.

Recipes contain local filenames in plain text. Keep them private when those paths reveal sensitive project information. Moving a recipe to another computer requires adjusting its clip paths.

Relink a moved source file

  1. Select the stored clip in the clip list. Expand Relink source media and choose its replacement local video. Use the replacement field in this section; unapplied trim fields are not used by relinking.
  2. If several cuts refer to the same old path, select Relink every clip with the same source path. Matching uses the exact stored path, including its spelling.
  3. Press Relink source. This changes only the source references. Clip IDs, order, source start/end times and output settings remain unchanged. The selected clip remains selected even after moving it to another timeline position.
  4. Preview the replacement. A valid path does not prove it is the same recording or has enough media for the existing trim. Relinking does not copy, rename or overwrite either source file.
  5. Use Undo to restore the whole relink, or Redo to reapply it. Save a new recipe to keep these references after closing. A failed relink preserves the recipe and its undo history.

Other native or headless hosts use video_relink.h. Each request binds a clip ID, its expected old path and its replacement. If the old path has changed, the entire request returns UMI_STATUS_INVALID_STATE; reload and review the current references before retrying. The caller serializes editing on its owning thread. Relink validation performs no filesystem or codec inspection.

Render a video

  1. Open Export on the right and select a trusted native FFmpeg executable that includes the libx264 encoder. Umicom does not download or install it. Native rendering currently uses the Framework process channel on Windows and Linux.
  2. Choose a new filename ending in .mp4 in an existing directory you control.
  3. Press Render silent MP4. The job captures the current recipe, executable and path. Each clip uses its first video stream. Frames are scaled with letterboxing to preserve aspect ratio.
  4. Wait for the result. Cancel operation requests termination of this render's process group. A failed or cancelled render may leave a new partial file; it is retained for inspection. Use another output filename when trying again.
  5. Open the resulting MP4 in a video player and check the full sequence. Successful process completion and a container prefix do not replace playback verification.

Add a local soundtrack

  1. Render the silent sequence first and check it in a player. You may also choose another video whose codec FFmpeg can copy into MP4.
  2. Expand Add soundtrack to a rendered video. Choose the rendered video and a local audio file, such as a WAV exported from Umicom's audio arrangement tools.
  3. Select a new output path and press Export with soundtrack. The selected FFmpeg executable must include AAC audio encoding.
  4. Open the new MP4 and check both picture and sound. The first video stream is copied without re-encoding. The first audio stream from the selected soundtrack replaces any original audio, starts at the beginning and ends with the video. A short soundtrack is padded with silence.

This is a separate operation; soundtrack paths are not saved in the video recipe. It does not mix existing sound, align lyrics, change volume or generate music. Missing required streams and incompatible codecs fail visibly. Both inputs remain unchanged, and cancellation can retain a partial new output just as with silent rendering.

If something does not work

Preview unavailable: install matching GStreamer playback plugins and codecs. Editing and saving recipes remain available. Encoder missing: select the executable, not a folder or command string. Unknown encoder or filter: read the renderer diagnostics shown below the sequence summary and use a compatible FFmpeg build.

Range beyond the source: check the trim using preview. Render input is read when the job runs; a file changed or shortened since editing can produce a different or shorter result. Output already exists: select a fresh filename. Umicom never replaces it. Rendering is limited to fifteen minutes of elapsed work and 512 MiB of encoded output. A limit failure is reported and may retain partial output.

For contributors

Keep editing rules in video_sequence.h, persistence in the recipe service, and process ownership in video_render.h. Applications compose the native panel. New operations must validate a candidate before publication, retain previous edits on failure, and extend the recipe schema deliberately. Do not add user-supplied strings to FFmpeg filter expressions: paths belong in separate argument values. Decoder and encoder qualification should include decoded output checks, alongside cancellation, ownership and file-preservation coverage.

Implementation references: FFmpeg command documentation, concat and video filters, fragmented MP4, audio padding, and GTK media streams.

Add selectable captions

  1. Finish trimming and arranging the video. Render it, and add its soundtrack if needed.
  2. Use the captions editor to create or edit the words and cue timings, then export a UTF-8 SRT file. SRT, also called SubRip, stores a start time, end time and text for each caption.
  3. In the Export page, open Add captions to a rendered video. Choose the finished video, the SRT file and a new output filename ending in .mp4.
  4. Check the trusted FFmpeg executable field and select Export with captions. Wait for the completion message. The operation uses the same Cancel button as rendering.
  5. Open the new file in a compatible video player and enable its subtitle track. Check the words, timing, full video length and sound before sharing it.

The export copies the first video stream and, when present, the first audio stream. Those streams must already use codecs supported in MP4. It adds one mov_text caption track and leaves out earlier subtitle tracks. FFmpeg must supply the SubRip decoder, mov_text encoder and MP4 writer.

Captions remain selectable; they are not permanently drawn into the picture. Timing is not adjusted automatically, and a cue past the end of the video can extend the container's reported duration. Keep cues within the intended video timeline. If a player does not show the captions, check its subtitle controls and format support.

The recipe, original video and SRT file are unchanged. An existing output filename is refused. A failed or cancelled export can leave a partial new file; choose another filename when retrying and read the renderer diagnostics. Caption paths are export inputs and are not saved inside the sequence recipe.

Cancel opening a recipe safely

  1. Save edits you want to keep. If replacing unsaved edits, review the replacement confirmation before choosing Open recipe.
  2. While the open is pending, use Cancel operation. Cancellation requested before the GTK owner accepts the parsed recipe keeps the current sequence and undo history.
  3. Wait for the result before starting another file operation. If the recipe was already accepted before you cancelled, the open has completed; cancellation does not undo a completed operation.

Saving and rendering are different: a file successfully created before cancellation remains a completed output. The result must not report that file as cancelled merely because a late request arrived. Failed or interrupted exports can still leave a partial new output, as described above.

Embedding applications must call UmiVideoSequenceGtk4Retire before removing a live panel. Retirement requests cancellation and prevents late results from updating controls. Keep the GTK main loop running while accepted work finishes; process termination cannot report or recover incomplete work.
