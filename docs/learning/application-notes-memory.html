Understand who owns a note in memory

A note must remain available after the function that first supplied its text has finished. That is a memory-lifetime problem. We will trace one note through the existing Framework document API and identify which object is responsible for releasing its text.

Start from an empty object

UmiDocument note; reserves storage for the document structure. Before using it, call umi_document_init(&note). The initialised structure has no allocated text. Initialisation establishes a state that later operations can recognise.

The structure contains a char * field. This pointer holds the address of text stored elsewhere; the pointer is not the text itself. Copying an owning structure with a simple assignment can therefore give two structures the same address. Disposing both would attempt to release the same allocation twice.

Observe a copy

umi_document_set_text allocates storage for its own copy of the supplied text. Our input array is changed immediately afterwards. The document should still start with Umicom, because it does not borrow that input array.

By contrast, a borrowed pointer is usable only while its owner keeps the pointed-to storage valid. Read a function’s ownership contract before retaining a pointer. A name such as “get” is not a sufficient guarantee that the returned data is yours to free.

Append without holding an old pointer

Appending text may require a larger allocation. A resize can move the text to a new address. Do not keep a pointer into the old text and assume it remains valid after an append. In this exercise, read note.text after the append has completed.

/* Unsafe ownership pattern: both objects would refer to the same text. */
UmiDocument second = note;
/* Disposing both note and second is not a valid independent-copy operation. */

Understand the cleanup

umi_document_dispose(&note) releases the document’s allocated text and resets the structure. Call it even when an earlier operation failed. The example records a status, performs whichever steps remain valid, then reaches one cleanup point.

Inside a lower-level allocation function, a failed realloc must not destroy your only reference to an existing buffer. Assign the returned pointer to a temporary, check it and replace the owner’s pointer only after success. The Framework implementation is a useful place to study that pattern.

Test lifetime rather than luck

The example checks that changing the caller’s array did not change the document. It also exercises an append and cleanup. Extend it with an empty note and a longer paragraph. Use the dynamic-memory lesson to inspect allocation failures and the sanitizer lesson to detect invalid memory access.

Being able to run a program once does not establish safe ownership. A dangling pointer can appear to work until a later allocation reuses the same memory. Your explanation of who owns each allocation should be as clear as the code.

/*-----------------------------------------------------------------------------
 * Umicom Framework — application development lessons
 * File: examples/learning/projects/notes_memory.c
 * PURPOSE: Trace note ownership using the existing Framework document API.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include "umicom/platform/document.h"

int main(void)
{
    UmiDocument note;
    char title[] = "Umicom Notes: review the build output.\n";
    umi_document_init(&note);
    UmiStatus status = umi_document_set_text(&note, title);
    /* Framework copied the text. Changing the input does not change the note. */
    title[0] = 'X';
    if (status == UMI_STATUS_OK)
        status = umi_document_append(&note, "Next: run the tests.\n");
    if (status == UMI_STATUS_OK) {
        printf("The document owns %zu text bytes.\n%s", note.length, note.text);
        if (strncmp(note.text, "Umicom", 6U) != 0) status = UMI_STATUS_INVALID_STATE;
    }
    umi_document_dispose(&note);
    return status == UMI_STATUS_OK ? EXIT_SUCCESS : EXIT_FAILURE;
}
