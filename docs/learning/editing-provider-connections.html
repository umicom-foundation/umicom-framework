Edit provider connections

The native connection editor saves non-secret settings for application adapters. Studio opens the same Framework editor used by other hosts. You can create a connection, change its settings, keep a draft while checking changes from another window, and remove a saved connection.

This screen does not sign in to a provider, provision an API key, start a model, or switch Studio's active AI provider. Saving an enabled configuration makes it available to a compatible adapter; it does not establish a live connection. Credential entry and provider-specific request workflows are separate integrations.

The statements below about authentication apply to editing and saving metadata. The separate Check saved connection action now supports an explicitly approved model-catalogue request. Follow Check a saved provider connection for its supported destinations, local password verification and limits.

1. Open the editor

  1. Open the AI Coding panel in Studio's GTK workbench.
  2. Choose Connections….
  3. Wait for the saved list to load. If storage cannot open, the editor explains the failure and keeps saving disabled. It does not silently use temporary memory instead.

Studio uses the studio application scope and desktop profile scope for the current operating-system user. The desktop scope is an alias, not a separate signed-in account. The database is named provider-connections.sqlite3 in Framework's per-user application data directory. Windows uses a location under LOCALAPPDATA; other platforms use the Framework application-path service. Source repositories and the process working directory are not used to choose this location.

2. Save a local model configuration

  1. Choose New. If another draft is unsaved, save it first or confirm discarding it.
  2. Enter a connection ID such as local-model. IDs start with a lower-case ASCII letter and use lower-case letters, digits, dots, underscores or hyphens.
  3. Keep or change the provider alias local-chat and enter a display name.
  4. Choose Local loopback (no credential). Use an address such as http://127.0.0.1:8080/v1/chat/completions only when it matches the server you intend to use. The allowed port range is 1024–65535.
  5. Enter the model identifier expected by that adapter, or leave it empty while preparing a draft. Keep the credential reference empty for a local loopback route.
  6. Review the timeout and enabled checkbox. New configurations start disabled.
  7. Choose Save draft. The saved list and saved-settings panel should update after the database operation finishes.

The local model must be installed and started separately. This editor does not verify which process owns the chosen port or whether its protocol is compatible.

3. Prepare remote settings

Choose Remote HTTPS, enter the provider alias and endpoint approved by its adapter, then enter a model identifier when required. Endpoints cannot contain passwords, user information, query strings, fragments, percent escapes, backslashes or dot path segments. These syntax checks do not prove that a destination is trustworthy.

The credential field accepts a reference such as vault:personal-key. It names a key stored separately; never paste the actual key into this field, a display name, a model identifier or the URL. Read Store provider keys on this computer for the native credential service and its limits. The editor does not check whether the reference exists or authenticate with it.

Choose Manage local keys… for the separate, profile-verified credential panel. It opens in this editor's application/profile scope and keeps key bytes out of the settings database. Follow Manage local provider keys to create a local profile if needed, save or replace a key, check local availability, or remove a key. These actions do not switch the active AI provider.

4. Handle conflicting edits without losing your draft

A revision identifies the saved settings you last reviewed. Any edit in the same application/profile scope changes that revision, including edits to a different connection.

  1. If Save reports changed settings or busy storage, keep the editor open. Your fields remain intact.
  2. Choose Reload saved settings. The saved-settings panel updates, while an unsaved draft remains in the editable fields.
  3. Compare the current saved values with your draft. If you want to keep the draft, check I reviewed the saved settings shown above.
  4. Choose Keep my draft using the reviewed revision, then Save draft. Saving still checks for another intervening edit.

If the record was removed or a different window created your new ID, review that change before proceeding. Keep a copy of fields you want to reuse before choosing New or another saved record. The editor does not silently convert a missing replacement into a new record.

5. Remove a connection or close the window

  1. Select the saved connection you intend to remove.
  2. Check Remove the selected saved connection; keep its credential. If your fields contain unsaved edits, confirm discarding that draft as well.
  3. Choose Remove selected. Only the settings record is removed; a shared or remotely issued credential is not deleted or revoked.

Normal window closing waits for an active database operation and asks you to acknowledge an unsaved draft. Closing Studio or forcing the host to destroy the panel can retire it immediately. A database write already started may still finish, so reopen the editor to check the saved state. Closing a window is not a promise to roll back a write.

Storage recovery

MessageNext step
SQLite is unavailableUse a build with SQLite support. The screen does not claim temporary values were saved durably.
Damaged or inconsistent saved settingsPreserve the database for investigation. Do not replace it with an empty database to dismiss the error.
Edit saved, but list could not reloadChoose Reload before editing again. Do not repeat creation assuming the first write failed.
Field too long in UTF-8 bytesShorten the field. Some characters use several bytes; the display-name limit is 160 bytes.
Storage could not confirm a safe resultKeep the draft, inspect storage availability, and explicitly reload. Review the saved values before deciding whether another save is needed.

Compose the editor in another application

Link the GTK host to Umicom::ui_gtk4 and include umicom/provider_connections/gtk4.h. Call UmiProviderConnectionsGtkPresent(parent, application_id, profile_id) for the standard per-user window. To embed a panel, supply an absolute SQLite path with UmiProviderConnectionsGtkCreate, attach its borrowed widget, and call UmiProviderConnectionsGtkDestroy when the host retires it. Call these presentation APIs on the GTK thread.

Each database job owns its path, settings copy and temporary Data Server. The worker never reads widgets or retains an application runtime pointer. Destroy retires callbacks immediately; a worker may finish without updating a closed panel. Embedding hosts can use UmiProviderConnectionsGtkCanClose for normal close decisions, and must coordinate any forced shutdown themselves.

The persistence service guide explains revisions and explicit credential acquisition. For future request integration, the host must unlock the appropriate local profile, supply the correct credential registry, approve destinations and authentication methods, and clear credentials after use. Namespaces in this settings editor do not enforce those permissions.
