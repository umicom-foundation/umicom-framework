Format complete server-sent events

A server can send a sequence of text events over one HTTP response. This is called Server-Sent Events, or SSE. A native application must distinguish its text payload from the line-based fields which carry that payload. Framework's Web formatter prepares one complete event; it does not open a connection or send bytes.

1. Start with a bounded value

UmiWebSseEvent event = {
    .id = 7,
    .event = "update",
    .data = "first line\nsecond line"
};
char wire[16000];
size_t written = 0;
UmiStatus status =
    umi_web_sse_format(&event, wire, sizeof wire, &written);

Include umicom/web/sse.h and link Umicom::web. The event name holds at most 63 bytes plus its NUL terminator. Data holds at most 2047 bytes plus NUL. These are byte limits, so a Unicode character can occupy several positions. Do not truncate a UTF-8 character merely to make input fit.

2. Keep payload inside data fields

id: 7
event: update
data: first line
data: second line

The SSE line grammar uses named fields and a blank line to finish a record. Multiple data fields are joined with LF by the receiver. Framework turns CR, LF and CRLF in data into these separate fields, including empty and trailing lines. This follows the WHATWG event-stream grammar.

For example, data containing hello\nid: forged becomes two data fields. The text id: forged remains payload; it cannot change the event identifier. An event name containing CR or LF is refused instead. Event names are metadata, so inventing multiple names from one input would change the caller's meaning.

3. Publish only a complete record

The implementation first locates the terminator inside each fixed input array, validates UTF-8 and checks the event name. It then formats into private stack storage. Only after the complete record fits does it copy the bytes into the caller's output.

A capacity error therefore leaves both the output buffer and the optional length unchanged. Capacity includes the final NUL byte; the reported length excludes it. Check the status before sending anything. Old output may still be present after refusal and must not be mistaken for the requested new event.

if (status == UMI_STATUS_OK) {
    /* Send exactly written bytes through your checked HTTP transport. */
} else {
    /* Do not send wire: it was not replaced by this call. */
}

Output may overlap the input event because formatting finishes before publication. The separate length pointer must not overlap either object. This does not authorize supplying an invalid pointer or a capacity larger than its actual allocation.

4. Diagnose a refusal

StatusCheck
INVALID_ARGUMENTBoth objects exist, both fields contain NUL within their arrays, and the name has no line break.
PARSE_ERRORBoth fields contain complete valid UTF-8. Keep an incomplete incoming prefix pending rather than formatting it early.
CAPACITY_EXCEEDEDReserve space for field prefixes, line terminators and the final NUL. Payload size alone is insufficient.

At the fixed input limits, newline expansion is bounded. A 16,000-byte output buffer is sufficient for every accepted event in this API. A smaller buffer is useful when your own data limits are lower; always handle refusal.

5. Exercise the boundary cases

After configuring and building Framework in your own checkout, run the registered formatter regressions:

cmake --build build/windows-ucrt64-debug --target umicom-sse-format-test
ctest --test-dir build/windows-ucrt64-debug -R "^framework\.web\.sse_format\." --output-on-failure

The cases cover golden records, all line endings, field injection attempts, maximum fields, every insufficient capacity for a normal record, malformed input and overlapping output. A successful test run should report 26 passing cases. This describes the expected result, not an executed qualification claim. If a case fails, retain its output and compare the bytes against the expected wire record before changing the assertion.

6. Connect the next layer deliberately

SSE formatting is independent of model inference. An AI client still needs a receiving parser, provider-specific JSON decoding, request identity, bounded retained text, cancellation and transport ownership. Continue with incremental UTF-8 and request-owned model streams. Neither a formatted event nor a static example proves a live server is compatible.
