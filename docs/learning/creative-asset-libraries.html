Keep creative assets together

An asset library holds complete files in one portable collection. It can contain images, audio, video, lyrics and reference documents. Media, Music, CAD, Kitchen, Games, Web Studio and Mobile Studio use the same Framework library. A saved collection can be reopened by another creative workbench.

The library is separate from the scene project, song plan and provider pages. Importing a file does not place it on a timeline, decode a video, run code or upload anything. You choose those actions separately in tools that support the required format.

Create a collection

  1. Open Creative workbench → Asset library. The initial empty library lives in memory.
  2. Enter a title, such as Welcome tutorial, and choose Apply library title. The summary shows the applied title. Merely editing the title field does not rename the library.
  3. Choose a source file or enter its complete absolute path. Selection alone does not import it.
  4. Give the asset a unique ID, such as opening-image, and a readable name. IDs start with a letter or digit and may contain letters, digits, dots, underscores and hyphens. IDs are case-sensitive and have at most 63 ASCII bytes; names and titles have at most 191 UTF-8 bytes.
  5. Select the declared purpose and choose Import complete file. Wait for the result. The summary increases only when the whole file has been captured. Its original file can subsequently move or change without altering this captured copy.
  6. Repeat with other files. Select an entry to see its ID, name, declared purpose and complete size. Use the move buttons to change its order.

There can be up to 32 entries with a combined payload of 64 MiB. Empty files are supported. The purpose is your description of the file, not a format check. Two IDs may deliberately hold identical bytes; an existing ID is never silently replaced.

Save and reopen

  1. Enter a new absolute library path, for example C:\Projects\Tutorial\materials.umilibrary on Windows or /home/sam/projects/tutorial/materials.umilibrary on Linux. The parent folder must exist.
  2. Choose Save library to new file. A successful result reports the path and written size. Existing files are never overwritten. Choose another name for each saved edit.
  3. To reopen later, choose the saved library file and then Open complete library. If the current library has unsaved edits, save them first or explicitly enable replacement.
  4. Changing the selected library path or editing the collection clears replacement approval. Opening replaces the current collection only after every entry and the complete bundle have passed validation.

The file contains the library title, asset IDs, names, purposes and complete bytes in order. It omits original machine paths and does not look up external files. It is plaintext. A SHA-256 checksum detects damaged data; it does not prove who created the file or make untrusted media safe.

Use an asset

  1. Select it, then enter a new absolute destination and choose Export selected asset to new file to recover its original bytes. This does not convert its format.
  2. For a PNG, choose Copy selected asset to Assets editor, then switch to the Assets page. Preview or edit the independent capture there. Exporting an edited PNG does not alter the library entry; explicitly import the result under another ID if you want to keep it.
  3. Remove selected asset from library changes only the in-memory collection. Undo last removal restores the most recent removed capture while its ID and capacity remain available. Another removal or a successful Open replaces that one-entry undo record. Save a new library file to retain your chosen membership.

Recover from a refusal

ResultWhat to do
ID already existsChoose a different meaningful ID. The old entry remains intact.
Capacity exceededUse smaller captures or create a separate saved collection. No truncated file is imported.
Damaged or unsupported libraryKeep the file for diagnosis and open another saved copy. The current collection remains intact.
Destination already existsChoose a new filename. The existing destination has not been overwritten.
Cancelled or failed writeRead the result: a newly created partial or complete file may remain. Do not treat it as a successful save. Choose another filename before retrying.
Assets editor busyWait for its existing operation, then copy the selected library asset again.

For contributors

The portable asset_library.h owner controls membership and ordering. Insert transfers a capture only on success; Detach returns it to the caller. Borrowed captures remain valid only while their library owner retains them. Keep these operations on one owner thread.

The archive codec reuses the existing single-asset envelope and Framework SHA-256 implementation. Native Save streams existing bytes without allocating another whole-library buffer. Load temporarily holds the encoded bundle and decoded assets; retaining the previous collection or an editor copy uses additional memory. The last removed capture also occupies memory until replaced, reopened or closed. The GTK adapter transfers exclusive ownership to each worker and uses a weak widget reference on completion. Extend this shared boundary when adding a different host toolkit.

File operations require ordinary absolute local paths and trusted parent directories. Final symlinks, devices and oversized files are refused by the shared file reader. Ancestor directories are not a filesystem sandbox. Cancellation is checked around native reads and between bounded codec chunks.
