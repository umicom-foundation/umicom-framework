Find commands and windows

The shared command bar searches actions registered by the current application. Searching alone does not run a command, connect to a service, or submit an order.

Find an action

  1. Select the search field in the application toolbar.
  2. Type words describing the action. For example, build project can find an IDE build command. Words may appear in its title, description, keywords or identifier; every word must match somewhere.
  3. Read the results. An exact title appears before a title prefix. Other matches use the application's priority, with registration order breaking ties.
  4. Use Up or Down to choose a result. Press Enter to activate it, or click its button. A disabled result remains visible but cannot be activated.

ASCII letters are matched without regard to case. Other Unicode text is preserved and compared exactly; translated case folding and fuzzy spelling correction are not implemented. Quotation marks are ordinary search characters.

Browse more results

The footer shows the visible range and total, such as “11-20 of 23 matches”. Use Previous or Next for another page. Page Up and Page Down move a page at a time. Ctrl+Home and Ctrl+End choose the first and last result. Ordinary Home and End retain their text-editing meaning. Escape closes suggestions.

On narrow windows, the Commands button opens the catalogue even when there is not enough room for the search field. Paging still makes every result reachable. Widen the window to type a filter.

When results change

A refreshed catalogue keeps the selected action when its item identifier and command identifier still agree. If the action disappears, selection returns to the first match. A reused item identifier with a different command is treated as a new action. Always read the label before activation.

If pasted input exceeds the supported text capacity, the bar shows an error and hides the old results. Shorten the text to resume searching. An empty result list means no registered action matches; remove a word or scope prefix.

Using this in an application

  1. Register real actions with umi_ws_command_bar_model_add. Give each action stable identifiers, a clear title and useful search keywords.
  2. Create the GTK component with umi_gtk4_ws_command_bar_create_managed and install its activation callback.
  3. Refresh the model when availability changes. Continue checking permissions and current application state in the command handler; discovery does not grant permission.
  4. Destroy the command-bar controller before releasing the owner used by its callback. The controller disconnects retained widgets and event controllers.
The portable model also exposes selection and page snapshots for other frontends. GTK implements the keyboard and paging controls described here. Other renderers need their own native control integration.

The GTK integration follows the documented key event controller and popover focus behaviour.
