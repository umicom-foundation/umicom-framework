Create and check a PixVerse video

The PixVerse videos page in Umicom Media and Umicom Music submits a reviewed text-to-video request and checks its status when you ask. Framework owns the request, response and credential boundary so creative applications share one implementation.

Prepare your account and local key

  1. Use the official PixVerse API platform. Its key guide explains the API Keys page and key creation. API credits and web membership are separate.
  2. In the creative workspace, open PixVerse videos and choose Manage local profile and API keys. Create or unlock the local profile and save the provider key under the alias pixverse.
  3. Return to the panel and enter your local profile password. Media uses the umicom-media / default namespace; Music uses umicom-music / default. Save the key separately in each application profile you intend to use.

The alias identifies a key in the existing local credential service. Do not put keys in prompts, project documents, source files or Git. The request preview omits the key and password; the password field is cleared when a request starts.

Request a video

  1. Describe the scene, subject, movement, lighting and mood.
  2. Choose 1–15 seconds, an aspect ratio, and a resolution of 360, 540, 720 or 1080. Optional controls request generated audio and multiple shots. Account access to the adapter's documented model is required.
  3. Choose Review new video request. Inspect the destination and JSON body. Preparation does not send a request.
  4. Approve the displayed request and provider charge, then choose Send reviewed request.
  5. Copy the returned video ID before closing the page. A receipt means the remote job was accepted; it does not mean the video is ready.

Check progress

  1. Enter or retain the video ID. Enter the local password again if it was cleared.
  2. Choose Review status check, approve it, then send.
  3. Read the state. A ready result includes a private HTTPS result URL. Copy it only to an appropriate private destination. The panel does not automatically follow the link, download the movie or import it into the timeline.

Each status check gets a fresh trace identifier. Reusing a trace can return a cached response, so status plans are single-use too. There is no background polling.

Recover safely

  • Changing a prompt, setting, alias or password retires the old review. Prepare and approve again.
  • A timeout or local cancellation cannot prove that PixVerse did no work. Check the provider account before creating a replacement. The panel asks you to acknowledge that check after an uncertain creation.
  • A failed or moderated job state is displayed as such. It is not silently resubmitted.
  • If the native HTTP adapter is unavailable, the panel can prepare a request but cannot send it. Verify that the application was configured with its supported HTTP dependency.
  • Receipts currently live only in the panel. Copy the ID before leaving. Durable job history and automatic restart recovery are separate work.

Supported scope

This adapter provides text-to-video and one-job status lookup. Image/video uploads, reference characters, transitions, restyling, lip sync, VibeMV orchestration and local video rendering are not provided by this page. Wire model and route identifiers follow the official creation contract and status contract.

Framework's portable C interface also accepts a trusted transport for another platform. Such adapters must enforce verified TLS, bounded responses and no credentialed redirects. Native calls belong on workers. Never retry an uncertain creation automatically.
