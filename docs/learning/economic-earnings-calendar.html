Review economic events and earnings

An economic calendar lists scheduled releases such as employment figures. An earnings calendar lists company reporting events. Umicom's calendar reviews a saved snapshot: a set of observations copied at a stated time. It does not fetch a live feed or submit orders.

1. Open the calendar

  1. Open Umicom Trader and choose a guest session for this exercise.
  2. Use the workspace tool catalogue to add Economic Calendar, or open the Market Analysis layout that includes it.
  3. Choose Import calendar CSV and select calendar-example.csv. Download or copy the file first if your browser displays it.
  4. Expect two fictional rows: an employment release and an earnings event. Both are labelled example. They are not market forecasts or real company results.

2. Find and inspect events

  1. Type company in the search field and choose Apply filters. One row should remain.
  2. Select that row. The lower pane shows its source, observation timestamp, reporting period and unit. after-hours is a session label, not an exact clock time.
  3. Clear the search field. Expand Event filters. Select economic events or earnings, set an inclusive date range, country, currency or minimum importance, and apply.
  4. Use the divider between events and details to resize them. The workspace host controls docking and floating. Use Previous/Next page for snapshots containing more than 100 matching events.

Dates refer to each source's stated timezone. Mixed timezones are not converted or sorted as a global timeline. A blank actual value means “Not supplied”, never zero. Importance is a source label, not an investment recommendation. No matches does not establish that the market has no scheduled events.

3. Prepare your own snapshot

A CSV file stores a table as plain text: commas separate cells, and a newline ends a record. Use UTF-8, the common text encoding that represents characters as bytes. Use these exact 21 column names in this order:

id,kind,date,time,timezone,timing,status,country,currency,symbol,venue,title,period,importance,estimate,actual,previous,unit,source,observed_at,quality
FieldsRequired interpretation
id, source, titleNonempty event identifier, source label and description. Each (source,id) pair appears only once.
kindeconomic or earnings. Earnings also requires symbol and venue; a symbol alone is not globally unique.
date, time, timezone, timingDate is YYYY-MM-DD. exact requires HH:MM in the source timezone. pre-market, after-hours and unspecified require an empty time. The timezone label must be supplied; this importer does not validate it against a timezone database.
status, importanceStatus: scheduled, reported or cancelled. Importance: unknown, low, medium or high.
country, currencyOptional uppercase codes of two and three letters respectively. Syntax is checked; membership in a current code registry is not.
period, estimate, actual, previous, unitValues remain text. A unit is required whenever a value is supplied. Do not compare earnings per share with revenue, percentages or differently defined periods.
observed_at, qualityUTC observation timestamp YYYY-MM-DDTHH:MM:SSZ. Quality is example or imported; neither attests accuracy. There is no “live” import label.

Use double quotes around a value containing a comma, and double an embedded quote. Multiline cells, control characters, malformed UTF-8 and unknown enum labels are refused. Limits are 4 MiB and 4096 data records. Individual field capacities are documented in include/umicom/trading/event_calendar.h; the terminating zero byte also uses capacity. Empty header-only files represent empty snapshots.

4. Understand ownership and failures

UmiEventCalendarReadCsv copies and validates the entire input before returning an immutable model. UmiEventCalendarSelect filters that model without changing a trading workspace. The GTK adapter reads files on a worker and publishes the completed snapshot on the GTK thread. A failed import keeps the previous model. Quote refreshes keep the same calendar widget and its filters. Closing the workspace cancels pending reads and disables retained calendar controls.

SymptomRecovery
Import refused at record 0Check byte size, text encoding and prohibited control characters. The reader could not establish a valid record stream.
Import refused at a later recordCheck the schema and that logical record, including duplicate identities and field limits. A quoted multiline record may span physical lines.
Filters not appliedUse valid dates and uppercase codes; the end date must not precede the start. Previous rows remain visible until valid filters are applied.
No matching eventsClear filters and verify the supplied source coverage and observation time.
Workspace closedOpen a new calendar panel and import again. Retained views are read-only.

Current limits

There is no automatic download, subscription, timezone conversion, surprise calculation, alert scheduling or cross-panel persistence. Separate calendar panels own separate imports. Closing the panel discards its snapshot and filter state. The data source's terms determine whether a file may be redistributed. Use source revision and environment details when reporting a failed workflow.

Use date and search shortcuts

Press Enter in the search field to apply it. Choose Today (local date) to set both date limits to your computer’s current date, keeping the other filters. This compares source calendar dates; it does not convert events to your timezone. Clear filters restores all imported events, including when a date or country field contains invalid text.

Cancel a file import

While a file is being read, choose Cancel import to keep the current calendar. Cancellation takes effect before a late result can replace your rows. You can then import another file. Closing the workspace also retires an outstanding import.
