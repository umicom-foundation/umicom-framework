Search saved document text

A file's stored bytes and its editable text are not always the same. UTF-16 uses two-byte units, and Windows line endings contain two characters. Framework's document search decodes these formats before the shared search engine looks for matches.

1. Choose the reader

Include umicom/document/file_search.h and link Umicom::document. Use UmiDocumentSearchFileIndex for synchronous command-line work. For an interface, create a session with UmiDocumentFileSearchCreate; it reuses the Platform search worker. A session borrows its file index, so destroy the session before destroying the index.

2. Submit a saved-file search

  1. Create and rebuild a file index for an absolute workspace root you control.
  2. Construct a request with umi_search_request_default("needle"). Matching is literal. Case-insensitive matching folds ASCII letters only.
  3. Supply a result callback to the synchronous API, or use UmiFileSearchStartFiltered on the document session. An accepted asynchronous request has not finished yet.
  4. Read the session snapshot until active is false. Show rows only when ready is true. A failed or cancelled operation must not present its partial streaming matches as complete.
  5. Use UmiFileSearchMatchAt with the retained request identity. After an index change, search again.

3. Interpret positions correctly

Supported files are UTF-8, with or without a byte-order mark, and BOM-marked UTF-16 little-endian or big-endian. CRLF and CR become LF before matching. Lines and UTF-8 byte columns start at one. A byte column is not a count of displayed characters. UmiSearchMatchLocate checks the literal text at the reported position in a current decoded draft; it returns NOT_FOUND if the saved match moved. Studio's document owner performs this check before moving the caret and never replaces an unsaved draft to open a result.

4. Handle skipped files and failures

Malformed encoding, embedded zero characters and unsupported binary content increment binary_files_skipped. Files whose normalized text exceeds the requested bound increment oversized_files_skipped. The maximum decoded bound is 8 MiB. The serialized allowance is four times the requested text bound plus three bytes to accommodate encoding, line endings and a marker. Both cached size and actual reads are bounded. The read handle must name an ordinary regular file, not a link leaf; parent aliases may be followed, so this is not a filesystem sandbox. Ordinary Windows drive paths are accepted; network and device path forms are not.

Access failures and observable changes during reading fail the request. Fix access or refresh the index, then retry. Cancellation is checked between bounded read, decode and normalization phases; a blocking operating-system read cannot be interrupted by this token.

5. Extend decoding without duplicating search

The lower Platform layer exposes UmiSearchFileReader. Its immutable descriptor is copied into a session. A custom reader returns owned, NUL-free UTF-8 text with LF endings; its paired release callback handles every non-null returned allocation. Keep any reader context alive until session destruction drains the worker. Do not access UI widgets from the reader. Additional format support belongs in a higher document service that supplies this contract; Platform retains matching, filtering, revisions, cancellation and result limits. Existing raw-byte search APIs keep their earlier behavior.
