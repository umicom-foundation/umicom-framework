Typed AI workflows in C

Plan dependencies, check inputs and describe missing providers before accepting an AI job.

This lesson builds on native dependency graphs. You will use a small C API to describe ports, select a result and receive a deterministic plan. A port is a named input or output, such as a text prompt or an image. Its type describes the kind of value expected at that connection.

Preflight performs no inference or I/O. A valid plan is not a generated image, a qualified provider, a complete cache key or permission to execute. The native build, tests and installed example require qualification on your chosen toolchain.

1. Separate schema, availability and permission

QuestionWhere it belongsWhat preflight checks
Can this input accept an image?Operation schemaConnected port kinds must match exactly.
Is a provider usable now?Host capability registryReports host-declared unavailable nodes in the selected plan.
May this job write a file?Host policy and execution serviceSelected declared effects must fit the supplied effect mask. Actual paths and approvals are checked later.
Which steps are needed?Selected outputs and dependency graphIncludes all ancestors, then uses Framework's dependency ordering.
Has this provider actually worked?Qualification evidenceNot established by the schema or the available flag.

The service is exported as Umicom::ai_workflow_preflight. Its header is umicom/ai_workflow/preflight.h. Application clients describe their own operations; the reusable admission and ordering logic stays in Framework.

2. Describe an operation and its ports

UmiAiWorkflowNodeType inference = {
    .operation_id = "image.inference",
    .inputs = {{"prompt", UMI_AI_WORKFLOW_TEXT, true}},
    .input_count = 1U,
    .outputs = {{"image", UMI_AI_WORKFLOW_IMAGE, false}},
    .output_count = 1U,
    .available = false
};

The input is required. The output's required field has no admission meaning; use false for outputs. An unavailable operation can still have a known schema. That allows an editor to explain a missing engine without replacing it with synthetic success.

Supported value kinds are text, image, video, audio, document, conditioning, latent, number and Boolean. Conditioning and latent describe values passed between model stages; the preflight library does not interpret their tensors. Identifiers contain ASCII letters, digits, underscores, dots or hyphens. They are labels, not file paths. Identifiers must be nonempty and terminated within their fixed storage.

3. Connect nodes and select the desired result

A node refers to an operation type by index. A link stores source node, source port, target node and target port indices. Each input accepts one binding. An input can instead be marked externally supplied through bit p of supplied_inputs; it cannot be both supplied and linked. The executor must later validate the actual supplied value.

UmiAiWorkflowNode nodes[] = {
    {"prompt", 0U, 0U}, {"generate", 1U, 0U},
    {"watermark", 2U, 0U}, {"export", 3U, 0U}
};
UmiAiWorkflowLink links[] = {
    {0U, 0U, 1U, 0U}, {1U, 0U, 2U, 0U}, {2U, 0U, 3U, 0U}
};
size_t selected_outputs[] = {3U};

Selecting export also selects prompt, generation and watermarking. Two connections between the same pair of nodes are valid when they bind different destination ports. Two links to the same input are refused. Required-input and effect checks apply to selected nodes; malformed schemas, malformed links and cycles are refused anywhere in the description, including an inactive branch.

The public limits are 32 operation types, eight inputs and eight outputs per type, 64 nodes, 128 links and 64 selected output nodes. Count bounds are checked before array indexing. Unused fixed slots are ignored.

4. Receive a complete plan or preserve the old one

UmiAiWorkflowDiagnostic diagnostic = {0};
UmiStatus status = umi_ai_workflow_preflight(
    &description, UMI_AI_WORKFLOW_EFFECT_WRITE_FILE, &plan, &diagnostic);

if (status != UMI_STATUS_OK) {
    fprintf(stderr, "%s\n", umi_ai_workflow_issue_text(diagnostic.issue));
    /* plan still contains its previous complete bytes. */
}

The function needs temporary allocation. Both allocation failure and invalid input preserve the previous plan. The diagnostic identifies an affected node, link, port or type where applicable; SIZE_MAX means that no such index applies. Keep input arrays, plan and diagnostic storage separate and serialize changes during the call.

On success, plan.order contains the selected order and node_indices maps that order to original description nodes. Dependencies precede their consumers; ready independent nodes are ordered lexically by identifier. unavailable_indices follows that execution order. execution_ready only means every selected type was declared available.

Framework retains an order-only fingerprint. It omits parameters, model identities, provider revisions, policy and linked-port details. Never use it as a job approval token or a complete cache identity. A future executor must bind the reviewed graph, model and runtime identity, settings, input content, scoped capabilities and output destinations.

5. Build a consumer from an installed SDK

  1. Build and install a Framework SDK containing the new component using your normal owner-controlled qualification workflow. Preserve existing installed SDKs until the replacement is verified.
  2. Copy examples/ai_workflow into a separate application directory, or use the installed copy under share/umicom-framework/examples/ai_workflow. Its CMake file does not include Framework source files.
  3. Configure with the path to that qualified SDK. Replace the two example paths below with your actual SDK and copied example locations.
cmake -S C:/Projects/typed-workflow -B C:/Projects/typed-workflow/build -G Ninja -DUMICOM_SDK_ROOT=C:/SDK/Umicom
cmake --build C:/Projects/typed-workflow/build
& C:/Projects/typed-workflow/build/umicom-typed-workflow.exe

The example validates the selected installation with Framework's shared SDK helpers. Imported libraries and public headers must belong to that installation, the public contract fingerprint must match, and the environment must satisfy the consumer's C ABI requirement. The existing branding helper stages approved SVG resources and supplies the Windows ICO metadata. These checks reuse the installed Framework services.

If a previous CMake cache points to another SDK, configuration must refuse the mismatch. Use a new build directory or explicitly correct the cached package selection after reviewing it. Do not mix new headers with older libraries to bypass a missing component. Existing CMAKE_PREFIX_PATH discovery remains supported, but the discovered installation is still validated.

The consumer uses this package contract:

find_package(UmicomFramework CONFIG REQUIRED COMPONENTS ai_workflow_preflight)
add_executable(umicom-typed-workflow main.c)
target_link_libraries(umicom-typed-workflow PRIVATE Umicom::ai_workflow_preflight)

The example is expected to print:

Umicom Framework: typed workflow plan
1. prompt
2. generate
3. watermark
4. export
Host-declared ready: no
Unavailable: image.inference
Unavailable: brand.watermark
Planning only. No provider, model, watermark or export operation ran.

Configuration of this separate installed consumer, compilation, icon appearance and execution still require owner qualification. These are expected results, not a record of execution. A missing component at configuration time means the selected SDK does not export the service. Check the selected package path and producer revision; do not work around that by mixing arbitrary source headers with older libraries.

6. Qualify the contract and diagnose failures

Run each step separately and stop on an error. These producer commands are for the Framework checkout and its existing UCRT64 debug preset:

Set-Location C:\umicom\Umicom-Applications\framework
cmake --preset windows-ucrt64-debug
cmake --build --preset windows-ucrt64-debug --target umicom-ai-workflow-preflight-test umicom-ai-workflow-allocation-test
ctest --test-dir build/windows-ucrt64-debug -R "^framework\.ai_workflow\." --output-on-failure
DiagnosticRecovery
Missing or mismatched portCheck both operation schemas and all four link indices. Insert a real conversion operation if types differ.
Conflicting bindingKeep one source per input. Remove the external-input bit when connecting a link.
Required input missingConnect or supply that input on a selected node. Do not mark it optional unless the operation truly supports omission.
Effect deniedReview the requested operation and scope. A broader bit mask is not a substitute for user approval and resource policy.
Unavailable providerKeep the valid plan visible and explain the missing capability. Do not execute until the host has qualified and bound a provider.
Dependency cycleBreak the cycle in the whole description, even if that branch is not currently selected.
Allocation failureKeep the earlier plan, report failure and retry only after the host has sufficient resources.

7. Apply the service in applications

Media can describe generation, branding and export dependencies. Studio can inspect a workflow and show diagnostics before requesting a reviewed job. LLM and RAG applications can describe retrieval, context preparation and inference. Trader can use the same model for research pipelines, while order submission remains a separately authorized financial operation. These are integration designs; this library does not wire new product UI or implement those executors.

Umicom Media output must use the approved logo watermark through its existing native branding/export services. Merely naming a node brand.watermark does not apply a watermark. Bind a qualified implementation and verify the exported pixels before reporting completion.
