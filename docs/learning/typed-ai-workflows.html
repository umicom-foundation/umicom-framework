Typed AI workflows in C

Plan dependencies, check inputs and describe missing providers before accepting an AI job.

This lesson builds on native dependency graphs. You will use a small C API to describe ports, select a result and receive a deterministic plan. A port is a named input or output, such as a text prompt or an image. Its type describes the kind of value expected at that connection.

Preflight performs no inference or I/O. A valid plan is not a generated image, a qualified provider, a complete cache key or permission to execute. The native build, tests and installed example require qualification on your chosen toolchain.

1. Separate schema, availability and permission

QuestionWhere it belongsWhat preflight checks
Can this input accept an image?Operation schemaConnected port kinds must match exactly.
Is a provider usable now?Host capability registryReports host-declared unavailable nodes in the selected plan.
May this job write a file?Host policy and execution serviceSelected declared effects must fit the supplied effect mask. Actual paths and approvals are checked later.
Which steps are needed?Selected outputs and dependency graphIncludes all ancestors, then uses Framework's dependency ordering.
Has this provider actually worked?Qualification evidenceNot established by the schema or the available flag.

The service is exported as Umicom::ai_workflow_preflight. Its header is umicom/ai_workflow/preflight.h. Application clients describe their own operations; the reusable admission and ordering logic stays in Framework.

2. Describe an operation and its ports

UmiAiWorkflowNodeType inference = {
    .operation_id = "image.inference",
    .inputs = {{"prompt", UMI_AI_WORKFLOW_TEXT, true}},
    .input_count = 1U,
    .outputs = {{"image", UMI_AI_WORKFLOW_IMAGE, false}},
    .output_count = 1U,
    .available = false
};

The input is required. The output's required field has no admission meaning; use false for outputs. An unavailable operation can still have a known schema. That allows an editor to explain a missing engine without replacing it with synthetic success.

Supported value kinds are text, image, video, audio, document, conditioning, latent, number and Boolean. Conditioning and latent describe values passed between model stages; the preflight library does not interpret their tensors. Identifiers contain ASCII letters, digits, underscores, dots or hyphens. They are labels, not file paths. Identifiers must be nonempty and terminated within their fixed storage.

3. Connect nodes and select the desired result

A node refers to an operation type by index. A link stores source node, source port, target node and target port indices. Each input accepts one binding. An input can instead be marked externally supplied through bit p of supplied_inputs; it cannot be both supplied and linked. The executor must later validate the actual supplied value.

UmiAiWorkflowNode nodes[] = {
    {"prompt", 0U, 0U}, {"generate", 1U, 0U},
    {"watermark", 2U, 0U}, {"export", 3U, 0U}
};
UmiAiWorkflowLink links[] = {
    {0U, 0U, 1U, 0U}, {1U, 0U, 2U, 0U}, {2U, 0U, 3U, 0U}
};
size_t selected_outputs[] = {3U};

Selecting export also selects prompt, generation and watermarking. Two connections between the same pair of nodes are valid when they bind different destination ports. Two links to the same input are refused. Required-input and effect checks apply to selected nodes; malformed schemas, malformed links and cycles are refused anywhere in the description, including an inactive branch.

The public limits are 32 operation types, eight inputs and eight outputs per type, 64 nodes, 128 links and 64 selected output nodes. Count bounds are checked before array indexing. Unused fixed slots are ignored.

4. Receive a complete plan or preserve the old one

UmiAiWorkflowDiagnostic diagnostic = {0};
UmiStatus status = umi_ai_workflow_preflight(
    &description, UMI_AI_WORKFLOW_EFFECT_WRITE_FILE, &plan, &diagnostic);

if (status != UMI_STATUS_OK) {
    fprintf(stderr, "%s\n", umi_ai_workflow_issue_text(diagnostic.issue));
    /* plan still contains its previous complete bytes. */
}

The function needs temporary allocation. Both allocation failure and invalid input preserve the previous plan. The diagnostic identifies an affected node, link, port or type where applicable; SIZE_MAX means that no such index applies. Keep input arrays, plan and diagnostic storage separate and serialize changes during the call.

On success, plan.order contains the selected order and node_indices maps that order to original description nodes. Dependencies precede their consumers; ready independent nodes are ordered lexically by identifier. unavailable_indices follows that execution order. execution_ready only means every selected type was declared available.

Framework retains an order-only fingerprint. It omits parameters, model identities, provider revisions, policy and linked-port details. Never use it as a job approval token or a complete cache identity. A future executor must bind the reviewed graph, model and runtime identity, settings, input content, scoped capabilities and output destinations.

  3. Configure with the path to that qualified SDK. Replace the two example paths below with your actual SDK and copied example locations.

The example validates the selected installation with Framework's shared SDK helpers. 7. Apply the service in applications

Media can describe generation, branding and export dependencies. Studio can inspect a workflow and show diagnostics before requesting a reviewed job. LLM and RAG applications can describe retrieval, context preparation and inference. Trader can use the same model for research pipelines, while order submission remains a separately authorized financial operation. These are integration designs; this library does not wire new product UI or implement those executors.

Umicom Media output must use the approved logo watermark through its existing native branding/export services. Merely naming a node brand.watermark does not apply a watermark. Bind a qualified implementation and verify the exported pixels before reporting completion.

8. Plan the lifetime of intermediate results

An intermediate result is a value needed between steps. Imagine taking a photograph, editing it and inspecting the edited picture. The original pixels must remain available until editing finishes. Keeping both pictures forever wastes memory; freeing the original while editing is still reading it is unsafe. A lifetime describes the interval during which that value must remain usable.

A byte is a unit of storage containing eight bits. RAM is working storage used while a program runs. A model file on disk is not the same thing as the memory occupied by its loaded weights, temporary calculations and conversation state. Start with the deliberately tiny byte counts below so that you can check every addition by hand. They describe a teaching fixture, not a real photograph or model.

  1. Reserve 10 bytes for values that remain present throughout the fixture. This is the resident baseline.
  2. Source needs 100 bytes for its result and 5 temporary bytes. Its peak is 10 + 100 + 5 = 115. Releasing its temporary space leaves 110.
  3. Edit still needs the original 100 bytes while producing 40 new bytes and using 20 temporary bytes. Its peak is 10 + 100 + 40 + 20 = 170. After editing, release its temporary space and the original result. There are 50 live bytes.
  4. Inspect uses the edited 40 bytes and 7 temporary bytes: 10 + 40 + 7 = 57. Afterwards, release both temporary space and the edited result. The baseline of 10 remains.

Scratch means temporary storage used within one step. “Released outputs” counts output storage only; scratch also ends when its step finishes. The highest peak is 170, not the sum of the three peaks. The operations run sequentially.

Describe costs without pretending to know them

Include umicom/ai_workflow/memory_plan.h. Supply one UmiAiWorkflowNodeMemory per original node. The first element of output_bytes describes output port zero. The first bit of known_outputs says that estimate is known. scratch_known separately describes temporary storage. A known zero means no storage is expected; an unknown value means you have not established its cost.

UmiAiWorkflowNodeMemory costs[3] = {
    {.output_bytes={100}, .known_outputs=1, .scratch_bytes=5, .scratch_known=true},
    {.output_bytes={40}, .known_outputs=1, .scratch_bytes=20, .scratch_known=true},
    {.scratch_bytes=7, .scratch_known=true}
};
UmiAiWorkflowMemoryPolicy policy = {
    .resident_bytes=10, .byte_limit=200, .resident_known=true
};

A bit mask stores several yes/no answers in one integer. Bit zero has value 1, bit one has value 2 and bit two has value 4. Knowing output ports zero and one therefore gives a mask of 1 + 2 = 3. Bits outside the operation's output ports are invalid. Unknown bytes must be zero so that a leftover number cannot silently masquerade as a justified estimate.

The service reuses Framework's typed preflight and dependency ordering. It copies the resulting plan and reports the first and last step using each output. Two consumers reading the same output extend its lifetime; they do not count two copies. If you select a node as a requested result, all its outputs remain retained after the final step. Unselected branches do not contribute memory. Invalid graphs and malformed cost records are still refused.

Build and run the installed example

An SDK, or software development kit, contains headers declaring functions, libraries implementing them, and build information telling your tools how to link them. This example uses those installed files. It does not require a Framework source clone inside your application.

  1. Install a matching Framework SDK using its SDK composition guide. Its compiler architecture and runtime must match your application.
  2. Open PowerShell. Replace C:\UmicomSDK below with the actual installed prefix and choose a new writable project directory. Stop after any command reports an error.
  3. Copy the supplied complete example. A quoted path remains one argument even if it contains spaces.
Copy-Item -LiteralPath "C:\UmicomSDK\share\umicom-framework\examples\ai_workflow_memory" -Destination "C:\Projects\workflow-memory" -Recurse
Set-Location "C:\Projects\workflow-memory"
cmake -S . -B build -G Ninja -DUMICOM_SDK_ROOT=C:/UmicomSDK
cmake --build build
ctest --test-dir build --output-on-failure --no-tests=error
& ".\build\umicom-workflow-memory.exe"
& ".\build\umicom-workflow-memory.exe" --unknown-scratch

Copy-Item copies files. -Recurse includes the directory's contents. Set-Location changes the terminal's current directory. CMake's -S identifies source files and -B a separate directory for generated build files. Ninja is the requested build tool. Configuration prepares instructions; the build compiles and links; CTest executes registered checks. PowerShell's & runs the quoted executable path.

The intended first result is declared=complete peak=170 final=10. The unknown-scratch case reports declared=incomplete peak=150 final=10: 150 is the sum of known contributions at the busiest known step, not permission to fit the job into 150 bytes. These are expected fixture results; qualify the installed example on your toolchain.

Understand errors and limits

ObservationMeaning and next step
SDK configuration failsCheck the installed prefix, required component, compiler runtime and SDK identity. Do not substitute an unrelated source checkout.
COST diagnosticCheck the original node index, known mask and unused output slots. Unknown fields must contain zero.
WORKFLOW diagnosticInspect the nested typed-preflight diagnostic for missing inputs, a cycle, mismatched types or denied effects.
OVERFLOW diagnosticA sum exceeds the largest representable unsigned 64-bit number. Correct the estimates; wrapping the number would create a falsely small budget.
EXCEEDS_LIMIT verdict with an OK returnThe analysis succeeded and found insufficient declared budget. Reduce the workload or revise justified limits before a separate execution decision.
INCOMPLETE verdictMeasure or derive every missing selected cost. The service does not guess that an unknown cost is harmless.

This planner does not load models, free real image buffers, enforce a heap limit, measure RAM, inspect a GPU or fix an existing leak. Each output is assumed to own distinct storage. Zero-copy aliases, asynchronous kernels, parallel nodes and persistent caches require different lifetime contracts. Account for loaded weights, context state, externally supplied inputs, alignment, decoder expansion and runtime overhead. Do not add GPU memory to system RAM as though they were one interchangeable pool.

Keep the returned plan separate from the input arrays and diagnostic, and serialize calls. Allocate its bounded report on the heap when stack space is limited. Check allocation results. The service stages the complete report before publication and releases its private workspace on every return path. When graph settings, model identity or input dimensions change, recompute the plan.

Practice and check your reasoning

  1. Change the limit to 150. Explain why the complete fixture has a 20-byte deficit.
  2. Select the edited result instead of the final inspection node. Predict which two nodes are needed and why the final live total is 50.
  3. Add a second consumer of the source result. Draw the dependency arrows and locate its last reader before deciding when release is safe.
  4. Make one selected output size unknown. Confirm that this prevents a fit verdict even if all remaining known sums are small.
  5. Explain the difference between a leak, retained cache, legitimate model memory and temporary peak before diagnosing a crash.
