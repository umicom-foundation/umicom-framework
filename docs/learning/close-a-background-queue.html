Close a background queue without losing its work

A Notes application may be indexing documents when its user presses Close. The window must not freeze, but its controller must not free text that a worker is still reading. This lesson separates asking work to stop from proving that it has stopped.

You will build a small C application that indexes three in-memory note snapshots. You will run it once with a drain policy and once with cancellation. No file is saved, no window is opened and no external service is contacted.

1. Learn the three completion boundaries

A task can finish its callback before the queue updates its totals. Later, the queue can become idle while its worker threads are still leaving the operating system. Thread-local cleanup is one reason these moments differ.

Close admission→Request drain or cancellation→Poll native completion→Release the stopped queue
ObservationWhat it establishesWhat it does not establish
A task result is availableThe task runner recorded a result.Every queue worker has exited.
The queue is idleNo task is currently queued or running in the queue accounting.Native thread teardown has completed.
Shutdown completion returns OKAll workers were joined and queue accounting is empty.Every task succeeded, or every external action was reversed.

UmiTaskQueueTryFinishShutdown checks the last boundary without waiting for a running callback or its native cleanup. UMI_STATUS_BUSY means “keep the owner alive and check again later”. It does not mean “give up and free the queue”.

Keep the old route where it belongs. umi_task_queue_shutdown still waits for workers. Command-line tools and shutdown threads can use it deliberately. This update does not turn existing blocking callers into asynchronous code automatically.

3. Let accepted work drain

Run:

& ".\build\queue-shutdown\bin\umicom-queue-shutdown.exe" drain

The first worker waits at a practice gate so that the controller can demonstrate closing admission while work is still alive. The controller requests shutdown with both cancellation flags set to zero, makes a nonblocking completion pass, then opens that gate. Accepted work finishes; new submissions are refused.

Admission closed. The controller can process another event while workers finish.
Stopped: submitted=3, completed=3, cancelled=0, failed=0.
Notes word counts: 8, 7, 8.
Practice complete. Every worker was joined before its text snapshots left scope.

The word counter recognises spaces, tabs and line endings. It teaches task ownership, not a full international-language tokenizer. The three texts and all result counters remain in memory.

4. Cancel work that no longer needs to run

Run the cancellation version:

& ".\build\queue-shutdown\bin\umicom-queue-shutdown.exe" cancel

This time the controller calls UmiTaskQueueRequestShutdown(queue, 1, 1). The queue removes queued work and requests cancellation of its active callback. The callback checks its cancellation token and returns normally. The controller still waits for native completion through later polling passes before releasing the queue.

Admission closed. The controller can process another event while workers finish.
Stopped: submitted=3, completed=3, cancelled=3, failed=0.
Practice complete. Every worker was joined before its text snapshots left scope.
Cancellation is not rollback. A callback may already have written a file or sent a message before observing cancellation. The queue does not undo those effects. A callback that ignores cancellation remains running; its owners must remain alive.

Completed includes cancelled and failed tasks. Always inspect those separate counters rather than interpreting completed == submitted as “all work succeeded”.

5. Keep ownership visible

The Notes Master Controller owns its queue, task references and text snapshots. Its indexing worker reads those snapshots and writes its designated result. The queue retains accepted task records, but it does not retain arbitrary caller buffers.

ObjectOwner and release point
Text snapshot and result storageThe controller keeps them alive until the worker has finished using them. This lesson keeps them until all workers are joined.
Task returned by createThe caller owns one reference and releases it with umi_task_destroy. A successful submission adds the queue’s separate reference.
QueueThe lifecycle owner excludes all other queue users, confirms STOPPED, then calls UmiTaskQueueReleaseStopped.
Captured shutdown snapshotA plain-value copy. It remains readable after the queue is released, but it describes the earlier capture—not current activity.

The existing thread-lifetime reference fix remains intact. A thread record surviving early owner release does not keep the worker’s user_data alive, and does not turn the queue into a reference-counted object.

Connecting this pattern to a future graphical close handler

On Close, stop admitting new work and record that shutdown was requested. Schedule one completion pass per event-loop callback. On BUSY, return control to the toolkit. On OK, remove polling sources, exclude remaining aliases, and release the stopped queue and its context.

Do not copy the CLI’s sleep loop into a GTK callback. Do not block inside a worker while waiting for a UI action whose handler is blocked in a join. This delivery supplies the native contracts and executable lesson; it does not rewrite or qualify Studio’s or Desk’s close handler.

6. Read the complete C source

The file below is the compiled framework/examples/queue_shutdown/notes_index.c. Start with CountWords, then follow the controller from create to submit, request, poll and release.

/*-----------------------------------------------------------------------------
 * Umicom Framework | Sammy Hegab, Umicom Foundation | MIT
 * File: examples/queue_shutdown/notes_index.c
 * A Notes Master Controller owns the text snapshots and the queue. It stops
 * admission, optionally cancels work, then polls native completion before
 * releasing either owner. No files, windows or external services are opened.
 *---------------------------------------------------------------------------*/
#include "umicom/platform/task_queue.h"
#include "umicom/platform/threading.h"
#include "umicom/platform/clock.h"
#include <stdatomic.h>
#include <stdio.h>
#include <string.h>
#include <inttypes.h>

typedef struct NotesIndex {
    atomic_int permitted;
    atomic_int entered;
    const char *text;
    size_t words;
} NotesIndex;

static UmiStatus CountWords(UmiTaskContext *context, void *data)
{
    NotesIndex *index = data;
    int inWord = 0;
    atomic_store_explicit(&index->entered, 1, memory_order_release);
    /* This gate makes the ownership exercise repeatable. A real indexer would
     * receive its complete input snapshot before submission, then scan it. */
    while (!atomic_load_explicit(&index->permitted, memory_order_acquire)) {
        if (umi_task_context_is_cancelled(context)) return UMI_STATUS_CANCELLED;
        umi_thread_sleep_ms(1U);
    }
    for (const unsigned char *p = (const unsigned char *)index->text; *p != 0U; ++p) {
        int whitespace = *p == ' ' || *p == '\t' || *p == '\r' || *p == '\n';
        if (umi_task_context_is_cancelled(context)) return UMI_STATUS_CANCELLED;
        if (!whitespace && !inWord) ++index->words;
        inWord = !whitespace;
    }
    return UMI_STATUS_OK;
}

static uint64_t Now(void)
{
    UmiClock clock = umi_clock_system();
    return clock.monotonic_nanoseconds(&clock);
}

int main(int argc, char **argv)
{
    int cancel;
    UmiTaskQueue *queue = NULL;
    UmiTask *tasks[3] = {NULL, NULL, NULL};
    NotesIndex notes[3];
    const char *text[3] = {
        "Save the workshop notes before closing the window.",
        "A queued search owns its input snapshot.",
        "Cancellation is a request, not proof of completion."
    };
    UmiTaskQueueConfig config = {1U, 4U};
    UmiTaskQueueShutdownSnapshot snapshot;
    UmiStatus status = UMI_STATUS_OK;
    uint64_t start;
    if (argc != 2 || (strcmp(argv[1], "drain") && strcmp(argv[1], "cancel") &&
        strcmp(argv[1], "--self-test"))) {
        puts("Usage: umicom-queue-shutdown drain|cancel|--self-test");
        return argc == 2 && !strcmp(argv[1], "--help") ? 0 : 2;
    }
    cancel = !strcmp(argv[1], "cancel");
    if (!UmiThreadCanTryJoin()) {
        puts("NOT RUN: this build has no nonblocking native join adapter.");
        return 77;
    }
    for (size_t i = 0U; i < 3U; ++i) {
        atomic_init(&notes[i].permitted, i != 0U);
        atomic_init(&notes[i].entered, 0);
        notes[i].text = text[i];
        notes[i].words = 0U;
    }
    status = umi_task_queue_create(&config, &queue);
    if (status != UMI_STATUS_OK) goto cleanup;
    for (size_t i = 0U; i < 3U; ++i) {
        UmiTaskConfig task = {"Index Notes snapshot", CountWords, &notes[i], NULL, NULL};
        status = umi_task_create(&task, &tasks[i]);
        if (status == UMI_STATUS_OK) status = umi_task_queue_submit(queue, tasks[i]);
        if (status != UMI_STATUS_OK) goto cleanup;
    }
    start = Now();
    while (!atomic_load_explicit(&notes[0].entered, memory_order_acquire)) {
        if (Now() - start > 5000000000ULL) { status = UMI_STATUS_TIMEOUT; goto cleanup; }
        umi_thread_sleep_ms(1U);
    }
    status = UmiTaskQueueRequestShutdown(queue, cancel, cancel);
    if (status != UMI_STATUS_OK) goto cleanup;
    status = UmiTaskQueueTryFinishShutdown(queue);
    if (status != UMI_STATUS_OK && status != UMI_STATUS_BUSY) goto cleanup;
    puts("Admission closed. The controller can process another event while workers finish.");
    atomic_store_explicit(&notes[0].permitted, 1, memory_order_release);
    start = Now();
    while ((status = UmiTaskQueueTryFinishShutdown(queue)) == UMI_STATUS_BUSY) {
        /* A GTK host schedules the next pass in its event loop instead of
         * sleeping in a UI callback. This command-line lesson yields here. */
        if (Now() - start > 5000000000ULL) { status = UMI_STATUS_TIMEOUT; goto cleanup; }
        umi_thread_sleep_ms(1U);
    }
    if (status != UMI_STATUS_OK) goto cleanup;
    status = UmiTaskQueueCaptureShutdown(queue, &snapshot);
    if (status != UMI_STATUS_OK) goto cleanup;
    printf("Stopped: submitted=%" PRIu64 ", completed=%" PRIu64
        ", cancelled=%" PRIu64 ", failed=%" PRIu64 ".\n",
        snapshot.tasks.submitted, snapshot.tasks.completed,
        snapshot.tasks.cancelled, snapshot.tasks.failed);
    if (!cancel) printf("Notes word counts: %zu, %zu, %zu.\n",
        notes[0].words, notes[1].words, notes[2].words);
    status = UmiTaskQueueReleaseStopped(&queue);
    if (status != UMI_STATUS_OK) goto cleanup;
    puts("Practice complete. Every worker was joined before its text snapshots left scope.");
cleanup:
    if (queue != NULL) {
        atomic_store(&notes[0].permitted, 1);
        (void)UmiTaskQueueRequestShutdown(queue, 1, 1);
        /* CLI error cleanup may wait. A graphical controller instead retains
         * its context and keeps polling; never free a busy worker's payload. */
        UmiStatus joined = umi_task_queue_shutdown(queue, 1);
        if (joined == UMI_STATUS_OK) (void)UmiTaskQueueReleaseStopped(&queue);
        else fprintf(stderr, "Shutdown cleanup failed (%d).\n", (int)joined);
    }
    for (size_t i = 0U; i < 3U; ++i) umi_task_destroy(tasks[i]);
    if (status != UMI_STATUS_OK) fprintf(stderr, "Notes exercise failed (%d).\n", (int)status);
    return status == UMI_STATUS_OK ? 0 : 1;
}

7. Handle errors without discarding the owner

ResultNext action
INVALID_STATE before a stopChoose a shutdown policy and call RequestShutdown first. The polling call does not silently stop a usable queue.
BUSYKeep the queue and callback context. Return to other work and make another pass later.
Native join failureKeep the owner and record the failure. A later pass retains any workers already joined successfully. Investigate repeated failures.
Release failureThe queue pointer remains owned. Earlier successful native-handle releases remain released; retry the stopped-queue release after investigation.
NOT_IMPLEMENTEDThis build has no supported nonblocking join. Use an explicitly chosen blocking lifecycle worker, not a hidden fallback on the UI thread.

The native polling profile supports Windows and non-Android Linux. Other platforms report unsupported. The included fallback test compiles the real implementation with polling disabled and checks that the existing blocking route still works.

Queue locking and native scheduling are not real-time guarantees. Cancelling a large pending queue takes time proportional to its retained tasks. Set a user-facing deadline in the controller, but retain the context after that deadline until shutdown really completes.

Task callbacks must return through the task runner. Forced thread termination, jumping out of a callback, and calling pthread_exit from a queued task are not supported recovery mechanisms. A direct native-thread test covers a missing integer result; it does not make an abruptly exited queued task valid.

8. Check your understanding

Why can zero queued and running tasks still be insufficient?

The worker can be performing native thread-local cleanup. The regression test deliberately holds that cleanup open and verifies that queue polling returns BUSY despite idle task counters.

Can you discard task payloads after cancelling the task?

No. Cancellation is a request. Keep the payload until the callback has finished using it. This lesson uses successful queue shutdown completion as its conservative release point.

Why does releasing a stopped queue take a pointer to the owner pointer?

Successful release clears that pointer. A failure keeps it available for investigation and retry. Other uncoordinated aliases are still the caller’s responsibility.

Exercise: make one task return an I/O error.

Return UMI_STATUS_IO_ERROR from a practice task. After a drained shutdown, the queue should be STOPPED, completed should include that task, and failed should increase. Completion of the queue is not success of its jobs.

Exercise: keep the practice gate closed after cancellation.

A cooperative worker returns CANCELLED without needing the gate. A non-cooperative worker remains BUSY until it can return. Never test this by freeing the worker’s context while it is alive.
