Turn a design into a native Umicom application

Build a small Notes workspace from a reusable window, panel, text controls and a button. Then inspect the C source that makes the design real.

You do not need to know C to try the first exercise. You will use PowerShell to prepare a project, ask CMake to build it, and run a model check. Later, you can open the ordinary C files and see how each control is described.

This lesson uses temporary practice text. The Notes window does not save documents. Closing it discards its edits. Use fictional notes, not passwords, customer data or anything you cannot replace. The graphical route needs a GTK-enabled Framework SDK; a headless model check does not prove that the window has been tested.

1. Understand what each step proves

A design describes the parts of a window and their relationships. A project adds the files a compiler needs. A build turns those files into a program. Running that program is another step. Keep these steps separate: creating a folder of source files is not the same as compiling or testing them.

Canonical design→Source plan in memory→New project folder→Build and test→Run the window

The native exporter prepares six files. It writes them only into a new directory whose parent already exists. It refuses an existing directory, even an empty one. That rule protects handwritten code when you later generate another version.

FileWhat to look for
application.hThe declaration of the model-construction function.
application.cCalls to the canonical Framework document and node APIs. It describes the controls; it does not implement its own GTK widgets.
main.cA thin entry point. --check validates the model without opening a window; a graphical build runs the shared GTK adapter with no arguments.
CMakeLists.txtThe executable target, C23 requirement and Framework dependencies.
README.mdBuild boundaries, temporary-draft behaviour and regeneration guidance.
EXPORT-COMPLETE.txtSource revision, component count and file lengths. It is not a signature, checksum, successful-build record or proof of durability.

2. Prepare a practice SDK

An SDK is a set of headers and libraries another project can build against. Begin after the batch has been merged into your Framework checkout. Open PowerShell as your normal account. Do not use an administrator session.

These commands use the existing MSYS2 UCRT64 toolchain and your C:\umicom\Umicom-Applications checkout. This isolated SDK build does not replace the full application build and tests supplied with the batch.

$ErrorActionPreference = "Stop"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
$Framework = "C:\umicom\Umicom-Applications\framework"
$Lab = "C:\umicom\Practice\NativeDesigner"
$SdkBuild = Join-Path $Lab "sdk-build"
$Sdk = Join-Path $Lab "framework-sdk"
New-Item -ItemType Directory -Force -Path $Lab | Out-Null

& "C:\msys64\ucrt64\bin\cmake.exe" `
    -S "$Framework\examples\designer_native" `
    -B $SdkBuild -G Ninja `
    -DCMAKE_BUILD_TYPE=Debug `
    -DBUILD_TESTING=ON `
    -DUMICOM_DESIGNER_NATIVE_GTK4=ON
if ($LASTEXITCODE -ne 0) { throw "SDK configuration failed." }

& "C:\msys64\ucrt64\bin\cmake.exe" --build $SdkBuild --parallel 2
if ($LASTEXITCODE -ne 0) { throw "SDK build failed." }

& "C:\msys64\ucrt64\bin\ctest.exe" `
    --test-dir $SdkBuild --parallel 2 --no-tests=error --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "SDK tests failed." }

if (Test-Path $Sdk) { throw "Choose a new SDK install folder; do not replace another SDK." }
& "C:\msys64\ucrt64\bin\cmake.exe" --install $SdkBuild --prefix $Sdk
if ($LASTEXITCODE -ne 0) { throw "SDK installation failed." }

Keep this PowerShell window open; it holds the paths used in the following steps. A graphical build requires GTK4 development files. For a Linux or headless exercise, configure with UMICOM_DESIGNER_NATIVE_GTK4=OFF and also use UMICOM_NATIVE_PROJECT_GUI=OFF for the generated application below. That route builds and checks the model, not a graphical substitute.

The delivery's Linux native tests were run with GCC and Clang. Its GTK and Windows paths are supplied for local acceptance, not represented as already executed. A skipped display test must be recorded as not run.

3. Create an Umicom Notes project

The tool can first practise entirely in memory. The example constructs seven components, prepares a plan and releases the original model. The generated plan remains usable because it owns its own source text.

$Tool = Join-Path $Sdk "bin\umicom-designer-project.exe"
& $Tool --self-test
if ($LASTEXITCODE -ne 0) { throw "The native self-test failed." }

$Project = Join-Path $Lab "notes"
& $Tool notes $Project
if ($LASTEXITCODE -ne 0) { throw "Source preparation failed. Read the message before continuing." }

You should see six file names and their byte lengths, followed by a message that source preparation completed. Open the notes folder in File Explorer and inspect every file before building. There is no downloaded compiler, hidden shell command or running guest.

Running the same export again must report that the destination already exists. Do not delete a project you have edited just to make the command succeed. Use a new name, such as notes-next, and compare the files.

4. Build the generated program and check its model

$ProjectBuild = Join-Path $Lab "notes-build"
& "C:\msys64\ucrt64\bin\cmake.exe" `
    -S $Project -B $ProjectBuild -G Ninja `
    "-DCMAKE_PREFIX_PATH=$Sdk" `
    -DUMICOM_NATIVE_PROJECT_GUI=ON
if ($LASTEXITCODE -ne 0) { throw "Project configuration failed." }

& "C:\msys64\ucrt64\bin\cmake.exe" --build $ProjectBuild --parallel 2
if ($LASTEXITCODE -ne 0) { throw "Project build failed." }

& "C:\msys64\ucrt64\bin\ctest.exe" `
    --test-dir $ProjectBuild --no-tests=error --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "Project model test failed." }

& "$ProjectBuild\umicom_notes.exe" --check
if ($LASTEXITCODE -ne 0) { throw "Model validation failed." }
Model valid: 7 components. No window or file was opened.

The model test reconstructs and validates the canonical document. It checks the component hierarchy and supported properties, including the button's target references. It does not click controls or certify that the application has no bugs.

Try running the same --check command from a different folder. The design is compiled into ordinary C construction calls; the program does not look for application.umiapp in the current working directory.

5. Use the Notes window

& "$ProjectBuild\umicom_notes.exe"

In a GTK-enabled build, the shared adapter opens an Umicom-branded practice window. Edit the title and the larger note field. Choose Count characters. The result label counts Unicode scalar values in the note, including spaces and line breaks. It is not a word counter or a count of user-perceived grapheme clusters; an accented character written as two scalar values counts twice.

Replace the note with Aé🙂, with no final newline. The expected result is 3 Unicode characters. Change the title only, then count again: the title is not the button's source. Close the window, reopen the executable and observe that the original practice text returns.

The entry is limited to 4,096 characters and the editor to 262,144 scalar values. An insertion that would exceed the editor limit is refused as a whole. These are teaching-workspace bounds, not a large-document editor replacement.

This executable is a development build. On Windows, keep the UCRT64 runtime on PATH while running it. The export does not create a click-ready redistributable package or installer. Test installed startup separately before distributing a release.

6. Read the C behind one control

Open application.c. Each control is a canonical UmiDeclNode. Its identity lets a command refer to the same control without guessing its screen position.

status = umi_decl_node_init(&node, "count", "button", "content");
/* Check status after every call, as the complete generated file does. */
status = umi_decl_node_set_attribute(&node, "title", UMI_DECL_VALUE_STRING, "Count characters");
status = umi_decl_node_set_attribute(&node, "action", UMI_DECL_VALUE_STRING, "text.count");
status = umi_decl_node_set_attribute(&node, "source", UMI_DECL_VALUE_STRING, "notes");
status = umi_decl_node_set_attribute(&node, "target", UMI_DECL_VALUE_STRING, "result");
status = umi_decl_document_add_node(document, &node);

This shortened reading excerpt shows the relationships; use the generated file's complete failure checks. content is the parent panel. notes identifies the editable source. result identifies the destination label. The shared adapter understands text.count; it does not evaluate source text as code.

The project's main.c constructs the model and calls Framework. Reusable widget construction, validation and action handling stay in Framework instead of becoming a private copy in every application.

7. Change a model without replacing your source project

The batch includes a readable notes.umiapp. Copy it to your practice folder. Change its window title or panel spacing, then export into a different new directory.

Copy-Item "$Framework\examples\designer_native\notes.umiapp" "$Lab\notes.umiapp"
# Edit the copied file in your text editor before the export.
& $Tool export "$Lab\notes.umiapp" umicom_notes_next "$Lab\notes-next"
if ($LASTEXITCODE -ne 0) { throw "The changed model was not exported." }

For example, change property content spacing 12 to property content spacing 20. Rebuild the newly generated project and compare the spacing. A misspelled component type, unsupported property, missing parent, parent cycle or invalid action target is an error—not something the exporter silently ignores.

ComponentProfile rule
windowExactly one root window and one content child; width/height 240–8,192.
paneHorizontal or vertical children; spacing 0–64.
splitExactly two children; orientation and initial separator position.
tabsOne to sixteen children; their titles label the tabs.
labelText without markup interpretation; no children.
textA single-line entry, with optional placeholder.
editorA scrollable multiline text area, with wrap and read-only settings.
buttonThe explicit text.count binding, or disabled when no action is assigned.

The profile allows up to 128 nodes and depth 32. It does not claim the entire Framework catalogue is available through this particular exporter. Tables, charts, images, menus, arbitrary command bindings and file-save actions are not part of this profile yet.

A note about the existing text format

The original line-oriented parser infers property types. A quoted value such as "123" is still inferred as an integer. Quotation does not add a new typed-string syntax. The native exporter preserves exact types and UTF-8 bytes when given a document built through the C API, but it does not rewrite this older grammar. Multiline strings and strings needing both quote styles are best constructed through the explicit C API in this profile. A missing closing quote is now rejected.

8. Understand ownership and failed changes

The document owns its nodes. A prepared source plan owns its generated text. A file view borrows text from that plan, so you must not free it or keep it after destroying the plan. The GTK window creates its own widgets and does not keep the original document alive.

For a property edit, the Framework first prepares and validates the replacement. Only a successful edit changes the stored attribute. An invalid integer such as wide must not replace a previous valid width. A failed edit therefore leaves the previous value available for correction.

Removing a panel from a model removes its descendants as one change while retaining the order of unrelated nodes. Framework now marks the entire subtree before compacting the storage, so an intermediate parent does not disappear before its grandchildren are discovered. Try this only in a copy or a practice document. The new exporter does not add Undo/Redo to the existing authoring UI.

9. Troubleshooting

What you seeNext step
Destination already existsChoose a new child directory. Preserve and compare the old project.
Unknown property or unsupported componentCheck the eight-component profile. Do not assume a successful palette entry elsewhere is supported by this exporter.
Invalid source lineCheck the application statement, parent identifiers and closing quotes. The input must be a regular text file of at most 1 MiB, with no embedded NUL.
No native GTK adapterSelect a GTK-enabled SDK, or deliberately build with the GUI option off for model checks only.
Missing runtime DLLUse the existing UCRT64 development PATH. A release needs separately qualified runtime packaging; do not download individual DLLs from unknown sites.
Partial directory after an I/O failureKeep it for review, correct the error and retry into a different new directory. Do not treat a completion marker alone as proof of a successful run.
Character count differsCheck for a final newline, spaces or combining characters. The title is separate from the note field.

10. Exercises and answers

Exercise A. Generate a Notes project, add a comment to its C source and repeat the export to the same destination. What should happen, and why?

Answer A

The export must fail without changing your comment. Generation is not permission to overwrite a handwritten project. Use a new destination and merge deliberately.

Exercise B. Change source notes to source heading in the count button's model. Should the exporter accept it?

Answer B

No. A count action needs a text entry or editor as its source and a label as its target. The heading is a label, so this binding is invalid.

Exercise C. Build with the GUI option off and run --check. Does a passing result prove that clicking the button works?

Answer C

No. It proves the generated model can be constructed and validated in that build. Graphical behaviour needs the actual GTK adapter, display and interaction checks.

Exercise D. Create a source plan, then change the original model. Which title belongs in the existing plan?

Answer D

The title captured when the plan was created. The plan owns a snapshot of generated source. Prepare a new plan to export a later edit.
