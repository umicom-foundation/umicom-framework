Saving local broker connection settings

A connection setting tells one program how to reach another program. In Umicom Trader, a port identifies the local broker endpoint and a client ID identifies this API connection. These values are different from your broker username and password.

The shared Framework broker window can save separate Paper and Live settings. It stores the selected program, port and client ID on your computer. A saved file never contains broker credentials, an authentication code, an account balance or permission to connect automatically.

Save your selected mode

  1. Open the broker connection window in Umicom Trader. Select Paper or Live and check which program you are using.
  2. While disconnected, enter the API port configured in your broker program and an unused client ID.
  3. Expand Saved Paper and Live settings.
  4. Review the Settings file field. Its default is umicom-broker-profiles.txt in your operating system's user configuration directory. You may enter another absolute path in an existing directory you control.
  5. Choose Save selected mode. Wait for the confirmation. The other mode's saved settings are preserved.

On Windows, an absolute path includes a drive and directory, such as C:\Users\YourName\AppData\Roaming\umicom-broker-profiles.txt. The actual default depends on your operating system configuration; use the path displayed by the application. Do not put this personal settings file in a source repository.

Load settings before connecting

  1. Select the mode you intend to use. Loading Paper settings does not switch the window to Live.
  2. Choose Load selected mode and wait for the result.
  3. Check the program, port and client ID. Loading Live settings clears the acknowledgement checkbox.
  4. Authenticate in the broker program itself. Check the actual Paper or Live login there.
  5. When you are ready, explicitly choose Connect read-only. Saving or loading alone never connects.

The existing broker inspector reads observations. It does not place, modify or cancel orders. A saved Live mode describes intent; it does not prove which account the broker program has authenticated.

Understand a settings file

UMICOM-BROKER-PROFILES 1
paper 0 7497 35
live 0 7496 35

The first line identifies the format and its version. Each following line contains a mode, program number, port and client ID. Program 0 means TWS and 1 means IB Gateway. The format uses decimal digits and newline separators. It deliberately rejects unknown fields and unsupported versions rather than guessing what they mean.

Use the application to edit settings. Adding a password or an acknowledgement field makes the file invalid; it cannot enable authentication or bypass the connection policy.

When an operation fails

MessageWhat to do
No saved settings foundThe current fields stay unchanged. Check the path or save your settings for the first time.
Parent directory must already existChoose an existing directory you control. The service does not create directories.
Settings are in useWait for the other application to finish. Do not delete the .umi-guard file: its presence alone does not mean the settings are busy.
Damaged, too large or unsupportedKeep the file for investigation. Choose a different filename to save a new profile. The application refuses to replace the damaged file.
Fields changed while loadingReview the current fields and load again if desired. A stale result is not applied over changed connection settings.
Operation failed after savingReload and inspect the result before retrying. A late I/O error may occur after the replacement was published.

Use the Framework service

The public header is umicom/broker_connectivity/access_profiles.h. UmiBrokerAccessProfilesLoad reads a complete pair of settings without changing files. UmiBrokerAccessProfilesStore updates one mode under a cooperative file lease and publishes a complete replacement. Calls may block, so graphical applications call them from a worker.

A cooperative lease is an operating-system handle that participating writers agree to hold while they update a file. All writers must use the same guard path. It does not stop arbitrary programs that ignore the protocol. The parent directory must remain trusted and stable.

A complete-file replacement prepares and flushes a new file before publishing it. It reduces partial-write risk, but is not a guarantee against power loss. The Framework preserves the established platform storage contracts and their limits.

Closing the broker window does not cancel a save already running. Its completion cannot repaint the closed window. Reopen and load to inspect the saved result.
