Connecting a native language server

A language server is a separate program that analyses source code and answers requests such as completion or navigation. Framework's process stream carries bytes between the application and that program. The language runtime adds message framing, initialization and request tracking. Opening a process stream alone does not make an editor language-aware.

Prepare the connection

  1. Install a language server that supports standard-input and standard-output communication, such as clangd for C. Let the user select the executable; do not run an executable supplied by an untrusted workspace automatically.
  2. Keep the executable and project folder as absolute paths. Windows inputs use UTF-8. Native Windows conversion preserves names such as café and 文, provided the external server also supports those paths.
  3. Pass each argument separately. An empty string is a real argument, and spaces or quotes do not need shell escaping. Do not turn an argument list into a shell command.
  4. Leave merge_stderr at zero for a language protocol. Diagnostic text on standard error must not become protocol input. Standard error goes to the parent's diagnostic destination; a Windows GUI host without one uses a null sink.
  5. Run the connection on a persistent worker. Start borrows configuration strings until it returns. Thereafter the stream owns the direct child and its communication handles. Use one calling thread at a time.

Use the appropriate layer

For an editor, use umi_language_runtime_platform_open_document with a configured server profile. The runtime creates or reuses a workspace server, initializes the protocol and sends document state. The low-level umi_language_runtime_process_stream_start API is for transport implementations and native integration fixtures. It returns a null stream on failure.

The parent environment is inherited. Framework does not change the parent's current directory or environment. Windows uses its normal search rules for bare executable names; POSIX uses PATH. Absolute paths make selection more predictable. POSIX retains the native executable-text-file fallback through /bin/sh, with separate literal arguments; this is another reason to trust the selected executable.

Select a configured server

UmiLanguageRuntimeServerManagerStartProfile starts a caller-selected enabled profile, completes initialization and transfers the server to the manager only after success. Existing workspace entries are not silently replaced. The older language-based entry point reuses a ready server and otherwise reads the built-in profile's current registry values, including user-selected paths and disabled state.

UmiLanguageRuntimeProbe provides a shorter connection check: it starts a real server, records its advertised capabilities and closes it. The GTK connection panel exposes this as an explicit user action. It does not activate completion in an editor or send document text. No configuration is saved by the probe.

Read, write and close

  1. After a successful start, exchange framed protocol messages. Reads may return only part of a message, and a read may contain several messages. Keep framing in the language runtime.
  2. Treat UMI_STATUS_NOT_FOUND from read as no available bytes or exhausted output. Check is_running for process lifetime, and drain remaining stdout after exit. Other read errors must be reported.
  3. A write either reports success or an error. An error can follow partial delivery, so do not blindly repeat the frame. Writes are synchronous and may block if the child stops reading; they must not run on the GUI thread.
  4. Request the protocol's normal shutdown and exit first. Use stop when the server must be closed. Windows closes stdin, waits for the requested interval and terminates a child that remains. POSIX sends SIGTERM, waits, then SIGKILL if needed.
  5. Destroy the stream once its last user has finished. This closes native handles and stops a surviving direct child. Neither stop nor destroy manages descendants or provides a security sandbox.

Troubleshooting

An invalid working directory or failed POSIX executable lookup is reported during start. On Windows, malformed UTF-8 is rejected rather than replaced with different characters. Command lines may contain at most 32,767 UTF-16 units including the final NUL. Output is kept as bytes and is not converted through the current Windows code page.

A process that launches can still exit during its own initialization, for example because a shared library or configuration file is missing. Preserve the external tool's diagnostics. On POSIX, let Framework reap its own child: another thread's wait operation or automatic SIGCHLD reaping can invalidate lifetime accounting.

Extending the transport

The native backends share Framework's Windows argument encoder and POSIX launch preparation. Add native fixtures for argument boundaries, Unicode paths and failed child setup before extending launch behaviour. Keep stderr out of protocol stdout. The POSIX input socket suppresses SIGPIPE for the connection without replacing the application's signal handlers.

The shared virtual-machine process channel has a different environment and lifetime policy. Do not substitute it solely because both APIs use pipes. A transport change must preserve the caller's documented environment, argument and shutdown behaviour.
