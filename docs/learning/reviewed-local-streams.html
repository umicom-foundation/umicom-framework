Stream an approved local AI request

Streaming displays text while a model is still generating it. Review and persistence answer different questions: was this request approved, and was its final outcome saved? Umicom Framework combines these responsibilities through a reviewed stream controller while retaining the existing raw transport and synchronous provider interfaces.

1. Establish owners before work begins

Create UmiAiLocalTransport at single-threaded process startup, before starting a toolkit or other workers. It owns the shared HTTP library lifetime. Create a Data Server, AI runtime and cancellation token, then register the canonical local provider with its port, deadline and borrowed token. Create a workspace that borrows the runtime and storage connection.

Keep these owners alive until their dependants are released. All reviewed-controller calls use the transport's creating thread. Workspace, runtime and Data Server operations remain serialized; the cancellation token is the separately thread-safe signal.

2. Prepare and review the request

UmiStatus status = UmiAiWorkspacePrepare(workspace, "draft.one",
    UMI_AI_WORKSPACE_DRAFT, "umicom.local-chat", "selected-model", NULL,
    "Explain this function's ownership.", "author", 256);
if (status == UMI_STATUS_OK) {
    /* Obtain this decision from the application's review workflow. */
    status = UmiAiWorkspaceReview(workspace, "draft.one", "reviewer", true);
}

A grounded draft includes selected source passages and a corpus revision. Streaming preserves the same final citation validation. The current stream path accepts only draft and grounded-draft jobs backed by Framework's canonical local-chat adapter. Tools and other providers keep their existing interfaces. An adapter name alone does not prove its private instance type.

3. Create without contacting the model

UmiAiWorkspaceStream *stream = NULL;
UmiAiWorkspaceStreamOptions options = {
    .maximum_wire_bytes = 16U * 1024U * 1024U,
    .allow_network = true
};
status = UmiAiWorkspaceStreamCreate(workspace, "draft.one",
    transport, &options, &stream);

Create requires an approved job and current policy admission. It copies the request and canonical endpoint settings, retains workspace execution storage and prepares the raw transport. It starts no worker, sends no HTTP and writes no RUNNING record. An already successful job returns ALREADY_EXISTS; it is not generated again. Failure leaves the output unchanged.

The registered adapter and borrowed cancellation token must remain alive. Changing the registered provider instance, port, deadline or token before Start is detected. These checks govern a local ownership contract; they do not authenticate a model server.

4. Start only after durable RUNNING

status = UmiAiWorkspaceStreamStart(stream);

Start rechecks current policy and the frozen adapter binding. It writes RUNNING before launching the raw worker. A failure before that write leaves a prepared owner; abandoning it preserves the approved job. A failure afterwards settles a failed or cancelled outcome and keeps the controller available for inspection and release. Neither path retries network generation automatically.

PhaseMeaningRelease
PREPAREDNo worker has started through this controller.May abandon without changing approval.
RUNNINGThe durable start succeeded; native work or settlement is outstanding.Refused, even when raw transport has finished.
SETTLEDFinal validation and save were attempted once.Checked native release is allowed; a release failure retains ownership.

5. Observe partial text without lending GUI memory

Poll returns a copied phase and transport snapshot. CopyText returns separately owned complete UTF-8 text; release it with UmiAiResponseStreamTextFree. The producer never writes into a widget or console buffer. Text snapshots may be newer than an immediately preceding poll because the worker continues between calls.

Partial text is a draft. Cancellation, invalid protocol, a missing terminal event, an invalid citation or a transfer failure can reject it. Saved responses currently hold at most 4095 UTF-8 bytes; the raw stream is bounded to that capacity. Wire-byte limits separately bound the encoded response.

6. Finish, then read both outcomes

status = UmiAiWorkspaceStreamTryFinish(stream);
if (status == UMI_STATUS_OK) {
    UmiAiWorkspaceStreamResult result;
    status = UmiAiWorkspaceStreamReadResult(stream, &result);
    /* Inspect result.operation_status AND result.publication_status. */
}

TryFinish returns BUSY while native joining is incomplete, or NOT_IMPLEMENTED where that platform lacks nonblocking join. Finish is the explicitly blocking alternative. Successful joining is followed by final response checks and one save attempt. Persistence itself may take time: TryFinish is not a guarantee that every part of the call is nonblocking.

An OK finish return means the settled outcome can be read. It does not mean the model succeeded or the result was saved. A successful model result with a failed publication requires recovery, not automatic repetition. Reopening a stored RUNNING record marks it interrupted.

Before blocking Finish during shutdown, call Cancel. A later change to the provider token is only forwarded on owner-thread Start, Poll or Finish entry; a thread already blocked in Finish cannot forward it until the join returns. Event-loop clients should keep polling and trying completion. Cancellation requests never prove that native storage is safe to free.

7. Release in dependency order

  1. Join and settle the reviewed stream.
  2. Read the model and publication outcomes.
  3. Destroy the stream with its checked pointer-to-pointer API; keep it on failure.
  4. Release the workspace, then runtime, cancellation token and Data Server.
  5. Release the transport after all raw and reviewed request owners are gone.

A native release failure retains the controller. Do not free its borrowed workspace or token underneath it. Independently copied text remains valid after successful controller destruction.

8. Run focused qualification

cmake --build build/windows-ucrt64-debug --target umicom-reviewed-local-stream-test umicom-local-provider-settings-test umicom-local-provider-settings-offline-test
ctest --test-dir build/windows-ucrt64-debug -R "^framework\.ai_workspace\.(reviewed_stream\.|local_provider_settings)" --output-on-failure

With HTTP enabled, this selects 23 reviewed scenarios and two settings tests. Cases cover approval, policy/binding changes, wrong-thread calls, abandoned preparation, real loopback success, grounded citations, overflow, truncated transfer, deadline, cancellation, join/release failures and SQLite publication failure. The peer uses an ephemeral loopback port and synthetic protocol data; no model or hosted service is involved.

The publication fixture refuses to overwrite an existing failed-run database. Preserve that file for diagnosis, then remove or rename it explicitly before rerunning. Skipped capability checks are missing coverage, not passes. Source and registration checks alone do not establish compilation or runtime correctness.

9. Build an application against the installed package

The independent reviewed-chat example shows the complete C23 lifecycle with a SQLite file, a user review prompt and Ctrl+C. It uses exported SDK targets and shared SVG/ICO branding. Compilation, installed-consumer execution and live inference require separate qualification.
