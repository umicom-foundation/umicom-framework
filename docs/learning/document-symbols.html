Explore a source document outline

To find names across the server's project index, use project symbol search. Document outlines remain the default.

A document outline lists declarations such as functions, classes, fields and variables. Framework owns the captured source, language-server request and returned symbol tree. Studio supplies discovery controls and the current project folder.

  1. Open a source document. The outline uses the whole current draft, including unsaved changes. Read-only documents are supported.
  2. Choose Symbols… in the editor command bar, or Document symbols… in the Outline panel. Scroll the command bar horizontally if necessary. Opening the form captures the draft; it does not start a program.
  3. Enter a trusted language server's absolute executable path, arguments and project folder, or choose Load saved server. The same per-language local settings serve completion, formatting, source information and navigation. Loading settings does not start the server. Paths and arguments are unencrypted preferences, so keep credentials out of them.
  4. Choose Request document symbols. The selected local server receives the captured source and can inspect the project folder. The temporary connection closes before its result is published.
  5. Search the list for a name. Rows show the symbol kind, any deprecation marker, its URI and position, and available detail or container text. Indentation means the server supplied an explicit parent-child relationship. Flat server results remain flat even when they name a container.
  6. Select a row and choose Open selected location. A hierarchical symbol selects its identifier range. A flat result opens the starting caret of its reveal range. Existing unsaved target drafts are kept. Back and Forward use the normal document navigation history; this action neither saves nor edits text.

Troubleshooting

What you seeWhat to try
An empty outlineThe server may return no symbols for this document. Check its language and project settings. A temporary connection may not have the indexing state available to a persistent editor session.
Stale capture or unavailable openingClose the form and capture again after editing, moving the caret, saving or changing permissions. Changing server settings invalidates the current list. No stale row is used to edit source.
Unsupported capabilityThe server must advertise document symbols, document open/close synchronization and UTF-16 positions. This workflow does not handle arbitrary server-to-client configuration requests.
Timeout or excessive responseThe native form has a five-second read budget, a 65536-byte message capacity including the escaped draft and JSON envelope, and at most 4096 parser tokens. A large outline or draft can exceed this. Synchronous launch and writes may finish before cancellation.
A destination cannot openThe selected range must fit the current target. New destinations require a supported local file URI. A source file moved since indexing or an out-of-range result is refused without replacing the current draft.

Extend the outline services

UmiLanguageSymbolCatalogueCreate reads either hierarchical document symbols or flat symbol information. Every row owns its strings and preserves its source range. The catalogue stores explicit children in preorder: a parent appears before its descendants, and each child holds its parent's stable row index. Root rows have parent == SIZE_MAX. Never infer hierarchy from flat container names or overlapping ranges.

The reader allows 4096 rows, 32 hierarchy levels, 4096 UTF-8 bytes per name, detail or container, 8192 URI bytes and 1 MiB of JSON. An invalid row fails the complete read. Names consisting only of Unicode whitespace are rejected. Unknown positive symbol kinds remain available to the host, which displays a generic kind; unknown positive tags are ignored. Deprecation tags are retained. Only the decoded catalogue owns strings returned by At; they expire on Destroy.

UmiLanguageSymbolQueryNative uses the shared source-query connection owner, advertises hierarchical support and validates all ranges referring to the captured document with one immutable text-position index. It has the smaller native transport limits described above. A supplied-server call requires a new connection in its starting state; it must not take over an active editor session.

The GTK form shares inspection-only capture, worker cancellation and saved settings with the other source tools. Symbols never acquire Stage or Apply permission. Rows store decoded metadata separately from their display labels: clicking Open uses UmiDocumentCoordinatorOpenSourceRange, not text parsed back from a label. This preserves Unicode coordinates and existing drafts.

Current boundaries

This searchable list shows indentation but is not a persistent collapsible tree. It refreshes only when requested; automatic indexing and caret tracking are not implemented here. A new local destination is loaded synchronously after explicit Open. Local path syntax checks are not a project confinement boundary and may follow filesystem aliases. The language session owns only the direct child, not descendants started by a server.
