Review complete document replacements

A replacement set captures all currently open documents and prepares the proposed text before editing anything. You can inspect each complete comparison, then apply the set together. If one captured document changed, closed or became read-only, the operation refuses the entire set.

Use the Studio editor

  1. Open the documents you want to change. This workflow includes pinned and untitled drafts and requires every captured document to be writable. Close unrelated documents first if they should be outside the set.
  2. Enter a literal word or phrase in Find and its new text in Replace with. An empty replacement removes matching text. An empty Find value is refused. Smart case ignores ASCII letter case unless the search contains an uppercase letter; this is not a regular expression or a language-aware symbol rename.
  3. Choose Review Complete Set in the editor toolbar, or Review Complete Replacement Set in command search. No source is changed when the window opens.
  4. Use Previous and Next to inspect the complete captured and proposed text. Choose Mark this draft reviewed for each changed document. Unchanged drafts do not need a review acknowledgement.
  5. When all changed drafts are reviewed, select I approve all reviewed draft changes, then choose Apply complete set. Approval does not apply changes by itself.
  6. Check the edited documents. Use Undo in a particular document to restore that document's captured draft. Earlier unsynchronized typing has its own prior Undo step. Save the documents separately when you are ready.

Close abandons an unapplied set without changing any draft. Applying a complete set does not create a project-wide Undo command. Each document keeps the existing bounded Undo history. Documents opened after capture are outside the set.

Recover from a refused operation

If text, caret, selection, language, save state, path, conflict state or write permission changed, close the review and capture again. This includes changing text away and back: its revision is different. A read-only member prevents capture; the existing Review Open Documents workflow can instead review and skip documents individually. Its earlier accepted edits remain if a later document fails, whereas the complete-set workflow applies all its changes together.

A set is limited to 64 open documents. Each document is limited to 8 MiB. Captured text, proposed text and stored text prepared for Undo each have a separate 64 MiB aggregate limit; existing view and Undo allocation limits also apply. Capacity failures leave document contents unchanged. A large comparison may take time to prepare on the document owner's thread.

Extend the shared service

  1. Use UmiDocumentReplacementSetCreate for literal replacements across all open drafts. The returned object owns the captures and proposals; destroy it on every completion path.
  2. Read Inspect, At and Texts to present the complete result. Copy borrowed text if a widget can outlive the set. Mark a document reviewed only after its full comparison was successfully presented.
  3. Pass the set's revision to Review and Apply. Require explicit approval in your frontend. Recheck the owning document lifetime before calling the service from a retained control.
  4. For a different source tool, use UmiDocumentSourceBatchCreate with explicit document IDs, stage a complete proposal for every member and approve the batch revision. This primitive does not provide UI review flags; the tool must implement its own full-proposal review.
  5. Keep edits on the coordinator's owning thread. Framework prepares Undo, reserves the complete view set and commits checked store replacements under the existing locks. Applications must not reproduce this as a loop of single-document Apply calls.

These services never write files, run server commands or open unknown documents. The store primitive is byte-oriented; the document transaction additionally validates UTF-8 and preserves the existing Undo owner. Language-server rename and code-action forms retain their current single-document restriction until all affected drafts can be synchronized and reviewed through their protocol workflow.
