Import a document for local source retrieval

RAG means retrieval-augmented generation: look up relevant source passages, then include selected passages with a model question. The shared AI workspace in Umicom RAG, LLM and Creator can import a local text document into its existing source library. Importing text does not contact a model or send a request.

Load, review and save

  1. Open the application’s AI workspace, then its Import document tab.
  2. Enter a collection ID and collection name. A collection groups passages for search. If the ID already exists, use its exact current name; an import does not rename an existing collection.
  3. Choose a new document ID and a readable source title. IDs use letters, numbers, dots, underscores and hyphens, start with a letter or number, and have at most 55 bytes. An example is workshop-notice. Each passage receives an ID such as workshop-notice.part.1.
  4. Choose Load local text file… and select a UTF-8 text file, or paste its complete text into the input area. Plain text, Markdown and source files work when their contents satisfy the text rules. PDF, Word, image OCR and web-page extraction are not provided by this importer.
  5. Select Preview all passages. Read the destination, complete passage text, line ranges and byte offsets. A byte offset measures the position in encoded text; it can differ from a displayed character position. A long line may continue in another passage with the same line number.
  6. Select the approval checkbox, then Save reviewed passages together. The collection and all new passages save in one transaction, meaning one complete change. If the transaction fails, no partial import is published.

Editing any import field revokes the preview and approval. If another workspace operation changes saved state before you save, preview again. Existing passage IDs cause an error; choose a genuinely new document ID or use the existing passage editor when you intend to edit a specific saved source.

Search and ask a grounded question

  1. On Sources, enter the imported collection ID. Choose Reload shared workspace when you want to refresh the complete saved-source catalogue.
  2. Enter a search question and choose Inspect retrieval. Search ranks matching words locally. It does not manufacture embeddings or call a model.
  3. On Drafts and review, choose a grounded draft and enter your question. Prepare inspected results uses the copied passages from the search you inspected; it does not silently run a different search.
  4. Read the frozen request and its source passages. Approve and run it only when the provider, model and content are the ones you intend to use.
  5. The extractive preview copies source excerpts and is explicitly labelled as a preview, not an LLM answer. For actual generation, the configured local-model service must already be available. Check source references before relying on generated text.

Limits and recovery

  • One import accepts at most 98,240 input bytes. The workspace holds at most 64 saved passages, with at most 1,535 UTF-8 bytes in each passage. Existing passages consume that allowance. Line-aware splitting can reach the passage limit before the input-byte limit; the importer rejects the complete import instead of omitting a tail.
  • A leading UTF-8 byte-order mark is removed. Windows CRLF and old-style CR line endings become LF in the copied passages. The original file is not modified. The preview shows all normalized text before approval.
  • Empty text, embedded zero bytes, invalid UTF-8 and unsupported control characters are refused. Save a plain UTF-8 export from the source application and inspect it before importing.
  • The file chooser accepts ordinary local files with absolute paths. Directory, device and final-component link reads are refused. A selected file that is too large is rejected before allocating its contents. The reader checks its open handle for observable changes during reading; a changing file may need to be saved and loaded again.
  • File reading occurs on a worker. Editing the form discards its pending result instead of overwriting your current text. Closing the workspace retires the form; a late file result cannot write into a closed application or database.
  • A save failure leaves the previous library intact. Resolve the reported storage problem, reload and preview again. If a save succeeded but the form was closed before you saw confirmation, inspect the source catalogue before trying another ID.

Storage and privacy

The application’s shared workspace uses its existing local database. Imported text, collection names, titles and generated passage IDs are saved there. The importer does not store the selected file’s path automatically, upload it, save an API key or run instructions contained in it. Local storage is not a claim that the database is encrypted. Use operating-system account and disk protections appropriate to your documents.

The import section is private to Framework’s recording and screenshot policy. Imported passages can later be included in a separately reviewed model request. Review that request’s destination and contents before sending. Saved jobs keep their original source evidence, even if a source is later edited or removed from the active library.

To revise an existing document or remove its passages from search, follow Review changes to your source library. The shared review page can replace several explicitly selected passages in one transaction while retaining earlier job evidence.

Extend the shared service

UmiAiWorkspaceImportCreate copies explicit bytes into an immutable import plan. Inspect its summary and every UmiAiWorkspaceImportPassageAt result before calling UmiAiWorkspaceImportApply with approval. Keep the workspace alive and use its owner thread. Apply checks the captured workspace revision and uses the established Data Server transaction and embedding-cache invalidation.

New file-format extractors should produce bounded UTF-8 text and feed this same review boundary. Keep extraction separate from approval and persistence. The platform’s UmiInputFileRead supports bounded regular-file reads for other importers; use a worker for disk I/O and free returned bytes with UmiInputFileFree.
