Own a background local model request

A graphical application should stay responsive while a local model generates text. Moving HTTP to a worker solves only part of that problem. Someone must retain the request, cancel it, copy readable output, wait for native thread teardown and release storage in the right order. Framework now provides a public C service for those responsibilities. Application adoption and runtime qualification remain separate work.

1. Establish the runtime before starting threads

A runtime is an explicit owner for the HTTP library's global lifetime. Create UmiAiLocalTransport during single-threaded startup, before a GUI toolkit or another subsystem starts workers. Do not call it from a Windows DLL entry point or static initializer. The service initializes HTTP first and then checks its thread-safe global capability; checking library version information before initialization is not a safe substitute.

UmiAiLocalTransport *transport = NULL;
UmiStatus status = UmiAiLocalTransportCreate(&transport);
if (status != UMI_STATUS_OK) {
    /* Display the unavailable capability; do not substitute a fake reply. */
}

This service sends no request and loads no model. It retains one global initialization reference. It refuses release while request owners still retain it, including jobs that have finished but have not been destroyed. Other HTTP clients remain responsible for their own lifetime. See the upstream initialization contract and threading contract.

2. Admit and copy one request

Use UmiAiLocalStreamCreate with that runtime, a normal UmiAiRequest and explicit options. Creation checks the request and encodes its JSON before returning. It copies the local request/model revision tokens, transport limits and provider identity needed for decoding. The application may then edit or free its original request and options.

UmiAiLocalStreamOptions options = {
    .port = 8080,
    .timeout_millis = 30000,
    .maximum_text_bytes = 1024 * 1024,
    .maximum_wire_bytes = 16 * 1024 * 1024,
    .identity = {42, 7},
    .allow_network = true
};
UmiAiLocalStream *job = NULL;
status = UmiAiLocalStreamCreate(transport, request, &options, &job);

The example values are choices, not a discovered server configuration. Set allow_network only after the application has obtained the appropriate user decision. This flag records admission; it does not implement a dialog or authenticate the endpoint. Only an existing trusted 127.0.0.1 server and the fixed chat-completions route are supported. The shared transport refuses redirects, proxies and unsupported response representations.

Text and wire budgets serve different purposes. Text is decoded output retained for the reader. Wire bytes also include JSON and event framing. A bounded response may fail when either budget is exceeded; previous accepted text remains distinguishable from a complete response.

3. Start a producer and read owned copies

UmiAiLocalStreamStart starts one Framework thread. A native start failure leaves the job created and retryable. A second successful start is refused. The producer owns its HTTP handle, decoder and protocol metadata. It receives no GUI pointer and invokes no application callback.

Call UmiAiLocalStreamPoll from the creating thread to observe operation progress. Use UmiAiLocalStreamCopyText for an allocated UTF-8 string and matching text snapshot. Release that copy with UmiAiResponseStreamTextFree. The producer can continue while the application reads its copy; only the shared text mutex is involved.

Protocol metadata such as completion ID, usage and finish reason is different from partial text. The worker publishes one immutable result after the operation. UmiAiLocalStreamReadResult returns BUSY before that point. Afterwards, inspect both operation_status and observation_status: a completed HTTP operation and a successful final metadata observation are separate outcomes.

4. Keep completion and joining separate

StateMeaningSafe next action
CreatedInputs and buffers are owned; no worker exists.Start, cancel or destroy.
RunningA native worker may still access job storage.Poll, copy text or request cancellation.
FinishedThe operation has published its result.Join the native worker before destruction.
JoinedNative teardown has been confirmed.Read retained results and release the job.

A terminal text snapshot can appear before native thread teardown ends. A finished result is also not a join. UmiAiLocalStreamDestroy returns BUSY for an unjoined started worker, even when its result is already available.

TryJoin is nonblocking on supported Framework platforms; others report NOT_IMPLEMENTED. A GUI host must retain its controller and schedule another observation when TryJoin reports BUSY. Join is the explicit blocking alternative for a command-line caller or controlled shutdown path. Never block an interactive event handler for an entire model request.

5. Cancel without freeing borrowed storage

  1. Request cancellation on the creating thread.
  2. Continue retaining the job, runtime and any application owner needed by scheduled observations.
  3. Wait for a confirmed join. Cancellation alone does not establish quiescence.
  4. Read the result and partial text if needed.
  5. Destroy the job. A handle-release failure retains the pointer for investigation or retry.
  6. Destroy the runtime after its retained request count reaches zero.

Cancelling a created job finishes it without starting a worker. Cancelling an already finished operation does not rewrite its result. During HTTP, cancellation is cooperative and observed by transport callbacks and the publication boundary. There is no promise of instantaneous interruption.

Only the creating thread controls a runtime or job. The private worker updates protocol state, and text copies use the shared synchronized owner. Application code should not route controller calls from arbitrary threads or store raw widget pointers in request state.

6. Use the independent SDK client

The native local chat example consumes an explicitly selected installed SDK. It requires a command-line network flag, copies its request before starting, prints only new complete UTF-8 text, and turns Ctrl+C into an owner-thread cancellation request. It uses the shared SVG/ICO branding helper and does not clone Framework.

Generated text depends on the selected model. A configured endpoint is not proof of model identity or quality. The example and APIs are authored; installed-package linkage, live inference, cancellation latency and icon appearance need execution evidence.

7. Qualify the boundaries independently

cmake --build build/windows-ucrt64-debug --target umicom-local-transport-test umicom-local-transport-offline-test umicom-local-stream-job-test umicom-local-stream-job-loopback-test
ctest --test-dir build/windows-ucrt64-debug -R "^framework\.ai_workspace\.(local_transport|local_stream_job)" --output-on-failure

There are nine runtime boundary cases, twelve controlled worker cases, four public-job loopback cases and one offline-runtime case. With the relevant native capabilities, the expected total is 26 passes. These expectations are not executed results.

The runtime suite injects initialization and capability failures. Controlled worker cases retain the actual controller, Framework thread, cancellation and text services while replacing the exchange; they test partial output, input copying, wrong-thread calls, cancellation, and failed start/join/release. The loopback suite uses actual HTTP for successful, timed-out, cancelled and truncated responses. The offline case compiles the actual unavailable branch.

If a test fails, first identify which boundary supplied the evidence. A fixture error is not a successful negative client test. A configuration pass is not compilation. A loopback peer is not a qualified local-model server. Preserve the observed status and tested source identity before changing the policy.

Continue with HTTP admission, terminal sequencing and text ownership. Existing full-response provider contracts remain available. Studio, Media and LLM still need their application lifecycle wiring and GUI qualification.
