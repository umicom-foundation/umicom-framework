Follow a price without losing the missing events

A chart, a watchlist and a price ladder should tell the same story. This workshop follows two fictional instruments through a shared market tape, then shows what happens when observations become old or a message goes missing.

Practice, not trading. ALPHA and BETA are invented instruments. Nothing in this workshop connects to a broker, creates an order, reads an account or writes a database. Closing the practice window discards its observations.

1. Open the practice workspace

Begin with a successfully built copy of Umicom Trader. Open Trader, wait for its normal workspace, then choose Open linked market tape. The existing trading workspace remains underneath; the new window is a separate learning session. Its title includes practice.

The same shared interface is available as umicom-market-tape-workbench.exe in a GTK-enabled build. It does not need the Trader application to own its observations. Opening two practice windows creates two independent sessions.

At first the watchlist contains ALPHA and BETA, but neither has a quote. “No quote” means no quote has been observed. It is not a price of zero. The chart and Time & Sales are empty for the same reason.

The workspace has a practice clock. Waiting at your desk does not advance it. The buttons advance it explicitly, which lets you repeat the same exercise and compare the results.

Build the focused native tools in PowerShell

The following commands build the small market-tape laboratory using canonical Framework source. They do not build the entire application suite. The graphical target is included only when GTK4 development files, version 4.10 or later, are available.

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& "C:\msys64\ucrt64\bin\cmake.exe" `
    -S ".\framework\examples\market_tape" `
    -B ".\build\market-tape-practice" -G Ninja `
    -DCMAKE_BUILD_TYPE=Debug
if ($LASTEXITCODE -ne 0) { throw "Configuration failed." }
& "C:\msys64\ucrt64\bin\cmake.exe" `
    --build ".\build\market-tape-practice" --parallel 2
if ($LASTEXITCODE -ne 0) { throw "Build failed." }
& "C:\msys64\ucrt64\bin\ctest.exe" `
    --test-dir ".\build\market-tape-practice" `
    --no-tests=error --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "Tests failed." }

The native tools are then under build\market-tape-practice\bin. A missing display can cause graphical tests to report a skip; that is not a graphical pass.

2. Read the first observation

Select ALPHA and choose Next observation once. This adds three fictional messages, in order: a quote, a complete depth snapshot and a trade. The practice clock advances by 250 milliseconds.

ViewExpected first ALPHA result
WatchlistBid 100.000 and ask 100.250.
Time & SalesOne trade: price 100.125, quantity 1.000.
Depth ladderFive bid levels and five ask levels. Bids are highest first; asks are lowest first.
BarsOne one-second bucket beginning at practice time 1000000 ms. Its opening, highest, lowest and closing prices are initially identical.
SequenceLast accepted message 3; expected next message 4.

A quote describes bid and ask observations. A trade describes an observed transaction. Depth describes quantities at several prices. These are different records, so the workspace keeps their freshness indicators separate.

For this first step all three are fresh. The ladder is still only a fictional observation. Its quantities are not your orders, and the presence of a displayed quantity is not an execution guarantee.

3. Switch instruments without mixing their information

Choose Next observation several more times for ALPHA. Then select BETA. The chart, Time & Sales, depth and bar table all switch to BETA together. They should be empty until you add a BETA observation; ALPHA's records must not remain under the new heading.

Add one BETA observation. Its first bid is 50.000, ask 50.250 and trade price 50.125. Select ALPHA again. Its earlier records are still there because selecting an instrument does not discard its history.

The watchlist and selected panes are rendered from one copied snapshot. A snapshot contains the selected index, instrument identities, rows, trades, bars and depth at the same model revision. The interface does not fetch each pane from a separate private cache.

The snapshot also records the observation time. Two reads may have the same model revision but different freshness because time has advanced. A revision identifies changes to retained data; it does not stop that data ageing.

4. Let information grow old

With an instrument selected, choose Advance 3 seconds. No quote or trade is added. The practice clock moves forward and the lane indicators become NOT current. Existing values remain visible so you can inspect the last known observation.

Choose Next observation for the selected instrument. Its three lanes receive new observations and become fresh again. The other instrument has not received those messages and must not acquire their freshness.

The default freshness boundary is two seconds: an age of exactly 2000 milliseconds is stale. The core checks source-event time for each lane. Separately, the stream state reports whether an event was received recently. A newly delivered but delayed quote can therefore belong to a recently active stream while its quote is already old.

Read both indicators. “Current observations” is a stream-arrival state, not a promise that every displayed quote, trade or depth level is fresh. The individual lane badges provide the distinction.

5. Introduce a missing sequence

Select an instrument that has at least one observation, then choose Introduce gap. The practice source deliberately sends a number after the expected number. For example, after accepting 3 it sends 5 rather than 4.

The later message is not applied. The old quote and history remain visible, the gap is recorded, and the pane no longer describes those values as current. Next observation is disabled because further packets cannot establish the missing history.

This is a latched condition: receiving a later number does not automatically repair it. Even a belated message with the missing number cannot silently undo the known gap in this profile.

Start a new epoch deliberately

Choose New epoch only after reading its tooltip. This discards the selected instrument's retained observations, increases its generation and starts a new sequence boundary. It does not recover missing events. The other instrument's history remains unchanged.

The chart becomes empty and the instrument waits for a new observation. Choose Next observation to begin collecting again. The generation distinguishes this new history from delayed packets belonging to the old one.

Try a disconnection

Choose Disconnect. Values remain available for inspection, but incoming observations are refused and freshness is false. This workshop requires another New epoch to resume. In a real adapter, reconnect and resynchronisation would need provider-specific work before establishing that boundary.

6. Understand what the chart has retained

The tape combines trades into fixed-time bars. For each bucket it retains the first price as open, the largest as high, the smallest as low, the last as close, and the sum of quantities as volume.

The interval is written [start, end): include the start, exclude the end. A trade arriving at exactly the end belongs to the next bucket. No trades means no bar; the tape does not invent flat candles across an empty period.

The chart uses actual bucket times along its horizontal axis, leaving empty time spans empty. Hollow bodies indicate a close at or above the open, while filled bodies indicate a lower close. The Bars tab provides exact numeric values and is also useful when a drawing is difficult to read.

The last bucket may still be forming. In this profile there is no separate bar-finalisation clock, exchange-session calendar or holiday adjustment. The interval is fixed when the tape is created.

For each instrument the workspace retains the newest 64 trades and 64 bars. Older retained records are retired when capacity is reached. The displayed retirement counters refer to this intentional limit, not to messages missing from the feed. A fresh epoch clears both the retained records and their counters.

7. Build the same rule in C

Open framework\examples\market_tape\lesson.c. It is a complete program using the public API, not a fragment that depends on hidden application state. The sequence is straightforward: create a tape, register an instrument, begin an epoch, submit four trades, read one snapshot, then release both owned objects.

UmiMarketTapeConfig config = UmiMarketTapeConfigDefault();
UmiMarketTape *tape = NULL;
UmiStatus status = UmiMarketTapeCreate(&config, &tape);
/* Check status before using tape; see lesson.c for the complete flow. */

The complete example submits prices 100.00, 101.00, 99.00 and 100.50 with a quantity of two each. They fall within the same second. Run its executable:

& ".\build\windows-ucrt64-all-debug\bin\umicom-market-tape-example.exe"
if ($LASTEXITCODE -ne 0) { throw "The market-tape lesson failed." }

Expected output:

WORKSHOP: open 100.00, high 101.00, low 99.00, close 100.50, volume 8
Four trades share one bar. The missing quote is not a zero price.
Practice complete. Memory only; no order was created.

The program owns the tape and snapshot. Framework stores copies of the accepted canonical records; it does not keep a pointer to the temporary packet on the caller's stack. The snapshot remains readable after the tape is destroyed. In a threaded application, however, the owner must stop and join clients before destroying the tape itself.

A command-line gap exercise

& ".\build\windows-ucrt64-all-debug\bin\umicom-market-tape.exe" demo
if ($LASTEXITCODE -ne 0) { throw "The practice sequence failed." }

This submits 24 ALPHA trades, reports seven observed time buckets, introduces a gap and begins a new epoch. It finishes by stating that no file, database, broker or network was opened.

Use the installed C contract

A native consumer links Umicom::market_tape. It sends the established UmiQuote, UmiTradeTick and UmiMarketDepth records inside an envelope carrying generation, sequence and receipt time. An adapter must supply contiguous per-instrument sequence numbers. Venue-wide numbers cannot simply be reused after filtering unrelated instruments.

Positive finite prices and quantities are required by this tape profile; quote sizes may be zero. It does not cover negative-price products, trade corrections, busts, depth deltas, order execution or currency settlement. The public header and developer guide state the validation boundary.

8. Practise and explain the result

Exercise A. Add five ALPHA observations, select BETA and add one. Return to ALPHA. Which records should each instrument retain?

Exercise B. Advance the clock by three seconds. Why can the old prices remain visible without being called current?

Exercise C. Introduce a gap, then begin a new epoch. Has the gap been recovered?

Exercise D. In a copy of the C lesson outside the repositories, move the fourth trade to time 2000 ms. Predict the bar count before changing the assertion and running the program.

Compare your answers

A: ALPHA retains five trades and BETA one, with their own charts and depth. Selection alone changes neither history.

B: Retention and freshness answer different questions. The tape can preserve an old observation for inspection while refusing to label it current.

C: No. The selected history was discarded and a new boundary established. Recovery would require a replay or snapshot protocol that this practice source does not implement.

D: There should be two bars. The first holds the first three trades and the second holds the fourth. The supplied lesson currently expects one bar, so its expectation must be deliberately updated for this new experiment.

When something does not match

No entry in Trader: confirm the Framework and Trader source changes were both merged and the GTK target was built. A core-only build provides the command-line examples but not a graphical window.

Next observation is disabled: inspect the stream status. A gap or disconnection requires a new epoch in this practice profile. Changing instruments may select another independent stream.

The chart is empty: select an instrument and add a trade. A quote or depth record alone is not a trade bar.

The layout needs more room: resize the window or use its scrollbars. Exact values remain in the text tabs. Keyboard, display scaling and assistive-technology behaviour should be checked on the target desktop.

Where to go next

Use the lesson to understand event ownership before adding a real transport. The next integration step is an explicit adapter with its own sequencing and resynchronisation contract, followed by tests proving that the same snapshot reaches the intended application panes. Do not turn a practice label into a claim of live connectivity.
