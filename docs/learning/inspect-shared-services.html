Inspect shared services safely

A registry lookup and a diagnostic report have different lifetimes. umi_service_registry_find returns a borrowed descriptor: the registry owns its storage. A later register or unregister can replace or move that storage. A panel which keeps the pointer can therefore display a different record or read released memory. Serialize borrowed lookups with mutations and reacquire them after a change.

For diagnostic views, use copied metadata. UmiServiceSnapshot contains the service identifier, provider identifier, version and flags in the caller's own storage. It contains no service object, callback or registry pointer. It remains readable when the registry changes or is released. The copy records what was registered at capture time; it does not promise that the service still exists or is healthy.

Copy one service

UmiServiceSnapshot description;
UmiStatus status = UmiServiceRegistryCopySnapshot(
    registry, "example.counter", "example.counter.provider", &description);
if (status == UMI_STATUS_OK) {
    printf("%s comes from %s\n",
        description.service_id, description.provider_module_id);
}

The last argument points to your output object. The registry copies the metadata while holding its mutex, then releases the mutex before returning. A missing entry returns UMI_STATUS_NOT_FOUND and leaves the output unchanged. Do not read an uninitialised output when the call failed.

Use a provider identifier when the choice matters. A NULL provider chooses the first matching provider in registration order. It does not choose the newest version, healthiest instance or most trusted implementation.

Copy a bounded list

UmiServiceSnapshot rows[8];
size_t total = 0U;
UmiStatus status = UmiServiceRegistryCopySnapshots(
    registry, rows, 8U, &total);
if (status == UMI_STATUS_OK || status == UMI_STATUS_CAPACITY_EXCEEDED) {
    size_t visible = total < 8U ? total : 8U;
    for (size_t index = 0U; index < visible; ++index)
        printf("%s\n", rows[index].service_id);
    /* If total exceeds visible, tell the user the list is incomplete. */
}

The count and copied rows come from the same locked observation. If more than eight entries exist, the first eight rows are valid and the status is UMI_STATUS_CAPACITY_EXCEEDED. total reports the whole count, not the number copied. Never use total as an array bound when your capacity is smaller. Zero capacity with a non-NULL output also reports insufficient room for a nonempty registry.

For a count-only query, pass NULL, 0U, &total. That query succeeds without writing rows. A later allocation and second call are separate observations: a permitted writer may add entries between them. Handle a larger second count or allocate the documented maximum for a complete bounded list.

Summarise without allocating a list

UmiServiceRegistryCopySummary fills a small UmiServiceRegistrySummary with the total and counts of singleton, owned, thread-safe and replaceable registrations. All five counts come from the same locked observation. Use it for a status bar that only needs totals; copying every name would add unnecessary storage and work.

UmiServiceRegistryCountPrefix counts identifiers beginning with a supplied prefix under the same lock. An empty prefix matches every row. Two providers registered under one identifier count as two rows, not one distinct service name. Runtime inventory delegates its service queries to these operations.

Command totals also come from their own locked observation. Capability mutation still needs owner serialization. Separate observations do not make the entire multi-registry report atomic.

Keep ownership explicit

  • Keep the registry alive throughout each call. A mutex cannot protect a registry which another owner has already freed.
  • Copies serialize against registration and removal. Exclude all concurrent operations before releasing the registry.
  • Owned-service destructors may read metadata under the registry's exclusive release owner. The retiring entry is detached before its destructor runs.
  • Snapshots do not retain service objects or make them thread-safe. Invoke a service only through an established owner and dependency contract.
  • Flags describe registration policy. OWNED identifies destruction responsibility, SINGLETON excludes other providers, REPLACEABLE permits replacement, and THREAD_SAFE is a provider declaration. None is a current health result.

Follow the application example

Studio's UmiStudioStateCopyServices delegates to this API. Its native umicom-studio-state --services command prints copied names, providers, versions and flags. The application formats the report; Framework owns discovery. This also supports a desktop panel or web response without returning process addresses to the presentation layer.
