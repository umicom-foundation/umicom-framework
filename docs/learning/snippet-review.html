Own linked snippet edits and document insertion review

Framework keeps template composition separate from document mutation. The editor snippet session owns expanded text and placeholder byte positions. The document snippet review owns an immutable source capture and stages a complete draft. The GTK adapter presents those services; applications supply only the action that opens the form.

  1. Create UmiDocumentSnippetReview with the existing document coordinator and document ID. Keep the coordinator, store and workbench alive and use their owning thread.
  2. Inspect the review to obtain its revision. Supply a valid UmiEditorSnippetTemplate, including its structure size, API identifier, ID, language and name, to UmiDocumentSnippetReviewTemplate. The template is copied.
  3. Read placeholder metadata and use UmiDocumentSnippetReviewValue to change a nonzero ordinal. Every linked occurrence is updated atomically, and later positions move. Failure leaves the previous session and proposal intact.
  4. Call UmiDocumentSnippetReviewPrepare with the current review revision. Framework rechecks the captured source and selection, assembles the complete proposed draft, and stages it without changing source or history.
  5. Read the original and proposed text for comparison. Copy borrowed bytes before callbacks can change or destroy the review. Preparation advances the review revision, so approval must identify this newly presented revision.
  6. After explicit approval, call UmiDocumentSnippetReviewApply. The source request rechecks document identity, content, caret, permissions and save/conflict state. It applies one undoable edit, retains the active tab and performs no save.
  7. Destroy the review when finished. After a successful Apply, the original capture remains readable, but the review cannot be applied or edited again.

Use the editor session independently

UmiEditorSnippetSessionRestart validates a replacement session before publishing it. UmiEditorSnippetSessionReplace rebuilds immutable original segments into candidate storage, updates all matching occurrences and shifts subsequent ranges. It preserves the selected ordinal and advances the session revision once. Both operations accept cancellation and leave the previous session intact on failure. The original parser and traversal APIs remain available.

Replacement values must be valid UTF-8 without embedded NUL. They are literal text and may contain snippet-looking characters. The final stop, ordinal zero, is not editable. Coincident empty placeholders follow their original textual order. Choice lists remain suggestions. The parser's existing supported forms and literal fallback are preserved; these ownership APIs do not claim complete language-server snippet syntax.

Extend the workflow safely

A snippet library can supply templates to this model without implementing a second history stack. A future inline editing feature will need separate source-revision tracking and explicit rules for edits outside the active placeholder. Do not reuse pre-insertion ranges after arbitrary document edits. Likewise, full language-server snippet support needs a strict grammar and provider capability negotiation before it can be advertised.

The GTK form borrows the document editing lifetime token, retains its controls through callbacks and marks its source content private for interaction recording. Changing inputs expires approval. Applying checks the current field contents as well as the presented revision, so a retained or reentrant control cannot silently apply an older proposal.

Store a named template locally

Link Umicom::developer for the bounded storage API in umicom/developer_project/snippet_storage.h. The parser-only editor target does not acquire JSON or filesystem dependencies. UmiSnippetTemplateEncode and Decode use exactly five fields: format, id, language, name and body. Unknown, duplicate, missing or mistyped fields reject the whole record, and output objects remain unchanged on failure. Storage validation checks UTF-8 and metadata; it does not expand or reinterpret the template grammar.

  1. Resolve an explicit application settings path with UmiSnippetTemplatePath. Both identity strings are encoded into separate directory components; the longest accepted ID still fits a 255-byte component. Resolution creates no directories.
  2. Use UmiSnippetTemplateSave only for an explicit save request. Its trusted parent must exist. The shared atomic replacement service owns staging and publication.
  3. Use UmiSnippetTemplateLoad with the expected language and ID. The result is a draft template, not an instruction to edit source.
  4. In GTK hosts, call UmiGtk4AdapterReviewSnippetWithSettings. The adapter copies worker inputs, keeps source objects on the owner thread and rejects retired load results. The existing no-settings form remains available.

The storage record is limited to 65,536 JSON bytes. Metadata uses the existing snippet structure capacities; template bodies retain the 8,191-byte payload limit. Each file is ordinary local data, not encrypted secrets. Save has last-writer behaviour and inherits the shared file replacement service's permissions and durability limits. It is not a hostile-filesystem sandbox or a synchronization service.
