Export a course project and open it in Studio

The learning practicum can create editable copies of the Notes, Assembly stock totals and Framework storage courses. You choose where their source files live. Reading lessons and exporting source do not require opening a learner database.

  1. In Studio's Guided Learning panel, open the learning practicum. Select a lesson from the course you want to practise. All lessons in that course share its project.
  2. Find New project directory. You can type a complete path to a folder that does not exist, or expand Choose a parent folder and a new project name. Choose an existing parent folder, enter a new folder name, and select Use this project destination. This prepares the path without creating it.
  3. Read the prepared path above the chooser. For example, choose C:\Projects\Learning as the parent and notes-practice as the new name. The parent must already exist; the new project folder must not.
  4. Select Export this course project. Export uses the course and destination shown when you click. You may keep reading while files are written. Changing the lesson or path does not redirect the accepted export.
  5. Wait for the completed export message. When launched from Studio, select Open last exported project in the IDE. The action opens the directory that was successfully exported, even if you have since edited the destination field. The standalone practicum does not display this IDE action.
  6. In Studio, edit the project's main.c and supporting source files. Save changes before compiling. Review project trust and the compiler in Build > Project Settings, then configure and build. The supplied profile uses Ninja, Debug, and build/default. Framework storage lessons also need an installed Framework data SDK selected in CMake settings.
  7. Run the configured executable after a successful build. To debug, configure a supported debug adapter and set a breakpoint. Review installation settings separately before deploying. Exporting or opening a project never grants trust or starts these actions.

If export cannot complete

An existing destination is refused, including an empty directory. Choose another new folder name; your existing files are kept. A missing parent folder, unavailable drive or write error can prevent completion. Check the displayed destination and the number of completely written files. A partial new folder is left for inspection and is not automatically deleted or adopted by Studio.

Closing the practicum retires its controls. A write already accepted by the worker can finish while the application continues running. Closing the whole application or losing power can interrupt it; export does not promise transactional recovery. Inspect the chosen folder before retrying. Open a completed project through Studio's normal project workflow if its original practicum window has closed.

Store projects in a trusted local folder. A path is not a filesystem sandbox: parent directory links and permissions are controlled by your operating system. Portable folder names reject path traversal and reserved device names. Advanced users can still type the full destination directly.

Quiz progress records learning activity. It is separate from actual compiler, test and debugger results.
