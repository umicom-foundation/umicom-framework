Complete a local model stream honestly

A model may send useful text and then lose its connection. The text still has value, but the answer is incomplete. A native client needs to retain that distinction through parsing, cancellation, background work and the final display.

This lesson extends SSE reception, delta admission and request-owned text. It uses Framework's private local-chat sequencer as a concrete example. The sequencer is implemented source; it does not itself start HTTP or create an application window.

1. Give each layer one responsibility

  1. Web's SSE parser reconstructs complete events from fragmented bytes.
  2. The local provider codec validates each event's bounded JSON fields.
  3. The sequencer binds events to one provider completion ID and enforces order.
  4. The shared AI response owner retains accepted text with the caller's local request and model-revision tokens.
  5. The transport reports whether the HTTP request actually completed successfully.

The provider's completion ID is an untrusted string, not an authenticated model identity. Local request and revision tokens prevent a different class of mistake: attaching old output to a new application request. Both identities are necessary and neither replaces endpoint verification.

2. Follow the state transitions

Current stateAccepted observationNext state

ActiveOne supported stop or length finish chunk; final text and usage may be includedFinish reported

Any unfinished stateCancellation or parsing/transport failureCancelled or failed; prior text retained

A marker alone leaves the text owner active. EOF without both a finish chunk and a complete marker fails. After the marker this profile accepts only ASCII spaces, tabs and line endings. Another event, comment or partial event is rejected. A length finish is retained as length, so a UI can explain that generation reached a limit.

The Chat Completions chunk schema distinguishes a choice delta from an empty choices array used for final usage. The codec preserves that shape explicitly. An empty choice containing usage after finish is not silently treated as the zero-choice usage record.

3. Preserve text without declaring success

text: "Hello"        → retained partial text
finish: "stop"       → finish reported
data: [DONE]         → marker received, still incomplete
HTTP read failure    → failed, retained text remains "Hello"

This is an authored diagnostic example. The failure does not erase accepted text or invent a successful result. Further feed, finish and cancellation attempts return the original failure. A completed stream also refuses subsequent data, failure or cancellation attempts.

Cancellation is a terminal state, not a thread join. The transport must stop its work and the host must join the worker before destroying the sequencer. All sequencer calls belong to one serialized owner thread. The underlying response text owner has its own synchronization, but that does not make the whole protocol sequencer concurrently callable.

4. Integrate the private boundary deliberately

Inside Framework, the intended call order is create, feed repeated bounded reads, then finish or fail/cancel. Copy returns an independently allocated text snapshot with matching protocol metadata. Release the copy with UmiAiResponseStreamTextFree; it remains readable after the sequencer is destroyed.

/* Framework-internal outline. Network transport is a separate owner. */
status = AwLocalChatStreamFeed(stream, received_bytes, received_length);
if (status != UMI_STATUS_OK) {
    /* Stop receiving and retain the failure snapshot. */
}
/* Only after the transport reports success and headers were admitted: */
status = AwLocalChatStreamFinish(stream);

Do not call Finish in a generic cleanup block. Cleanup also runs after timeouts, cancellation, rejected status codes and truncated responses. Use Fail or Cancel for those outcomes. Applications should use a public Framework service rather than including this private header.

5. Account for synchronization errors after mutation

A mutex unlock error can occur after the text owner has appended data. Retrying the same event blindly could duplicate text or obscure the original failure. The sequencer inspects the owner's committed sequence before publishing an external failure.

It also records a separate terminal-publication status. If publishing failure itself fails, or a final text event was already committed before an unlock error, the protocol failure remains visible alongside the underlying text state. Consumers must inspect both, rather than interpreting text presence or its terminal state alone as a successful request.

6. Qualify without a live model

cmake --build build/windows-ucrt64-debug --target umicom-local-chat-stream-test umicom-local-chat-stream-boundary-test umicom-local-chat-stream-offline-test umicom-local-chat-stream-fault-test
ctest --test-dir build/windows-ucrt64-debug -R "^framework\.ai_workspace\.stream_(sequence|boundary|offline|fault)" --output-on-failure

The GNU/Clang configuration registers 42 cases: 29 sequence cases, nine boundary cases, one real offline-codec case and three link-interception fault cases. The fragmented success case tries every two-part split and then every byte separately. The fault target is omitted on unsupported linker configurations. When optional native JSON support is absent, dependent cases explicitly skip; the offline branch remains testable.

These are authored regression checks with expected outcomes, not recorded test passes. Start with the failing fixture name, inspect its input and expected retained text, and determine whether rejection arose from framing, JSON, identity, ordering or capacity. Preserve a failing input before changing acceptance rules.

7. Understand the remaining boundary

The existing public local provider still uses full responses. A separate public background stream service now composes runtime ownership, the blocking HTTP exchange and this sequencer. Its text-only copy path is synchronized; protocol metadata is read after operation publication. Application adoption, safe UI closure and live server compatibility still need qualification. This source is not evidence that Studio or Media already displays streamed model output.
