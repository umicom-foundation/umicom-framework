Native AI application learning path

ComfyUI system reports with the Umicom SDK

Build a C23 application that inspects reported system and device metadata without starting a generation job. You need an installed Umicom Framework SDK and familiarity with structures, pointers and error handling. The complete project uses synthetic JSON and makes no network request. It teaches a reusable service that Media or Studio can consume without maintaining another parser.

Lesson 1: separate reports from actions

ComfyUI documents GET /system_stats as a system and device information route. Its server interface includes version metadata and memory counters. Read the official route guide and server interface when adapting to your installed version. The Umicom implementation independently decodes supplied response bytes in C; it does not port ComfyUI's Python implementation.

A memory report is an observation. Loading a model, reserving device memory, changing an execution queue and generating an image are separate operations. This example performs none of them. The caller of a live adapter must establish which reviewed connection produced a successful response before handing bytes to the decoder.

The copied structures initialize unknown storage to zero for deterministic ownership, so testing only the numeric member loses this distinction. Required device names and types must be nonempty; unfamiliar type names remain usable report text.

Lesson 3: keep integers exact

Memory fields use byte counts. The service accepts exact integer tokens from zero through INT64_MAX, including values greater than a binary floating-point number can represent exactly. It rejects exponent and fraction notation instead of rounding. Display bytes with PRIu64 from <inttypes.h>. Convert only a presentation copy when showing GiB, where one GiB means 1,073,741,824 bytes.

if ((device.known & UMI_COMFY_DEVICE_VRAM_FREE) != 0U) {
    printf("Reported free: %" PRIu64 " bytes\n", device.vram_free);
} else {
    puts("Reported free: unknown");
}

The fragment assumes a copied UmiComfyDeviceObservation named device and the usual standard headers. It does not claim that those bytes remain free at the moment you display them.

Lesson 4: create and release an observation

#include <umicom/media_generation/comfy_system.h>

UmiComfySystemStats *stats = NULL;
UmiStatus status = UmiComfySystemStatsCreate(
    &connection, saved_revision, response_bytes, response_length,
    cancel, &stats);
if (status == UMI_STATUS_OK) {
    UmiComfySystemSummary summary;
    status = UmiComfySystemStatsInspect(stats, &summary);
    /* Read summary.device_count rows with UmiComfySystemStatsDeviceAt. */
}
UmiComfySystemStatsDestroy(stats);

The complete example supplies the connection and JSON omitted from this fragment. Initialize the output owner to NULL. Creation publishes it only after the complete report is admitted. A failed refresh leaves your old displayed owner intact when you create into a separate temporary pointer. Replace the old owner only after a successful capture and after its readers finish.

The service retains copied named fields, the response digest and saved connection identity. It does not retain launch arguments or opaque extension metadata. Those fields still undergo complete JSON and duplicate-key validation. A digest identifies the bytes; it does not authenticate the sender. A matching saved revision does not prove that memory values are current.

Accessors copy values and preserve outputs on refusal. Copies can outlive the owner; the caller is responsible for their disposal. Coordinate all readers with destruction. Cancellation is cooperative and does not interrupt a remote process.

Lesson 5: build a project against the installed SDK

  1. Install a matching Framework SDK that exports Umicom::comfy_protocol and contains comfy_system.h plus its compiled implementation.
  2. Copy share/umicom/framework/examples/comfy_system from that SDK into C:\Projects\comfy-system.
  3. Use the same architecture and compiler family as the SDK, and run each command separately:
cmake -S C:/Projects/comfy-system -B C:/Projects/comfy-system/build -G Ninja -DUMICOM_SDK_ROOT=C:/SDKs/Umicom -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe -DBUILD_TESTING=ON
cmake --build C:/Projects/comfy-system/build
ctest --test-dir C:/Projects/comfy-system/build --output-on-failure

Stop on an error. The project checks installed package identity and ABI, links public libraries and applies the shared SVG/ICO branding resources. It does not embed Framework source files. Successful configuration alone does not establish successful linking or execution.

Expected output describes two synthetic devices, an unknown CPU index and known GPU index zero. It ends by detecting a changed saved connection label. The report remains readable after its input buffer is cleared. Record your actual output and exit status before describing the example as passed.

Lesson 6: present observations responsibly

Streamlit's metric element presents a labelled value and optional change indicator. Its useful design lesson here is to keep the label, value and comparison context explicit. A native host can consume copied SDK values in its approved view; this course adds no new GUI layout or Python runtime.

Use a label such as “Reported device free bytes” with a capture time recorded by the host. Show unknown distinctly from zero. Suppress a computed used-memory figure when vram_inconsistent is true. The flag means known free exceeds known total; it does not diagnose a driver or prove unhealthy hardware. Keep the original counters visible for investigation.

Do not add host RAM, device VRAM and PyTorch counters. They may describe overlapping memory. Do not calculate a model-fit promise from file size alone. Loading overhead, working buffers, other processes and changing availability require separate execution evidence. Avoid comparing row zero across captures as if it were a permanent hardware identity; report order and device metadata can change.

Lesson 7: qualify adverse inputs and recovery

  1. Replace a null index with zero. Confirm that the known bit changes and the display does not confuse the values.
  2. Supply 9007199254740993 as a synthetic counter. Verify exact copied digits; do not route the integer through floating point.
  3. Make free greater than total. Verify the inconsistency flag and preserve both observed values.
  4. Supply a duplicate JSON key, including an escaped spelling of the same key. Expect UMI_STATUS_ALREADY_EXISTS; do not accept an arbitrary first or last value.
  5. Try 65 devices or more than 1 MiB of response bytes. Expect a capacity refusal without a partial owner.
  6. Clear the input buffer after successful creation, copy a row, then destroy the owner. Check the copied row remains usable.
  7. Change saved connection content or revision. Expect BUSY from the connection check, and deliberately obtain a new observation.

The producer registers framework.media.comfy.system.* cases covering these boundaries, every optional numeric field, Unicode, resource limits and ownership. They must be executed against the built source before reporting runtime success. The installed example has its own test; keep that result separate from producer tests and real-server qualification.

Lesson 8: inspect a captured report from a file

The SDK also composes the decoder with its existing connection-document and regular-file readers. This is useful when reproducing a report privately, building an offline support tool or comparing native application hosts. The input files are separate captures; the reader does not claim an atomic snapshot of both files.

  1. Use the portable connection document described in the ComfyUI workflow course. It must describe an enabled ComfyUI connection to a literal loopback HTTP origin. Keep its saved revision with the report.
  2. Save a reviewed /system_stats capture as a UTF-8 JSON file. For an entirely offline exercise, create a synthetic report as shown below.
  3. Build the installed-SDK example from Lesson 5. Its no-argument exercise remains available. Its command mode uses the same Framework service as the native CLI and Media console.
New-Item -ItemType Directory -Force C:\Examples | Out-Null
@'
{"system":{"ram_total":17179869184,"ram_free":9007199254740993},"devices":[{"name":"Synthetic CPU","type":"cpu","index":null}]}
'@ | Set-Content -LiteralPath C:\Examples\system.json -Encoding utf8
Set-Location C:\Projects\comfy-system
.\build\bin\umicom-sdk-comfy-system.exe comfy system --help
.\build\bin\umicom-sdk-comfy-system.exe comfy system C:\Examples\connection.umiconnection C:\Examples\system.json

The fixture deliberately reports free RAM greater than total. Expect ram_inconsistent: true, exact counter digits and an unknown CPU index. Do not interpret these invented values as information about your computer. The command refuses a missing or disabled connection document; it does not create settings implicitly.

When using PowerShell, inspect $LASTEXITCODE immediately after each native command. Exit 0 means a complete report was emitted, 2 means the argument form is wrong, and 1 means file admission, parsing or output failed. Stop and investigate an error. Use absolute paths. The reader refuses a final file symlink, device or directory; parent directory aliases remain possible, so the selected paths still need review.

The equivalent product commands are umicom.exe comfy system CONNECTION SYSTEM_JSON and umicom-media-studio-console.exe comfy system CONNECTION SYSTEM_JSON. They make no provider request and perform no model or generation action. A 1 MiB response limit and 64-device limit bound the report. An empty file is not an empty device list: use a valid JSON object containing system and devices.

Lesson 9: consume the report without losing information

Standard output contains a JSON object with origin: "offline-files" and a report member. The report contains response and connection digests, the saved connection revision, a known-field mask and copied system/device observations. Device rows retain response order, with a zero-based response_index. That index identifies a row in this capture, not a permanent device identity.

Memory counters, device index, connection revisionDecimal string when knownPreserve every digit in consumers that normally parse numbers as floating point

In C, include umicom/media_generation/comfy_system_file.h, initialize a UmiComfySystemStats * to NULL, and call UmiComfySystemStatsFileRead(document, response, cancel, &stats). Use UmiComfySystemStatsJson with a buffer of UMI_COMFY_SYSTEM_JSON_CAPACITY bytes, then destroy the owner. Check every status. On failure, the serializer preserves both the caller's buffer and its supplied output length. Successful output includes a terminating NUL; the returned length excludes it.

Run synchronous file reading on an appropriate worker in a graphical application. A cancellation token is checked at boundaries; it cannot interrupt an already blocking file read. Keep the owner alive while reading it and coordinate its destruction. Metadata text remains untrusted display content even after JSON escaping; this service is not a general secret redactor.

Extend the previous assessment by trying an output buffer exactly one byte too short, a null index and a known zero index, a Unicode filename, a missing response file and a disabled connection. Check that failed commands emit no partial standard-output report. The installed example registers sdk.comfy-system.files.*; producer registrations include framework.media.comfy.system_file.*, system_json.*, system_sdk.* and system_command.*. Media registers media.comfy.system.*. Record executed results separately for each built host.

Troubleshooting and assessment

If the header exists but the symbol cannot link, compare the SDK headers and libraries and inspect the selected prefix. If parsing rejects a report, preserve it privately and compare its schema with the actual installed server version. Never replace malformed metadata with zero. If counters look contradictory, retain their observed identity and investigate the provider independently; refreshing metadata does not repair a driver.
