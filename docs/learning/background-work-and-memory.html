Let background work finish before you release its memory

Build a small Notes indexer, run it on a worker thread, and learn which object must stay alive at each step. The same ownership rules apply to an editor, a market-data worker and an operating-system service.

Practice scope. This lesson counts the words in one sentence held in memory. It does not edit your notes, open a database, contact a broker or start an OS guest.

1. Start with a Notes draft

An application sometimes has work that should not run inside a button handler: indexing text, inspecting a large document or preparing a preview. A worker thread runs a function while the application continues with other tasks.

That does not give the worker its own copy of every object it uses. In this example, the controller owns a NotesIndex structure. The worker borrows its address, reads the sentence and writes the word count. The controller keeps that structure alive until the worker has been joined.

First merge the supplied files into their matching repository paths. Open PowerShell and run this smaller build before the complete application build. It compiles the actual Framework thread implementation, not a second implementation inside the example.

Set-Location "C:\umicom\Umicom-Applications"
$ErrorActionPreference = "Stop"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"

& "C:\msys64\ucrt64\bin\cmake.exe" `
    -S ".\tools\thread-safety" `
    -B ".\build\thread-safety" `
    -G Ninja `
    -DCMAKE_BUILD_TYPE=Debug
if ($LASTEXITCODE -ne 0) { throw "Configuration failed." }

& "C:\msys64\ucrt64\bin\cmake.exe" `
    --build ".\build\thread-safety" --parallel 2
if ($LASTEXITCODE -ne 0) { throw "Build failed." }

& ".\build\thread-safety\bin\umicom-thread-lifecycle.exe" --self-test
if ($LASTEXITCODE -ne 0) { throw "The lesson failed." }

The expected output is:

Notes index: 8 words. The worker was joined before its data left scope.
Practice complete. No file, database, window or network was opened.

The count is based on spaces, tabs and line breaks. It is a small indexing example, not a language-aware word segmentation engine. Punctuation remains part of a word.

2. Separate the handle from the work

A thread handle is the controller’s way to refer to a native thread. Releasing that handle does not mean the callback has stopped. Native handle closure on Windows and detachment on POSIX both leave a running callback running; the platform references at the end explain these native rules.

Controller reference
Released when the owning handle is closed.
＋
Worker reference
Released after the callback wrapper finishes using its result.
→
Private block reclaimed
Only after both references are gone.

The Framework now keeps those two ownership interests separate. It allocates one private control block, initialises both references before the native worker can run, and frees the block only after both owners have released it.

This fixes the case where a controller releases its handle while the worker is still inside the callback. Previously, the wrapper could return from the callback and write its exit code into an allocation that had already been freed.

The fix does not take ownership of your callback data. A pointer to a window, document, buffer or stack variable still needs its own lifetime rule. The example’s stack structure stays in scope through umi_thread_join. Do not replace that join with release and then let the structure leave scope.

3. Observe a result, then join

UmiThreadTryGetExitCode is a nonblocking observation. It returns UMI_STATUS_BUSY while the callback is running. After an ordinary callback return, it copies the integer result and returns UMI_STATUS_OK. An unsuccessful observation leaves the caller’s result variable unchanged.

The callback’s integer result and a Framework status are different things. The example chooses callback result 0 for completed counting and 2 for cooperative cancellation. The call to umi_thread_join separately reports whether joining worked.

OperationWhat it establishes
TryGetExitCodeThe callback published an integer result, or is still busy. It does not wait for the complete native exit.
joinThe native thread has ended, including its native exit cleanup. Self-join is refused.
ReleaseThe controller has relinquished its owning handle. It does not stop or join the callback.

A callback can return before thread-local-storage destructors finish. The regression suite deliberately holds one such destructor and observes the callback result while native teardown is still in progress. This is why an available result is not interchangeable with a join.

The controller operations on a handle must be serialised. Do not race a release against a join or observation through a second copy of the same pointer. The reference count is private worker/controller accounting, not a general shared-pointer API.

For a graphical application, do not blindly wait on a long-running job inside the GUI event loop. Its controller should request cancellation, retain the affected state and arrange orderly completion. This lesson does not introduce a new GTK scheduling service.

4. Cancel by agreement

The worker checks an atomic cancellation flag between characters. Atomic access lets the controller communicate that request without an unsynchronised read/write of an ordinary integer.

& ".\build\thread-safety\bin\umicom-thread-lifecycle.exe" cancel
if ($LASTEXITCODE -ne 0) { throw "The cancellation lesson failed." }

The expected output is:

The Notes index was cancelled before counting; the worker was joined.
Practice complete. No file, database, window or network was opened.

This version queues cancellation before starting, so the exercise is repeatable. A real Cancel command can set the same atomic flag while the worker is running, provided the flag itself remains alive. After the callback acknowledges cancellation by returning, the controller still joins it and releases the handle.

Forcibly terminating a thread is not the same operation. This portable API does not promise to repair locks, files or application state after forced native termination. POSIX cleanup coverage protects the Framework control block on native exit paths; it does not make arbitrary callback cancellation safe.

5. Use the checked release when errors matter

UmiThreadRelease(&thread) clears the caller’s pointer only after the native handle has been successfully closed or detached. A failed native release leaves the pointer owned by the caller. Releasing an already-empty handle is a successful no-op.

The earlier umi_thread_destroy function remains available as a compatibility wrapper. Its void return type cannot explain a native release failure, so new controller code should use the checked operation where that distinction matters.

None of these operations repairs an invalid pointer or permits a double release through a saved alias. Settle the ownership rule first: one controller owns one handle and decides when it is relinquished.

6. Read the complete implementation of the lesson

The file is framework/examples/thread_safety/notes_worker.c. The interesting sequence is near the end: start, optionally observe, join, release, and only then read the completed count and leave the scope.

/*-----------------------------------------------------------------------------
 * Umicom Framework | Sammy Hegab, Umicom Foundation | MIT
 * Count words in a Notes draft on a worker, then join before releasing its data.
 * This is the complete memory-only lesson; it performs no application edits.
 *---------------------------------------------------------------------------*/
#include "umicom/platform/threading.h"
#include <stdatomic.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct NotesIndex {
    const char *text;
    size_t words;
    atomic_int cancelRequested;
} NotesIndex;

static int CountWords(void *context)
{
    NotesIndex *index = context;
    int inWord = 0;
    for (const unsigned char *p = (const unsigned char *)index->text; *p; ++p) {
        if (atomic_load_explicit(&index->cancelRequested, memory_order_relaxed))
            return 2;
        int space = *p == ' ' || *p == '\n' || *p == '\r' || *p == '\t';
        if (!space && !inWord) ++index->words;
        inWord = !space;
    }
    return 0;
}
int main(int argc, char **argv)
{
    if (argc > 2 || (argc == 2 && strcmp(argv[1], "--self-test") && strcmp(argv[1], "cancel"))) {
        fputs("Usage: umicom-thread-lifecycle [--self-test|cancel]\n", stderr);
        return 2;
    }
    NotesIndex index = {0};
    index.text = "Save the workshop notes before closing the window.";
    atomic_init(&index.cancelRequested, 0);
    UmiThread *thread = NULL;
    int result = -1;
    const int cancelling = argc == 2 && !strcmp(argv[1], "cancel");
    /* A queued cancellation is deterministic in this lesson. In an application,
     * its controller sets this atomic flag when the user presses Cancel. */
    if (cancelling) atomic_store(&index.cancelRequested, 1);
    UmiStatus status = umi_thread_start(CountWords, &index, &thread);
    if (status != UMI_STATUS_OK) { fprintf(stderr,"Start failed: %d\n",(int)status); return 1; }
    status = UmiThreadTryGetExitCode(thread, &result);
    if (status != UMI_STATUS_OK && status != UMI_STATUS_BUSY) {
        /* Even an observation error is not a reason to free a live context. */
        (void)umi_thread_join(thread, NULL); (void)UmiThreadRelease(&thread); return 1;
    }
    status = umi_thread_join(thread, &result);
    if (status != UMI_STATUS_OK) {
        fprintf(stderr,"Join failed: %d. Caller data must stay alive.\n",(int)status);
        /* This executable now ends the process; a GUI must retain the context. */
        return 1;
    }
    if (UmiThreadRelease(&thread) != UMI_STATUS_OK || thread != NULL) return 1;
    if (cancelling) {
        if (result != 2 || index.words != 0U) return 1;
        puts("The Notes index was cancelled before counting; the worker was joined.");
    } else {
        if (result != 0 || index.words != 8U) return 1;
        printf("Notes index: %zu words. The worker was joined before its data left scope.\n",index.words);
    }
    puts("Practice complete. No file, database, window or network was opened.");
    return 0;
}

7. Run the regression checks

& "C:\msys64\ucrt64\bin\ctest.exe" `
    --test-dir ".\build\thread-safety" `
    --parallel 2 --no-tests=error --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "Thread regression tests failed." }

The checks cover ordinary and extreme integer results, release while a worker is running, failed allocation, failed native release, self-join and retained mutex/condition behaviour. On Linux, linker wrappers inspect exact allocation release and interrupted-sleep remainders. POSIX-only cases are not counted as Windows passes.

A failed test is not repaired by disabling it or suppressing its warning. Keep its name and output, then investigate the boundary it was checking. The delivery’s validation record distinguishes this focused build from the complete repository suite.

The smaller SDK can also be installed and consumed by the separate client in examples/thread_safety/client. Use the supplied build instructions for that exercise. Keep a focused SDK prefix separate from an installation of the full Framework.

The separate OS repository has a thin host at umicomOS/tools/thread-safety. It selects the same Framework example; it contains no duplicate worker implementation and does not build a kernel or boot a virtual machine.

9. Practise and explain

Why can a released handle still have a running worker?

Release relinquishes the controller’s native handle. It does not instruct the callback to return. Framework must retain the private block until the worker finishes using it.

Can the NotesIndex structure leave scope as soon as release succeeds?

No. It is caller-owned callback data, not the private Framework block. Join before it leaves scope, or provide a separate, correctly synchronised lifetime that outlasts all worker and exit-cleanup uses.

Why does the lesson accept both BUSY and OK from its first observation?

The scheduler may already have finished the short callback. The example must be correct whichever thread happens to run first.

What changes when an observation succeeds?

You have the callback’s result and its published work. Native thread teardown may still be running. Joining remains the way to establish that the whole native thread has ended.

Change the sentence and predict its new count.

Use only the lesson’s documented whitespace rules, then update the expected value in the example, rebuild and run it. For example, “Review the saved notes.” contains four words.

Why are original implementations retained in disabled blocks?

They preserve the earlier design for review. Active replacements explain their ownership change. Deciding to remove the obsolete source is a separate maintenance decision.

Platform references and limits

The native thread rules used here are documented by POSIX pthread_detach, POSIX pthread_join, POSIX nanosleep, and Microsoft CloseHandle.

Mutex recursion differences, condition-variable clock selection, GUI shutdown orchestration, forced native termination and repository-wide race detection are outside this focused change. A passed native test does not certify every application using the service.
