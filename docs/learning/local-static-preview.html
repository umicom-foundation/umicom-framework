Preview local files with Umicom

The native CLI can serve a selected export directory through the same rooted-file and HTTP services used by C applications. Choose a directory containing only files intended for this preview.

1. Inspect the plan

umicom preview --root "C:\Sites\MyExport" --port 8080 --dry-run

This checks path and decimal port syntax. It does not read the directory, reserve the port, start a server or open a browser. The port must be 1024 through 65535.

2. Start the local server

umicom preview --root "C:\Sites\MyExport" --port 8080

Use a matching built or installed CLI. On POSIX, substitute an absolute path such as /home/sam/sites/export. Open http://127.0.0.1:8080/ in your browser. A slash selects index.html; without that file, expect 404. Stop with Ctrl+C in the terminal.

3. Read the actual outcome

Only GET and HEAD are accepted. The server reads a complete regular file below the selected root; links and traversal are refused. Each file must fit 16,383 bytes. A larger file produces 413, a missing file 404 and a denied path 403. Successful replies include their MIME type, nosniff and no-store. HEAD keeps the representation length while suppressing the wire body.

4. Reuse the service in C

Include umicom/web/preview.h and link Umicom::web. Create copies the root and owns routing contexts. Start opens the loopback listener. Handle is available for headless parsed-request exercises; ServeNext performs one bounded native exchange. Destroy releases the listener and service in order. Keep calls on one owner thread and perform file reads away from GUI event handlers.

5. Diagnose startup and shutdown

Unknown or duplicate options are rejected before binding. If the port is occupied, choose another and update the browser address. A client refusal does not stop the listener. A failure before request progress stops the CLI rather than repeating the same listener error indefinitely. The signal handler only records a stop request. Socket waits are bounded, but a synchronous filesystem read must return before normal cleanup can finish.

Limits and qualification

The address is fixed to IPv4 loopback. Host/Origin admission reduces unrelated browser requests; it is not authentication, and local processes can supply allowed headers. This service provides no TLS, upload, directory listing, remote deployment or sandbox. Test the selected source, runtime, port, Unicode root and shutdown behavior on each target. A dry-run is not runtime qualification.

The original local service example remains available with --port and --root. Its native entry now captures Unicode arguments through Framework.
