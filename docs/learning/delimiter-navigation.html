Reuse delimiter discovery and document navigation

The editor service discovers complete delimiter pairs in a stable UTF-8 text view. The document service applies those positions to an identified working copy. Keeping these responsibilities separate lets command-line tools inspect text without importing GTK, a compiler lexer or an application document model.

  1. Link Umicom::editor and include umicom/editor/delimiter_navigation.h. Fill the normal text-view structure metadata, borrowed byte pointer, byte count and capacity. Keep that source unchanged for the duration of the call.
  2. Choose an explicit lexical profile: literal brackets, C quoted/comment content, or JSON strings. The C profile handles escaped physical newlines before interpreting comments and retains original byte offsets.
  3. Call UmiEditorDelimiterMatch for a bracket at or immediately before the caret, or UmiEditorDelimiterEnclosing for the smallest complete pair containing the caret. Successful output includes opening/closing byte positions and their characters. Match also records the chosen anchor; Enclosing uses SIZE_MAX for that field.
  4. Handle NOT_FOUND as an ordinary incomplete or ineligible location. Invalid UTF-8, an interior character/CRLF caret, excess source size or excess nesting returns a failure without changing output.
  5. For a managed document, use UmiDocumentCoordinatorNavigateDelimiter from Umicom::document. Supply the document ID, action and profile. The coordinator captures the complete current draft, discovers ranges, converts exact text positions, rechecks the capture and uses existing navigation history.

Limits and extension points

Input is bounded to eight MiB and the heap-owned open stack holds 512 entries. A crossed or unmatched closer discards the unfinished stack rather than guessing a match. Later independent pairs remain eligible. Literal mode treats all brackets as structural. The C and JSON profiles skip their supported quoted regions, but do not validate full language syntax. C preprocessing decisions, raw C++ strings, alternate delimiter spellings and angle-bracket meaning require a dedicated grammar.

The scanner performs no I/O and does not mutate its borrowed view. Hosts must serialize calls against source mutation. Add a new lexical profile in Framework and cover its quote, comment, escape and incomplete-input rules before selecting it for an application language. Keep compiler parsing separate when the task requires semantic correctness.

Native integration

UmiGtk4AdapterNavigateDelimiter reads the active document identity and language, uses the shared coordinator and refreshes the native selection through the existing editing lifetime. Studio supplies only the three toolbar intents. C and JSON identities select their profile; all other identities remain literal. Read-only documents are accepted because these operations change location metadata only.

Navigation neither synchronizes unsaved typing into a new history entry nor saves a file. It records a normal navigation jump and leaves text Undo unchanged. Selecting a hidden destination also activates the existing fold-reveal behavior. See source navigation ownership for coordinate and lifetime details.

UmiDocumentCoordinatorNavigateActiveDelimiter chooses the profile from the active document identity. Canonical command registration also exposes umicom.document.match-delimiter, umicom.document.select-delimiter-content and umicom.document.select-delimiter-pair. They accept no arguments and retain the established Document command authorization and location-state policy.
