Choose where test fixtures are stored

A test fixture is a temporary workspace containing files created for a test. A failed editor test may keep its fixture so you can inspect the source, settings and logs. These files are separate from your own projects.

1. Choose a visible location

Framework's full CMake build sets UMICOM_TEST_WORK_ROOT to the build folder's test-work directory by default. Each registered test gets a named subdirectory with a short identity suffix. Different builds and tests receive different directories.

You can choose a shorter absolute path, especially when building on Windows. For example, from an Umicom Applications checkout with its dependencies installed:

cmake --preset windows-ucrt64-all-debug -DUMICOM_TEST_WORK_ROOT=C:/Umicom-Test-Work

For a standalone Framework build, add the same option to your existing configure command:

cmake -S . -B build/qualification -DUMICOM_TEST_WORK_ROOT=C:/Umicom-Test-Work

Keep your usual compiler and feature options. The directory is created during configuration. This setting changes where test processes create temporary files; it does not move existing fixtures, change application workspace preferences or redirect the desktop's normal data storage.

2. Build, then record a test run

For the Applications preset:

cmake --build --preset windows-ucrt64-all-debug --parallel 2
ctest --preset windows-ucrt64-all-debug --parallel 2 --output-on-failure --no-tests=error --output-log build/windows-ucrt64-all-debug/tests.log

Stop if the build fails. A test run against older executables does not validate the latest source. A successful run prints a final summary. A log ending at a Start line is incomplete; it cannot establish the result of the remaining tests.

3. Inspect retained evidence

Look under your selected root for the test name. Tests using GLib's temporary-directory helper create a further unique folder there. Their failure output prints the retained path. Other tests may remove their own fixture after success.

Cross-directory test environment configuration requires CMake 3.28 or newer. Older CMake versions retain the existing same-directory limitation. Keep fixtures and raw logs in local build or private working folders; they can contain paths and project data.

Live tests started by Studio or Framework

The native CTest execution service creates its temporary JUnit report beneath SELECTED_BUILD/test-work/umicom-ctest-.... It resolves the build root once, uses a new directory for each invocation, and removes only its own result file and empty directory. It does not fall back to the user profile if the selected build is unwritable.

This temporary internal report is separate from retained test fixtures and saved qualification reports. To keep a complete suite report for review, use CTest's explicit output options described in Inspect saved test reports.

Tests that require a directory outside Git

A repository-discovery test can accidentally discover your source checkout when its scratch files sit below the build directory. A publication-report privacy test must also use a destination outside every checkout. Those tests declare UMICOM_TEST_OUTSIDE_REPOSITORY; normal tests retain the usual work root.

If the normal work root lies inside Git, Framework places these fixtures in _local/test-work beside the outermost checkout. For example, a build below C:/umicom/Umicom-Applications/framework uses C:/umicom/_local/test-work. Test names and build identities still separate each fixture. A normal work root already outside Git is reused.

You can choose the location explicitly:

cmake --preset windows-ucrt64-all-debug -DUMICOM_TEST_EXTERNAL_WORK_ROOT=C:/Umicom-Test-Work/external

The external root must be outside Git checkouts, including submodules and worktrees represented by a .git file. Configuration rejects an explicit external root under a checkout. If the default parent is unwritable, choose an accessible external directory. No source files or Git metadata are moved.

Contributing a test

Use the process temporary-directory API for scratch work. CTest supplies TMPDIR, TEMP and TMP consistently, plus UMICOM_TEST_WORK_DIRECTORY for diagnostics. Keep unrelated environment settings. For tests that need to observe a non-repository location, set the CTest property UMICOM_TEST_OUTSIDE_REPOSITORY TRUE. This changes the fixture environment, not production repository detection. If a fixture deliberately tests a particular temporary-directory policy, give it an explicit test environment override; Framework will leave that policy alone.

For GTK controls inside collapsed sections, lookup is read-only. Explicitly reveal the section before simulating an action, then reacquire the control. Retained widgets from removed panels must remain unable to trigger commands. Checked lookup reports missing, ambiguous and oversized trees as separate outcomes instead of treating all three as an absent control.
