Working with Unicode project paths

Project names can contain characters from many languages. Framework uses UTF-8 for Windows path strings and converts them to the UTF-16 names used by native Windows file APIs. UTF-8 and UTF-16 are two ways of representing Unicode characters. This conversion concerns the name of a file; it does not change the bytes stored inside it.

Create and read a file

  1. Start with the absolute project folder chosen by the user. Keep that folder with the project instead of relying on the process's current directory.
  2. Join the folder and filename with umi_path_join. Check its result: a path that does not fit the supplied buffer is an error.
  3. Use umi_fs_make_directories for an owned project directory. It can create missing parent directories. On Windows, an existing ordinary file at the requested directory path is an error.
  4. Read and write through the filesystem API. Release returned buffers with umi_fs_free_bytes or umi_fs_free_text. The text writer preserves the supplied newline bytes.
  5. Use umi_directory_walk to list entries. Returned Windows names are UTF-8 too, so pass them directly to Framework path operations instead of converting them through the current ANSI code page.
#include "umicom/platform/filesystem.h"

UmiStatus WriteProjectNote(const char *projectDirectory)
{
    char path[UMI_PATH_CAPACITY];
    UmiStatus status = umi_path_join(projectDirectory, "notes.txt", path, sizeof(path));
    if (status != UMI_STATUS_OK) return status;
    return umi_fs_write_text(path, "Project notes\n");
}

The caller must supply an existing project directory. This small example overwrites notes.txt; an editor should use its document save and conflict-review service instead. For replacement of a small application-owned preferences file, see UmiLocalFileReplace.

Copy, rename and remove

umi_fs_copy_file copies bytes and can create destination parents. umi_fs_rename keeps the platform's existing rename policy; Windows does not replace an existing destination through this function. Neither operation establishes a reviewed document save or a conflict-free transaction.

Only call umi_fs_remove_tree for a tree the application owns and the user has chosen to remove. On Windows it refuses drive and share roots, removes reparse points as leaves, and limits recursion to 128 directory levels. A reparse point is a filesystem redirect such as a symbolic link or junction. Refusing to follow it prevents ordinary linked folders from being emptied through the link. This does not protect against another process replacing parent directories during the operation. Failure can leave a partially removed tree.

Check the workflow in an application

  1. Create a temporary project folder with spaces and characters such as café, ملف or 文.
  2. Create a text file, save it, close it and reopen it. Confirm that its contents and displayed name are unchanged.
  3. Refresh the project listing. Copy and rename a disposable file, then reopen the new path.
  4. Configure and build the project with the selected compiler. Framework path handling does not guarantee that every compiler, debugger or external tool supports the same path.

Limits and troubleshooting

Malformed UTF-8 Windows paths are refused. Existing public path buffers, operating-system limits and external tool restrictions still apply; this does not enable extended-length or device paths throughout the suite. On POSIX systems, paths continue to use native byte strings.

The legacy whole-file reader allocates memory for the entire file and uses a long-sized seek. Use the bounded input-file service for untrusted input and streaming services for large media. Folder creation and copy are not atomic multi-file operations. Do not interpret a partial failure as a completed project installation.

Extending Framework

Keep native encoding conversion inside platform adapters. The private native_path_internal.h helper rejects lossy conversion and publishes complete strings. Directory enumeration converts names before the existing sorting, cancellation and visitor logic. Add regression coverage with an independent native reader so two equally incorrect path conversions cannot make a test appear successful.
