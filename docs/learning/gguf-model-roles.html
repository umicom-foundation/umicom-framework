Is this GGUF file a complete model?

A file ending in .gguf is a container, not a promise that it can answer a chat message. A container describes how information is stored. Its contents may be model weights, auxiliary data for another model, or vocabulary information. This lesson reads metadata without starting an inference engine.

Start with files and paths, bytes and PowerShell if those terms are new. For the C API, also complete the first C program and SDK project setup.

1. Separate five questions

QuestionEvidence needed
Which file did I choose?An explicit path and the intended repository/revision, where known.
Which bytes were read?A complete file byte count and SHA-256 digest.
What role does it declare?Parsed role metadata, with missing values kept unknown.
Can this engine use it?Tensor layout, architecture, tokenizer and runtime compatibility checks.
Did generation work?An actual request and result from the identified runtime.

A digest is a fixed-size value calculated from the file's bytes. Matching a reviewed digest helps establish byte identity. It does not prove who published the file or that its contents are correct. Metadata describes data; weights are the numerical values used by a model. A runtime or inference engine executes the model's operations.

2. Read the role instead of guessing from the name

GGUF stores typed key/value metadata before its tensor descriptions and data. Keys include an architecture identifier; values can include strings and arrays. Umicom's inspector reads the little-endian version 2/3 metadata profile and reports selected identity fields. It does not validate every tensor. See the GGUF format specification.

A control vector is supplied alongside a base model. It is not itself a substitute for that base model. The llama.cpp control-vector example shows separate model and control-vector arguments. LoRA adapters likewise declare an adapter type and must match the intended base model; the upstream adapter loader checks those identities.

Umicom observationWhat it means
auxiliaryRecognized controlvector/clip architecture, declared adapter type, or an adapter.type field. Do not select it as a standalone text model merely because its extension is GGUF.
vocabulary-onlyNo declared tensors and no recognized auxiliary classification. This is not a full weight set.
model-candidateAn architecture exists and the general type is absent or model. The inspector has not established completeness or compatibility.
unknownInsufficient or unrecognized role information. Do not silently turn this into “ready”.
The role command remains a read-only observation. Current native run and serve session submission also uses shared role inspection and a reviewed digest. Auxiliary or unknown roles are refused before a process is created. Candidate status still does not establish engine compatibility. See the native admission lesson.

3. Inspect a local file with the native CLI

  1. Use a current Framework build that includes the optional model_formats component. The build must contain the new command; a new source file alone does not update an older executable.
  2. Find the exact existing GGUF file you intend to inspect. Replace C:\models\selected.gguf below with its full path. This lesson does not download a model.
  3. Check that both files exist. Run each PowerShell line separately, and stop if a command fails.
Test-Path "C:\umicom\Umicom-Applications\framework\build\windows-ucrt64-debug\bin\umicom.exe"
Test-Path "C:\models\selected.gguf"
& "C:\umicom\Umicom-Applications\framework\build\windows-ucrt64-debug\bin\umicom.exe" models inspect-role "C:\models\selected.gguf"
$LASTEXITCODE

& asks PowerShell to run the quoted executable path. The command reads the complete file to calculate its digest, so a large model may take time even though the parser retains only a small amount of metadata. $LASTEXITCODE is the last native program's exit status: zero means inspection and output delivery succeeded, not that inference succeeded.

Read the fields labelled Bytes, SHA256, Role, Architecture, Type, Adapter type, and the metadata/tensor counts. Their values depend on your file. A recognized control vector should report Role: auxiliary; a candidate result still requires runtime qualification. The standalone umicom-models host accepts the same command without the leading models word.

The older models inspect command remains available for its original basic-header and digest checks. Use inspect-role when you need the additional metadata distinction. If this optional component is unavailable, the command reports an unsupported operation rather than pretending to have inspected the file.

4. Use the same service from C

Request the model_formats component from the installed SDK and link Umicom::model_formats. The following fragment belongs inside your application's checked operation; it is not a complete program:

#include "umicom/model_formats/gguf.h"

UmiGgufFileInspection result = {0};
UmiStatus status = UmiGgufFileInspect(
    "C:/models/selected.gguf", NULL, NULL, &result);
if (status == UMI_STATUS_OK) {
    /* Present the copied role and identity for review.
       Do not equate MODEL_CANDIDATE with engine readiness. */
}

The second argument can point to an expected byte count and binary SHA-256 identity. Passing NULL records what was observed without asserting a previously reviewed identity. The third argument is an optional cancellation token. The final argument is where the completed result is written. An error leaves that result unchanged, so a GUI can retain its previous complete observation while displaying the new failure.

Call blocking file inspection on a worker, then pass a copied result back to the UI using the application's existing event service. Do not capture a mutable model picker and read it again halfway through the operation. The chosen path and request identity belong to that request.

5. Keep parsing memory bounded

The native scanner stores fixed-size fields and a bounded array stack. Large unselected strings and arrays are consumed from successive chunks rather than copied into a model-sized buffer. It limits metadata bytes, entries, nested array frames and total values. Selected role strings and keys have fixed bounds too. A limit refusal is explicit; increasing a limit requires reviewing time and memory costs.

The shared file reader owns one regular-file handle, checks it before and after reading, and closes it before publication. File changes, a late read/close failure, or cancellation cannot publish a successful partial digest. This is not a permanent file lock: a later operation must recheck identity before using the path again.

Not every metadata value is fully validated. Unselected strings are skipped as raw bytes; selected role fields must meet the documented ASCII profile. Tensor offsets, tensor shapes, numerical values and architecture support remain outside this inspector. Unsupported versions or profiles should produce an error, not a guessed answer.
