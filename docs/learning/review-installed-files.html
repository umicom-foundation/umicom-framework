Review installed files and choose a program

Building produces files in a build folder. Installing copies selected programs, libraries and resources to an install folder. Studio can review CMake's full-install manifest and copy one installed program into the project's run settings.

From installation to a run setting

  1. Open a project you control and its build settings. Choose the actual build folder and install folder. Relative folders are resolved from the project folder. When using presets, inspect the CMake cache to check the actual folders; install review does not evaluate presets.
  2. Apply the intended settings, configure and build successfully, then use the project's Install action. Resolve any install error before proceeding. A manifest may remain from an earlier run, so its existence alone does not prove that the latest install succeeded.
  3. Reopen build settings and choose Read installed files. The read runs in the background. A full installation normally writes install_manifest.txt in its build folder. The list keeps the manifest's order and reports missing or unreadable entries.
  4. Search the list and select a program. A regular .exe is a candidate on Windows; POSIX platforms require executable permission on a regular file. Directories, links and data files cannot be copied through this action.
  5. Choose Use installed program. Framework rechecks the manifest bytes and the selected file's metadata. On success, only Program to run changes. Your arguments, working folder, build options and trust choice remain as entered.
  6. Review the program, arguments and working folder. Choose Apply Settings, then use the normal Run action separately when you want to launch it. This review never launches a program or grants execution trust.

Recover from a refused selection

If folders or the program field change during a read, read again. If a manifest or file changes after inspection, complete the installation again and refresh the list. Missing files remain visible so you can identify incomplete or moved installations. A failed read never changes the program field.

Review supports a full-install UTF-8 manifest with at most 32,768 paths and 16 MiB of text. Paths must stay lexically under the selected install prefix. Component-specific manifests, DESTDIR staging, UNC/device paths on Windows, filenames containing control characters, and aliases requiring filesystem identity resolution are outside this workflow. Choose ordinary absolute folders or use manual run settings for those installations.

What the review establishes

The manifest is a local list, not an installer receipt or a signature. File size and modification time are observations, not content hashes. They do not establish that dependencies are present, an executable is compatible, or a program is trustworthy. Files may change after review, and parent directory links may be followed. Use an install folder you control.

Use the service in another frontend

Include umicom/developer_project/installed_files.h and link the developer module. Call UmiProjectInstalledFilesRead on a worker with a copied profile and optional cancellation token. Retain the returned catalogue while displaying rows. Call UmiProjectInstalledFilesSelect on a worker for an explicit choice, then apply the resulting profile separately on the owning UI thread. Destroy the catalogue only after all readers finish.

Future frontends can reuse the same parsing, cancellation and stale-file checks. Support for component installs should be a separate explicit manifest choice, rather than silently guessing which install run a user intended.

See the CMake install reference for install prefixes and components.

Find a program in a long install list

  1. Read installed files after a successful full installation.
  2. Enter part of a path, or program candidate to find executable candidates. Choose Original order, Text A-Z or Text Z-A, then press Apply filter and order. Matching is literal; Ignore case folds ASCII letters only.
  3. Select a visible row and inspect its full path and status. Filtering a selected file out clears its selection. Clear the text and apply again to recover the complete list.
  4. Choose Use installed program. The manifest and file are checked again before the path is copied. Reordering during that check keeps the same file identity; hiding it or choosing another row refuses the late result.
  5. Review Program to run, arguments and the working folder, then Apply Settings. Run remains a separate action.

A new manifest read clears the previous selection and keeps the applied filter. If no rows appear, clear that filter. A failed read or changed input requires another read; a matching label never substitutes for executable validation.
