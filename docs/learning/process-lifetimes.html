Own background process lifetimes

A build command starts another program and waits for its result. While that program runs, the editor should still respond to input. Framework's process supervisor owns background jobs so Studio can observe output and completion without placing every process directly in its user-interface code.

A job is the supervisor's record of one submitted request. It includes a job identifier, a worker, cancellation state and a result snapshot. A terminal job state means the result has been published. It does not by itself mean every native thread handle has been released.

Separate three obligations

ObligationMeaningWhat it does not establish
Close admissionRefuse new jobs and request cancellation for active jobs.Workers may still be running.
Join workersWait until workers have returned and acknowledge their native thread completion.A native handle may still need release.
Release ownershipClose native handles and free the supervisor's job storage.Separate application payloads and borrowed aliases are not automatically managed.

umi_process_supervisor_shutdown closes admission, requests cancellation and waits for occupied jobs. A second call checks any unfinished join obligations. It must not return success merely because an earlier call already closed admission. Call it from an external lifecycle controller, not from work whose completion it must wait for.

Keep the owner until release succeeds

  1. Prevent new UI commands from submitting jobs.
  2. Stop other application users of the supervisor and exclude concurrent calls.
  3. Call UmiProcessSupervisorRelease(&supervisor).
  4. If it returns UMI_STATUS_OK, the pointer is cleared. Release separate application state only when its other background owners have also stopped.
  5. If it returns an error, retain the pointer, record the status and investigate the failing operation. Retry shutdown or release from the same exclusive owner. Do not resume submission after shutdown has closed admission.
UmiStatus status = UmiProcessSupervisorRelease(&supervisor);
if (status != UMI_STATUS_OK) {
    /* supervisor remains owned here. Report the error and keep its
     * dependent data alive until shutdown can be completed. */
    return status;
}
/* supervisor is now NULL. */

This fragment belongs in a controller that already owns the pointer. Passing a borrowed copy does not make the caller the owner. Clearing one pointer cannot clear other aliases elsewhere in the application.

The established umi_process_supervisor_destroy function remains available. Because it returns no status, new lifecycle code should use checked release. The compatibility function retains memory if shutdown fails; a caller must not infer successful cleanup simply because that void function returned.

Release completed jobs without closing the supervisor

UmiProcessSupervisorReleaseJob acknowledges a terminal job and makes its slot reusable. It refuses an active job or a slot pinned by a waiter. If joining or native-handle release fails, the identifier and result remain available. Retry the same job release instead of submitting another job into storage that may still be owned.

A joined worker whose handle could not close must not be joined twice. Framework records join progress separately from handle ownership. A native thread that finished without an ordinary integer result may return UMI_STATUS_UNAVAILABLE; that diagnostic is retained while the consumed join obligation is recorded.

Read and qualify the implementation

Start with include/umicom/platform/process_supervisor.h, then follow src/platform/process_supervisor_lifecycle.inc and tests/test_process_supervisor_lifecycle.c. The regression fixture launches its own executable as a small child, captures its output and examines terminal state. It does not invoke a shell or an arbitrary external command.

After configuring a Framework build with testing enabled, build the target umicom-process-supervisor-lifecycle-test and run CTest with -R "^framework[.]process_supervisor[.]lifecycle[.]" --output-on-failure --no-tests=error. On Linux with GNU or Clang, the additional umicom-process-supervisor-lifecycle-fault-test target injects a single join or release error; its tests use the framework.process_supervisor.lifecycle-fault. prefix. These fault cases verify retained ownership and retry progress; they are separate from ordinary process execution tests.

Apply the same reasoning to other background owners

A window, file index or document model can be used by several workers. Stopping one owner is not enough if another callback still references the same model. Read Watch files without releasing live callbacks and Check queue shutdown through an installed SDK before composing these services.

For application modules that depend on those services, see Design retryable module lifecycles.
