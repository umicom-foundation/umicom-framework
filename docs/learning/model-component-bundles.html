Plan model component bundles in C

Record the exact selected bytes before designing download, installation or inference.

A text model may arrive as one GGUF file. Other models can require weights, tokenizer data and configuration files, sometimes in several directories. A bundle plan groups an explicit selection under one immutable repository revision. It does not decide whether the selection contains every file needed by an engine.

This API is pure planning. It makes no network request, opens no model file and reports no model as ready. A filename extension and a supplied digest are expectations to verify later, not evidence of valid content or a working model.

1. Understand the identity record

FieldMeaningWhat it does not establish
RepositoryAn explicit owner/repository namePublisher trust, licence acceptance or authorization
RevisionA full lowercase 40-digit commit identifierThe actual downloaded content identity
FilenameThe selected relative path within that revisionA safe resolved destination directory
SHA-256The exact expected file digestSuccessful verification until actual bytes are hashed
Byte countThe exact expected sizeRequired RAM, VRAM or temporary download space
FormatA supported filename classificationA successful parser, tensor validator or inference backend

UmiModelBundlePlanCreate copies the complete selection into owned inline fields. It accepts one to 128 files and bounds total selected bytes to UMI_MODEL_MAX_BYTES. Every file needs a digest and positive size. GGUF requires at least 24 bytes and Safetensors at least 10 bytes; these minimum sizes are admission boundaries, not content validation.

2. Build a synthetic plan without downloading anything

The following complete program uses deliberately synthetic metadata. Do not use its hashes to download a real model. Replace every identity field with reviewed publisher metadata when preparing a real selection.

#include "umicom/local_models/bundle.h"
#include <inttypes.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    UmiModelBundleFile files[2] = {0};
    strcpy(files[0].filename, "weights/model.gguf");
    files[0].format = UMI_MODEL_ARTIFACT_GGUF;
    files[0].bytes = 24U;
    strcpy(files[1].filename, "config.json");
    files[1].format = UMI_MODEL_ARTIFACT_JSON;
    files[1].bytes = 2U;
    for (size_t i = 0U; i < 2U; ++i)
        memset(files[i].sha256, 'a', 64U); /* Synthetic digest, not real model evidence. */

    UmiModelBundlePlan *plan = malloc(sizeof(*plan));
    if (plan == NULL) return 1;
    UmiStatus status = UmiModelBundlePlanCreate(
        "umicom-fixtures/synthetic",
        "0123456789abcdef0123456789abcdef01234567", files, 2U, plan);
    if (status == UMI_STATUS_OK)
        printf("Selected %zu files, %" PRIu64 " bytes. No files downloaded.\n",
            plan->count, plan->total_bytes);
    else
        fprintf(stderr, "Bundle admission refused: %d\n", (int)status);
    free(plan);
    return status == UMI_STATUS_OK ? 0 : 1;
}

Expected output after a successful qualified build:

Selected 2 files, 26 bytes. No files downloaded.

The plan is large enough to keep off a small worker stack. The constructor also allocates staging storage. If any input is refused or allocation fails, the caller's previous complete plan remains unchanged. Repository, revision and file inputs may borrow fields from that previous plan during replacement.

3. Refuse ambiguous selections

Framework checks every live file before accepting the selection. It rejects traversal, unsupported characters, duplicate paths, case-insensitive aliases and file/directory prefix conflicts. For example, model.gguf and MODEL.gguf collide. So do config.json and config.json/child.json. Two different files in the same directory are permitted.

The service reuses the existing model-name grammar and native output-path syntax checks. It does not normalize an unsafe name into a safe-looking replacement. Host-specific restrictions are applied on the current host; revalidate on the destination host. The syntax check uses a synthetic absolute prefix only for validation and never accesses that path.

FormatAdmitted names
GGUFLowercase .gguf extension
SafetensorsLowercase .safetensors extension
Metadata and text.json and .txt
Tokenizer data.model, .tiktoken, .vocab, .merges
DocumentationREADME.md, LICENSE, LICENCE, LICENSE.md and LICENCE.md; case-insensitive basenames

No supported format admits Python modules, DLLs or pickle checkpoint extensions. That restriction does not prove that an admitted file contains safe or correctly formatted bytes. Content parsers and execution policy remain separate.

4. Query the exact selected record

UmiModelBundlePlanValidate validates every record and recomputes the total. If a caller edits total_bytes without matching the files, it returns UMI_STATUS_INVALID_STATE. Unused array slots do not affect admission.

UmiModelBundleUrlAt builds a pinned public HTTPS URL from the validated repository, revision and selected filename. It does not accept an arbitrary URL and does not send a request. If the output buffer is too short, every output byte remains unchanged.

UmiModelBundleGgufSourceAt copies a selected GGUF record into the established UmiModelSource contract. For other formats it returns UMI_STATUS_NOT_IMPLEMENTED. This keeps the existing single-GGUF downloader's verified behavior intact. A bundle plan does not silently turn that downloader into a generic file-transfer or pipeline-installation service.

4a. Select every explicitly numbered GGUF companion

A split GGUF publication can use names such as weights/model-00001-of-00003.gguf. Each suffix states a part number and a declared total using five decimal digits. Selecting part two should not silently omit parts one and three.

  1. Build a catalogue plan containing the reviewed files from one pinned repository revision. Include exact expected sizes and digests.
  2. Pass the index of any GGUF part to UmiModelBundleSelectGguf.
  3. Framework validates the whole catalogue, recognizes the explicit numbered suffix, and requires all exact companion names from part one through the declared total.
  4. On success, the output contains only those GGUF parts in numeric order. The unrelated configuration and documentation records are not selected.
  5. If a companion is missing, the result is UMI_STATUS_NOT_FOUND and the previous output plan is unchanged. Keep the reviewed catalogue and investigate the publisher's complete file list before trying again.

For a catalogue ordered as part three, configuration, part one, part two, selecting index zero produces parts one, two, three. All original digest and size records survive selection; the output total is recalculated. The output can replace the input catalogue in place because the service stages the complete selection before publishing it.

/* catalogue and selected are complete caller-owned plans.
 * This call performs no download or model execution. */
UmiStatus status = UmiModelBundleSelectGguf(catalogue, 0U, selected);
if (status == UMI_STATUS_NOT_FOUND) {
    /* Keep the previous selection and obtain the missing pinned metadata. */
}

The basename prefix must be nonempty. Parts start at one, cannot exceed the total, and the total cannot exceed 128. A malformed recognized suffix is refused. Companion spelling is exact and case-sensitive because it names a repository file. Other filename patterns, including model-1-of-3.gguf, stay single-file selections with completeness unassessed. The selector does not guess alternate publisher conventions.

A complete declared filename set is still not proof of a valid GGUF model. The file headers may disagree, tensors may be corrupt, and the engine may not support the architecture. This selector does not inspect those bytes or qualify a backend.

5. Keep selected, verified and runnable states separate

  1. Selected: admit the exact repository revision and files into a bundle plan.
  2. Downloaded: an explicitly approved transfer obtains bytes in a controlled staging location. A future bundle downloader must enforce destination confinement and preserve partial failures.
  3. Verified: compare every actual file size and digest, then validate its format. Publish a completion receipt only for the complete selected set.
  4. Compatible: a qualified backend recognizes the architecture, tokenizer and configuration. Check all required shards and components.
  5. Ready: an owned runtime loads the model and supplies current readiness evidence. Keep that observation bound to model and runtime identity.

These bundle APIs implement selection only. The general constructor accepts an explicit file set without inferring completeness. The GGUF selector additionally checks every companion declared by its supported numbered filename convention. Neither validates tensor metadata, reserves disk space, assesses memory needs nor proves that image/video generation will work. Keep those as explicit services rather than deriving them from the presence of files.

6. Use and qualify the installed SDK

Include umicom/local_models/bundle.h and link the existing Umicom::local_models component. The existing installed model consumer now exercises synthetic bundle admission and the refusal to expose data components through the GGUF-only execution contract. It remains an offline consumer.

find_package(UmicomFramework CONFIG REQUIRED COMPONENTS local_models)
add_executable(model-bundle-example main.c)
target_link_libraries(model-bundle-example PRIVATE Umicom::local_models)

Run each producer qualification command separately and stop on an error:

Set-Location C:\umicom\Umicom-Applications\framework
cmake --preset windows-ucrt64-debug
cmake --build --preset windows-ucrt64-debug --target umicom-model-bundle-test umicom-model-bundle-allocation-test
ctest --test-dir build/windows-ucrt64-debug -R "^framework\.local_models\.bundle(_allocation)?\." --output-on-failure

Also qualify companion selection and its allocation ownership:

cmake --build --preset windows-ucrt64-debug --target umicom-model-bundle-selection-test umicom-model-bundle-selection-allocation-test
ctest --test-dir build/windows-ucrt64-debug -R "^framework\.local_models\.bundle_selection(_allocation)?\." --output-on-failure

These are commands to execute, not a claim that native qualification has passed. Configuration checks target registration; compilation, tests and the independently installed consumer must be verified separately. No real model weights are needed by the synthetic tests.

7. Extend the design without overstating it

Media can show a selected component set and its byte total before a reviewed download. LLM applications can use the same record for multi-file model libraries. Studio can explain a missing component and attach source identity to a workflow proposal. The actual app wiring, bundle materializer and model-specific compatibility checks are separate work.
