Lesson 14

GTK widgets and events

GTK builds a graphical interface from widgets. A window contains other widgets, such as labels and buttons. Containers arrange those children. A graphical application also has an event loop that receives input and dispatches callbacks.

In this course, Framework creates the components. GTK supplies the adapter's event loop and widget ownership mechanisms. You are composing the existing implementation, not replacing it.

Trace the lifetime

Open framework/examples/learning/window/main.c and find main.

create GtkApplication
    -> connect activate
    -> run the event loop
    -> activate builds the window
    -> events call callbacks
    -> last window closes
    -> release the application

g_application_run is not a quick “draw once” call. It normally remains active while the application is running. Code after it handles shutdown.

Read the widget tree

window
  box, arranged vertically
    label
    button

The box places its children one after another. Spacing and margins provide readable gaps. This avoids hard-coding every label to an absolute screen coordinate. A movable workspace canvas is a different shared Framework facility; a small introductory window does not need to reimplement it.

Understand the button callback

static void SayHello(GtkButton *button, GtkLabel *label)
{
    (void)button;
    gtk_label_set_text(label, "You connected a button to a C function.");
}

static limits this function name to this source file. The callback receives the button that emitted the signal and the label supplied as associated data. (void)button states that this example intentionally does not use the button parameter.

The signal connection uses g_signal_connect_object. Its object-lifetime connection avoids keeping a callback pointed at a destroyed label. The widget tree owns its children; the callback must not call free(label).

Avoid freezing the interface

A callback should do short work. Long compilation, file indexing or network operations belong in the existing Framework job or service facilities. Their results can be delivered back to the UI thread. Starting a long loop inside a click handler can stop the window from responding even though the operating-system process still exists.

Check the environment

pkg-config --modversion gtk4

Framework's current GTK adapter requires GTK 4.10 or later. A Linux headless build does not create a display session. Under WSL, use a working WSLg session; do not set an invented DISPLAY address to hide a configuration problem.

Try it

Locate the signal connection for clicked. Follow its callback and identify the one line that changes the visible text. Predict whether clicking it a second time creates a second window. Then compare your prediction when running the next lesson.

Compare your answer

The click changes the existing label. It does not create another window. Re-activation of the application also presents its existing active window rather than building another tree.
