Search workspace symbols through a captured source connection

The workspace-symbol query shares native transport, owned catalogues and checked navigation with document symbols. Its search scope and server capability are explicit, so a project query cannot silently become a document outline.

  1. Include umicom/language_runtime/symbol_query.h and link Umicom::developer.
  2. Fill UmiLanguageWorkspaceSymbolRequest. Its source member carries the project URI, exact document URI, language ID, complete UTF-8 source and timeout. Its query is a non-null UTF-8 string, up to 4096 bytes; an empty string is valid.
  3. Copy the request strings and server configuration into worker-owned memory. Keep that memory alive until UmiLanguageWorkspaceSymbolQueryNative returns. The worker must not access document-owner state or native widgets.
  4. The operation negotiates workspaceSymbolProvider, UTF-16 positions and document synchronization. It sends the captured primary document, then a workspace/symbol request containing only the search query.
  5. On success, enumerate UmiLanguageSymbolCatalogue. Each result owns its name, optional container label and complete location. Workspace rows are flat; container names do not define a hierarchy. A null server result becomes an empty catalogue.
  6. On the document owner's thread, recheck the captured source and explicitly open the chosen location. Primary-source ranges were checked during the query; other source ranges must be checked against the actual destination text before navigation.
  7. Destroy the catalogue when it is no longer needed. The native query withholds results if document closure or server shutdown fails.

UmiLanguageWorkspaceSymbolQueryOnServer accepts an exclusively owned server in STARTING state. Invalid preflight leaves it untouched. Once initialization begins, the query owns connection cleanup; the caller still destroys the server object after return.

Protocol and ownership boundaries

The client does not advertise lazy symbol resolution. Every returned row must contain a full URI and range. Hierarchical document symbols, malformed rows and incomplete locations reject the whole result. No symbol command or opaque server action is executed. Unknown positive symbol kinds retain their value and use a generic display label.

Only the primary draft is synchronized. There is no persistent index, background refresh, dynamic registration or partial-result accumulation. The server controls matching and which workspace files it indexes. Extensions that synchronize additional drafts must capture and validate those dependencies explicitly rather than reading live widgets in a worker.

Queries retain existing native message and catalogue bounds: 65536-byte native JSON messages, 4096 catalogue rows and 1 MiB catalogue input. JSON escaping can exceed a request buffer before the raw query reaches 4096 bytes. A capacity error publishes no partial catalogue.

Initialization and query reads share the requested timeout. Read cleanup has its own bounded allowance. Cancellation is cooperative between operations; native startup and synchronous writes retain their existing limits. A server can spawn descendants; the transport owns its direct child.

Recovery

  1. For an unsupported capability, use a server that implements workspace symbol requests or explicitly choose document scope.
  2. For invalid coordinates, recapture source rather than rounding positions.
  3. For empty results or timeouts, inspect the project root and server indexing configuration. Neither condition proves successful project analysis.
  4. For stale UI results, retire the catalogue and request again. Restoring earlier query text must not revive earlier authority.
