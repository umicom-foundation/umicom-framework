Definition lookup finds where a symbol is declared or implemented. Reference lookup finds places where it is used. Framework separates requesting these locations from opening a file, so the user can inspect the destination first.

Find a definition or its references

  1. Open a source draft and place the caret before the symbol you want to explore. A selection uses its starting position. Read-only source documents also support lookup.
  2. Choose Definitions… or References… in Studio's editor command bar. Scroll the bar horizontally if necessary. Opening the form captures the draft and caret; it does not start a server.
  3. Enter a trusted language server's absolute executable path, arguments and project folder, or choose Load saved server. These ordinary local settings are shared with completion, formatting and source information for the same language. Loading settings does not launch a process. Keep credentials out of these unencrypted path and argument fields.
  4. For references, choose whether to Include the declaration. Choose Find definitions or Find references. The selected local program receives the captured draft and can inspect the project folder.
  5. Review the returned locations in the searchable list. Each row shows a URI, line and UTF-16 column; the displayed line and column start at one. A URI identifies a document, for example file:///C:/Projects/Demo/main.c. Fetching the list does not open a destination.
  6. Select a row and choose Open selected location. An already open target uses its complete current draft, including unsaved edits. An unopened local file is read through the document provider. The requested selection must fit the target text before a new tab is attached. A successful opening closes the form.
  7. Use Studio's existing navigation Back and Forward actions to revisit the departure and destination carets. Navigation does not change source bytes, add an Undo edit or save a file. It also works when the target draft is read-only.

When a result cannot be used

SituationRecovery
No locationsA server may legitimately return an empty list. Try a different symbol in a new capture. Project indexing may need a persistent connection, which this temporary request does not provide.
The source changedClose the form and reopen it after moving the caret, editing the draft, saving, or changing document permissions. This avoids using locations computed for an earlier source state.
The server choice changedRequest again. Changing arguments, paths or declaration inclusion invalidates the previous result, even if a setting is changed back. Closing the editor cancels publication of a late worker result.
The target range is invalidThe target may have changed since the server indexed it. Exact range selection refuses missing lines and positions that split Unicode characters. The current tab remains available; choose another row or request fresh locations.
The URI is unsupportedNew targets must use a local file URI. Remote authorities, implicit network paths, query strings, fragments and malformed percent escapes are refused. A document already managed under an exact URI may still be selected without opening that URI. Windows device aliases and alternate data streams are not accepted as new source files.
Timeout or unsupported serverThe selected server must advertise the requested capability, document open/close synchronization and UTF-16 positions. The form has a five-second read budget and a 65536-byte message capacity including the escaped draft and JSON envelope, with at most 4096 parser tokens. Synchronous launch and writes may finish before cancellation.

Extend the shared services

UmiLanguageNavigationQueryNative owns the temporary connection: initialize, open the copied draft, issue the chosen request, close the draft and shut down the server. It returns an owned UmiLanguageLocationCatalogue only after successful cleanup. A supplied-server variant requires a new server in its starting state; it must not interrupt an existing editor session.

The catalogue accepts definitions as a location, a homogeneous location list, or a list of location links. Links retain their target range, selection range and optional origin range. Reference replies accept locations only. The decoder checks the response identity, URI syntax, ordered endpoints and selection containment. Ranges referring to the captured URI are checked against that source immediately. Other target content is checked only when the host opens the chosen selection.

The standalone catalogue reader allows 1 MiB of JSON, 4096 locations and 8192 bytes per URI. These limits are larger than the native form's transport limit. A caller must handle capacity failures instead of assuming a partial list. At returns borrowed URI text that lasts until catalogue destruction; copy it before invoking callbacks that may retire the catalogue.

UmiDocumentSourceRequestCreateInspection captures the source without granting Stage or Apply permission. The GTK host rechecks that capture before requesting and before opening. UmiDocumentCoordinatorOpenSourceRange copies the URI, finds an existing draft by exact URI or normalized local path, then resolves the exact UTF-16 selection. Otherwise it loads a local target through the existing provider, with a 16 MiB source limit, and validates before attaching. Provider I/O is synchronous on the owning thread after the user's explicit Open action. Keep the coordinator alive during provider callbacks.

The document owner records successful jumps in its existing history. Go to Line, bookmarks and history share LF, CRLF and CR line-ending rules. Their existing one-based byte-column contract remains unchanged; only protocol selections use zero-based UTF-16 columns. If an older bookmarked line becomes shorter, its byte column clamps to the end without splitting a UTF-8 character.

Current boundaries

The local path decoder checks syntax; it does not confine access to a project folder, resolve symlink trust, or detect a network mount behind a local path. The native session owns only the direct child, not descendants started by the server. Server-to-client configuration requests, persistent indexing, automatic typing queries and server installation are outside this explicit workflow. Completion, formatting, information and navigation share one source-tool slot.
