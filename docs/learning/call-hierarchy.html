Own native caller and callee inspection

Framework separates protocol ownership from document navigation. The call catalogues own validated server results. The native query owns the temporary server session. The document coordinator owns opening a current local source range. Applications choose a direction and connect these existing services.

  1. Capture the document URI, language, UTF-8 source, byte length and caret byte offset. Put these in UmiLanguageCallRequest.source and choose UMI_LANGUAGE_CALL_INCOMING or UMI_LANGUAGE_CALL_OUTGOING.
  2. Call UmiLanguageCallQueryNative with a local server profile, or UmiLanguageCallQueryOnServer with an exclusively owned starting connection. Keep input strings alive until the call returns.
  3. The shared query validates inputs, negotiates call hierarchy and UTF-16, opens the captured draft and sends textDocument/prepareCallHierarchy.
  4. Each complete prepared item is returned to the same session in callHierarchy/incomingCalls or callHierarchy/outgoingCalls. Opaque data and extension properties remain intact; they are not reconstructed from a displayed name.
  5. Use UmiLanguageCallResultRootCount and UmiLanguageCallResultRootAt to inspect prepared symbols, including those with no relations. Use UmiLanguageCallResultCount and UmiLanguageCallResultAt for the flat direct relationship list.
  6. Read destinations with UmiLanguageCallResultLocation. Destination zero selects the related symbol. Destinations one through call_sites select each exact call expression in the caller's URI.
  7. Before explicit navigation, recheck the captured document request and copy borrowed metadata before host callbacks can destroy its owner. Open through the document coordinator, which validates current text positions and preserves unsaved drafts.
  8. Destroy the result with UmiLanguageCallResultDestroy when it is no longer displayed.

Decode replies independently

UmiLanguageCallItemCatalogueCreate reads a complete prepared-item array; ReadResponse also checks response correlation. Names, details and URIs are copied. The catalogue retains the original JSON tree so ItemJson can return the whole object with opaque provider state. The shared symbol-label helpers also serve document outlines; the existing editor call-graph traversal service remains available for already indexed symbols.

UmiLanguageCallEdgeCatalogueReadResponse reads one root's direct incoming or outgoing relationships. It copies the root URI and owns each related item and call-site range independently. Incoming sites use the returned caller's URI; outgoing sites use the prepared root URI. Empty arrays and duplicate sites remain in server order. These readers never access source files or run commands.

Boundaries and failure behaviour

Standalone readers bound input to one MiB, 131,072 JSON nodes, 80 container levels, 4,096 items or relations and 16,384 sites. Labels allow 4,096 decoded bytes; URIs allow 8,192 bytes. Those are upper bounds, not promises that a result reaching every limit will fit the combined budgets. Names must contain visible text, kinds and tags are positive integers, ranges are ordered, and symbol selections fit their enclosing ranges. Invalid known fields reject the whole result.

The native owner limits preparation to 16 roots and totals to 4,096 relations and 16,384 sites across all roots. It also applies the smaller per-message native transport and parser bounds. Every range whose URI exactly matches the captured source is checked against that source, including Unicode character boundaries. A prepared symbol may refer to another URI or a definition elsewhere; it need not contain the original caret.

Initialization, preparation and follow-up replies share one elapsed read budget. The shared cleanup path closes the captured source and shuts down the server before publishing results. Any query, cancellation or cleanup failure discards the complete result. Preflight failure leaves an owned starting connection untouched. After initialization starts, the query owns cleanup; the caller still destroys its server object. The native owner controls its direct child, not descendants.

Extend the workflow

A future persistent call graph can feed validated relationships into the existing editor graph services. It will need explicit source revisions, index invalidation and provider-session ownership. Do not replay opaque call items to a newly started server or treat this one-shot result as a current project-wide index. Other unsaved documents are not synchronized by this query.
