Review and restore saved workspaces

A workspace has several kinds of saved information. A named layout describes where panels appear. A desktop checkpoint contains notes and appearance preferences. These controls keep their scopes separate, so recovering an arrangement does not replay a business action.

Recover named layouts in an application

Studio and applications using Framework's shared Layout Library, including Trader and Bank, offer the same complete comparison. Media, Music and the other shared workstations use this control too. Storage must be connected by the application; a memory-only service cannot keep a library after the application closes.

  1. Finish your layout edit using Apply and Lock, or cancel it. Open Layout Library.
  2. Choose Save library when you want to keep all named arrangements, including inactive layouts. This is separate from saving source files, media projects or account data.
  3. To inspect the saved copy, choose Review saved layouts. The current workspace stays unchanged. Read both sides of the comparison, including hidden panels, placement, size and linked context identifiers.
  4. If recovery used the last valid saved copy because the latest copy was unusable, the comparison explains that. Inspect it carefully; displaying it does not repair the saved data.
  5. Tick Replace my named layouts with this reviewed library, then choose Apply reviewed layouts. Only the exact arrangement displayed is applied. A later storage write cannot substitute different content.
  6. If you change your mind after applying, use the library's Undo action while the session history remains available. Undo changes the session arrangement; it does not rewrite saved storage.

The review includes the complete named list and panel geometry. It does not save or restore document drafts, executable processes, broker connections, orders, payments, credentials or application settings. Keep those items through their own application workflows.

Understand the two restore choices

ChoiceWhat happens
Review saved layouts, then Apply reviewed layoutsApplies the exact captured library after comparison. It leaves storage and the application's existing Save revision unchanged.
Confirm and Restore libraryUses the existing restore action to reread the latest library at that moment. It may therefore differ from an earlier preview, and refreshes the accepted storage evidence when successful.

A revision is a counter used to notice changes. If another window saves first, your older Save request is refused instead of overwriting its work. A fresh frozen review does not silently accept that competing revision. Inspect the latest saved content and, if appropriate, use the confirmed Restore library action before retrying Save. Export your current arrangements first if you want to keep a separate copy.

Choose an Umicom desktop checkpoint

  1. Open Persistent desktop workspace from the Umicom OS desktop shell, then choose Open workspace.
  2. The checkpoint list shows retained revisions, newest first, with the number of notes and the selected note's title. Up to eight complete checkpoints are retained. A record that cannot be read is marked unavailable.
  3. Select a usable checkpoint. This fills the checkpoint number; it does not restore anything. The manual number field remains available.
  4. Save or discard any unsaved draft before choosing Preview checkpoint. Compare the full notes and appearance preferences.
  5. Choose Restore reviewed checkpoint only when the comparison is the state you want. Restoration creates a new saved revision. Cancel leaves the current workspace unchanged.
  6. Choose Refresh checkpoints to reread the list. Refresh preserves unsaved editor text. Closing during a refresh still asks about an unsaved draft before ending the session.

When a review cannot be applied

If the live layout changes after review, prepare a new comparison. An old review is deliberately refused. If storage is unavailable, finish editing, check the application's storage status and retry the explicit read. An unavailable checkpoint row does not hide older usable checkpoints. Do not assume an unreadable row was deleted.

These are native application workspace features. The Umicom OS shell runs on the current operating system; this workflow does not install an OS or change its boot configuration.

Extend the shared implementation

Native hosts bind umi_gtk4_ws_layout_library_set_saved_review_handler after binding their existing file-exchange callbacks. The read callback uses umi_ui_workspace_library_checkpoint_review and returns owned evidence. The existing import publisher accepts the candidate only after its widgets accept the arrangement, keeping layout history in one place.

Desktop shells read UmiDesktopWorkspaceReadHistory on the workspace's sole worker. Rows are copied observations, not restore permission. Use their stable revision numbers to prepare a fresh restore review; never pass a list position as a revision. Keep controllers alive through callbacks and disconnect retained controls during destruction.
