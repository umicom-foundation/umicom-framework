Reading Time & Sales with Umicom Framework

Time & Sales lists individual market events. A trade event records a reported price and size. A bid/ask event records prices and quantities offered by buyers and sellers. A midpoint is halfway between a bid and an ask. These observations describe the feed; they are not your account's executions.

Current scope. Framework provides live tick subscriptions through its read-only connection. This service does not place orders, request historical tick backfill or create a Trader window. A compatible running TWS or Gateway session and market-data permissions are required.

1. Resolve an instrument

A symbol can identify different instruments on different exchanges. Use the contract-details service, then retain the selected contract ID and route. The connection must reach UMI_IBKR_READY. Paper or Live in connection options records requested intent; confirm the actual account mode in the broker application.

2. Choose an event kind

  • UMI_IBKR_TICKS_LAST: reported trade ticks.
  • UMI_IBKR_TICKS_ALL_LAST: a broader trade feed, including reported attributes and conditions.
  • UMI_IBKR_TICKS_BID_ASK: bid and ask prices and sizes. ignoreSize may omit size-only changes.
  • UMI_IBKR_TICKS_MIDPOINT: midpoint observations, without a trade size.

3. Subscribe through Framework

This excerpt belongs inside a host that already owns a ready connection. resolvedContract is the user's selection from contract discovery. Check the returned status before retaining the request ID.

#include "umicom/broker_connectivity/time_sales.h"

UmiIbkrTimeSalesQuery query = {0};
query.contract = resolvedContract;
query.kind = UMI_IBKR_TICKS_LAST;

uint32_t requestId = 0;
UmiStatus status = UmiIbkrTimeSalesRequest(
    connection, &query, UmiIbkrMonotonicMilliseconds(), &requestId);
if (status != UMI_STATUS_OK) {
    /* Display the failure; requestId is not a subscription. */
    return status;
}

The service retains four subscription slots and applies a conservative 15-second interval between tick requests on the same connection, including retries. Too-early requests return UMI_STATUS_BUSY. Other API clients have their own pacing obligations. A full transmit queue leaves the output ID and previous observations unchanged.

4. Copy observations into your view

  1. Continue calling UmiIbkrConnectionPump from the connection's owning thread. Pump failure makes retained observations stale.
  2. Call UmiIbkrTimeSalesCopy with a nonzero maximum receipt age. Inspect active, failed, stale and message.
  3. For indices zero through count - 1, call UmiIbkrTimeSalesEventCopy. Both functions return owned copies; the UI never borrows a receive buffer.
  4. Display reportedText. Use the numeric value for arithmetic only if exact is true. Unrepresentable decimals remain text, never silently rounded or replaced with zero.

The window holds 512 events in receipt order. droppedEvents counts window evictions, not network packet loss. Equal prices and timestamps remain separate events. Exchange timestamps may arrive out of order. Recent receipt does not prove market freshness. Sizes retain provider units.

5. Cancel and reconnect deliberately

Call UmiIbkrTimeSalesCancel(connection, requestId, now) when the user closes or replaces a subscription. It cancels market data only. If the queue is full, the subscription remains available for a cancellation retry. After successful queueing, late events are ignored. Retained data stays readable and stale until the slot is reused.

After failure, create a new connection and explicitly subscribe again. Never reuse the old request ID. Framework shares a non-repeating request sequence across its observation services.

Troubleshooting

  • No events: check the request message, broker permissions and market activity. Connection readiness does not establish entitlement.
  • Provider error: inspect providerCode and message. Cancel the failed stream or close the connection before replacing it.
  • Unsupported protocol: this adapter accepts legacy versions 151–176. This service does not add Protobuf support or historical ticks.
  • Malformed data: validation failure on a known tick packet fails the connection. Previous rows remain stale evidence instead of being partly overwritten.
  • Zero price or size: retain the associated flags. These may be broker markers; a zero alone is not a trade decision.

Source walkthrough

The public contract is include/umicom/broker_connectivity/time_sales.h. Subscription ownership lives in src/ibkr_connection/time_sales.c; packet validation lives in time_sales_decode.c. Synthetic scenarios in tests/ibkr_connection/test_time_sales.c require no broker credentials. Build the umicom-ibkr-time-sales-test target, then run framework.ibkr_time_sales.* cases.
