Filter complete code-action proposals

Use Resolve missing text edits to prepare deferred actions in their original server session before review.

Action-family selection belongs in the shared language service so every application keeps the same metadata, ownership and review rules. The filter narrows complete proposals; it never grants permission to execute one.

  1. Include umicom/language_runtime/code_action_query.h and link Umicom::developer.
  2. Capture the primary source and selected byte range. Copy request inputs before handing them to a worker.
  3. Initialize UmiLanguageCodeActionQueryOptions to zero. This selects all actions, no additional sources and empty diagnostic context.
  4. Choose filter from ALL, QUICK_FIX, REFACTOR, ORGANIZE_IMPORTS or FIX_ALL using the UMI_LANGUAGE_ACTION_FILTER_ prefix. Set optional additional sources and the explicit diagnostic delivery mode independently.
  5. Call UmiLanguageCodeActionQueryNativeWithOptions. A specific family adds context.only to the request. Fresh diagnostic reconstruction preserves that family in the same connection.
  6. On success, inspect the returned catalogue. Every original action is parsed before filtering. The filtered owner preserves matching complete JSON items, source order, disabled reasons, commands, preferred flags and opaque data.
  7. Decode only an explicitly selected supported edit. Use the source-review and document transaction services to validate every target, show complete comparisons, collect approvals and apply against unchanged captures.
  8. Destroy the catalogue after its borrowed views are no longer used. A filtered catalogue owns its own storage and does not depend on the source catalogue's lifetime.

Contracts and limits

UmiLanguageCodeActionQueryOnServerWithOptions accepts an exclusively owned STARTING connection. Invalid options fail before initialization or document synchronization. Once initialization begins, the query owns cleanup and withholds results when closure or shutdown fails. Existing query APIs retain their unfiltered behavior.

UmiLanguageCodeActionCatalogueFilter supports independently owned catalogues outside native queries. A specific family matches the exact kind or a dot-delimited descendant. Missing and empty kinds match only ALL. Unknown filter values return INVALID_ARGUMENT; failures and cancellation clear the output pointer.

The standalone catalogue retains its one-megabyte JSON and 512-action limits. Native messages retain the smaller 65536-byte serialized transport bound. Filtered results do not bypass these limits. Filtering preserves lazy edit payloads; it does not claim that an unselected edit is applicable.

Commands, resource operations and unreviewed partial edits remain unsupported for application. Deferred text edits have a separate explicit resolution option. A fix-all family requests a complete proposal; it does not start a background repair, save files or apply every returned action.

When extending families, add a named enum and static protocol mapping, retain exact dot-boundary matching and invalidate any UI result when the request changes. Keep worker options immutable and never reconstruct an action by retaining only its edit field.
