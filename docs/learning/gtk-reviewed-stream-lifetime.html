Keep GTK AI streaming owners alive

A responsive interface needs more than a background HTTP request. The interface must keep the request, approved job, database connection and cancellation token alive until the producer has stopped and native cleanup has succeeded. Framework's existing AI workspace panel now composes the reviewed-stream service into its current controls.

1. Follow the existing review workflow

  1. Open or create a library in a product that uses the shared AI workspace.
  2. Choose the configured local provider and enter the actual model ID. Opening a library does not contact a model.
  3. Prepare a free or grounded draft, inspect its frozen input and approve the selected job.
  4. Choose Run approved job. The source and job forms become unavailable while that request owns the workspace.
  5. Read the streamed draft in the existing review pane. Its notice identifies it as incomplete and not yet saved.
  6. Use Stop current request to request cancellation. The controls remain retained until completion and cleanup.
  7. Inspect both Generation and Save statuses. A failed save requires inspection and recovery; it never silently repeats generation.

The extractive preview remains explicitly identified as not being an LLM. Tools and unsupported provider adapters retain their complete-response route. No new layout, provider implementation or model-download mechanism is introduced by this panel integration.

2. Initialize shared HTTP lifetime before GTK

The shared AI product host creates its transport before starting the GTK workstation. It lends that transport to the library surface, which lends it to each opened panel. Older constructors remain available. A custom host can attach a startup-created transport explicitly:

/* Before GTK and other worker initialization: */
UmiAiLocalTransport *transport = NULL;
UmiStatus status = UmiAiLocalTransportCreate(&transport);

/* Later, on the same owner thread, after constructing the surface: */
if (status == UMI_STATUS_OK) {
    status = UmiAiWorkspaceGtkSurfaceEnableLocalStreaming(surface, transport);
}

Attach before opening a library; an existing session returns BUSY. Panel-only clients may use UmiAiWorkspaceGtkPanelEnableLocalStreaming while idle. These attachment calls borrow the transport and start no request. Keep it alive until every attached owner is released, including periods with no active raw job.

The existing shared native-product composition selects this host for AI-attached modules such as LLM, RAG and Creator when their frontend is enabled. A separately implemented Studio or Media frontend does not acquire this workflow merely by linking Framework. Its integration and product qualification remain separate work.

3. Keep the worker away from widgets

The raw producer owns encoded request and response storage. On each GTK timer callback, the panel polls copied state and obtains an owned text copy. Only the GTK owner changes the text buffer. The review/export forms remain disabled during the request; the stop button remains available.

Normal completion uses TryFinish. On a platform without nonblocking native join, the panel calls the blocking finish alternative only after observing raw producer completion. Native thread teardown and final database publication can still take time; this is not a hard real-time interface.

A pre-start refusal keeps the approved job and reports that no generated result was saved. A settled request reports separate operation and publication statuses. Failed or cancelled partial text, when available, retains an explicit temporary-draft notice instead of being presented as a saved answer.

4. Understand reentrant callbacks

A function is reentered when one of its calls causes another callback to call back into the same owner before the first call returns. For example, changing a GtkTextBuffer emits a changed signal. Another handler could try to close the panel from inside that notification.

The stream/run callback holds a short callback lease. Checked release returns BUSY during that lease, leaving the pointer unchanged. This prevents a close notification from freeing the panel while the timer still has its address on the stack. The guard is not a substitute for thread serialization; it handles nested calls on the owner thread.

5. Release the whole dependency chain

UmiStatus release = UmiAiWorkspaceGtkSurfaceRelease(&surface);
if (release != UMI_STATUS_OK) {
    /* Keep surface and its borrowed transport alive. Retry on the owner thread. */
} else {
    /* surface is NULL. Release transport only when every other borrower is gone. */
}

Panel release retires controls and disconnects signals before cancellation and joining. A native finish or release failure retains the closed panel. Surface release then retains its session, which still owns the workspace, runtime, token and Data Server. Each checked release must succeed before cleanup advances to the next dependency.

Shutdown deliberately permits blocking cancellation and settlement. A failed checked shutdown in the common product host keeps its heap context alive until process exit, avoiding a pointer into an expired stack frame. The legacy void destructors remain for compatibility but cannot report a retained owner; streaming hosts should use checked release.

6. Replace libraries without losing either owner

The surface opens a candidate library before retiring the old one. A missing or corrupt candidate leaves the current forms intact. A failure while retiring the old native owner is different: the surface keeps both the old chain and candidate chain, and reports failure. It does not release the old runtime underneath an active producer.

A partially retired closed session requires checked shutdown/recovery; its old controls are not promised to remain editable. An unsuccessful candidate whose own cleanup refuses is also retained. This is why a single pointer-to-pointer release at each layer is useful: success clears the pointer, refusal keeps concrete cleanup responsibility visible.

Read and append bounded draft ranges

The existing panel now tracks the number of payload bytes displayed for its current stream. Each poll asks the shared Framework range reader for at most 4096 new bytes and inserts nonempty text at the end of the existing draft buffer. A new request resets that cursor before its initial draft label is shown.

The shared response owner selects complete UTF-8 scalars and publishes the copied bytes and snapshot together. The panel keeps its callback retirement guard during insertion because GTK text-change signals can reenter the application. An empty range causes no text-buffer mutation. Failed reads still request cancellation and retain owners for the existing settlement path.

Final settlement continues to validate and save a complete response separately. A completed provider may settle before every intermediate window was drawn; the final refresh presents the recorded result. Earlier failure text remains visibly labelled as a temporary draft. No new layout, provider capability or model-readiness claim is introduced.

The native range tests cover boundaries, pending scalars, retained copies and allocation/mutex errors. The actual reviewed-controller fixture compares bounded ranges with its joined full copy. The GTK fixture routes copy-failure injection through the new method, retains nested-close coverage, and includes range-append: it joins an inert peer before asserting a correct append and no change signal for a repeated empty read. These tests require owner-run execution; configuration does not establish their results.

See request-owned text ranges for the byte cursor contract. Real application responsiveness, selection behavior, rendering and font fallback still need GUI qualification.
