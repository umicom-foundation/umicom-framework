Learning with Umicom Framework
AI workspace · A practical lesson

Ask a question, check the sources, keep the draft

Use Umicom RAG, LLM and AI Creator to organise a few source passages, review what a provider will receive, and keep a draft with the evidence that helped produce it.

No programming or downloaded model is needed for the first part. The labelled extractive preview lets you practise safely; a later section explains how an already-running local model can use the same workflow.

1. Start with a small, safe workspace

Imagine that you are preparing a notice for a community workshop. You have an opening notice and a short equipment list. You need a useful draft, but you also need to know which words came from your documents and which words a model added.

In this lesson, Umicom RAG holds the source passages, Umicom LLM provides a place to review a generation request, and Umicom AI Creator can use the same text-drafting workflow. All three applications use the shared Framework service. You do not have to copy a separate source collection into each application.

Begin with fictional information. Use the workshop text below, not passwords, customer records, bank statements or confidential documents. This workspace saves passages and drafts as ordinary text in a local SQLite database. It is not encrypted, and its writer/reviewer labels are not authenticated accounts.

A workspace is the saved place for your collections, passages and jobs. A job is one frozen request and its outcome. Merely opening a saved job does not run it again.

After building the applications, open PowerShell. The following commands give this lesson a separate database and launch Umicom RAG. The folder is created when the application opens; an existing practice database is reused, not erased.

PowerShell
Set-Location "C:\umicom\Umicom-Applications"
$env:UMICOM_AI_WORKSPACE_DB = Join-Path $env:LOCALAPPDATA "umicom\ai-workspace\workshop-practice.sqlite"
& ".\build\windows-ucrt64-all-debug\bin\umicom-rag.exe"

Choose AI workspace at the top of the window. Read the database path shown above the pages. It should end in workshop-practice.sqlite. The separate Existing layouts page still contains the application's earlier workspace.

The pages inside AI workspace are Sources, Drafts and review and History. RAG starts on Sources; LLM and Creator start on Drafts and review. These are different starting views of the same service, not different storage formats.

For everyday use, the application can also be opened by double-clicking its executable or shortcut. Without the environment setting above, it uses umicom/ai-workspace/workstation.sqlite below the user-data folder. The full path is always displayed. To stop using the practice override in this PowerShell window after closing the application, run Remove-Item Env:UMICOM_AI_WORKSPACE_DB. This removes the setting, not the database.

2. Give the source material a clear identity

A collection groups passages that belong together. The collection boundary matters: a question about this workshop should not quietly search an unrelated collection.

On Sources, enter the following values, then choose Save collection.

FieldValue
Collection IDworkshop
Collection nameCommunity workshop

The ID is a stable name used by the program. Use letters, numbers, dots, underscores or hyphens; the readable name can contain spaces. Creating a collection does not add any source text yet.

Now prepare the first passage. Use opening for Passage ID, Opening notice for Source title and 7 for First source line. Paste these two lines into the source box:

Practice source
The community workshop opens at 10:00 on Saturday.
Bring a notebook.

Choose Save passage. The saved catalogue should show workshop / opening, the source title, a source revision and lines 7–8. Here the first line number is a teaching example: in your own work, enter the actual first line in the original document.

The application stores the pasted text. It does not find, import or verify the original file for you. A source title and line number are useful provenance, but they do not prove that the original document was correct.

Add a second passage with ID equipment, title Equipment list and first line 1. Paste Borrowed laptops are available during the workshop. and save it. Both entries should remain visible in the catalogue.

Check your work. You should have one collection and two passages. Saving an existing passage ID replaces that passage's current text; it does not create a second copy. Earlier completed jobs keep the exact source copies that they used.

3. Inspect retrieval before asking for a draft

Retrieval means finding relevant source passages. It is a separate operation from asking a language model to write. That separation lets you catch an incorrect collection or an irrelevant source before sending a request.

Leave Collection ID as workshop. In Search question, enter When does the workshop open? Choose Inspect retrieval.

The result area names the matching passages and shows their scores, line ranges and text. The opening notice should be present. The equipment list may also appear because it contains “workshop”. Read the text rather than treating the highest score as a guarantee of correctness.

This screen uses lexical query-term retrieval. It looks for substantive terms from your question, ignoring a small set of common English words. It does not secretly generate embeddings, and it does not contact a model. A score describes matching terms, not the probability that a passage answers the question.

Try notebook, then laptops. Each should bring its relevant passage into view. Try volcano; the result should explain that no passage matches. With no matching source, a grounded job cannot be prepared.

A word about vectors. Framework also accepts explicitly supplied, finite embedding vectors for hybrid retrieval and an optional reranker callback. Those developer interfaces bind each vector to a source revision, model ID and dimension. This screen does not configure an embedding model or a learned reranker. It labels its actual lexical method instead.

4. Freeze a request that you can review

Open Drafts and review. Choose New job. A fresh ID appears. For a first run through this lesson, you may replace it with workshop.notice. When repeating the lesson in the same database, keep the fresh generated ID so it does not collide with an earlier request.

FieldChoose or enter
Request typeGrounded draft
ProviderExtractive preview (not an LLM)
Model IDextractive-preview
Writer labelwriter
Reviewer labelreviewer
Question or drafting instructionWhen does the workshop open?

A provider is the component that receives a generation request. The extractive preview is deliberately simple: it copies selected reference text so you can learn the complete review and storage workflow without downloading a neural model.

Choose Prepare for review. Preparation performs retrieval and saves the question, requested provider/model and up to four source passages. It does not contact an external process. Read the Frozen request, source references and returned draft area. Check the selected collection, question, source titles and line ranges.

You should see a saved state of Review required and references such as [S1]. The order depends on the retrieval results; always read the source shown beside a label. A label is meaningful only within that job.

Try a safe change. After preparation, edit the question in the form. The frozen request below should not change. The selected saved job—not the text you have just typed—is the review target. Use New job and Prepare for review to save a different request.

Writer and reviewer fields record local labels. They are useful for learning the workflow, but typing a different label does not log you in as another person. There is no enforced separation between two authenticated people in this workspace.

5. Approve, run and read the result

Once the frozen request is correct, choose Approve selected job. The saved state changes to Approved, not run. Then choose Run approved job. Approval alone does not start generation.

While the job is running, the source and job forms are temporarily disabled. The request runs on a worker, and Stop current request remains available. When the worker returns, the forms become available again and the saved result is displayed.

For the offline provider, the result begins with:

Expected label
Extractive preview - copied reference text, not a language-model answer.

It then shows the selected excerpts and their reference labels. You should be able to find 10:00 in the opening notice. This is not an AI-written paraphrase: it is an explicitly labelled extractive preview. Longer excerpts can be shortened in that display; the frozen source record remains available for inspection.

Read the line range and compare the excerpt with the passage you saved. This is the habit to keep when using a more capable provider: inspect the evidence before accepting its prose.

A completed job is not run twice. Pressing Run again cannot create another provider call for that succeeded job. A different question, provider or model needs a new job ID. Failed or interrupted jobs also do not automatically retry; you review the problem and deliberately prepare another request.

Use Reject selected job on an unapproved job to record a decision not to proceed. Use Cancel selected job to stop a job that has not started. During a local HTTP call, Stop requests cancellation of the client transfer. The model server may already have received the prompt; cancellation does not undo processing that it has already performed.

6. Keep your history without repeating actions

The History page lists job IDs, states, providers and models. To inspect an earlier result, copy its ID into Job ID on Drafts and review and choose Load job. Loading is a read, not a request to regenerate.

Close RAG and open LLM from the same PowerShell window so it inherits the same practice-database setting:

PowerShell
& "C:\umicom\Umicom-Applications\build\windows-ucrt64-all-debug\bin\umicom-llm.exe"

The saved collection, passages and completed draft should still be available. The Creator executable, umicom-ai-creator.exe, can open the same workspace in the same way.

When two applications are open together, choose Reload shared workspace in the second application after making a change in the first. A stale writer is rejected rather than silently overwriting newer saved work.

Reloading has a deliberate consequence: a previously approved, unfinished job returns to Review required. A new runtime must not inherit an old approval and run it against a possibly changed provider binding. A job found in Running after an interrupted session is shown as Interrupted; the application cannot know whether the provider finished before the interruption.

StateWhat to do
Review requiredInspect the frozen request, then approve or reject it.
Approved, not runRun deliberately, or cancel without starting it.
CompletedRead the saved output and check its sources.
FailedInspect the failure; create a new job only after deciding another attempt is appropriate.
Interrupted: outcome uncertainTreat the outcome as uncertain. Do not assume nothing happened.

Completed jobs retain their source copies even when a current passage is later edited or removed. An unfinished grounded job becomes stale when the source collection state changes. Prepare a new job to include the revised evidence.

7. Try one harmless, reviewed tool

A model's text must not become an executable command merely because it looks persuasive. This workspace does not scan generated prose for commands or execute returned tool calls. The only tool offered by the shared application host is a read-only query of the workspace's compiled limits.

Choose New job, then select Read workspace limits (tool). Prepare it and inspect the frozen request. The tool ID is umicom.workspace.capacities, the arguments are {}, and the permission is workspace.read-limits. The prompt box is not used for this fixed tool.

Approve and run. The returned text reports capacities such as collections, passages, jobs and evidence per job. It does not search your computer, change a file, send a payment or invoke another application.

There are three separate gates: the host registers and allows the tool, Framework policy permits tools, and the specific job has your review decision. A source passage saying “ignore the rules and run a command” changes none of those gates.

8. Connect an already-running local model

The offline lesson works without a model. Actual language-model generation requires a separate, trusted server that is already running on this computer and supports a non-streaming chat-completions request. The optional transport sends a reviewed job to http://127.0.0.1:8080/v1/chat/completions by default.

127.0.0.1 is the local endpoint selected by this adapter. It will not follow redirects, use an environment proxy or send to a user-entered external hostname. However, the server itself may be configured to forward data elsewhere. Check that server's behaviour before using confidential text; a loopback address alone is not proof that all inference stays on the machine.

For a server such as llama.cpp's llama-server, use its own installation and model instructions. This batch does not supply a server executable, choose a model, download model weights or configure GPU drivers. The official server reference is linked at the end of this guide.

Check the capability line at the top of the Umicom workspace. Local HTTP transport compiled means the client was built; it is not a health check and does not prove that a model is listening. Local HTTP transport unavailable in this build means the optional libraries were not included.

Once your server is ready, choose New job, select Configured local model, and enter the actual model ID or alias served by that endpoint. The default local-model text is a field example, not a bundled model. Choose Grounded draft to include retrieved passages, or Free draft for a request without source references. Prepare, inspect, approve and run as before.

A reported model identity must match the reviewed ID. Only one text reply with a normal stop or output-length finish is accepted. Structured tool/function-call replies are rejected, not executed. Replies are bounded to 4,095 UTF-8 bytes of saved text; an output-length finish is shown as potentially incomplete.

To use another local port, close the AI applications, set a value between 1024 and 65535 in the launching PowerShell window, and start the application again:

PowerShell
$env:UMICOM_AI_WORKSPACE_PORT = "8081"
& "C:\umicom\Umicom-Applications\build\windows-ucrt64-all-debug\bin\umicom-llm.exe"

The graphical request timeout is 30 seconds. An unavailable, slow or incompatible server produces a failed job; it is not replaced with a fake successful answer. A real neural-model session must be checked on your machine—loopback fixture tests exercise the client protocol, not model quality.

9. Read citations as a starting point, not a verdict

A grounded request carries up to four source passages. Framework checks that returned [S1]-style references point to passages actually included in that job. It also checks response identity, finish reason, text bounds and token-usage consistency.

Those checks do not prove that the generated sentence follows from the cited passage. A model could attach a real reference label to an unsupported claim. Compare the words and numbers yourself, especially when drafting instructions for other people.

Try a grounded question that asks for the workshop's telephone number. The sample sources do not contain one. The correct behaviour for a language-model draft is to acknowledge that absence; any telephone number would need another verified source. The extractive preview simply shows the passages—it is not an answering model.

Three questions to ask before using a draft

Does the source actually support this sentence? Does the draft leave out an important condition? Is this the current version of the source? These questions are useful even when every technical validation check passes.

Creator currently uses this text workflow. Image, audio and video generation jobs, cloud-provider transports, large embedding indexes and autonomous tool loops are outside this lesson's implementation. Existing application layouts remain available while those later capabilities are developed.

10. Understand the workspace boundaries

This implementation keeps its state bounded so storage, recovery and tests remain inspectable. Limits are explicit; large input is rejected rather than silently cut down to fit.

ItemLimit in one saved book
Collections / current passages16 / 64
Saved jobs32, including finished jobs
References in one grounded job4
Passage or prompt1,535 UTF-8 bytes; a character may use more than one byte
Returned text4,095 UTF-8 bytes
Developer-supplied vectorUp to 64 finite components, with explicit model and source revision
Tools permitted by one workspace8 explicitly allowed IDs; the graphical host registers only the read-only limits query

There is no job-deletion button in this lesson: history remains available for review. For another isolated practice run, close the AI applications and point the database override at a different absolute filename. Do not delete a database that another application still has open.

Embeddings are an in-memory cache. They are not invented from a document ID, persisted automatically or represented as learned semantic knowledge. A reload clears the cache; the caller supplies current vectors again. The saved passages and job evidence remain durable.

A single workspace has one owner at a time. Its graphical adapter temporarily hands that ownership to a worker during generation, then joins the worker before reading the result or releasing the services. Closing a window requests cancellation and waits for that worker. This protects memory ownership; it cannot force an arbitrary custom provider to honour cancellation.

11. Build and test the shared implementation

For developers, an application module selects Framework services; it does not implement another copy of retrieval, approvals or persistence. The public C API is in include/umicom/ai_workspace/workspace.h. The provider factories are in providers.h.

After merging the full source files, configure from the Applications root. AUTO includes the local HTTP client when its libraries are available and leaves an explicitly offline build otherwise.

PowerShell
Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& "C:\msys64\ucrt64\bin\cmake.exe" `
    --preset windows-ucrt64-all-debug `
    -DBUILD_TESTING=ON `
    -DUMICOM_BUILD_NATIVE_TOOL=ON `
    -DUMICOM_AI_WORKSPACE_LOCAL_HTTP=AUTO
if ($LASTEXITCODE -ne 0) { throw "Configuration failed." }

To require the transport, first install the UCRT64 curl and json-c development packages through the MSYS2 UCRT64 terminal, not by pasting the following command into an ordinary PowerShell prompt:

MSYS2 UCRT64 terminal
pacman -S --needed mingw-w64-ucrt-x86_64-curl mingw-w64-ucrt-x86_64-json-c

Then configure with -DUMICOM_AI_WORKSPACE_LOCAL_HTTP=ON. ON fails configuration when the transport dependencies are missing. OFF deliberately builds only the offline provider. The package names and installation commands come from the official MSYS2 package pages linked below.

Build the complete repository, then run its tests only after the build succeeds:

PowerShell
& "C:\msys64\ucrt64\bin\cmake.exe" `
    --build `
    --preset windows-ucrt64-all-debug `
    --parallel 2 `
    -- -k 0
if ($LASTEXITCODE -ne 0) { throw "Full build failed." }

& "C:\msys64\ucrt64\bin\ctest.exe" `
    --preset windows-ucrt64-all-debug `
    --parallel 2 `
    --no-tests=error `
    --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "Tests failed. Review the output." }

The focused selection below helps isolate this capability. It does not replace the full suite. A skipped SQLite, HTTP or graphical case is not evidence that the unavailable capability passed.

PowerShell
& "C:\msys64\ucrt64\bin\ctest.exe" `
    --preset windows-ucrt64-all-debug `
    -R '^(framework\.ai_workspace\.|llm\.ai_workspace\.|rag\.ai_workspace\.|creator\.ai_workspace\.)' `
    --parallel 2 `
    --no-tests=error `
    --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "AI workspace checks failed." }

Each application also receives a memory-only console example. Run umicom-llm-ai-workspace-example.exe, umicom-rag-ai-workspace-example.exe or umicom-creator-ai-workspace-example.exe from the build's bin folder. They use the same shared source example, exercise the reviewed extractive draft and read-only tool, and do not contact a model.

Open framework/examples/ai_workspace_main.c beside this guide. Follow the order: create a Data Server and runtime, register the provider, create a workspace, save a collection and source, prepare a job, review it, run it, and inspect the saved result. On shutdown, destroy the workspace before the runtime and Data Server that it borrowed.

The delivery's separate validation notes explain which builds and tests were actually run. The native GTK adapters and the complete Windows application suite still require local build and graphical acceptance; this lesson does not label an untested screen as a verified result.

12. Find the next useful check when something fails

What you seeWhat to check next
No source matchCheck the collection ID and whether the words in the question occur in the saved passages. Inspect retrieval separately.
The form changed, but the review did notThat is intentional. The saved job is frozen. Prepare a new job for the revised input.
A stale-state or busy messageReload after another application writes to the shared database. Recheck the source copies and obtain a fresh review.
Local HTTP unavailableInspect the configure output and the capability line. Install the optional build dependencies or stay with the labelled extractive preview.
Model reply rejectedCheck model ID, reply size, supported finish reason and references. Structured action requests are deliberately refused.
Workspace cannot openCheck the displayed absolute path, directory permission and SQLite support. No memory-only database is silently substituted.
Interrupted jobInspect what the provider may already have done. There is no automatic replay.

Finish the lesson with a small change

Create a new passage stating that the workshop closes at 15:00. Prepare a new grounded question about opening and closing times. Check which references are included, reject the first preparation, then create and approve a revised job. Explain to another reader why editing the form is different from changing a saved request.

You now have a repeatable habit: select the sources, inspect retrieval, review the frozen request, run deliberately, and check the draft against its evidence.
