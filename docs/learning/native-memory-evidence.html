Native AI learning path · Bounded memory

Observe a native model lifecycle

A language model is not just a file. Loading creates a live decoder with owned memory; generation may need temporary work buffers; cleanup releases the decoder. This lesson follows those stages in Umicom LLM's native teaching benchmark. It measures the process containing the decoder, without measuring external model servers or GPU memory.

Start with measuring native memory if resident memory, committed memory, ownership or process identity are unfamiliar. You need an approved Umicom training-decoder checkpoint, not an arbitrary downloaded GGUF model. Prepare the checkpoint and cases separately using the native benchmark guide.

1. Understand the two output streams

A console program has standard output for its result and standard error for diagnostics. The optional --evidence-json flag writes score evidence to standard output. The separate --memory-observations flag writes memory records to standard error. JSON is a text format with named fields. Each complete memory record occupies one line, so readers can process it incrementally instead of retaining an unlimited history in RAM.

Normal benchmark invocations make no memory observations. When requested, Framework captures and formats each observation; the application supplies a stage and output choice. A capture failure produces an unavailable message without changing the benchmark's score. A zero benchmark exit status alone does not prove all memory observations succeeded.

2. Follow ownership through the stages

StageStateInterpretation
before-loadArguments accepted; suite and decoder not loaded.Includes startup, stack and library costs.
loadedDecoder and optional suite owned.Includes loading work, not only weight bytes.
generatedCompletion cases finished.A point-in-time observation, not a generation-only peak.
releasedDecoder and suite destruction returned.Allocator caches and library state may remain resident.

Failures use load-failed or released-after-failure. A crash can prevent a final line entirely. Missing cleanup evidence must stay missing.

before-load → load → loaded → generate → generated
            → report scores → destroy decoder and suite → released

3. Configure and build the optional console

Configuration selects components and creates build instructions. Building compiles and links the executable. Open PowerShell and run each line separately; stop on errors. These are commands for your machine, not executed qualification evidence.

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake --preset windows-ucrt64-all-debug -DUMICOM_APPLICATIONS_BUILD_LLM=ON -DUMICOM_LLM_BUILD_NATIVE_BENCHMARK=ON
cmake --build .\build\windows-ucrt64-all-debug --target umicom-llm-benchmark llm-benchmark-options-test llm-benchmark-memory-test umicom-self-memory-report-test
ctest --test-dir .\build\windows-ucrt64-all-debug --no-tests=error --output-on-failure -R "^(llm[.]benchmark[.]|framework[.]desktop_system[.]self_memory_report[.])"

This selection has 25 Framework formatting/output checks, 21 application argument checks and 11 lifecycle checks. Lifecycle tests inject model services to check stage ordering and cleanup without real weights. Such regression tests do not measure actual model performance. Native host sampling has separate self-memory tests.

  2. Review the suite before running. It contains byte-completion cases, not executable code.
  3. Choose a writable output directory and retain both score and diagnostic files.

& ".\build\windows-ucrt64-all-debug\bin\umicom-llm-benchmark.exe" "C:\path\to\approved-decoder-checkpoint.umi" ".\framework\learning\native-llm\fixtures\benchmark-reviewed.txt" --evidence-json --memory-observations 1> scores.json 2> memory-observations.log
$LASTEXITCODE
Get-Content .\memory-observations.log

Successful sampling gives four complete stage records. A query or write failure can also produce ordinary diagnostic text or an incomplete line. Such a file is not an all-success JSON-lines dataset. Keep the original and investigate failures before comparing values.

5. Read exact counters and unknown values

Version 1 records include scope, provider, process ID, creation ticks, capture time, known-metric flags and three memory quantities. An operating system can reuse a process ID after exit. Compare creation identity and provider too, and use samples from the same host and run.

All 64-bit counters, times and identities are decimal strings. Some JSON readers store ordinary numbers as floating point and cannot represent every large integer exactly. Strings preserve every digit. Unknown memory is JSON null; measured zero is the string "0". Those meanings must stay distinct.

"resident_bytes": "1048576"
"peak_resident_bytes": "2097152"
"private_committed_bytes": null

This is an illustrative fragment, not an observed run. Convert known strings to integer values before arithmetic. Never convert null to zero. Windows private committed and resident memory answer different questions; Linux private committed remains unavailable in this service.

After reviewing the entire diagnostic file, inspect complete records in PowerShell:

$samples = Get-Content .\memory-observations.log |
    Where-Object { $_.StartsWith('{') } |
    ForEach-Object { $_ | ConvertFrom-Json }
$samples | Select-Object stage, pid, creation_ticks, resident_bytes, private_committed_bytes

This display does not validate missing stages, partial lines, identity or source revision. Preserve those checks in your experiment notes.

6. Reuse the same service

Link your installed-SDK consumer to Umicom::desktop_system. The caller owns its byte-oriented stream. Framework opens no file and starts no monitoring thread. A stage is a short ASCII identifier such as loaded, not a path or prompt.

#include "umicom/desktop_system/self_memory_report.h"

UmiStatus status = UmiDesktopSelfMemoryReport("loaded", stderr);
if (status != UMI_STATUS_OK) {
    /* Keep this observation unavailable; do not reuse a previous number. */
    fprintf(stderr, "Memory observation unavailable: %d\n", (int)status);
}

To format an existing sample, use UmiDesktopSelfMemorySampleJson with a caller-owned buffer of UMI_SELF_MEMORY_REPORT_CAPACITY bytes. The returned length excludes the terminating zero byte. Validation and capacity failures preserve the buffer and length. Stream writes can fail partway and cannot retract an already written prefix.

7. Make a fair efficiency comparison

  1. Keep the same checkpoint bytes, cases, generation length, threads, build type and machine.
  2. Record the source revision and compiler for each executable.
  3. Separate cold startup from warmed repeated work.
  4. Compare ownership stages over repeated comparable runs. Resident growth is a reason to investigate, not proof of an unreleased allocation.
  5. Use memory-safety tools and ownership checks to locate leaks. Measure subprocess and device memory separately when those backends are present.

C can remove interpreter and object-management overhead and make ownership explicit. It can also introduce invalid accesses when ownership is wrong. Many Python model interfaces already call native inference libraries, so rewriting the interface does not remove intrinsic model weight or working-memory requirements. See the llama-cpp-python native-binding architecture.

This exercise supplies observations. It does not establish faster inference, lower memory, a repaired leak or parity with a complete competing framework.

8. Troubleshoot the first failed step

  • Target missing: enable the LLM module and optional benchmark, then configure again.
  • desktop_system missing: select a Framework SDK/composition containing that component.
  • Checkpoint rejected: verify the native decoder format and reviewed identity.
  • Observation unavailable: retain the error and stage; even supported counters can fail to read.
  • Released memory stays high: consider lifetime peaks, allocator caching, other live owners and repeated runs before deciding a leak exists.
  • Incomplete output: check disk space, redirection and stream errors; partial lines are not samples.
