Use one literal-search policy for editing and review

The document layer composes the existing editor search engine with document selection, immutable replacement proposals and Undo. Applications supply choices; they do not implement another matcher.

  1. Include umicom/document/search.h and link Umicom::document. Create a UmiEditorSearchOptions value with the desired case_mode and a whole_word value of zero or one.
  2. Call UmiDocumentCoordinatorFindWithOptions to move to the next or previous match. Both directions wrap once. Outputs change only on success, and the draft is neither saved nor synchronized by searching.
  3. Use UmiDocumentCoordinatorReplaceNextWithOptions for one undoable replacement. Selected matches are checked against the complete source so a selection inside a longer identifier cannot bypass whole-word matching.
  4. For review, call UmiDocumentCoordinatorPrepareReplacementWithOptions, UmiDocumentReplacementSessionCreateWithOptions, or UmiDocumentReplacementSetCreateWithOptions. These retain the existing immutable text comparisons, stale-source checks and approval workflows.
  5. In a GTK host with document editing already bound, call UmiGtk4AdapterReviewOpenReplacementsWithOptions or UmiGtk4AdapterReviewReplacementSetWithOptions. Each form shows the captured case and word policy. The host retains responsibility for its editing lifetime and separate Save action.
  6. Handle invalid policy before publishing new UI state. Keep the coordinator and its services alive on their owner thread while preparing or applying changes. Destroy completed or cancelled plans and sessions through their existing destructors.

Defaults and complete replacement

Passing NULL chooses smart case and allows substring matching, preserving existing document APIs. The older entry points delegate to that default. Only case_mode and whole_word affect these operations; maximum_matches and allow_overlapping do not truncate or change complete replacement. Every original non-overlapping match is considered.

Smart case looks for uppercase ASCII letters in the query. Explicit insensitive mode folds ASCII letters only. The shared word rule treats ASCII letters, digits, underscore and all non-ASCII bytes as word bytes. It is deliberately not a language parser or a Unicode word-segmentation service.

Captured values and extension

Each preparation uses a copied policy. A sequential session stores it for later drafts, while a single plan and complete set own the prepared output. Mutating the caller's options cannot change a pending proposal. Extend policy at the shared engine/document boundary and give new behavior an explicit contract; do not reinterpret an approved proposal when UI settings change.
