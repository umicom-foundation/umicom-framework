Close a period with no unfinished work

Follow a small exchange trade from matching to settlement, explain the remaining close controls, and learn why balanced books are only one part of completion.

This lesson uses fictional accounts and a local practice book. It neither connects to a broker nor sends a real payment.

1. Begin with the question, not the button

An accounting period is a named date range. Closing it prevents ordinary posting into that range. Before closing September, an operator needs to know whether earlier periods are closed, journals have been posted, old orders have finished, trades have settled and the latest reconciliation covers the latest postings.

A trial balance compares posted debits and credits. A fill records that two orders matched. Settlement completes the corresponding cash and asset movements. Reconciliation compares an independently supplied balance with the ledger. These are different questions; answering one does not answer the others.

Match→Clear→Settle→Reconcile→Prepare and close

The new close review explains the existing controls. It is a read-only snapshot, not a new posting engine or a replacement for those controls. The application still submits commands to Framework; Framework still commits accepted commands through its Data Server.

What you need

Use your existing Umicom source checkout and C23 toolchain. The complete Windows build uses the established windows-ucrt64-all-debug preset. The smaller laboratory below needs CMake, Ninja and a C23 compiler. SQLite is optional for the laboratory; the memory example does not need a persistent database.

Close the Umicom applications before merging source files. Keep new work in a staging folder, compare whole files, and retain any local changes. Do not delete files simply because an update does not contain them.

3. Read the four blockers

The practice buyer starts with GBP 500.00. The seller has 100 fictional lots. A sell order offers 10 lots at 1,000 ticks. A buy order requests 6 lots at a limit of 1,100 ticks. The existing matching engine executes the six matched lots at the older resting order's price. In this example one tick is one penny per unit and one lot contains one unit, so the cash obligation is GBP 60.00.

RecordWhy it blocks closingWhat to inspect
sell.1Four lots remain on the sell order.Cancel the remainder deliberately or allow it to finish.
system.fill.000001The six-lot match is not settled.Complete the separate clearing and local settlement operations.
controlA posted account has no reconciliation.Record an independently checked observation.
buyer.cashThe buyer's posted cash account has no reconciliation.Check the external amount and the posting revision covered.

The trial balance can agree throughout this sequence. A balanced ledger is not a list of all uncompleted obligations.

The lesson supplies fixed expected observations of 50,000, 44,000 and 6,000 minor units for the control, buyer and seller accounts. That is appropriate for a deterministic exercise. In real reconciliation, do not copy the ledger's value back as supposedly independent evidence.

Old evidence remains visible

A reconciliation records the posting revision it covered. Another posting can make a previously matched record stale. The report distinguishes missing, mismatched and stale observations. Recording a later mismatch does not erase an older match or allow it to override the latest evidence.

Preparing a close puts the period into its existing soft-closed state. A different actor label must complete the final close. These labels demonstrate workflow separation; they are not authenticated users. The read-only review neither freezes the book nor grants authority.

5. Follow ownership in the C interface

UmiFinanceCloseReviewCreate copies the period and its explanations into an owned object. It does not borrow pointers to mutable ledger records. Queries return copies, and UmiFinanceCloseReviewDestroy releases the report. Close the report only after its readers finish.

UmiFinanceCloseReview *review = NULL;
UmiStatus status = UmiFinanceCloseReviewCreate(operations, "september", &review);
if (status == UMI_STATUS_OK) {
    UmiFinanceCloseReviewInfo info;
    status = UmiFinanceCloseReviewGetInfo(review, &info);
    /* Capture success and checksPass answer different questions. */
}
UmiFinanceCloseReviewDestroy(review);

A successful capture means the report was constructed. Check checksPass and evaluationStatus separately. The lifecycle flags canPrepare and canFinalise include the period's current state and any blocked-write condition, but do not authenticate the actor.

The Master Controller owns the operations service and its serial command sequence. The accounting and settlement Slave Controllers retain their domain transitions. The report uses the same private close evaluator as the command path, so the screen cannot quietly invent a different close rule.

For formatted output, first measure with a NULL buffer and zero capacity. The returned size includes the final NUL byte. Allocate that many bytes, format again and release the buffer. An undersized buffer is returned as an empty string, not a convincing partial report.

/*-----------------------------------------------------------------------------
 * Umicom Framework | Sammy Hegab, Umicom Foundation | MIT
 * A matched trade is not a settled trade; balanced books still need controls.
 * Uses public service contracts only, with integer minor units and whole lots.
 *---------------------------------------------------------------------------*/
#include "lesson.h"
#include "umicom/finance_operations/close_review.h"
#include <inttypes.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct Practice {
    UmiDataServer *server;
    UmiFinanceOperations *operations;
    UmiFinanceOperationCommand command;
    UmiFinanceOperationReceipt receipt;
    uint64_t revision;
    unsigned request;
} Practice;
static UmiStatus Id(UmiFinancialId *id, const char *text) { return umi_financial_id_assign(id, text); }
static UmiStatus Begin(Practice *p, UmiFinanceOperationKind kind, const char *id, const char *actor)
{
    char request[40];
    UmiFinanceOperationCommandInit(&p->command);
    p->command.kind = kind; p->command.expectedRevision = p->revision;
    int n = snprintf(request, sizeof request, "practice.%u", ++p->request);
    if (n < 0 || (size_t)n >= sizeof request) return UMI_STATUS_CAPACITY_EXCEEDED;
    UmiStatus s = Id(&p->command.requestId, request);
    if (s == UMI_STATUS_OK) s = Id(&p->command.id, id);
    if (s == UMI_STATUS_OK) s = Id(&p->command.actorId, actor);
    return s;
}
static UmiStatus Apply(Practice *p)
{
    UmiStatus s = UmiFinanceOperationsApply(p->operations, &p->command, &p->receipt);
    if (s == UMI_STATUS_OK) p->revision = p->receipt.revision;
    return s;
}
static UmiStatus Inspect(Practice *p, int verbose, size_t expected)
{
    UmiFinanceCloseReview *r = NULL;
    UmiStatus s = UmiFinanceCloseReviewCreate(p->operations, "september", &r);
    if (s != UMI_STATUS_OK) return s;
    UmiFinanceCloseReviewInfo info;
    s = UmiFinanceCloseReviewGetInfo(r, &info);
    if (s == UMI_STATUS_OK && info.issueCount != expected) s = UMI_STATUS_INTERNAL_ERROR;
    if (s == UMI_STATUS_OK && verbose) {
        size_t bytes = 0;
        s = UmiFinanceCloseReviewFormat(r, NULL, 0U, &bytes);
        if (s == UMI_STATUS_CAPACITY_EXCEEDED) {
            char *text = malloc(bytes);
            if (!text) s = UMI_STATUS_OUT_OF_MEMORY;
            else { s = UmiFinanceCloseReviewFormat(r, text, bytes, NULL); if (s == UMI_STATUS_OK) puts(text); free(text); }
        }
    }
    UmiFinanceCloseReviewDestroy(r);
    return s;
}
int UmiFinanceCloseLesson(int verbose)
{
    Practice p = {0};
    UmiStatus status = umi_data_server_create_memory(&p.server);
    if (status == UMI_STATUS_OK) status = UmiFinanceOperationsCreate(p.server, &p.operations);
    if (status != UMI_STATUS_OK) goto done;
#define STEP(call) do { status = (call); if (status != UMI_STATUS_OK) goto done; } while (0)
    const char *accounts[] = {"control", "buyer.cash", "seller.cash"};
    for (size_t i = 0; i < 3U; ++i) {
        STEP(Begin(&p, UMI_FINANCE_CREATE_ACCOUNT, accounts[i], "operator"));
        memcpy(p.command.name, "Workshop account", sizeof "Workshop account");
        p.command.currency = (UmiCurrency){{'G','B','P','\0'}}; p.command.scale = 2U;
        p.command.accountClass = i == 0U ? UMI_ACCOUNTING_ASSET : UMI_ACCOUNTING_LIABILITY;
        STEP(Apply(&p));
    }
    STEP(Begin(&p, UMI_FINANCE_OPEN_PERIOD, "september", "operator"));
    p.command.date = (UmiFinancialDate){2026,9U,1U}; p.command.endDate = (UmiFinancialDate){2026,9U,30U}; STEP(Apply(&p));
    STEP(Begin(&p, UMI_FINANCE_ENTER_JOURNAL, "funding", "maker"));
    STEP(Id(&p.command.referenceId, "september")); p.command.date = (UmiFinancialDate){2026,9U,28U};
    p.command.lineCount = 2U; STEP(Id(&p.command.lines[0].accountId, "control"));
    p.command.lines[0].debitMinor = 50000;
    STEP(Id(&p.command.lines[1].accountId, "buyer.cash")); p.command.lines[1].creditMinor = 50000; STEP(Apply(&p));
    STEP(Begin(&p, UMI_FINANCE_APPROVE_JOURNAL, "funding", "checker")); STEP(Apply(&p));
    STEP(Begin(&p, UMI_FINANCE_POST_JOURNAL, "funding", "checker")); STEP(Apply(&p));
    for (size_t i = 0; i < 2U; ++i) {
        STEP(Begin(&p, UMI_FINANCE_REGISTER_PARTICIPANT, i ? "seller" : "buyer", "operator"));
        STEP(Id(&p.command.accountId, accounts[i + 1U]));
        memcpy(p.command.name, "Workshop participant", sizeof "Workshop participant"); STEP(Apply(&p));
    }
    STEP(Begin(&p, UMI_FINANCE_LIST_INSTRUMENT, "practice", "operator"));
    memcpy(p.command.name, "Workshop lots", sizeof "Workshop lots");
    p.command.currency = (UmiCurrency){{'G','B','P','\0'}}; p.command.scale = 2U;
    p.command.minorPerTick = 1; p.command.unitsPerLot = 1; p.command.maxOrderLots = 100; STEP(Apply(&p));
    STEP(Begin(&p, UMI_FINANCE_SET_MARKET_STATE, "practice", "operator")); p.command.enabled = true; STEP(Apply(&p));
    STEP(Begin(&p, UMI_FINANCE_DEPOSIT_LOTS, "seller", "custodian"));
    STEP(Id(&p.command.instrumentId, "practice")); p.command.lots = 100; STEP(Apply(&p));
    for (size_t i = 0; i < 2U; ++i) {
        STEP(Begin(&p, UMI_FINANCE_PLACE_ORDER, i ? "buy.1" : "sell.1", "trader"));
        STEP(Id(&p.command.participantId, i ? "buyer" : "seller"));
        STEP(Id(&p.command.instrumentId, "practice")); p.command.date = (UmiFinancialDate){2026,9U,28U};
        p.command.side = i ? UMI_SIDE_BUY : UMI_SIDE_SELL;
        p.command.priceTicks = i ? 1100 : 1000; p.command.lots = i ? 6 : 10; STEP(Apply(&p));
    }
    STEP(Inspect(&p, verbose, 4U));
    puts("After matching: balanced ledger, but four close blockers remain.");
    STEP(Begin(&p, UMI_FINANCE_CLEAR_FILL, "system.fill.000001", "clearing")); STEP(Apply(&p));
    STEP(Begin(&p, UMI_FINANCE_SETTLE_FILL, "system.fill.000001", "settlement"));
    STEP(Id(&p.command.periodId, "september")); p.command.date = (UmiFinancialDate){2026,9U,28U}; STEP(Apply(&p));
    STEP(Begin(&p, UMI_FINANCE_CANCEL_ORDER, "sell.1", "trader"));
    STEP(Id(&p.command.participantId, "seller")); STEP(Apply(&p));
    const int64_t observations[] = {50000,44000,6000};
    for (size_t i = 0; i < 3U; ++i) {
        /* Fixed independent observations for this fictional exercise, not a
         * production practice of copying the ledger into reconciliation. */
        const char *ids[] = {"recon.control", "recon.buyer", "recon.seller"};
        STEP(Begin(&p, UMI_FINANCE_RECONCILE_ACCOUNT, ids[i], "reconciler"));
        STEP(Id(&p.command.accountId, accounts[i])); p.command.amountMinor = observations[i]; STEP(Apply(&p));
    }
    STEP(Inspect(&p, verbose, 0U));
    puts("After settlement, remainder cancellation and reconciliation: zero close blockers.");
    STEP(Begin(&p, UMI_FINANCE_PREPARE_CLOSE, "september", "preparer")); STEP(Apply(&p));
    STEP(Begin(&p, UMI_FINANCE_CLOSE_PERIOD, "september", "preparer"));
    if (Apply(&p) != UMI_STATUS_PERMISSION_DENIED) { status = UMI_STATUS_INTERNAL_ERROR; goto done; }
    STEP(Begin(&p, UMI_FINANCE_CLOSE_PERIOD, "september", "closer")); STEP(Apply(&p));
    puts("A separate closer completes the period; the preparer cannot close it alone.");
    puts("Practice complete. Memory only; no broker connection or real settlement was made.");
#undef STEP
done:
    UmiFinanceOperationsDestroy(p.operations); umi_data_server_destroy(p.server);
    if (status != UMI_STATUS_OK) fprintf(stderr, "Practice failed: status %d\n", (int)status);
    return status == UMI_STATUS_OK ? 0 : 1;
}

7. Understand the Windows compiler warning

The reported warning is about an API command word, not an amount, quantity or socket error. FIONBIO requests nonblocking mode. The Windows function takes that command as a signed long, while the selected header presents its high-bit command word as unsigned.

ioctlsocket(socket, (long)FIONBIO, &nonblocking)

The explicit conversion documents the ABI boundary. Compile-time checks ensure that converting back preserves the original unsigned command word. Nonblocking mode and handle-inheritance policy are unchanged. The earlier implicit call remains in a commented, disabled source block for review; warning flags stay enabled.

Microsoft documents the signed command parameter and the meaning of the mode argument. The current MinGW definition can therefore generate a sign-conversion diagnostic even for the intended control word. See Microsoft's ioctlsocket reference.

The included transport regression connects only to its own ephemeral loopback listener, checks that an empty read returns without blocking, exchanges test bytes and closes its resources. It does not connect to a Paper or Live account.

9. Troubleshooting and boundaries

No report appears. Ensure at least one accounting period exists. The existing Accounting periods view cannot review an unidentified period.

The report is old. Refreshing does not reload another application's database changes. Use Reload shared book, investigate any error, and refresh again. A failed reload leaves a last-known view marked as not writable.

Submission returns busy. A revision or stored-history difference was detected. Do not edit the high-water record to force a match. Preserve the database and determine which writer changed it before reloading and reviewing.

The GUI case is skipped. That is not a GUI pass. It needs a built GTK adapter and an available display. Native tests cannot replace target-platform interaction.

SQLite is unavailable. The focused laboratory can run with -DUMICOM_CLOSE_REVIEW_SQLITE=OFF. Its SQLite-specific tests are then explicitly skipped. Persistent applications must not silently substitute memory storage.

The Windows warning remains. Check that you merged the complete replacement framework/src/ibkr_connection/network.c. Do not add -Wno-sign-conversion or edit a generated object file.

The report retains the current local-simulation limits: 64 accounts, 16 periods, 128 journals/orders/fills and 512 accepted commands. It does not authenticate operators, change real orders, value portfolios, add a new close system or guarantee that external balances are correct. Earlier original and compensating journals remain part of the trial balance.

This batch continues the Accountant/Exchange post-trade controls. It does not mark the entire product family, Windows distribution, OS image or physical-media workflow as complete.
