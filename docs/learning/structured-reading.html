Read structured product guides

The offline learning catalogue reads guides from an admitted learning pack. A pack names its resources and their content digests. Opening a resource checks its bytes against that digest before presenting it. A digest detects changed bytes; it does not prove who published the guide.

The reading view preserves headings, emphasis, code indentation, list markers and simple table-cell boundaries. It offers explicit local links, section navigation and a text-size control. Images are represented by their alternative-text descriptions. This is a limited document reader: it does not run scripts, apply page CSS, submit forms or fetch remote content.

Open a guide

  1. Open your application's guided learning catalogue. In Studio, use the existing Guided Learning entry.
  2. Choose an absolute folder containing learning-pack.json, then choose Load learning pack. Wait until the reading operation finishes.
  3. Search for a title or topic, select a guide and choose Open selected. The result message explains whether structured reading or the plain-text fallback was used.
  4. Read the code examples as text. Merely opening an example does not build or run it. Copying an example remains a separate explicit operation.

Use reading controls

Expand Reading controls above the document. All controls are ordinary keyboard-focusable controls; press Tab to move between them and use their normal activation keys.

A section identifier is the value of an HTML id attribute. For example, <h2 id="ownership">Ownership</h2> can be reached using ownership. IDs are exact and case-sensitive. A missing ID reports a refusal and leaves the current cursor unchanged. A followed link whose document exists but whose requested section is absent shows the verified document with a missing-anchor message.

Find text in this guide

Catalogue search looks at resource titles and topics. Find in this guide instead searches the text of the structured guide already on screen. It does not read another file, change the guide, add a history entry or search every installed pack.

  1. Open a structured guide and wait for it to finish loading.
  2. Press Ctrl+F while focus is inside the catalogue, or expand Find in this guide.
  3. Enter a word or phrase. Choose Find next, or press Enter in the query field. The matching text becomes selected.
  4. Choose Find next again to continue after that selection. Find previous searches before it. At an end, search wraps once and the result message says so.
  5. Enable Match case (ASCII letters) to distinguish Framework from framework. Without it, English A–Z letters compare without case; other characters still compare exactly.

A query is literal: . means a period, not a wildcard. Queries must contain valid UTF-8 and occupy at most 255 bytes. A displayed character can occupy several bytes, so some queries reach the byte limit before 255 characters. Unicode normalization, accent removal, regular expressions and whole-word rules are not part of this control.

A missing match leaves the current selection where it was. Source examples, binary notices, image selections and plain-text fallbacks are not searched by this version. Return to a structured guide to use Find. If a read is busy, wait before trying again. Find does not grant permission to execute an example.

Application developers call UmiLearningCatalogueGtk4FindText to use the same operation. Its optional result describes the selected byte range and the current reader revision. Treat that result as a snapshot of this panel, not a permanent document identity. A later navigation can replace the reader. The shared UmiEditorSearchNavigate service performs matching; GTK only translates the result into a selection.

The installed SDK example share/umicom/framework/examples/reading_search demonstrates the reading model and literal matcher without opening a window. It expects two visible matches and a third search that wraps to the first. Its separate CMake project includes the sdk.browser.reading_search check; running that console example does not validate native keyboard or focus behaviour.

Understand what the reader retains

The reader owns its admitted source and navigation history. The structured reading model separately owns the displayed text and its ranges. Reopening another guide replaces the model only after a candidate is ready. A failed read or recoverable model-allocation failure keeps the previous selection and reading history. Closing a panel prevents late worker results from updating it.

Author compatible guides

  1. Write well-nested headings, paragraphs, links, emphasis and code. Encode a literal less-than sign as &lt; when it is part of displayed code.
  2. Place code inside <pre><code>...</code></pre>. Spaces and line breaks inside this block are retained.
  3. Use unique, portable section IDs. Use local literal filenames and fragments for navigable links, and declare linked files in the pack manifest.
  4. Give meaningful images an alt description. An empty description identifies a decorative image. A missing attribute is reported as description missing.
  5. Keep tables simple. Cells are separated in reading order; complex spanning cells and visual page layouts are not reproduced.

The model accepts at most 1 MiB of source, 64 KiB of reading text, 512 semantic ranges, 128 links, 128 anchors and 64 nested styled elements. It never publishes a partial structured model. Unsupported or malformed structure uses the earlier bounded plain-text fallback. Its notice distinguishes that fallback from structured reading. Original source bytes remain available through the reader's existing copy workflow.

Troubleshooting

  • A remote link is refused: this is an offline local-content workflow. It does not launch a browser or send context to a remote server.
  • A guide uses fallback: inspect tag nesting, duplicate IDs and capacity limits. Do not claim full layout support for that page.
  • An inline image appears as a description: HTML images retain their alternative text. To view pixels, explicitly open a declared PNG resource or follow a declared image link. See View learning illustrations for format and size limits.
  • Characters do not display: resources must be valid UTF-8 for native text presentation. Binary and invalid text receive an explicit notice.
  • A link no longer matches after an update: reload and verify the intended guide revision; do not silently combine metadata from one version with bytes from another.

Developer entry points

The reusable model is declared in umicom/browser/reading_document.h. UmiBrowserReadingDocumentCreate owns a projection from a bounded byte buffer. The native adapter translates byte ranges into GTK character positions, then styles a text buffer. Link metadata does not grant permission to follow a link.

A complete, small C program is installed with the SDK under share/umicom/framework/examples/reading_document. Its CMake project requests the browser component and an explicit UMICOM_EXPECTED_SDK_PREFIX. It prints text and inspects copied link and anchor metadata without opening any file or network connection.
