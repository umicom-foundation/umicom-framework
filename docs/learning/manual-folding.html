Keep folding inside the native buffer owner

Framework reuses its bounded folding projection to present manually selected source ranges in a GTK text view. The projection records one-based source lines. A private invisible-text tag controls presentation; it does not replace the document model or own a second copy of source.

  1. Link Umicom::ui_gtk4 and include umicom/ui/gtk4/text_folding.h. Use the service on the GTK owner thread with a live text view.
  2. Set the desired native selection. Call UmiGtk4TextFoldSelection. At least two lines are required. The first remains visible; a selection ending at the next line start excludes that next line.
  3. Inspect UmiGtk4TextFoldCount or UmiGtk4TextFoldLineHidden if your host needs to describe the presentation. These queries describe the current buffer, and line numbers start at one.
  4. Call UmiGtk4TextFoldClear to reveal this service's ranges. Syntax and annotation tags owned by other components remain in place.
  5. Keep hidden text included whenever reading complete source. In GTK, pass TRUE for the final argument of gtk_text_buffer_get_text. The shared Framework editor already does this for its document, clipboard and editing paths.

Ownership and callbacks

Fold state belongs to the text buffer. Two views of the same buffer share that state; different buffers remain independent even when they share a tag table. The service retains the view and buffer through callbacks. It rechecks the captured selection and generation after publishing a tag, applying it, and moving the caret. A callback that replaces the source or changes the selected range causes the request to fail and reveals the affected ranges.

Clearing removes the private tag from the tag table, which also removes its ranges. This avoids retaining iterators across a remove-tag callback that could edit the text. The tag-table observer is weakly connected to the buffer. It also retires the projection when another host component removes the private tag. Content changes and navigation into hidden source reveal all folds.

Extend the service

Application code should call UmiGtk4AdapterFoldSelectedCode or UmiGtk4AdapterRevealFoldedCode to use the active Framework editor. Keep parsing, language-server range acquisition and persistent fold identities separate from this presentation service. Adding those features requires document-revision checks and rules for adapting ranges after edits; this API intentionally reveals ranges after any text change.

The native operation supports read-only views and at most 64 ranges. It creates no document history entry, save or network request. The registered GTK regressions cover complete source retention, range boundaries, shared ownership, navigation, capacity and reentrant callbacks. Execute them with the project's normal qualification before treating the native behavior as verified.
