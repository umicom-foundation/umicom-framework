Edit captions and prepare a shorter clip

A caption cue is a piece of text with a start and end time. The shared Captions page in the Media and Music creative workspace lets you write or import these cues, move their timing and save a subtitle file. It does not need a model, API key or online account.

Write or open captions

  1. Select Creative workbench, then open Captions.
  2. Paste plain SRT text into the editor. This example displays a caption from one to three seconds:
1
00:00:01,000 --> 00:00:03,000
Welcome to the lesson.

2
00:00:03,000 --> 00:00:05,500
Let us open the project.
  1. Alternatively, enter the full path to an existing UTF-8 .srt or plain .vtt file and select Open SRT or WebVTT from path. Choose your own document folder. If the editor already has text, save it first and tick the replacement approval. An unsuccessful import leaves it unchanged.
  2. Select Prepare captions after editing. The editor shows normalised SRT, with cue numbers starting at one. The message shows the cue count and latest end time.
  3. Enter a preview time in milliseconds and select Preview active captions. One second is 1,000 milliseconds. All overlapping captions are shown; a caption disappears at its exact end time.

Adjust timing and extract a short clip

  1. To move every caption later, enter a positive shift, for example 500, and select Apply time shift. Use -500 to move earlier. If any cue would start before zero, the whole shift is refused.
  2. For a video excerpt, enter its original begin and end times. An excerpt from 10 to 25 seconds uses 10000 and 25000.
  3. Leave Start the extracted clip timeline at zero selected when the excerpt will be a new video. Clear it when you want the original time positions.
  4. Select Extract captions for this clip. Cues crossing either boundary are shortened. Cues entirely outside it are omitted from the new caption draft; the original file is unchanged.
  5. Use Undo / redo last prepared change to switch between the two most recent prepared states. This is one-step history. Manual edits retire the prepared state and its history; prepare again before exporting.

Save the result

  1. Enter a new absolute path in your chosen folder. Use .srt for subtitle editors or .vtt for a web video text track. The selected save button determines the format; the extension is not changed automatically.
  2. Select Save new SRT file or Save new WebVTT file. The parent folder must already exist. An existing file is never replaced.
  3. Wait for the result message before closing the page. Stop file operation requests cancellation. A cancelled or failed write may leave a newly created partial file; the message identifies it for inspection.

Scene project saving does not save this independent caption draft. Export it explicitly before closing. Both SRT and plain WebVTT can be reopened; the editor displays canonical SRT after either import.

Supported input and troubleshooting

Message or conditionWhat to do
Parse errorUse increasing positive cue numbers, exact HH:MM:SS,mmm --> HH:MM:SS,mmm timestamps, nonblank text and a blank line between cues. Minute and second fields must be below 60.
Formatting tags or entitiesThis editor accepts plain text. Characters <, > and & are refused rather than interpreted as styling. Keep a copy of styled captions in their original editor.
Capacity exceededSplit the document into smaller parts. Limits are 512 cues, 2,048 UTF-8 bytes per cue and a 2 MiB input file. Times range from zero through 99:59:59,999.
File cannot be opened or savedCheck the full path, folder permissions and whether the destination already exists. Final symbolic links and special-device files are refused by the shared file service.
Draft changed while openingThe late import is discarded. Save your newer draft and retry the open operation explicitly.

UTF-8 may have an initial byte-order mark. LF and CRLF line endings are accepted. Empty documents are valid. Cues may overlap or start together, but their start times must not move backwards. The editor does not transcribe audio, translate speech, generate voices, play video or burn subtitles into a video.

Reopen web captions

WebVTT is a subtitle format used with web video. The shared reader accepts the plain caption subset described here. It does not import a browser stylesheet or discard unsupported fields.

  1. Open a plain WebVTT file or paste this example into the editor:
WEBVTT

00:01.000 --> 00:03.000
Welcome to the lesson.

00:02.500 --> 00:05.500
A second speaker can overlap the first.
  1. Select Prepare captions for pasted text. After an import, the editor displays numbered SRT cues with comma-separated milliseconds. Times, text and overlapping cues retain their meaning.
  2. Edit, shift or extract captions as usual. Select Save new WebVTT file to create another web subtitle file, or choose SRT for another editor.
  3. To check your exported work, open that file again. The reader recognises its contents, even if the extension is wrong. Use the correct extension when sharing it with other applications.

The WebVTT header must be exactly WEBVTT, followed by a blank line before cues. Times use MM:SS.mmm or HH:MM:SS.mmm; spaces or tabs separate the arrow. Optional numeric cue labels must be positive and increase; export renumbers them. Named labels, header descriptions, metadata, notes, styles, regions, cue positioning, markup and entities are rejected because this caption editor cannot retain them. Keep those files in their original editor instead of removing information merely to make an import succeed.

The file may use UTF-8 with an initial byte-order mark and LF or CRLF endings. A header-only WebVTT document is an empty track. Input bounds match SRT. This deliberate editing subset is narrower than the WebVTT specification.

Extend the shared service

Include umicom/creative_workspace/captions.h and link Umicom::creative_workspace. Create or parse an immutable UmiCaptionTrack, then use the shift, clip, replace, insert and remove functions to obtain new tracks. Initialise each output pointer to NULL; destroy owned tracks when finished. Failed operations leave an existing input and the output pointer unchanged.

The native adapter links Umicom::creative_workspace_gtk4 and creates UmiCaptionsGtkCreate. Other frontends can reuse the same core without GTK. Provider transcription adapters should validate returned cues through this owner before showing a review. File operations belong on workers; credentials and network uploads do not belong in the caption document.

Use UmiCaptionTrackParse when a caller may supply either file format, or select UmiCaptionTrackParseWebVtt explicitly. Both publish a complete immutable track only after validation. Add new format adapters beside these readers and keep their parsing independent of the user interface.

Edit individual captions

The caption form is shared by Media and Music. Each cue is one timed piece of subtitle text. Preparing a document validates it; saving a scene does not save captions.

  1. Open or paste plain SRT or WebVTT, then choose Prepare captions.
  2. Expand Edit an individual caption. Enter its caption number, starting at 1, and choose Load caption into form.
  3. Change its beginning, ending or text, then choose Replace loaded caption. The document changes only after the whole edit passes validation.
  4. To add a cue, fill in the form and choose Insert before caption number. Use the current number of cues plus one to append. Start times must stay in order; overlapping captions are allowed.
  5. Use Remove loaded caption to remove that cue. Undo / redo last prepared change reverses the latest successful edit.
  6. Choose a new output location and save SRT or WebVTT. Existing files are preserved. Browsing only fills in the path; use the separate Open or Save action to read or write.

Split and merge

To split a loaded cue, enter an interior split time. Put the first half's text in the main cue form and the second half's text in its separate field, then choose Split loaded caption. The original beginning and ending are retained. Split does not guess word timing. It refuses an edit that would move the second half past the start of the following cue.

Merge loaded caption with next joins the two prepared texts with a line break and covers their full time range, including any gap. It does not use unsaved text in the form. If the combined text exceeds 2048 UTF-8 bytes, shorten the captions or keep them separate; text is never silently cut.

Recover from a refused edit

If the row number or prepared document has changed, load the cue again. If you edited the subtitle source directly, prepare it again first. Check that beginning is less than ending and that start times remain in order. Plain captions do not support markup. A refused row edit preserves the prepared document; if another part of the application changes the text during publication, its newer draft is kept and must be prepared again.
