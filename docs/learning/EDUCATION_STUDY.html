Umicom learning guide · Education Study

Plan your next practical Umicom lesson

Find a useful goal, see what comes before it, and keep learning progress separate from a working program.

1. Choose a useful goal

You do not need to read every page before making something useful. Start with a small goal: a Notes program that stores and retrieves a note, a stock-total function that you can inspect in Assembly, or a note saved through the Umicom Data Server.

The learning practicum already contains twelve lessons in three courses. A study route shows the unfinished practice quizzes on the way to a selected lesson. It uses the existing course order; it does not invent a new curriculum or mark work complete on your behalf.

Three different kinds of evidence

Reading a lesson, passing its practice quiz and compiling a working program are different achievements. The route describes the first two. Use the course project's actual build and tests to establish the third. None of these local records is an authenticated qualification certificate.

This guide follows the Notes course. Its last lesson is notes.tests. You will first inspect a fresh route, then complete one practice step and compare the old and new captures.

2. Understand the few terms you need

TermMeaning in this guide
CatalogueThe supplied, read-only list of courses, lessons and guide descriptions.
Learner recordYour local read flags, quiz attempts and learning notes. The record has a chosen ID, not an authenticated login.
RevisionA number that advances when a learning action is saved. A later revision may contain different progress.
Capture or snapshotAn owned copy of the progress visible at one moment. It does not update itself when the original changes.
PrerequisiteAn earlier quiz in the same course that must pass before the next quiz can be submitted.
FrameworkThe shared implementation used by Education Studio and other Umicom hosts.
Data ServerThe owner of database access. The study tools ask the existing workspace for progress; they do not create another database.

The three courses are independent under the current practicum rules. A recommendation to learn C before Assembly is educational advice, not an extra prerequisite secretly enforced by the software.

3. Run the memory-only lesson

First build the merged source using the batch instructions. Then open PowerShell and run:

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
$Study = ".\build\windows-ucrt64-all-debug\bin\umicom-study.exe"
& $Study --self-test
if ($LASTEXITCODE -ne 0) { throw "The study lesson failed." }

The expected result is:

The Notes goal begins with four practice quizzes remaining.
After one explicit quiz attempt: the new capture has three; the old capture still has four.
Both captures remain readable after the learner workspace closes.
Practice complete. Memory only; no compiler, files, network or certificate was used.

The example supplies known quiz answers as a test fixture. It demonstrates the progress contract, not a way to assess a person. Its learner exists only in memory and disappears when the program exits.

You can also list lesson IDs and inspect the route for a fresh practice record:

& $Study lessons
if ($LASTEXITCODE -ne 0) { throw "Lesson listing failed." }
& $Study plan notes.tests
if ($LASTEXITCODE -ne 0) { throw "Route planning failed." }

plan does not open your saved Education database. Every invocation begins with a fresh memory record. A four-step result from this command does not contradict a saved learner who has already passed two quizzes.

4. Open a separate practice learner

In a GUI-enabled build, open Education Studio and its existing learning practicum. Existing lesson, quiz, note and project-export controls stay in place. The new Study route and learning library section is underneath them; expand it when you are ready.

Enter study42 as the learner ID and Workshop learner as the display name, then choose Open learner record. Use another new ID when that one already holds work you want to preserve. Opening an existing ID keeps its saved name and progress.

The adapter uses its existing per-user umicom/education/learning.sqlite location and reports its storage choice. Inspect the application's message rather than guessing which database is open. Notes and progress are plaintext: do not use passwords, customer details or real account information in this exercise.

Opening is not writing

Opening a fresh learner, selecting a lesson and capturing a route do not save completion. Explicit actions such as Mark lesson read, Check my answers and Save learning note use the existing Data Server-backed workflow.

If SQLite is unavailable, do not assume you have durable progress. Follow the message from the existing workspace and correct the build dependency before relying on restart persistence.

5. Capture the route to Notes tests

Use the original lesson selector above the new section to choose the Notes testing lesson, whose ID is notes.tests. This is the goal. Inside the new section, leave the text search empty, choose All courses and All lessons, then choose Capture study snapshot.

The result contains the learner ID, captured revision, matching lessons and a route to the selected goal. A new learner has these four unfinished Notes steps:

OrderLesson IDProgress to make
1notes.valuesRead, then try the first practice quiz.
2notes.contractsContinue after the preceding quiz passes.
3notes.memoryStudy the ownership and memory activity.
4notes.testsComplete the testing activity and its quiz.

The minute total is the sum of the catalogue's estimates for unfinished lessons. It is not a stopwatch, attendance record or promise about how long you should need.

Choose Open next step. The original lesson selector navigates to the first unfinished step. It does not mark that lesson read, reveal a hint or submit a quiz.

6. Complete one step and capture again

Read the explanation and example in the first lesson. Work through its practice activity, then choose Mark lesson read. Select an answer for each of the three questions and choose Check my answers.

A practice quiz requires all answers to be correct. An unsuccessful attempt retains its feedback and previous best score. Read the explanations before trying again; do not interpret a quiz failure as a compiler error.

Return to notes.tests in the original selector and capture a new route. After the first quiz passes, the route has three remaining Notes quizzes. Merely marking it read is not sufficient to remove it from the route.

Normal learning actions refresh the panel and invalidate an older study capture. If another application changes the shared learner, choose Reload saved record, then capture again. Capture reads the loaded record; it never reloads behind your back.

Before switching lessons, save a useful learning note such as “A snapshot owns the progress it displays.” Unsaved edits deliberately block Open next step. Choose Save learning note or explicitly choose Discard note edits before navigating. Discarding a draft is not deletion of the saved learner record.

7. Search without changing the goal

Search and course filters narrow the displayed lesson list. They do not change the goal in the original selector, nor do they remove prerequisites from its route. A filter can show no matches while a valid route still has steps.

FilterWhat it selects
All lessonsEvery lesson matching the course and text.
Ready to studyUnpassed lessons whose existing prerequisites are met and whose workspace is not recovery-required.
BlockedUnpassed lessons that cannot currently be recommended because of prerequisites or recovery state.
Practice quiz passedLessons with an existing passing practice result.
Not marked readLessons without the saved read flag.

Search is a literal UTF-8 byte substring, with English ASCII upper/lower-case folding. It is not a regular expression, semantic search, translation system or locale-aware dictionary search. You may enter up to 128 UTF-8 bytes. Non-ASCII characters can use more than one byte each.

Lesson search covers public descriptions and project IDs. It does not search quiz answers, hidden hints or personal learning notes. A copied study result includes your learner identity and progress, so still treat that result as personal data.

8. Find a guide in the learning library

Type audio, transaction or another subject in the same search field and choose Search guide library. This displays guide titles, paths and the important limits of each example. It opens no browser, source file, compiler or network connection.

The first library contains 22 curated guides spanning the practicum, Notes, transactions, build results, layouts, design export, market observation, replay, Paper/Live inspection, financial controls, AI sources, enterprise recovery, audio and OS/installer tools. It is not every Bits to Banking volume or the entire programming curriculum.

For clickable local links, open LEARNING_LIBRARY.html beside those guides. The separate offline Library ZIP includes that index and the 22 guide snapshots. A framework checkout can use framework/docs/learning/LEARNING_LIBRARY.html.

Native search uses the same catalogue:

& $Study library audio
if ($LASTEXITCODE -ne 0) { throw "Guide search failed." }
& $Study library
if ($LASTEXITCODE -ne 0) { throw "Guide listing failed." }

library-html sends the index to standard output; it does not choose or overwrite an output file. The catalogue provides titles and relative paths, not a filesystem scan. An entry does not prove that its guide is installed or that its Windows demonstration passed. Keep each guide's limitations attached to its instructions.

9. Build the actual course project separately

The existing Export this course project operation remains the way to create a Notes, Assembly or Framework practice project. Use a new absolute directory that does not already exist. An export is source preparation, not a passing test.

For the standalone Notes course, an example destination is C:\umicom\Practice\NotesStudy. After export, open the project's README and run its actual CMake workflow. A typical Notes build is:

& "C:\msys64\ucrt64\bin\cmake.exe" `
    -S "C:\umicom\Practice\NotesStudy" `
    -B "C:\umicom\Practice\NotesStudy-build" -G Ninja
if ($LASTEXITCODE -ne 0) { throw "Practice configuration failed." }
& "C:\msys64\ucrt64\bin\cmake.exe" `
    --build "C:\umicom\Practice\NotesStudy-build" --parallel 2
if ($LASTEXITCODE -ne 0) { throw "Practice build failed." }
& "C:\msys64\ucrt64\bin\ctest.exe" `
    --test-dir "C:\umicom\Practice\NotesStudy-build" `
    --no-tests=error --output-on-failure
if ($LASTEXITCODE -ne 0) { throw "Practice tests failed." }

The Assembly and Framework projects have different dependencies, described in their supplied README files. Do not infer that a C reference test executed Assembly, or that a quiz tested your edited program. Keep the compiler and CTest results with the project you actually built.

10. Read the complete C ownership example

The source below is examples/education_study/lesson.c. The workspace borrows the Data Server while it is open. Each capture owns the progress it needs; only immutable catalogue strings remain shared. That is why both captures can still be read after the services close.

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/education_study/lesson.c
 * PURPOSE: Demonstrate explicit study capture without granting code-test credit.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "lesson.h"
#include "umicom/education_workspace/study.h"
#include <stdio.h>
/* The supplied quiz answers are used only by this explanatory fixture. They
 * demonstrate the progression contract, not a method of assessing a learner. */
int UmiEducationStudyLesson(void)
{
    UmiDataServer *server=NULL;
    UmiEducationWorkspace *workspace=NULL;
    UmiEducationStudy *before=NULL,*after=NULL;
    UmiEducationStudyRoute original={0},updated={0},retained={0};
    UmiStatus status=umi_data_server_create_memory(&server);
    if(status==UMI_STATUS_OK)status=UmiEducationOpen(server,"workshop","Workshop learner",&workspace);
    const UmiEducationLesson *first=UmiEducationLessonAt(0U),*goal=UmiEducationLessonAt(3U);
    if(status==UMI_STATUS_OK)status=UmiEducationStudyCapture(workspace,&before);
    if(status==UMI_STATUS_OK)status=UmiEducationStudyPlan(before,goal->id,&original);
    if(status==UMI_STATUS_OK&&umi_data_server_count(server)!=0U)status=UMI_STATUS_INTERNAL_ERROR;
    if(status==UMI_STATUS_OK)status=UmiEducationMarkRead(workspace,first->id);
    uint32_t answers[UMI_EDUCATION_QUESTIONS];UmiEducationFeedback feedback={0};
    for(size_t i=0U;i<UMI_EDUCATION_QUESTIONS;++i)answers[i]=first->questions[i].correctChoice;
    if(status==UMI_STATUS_OK)status=UmiEducationSubmitQuiz(workspace,first->id,answers,&feedback);
    if(status==UMI_STATUS_OK)status=UmiEducationStudyCapture(workspace,&after);
    if(status==UMI_STATUS_OK)status=UmiEducationStudyPlan(after,goal->id,&updated);
    UmiEducationClose(workspace);umi_data_server_destroy(server);
    /* These captures own the progress they need, and no longer borrow services. */
    if(status==UMI_STATUS_OK)status=UmiEducationStudyPlan(before,goal->id,&retained);
    if(status==UMI_STATUS_OK&&(original.count!=4U||updated.count!=3U||retained.count!=4U))
        status=UMI_STATUS_INTERNAL_ERROR;
    if(status==UMI_STATUS_OK) {
        puts("The Notes goal begins with four practice quizzes remaining.");
        puts("After one explicit quiz attempt: the new capture has three; the old capture still has four.");
        puts("Both captures remain readable after the learner workspace closes.");
        puts("Practice complete. Memory only; no compiler, files, network or certificate was used.");
    } else fprintf(stderr,"Study lesson: %s\n",umi_status_text(status));
    UmiEducationStudyDestroy(before);UmiEducationStudyDestroy(after);
    return status==UMI_STATUS_OK?0:1;
}

The operation order is deliberate. Prepare an output pointer as NULL, check every returned status, use the result only after success, and destroy each owned capture once. Destruction is not safe while another reader is still using that object. The surrounding application must coordinate readers and shutdown.

Reusable planning stays inside Framework. Education's Master Controller and Slave Controllers can compose it through the public header without copying lesson rules or opening an independent database.

11. Interpret a refusal before retrying

ObservationWhat to check
Open next step is disabledCapture a route, check that the goal has unfinished steps and inspect any recovery message.
Navigation refuses to moveSave or explicitly discard unsaved learning-note edits.
No matchesClear the text/course filter. This is different from a storage error or all quizzes being passed.
Quiz says prerequisite not metComplete the preceding quiz in that same course. Reading alone does not satisfy it.
Busy after another writer changed progressInspect the other operation. Reload deliberately and capture again; do not retry with a forced revision.
Busy although the revision looks unchangedThe saved events may reconstruct different progress. This batch refuses to silently adopt that difference during another learning action. Preserve the data and inspect its origin.
Recovery requiredStop saving through that workspace. Preserve the database and investigate the reported storage failure before reopening.
A guide link is missingKeep the index beside its supplied guide files, or use the complete offline library. The catalogue itself does not install missing files.

The new storage check compares the reconstructed learning state with the state already loaded by the learner. It detects a disagreement; it does not undo an external edit, authenticate the author or prove an event journal is tamper-proof. Equivalent event changes that reconstruct exactly the same learning state are not detected by that semantic comparison.

12. Practise and explain the result

  1. For a fresh learner, capture the route to notes.tests. Record the revision and remaining steps.
  2. Mark the first lesson read without submitting its quiz. Capture again. Explain why four unfinished quizzes remain.
  3. Pass the first quiz and capture again. Explain why three remain.
  4. Choose a text filter that returns no lessons. Explain why that does not erase the goal's route.
  5. Type a private learning note and try to navigate. Check the save/discard guard, then verify that searching for the private text does not find it.
  6. Find the PCM16 audio guide in the catalogue. Identify one limit that the guide states, then build an actual course project and retain its real CTest result.
Answers and expected reasoning

A new Notes goal includes its four ordered quizzes. Marking a lesson read enables study progress but does not pass its quiz. A saved passing result removes that lesson from the unfinished route. Filters change only the displayed list, not the goal or prerequisite rules. Personal notes are deliberately excluded from search. Audio catalogue metadata describes PCM16 editing, not playback or arbitrary codecs. A CTest result belongs to the specific program and build; it is not automatically a learner assessment.

Continue with the learning library. Choose a practical result, follow its complete source example and keep the difference between a plan, a saved action and an executed test visible.
