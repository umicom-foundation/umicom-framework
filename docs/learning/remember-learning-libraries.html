Remember learning libraries

A learning library is a folder containing a learning-pack.json manifest and its guides, lessons and examples. A manifest is a small description of those files: it names the pack, its revision and the resources it declares. Remembering a library saves its location so that you can select it again later. It does not copy the course or give its examples permission to run.

This guide uses the native learning catalogue shared by Studio and other Framework hosts. The controls are in Remembered learning libraries. Open that section by clicking its heading. A newly created catalogue starts with an empty list and an empty settings filename. It does not search your computer.

1. Open and read the library first

  1. In Studio, open Guided Learning and choose Open local learning catalogue.
  2. Choose the folder that contains learning-pack.json, then select Load learning pack. The manifest must describe a compatible pack. If it is missing or invalid, the catalogue reports the failure.
  3. Select a guide or lesson from the results and choose Open selected. The reader checks its bytes against the manifest before displaying them.
  4. Expand Remembered learning libraries and choose Remember displayed library. The list now contains the pack ID, locale, revision and absolute folder.

An absolute folder identifies a location without depending on the application's current working folder. For example, C:\Learning\framework-pack is an absolute Windows folder. framework-pack alone is relative and is not accepted here. A locale such as en-GB identifies the language/region of the pack.

Remember captures the pack used by the displayed document. If you replaced a pack in the catalogue but are still reading its earlier revision, this button remembers that earlier reader's identity. Open a result from the new revision before remembering it. The same pack ID cannot appear twice in one choices list. To change its recorded folder or revision, explicitly forget its old choice, then remember the intended displayed pack.

2. Save the choices in a private file

  1. Create or choose an existing private folder outside your source repositories. For example, in PowerShell you can create your own local learning folder: 
    New-Item -ItemType Directory -Force "C:\umicom\_local\learning"
  2. Under Private folder-choices filename, enter a complete new filename, such as C:\umicom\_local\learning\libraries.json. The new-file Browse control can fill this field. Browsing alone does not save.
  3. Choose Save choices to new file. Wait for the operation to finish and inspect its result. Acceptance of the button press is not proof that the file was written successfully.
  4. Keep this file private. It contains local folder paths and pack identities. Do not add it to a public project commit.

Saving creates a new file. It never overwrites an existing one and does not create missing parent folders. To keep an updated list, choose a new filename. If an operation reports an incomplete new file, retain and inspect that file before trying another name. Closing the window does not undo an accepted save: the file worker may finish it while the application is shutting down normally.

The settings file is ordinary JSON, a text format for structured values. It is not encrypted. File access follows the chosen folder's operating-system permissions. A remembered entry contains its root, manifest filename, pack ID, product, locale and revision. It contains no password, execution permission or record of a learner passing an assessment.

3. Load a saved list, then reopen one library

  1. Open a learning catalogue. Enter the saved settings filename or choose it with the existing-file Browse control.
  2. Choose Load folder choices. A successful load replaces the in-memory choices list. It does not save the previous list, open the remembered folders, or change the current reading document.
  3. Select one item in the choices list and choose Reopen selected library. Framework reads that library's manifest again. The operation may take time if the disk is busy; the native adapter uses a background worker.
  4. After a successful reopen, select a result in the main catalogue and choose Open selected to read it. Reopening a library does not itself replace your current reading history.

4. Understand refusal and recovery

ResultMeaningNext step
Not foundThe selected settings file, folder or manifest is missing.Check its explicit location. Framework will not search another folder for a replacement.
Invalid state during reopenThe manifest's ID, product, locale or revision differs from the saved choice.Load and review the intended pack through the normal catalogue controls. If replacing an already loaded pack, use its explicit replacement review.
Already existsA pack ID is already in the choices list or shelf, or the settings output file already exists.Read which operation failed. Forget a choice before changing it; review a shelf replacement; choose a new settings filename.
UnavailableThe manifest does not support the host's version.Use a compatible pack. Do not edit its compatibility range merely to hide the refusal.
Parse error or invalid argumentSettings are malformed or contain unsupported fields, paths or identities.Keep the original file and choose a known-good list. Loading failure preserves the previous in-memory choices.
Capacity exceededA bounded input, output or choices list is too large.The list accepts at most 32 libraries and 256 KiB of settings. Keep a smaller list rather than truncating a file.

A manifest can use the same revision while changing its content. The settings list is not a signature and cannot prove that such a manifest matches a previous session. Reopen checks the declared identity and compatibility; each resource read then checks the bytes against that newly admitted manifest. Obtain learning content from a source you choose to trust and review examples before running them.

5. Forget a location without deleting learning material

Select a choice and choose Forget selected folder choice. This removes only the entry from the current list. It does not delete files, remove a pack already in the catalogue, clear reader history or modify an older saved settings file. Save the revised list to a new file if you want to keep it. There is no automatic startup reload or automatic overwrite in this workflow.

Follow the implementation

The reusable interfaces are in include/umicom/teacher/learning_library_choices.h. The owner, JSON codec and file operations are separate source files under src/teacher. The native controls are in adapters/gtk4/learning_catalogue_libraries.c, which uses the existing catalogue worker lifecycle. The small examples/learning_pack_inspector/libraries.c program demonstrates encoding, decoding and fresh admission without writing settings or executing course examples. See Using the learning catalogue for reading, navigation and practice-copy workflows.
