Find instruments and read P&L and market depth

Umicom Trader uses Framework's broker connection window for these observations. TWS or IB Gateway authenticates your account. Umicom connects to that local application; you do not enter your brokerage password into these controls.

This window is read-only. It can request data and stop its own data subscriptions. It does not submit, modify or cancel trading orders. The Paper/Live choice describes your requested connection; confirm the actual account environment in TWS.

Connect

  1. Sign in to TWS or IB Gateway. Use a paper account while checking a new installation.
  2. Enable its socket API and retain the read-only API setting. Note its socket port.
  3. Open Open Paper / Live broker connections in Trader. Choose the matching program and environment, enter the port, and connect.
  4. Wait for Read-only API ready. The account selector lists accounts advertised by that connection. If it stays empty, resolve the connection or broker permissions before continuing.

Find an instrument

  1. Expand Find an instrument and enter a symbol prefix or company-name fragment.
  2. Select Search symbols and names. Wait for the completed response. A successful empty result means no candidates were returned for that search.
  3. Compare the symbol, security type, listing exchange and currency. Where supplied, the description, issuer identifier and available derivative types give more context.
  4. Choose a candidate and select Use selected contract ID. Stop an active quote stream first. Only the contract ID is copied into the quote controls.
  5. Enter the intended exchange yourself, subscribe to the quote, and use Instrument description and route metadata to inspect its contract details. A listing exchange is not automatically the route you want to trade through.

Only one search is pending at a time, and accepted searches are at least one second apart. Abandon local search retires the result locally; this protocol has no search-cancel request. Late responses cannot complete a newer search. Up to 16 candidates are retained. Description and issuer fields depend on the negotiated protocol; empty fields are not invented.

Read account or position P&L

P&L means profit and loss. Daily, unrealized and realized figures are separate values; they should not be added together as if they were independent balances.

  1. Select an advertised account and expand Account and position P&L.
  2. Leave the model code empty unless you use a broker portfolio model. Leave the contract ID empty for account P&L, or enter a confirmed positive contract ID for one position.
  3. Select Subscribe to selected account P&L. The output identifies the captured account, model, contract and request. Changing an input does not relabel an existing subscription.
  4. Wait for values. Position subscriptions also report quantity and market value. Negative position quantities are preserved. An absent callback is shown as waiting rather than as zero.
  5. Select Stop P&L subscription before changing scope. If stopping cannot be queued, the previous subscription remains active. Disconnecting ends the underlying connection.

TWS controls the reset schedule. These callbacks do not carry a currency field, so Umicom does not infer currency or combine accounts. Provider unset values and numbers outside Framework's exact decimal range remain unavailable for arithmetic, with their reported text retained. The native view becomes stale after 15 seconds without an update; staleness records receipt age, not proof that the provider value changed.

Read the depth ladder

  1. Enter a confirmed contract ID and exchange in the quote controls above the depth section.
  2. Expand Market depth. Choose 1 to 50 rows for each side.
  3. For an explicit exchange such as LSE, leave Aggregate SMART depth off. For exchange SMART, turn it on. The combination is validated before a request is queued.
  4. Select Subscribe to market depth. The output shows received bids and asks, prices, sizes and, where supplied, the market maker or exchange identifier.
  5. Observe row ages. Updating one level does not refresh other levels. The ladder follows the broker's row order; Umicom does not sort incoming updates by price.
  6. Select Stop depth stream when finished. The retained ladder becomes historical. Stop and start explicitly after a stream failure.

IBKR reset message 317 clears both sides before subsequent inserts are applied. There is no complete-book marker: seeing rows does not certify that every order is visible. Displayed liquidity can change before an order arrives and does not enforce full-quantity execution. Depth requires the appropriate broker permissions and subscription allowance. Combos are not supported.

Understand limits and recover

Message or symptomWhat to do
No response for an instrumentCheck its contract identity, the account's position where relevant, data subscriptions and availability in TWS. Do not treat silence as zero.
Search pending or requests too close togetherWait for completion, abandon locally, or allow the request timeout to expire. Keep at least one second between accepted searches.
Unsupported protocol or malformed responseRetain the diagnostic and stop qualification. The current transport supports a bounded legacy protocol range; it does not decode every newer API format.
Depth needs an explicit restartStop that stream, review the provider code and correct its route or permissions before subscribing again. A reset is handled automatically only for code 317.
STALE after disconnectionRetained rows are historical. Reconnect and explicitly start new subscriptions. Previous request IDs never acquire authority on a new connection.

Extend the shared implementation

The public interfaces are broker_connectivity/symbol_search.h, broker_connectivity/pnl.h and broker_connectivity/market_depth.h. Keep one thread responsible for pumping the connection and calling its APIs. Copy snapshots for other consumers rather than sharing mutable connection storage. The C API permits 16 P&L streams and three depth streams locally; the native panels each show one stream at a time.

Depth selection exposes the contract descriptors used by its request: contract ID, symbol, security type, expiry, strike, right, multiplier, exchange, primary exchange, currency, local symbol and trading class, plus requested rows and SMART aggregation. Provider-internal options are sent empty. Adding a field requires checking its negotiated protocol layout, validation, lifetime and regression coverage. Do not add an unvalidated generic field passthrough.

Regression sources use invented accounts and injected byte transports. Native lifetime probes use an unconnected window. They cannot establish broker compatibility or permissions for a real account.
