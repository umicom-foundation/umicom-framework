Streaming five-second broker charts

The broker workbench can request five-second price bars from a local TWS or IB Gateway session. A bar records the open, highest, lowest and closing price during an interval. The shared Framework owns subscriptions and decimal records; the native view uses the existing chart renderer.

Start a chart

  1. Sign in to TWS or IB Gateway and enable its socket API. Open the broker connection window in Umicom Trader, choose the intended Paper or Live profile, and connect. Check the reported accounts. The selected profile and port do not prove which account environment the server is using.
  2. Use contract discovery to establish the instrument's contract ID and exchange route. Enter those values in the Contract ID and Exchange fields. The application does not guess a route from a symbol.
  3. Expand Streaming five-second chart. Choose Trades, Midpoint, Bid or Ask, and decide whether to request only regular trading hours.
  4. Select Start five-second bars. Expect a waiting message until the first valid bar arrives. Data availability depends on the instrument, session and your broker permissions.
  5. Change Visible bars (zoom) and Older bars offset (pan) to inspect the retained window. Zero offset follows its newest bars. These controls do not request more data. An older offset is relative to a moving window; it does not freeze a particular timestamp.
  6. Select Cancel streaming bars before changing instruments or starting another subscription in this panel. Cancellation retains the records for inspection and export.

Understand the window

ObservationMeaning
Retained barsAt most 512 bars remain in each subscription. The oldest leaves the window when a new bar arrives after capacity is reached.
Discarded barsThe number no longer present in this rolling window. This is not a permanent market-history archive.
Gap eventsConsecutive bars were not exactly five seconds apart. Closed trading hours can cause gaps. Missing prices are never invented.
StaleNo bar has arrived, the series stopped, or no newly accepted bar arrived within the view's 15-second freshness window. Stale charts are cleared; raw records remain available.
VolumeThe broker's original units are retained. They are not automatically converted to shares or lots. Midpoint, Bid and Ask do not advertise trade volume, weighted average price or trade count.

An identical repeat does not refresh the receipt time. A conflicting repeat, out-of-order bar or broker correction retires the series. Cancel it and start a fresh subscription after reviewing the message. A new connection requires an explicit new subscription; there is no automatic resubmission.

Save a report

  1. Enter a new absolute CSV path in the streaming panel, for example C:\Users\Public\Documents\streaming-bars.csv, using a directory that already exists.
  2. Select Write new streaming-bar report. The report captures the retained rows at that moment, including contract, data kind, regular-hours selection, request identity, receipt times, stale and failure flags, broker error code, discarded bars and gaps.
  3. Wait for the saved message. Existing files are never replaced. If writing fails, inspect any partial new file and select a different path before retrying.

The report owns its bytes before the background write starts. Later bars, cancellation, reconnection or closing the window cannot change that captured report. Text cells are protected from spreadsheet formula interpretation. Raw price text and exact-decimal flags are exported together.

Use the shared C interface

UmiIbkrRealtimeQuery query = {0};
query.contract.contractId = resolvedContractId;
UmiStatus status = umi_text_copy(query.contract.exchange,
                                 sizeof query.contract.exchange, resolvedExchange);
if (status != UMI_STATUS_OK) return status;
query.dataKind = UMI_IBKR_HISTORY_TRADES;
query.regularHours = true;

uint32_t requestId = 0;
status = UmiIbkrRealtimeRequest(connection, &query, nowMilliseconds, &requestId);
/* Continue pumping the connection on its owner thread. Check every status
 * before using the request ID or copying the newest observation. */

Include umicom/broker_connectivity/realtime_bars.h and umicom/base/text.h and link Umicom::ibkr_connection. The connection supports four independent streaming slots. Serialize requests, pumping and copies on the same owner thread. Request and copy failures leave caller outputs untouched. Cancelled slots may be reused, with a new request ID.

UmiIbkrRealtimeCopy copies metadata and evaluates the caller's freshness limit. UmiIbkrRealtimeBarCopy reads chronological retained rows, with index zero the oldest. A received timestamp measures local arrival freshness, not market-time accuracy or entitlement. Do not use an inexact decimal value for exact financial arithmetic.

Include realtime_chart.h and link the optional existing Umicom::ibkr_historical_chart target for candle and scene projection. Scene creation requires a fresh series and representable prices. The caller owns a successful scene. A scene is frozen: compare receivedBars and freshness before reusing it. Transport-only consumers do not need a graphics dependency.

UmiIbkrRealtimeExportCsv returns an owned CSV document and sets its output to null on failure. A stale or cancelled series remains exportable with its state attached to each row. Release the document with UmiCsvDocumentDestroy.

Recover from common problems

  • Busy: cancel the previous panel subscription and allow 15 seconds between new historical or streaming requests. This conservative local gate survives cancellation. Other applications and connections still consume account-wide broker limits.
  • No bars: verify the contract, route, trading session and market-data subscription. A waiting series is not evidence that real-time data is available.
  • Broker error or correction: inspect the code, cancel the affected subscription and explicitly request a new series when appropriate. Error 10225 is treated as a correction requiring a fresh series; retained prices are not silently rewritten.
  • Connection reset: reconnect and subscribe again. Previously retained bars remain stale.
  • Chart unavailable: review raw decimal values. If this build has no optional chart or Cairo adapter, the summary and export remain available.

Supported scope

This adapter uses the bounded legacy TWS protocol range 151–176 and resolved contract IDs. It does not negotiate protobuf, provide tick-by-tick data, merge historical and streaming series, persist an unlimited history, or submit orders through this observation window. Availability of a request does not guarantee support for every instrument and route.

For the broker requirements, see five-second bars, request fields and limits and returned values.
