Review document formatting

To focus a request on selected text, use selected-range formatting and review its complete result. Whole-document formatting remains the default.

Formatting adjusts a document's layout using the language server you select. Framework captures the current draft, requests edits and constructs a complete result without changing the editor. You decide whether to apply that result.

Use Format in Studio

  1. Open a writable source document and choose Format… in the editor command bar. Scroll the bar horizontally if needed. The form captures the whole draft, including unsaved text. A selection does not restrict formatting to that selection.
  2. Enter the absolute path to a trusted language-server program, its arguments and the project folder. If you saved this language's server choice previously, choose Load saved server. Loading fills the form without launching.
  3. Choose a tab width from 1 to 32 and whether to use spaces for indentation. These are preferences sent to the server; the server determines the edits. The options apply to this review and are not saved with the server path.
  4. Choose Request formatting. The worker sends the captured source after initialization, receives the edits, closes the document and stops the temporary connection. The server can inspect the selected project folder.
  5. Choose Preview complete draft and inspect both texts. Select I approve the displayed result only when it is correct.
  6. Choose Apply to captured draft. Framework rechecks the document and applies the result through its existing history. Use Undo to restore the earlier text. Save remains a separate action. Cancel leaves the draft unchanged.

When a result cannot be applied

A changed document, caret, selection or saved state invalidates the capture. Close the form and capture again. Changing connection or indentation settings discards the previous result. A late reply cannot publish into a retired editor binding. Completion and formatting share one review slot, so finish one before opening the other.

Message or situationWhat to check
The server cannot provide formattingChoose a server that advertises document formatting, document open/close synchronization and UTF-16 positions. A syntax checker without formatting support is insufficient.
The response is rejectedThe server must return an ordinary text-edit array or null. Overlapping edits, invalid positions and annotated edits requiring a separate confirmation model are refused.
No editsNull and an empty array are valid. Preview shows the unchanged document; the server may consider it already formatted.
Timeout or capacity exceededThe native request has a five-second read budget and a 65536-byte JSON message capacity, including the envelope and escaped source. The native parser also has a 4096-token limit. Large documents or servers requiring client configuration requests need further integration.

How contributors can extend it

UmiLanguageFormattingQueryNative handles the temporary protocol connection and returns an owned UmiLanguageTextEditPreview. The preview service independently supports up to 256 edits, a 1 MiB JSON reply, and source/result text up to 16 MiB. The native transport has the smaller limits above. Each range refers to the original source; Unicode positions are checked before constructing any result. Inserts at the same position keep their response order and may precede one replacement there.

For repeated range lookups, UmiEditorTextPositionIndexCreate captures the source and builds sparse checkpoints. Each lookup uses binary search followed by a short local Unicode scan. Formatting shares this index across all edit endpoints instead of rescanning the draft from its beginning. The index validates the entire captured source, keeps its revision metadata and owns its bytes; build a fresh index after the source changes.

Keep process work on a worker with copied inputs. Only the GTK thread uses the document coordinator. The source request stages a whole result and routes approved application through the existing Undo transaction. A caret inside a replacement moves to its end; other positions account for preceding edits. The service refuses a mapped caret that would split a newly formed CRLF pair.

Cancellation is observed between native reads. Launch and synchronous writes may finish first. Cleanup owns the direct child, not all descendants it might start. This workflow does not implement format-on-save, a persistent indexing session, range formatting, tool installation or arbitrary server callbacks.
