Create a complete preview from a formatting range

Range formatting shares the full-draft preview and document transaction used by whole-document formatting. The requested range guides the server; it is not a filter that discards edits elsewhere in the result.

  1. Include umicom/language_runtime/formatting_query.h and link Umicom::developer.
  2. Fill UmiLanguageRangeFormattingRequest.source with complete captured UTF-8 source, exact document URI, language ID, preview caret, timeout and formatting options.
  3. Set start and end to UTF-8 byte offsets in that source. Both must be character boundaries, start must not exceed end, and end must not exceed the source length. The SDK permits empty ranges. The preview caret is independent of the formatting range.
  4. Copy inputs into worker-owned storage and call UmiLanguageRangeFormattingQueryNative. Keep input memory alive until the call returns.
  5. Framework resolves both range boundaries into exact UTF-16 positions before native process ownership. It requires documentRangeFormattingProvider and sends textDocument/rangeFormatting with the document URI, range and formatting options.
  6. On success, inspect the complete UmiLanguageTextEditPreview. All returned edits pass the existing position, overlap and ownership checks. Edits outside the requested range are retained for review rather than clipped.
  7. On the document owner's thread, validate the captured source again, show the complete comparison and apply only after explicit approval. Use the existing draft transaction so Undo remains available and saving stays separate.

UmiLanguageRangeFormattingQueryOnServer accepts an exclusively owned STARTING connection. Invalid input leaves it untouched. Once initialization begins, the query owns cleanup; the caller destroys the server object after return. Results are withheld if document closure or server shutdown fails.

Limits and extension points

Tab width remains 1 through 32 and the spaces option is exactly zero or one. Whole-document formatting APIs keep their existing behavior. Supporting document formatting does not authorize range formatting, and an unavailable provider never triggers a fallback.

Native JSON messages must fit 65536 bytes, including escaped source and envelope. Initialization and response reads share the caller's budget, with a separate 250-millisecond read allowance for shutdown. Cancellation is cooperative between operations and retains existing native startup and synchronous-write limits. Only the direct child is owned.

Extend formatting by adding explicit policy and capability checks while preserving complete edit validation. Do not let a worker read live widgets or silently apply only a subset of the server's edits. See whole-document formatting for the shared preview workflow.
