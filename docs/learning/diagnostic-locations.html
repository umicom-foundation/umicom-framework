Navigate complete diagnostic destinations

Diagnostic storage and document navigation have separate responsibilities. The catalogue retains the provider's complete ranges and URIs. The document owner determines whether a selected destination can be opened against the current source.

  1. Capture a diagnostic publication through the existing query service and validate its primary source. Both notification and full pull catalogues expose the same location interface.
  2. Read the selected diagnostic with UmiLanguageDiagnosticCatalogueAt. It supplies the number of related-information rows.
  3. Call UmiLanguageDiagnosticCatalogueLocation with a location index of zero for the primary reported range. Index one selects the first related row; following indices preserve server order.
  4. Copy the borrowed URI before invoking callbacks that may release or replace the catalogue. The returned target and selection ranges are complete metadata copies.
  5. On the document owner's thread, recheck the captured primary request with UmiDocumentSourceRequestCheck.
  6. After an explicit user action, call UmiDocumentCoordinatorOpenSourceRange with the copied URI and selection endpoints. It resolves exact UTF-16 positions in the current target, preserves unsaved drafts, permits read-only navigation and records normal jump history.
  7. Destroy the catalogue after its borrowed views are no longer used.

Ownership and presentation

Invalid arguments and out-of-range location indices leave output unchanged. The accessor performs no allocation, provider access, URI launch or source edit. A diagnostic supports at most 128 related rows under the catalogue's existing publication limits.

In a native UI, copy messages and destination labels before publishing a model. Setting a GTK model can invoke observers synchronously. Recheck the form's owner and generation before exposing controls, and retire the destination model with its publication. Selecting a row is distinct from opening it.

Related ranges in the primary document are checked by diagnostic source validation. Other documents need exact validation when opened, and that validation does not establish that their analysis is fresh. A future multi-document diagnostic service should carry independent source captures rather than treating valid coordinates as revision evidence.
