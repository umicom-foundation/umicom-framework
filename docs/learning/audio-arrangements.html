Arrange audio clips in Media and Music

An arrangement places captured audio on a timeline. You can select part of a recording, delay its start, reduce its volume, fade its ends and overlap it with another clip. Framework produces a complete stereo WAV in memory. You then choose whether to export that render to a new file.

This editor accepts signed 16-bit PCM WAV files with one or two channels, at most 4 MiB per source. All source sample rates must equal the arrangement rate, from 8000 to 192000 Hz. It does not resample, decode MP3/AAC, record devices or play audio. Use an external player to listen to the exported WAV.

Prepare your sources

  1. In Media or Music, open Creative workbench → Asset library. Import your WAV files under meaningful IDs, such as narration and intro-music.
  2. Save the library to a new file. See Keep creative assets together.
  3. Open Audio arrangement. Enter the absolute saved library path and choose Load asset library. The result lists its asset IDs and sizes. A failed load retains the previous library. Editing the source library elsewhere does not change this captured copy.
  4. Set a title and the sample rate used by your WAV files, then choose Apply title and sample rate.

Place and edit audio

  1. Enter a unique placement ID, such as opening-voice, and its source asset ID.
  2. Set the timeline start in milliseconds. A value of 0 starts immediately; 2000 begins two seconds into the output.
  3. Set the source begin and end. The beginning is included and the ending is excluded. For example, 1000 to 3000 uses the recording's second and third seconds.
  4. Set gain between 0 (silent) and 1000 (original volume). Use 500 for half sample amplitude. Optional fades must fit within the selected source range.
  5. Choose Add new placement. Repeat for other sources, or use the same source ID again under a different placement ID. Overlapping placements are mixed; gaps become silence.
  6. To edit an existing placement, enter its ID, choose Load placement fields by ID, change the fields and choose Replace existing placement. Removal uses the entered placement ID and leaves the captured source file intact.

The summary shows the applied plan. Typing in the form alone does not change the arrangement. Accepted edits discard an older render so it cannot be exported as though it represented the new plan. There are at most 16 placements. This editor has no general Undo history; save new arrangement files when you want to keep alternative edits.

Render and export

  1. Choose Render arrangement in memory. Every referenced source must exist, decode as supported PCM and contain its complete requested range. A failed render creates no output file.
  2. Read the reported frame count, sample rate, source count and clipped-sample count. Clipping occurs when overlapping samples exceed the signed 16-bit range. Lower the relevant gains and render again when clipping is reported.
  3. Enter a new absolute WAV path and choose Export rendered WAV to new file. The parent folder must exist. An existing destination is refused, so use another filename.
  4. Open the saved WAV in a player and listen. No playback is started automatically.

Rendered output is stereo signed 16-bit PCM; mono sources appear in both channels. It ends at the last placement, with no automatic tail. The maximum rendered file is 64 MiB, including its 44-byte WAV header. At 48000 Hz stereo this is approximately 349 seconds. The timeline also has a ten-minute bound, so the smaller applicable limit controls each render.

Save and reopen an arrangement

  1. Enter an absolute JSON path and choose Save arrangement to new file.
  2. Keep that JSON file and its saved asset library. The JSON contains titles, IDs and timings; it does not embed audio or remember a machine-specific library path.
  3. In a later session, load the matching library and open the arrangement JSON. Opening over unsaved arrangement edits requires explicit approval. Changing the JSON path or accepting a plan edit clears that approval.

A damaged or unsupported recipe leaves the current plan intact. A saved recipe can reference IDs that are not in the loaded library; rendering will report the mismatch and produce no partial mix.

Understand timing and limits

Milliseconds convert to sample frames using the integer part of milliseconds × sample rate ÷ 1000. A frame contains one sample per channel. Gain is applied first, then fade-in and fade-out, with signed division towards zero. Placements add in a wide accumulator; only the final sample is saturated to the PCM range. This makes the mix independent of placement order.

Library bytes, decoded sources and the output may coexist in memory. Rendering caches a decoded source once per asset ID. File and render work runs on a worker. Cancel preserves the plan and library; a write that has already created its destination may leave a partial or complete new file. Read the receipt and use another filename before retrying. Closing the window discards unsaved in-memory work.

Use a Studio task or a shell

The installed umicom-audio-arrangement command uses the same services as the native page. Give it complete absolute paths as separate arguments. For example, from the directory containing the executable:

.\umicom-audio-arrangement.exe inspect "C:\Projects\Tutorial\mix.json"
.\umicom-audio-arrangement.exe render "C:\Projects\Tutorial\sources.umilibrary" "C:\Projects\Tutorial\mix.json" "C:\Projects\Tutorial\mix-output.wav"

On Linux, use the installed command without .exe and use absolute Linux paths. Inspect reads only the recipe; render loads its sources, reports clipping, then creates a new WAV. Exit code 0 means success, 1 means an operation failed, and 2 means the command arguments were invalid. No playback, upload or overwrite occurs. An interrupted write may leave a new partial file. In Studio, select this executable for an explicit task and pass the same separate arguments.

For contributors

The portable audio_arrangement.h interface separates editable plan values from library ownership and native controls. New frontends can use the same validator, strict JSON reader and renderer. Keep source libraries unchanged during rendering; publish a new asset only after the entire mix succeeds. Add format adapters at the existing decoder boundary instead of guessing formats from file extensions or silently changing sample rates.
