Choose context for a chat follow-up

A coding discussion often needs part of an earlier explanation. The shared chat window keeps up to eight completed exchanges in memory, so you can inspect them and choose an excerpt for your next question. An exchange contains the exact reviewed request and its text reply. Earlier conversation text is never added to a new request automatically.

Start a discussion

In Studio, open AI Coding → Connections and choose an enabled saved connection, or use Chat about selected code… after highlighting code in the active editor. Follow Chat with saved connections for setup, credentials and sending. The selected-code guide explains how editor text is captured.

After a successful send, the request and reply appear in This window's conversation. The entry shows the requested and reported model and whether the provider refused the request or returned an incomplete reply. Failed, timed-out and cancelled requests do not become completed exchanges. A review alone does not create an entry.

Ask about an earlier answer

  1. Wait for the current operation to finish. Scroll to This window's conversation.
  2. Choose the exchange, then choose Earlier request or Earlier reply. Inspect the displayed text and connection details.
  3. Highlight exactly the words you want to include. For example, select an explanation of who owns an allocation. Leaving the selection empty does not copy the entire answer.
  4. Choose Replace context with selected excerpt. This replaces the entire Optional context field with the selected text and a short label identifying it as quoted earlier text. If that field already contains code or another excerpt, keep any text you still need before replacing it.
  5. Enter the next prompt, such as “Show how that ownership rule applies to this function.” You may edit the copied context before reviewing.
  6. Choose Review request and inspect the complete message, destination, model and output limit. Copying an excerpt clears the previous review, approval, local password and displayed current reply. It does not send anything.
  7. Enter your local profile password if this is a remote connection, approve the displayed request and choose Send reviewed request once.

This is a new request containing the context you chose. It does not resume a provider-managed conversation or grant earlier model text permission to execute tools. A label such as “Earlier assistant text” describes the source of a quotation; the adapter still sends an ordinary user message. Read both your prompt and copied context before approving.

Limits and recovery

  • Context is too large: select a shorter excerpt. The context field holds at most 8,192 UTF-8 bytes, including the quotation label. Some characters use several bytes. An oversized excerpt is rejected without replacing the existing context or its review; text is never silently cut off.
  • History is full: use Forget selected exchange or Clear conversation. The first eight entries are retained. A later successful reply still appears in the current reply field, with a notice that it was not added to history. Do not resend a paid or otherwise completed request merely to record it.
  • The selection changed: select the exchange and highlight the intended text again. The owner checks a history revision and stable exchange identity before using the selection.
  • A reply is incomplete or a refusal: the history keeps that status and includes it in a copied reply's label. Ask a new question deliberately; the application does not automatically retry or continue it.
  • The connection changed: an old history entry records the destination used for that exchange. It does not approve a new destination. Reload the saved connection and review a new request using the ordinary connection workflow.

Clear the right copies

Forget selected exchange removes that owned history entry. Clear conversation removes all history entries. Text already copied into Optional context, the prompt or the current reply remains visible. This lets you finish a draft while removing earlier exchanges.

Clear local text clears the draft, current reply and this window's conversation together. Closing the window also retires its history. Use the existing discard control if the window asks you to confirm losing unsaved text. History is not saved to the connections database, a transcript file or a remote database by this workflow, and reopening the window starts empty.

Authentication passwords, API keys obtained from the credential store and raw transport bodies are not copied into history. The prompt and reply are kept as supplied, so do not include secrets in text you intend to send. Local clearing cannot retract content already sent to a provider. Nor does it promise erasure of copies held internally by the operating system, clipboard or third-party libraries.

Extend the shared owner

UmiProviderChatHistory belongs to one owner thread. Create it for the chat window and destroy it when the window retires. Append only a successfully validated request/result pair. The owner copies complete text and non-secret connection metadata, checks bounds and UTF-8, and returns a stable ID. It never evicts an older entry automatically.

Use UmiProviderChatHistoryCompose to build context from explicitly selected byte ranges. Each range must cover complete UTF-8 characters. The native view converts character selections into byte ranges only after comparing the displayed text with the owned entry. Composition checks the expected history revision and publishes output only when every excerpt fits. New consumers should preserve that all-or-nothing behaviour.

The generic API supports several selected excerpts in caller order; the native action copies one highlighted range at a time and replaces the context field. Neither route automatically includes an entire exchange, its metadata or the rest of the conversation. Review the final combined request in the ordinary chat owner before any send.

The existing small-message conversation and archive APIs remain available with their original limits. This owner supports the larger reviewed-chat request and reply limits without changing those older data structures or silently truncating messages. It keeps history on the heap and leaves worker threads responsible only for their own request and result. A worker completion records an exchange on the UI thread only while the window is still open.

When you decide to use suggested code, follow Review a replacement for selected code. Source editing has its own target capture, complete-draft preview and explicit approval; a chat send never approves an edit.
