Keep file format with document history

Source bytes, cursor positions and save policy have different roles. The editor uses UTF-8, while the document coordinator chooses the encoding and line endings passed to its storage provider. Changing visible newlines without changing that policy can cause Save to convert them back. The shared format service updates both through one document transaction.

Prepare an independent conversion

  1. Include umicom/document/format.h and link Umicom::document.
  2. Pass complete UTF-8 source, its byte count, caret offset and selection length to UmiDocumentFormatPlanCreate. Use LF, CRLF or CR as the target. NONE preserves bytes and requires the final-newline option to be zero.
  3. Inspect UmiDocumentFormatSummary and read the complete proposed text. The plan owns its result; the input can be released after creation returns.
  4. Destroy the plan after the borrowed output is no longer needed. Preparing a plan does not change any document or file.

The converter validates the complete source, refuses embedded NUL and endpoints inside a Unicode character or CRLF pair, and checks exact growth before allocation. Input and output are each bounded to 8 MiB. A requested final newline is appended only when absent; an original EOF caret stays before the newly appended ending. Cancellation is checked between bounded phases.

Apply an explicit choice to the active draft

UmiDocumentFormatOptions options = {
    .encoding = UMI_DOCUMENT_ENCODING_UNKNOWN,
    .line_ending = UMI_DOCUMENT_LINE_ENDING_CRLF,
    .ensure_final_newline = 0
};
UmiStatus status = UmiDocumentCoordinatorSetFormat(documents, &options);
/* Handle a refusal before offering Save. No file was written by this call. */

UNKNOWN retains the current encoding. NONE retains the current line-ending policy and source bytes. To change encoding only, select UTF8, UTF8_BOM, UTF16_LE or UTF16_BE and use NONE for line endings. To add a final newline, explicitly choose the target ending and set ensure_final_newline to one. BINARY, MIXED and invalid flags are refused.

Call on the document owner thread. Complete text is prepared before commit. Read-only drafts and busy save, reopen or navigation operations are refused. The existing commit reserves view storage before publishing and keeps earlier pending typing separate from the format step. Metadata-only changes advance the store revision, invalidate stale proposals, mark the document dirty and remain undoable.

Native integration and extension

UmiGtk4AdapterSetDocumentFormat uses the established editing binding and completion callback. It resolves the binding again after document work because a refresh may retire the native host. Applications need only declare their choices and invoke this shared API; they should not create another codec, save path or history owner.

History stores save policy only at format transitions. Undo and Redo transfer it together with source and selection. Reload captures the old encoding and ending policy even when decoded text is identical. Existing text-only history retains its positioning rules.

When extending supported encodings, add a loss-aware shared codec and failure coverage before exposing a new choice. Do not silently replace unrepresentable characters. Save remains separate and keeps its provider error and external-change checks. This service does not persist project defaults or change the recovery record format.

Read document history and recoverable drafts for their separate ownership and persistence contracts.

The encoded file on disk can be larger than its editable text. Open, source navigation, reload and external-change checking allow a bounded serialized size of up to 32 MiB plus three marker bytes, then enforce the existing 8 MiB limit on decoded, normalized UTF-8 text. This accommodates UTF-16 and CRLF expansion without opening oversized drafts partially. The generic document loader still honors the separate byte limit selected by its caller.
