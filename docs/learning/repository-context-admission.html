Admit repository context safely

A coding assistant needs to explain which repository files it may include in a prompt. Framework's coding-context index stores paths, language labels, summaries, privacy classes and token estimates. It owns metadata copies; it does not read files, parse source code or invoke a model. This lesson follows the public coding-context API.

1. Validate bounded values before string operations

A fixed C array can contain characters without a terminating zero. Passing that array to a path parser or string comparison can read beyond its intended boundary. UmiAiCodingContextFileValidate first delegates fixed-field checks to the shared snapshot validator, then applies the existing path and numeric rules.

FieldAdmission rule
pathTerminated within its array, nonempty and lexically relative.
language_id, summaryTerminated within their arrays; empty text is allowed.
estimated_tokens, priorityPositive values.
classificationA known value from public through restricted.
active, enabledExisting nonzero-is-true behavior, including negative values.
UmiAiCodingContextFile file = {0};
strcpy(file.path, "src/calculation.c");
strcpy(file.language_id, "c23");
strcpy(file.summary, "Calculation helpers");
file.classification = UMI_AI_DATA_INTERNAL;
file.estimated_tokens = 240U;
file.priority = 50U;
file.active = 1;
file.enabled = 1;
UmiStatus status = umi_ai_coding_context_upsert(index, &file);

These literals fit their destination arrays. Values from users or external tools need bounded copying and an explicit overflow response. Accepted upserts replace incoming historical revision metadata with the next revision assigned by this index.

2. Separate lexical paths from filesystem containment

The shared path rule rejects absolute paths, drive prefixes, colons, control bytes, empty components and dot or parent components. For example, src/math.c is accepted while src/../private.c is refused. Both slash styles are understood.

A lexically valid relative path can still refer through a filesystem link or to a file changed after preview. The adapter that eventually opens it must enforce the approved workspace and live filesystem rules. Index validation neither follows links nor proves that the file exists. An incoming language label is metadata rather than evidence of the file's contents.

3. Preserve optional-file selection

Enabled active files rank first, then higher priority, then lexical path order. Every file in this coding index is optional. A file rejected by privacy, remaining token capacity or file-count capacity is counted as dropped; the successful plan is marked truncated. This differs from the general context broker, which also supports mandatory sources.

A zero remaining token budget is valid. It can occur when general workspace context consumes the available budget. In that case enabled coding files are reported as drops and the returned plan is empty. Invalid privacy limits or unknown provider kinds instead refuse the entire operation, even when the index is empty; they are not ordinary file exclusions.

UmiAiPrivacyPolicy privacy = umi_ai_privacy_policy_default();
UmiAiCodingContextPlan *plan = malloc(sizeof *plan);
if (plan == NULL) return UMI_STATUS_OUT_OF_MEMORY;
UmiStatus status = umi_ai_coding_context_plan(index, remaining_tokens, 8U,
    provider_kind, &privacy, sensitive_approved, plan);
if (status == UMI_STATUS_OK) {
    /* Display plan->file_count, dropped_count and remaining_tokens. */
}
free(plan);

The complete plan is built in temporary storage before replacing the caller's value. On refusal the old output remains unchanged. Always branch on the return status: retaining an older plan does not make it appropriate for the failed request.

4. Capture and retire owner state deliberately

UmiAiCodingContextCapture reports the count and revision without copying file contents. UmiAiCodingContextIndexValidate checks owner bounds, stored metadata, unique paths and stored revisions before traversal. The legacy count helper returns zero for invalid state; callers that must distinguish an error from an empty index should use validation or capture.

Upsert, remove and clear refuse an exhausted revision instead of wrapping back to an earlier identity. UmiAiCodingContextClearChecked reports refusal. The older void clear delegates to it and leaves state unchanged on failure. A successful empty clear still advances the revision. Removal also zeroes the unused trailing record after compaction.

Serialize access to a live owner. These checks are not locks and cannot repair a dangling pointer. A copied plan is independent metadata and remains unchanged after later index edits; its revision does not track edits made directly to repository files.

5. Diagnose and verify a boundary failure

  1. Fill the entire path array with nonzero bytes. Expect invalid-argument refusal before the path parser runs; the index must remain unchanged.
  2. Set an active flag to a negative nonzero value. Expect it to rank ahead of inactive files.
  3. Prepare a zero-budget plan. Expect success, no selected files and one drop for each enabled file.
  4. Set a privacy limit to an unknown enum value. Expect refusal with the previous plan unchanged.
  5. Restore valid metadata and compare capture revisions before and after an accepted edit.
cmake --preset windows-ucrt64-debug
cmake --build --preset windows-ucrt64-debug --target umicom-ai-coding-context-admission-test
ctest --test-dir build/windows-ucrt64-debug -R '^framework[.]ai[.]coding-context[.]' --output-on-failure --no-tests=error

Stop on a failed command. The native regression cases also inject otherwise impractical invalid counts and exhausted counters. That direct representation access belongs only to the test fixture. The installed SDK consumer uses public APIs offline. Source inspection and test registration are not evidence that compilation, runtime checks or GUI behavior passed.
