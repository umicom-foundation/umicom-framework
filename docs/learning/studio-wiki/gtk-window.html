Connect a window to shared behaviour

GTK4 is a toolkit for graphical applications. A widget is an interface element, such as a label or a button. A container arranges widgets. A signal reports an event, and a callback is the function connected to that event.

Understand lifetime

Ownership describes who must release a resource. The window owns the counter's state through an attached cleanup function. GTK containers own their child widgets. A borrowed widget pointer lets the callback use a child without taking over its ownership.

The callback retains the window while updating its label so that a notification cannot destroy its state in the middle of the operation. Such rules matter when applications have several panels that can close independently.

Check the interaction

  1. Enable the example's BTB_ACTIVITY_GTK4 CMake option and build it.
  2. Start the window and expect a count of zero.
  3. Click once and expect one; click twice more and expect three.
  4. Use the keyboard to focus and activate the button.
  5. Close and reopen the window. The count starts at zero because this example has no persistence.

Logic tests and these window checks cover different behaviour. Neither replaces the other. Follow the full Bits2Banking GTK4 lesson for setup commands.
