Create a learning content module

A content module is a folder containing learning-pack.json and the files declared by that manifest. A manifest describes what is in a package. It is data, not a program to execute.

Prepare the content

  1. Choose a stable pack identity and product name.
  2. Write the introduction and lessons in a clear order.
  3. Give each resource an identity, title, topic, kind and relative path.
  4. Calculate its SHA-256 digest after reviewing the final bytes.
  5. Declare the Framework compatibility range you have reviewed.
  6. Keep all local reader links within the declared pack.

The reader compares the actual file bytes with the declared digest. This detects changed content; it does not prove who published it. A trusted installer chooses which pack directories to distribute.

Bundle an offered module

Framework's UmicomLearningModuleBundle.cmake validates a selected module, stages declared files beside the application and includes them in installation. Studio resolves that location from its executable, not the current project directory. Its optional Bits2Banking source can be selected with UMICOM_STUDIO_BITS2BANKING_MODULE.

Opening a module is explicit. The UI does not run a post-install script, compiler or example. Missing files and mismatched hashes are reported while retaining the previous reader. A local folder can also be loaded through the catalogue.

Maintain several formats

Keep Markdown and HTML as reviewed source versions. Preserve unique explanations when comparing them. Regenerate a pack digest only after reviewing its changed HTML. Use a browser for full HTML presentation; the native reader supports a bounded structured reading view.

To host this wiki on the web, publish these HTML pages together under one directory. No hosting or online marketplace account is created merely by bundling them locally.
