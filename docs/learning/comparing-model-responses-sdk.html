Native AI application learning path

Compare model responses with the Umicom Framework SDK

Learn how to keep several answers, preserve individual failures and select an answer without submitting the prompt again. This project uses C23 and the installed Framework SDK. The small example contains synthetic captured results and makes no provider calls.

1. Separate the workflows

Multi's product description distinguishes a single answer, comparisons, a judged panel and automatic routing. These are useful design ideas, but each needs different evidence. Comparing answers preserves alternatives. A judge adds another model request. Routing selects a provider before an answer exists. Agreement between models does not establish factual correctness.

Umicom's existing umi_ai_model_ensemble_query sends one copied request sequentially to enabled targets through runtime policy. It stores up to eight results and automatically selects the first success. It is synchronous, does not run providers in parallel, and does not implement a council, quality judge or automatic model router. A caller can choose a different successful result later.

2. Understand the report

FieldMeaning
result_countNumber of active slots, bounded by the eight-slot array. Disabled targets are omitted.
success_countExact number of active slots with status UMI_STATUS_OK.
selected_indexA successful result index, or SIZE_MAX when no result is selected.
revisionA local change counter. A query publishes revision one; a selection increments the existing counter. It is not a timestamp or proof of server identity.

Use umi_ai_model_ensemble_report_initialize rather than assuming an all-zero structure is a valid empty report: zero is an index, while SIZE_MAX represents no selection. The report also carries structure size and API version fields so functions can refuse incompatible records.

3. Admit data before indexing

Call UmiAiModelEnsembleReportValidate before another component consumes a manually assembled report. Selection and the comparison view call the same validator internally. It checks the active count before reading slots, validates result and target metadata, requires binary flags, checks successful responses through the shared response validator, and reconciles success and selection fields.

UmiStatus status = UmiAiModelEnsembleReportValidate(&report);
if (status != UMI_STATUS_OK) {
    /* Display a structural error; do not index the supplied report. */
    return status;
}
status = umi_ai_model_ensemble_select(&report, desired_index);
if (status != UMI_STATUS_OK) return status;
const UmiAiModelResult *selected = umi_ai_model_ensemble_selected(&report);
/* selected is borrowed from report; copy needed fields before changing it. */

The validator does not establish UTF-8 validity, identity correlation, factual quality, latency, cost or trustworthy token counts. Failed response storage remains diagnostic data and is not treated as a successful answer. Keep report storage complete and stable during a call; serialize changes from different threads. The query's output must not overlap its request, targets or runtime.

4. Build an independent project

First obtain a Framework SDK package built with a compatible compiler and these APIs. The SDK example is installed under share/umicom/framework/examples/model_comparison. Copy that folder into your own project workspace; it includes complete C and CMake files. The project links Umicom::ai instead of compiling Framework sources or cloning its repository.

In PowerShell, replace the SDK path below with your installed package. Run each command separately and stop on an error.

Set-Location C:\Projects\model_comparison
cmake -S . -B build -G Ninja -DUMICOM_SDK_ROOT=C:/SDK/Umicom -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
& .\build\bin\umicom-sdk-model-comparison.exe

The example initializes two captured slots: one contains a synthetic answer and the other is unavailable. It validates the report, selects the success, and checks that the failed result remains available for inspection. Expect a line naming model-a and the retained failure status, with exit code zero. This is a synthetic contract check, not evidence of a working server. The SDK branding helper supplies approved Umicom resources and Windows icon metadata.

5. Connect a real provider deliberately

  1. Complete the provider ownership lesson and configure the runtime's provider registry and policy.
  2. Create one request with the shared request initializer and setters. Keep its identity stable throughout the comparison.
  3. Initialize each target with umi_ai_model_target_initialize. A model identifier is bounded by the AI request contract; do not truncate a longer discovery identifier to make it fit.
  4. Review every enabled destination. Each provider receives the prompt separately, with its own policy decision, possible cost and failure.
  5. Call the query away from a UI thread if waiting would block interaction. The function itself supplies no asynchronous scheduler.
  6. Inspect both the returned status and individual results. A successful overall return means at least one answer succeeded; other results may still have failed.

All-failed queries preserve individual statuses and return the last useful failure. An all-disabled query returns invalid state with no active results. Selection only changes the report; it never retries a failed provider or reruns a prompt.

6. Diagnose boundary failures

ObservationRecovery
Invalid report or targetCheck initializers, counts, terminated identifiers, versions and exact success totals. Never repair a corrupt count by silently truncating it.
Selection returns capacity exceededThe 64-bit revision is exhausted. Preserve the report and create a new explicitly identified comparison; do not reset the counter on the same record.
Comparison view rejects a very large revisionThe current UI value model stores signed 64-bit integers. Values above INT64_MAX cannot be projected, even though the report's unsigned revision is structurally valid.
SDK helper or symbol missingCheck the selected package, compiler and component version. Use a fresh consumer build directory after choosing a matching SDK; do not mix headers from another checkout with old libraries.

7. Exercises and evidence

  1. Make both synthetic results successful and select the second. Verify the first answer is retained and the revision increments once.
  2. Set the active count to nine and attempt selection. The report must be refused before any array access, with caller data unchanged.
  3. Keep a failed slot containing arbitrary response bytes. Explain why its status remains useful but its text cannot be displayed as a validated success.
  4. Set the revision to UINT64_MAX. Verify refusal without changing selection or revision.
  5. Document SDK identity, compiler, command exits and failed or skipped checks separately. Compile, native tests and an actual UI workflow are separate qualification steps.

The authored Framework regressions cover these cases, malformed response finish reasons, pre-dispatch request/target checks, and partial provider failures using local test callbacks. Their presence does not claim that your installed SDK or live providers passed them. Continue with request-owned streams before designing streaming comparisons.
