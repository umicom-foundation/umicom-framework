Inspect loaded debugger modules

A module is a program or shared library known to the debugger. Its symbol information connects machine instructions to function names and source lines. The module browser reports what the connected adapter supplies; it does not search your disk or load symbol files.

Read modules in Studio

  1. Open your project, review its location and trust it. Start a native debugging session or attach to a process you are authorised to debug.
  2. Open the Debug surface, expand Loaded modules, then choose Refresh modules. Nothing is requested before this action.
  3. Expand a module to inspect its path, version, symbol status, symbol file, timestamp, address range and the optional user-code and optimisation flags. Not reported means the adapter omitted a value.
  4. Use Next or Previous to read another page. Each request contains at most 32 modules. A full page without a total may require another request to discover the end.
  5. After restarting, reconnecting or changing projects, choose Refresh modules again. A page captured from the old connection cannot be used to navigate the new one.

Interpret the results

Modules can load or unload between requests. Pages are separate observations, not a frozen snapshot of a process. Numeric and string module IDs remain distinct even when their visible spelling matches. Paths are adapter metadata and may refer to another machine; the browser does not treat them as trusted local files.

The displayed total may be absent. Navigation stops at the adapter protocol's maximum starting index of 2,147,483,647. Oversized fields, duplicate IDs within a page and malformed responses are reported as errors rather than silently truncated.

If a request fails

  1. If support is unavailable, check that the selected adapter advertises module browsing. A connected session alone does not guarantee that feature.
  2. If a session or workspace changed, refresh from the first page. Do not assume an old list describes the new process.
  3. If the adapter times out or sends an invalid response, inspect its own diagnostic output. The browser clears the stale page and does not retry automatically.

The request is bounded and synchronous, so the current Studio window may pause briefly while waiting. It does not resume or pause execution, evaluate an expression or change breakpoints.

Use the Framework component

Read UmiDebugRuntimeModuleSessionRead, then pass that captured identity to UmiDebugRuntimeModulePageRead. Call on the platform owner thread after checking workspace authority. The caller owns the returned page; failures leave it unchanged. Pending lifecycle events block inspection, and every restart attempt retires earlier captures. Allocate pages on the heap because their copied path fields are large. The existing whole-registry refresh API remains available for existing consumers.
