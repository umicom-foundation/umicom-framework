Practical workflow tools across Umicom applications

A useful application helps you finish a task without losing track of your work. In this lesson you will move between source files in Studio, prepare a fresh order ticket in Trader, find applications in Desk, and review financial amounts in Bank and TMS.

The screens have different purposes, but they share a design rule: the application asks Framework to perform a well-defined operation. Framework owns the calculation or state change. A button is the way you request that operation, not a separate implementation of it.

1. Move between source documents in Studio

Open a disposable Umicom Notes project with three files: notes.c, notes.h and tests.c. Open them in that order. Add a comment to notes.c, but leave it unsaved.

Choose Navigate → Next Source Document, or press Ctrl+Tab. Choose Previous Source Document, or press Ctrl+Shift+Tab, to move the other way. The sequence wraps around: after the last open document comes the first.

The order is the document coordinator’s opening order. It is not a list of recently visited files and does not follow a manually rearranged visual tab order. Only managed source documents participate; a tool panel is not a source document. With one document open, the command keeps that document active. With no active managed source document, the command is unavailable.

Return to notes.c. Your comment, caret, selection and Undo history should still be there. Switching a tab does not save a file, reload it, change its text or discard another draft. Read-only and pinned documents can still be visited.

2. Begin a fresh order ticket

Use Trader’s simulation environment and select an instrument. Change the ticket’s side, quantity and price. The Reset ticket button returns the draft to the existing defaults: Buy, Limit, Day and a quantity of one.

The selected instrument and account remain selected. Framework uses its existing instrument-selection routine to supply the initial limit price: the latest quote midpoint, a retained bar close when no quote exists, or zero when there is no usable price. The stop price returns to zero. Always check the instrument, quantity and price before submitting.

Reset clears the earlier risk-preview result. It does not cancel an order, reverse a fill, reset an emergency stop, change the environment, arm live trading or contact a broker. Existing orders and positions remain in their own stores. Resetting the ticket is therefore different from cancelling an order.

Try it with a simulation order already listed. Record its identifier and status, reset the ticket, and confirm that the order is unchanged. Repeat with the emergency stop engaged: reset must not release that stop.

3. Find applications in Desk

The category selector on Desk’s Home page works together with its name search. Begin with All applications, type part of an application name, and then select a category.

CategoryWhat it shows
All applicationsEvery application that also matches the name search.
AvailableApplications whose current launch-choice snapshot reports them eligible.
RunningApplications whose snapshot reports them running.
SelectedApplications currently selected in the catalogue, whether or not running.
Needs attentionApplications with an Attention or Failed runtime state.

Filtering changes visibility only. It does not start or stop a process and does not change the selected applications. A running application can be hidden by a filter and still be running. Choose All applications and clear the name search to show the complete catalogue again.

4. Review account funds in Bank

Open the Account funds review — manual values section above the Bank workstation. Enter GBP and select two decimal places. The currency code identifies the unit; the decimal-place setting tells the calculation how to represent it. The setting is explicit rather than looked up from a currency database.

FieldAmountMeaning
Ledger balance1000.00The starting balance supplied for this exercise.
Reserved funds100.00Money already set aside.
Proposed debit250.00An amount you are considering, not a payment instruction.

Choose Calculate. Available funds should be 900.00, and the amount remaining after the proposed debit should be 650.00. Change the debit and notice that the previous result is marked out of date until you calculate again.

This section is a manual calculation. It neither reads your real account balance nor creates a payment, approval or ledger entry. A negative result is shown rather than hidden, but it grants no overdraft permission. Clear amounts resets only these input fields; it does not clear saved financial data.

5. Review a cash forecast in TMS

Open Cash forecast review — manual values. Use GBP, two decimal places, and the values below.

FieldAmount
Opening cash1000.00
Inflows400.00
Outflows550.00
Required buffer200.00

The net flow is 400.00 − 550.00 = −150.00. Projected cash is 1000.00 − 150.00 = 850.00. Buffer headroom is 850.00 − 200.00 = 650.00.

Headroom means the amount left above the buffer you supplied. A negative headroom indicates a shortfall relative to that buffer. It is not a lending decision or a complete liquidity-risk measure. The calculation uses one currency and one simple period; it does not discount cashflows, convert currencies, apply calendars or create a trade or settlement.

6. Use the contracts in another application

A C header declares what a function accepts and returns. Its implementation performs the operation. A caller checks the returned status before using an output. All new review and filtering calls copy their results to caller-owned storage and retain no input pointers.

ContractPurpose and exampleOwnership and failure
UmiDecimalParseConvert counted decimal text to a signed integer coefficient at an explicit scale. 12.5 at scale 2 becomes 1250.Borrowed input during the call. Output unchanged on failure; no allocation.
UmiDecimalFormatTurn coefficient 1250, scale 2 back into 12.50.Caller supplies a buffer including room for its terminating zero. Too little space leaves it unchanged.
umi_decimal_rescaleChange scale with checked multiplication. Reducing scale truncates towards zero.Only scales 0–9. No signed overflow is evaluated; rejected output remains unchanged.
UmiFinanceReviewAccountCalculate ledger minus reservations, then minus the proposed debit.All amounts use the same currency and scale. Reservations and debit must be nonnegative.
UmiFinanceReviewCashCalculate net flow, projected cash and headroom above a buffer.Nonnegative inflows, outflows and buffer; signed opening balance. Intermediate overflow is rejected.
UmiDocumentCoordinatorCycleMove to the next or previous managed source document; direction is +1 or −1.Borrowed coordinator, owner-thread call. It activates through the existing workbench and does not write a file.
UmiGtk4AdapterCycleDocumentUse the same source-cycle operation in a GTK host.Uses the existing editing binding and completion callback.

Why the amount stays an integer

With two decimal places, 1250.75 is stored as the integer 125075 and the scale 2. Parsing does not first convert through a floating-point value. Formatting produces exactly the selected number of decimal places.

Use a decimal point, not a comma, and provide no more fractional digits than the selected scale. Optional signs and surrounding spaces or tabs are accepted. Exponent notation, embedded zero bytes and values outside the signed 64-bit range are rejected. The counted input limit is 96 bytes. If rescaling cannot be represented, keep the previous value and ask for a suitable amount rather than wrapping around.

Connect the widget without copying its logic

Create the component on the GTK thread, then append it to the host’s existing box:

GtkWidget *review = NULL;
UmiStatus status = UmiGtk4FinanceReviewCreate(
    UMI_GTK4_FINANCE_REVIEW_ACCOUNT, &review);
if (status == UMI_STATUS_OK) {
    gtk_box_append(GTK_BOX(contentBox), review);
}

Here contentBox is an existing GTK box owned by the application window. Appending adopts the component’s floating reference. Bank and TMS use this pattern above their existing workstations, leaving the normal layout and service-backed panels in place.

For a custom screen, call the pure review functions and display the returned fields yourself. Do not assume that a successful calculation authorises a financial action. A real payment or trade still requires its own service, permissions and business checks.

7. Compile the complete C example

The example below uses Framework’s real decimal, money-review and application-filter contracts. It performs the Bank and TMS calculations and checks the expected integer results. The application snapshot used for the final filter exercise is explicitly constructed in memory; it does not inspect or start a real process.

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/workflow_tools/main.c
 * PURPOSE:
 *   Read exact financial amounts, review funds and inspect an application filter.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/

#include "umicom/finance/decimal.h"
#include "umicom/finance_ui/funds_review.h"
#include "umicom/desktop/application_filter.h"
#include <stdio.h>
#include <string.h>

/* A scale of 2 stores GBP 125.50 as the integer 12550. No double conversion
 * takes place. This helper only chooses the currency for this exercise. */
static UmiStatus ReadGbp(const char *text, UmiMoney *out)
{
    UmiDecimal decimal;
    UmiStatus status = UmiDecimalParse(text, strlen(text), 2U, &decimal);
    if (status != UMI_STATUS_OK) return status;
    UmiMoney money = {0};
    money.minor_units = decimal.coefficient;
    money.scale = decimal.scale;
    memcpy(money.currency.code, "GBP", 4U);
    *out = money;
    return UMI_STATUS_OK;
}

static int ShowMoney(const char *caption, UmiMoney money)
{
    char text[UMI_DECIMAL_TEXT_MAX + 1U];
    UmiStatus status = UmiDecimalFormat(
        (UmiDecimal){money.minor_units, money.scale}, text, sizeof text);
    if (status != UMI_STATUS_OK) {
        fprintf(stderr, "%s: %s\n", caption, umi_status_text(status));
        return 1;
    }
    printf("%s: %s %s\n", caption, money.currency.code, text);
    return 0;
}

int main(void)
{
    UmiMoney ledger, reserved, proposed, inflows, outflows, buffer;
    if (ReadGbp("1000.00", &ledger) != UMI_STATUS_OK ||
        ReadGbp("100.00", &reserved) != UMI_STATUS_OK ||
        ReadGbp("250.00", &proposed) != UMI_STATUS_OK ||
        ReadGbp("400.00", &inflows) != UMI_STATUS_OK ||
        ReadGbp("550.00", &outflows) != UMI_STATUS_OK ||
        ReadGbp("200.00", &buffer) != UMI_STATUS_OK) {
        fputs("An example input could not be represented.\n", stderr);
        return 1;
    }

    /* These are manual reviews, not requests to move money. The structures
     * are caller-owned stack values. The functions retain no pointers. */
    UmiFinanceAccountReview account;
    UmiStatus status = UmiFinanceReviewAccount(&ledger, &reserved, &proposed, &account);
    if (status != UMI_STATUS_OK) {
        fprintf(stderr, "Account review: %s\n", umi_status_text(status));
        return 1;
    }
    if (ShowMoney("Available", account.available) ||
        ShowMoney("Remaining after proposed debit", account.remaining_after_payment)) return 1;

    UmiFinanceCashReview cash;
    status = UmiFinanceReviewCash(&ledger, &inflows, &outflows, &buffer, &cash);
    if (status != UMI_STATUS_OK) {
        fprintf(stderr, "Cash forecast: %s\n", umi_status_text(status));
        return 1;
    }
    if (ShowMoney("Net flow", cash.net_flow) || ShowMoney("Projected cash", cash.projected) ||
        ShowMoney("Buffer headroom", cash.buffer_headroom)) return 1;
    /* Independently check the expected minor-unit results, not just OK. */
    if (account.available.minor_units != 90000 ||
        account.remaining_after_payment.minor_units != 65000 ||
        cash.net_flow.minor_units != -15000 || cash.projected.minor_units != 85000 ||
        cash.buffer_headroom.minor_units != 65000 || ledger.minor_units != 100000) return 1;

    /* The filter consumes a presentation snapshot. It does not launch or
     * stop anything. Here the snapshot describes a selected, stopped app. */
    UmiApplicationLaunchChoice choice = {0};
    choice.selected = true;
    choice.state = UMI_APPLICATION_RUNTIME_STOPPED;
    bool visible = false;
    if (UmiDeskApplicationFilterMatches(&choice, UMI_DESK_APPLICATION_FILTER_SELECTED,
        &visible) != UMI_STATUS_OK || !visible) return 1;
    if (UmiDeskApplicationFilterMatches(&choice, UMI_DESK_APPLICATION_FILTER_RUNNING,
        &visible) != UMI_STATUS_OK || visible) return 1;
    puts("Selected app is visible under Selected, hidden under Running.");
    puts("No account, payment, trade, file or application process was changed.");
    return 0;
}

Save the programme as framework/examples/workflow_tools/main.c, or use the supplied file. In a configured Applications checkout, build and run its existing target:

cmake --build --preset windows-ucrt64-all-debug --target umicom-workflow-tools-example --parallel 2
.\build\windows-ucrt64-all-debug\bin\umicom-workflow-tools-example.exe

On Linux, use the matching native preset and executable:

cmake --build --preset linux-all-gtk4-debug --target umicom-workflow-tools-example --parallel 2
./build/linux-all-gtk4-debug/bin/umicom-workflow-tools-example

The example directory also supports find_package(UmicomFramework CONFIG REQUIRED) when building against an installed SDK. Set CMAKE_PREFIX_PATH to that SDK’s installation directory. The target checks its results with ordinary conditions, so the checks remain active in optimised builds.

9. Test the result, not only the click

After switching a source tab, verify the text and selection you left behind. After resetting a ticket, compare existing order identifiers, quantities and statuses. After filtering Desk, verify that no process was started or stopped and that selection is unchanged. For each financial review, compare the result with the explicit arithmetic above, then change an input and check that the previous result is invalidated.

Use Report problem to record a short interaction, add an expected-versus-actual note and export the report. Screenshots are optional and can contain visible private data. Use disposable projects and simulation records, review the exported evidence, and share only what is needed to reproduce the failure.

The review component supplies stable control identifiers such as finance.review.calculate and finance.review.result. An automated GTK fixture uses those IDs to enter values, request Calculate and inspect the result. Keep native keyboard, focus and installed-application checks alongside these toolkit tests.
