Terminal commands with Umicom Framework

A terminal session keeps a folder, an environment and a transcript. A supervised command runs separately from the interface thread, allowing an application to display output and request Stop while the command is working.

Choose the folder

  1. Read the session snapshot to show its current folder.
  2. Ask the user to select an existing absolute folder. Call UmiTerminalSessionChooseDirectory from umicom/terminal/location.h.
  3. Keep the previous folder visible if selection fails. A running or closed session cannot change folders.

This changes the selected session only. It does not change the application's current directory or another terminal. Windows selection accepts ordinary local drive paths. Directory inspection is not a filesystem sandbox and does not grant permission to run a project.

Submit through application policy

  1. Keep execution behind the application's normal command registry and trust checks.
  2. On the owning interface thread, call UmiTerminalControllerArmBackground immediately before dispatching the existing terminal Execute command.
  3. Always call UmiTerminalControllerDisarmBackground after dispatch, including when policy denies the command. Arming changes dispatch mode; it does not grant permission.
  4. Poll with UmiTerminalControllerPollJob from the normal application refresh. The snapshot identifies the originating session even if another tab is selected.
  5. Use UmiTerminalControllerStopJob to request cancellation. Continue polling until pending becomes false.

One controller owns one pending background command. Synchronous callers retain their existing Execute behavior. Direct session clients use the Start, Poll, Stop and Wait functions in umicom/terminal/execution.h.

Read the result

A successful Poll means the snapshot was copied, not that the command succeeded. Inspect the process state and exit code. Pending stays true until completion is published and the supervisor slot is released. History and counters update once, so another refresh cannot duplicate a completed command.

Output is a bounded tail, with an explicit truncation flag. It is not a complete log. Workflows needing a full log should use a dedicated logging service or explicit file output. Display captured text as text, repairing invalid encoding for presentation without treating it as markup or commands.

Ownership and shutdown

The supervisor copies arguments, folder and environment before submission returns. Its worker never borrows a widget or session pointer. Keep the supervisor alive until the job is retired. Stop affects the owned process and its ordinary descendants; it cannot reverse changes already made, and process groups are not a security boundary.

Normal refresh uses Poll, not Wait. When closing a window, request Stop and let refresh observe completion before releasing services. Explicit teardown cancels and waits for a remaining command. Retire the controller before destroying its borrowed manager and supervisor.

Limits

This captures one command at a time. It does not supply interactive standard input, persistent shell state, terminal emulation or full-screen console applications. A directory change inside one command does not alter the next command's session folder. Use explicit folder selection or an external terminal for those workflows.

Keep a delayed choice attached to its terminal

A native folder chooser may finish after the user selects another terminal. Comparing the visible session name alone is insufficient: the user may switch away and return, or close a session and reuse its name.

  1. On the controller's owner thread, call UmiTerminalSelectionCapture from umicom/terminal_ui/selection.h before opening the chooser. Keep the returned value in the request, together with the host's weak lifetime binding and the path field's edit generation.
  2. Use UmiPathPickerGtk4SetInitialLocation to seed a GTK chooser from explicit context. It chooses the initial navigation location without changing the terminal directory.
  3. After native setup and again on completion, first confirm that the original controller and window remain alive. Then call UmiTerminalSelectionValidate. Publish the chosen path only if it returns UMI_STATUS_OK and the original field has not changed.
  4. If validation reports UMI_STATUS_INVALID_STATE, discard that reply and leave the current draft untouched. The user can open a new chooser for the current session.

The value owns no pointers or resources. It is temporary, is not an execution permission and cannot keep the controller alive. Do not store it between application sessions. Controller changes invalidate it conservatively; changes to the directory, state and executed-command count are also checked. Appending transcript text alone does not invalidate it. It is not a lock against concurrent service access.

When publishing native controls, prepare text before notifying widgets, then recheck the weak owner and captured selection after each notification. Keeping a native window object alive does not keep its application runtime attached.
