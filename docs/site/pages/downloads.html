Before installing

Check the platform, processor architecture, release tag, source revision, runtime prerequisites and published checksums. A checksum helps check that bytes match; it does not by itself authenticate their publisher. Review signatures or other release provenance where supplied. Keep earlier installations and user data separate when evaluating an update.

These links lead to release listings, not invented asset filenames. A listing with no suitable asset means you should follow the developer build guide or wait for an appropriate release. The site does not silently substitute a Debug build for a stable installer.

Getting all source repositories

Use git clone --recurse-submodules as shown in Getting started. GitHub's automatic parent source archive does not contain each child repository's contents. Keep the parent lock so the intended Framework/application revisions are traceable.
