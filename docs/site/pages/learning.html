Umicom Framework

Learn Umicom Framework

A connected route from reading your first C program to using shared application services.

Begin with one small task, predict what it should do, then compare the result with that prediction. You do not need to understand the whole Framework before using one service. A service is code with a defined responsibility, such as reading compiler messages or managing editable documents.

A practical learning route

  1. Introduction to Umicom Framework

    Meet applications, shared services, public interfaces and ownership. Follow a compiler message from text to a useful result.

    Start here · No programming knowledge assumed

  2. Introduction to C programming

    Learn source files, functions, variables, strings, pointers and return values by reading the real diagnostic reader.

    Next · Read code before changing it

  3. Introduction to CMake

    Separate configuration, compilation, linking, testing and installation. Learn how an imported target connects an application to its SDK.

    Build tools · Includes exact commands and expected results

  4. Umicom Framework SDK guide

    Use an installed development kit to build an independent C program. Diagnose missing packages and incompatible toolchains.

    Hands-on · Requires a completed compatible SDK installation

  5. Introduction to GTK4

    Understand widgets, signals and the main thread, then follow the existing Notes window through Framework components.

    Native windows · Requires the GTK4 development dependencies

  6. Guide to documents and editing

    Learn the difference between a saved file and an editable working copy. Follow text ownership and Undo.

    Documents · Builds on C and the SDK guide

  7. Guide to project files

    Create files without replacing existing work and inspect a project index. Continue to search, refresh and source navigation.

    Projects · Uses the same services as Studio

    Bring source files, projects, build output and editing into one workspace. Follow the current product prerequisites and documented limits.

    Application workflow · Verify the actual build you use

  9. Read local documentation

    Build an SDK consumer for the same bounded HTML reader used by Studio. Learn paths, byte limits and output ownership.

    Practical example · Uses a local sample page

Keep a useful learning record

  1. Write the question you are testing: for example, “Does changing the sample line from 8 to 12 change the reported line?”
  2. Keep your practice copy separate from the original source and from personal files.
  3. Record the exact command and expected result before running it.
  4. Keep the actual output, including errors. Read the first useful diagnostic before changing unrelated settings.
  5. Explain the result in your own words. Restore the intended sample input and repeat its check.

These pages do not save your answers, progress or personal notes. Keep those locally. The Wiki provides more worked topics and the source map lets you inspect the owning code.
