Umicom Framework

Introduction to C programming

Read a real Umicom program one concept at a time, with no assumed programming experience.

A C program is text that describes a computation. A compiler translates that text into instructions for a processor. You edit the source text; you run the compiled program. This lesson reads examples/build_diagnostics/main.c, a small Umicom program that turns a compiler message into useful fields.

1. Find the starting function

int main(int argc, char **argv)

A function is a named operation. main is where this hosted command-line program starts. int is an integer type: a kind of whole number. The value returned by main tells the calling environment whether the program succeeded. This example uses zero for success and one for failure.

argc tells the program how many command-line arguments it received, including the program name. argv gives access to their text. With no extra argument, the example uses a built-in sample. With one extra argument, it reads that message instead. The braces { and } enclose the instructions in the function.

2. Read the declarations

UmiBuildDiagnostic problem;
UmiStatus status;

A variable names storage for a value. A type tells the compiler which kind of value belongs there. UmiBuildDiagnostic is a Framework structure: a value grouping related fields, such as a filename and line number. UmiStatus represents a result such as success or invalid input. These are declared by Framework headers; they are not built-in C keywords.

A semicolon ends a declaration or many other C statements. A statement is one instruction in the language. The compiler checks the structure of the program before it produces a runnable file. Its error line is a starting clue; sometimes the mistake is on an earlier line.

3. Understand strings and addresses

const char *line = "notes.c:8:5: error: expected a semicolon";

A character is a small unit of text storage. A C string is a sequence of characters ending in a zero character, written '\0'. The double quotes create a string literal. const means this code must not modify the characters through this pointer.

The star in char * declares a pointer: a value referring to a memory location. It is not a copy of the whole string. A pointer may refer to borrowed memory, owned memory or no object at all. Never infer how long it remains valid from its spelling alone.

status = umi_build_parse_diagnostic_line(line, &problem);

The ampersand in &problem obtains the address of the result variable. The parser can place its result there. The function reads the borrowed message during the call. Read the header for what is valid on success and failure; do not use uninitialised result fields after a refused call.

4. Check before using a result

if (status != UMI_STATUS_OK) {
    return 1;
}

if selects instructions only when its condition is true. != means “is not equal to”. Thus the program returns a failure if the parser did not succeed. The equals sign in an assignment stores a value; it is different from the double equals sign ==, which compares values.

After success, problem.file accesses the field named file inside the structure. The dot selects a field from a structure value. The example passes those fields to printf, a standard C output function. Its format placeholders must match the argument types: %s is for a string and %zu is for a size_t value.

5. Connect the header and library

#include makes declarations available to the compiler. It does not install a package or supply compiled function bodies. The build also links the Framework library. Linking joins the compiled program with the implementations it calls. That distinction explains why a missing declaration is a different problem from an undefined function during linking.

Use Introduction to CMake and the SDK guide to build this example. The complete program is included from its actual source file.

Practice with a prediction

  1. Run the unmodified example. Compare its file, line, column and message with the expected output in the guide.
  2. Pass "notes.c:12:3: warning: sample warning" as a quoted argument. Predict the line and column first.
  3. Pass "0 errors and 0 warnings". This is a summary, not a source diagnostic. Expect a refusal rather than invented coordinates.
  4. Explain why spaces in a filename do not mean the filename has ended. Compare this with the parser's test cases before changing its logic.

Use sample text. This exercise does not require editing a real user's file, invoking a compiler on untrusted code or changing the shared parser.

What should I remember before continuing?

A variable stores a typed value. A function performs a named operation. A pointer refers to memory whose lifetime has rules. Check a function's status before using its outputs. Compilation and linking are different stages, and neither alone proves that the program behaves correctly.
