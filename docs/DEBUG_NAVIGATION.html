Following Source and Machine Instructions

Umicom Framework keeps source locations, stack frames and disassembled instructions as separate debugger records. The debug navigation helper connects those records without opening windows or changing source files.

Why the views are separate

A C statement may compile into several machine instructions, and an Assembly source line may describe one or more instructions. The selected stack frame gives the current source context, while the disassembly view identifies the exact instruction.

Capture the current location

UmiDebugWorkbenchNavigationSnapshot location;
UmiStatus status = umi_debug_workbench_navigation_snapshot(platform, &location);

When an instruction is selected, its source association takes precedence. Otherwise the active stack frame supplies the source URI and line.

Follow a source line

status = umi_debug_workbench_navigation_follow_source(
    platform,
    "C:/projects/notes/count_byte.S",
    18U,
    &location);

The helper searches only instructions already present in Framework's disassembly model. It does not ask a compiler to invent a mapping and does not edit a document.

Select an instruction

status = umi_debug_workbench_navigation_select_instruction(
    platform,
    "instruction.4",
    &location);
DAP frame identifier zero is valid. Check has_frame rather than treating a numeric zero as “no frame”.
