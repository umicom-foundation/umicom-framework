Select retained test runs

A test can have records from several executions. A session ID identifies one recorded execution; it is an exact string supplied by the test provider. Use Framework's run catalogue to let a person choose which execution to inspect before showing its text, source locations or export.

  1. Obtain the result and output registries from the test-platform service. Keep all registry access on their owning thread.
  2. Call UmiTestEvidenceRunsCreate with the exact test item ID. The immutable catalogue discovers named sessions from every retained record, including runs that have only output or only results.
  3. Read its summary and iterate UmiTestEvidenceRunsAt. Show counts as records, not as tests passed. IDs are sorted as strings and do not imply a chronological order.
  4. Pass the chosen ID to UmiTestEvidenceRunsCapture. A null or empty ID explicitly means all runs. This checks the original registry identities and revisions before capturing.
  5. Use the same resulting evidence with the text, source-link and CSV services. Destroy the evidence and catalogue when finished.
#include "umicom/test_platform/evidence_runs.h"

UmiTestEvidenceRuns *runs = NULL;
UmiTestEvidence *evidence = NULL;
UmiStatus status = UmiTestEvidenceRunsCreate(results, output, "test.example", &runs);
if (status == UMI_STATUS_OK) {
    /* selected_session_id comes from a catalogue row, or is NULL for all runs. */
    status = UmiTestEvidenceRunsCapture(runs, results, output,
        selected_session_id, &evidence);
}
/* Inspect evidence only when status is OK. */
UmiTestEvidenceDestroy(evidence);
UmiTestEvidenceRunsDestroy(runs);

When evidence changes

INVALID_STATE means the catalogue no longer describes those live registries. Capture a new catalogue and let the person review the refreshed choices. NOT_FOUND means the named run is absent. Keep that choice visibly unavailable instead of silently displaying all runs. Native applications must also check their window and test selection after callbacks; a valid catalogue does not keep an application window alive.

Rows without a session ID appear in the unspecified summary counts and in all-runs evidence. They are never attributed to a named session. Catalogue discovery uses all retained records, but evidence capture retains its existing limits of 32 results and 64 output records. Its summary discloses the matching totals. Neither catalogue counts nor missing results prove a pass; skipped, cancelled, timed-out and not-run outcomes keep their meanings.

Captures are independent copies. Relative source paths still need an explicit working directory; choosing a run does not reconstruct an old filesystem, checkout or working directory. Compare its reported source location with the current project before opening it.
