Linking the editor’s shared components

Build matching libraries, read useful link reports and distinguish a pending decision from a completed operation.

From a source file to a running IDE

A C programme is built in stages. The compiler translates each source file into an object file. A library groups related object files. The linker then joins the programme with the library functions it calls.

Consider Studio’s Close All command. Studio asks Framework to manage the sequence. The document library owns that sequence, the workbench library owns the active selection, and the GTK library connects the operation to the window. All three libraries must match the code making the request.

An undefined reference means a required definition was not found in the objects and libraries selected for the link. A header can describe a function correctly while its library still lacks the implementation. Adding the same declaration again does not supply the missing code.

Find the component that owns the operation

ResponsibilityImplementationLibrary
Capture a group of documents, process decisions, report closing progress.src/document/close_session.cUmicom::document
Clear an absent source from the workbench’s active selection.src/ui/workbench.cUmicom::ui
Connect closing questions, busy state and cancellation to GTK.adapters/gtk4/document_commands_gtk4.cUmicom::ui_gtk4

Studio consumes those owners. It must not add local copies of the missing functions: a second copy could create conflicting state or allow a call to appear successful without doing the required work.

Check the actual libraries

From the configured Applications checkout, build the editor-library check first. It builds the owning libraries and inspects their actual archive files. It runs each time it is requested, even when no source needs rebuilding.

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& "C:\msys64\ucrt64\bin\cmake.exe" --build --preset windows-ucrt64-all-debug --target umicom-editor-native-link-check --parallel 2

The checks use GNU or LLVM nm on the GCC/Clang build. Each listed function must have exactly one externally visible code definition. A similarly named function, an unresolved reference, a private function or a data variable does not satisfy the contract.

The source registration is checked during configuration too. Missing files and missing source-list entries are reported before the application link. The checker does not repair a library itself; restore the owning source and rebuild it.

For a configuration that deliberately excludes GTK, use umicom-editor-core-link-check. The native check requires the actual GTK adapter library. Other toolchains can still use the compiled consumer checks; the explicit archive inspector requires a compatible nm.

Read the local report

The Windows Debug reports are written beneath:

build/windows-ucrt64-all-debug/link-reports/Debug

Each library has a JSON report, the symbol listing and the tool’s diagnostic output. The report contains the exact archive path, its SHA-256 hash, the required-symbol file and its hash, the check time, the outcome and a count for each required function.

Report state or messageWhat to do
passedProceed to the real executable link and application tests. A definition count alone does not test behaviour.
MISSING_SYMBOLCheck that the named function’s complete source is merged and compiled into the reported library.
DUPLICATE_DEFINITIONLook for a duplicate implementation in the archive. Keep one authoritative owner.
NON_CODE_SYMBOLThe name exists, but not as the required externally visible code definition.
TOOL_FAILURERead the saved diagnostic. Check the tool path and its ability to read this archive format.
incompleteThe check did not reach a final result. Run it again and investigate any interruption.

A new run replaces the previous state before inspecting the archive. An old successful report therefore does not become a substitute for the current check. Copy a report elsewhere when it is needed as historical evidence. Reports remain local and are not uploaded automatically; review source/build paths before sharing.

Know when Close All has really finished

A successful step can mean that a question is ready for the user. It does not necessarily mean every document has closed. UmiDocumentCloseProgressValidate() checks a copied summary for consistent counts, phase, status, name termination and Boolean flags. It does not read a document or change the session.

UmiDocumentCloseProgressRequireComplete() answers the different question: has this captured sequence completed? It returns OK only for a valid completed summary. A pending decision returns Invalid state; cancellation and failure retain their original status.

The formatter uses the same validation, as does the GTK progress accessor before publishing a copy. Invalid input leaves the caller’s previous output unchanged. A malformed summary must not replace a useful message or be treated as permission to proceed.

Earlier successful saves and closes remain completed after a later cancellation. Closing releases a document’s Undo history. These progress functions do not undo a completed write, reopen a document or provide crash recovery.

Build and read the Notes example

The complete example below uses sample Notes progress to demonstrate the distinction between a valid observation and a completed sequence. Its real calls also require the document and workbench functions to be present in the selected libraries. It does not close an actual file. The neighbouring close_documents.c example demonstrates real temporary documents and saved-file checks.

& "C:\msys64\ucrt64\bin\cmake.exe" --build --preset windows-ucrt64-all-debug --target umicom-editor-link-check --parallel 2
& ".\build\windows-ucrt64-all-debug\bin\umicom-editor-link-check.exe"
/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/editor_workflow/link_components.c
 * PURPOSE:
 *   Check the public editor libraries without creating a window or touching
 *   source files. Demonstrate that an accepted step is not a completed close.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "umicom/document/close_session.h"
#include "umicom/document/save_session.h"
#include "umicom/ui/workbench.h"
#ifdef UMICOM_CHECK_NATIVE_EDITOR
#include "umicom/ui/gtk4/document_commands.h"
#endif
#include <stdio.h>
#include <string.h>

#define CHECK(condition) do { \
    if (!(condition)) { \
        fprintf(stderr, "%s:%d: %s\n", __FILE__, __LINE__, #condition); \
        return 1; \
    } \
} while (0)

int main(void)
{
    /* A real call creates a link dependency; checking a prototype alone does
     * not establish that the selected static library contains its definition. */
    UmiDocumentCloseSession *session = NULL;
    CHECK(UmiDocumentCloseSessionCreate(NULL, UMI_DOCUMENT_CLOSE_ALL, 0U,
        &session) == UMI_STATUS_INVALID_ARGUMENT);
    CHECK(session == NULL);
    UmiDocumentCloseSessionDestroy(session);
    CHECK(UmiUiWorkbenchClearClosedDocument(NULL, "notes.c") == UMI_STATUS_INVALID_ARGUMENT);

    /* These are sample observations, not a request to close a real document.
     * One Notes document is accounted for, and one still needs a decision. */
    UmiDocumentCloseProgress progress = {0};
    progress.phase = UMI_DOCUMENT_CLOSE_DECISION;
    progress.last_status = UMI_STATUS_OK;
    progress.total = 2U;
    progress.closed = 1U;
    progress.remaining = 1U;
    progress.current.document_id = 7U;
    progress.current.dirty = 1;
    memcpy(progress.current.display_name, "notes.h", sizeof("notes.h"));
    CHECK(UmiDocumentCloseProgressValidate(&progress) == UMI_STATUS_OK);
    CHECK(UmiDocumentCloseProgressRequireComplete(&progress) == UMI_STATUS_INVALID_STATE);
    char message[768];
    CHECK(UmiDocumentCloseProgressFormat(&progress, message, sizeof(message)) == UMI_STATUS_OK);
    puts(message);

    /* Cancellation remains cancellation; it is not converted to completion. */
    progress.phase = UMI_DOCUMENT_CLOSE_CANCELLED;
    progress.last_status = UMI_STATUS_CANCELLED;
    CHECK(UmiDocumentCloseProgressRequireComplete(&progress) == UMI_STATUS_CANCELLED);

    /* A fresh, fully completed observation can authorise a completion label. */
    progress.phase = UMI_DOCUMENT_CLOSE_COMPLETE;
    progress.last_status = UMI_STATUS_OK;
    progress.closed = 2U;
    progress.remaining = 0U;
    CHECK(UmiDocumentCloseProgressRequireComplete(&progress) == UMI_STATUS_OK);
    CHECK(UmiDocumentCloseProgressFormat(&progress, message, sizeof(message)) == UMI_STATUS_OK);
    puts(message);

    /* Retain real link dependencies on the earlier Save All corrections. */
    UmiDocumentSaveProgress save = {0};
    save.phase = UMI_DOCUMENT_SAVE_COMPLETE;
    save.last_status = UMI_STATUS_OK;
    CHECK(UmiDocumentSaveProgressValidate(&save) == UMI_STATUS_OK);
    CHECK(UmiDocumentSaveProgressFormat(&save, message, sizeof(message)) == UMI_STATUS_OK);
#ifdef UMICOM_CHECK_NATIVE_EDITOR
    /* This optional build links the actual GTK adapter library, but does not
     * initialise GTK or simulate a click. Argument checks cannot test a GUI. */
    CHECK(!UmiGtk4AdapterCloseDocumentsBusy(NULL));
    CHECK(!UmiGtk4AdapterDocumentCloseBusy(NULL));
    CHECK(UmiGtk4AdapterCloseDocuments(NULL, UMI_DOCUMENT_CLOSE_ALL, NULL, NULL) == UMI_STATUS_INVALID_ARGUMENT);
    CHECK(UmiGtk4AdapterCancelCloseDocuments(NULL) == UMI_STATUS_INVALID_ARGUMENT);
    UmiDocumentCloseProgress before;
    memcpy(&before, &progress, sizeof(before));
    CHECK(UmiGtk4AdapterCloseDocumentsProgress(NULL, &progress) == UMI_STATUS_INVALID_ARGUMENT);
    CHECK(memcmp(&before, &progress, sizeof(progress)) == 0);
    CHECK(UmiGtk4AdapterDocumentSaveAllProgress(NULL, &save) == UMI_STATUS_INVALID_ARGUMENT);
    puts("Native editor APIs linked; null-argument checks passed.");
#endif
    puts("Editor library calls and completion checks passed.");
    return 0;
}

The caller owns the progress structures and message buffer. The validation, completion and formatting functions borrow their inputs only for the call. No returned text pointer needs freeing. A created close session is different: its caller owns it and must destroy it after use, while its borrowed document coordinator remains alive for all operations.

The optional UMICOM_CHECK_NATIVE_EDITOR build calls the actual GTK adapter’s argument boundaries without initialising a window. Use it to establish library linking separately from the interactive tests.

First, run the Notes example and identify where a pending question is refused as completion. Next, read a real archive report and find the path that was checked. Finally, run the framework.library_link.checker.missing test. It should pass because it confirms that an intentionally missing fixture function is correctly rejected—not because the fixture library is usable.

After the build checks, start Studio with a disposable Notes project. Create two source files, keep one unsaved, cancel Close All at its question, and verify that the unanswered draft is still open. Repeat with Save and Close, then inspect the saved file. These are separate behaviour checks.
