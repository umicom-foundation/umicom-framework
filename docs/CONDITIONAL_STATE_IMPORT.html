Constructing values and reviewing saved state

A value is a record that keeps its data in its own fields. It owns no open file, network connection or external resource. Framework provides checked construction and guarded archive import for selected value types so a failed operation does not erase the last accepted state.

Construct a replacement without losing the old value

  1. Use the type's status-returning initializer and inspect its result. Headers that document construction before replacement support the stronger failure contract.
  2. On success, use the new value. On failure, keep displaying the existing value and explain the returned status. Do not clear the record as an error-handling step.
  3. Inputs may refer to existing inline text fields when the header explicitly permits it. The initializer reads them before replacing the destination.
UmiWsChartSurface chart;
UmiStatus status = umi_ws_chart_surface_init(&chart, "market.chart", "Market");
if (status != UMI_STATUS_OK) return status;

/* The identifier belongs to chart. Construction reads it before publication. */
status = umi_ws_chart_surface_init(&chart, chart.chart_id, "Reviewed market");
if (status != UMI_STATUS_OK) {
    /* chart still contains its previous accepted fields. */
    return status;
}

These initializers allocate temporary heap storage. They can return OUT_OF_MEMORY. This keeps large records off the call stack, but adds allocation cost; it is not a real-time allocation guarantee. Types that own resources require their own lifetime protocol and are not interchangeable with inline values.

Import saved data without overwriting a changed draft

Reading a file and reviewing it can take time. If the displayed draft changes in that interval, importing against the old review would discard work. Typed functions ending in _archive_decode_if_unchanged compare the destination's encoded fields with a snapshot retained by the caller.

  1. Copy the value being reviewed into independent storage. Retain that snapshot until the review finishes.
  2. Read the archive into a separate bounded byte buffer. Do not treat a checksum as proof of a trusted sender.
  3. Serialize access to the destination for the entire import call. For an owner-thread UI, run the final comparison and import on that thread.
  4. Call the matching typed guarded decoder with the archive, expected snapshot and destination.
  5. If it returns INVALID_STATE, retain the current draft and ask the user to review the difference. Do not silently replace the expected snapshot and retry.
  6. After successful import into a draft, use the domain's reviewed publication API to update a live registry or service. Importing data does not authorize a command.
/* reviewed_plan and draft_plan are UmiDataQueryPlan values. */
UmiStatus status = umi_data_query_plan_archive_decode_if_unchanged(
    archive_bytes, archive_size, &reviewed_plan, &draft_plan);
if (status == UMI_STATUS_INVALID_STATE) {
    /* The current draft differs from the reviewed snapshot. Show it for review. */
    return status;
}
if (status != UMI_STATUS_OK) return status;
/* Continue with the query plan owner's normal review and publication workflow. */
What this checks: the complete canonical encoding, including all fields represented by that codec. It ignores struct padding and unused string tails. It validates the imported schema and fields before replacing any destination bytes.

Limits and recovery

  • INVALID_ARGUMENT: check required pointers and domain field validity.
  • INVALID_STATE: the expected and current encoded states differ. Obtain a new review; preserve the current work.
  • PARSE_ERROR or UNAVAILABLE: the archive is damaged or uses another schema. Use the matching supported schema or an explicit migration.
  • OUT_OF_MEMORY: temporary comparison or decoding storage could not be allocated. The destination remains intact; keep it and report the failure.

Comparison temporarily uses at most twice the encoded size. That storage is released before allocating one candidate record. The archive byte limit bounds encoded data; the type defines the candidate's size. Applications may impose smaller import budgets.

This is not a mutex, transaction log, automatic recovery service or historical change detector. A value that changes away and back has the same encoded state. Use an owner's monotonic revision token when history matters. Decoded identities and revisions remain archive evidence; the destination slot and publication policy belong to the caller. No network access, clinical action, payment or order submission is performed.

Text edits and context records

umi_text_replace checks capacity before replacing a fixed text field and supports overlapping input. umi_text_update also advances a separate revision. Existing presentation-copy functions retain their original failure behavior. Choose the function whose documented contract matches the operation.

Context-link reviewed replacement checks identity and expected revision. Text setters reject exhausted revisions, and a void touch operation leaves the record unchanged when its revision cannot advance. Call a status-returning reviewed operation when the caller needs to display a refusal reason.

Run the focused regression checks

From an Applications checkout configured with its all-applications debug preset and BUILD_TESTING enabled, build normally, then run:

cmake --build --preset windows-ucrt64-all-debug --parallel 2
ctest --preset windows-ucrt64-all-debug --output-on-failure --no-tests=error -R "framework.value.(construction|conditional_archive)"
ctest --preset windows-ucrt64-all-debug --output-on-failure --no-tests=error -R "archive-value|workbench_context_link|base_text"

Successful results mean the selected checks passed in that build. They do not replace the full suite or application workflow testing. If a check fails, keep its output with the compiler and dependency versions and inspect the first failing assertion before proceeding.
