Umicom Desk · saved workspaces

Bring your applications
back together

Save a group of applications for a task, see what will happen before opening them, and return to a familiar set without repeating every selection.

Some work needs more than one application. You might keep Umicom Bank beside Umicom Accountant while exploring a practice payment and its accounting records. Desk can remember that pair as Finance work. Later, you can review the pair and ask Desk to open it again.

Select applications→Save the set→Preview→Confirm

This lesson uses two kinds of saved set. A group remembers applications you selected. A session remembers applications that Desk currently knows are running. Neither one is a copy of the applications themselves.

Save your documents separately. These saved sets contain application identifiers. They do not contain open documents, unsaved editor text, window positions, account balances, passwords or instructions to make a payment or trade. Each application keeps responsibility for its own work.

Before starting, use an installation containing the Desk workspace controls described below. For this exercise, choose applications configured for practice rather than live financial connections.

No automatic launch on reloadReview before openingWorks with existing Desk controls

1Open workspace storage

Open Umicom Desk in the usual way. The existing launcher, application taskbar, layouts and context controls remain available. Find the collapsed section labelled Workspaces and session restore and open it.

At first, the section says that workspace storage is closed. Expanding it only reveals the controls; it does not create a database or start another application.

Choose Open / reload saved workspaces. Desk now opens its workspace store in your user-data area. A database is simply the organised file used to keep the saved entries between runs. The full path appears in the section, so you can see which file is being used.

What you should see: the editing controls become available. A new store has no saved workspaces. Opening an existing store lists its previous entries, but does not launch them.

The word reload matters when storage is already open. Choosing the same button again reads the latest saved entries. It also cancels any old preview so you cannot accidentally confirm a review made against older information.

2Save an application group

Use Desk’s existing application picker to select Umicom Bank and Umicom Accountant. Select the applications without launching the selection yet. The new group command reads this same selection; it does not maintain another competing picker.

In the workspace section, put finance in Saved ID and Finance work in Display name. The ID is the short reference used to find this saved entry. The display name is the readable label you see in the list.

Choose Save selected as group. Now select the new group in the saved-workspace list.

What you should see: a group named Finance work, with ID finance, containing two applications. Saving the group has not started or stopped either application.

Choose names that tell you what the set is for

Useful IDs include finance, coding-practice and market-review. Begin with a letter or number. Later characters may also include a dot, underscore or hyphen. Keep spaces in the display name rather than the ID.

Saving another group with the same ID replaces that group’s saved selection. It does not create an additional copy. A group and a session may share an ID because their kinds are different; the list clearly says which kind you are selecting.

A small experiment: change the selected applications, save the same group again, and inspect its count. You have changed a saved recipe for opening applications, not the contents of those applications.

3Read the preview

Select Finance work, then choose Preview saved workspace. A preview is a proposed set of requests. It is not an execution log.

Read each application’s name and identifier. Next to it, Desk explains the intended action. The exact result depends on what is installed, enabled and currently running in your installation.

Proposed actionWhat it means
StartAsk the existing Desk launcher to open the application.
ActivateAsk the existing host to bring forward the application it already tracks as running, rather than start a duplicate.
SkipDo not request this application. Read the reason: it may be missing, disabled, incompatible, in transition, unknown, or Desk itself.

For example, a review may propose starting Bank and activating Accountant. That is an illustration, not an expected result for every computer. Your preview should reflect your current application state.

Pause here: no application has been started or switched by the preview.

Choose Cancel preview to stop without changing any application. Changing the saved selection or editing the input fields also disables confirmation of the old preview. Make another preview after changing your choice.

4Confirm and check the result

When the preview describes the applications you intend to open, choose Confirm reviewed requests. Desk checks the saved data and relevant application state again before dispatching the requests.

A review can be used only once. This prevents a second click from replaying the same requests. To try again, make a fresh preview first.

The result lists accepted, failed and skipped requests. Read the individual results as well as the totals. One application’s failure does not hide the outcomes for the others.

Accepted is not the same as ready. An accepted request means the existing launcher accepted it. A window may still be starting, or the application may encounter a later startup problem. Check Desk’s taskbar and the application itself before continuing your work.

An activation request can also fail when the current host cannot bring that window forward. Desk must report that limitation rather than claim that focus changed.

If an application or the saved set changed since the preview, you may be asked to reload or preview again. That is useful protection: the action you reviewed should not silently become a different action.

5Capture a running session

Once your practice applications are open and visible in Desk’s tracked application state, enter afternoon as Saved ID and Afternoon practice as Display name.

Choose Capture running session. This saves the identifiers of the applications Desk currently observes as running, excluding Desk itself and applications still starting or stopping.

What you should see: a new entry labelled as a session. Inspect its application count rather than assuming every program on your computer was captured.

A program opened independently may not be part of Desk’s tracked runtime. This command is not an operating-system-wide search for every window. Its source is the existing Umicom runtime catalogue.

When no eligible running applications are tracked, Desk reports that there is no running set to save. It does not invent an empty successful session.

6Restore the set later

Save any documents in their own applications. At your next Desk session, expand Workspaces and session restore and choose Open / reload saved workspaces.

Select Afternoon practice in the saved list. Choose Preview saved workspace, inspect every proposed action, then confirm the reviewed requests.

The saved session supplies application IDs. The current runtime supplies the facts about those applications now. Old process identifiers and old running flags are not restored from disk. An application that is no longer installed remains explained in the review rather than being silently replaced by another executable.

To remove an entry you no longer need, select it and choose Remove saved entry. This removes that saved set only. It is not a command to close the listed applications or delete their documents.

Application-set restoration has a deliberate boundary. It does not yet restore document tabs, screen geometry, shared business context or each application’s internal session. Use the application’s own recovery and save tools for those tasks.

7Use a short Umicom link

A short link is another way to describe what you want Desk to review. In the Umicom link field, enter:

umicom://group/finance

Choose Preview link. You should see the same group reviewed through the same rules. The link itself does not bypass confirmation.

ExampleTarget
umicom://app/org.umicom.bankOne registered application.
umicom://group/financeThe saved group with ID finance.
umicom://session/afternoonThe saved session with ID afternoon.

Paste these links into Desk’s field. This implementation does not register umicom: as a system-wide browser protocol. It also does not accept file paths, web addresses, query parameters, encoded IDs or commands to submit business operations.

Try entering https://example.com and choosing Preview link. Desk should reject it as an invalid input, not open a browser. Then restore the group link and make a new preview.

8Understand Desk activity

Open Recent Desk activity (this run only). It shows local observations of changes in tracked application state, together with request receipts from this workspace section. New entries appear first.

The first observation establishes a starting point. It does not pretend that every application has just launched. Unchanged observations are not added repeatedly to fill the list.

Choose Mark activity read after reviewing the entries. This acknowledges the local list; it does not repair a failed application or change a payment’s status.

The list retains up to 64 entries. When older entries are omitted, the view shows that fact. The activity list is not persisted between runs and is not a business audit journal, a notification feed from every application, or an operating-system notification centre.

9Read signed money correctly

Money displays need to preserve both the decimal position and the sign. A small negative balance must not lose its minus sign simply because its whole-number part is zero.

Umicom’s canonical money record keeps an integer amount and a scale. The scale says how many digits go after the decimal point. An integer of 125 with scale 2 is displayed as 1.25.

Stored integerScaleDisplay
1252GBP 1.25
−12GBP -0.01
−1012GBP -1.01
120053GBP 12.005
02GBP 0.00

The shared UmiMoneyTextFormat function now supplies Bank’s money cells. It places the sign and decimal point using the integer’s digits. It does not convert the amount to floating point, change its scale or apply rounding.

A first look at the C interface

This fragment shows the formatter’s use inside a function. The complete header and implementation are part of Framework.

#include "umicom/finance/money_text.h"

UmiMoney balance = {
    .minor_units = -1,
    .scale = 2,
    .currency = { .code = "GBP" }
};
char text[UMI_MONEY_TEXT_CAPACITY];

UmiStatus status = UmiMoneyTextFormat(
    &balance, text, sizeof text, NULL);

/* On UMI_STATUS_OK, text contains "GBP -0.01". */

balance holds the input. text reserves space for the result. The ampersand in &balance passes the record’s address so the function can read it. sizeof text tells the function the actual output capacity. The returned status tells the caller whether a complete value was produced.

An output buffer that is too small is rejected without leaving a shortened monetary value. The formatter supports the whole public scale field, from 0 to 255. That is a formatting capability, not a claim that every currency or business operation permits every scale.

How Framework connects the parts

The reusable service is called UmiDeskFederation. It owns saved groups, session sets, previews and local activity. The existing Desk runtime still owns application discovery, launch policy, tracked processes and activation.

A small connection layer, UmiDeskFederationRuntimePorts, copies observations from that runtime and sends confirmed requests back to it. This avoids a second process launcher with different rules.

GTK supplies the visible controls. Its adapter translates clicks into Framework calls and renders copied results. The thin Desk application attaches the section to its existing window and invalidates its callbacks before releasing the runtime.

Click in Desk→Framework review→Existing launcher→Application

The Data Server is the only database authority used by the new service. A transaction keeps a save or removal together. If a write fails, the service attempts to roll back the storage changes rather than claim that a partial set was saved.

A revision is a number describing a saved version. Checking it prevents an older in-memory copy from overwriting a newer saved version without notice. Framework also validates the complete stored set, including its member IDs, before using it. This is error detection, not encryption or proof against an attacker who controls the local account.

The current limits are 24 saved groups and sessions combined, up to 64 applications in each set, and 64 local activity entries. Saved IDs have at most 63 ASCII characters. Display names have at most 191 UTF-8 bytes; some written characters require more than one byte.

When something is different

The workspace section is missing

Check that the updated Framework files and Desk integration were merged and that umicom-desk was rebuilt successfully. This lesson describes the new section, not an older installed executable.

The group is empty or will not save

Select applications in the existing Desk picker before choosing Save selected as group. An empty selection is not saved. Check the ID and display name too.

An application is skipped

Read its reason in the preview. Check installation and enabled state using the existing Desk controls. Do not alter the saved database to mark an application as installed; saved sets are not installation evidence.

The review expired or reports a change

Reload saved workspaces when storage changed, then make another preview. An application may also have started, exited or changed state since the first review. Review the new actions before confirming.

Some requests succeeded and another failed

Keep the per-application results in view. The accepted requests are not automatically undone. Make a fresh preview for the next attempt; applications now tracked as running should be reviewed for activation rather than an assumed duplicate start.

SQLite or saved data is unavailable

Check the displayed storage path and the reported failure. There is no silent memory-only substitute for persistent workspace storage. Invalid saved data is not overwritten as a recovery shortcut. Close Desk and keep a copy of the affected file for investigation before attempting repairs.

A captured session does not restore document tabs

That is outside this application-set feature. Restore documents using each application’s own saved session or recovery tools. Keep document saving separate from capturing a Desk session.

Try it yourself

Make a group called coding-practice containing Studio and one other installed practice application. Preview it, cancel the preview, and check that cancellation did not open either application. Preview again and confirm only the requests you intend.

When Desk tracks the applications as running, capture a session named lesson-end. Reload the saved entries and review that session without confirming it. Explain why the saved session can stay the same while the proposed actions change.

Check your explanation

The saved session contains stable application IDs. The current runtime supplies installation and running state. The same saved list can therefore propose Start at one time, Activate at another, or Skip when an application is unavailable. Saving the list does not freeze the computer’s live state.

Finally, predict the display for an integer amount of -5 at scale 2. It should be GBP -0.05: the sign belongs to the entire value, including a value smaller than one pound.

You have now saved a useful application set, reviewed its effects, understood the limits of session capture, and followed the same information from a desktop control into a reusable C interface.
