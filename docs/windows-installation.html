Before you start

The Windows distribution contains Umicom-Setup.exe. This is the installer: it copies the selected applications and their shared runtime into the destination you choose. The runtime includes the supporting libraries and resource files that the applications need when they start.

You do not install GTK, GLib, MSYS2 or a compiler just to open a correctly prepared Umicom package. Building software inside Umicom Studio IDE is a different task: a development project may need its own compiler, debugger or SDK.

Current installation scope. This setup installs 64-bit Windows applications for your current Windows user account. It accepts a new or empty folder on a local drive that you can write to. It does not request administrator privileges or change your system PATH.

Obtain the package from a trusted distributor. Check its publisher and any supplied checksum before opening it. Public releases should be signed by their distributor. An unsigned development build may produce a Windows security warning; do not disable Windows security protections to install an unknown package.

Keep your projects, financial records and other personal documents outside the application installation folder. For example, application software could live in D:\Umicom, while project files live in Documents\Umicom Projects.

Using the setup application

Step 1
Open the installer

Double-click Umicom-Setup.exe in File Explorer. Read the welcome page and continue to the licence page. The installer itself uses native Windows controls and does not need the GTK runtime that it is about to install.

Step 2
Choose the applications

The components page lists the graphical applications included in this particular package. Tick the applications you need. For example, a package may include Umicom Studio IDE, Umicom Trader, Umicom Bank and Umicom Desk.

Select Install all applications in the installation-type list to select every application included in that package. Change individual checkboxes to make a custom selection. At least one application must remain selected.

“All” means all applications included in the package, not every product ever proposed for Umicom. A product that was not enabled and built when the package was prepared is not offered as an installable application. This prevents a checkbox from promising software that the package does not contain.

The shared runtime is required and is selected automatically. You do not need to identify or select individual DLL files. Required command-line helper programs, when included by the distributor, are installed with the runtime rather than appearing as separate desktop applications.

Step 3
Choose the destination

Use the destination page to type a folder path or choose one with the browse control. The default is the Programs\Umicom directory inside your Windows account’s local application-data folder. A writable local path such as D:\Umicom is another example.

Choose a new or empty directory. Setup refuses to overwrite a directory containing existing files. It also rejects drive roots, network locations, a destination that is a file, and a destination that is itself a junction or symbolic link. An unusually long destination can be rejected so that the complete installed paths remain within the installer’s supported path limit.

A location such as C:\Program Files normally needs permissions beyond an ordinary user installation. Choose a location your current account can write to instead. This installer does not automatically elevate itself.

Step 4
Choose the shortcuts

The Application shortcuts page has two independent options:

OptionWhat it doesDefault
Create desktop shortcutsAdds a desktop shortcut for each selected application.Off
Add applications to the Windows Start menuAdds the selected applications under Umicom Applications in your Start menu.On

Neither option changes your PATH. Existing shortcuts with the same names are not silently replaced. Setup reports a warning when a requested shortcut could not be created or already existed; the installed executable can still be opened from the installation folder.

Step 5
Install and finish

Start installation and allow the progress page to finish. Setup copies the shared runtime and the selected applications, records the files it owns, creates the requested shortcuts, and registers an uninstaller with Windows.

Read any error shown on the progress page. Do not treat a failed or cancelled installation as complete. Setup attempts to remove files written by an interrupted installation. If a file cannot be removed, it retains the installation receipt and provides instructions for completing cleanup.

Opening an installed application

Open the Start menu, find Umicom Applications, and select the application. A desktop shortcut works in the same way. No terminal command is needed.

When shortcuts were not selected, open the installation’s bin folder in File Explorer and double-click the executable. For Studio, the executable is umicom-studio-ide.exe.

D:\Umicom\
  bin\
    umicom-studio-ide.exe
    ...other selected executables and runtime DLLs...
  lib\
    ...runtime modules...
  share\
    ...icons, schemas, licences and Framework resources...
  installation.ini
  Uninstall-Umicom.exe

This is one application installation, even though it contains multiple files. Do not move just the executable to your desktop. A shortcut points to the executable without separating it from its runtime. Do not edit installation.ini; it is the ownership receipt used by setup and the uninstaller.

Using the portable package

A distributor may also provide Umicom-Portable.zip. Extract the entire archive into a new folder, open its bin directory, and double-click an application.

The portable package contains every application chosen by the distributor at build time. It does not show the installer’s component-selection pages, create shortcuts, or register an uninstaller. To relocate it, close the applications and move the entire extracted folder, including bin, lib and share.

Do not run an executable from inside an archive preview. Windows may extract only that executable, leaving its supporting DLLs and resources behind.

Uninstalling or replacing an installation

Close all running Umicom applications. In Windows Settings, open Apps → Installed apps, find Umicom Applications, and choose Uninstall. The exact Settings labels can differ between Windows releases. You can also open Uninstall-Umicom.exe in the installation folder.

The uninstaller uses the receipt to remove the application files and shortcuts it owns. It does not recursively erase an arbitrary destination folder. Unrecognised extra files can cause the folder to remain after uninstalling. Keep your own documents elsewhere nevertheless: an installed application file that you manually replace is still part of the package’s ownership list.

If Windows reports files still in use, close the applications and run the uninstaller again. The receipt is retained when removal cannot be completed.

Replacing a release or changing the installed selection. This implementation supports a fresh installation, not in-place upgrades, repair, or “add/remove components” maintenance. Uninstall the existing registered installation first, then run the new package and choose the applications again. Back up any personal files before changing an installation.

Understanding common problems

A DLL is missing

An error naming a file such as libglib-2.0-0.dll means Windows could not load a required runtime library. Confirm that you extracted or installed the complete package and did not copy only the executable. Reinstall a complete package from its trusted distributor. Do not download individual DLLs from unrelated DLL-download sites.

The private runtime could not be prepared

This message comes from Umicom’s resource bootstrap rather than the Windows DLL loader. Check that the installation still contains its share and lib directories and that your Windows temporary folder is writable. The bootstrap uses a temporary, process-specific image-loader cache; it does not need to write into the installed application directory.

The folder is not empty

Choose a different new folder. Do not remove unfamiliar files simply to make an installation proceed. An existing registered Umicom installation should be removed through its uninstaller before installing another release.

An application is absent from the list

It was not included as an enabled graphical application in that package. Ask the distributor for a package containing that application. Selecting “Install all applications” does not download additional products.

A development build works only from a terminal

This is a packaging problem for the developer to correct. A release should not depend on the developer’s MSYS2 PATH. The shared deployment build target described below prepares the runtime before the application is distributed.

For application developers

Framework’s umicom_apply_application_branding integration registers locally built Windows executable targets with the shared deployment module. The module prepares private DLLs and resources, creates an application catalogue, and supplies the umicom-windows-runtime and umicom-windows-installer build targets.

The installer is generated with NSIS on the build machine. NSIS is not an end-user prerequisite. Application modules supply their identity and existing executable target; they do not maintain separate runtime-copying scripts or installer implementations.

See docs/windows-deployment-development.md in the Framework source for configuration commands, extension points, focused tests and the clean-Windows release checklist. A successful portable contract test is not a substitute for running the actual installer and applications on Windows without a development environment.
