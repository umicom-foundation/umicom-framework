Saving and reviewing workspace values

A saved value describes state. It does not own a window, start a process or authorize a trade. Framework separates reading saved bytes from applying a reviewed change so applications can keep a usable workspace when data is damaged or no longer supported.

Choose the appropriate contract

NeedUse
A supported individual recordIts public _archive_encode and _archive_decode functions. Check the record header: records with resource pointers are not automatically serializable.
A product's layout identity, ordered active panel IDs and lock stateThe application session functions in umicom/application/runtime/session_snapshot.h.
Native window placement and named layout recoveryThe existing workspace checkpoint and workspace library checkpoint services. A session archive does not replace these layout stores.
Documents, processes, debugger sessions or broker connectionsThe relevant live owner and its separate recovery policy. A passive archive cannot recreate these resources.

Transfer an individual value

  1. Initialize and configure the value through its normal public API. Fixed text fields must contain a terminator within their declared capacity.
  2. Call its encoder with NULL bytes and zero capacity. The returned size tells you how much caller-owned storage to allocate.
  3. Encode into that buffer. A short buffer reports UMI_STATUS_CAPACITY_EXCEEDED and the required size without partially writing the archive.
  4. Decode into a separate candidate. Decoding checks the envelope, schema, field bounds and domain validator before replacing the candidate.
  5. Review the candidate and use the live owner's normal mutation API to apply it. A saved revision is descriptive data; it cannot grant permission to overwrite a newer owner.
  6. Release your byte buffer when the transfer is complete. The record codecs themselves do not allocate, read files or open a database.
#include "umicom/context_channel/workspace.h"
#include <stdlib.h>

/* Assume current was configured through the workspace context API. */
size_t byte_count = 0;
UmiStatus status = umi_workspace_context_archive_encode(
    &current, NULL, 0, &byte_count);
if (status != UMI_STATUS_OK) return status;
unsigned char *bytes = malloc(byte_count);
if (bytes == NULL) return UMI_STATUS_OUT_OF_MEMORY;
status = umi_workspace_context_archive_encode(
    &current, bytes, byte_count, &byte_count);
UmiWorkspaceContext candidate;
if (status == UMI_STATUS_OK)
    status = umi_workspace_context_archive_decode(bytes, byte_count, &candidate);
free(bytes);
/* Use candidate only after a successful decode and an explicit review. */

Keep IDE records separate from running tools

Debugger views, editor intelligence, project profiles, test results, terminal bindings and reactive UI values expose the same record archive contract. Nested fields are written individually. Structure sizes are reconstructed for the receiving host, and unused text is omitted.

  1. Capture the value supplied by its Framework owner. For example, save a breakpoint description or a test result after its normal validator accepts it.
  2. Decode it into a candidate and show its identities, source locations and recorded results. The decoder preserves the existing domain validator's rules; it does not prove that an external file or process still exists.
  3. Resolve current project paths, tools and permissions through the live service before applying any request. Restoring a breakpoint description does not install a debugger breakpoint, and reading a build profile does not run a build.

The reactive UI records describe bindings and state. Their archive does not start an expression evaluator or reconnect listeners. A host must decide which reviewed records belong to its current workspace.

Review an application session

  1. Capture the current session with umi_application_session_archive_capture. Keep the session's current revision separately as the review's observation token.
  2. Preview the bytes with umi_application_session_archive_preview and the intended product's immutable experience catalogue. Unknown layouts, unknown panels, duplicate panels and another product's identity are refused.
  3. Show the candidate's layout and panel IDs to the user. Keep the current session and any live windows available while review is pending.
  4. On confirmation, call umi_application_session_archive_apply with the observed revision. If the session changed, the call returns UMI_STATUS_INVALID_STATE; capture a fresh observation and review again.
  5. On success, the session receives a new local revision. The archive's counter is never installed as the authority for that update.

Run these calls on the owner thread or protect them with the owner's synchronization. The revision check does not make unsynchronized C memory access safe. A GUI host must prepare its presentation before publishing a session replacement; these functions change a session value only.

Restored sessions borrow strings from the supplied catalogue. That catalogue must outlive the session. Archive and snapshot buffers can be released after a successful preview or restore.

Understand refusal and storage limits

  • Invalid argument: check initialization, fixed text termination, counts and the domain's required fields.
  • Parse error: keep the original bytes for diagnosis. A truncated or damaged archive does not partly change the destination.
  • Unavailable: the schema or numeric representation is unsupported. Use an explicit migration; do not bypass the schema check.
  • Permission denied: unlock the current layout explicitly before importing a session. Unlocking changes its revision, so review the current state again.
  • Not found: the product catalogue no longer contains a saved layout or panel. Ask the user to choose a supported replacement.
  • Capacity exceeded: allocate the measured byte size, or begin a new owner lifecycle if its revision counter is exhausted.

The envelope is limited to 16 MiB, and individual codecs enforce smaller bounds derived from their fields. A storage adapter may have a much smaller limit; the codec does not change it. Use the established storage service for durability and transactional publication.

The checksum detects accidental corruption. It provides neither authentication nor encryption. Store archives with the same access controls as their contents, and continue enforcing the live owner's permission and capability rules.

Extend a record safely

  1. Add the field to its public contract without removing existing headers, comments or API declarations.
  2. Include each new fixed text array in bounded validation before any string comparison or lookup.
  3. Extend the explicit writer, reader and size bound. Never serialize an entire C struct: padding and unused text are not part of a portable format.
  4. Change the schema identity and provide a deliberate migration if previously saved data must remain readable.
  5. Extend the existing domain fixture's field comparator and malformed-field checks. Confirm that damaged later fields leave the destination unchanged.
  6. Keep the implementation in its owning Framework library and update that library's archive symbol manifest.
