Review whitespace changes

Whitespace is part of your source. A tab can be significant in a Makefile, and trailing spaces can create a Markdown line break. These commands prepare a comparison; they do not run automatically when you save.

  1. Open a writable source document. Select a range if you want to work on selected lines. An empty selection means the current line for a selected-lines command.
  2. Choose a whitespace command in your application's editor tools. Trim removes only trailing ASCII spaces and tabs. Expand replaces leading tabs with spaces. Compact uses tabs for complete indentation stops and spaces for the remainder.
  3. Read both complete source panes. Conversion uses the named document's tab width, captured when the review opens. It leaves line endings, Unicode text and spaces inside each line unchanged.
  4. Choose Apply reviewed draft once. Undo restores the previous draft. Save is a separate action with the normal file-conflict checks.

When a review cannot apply

If the source changed, close the comparison and prepare a new one. Switching tabs or moving the caret does not redirect the captured edit. Closing the target, replacing its view or changing its save state can invalidate the review. Read-only documents cannot be changed.

Framework integration

Use UmiDocumentWhitespaceReviewCreate, inspect its summary and full texts, and call UmiDocumentWhitespaceReviewApply only after approval. Keep the original coordinator alive on its owner thread. Destroy the review after use. Native hosts can use UmiGtk4AdapterReviewWhitespaceCommand with IDs from the shared catalogue.

Input and output are limited to eight MiB. The pure planner accepts a cancellation token; native review preparation is synchronous and bounded. These are character-level operations, not a language-aware formatter. Compaction maps a caret inside a new tab to the preceding representable byte boundary.
