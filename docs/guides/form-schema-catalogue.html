Reading historical form versions

A saved form records the identifier and version of its schema. A catalogue keeps the trusted definitions that your application supports. Exact version selection prevents an old value from acquiring a new meaning after fields or units change.

Create a trusted catalogue

  1. Define each supported schema in application-owned immutable C data. Preserve old definitions while their records remain readable.
  2. Pass their pointers to umi_structured_form_catalogue_create. The catalogue copies and sorts the pointers. Duplicate identifier/version pairs are rejected, even if the descriptions appear similar. It accepts up to UMI_FORM_CATALOGUE_CAPACITY entries.
  3. Keep every descriptor, field array, option, rule and string alive and immutable until all catalogue readers and returned schema users have finished. The original pointer array may be released after creation.
  4. Use umi_structured_form_catalogue_find for an exact version or umi_structured_form_catalogue_at to list entries in deterministic identifier/version order.

Decode a snapshot

Link with Umicom::application and include umicom/application/experience/structured_form_catalogue.h. Call umi_structured_form_catalogue_decode with the snapshot bytes and a heap-allocated UmiStructuredFormResolved. It reads a bounded identity hint, finds the exact trusted schema and then validates the whole snapshot before returning either values or the schema pointer.

The low-level umi_structured_form_snapshot_identity function only reads a header. A successful header read does not prove that the remaining body is valid. Do not render answers or perform operations based on that hint alone. The catalogue never loads code, downloads a schema or opens a filename supplied by a record.

Read stored history

  1. Link with Umicom::form_records and include umicom/data/structured_form_reader.h.
  2. Call umi_structured_form_reader_load with a record identifier and historical revision. Revision zero selects the current head.
  3. The reader checks stored metadata and the document digest before decoding. Its result contains the stored revision, the original schema and a form marked saved at its own edit revision. Allocate this large result on the heap.
  4. When opening a current row selected from the record catalogue, use umi_structured_form_reader_open_reviewed. A changed head refuses the selection instead of displaying a different version silently.

Expected results and recovery

NOT_FOUND can mean a missing record or an unsupported schema identity/version. Preserve the original bytes and add the appropriate trusted historical definition before retrying. Never retry with the latest schema simply because the original is missing. PARSE_ERROR or INVALID_STATE can indicate malformed data, a digest mismatch, incompatible fields or a stale selected row. Reload the catalogue after a stale selection and investigate corrupt records without overwriting them.

umi_structured_form_catalogue_latest can suggest an upgrade destination. It does not change any stored data. Use the separate reviewed upgrade workflow when the reviewer explicitly chooses to create a new revision. The historical reader itself never migrates.

Catalogue trust is established by your application. These services do not authenticate users or grant access to records.
