Search typed record answers

A metadata catalogue searches record identifiers and amendment descriptions. A typed query also reads verified form answers, using their registered original schema. This lets a host find numeric values, plain text and explicit missing-answer states without interpreting raw stored bytes.

Build a filter

  1. Select one immutable schema and create a zero-initialized UmiStructuredFormFilter.
  2. Add up to eight terms, using the exact field identifiers. All terms must match.
  3. For a value term, set the operand to Known and supply the same value type and unit as the schema. Numeric comparisons never convert units or coerce integers to floating point. For example, compare count.items with count.items.
  4. Use State to select Unanswered, Known, Unknown or Not applicable. A State operand has no value, unit or reason. Unknown and Not applicable remain distinct.
  5. Validate the filter with umi_structured_form_filter_validate. Use umi_structured_form_filter_match for an in-memory draft.

Equal operands must satisfy the field's value rules. Ordered numeric thresholds may lie outside the field's allowed range. Contains searches plain text using case-sensitive bytes; it does not search translated choice labels or interpret calendar strings. Missing answers never satisfy a value comparison. A malformed later term is still rejected when an earlier term does not match.

Search saved records

  1. Authorize the selected Data Server in the host. Register trusted immutable schema versions in a UmiStructuredFormCatalogue.
  2. Create UmiStructuredFormQuery with a nonempty entity namespace, exact form ID/version, filter and a page limit from 1 to 16. Leave cursor and expected snapshot empty for the first request.
  3. Call umi_structured_form_query_page on a storage worker. It returns exact reviewed record metadata, matching counts and a query snapshot.
  4. If next_after_entity is nonempty, copy it and the snapshot into the next request. Keep namespace, metadata text, schema and filter unchanged. A changed source or query refuses continuation; restart explicitly.
  5. Open a selected row through umi_structured_form_reader_open_reviewed. If it changed after search, the open refuses the stale row instead of replacing a draft with newer data.

Limits and failure recovery

Search validates every metadata-selected record with its original registered schema. Known alternative schemas are excluded from answer matches. Unknown schemas, metadata-only rows and damaged selected payloads fail the request; they are not silently hidden. Narrow the namespace to typed records and register the historical schemas you support. Metadata filtering excludes nonselected payloads from inspection but does not authorize access.

The implementation composes bounded reads and rechecks the namespace head snapshot after inspecting answers. It does not hold one long database transaction, retry concurrent edits or provide an indexed database engine. The catalogue permits at most 256 heads and 32,768 storage rows per scan. Exceeding a bound fails rather than returning truncated success. The digest binds a query under the record append contract; it does not authenticate storage against arbitrary replacement.

SDK example

Link Umicom::application for portable filtering or Umicom::form_records for persisted search. The installed examples/data_history/form_search.c uses a fictional inventory and demonstrates two pages of quantity results. It uses only public SDK headers and owns its in-memory store.
