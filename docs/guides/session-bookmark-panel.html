Review session bookmarks

A bookmark records a location in an open source document. It does not copy or save the document.

  1. Open a source document and place the cursor on a useful line.
  2. Use the editor's Toggle Bookmark control. One marker is kept per document line.
  3. Open Bookmarks in Studio's View or window catalogue.
  4. Choose Refresh bookmarks after adding or removing markers elsewhere.
  5. Select a location to return to its document. The editor becomes visible and unsaved text stays intact.
  6. Choose Remove marker to forget that location. This never deletes a file or closes a tab.

Closed documents and changed lines

Closed markers stay visible but their location buttons are disabled. Reopening the same filename creates a new document identity, so an older marker does not jump into it. Remove the old marker and add a new one.

Locations are fixed line numbers and UTF-8 byte columns. They do not follow edits. A removed line refuses navigation; an overly long column clamps to the current line end. Refreshing does not repair an obsolete location.

Embedding in another application

Bind a document coordinator to the existing GTK4 adapter, then call UmiGtk4BookmarkPanelCreate. Parent the returned owned widget under that adapter's window and release your reference. The panel observes the binding's lifetime; it does not own the coordinator. A successful visit callback can reveal the application's editor. Call UmiGtk4BookmarkPanelRefresh when your host needs an updated list.

Selection and removal use the displayed bookmark revision. Busy or stale decisions are refused. Unbinding the adapter makes retained controls inactive. Bookmarks are session-only and are not restored when the application restarts.

Troubleshooting

If an action is refused, finish the active save or close decision and refresh. If a marker's line was removed, delete that marker and create one at the desired current location. Source text and undo history are not modified by these actions.
