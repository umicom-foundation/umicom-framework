Remember a private project board

A project binding remembers where you chose to keep a Kanban board. It contains the project path, the board folder and its filename. The board itself remains a separate document with its existing save, conflict and close rules.

Use it in Studio

  1. Open a project, then run project.board from the command search. A project board window opens.
  2. Choose an existing private folder and enter a filename ending in .umikb. Use Remember entered location while no board is open.
  3. Wait for “Private project location remembered”. This saves the location only. Use Create board or Open board separately.
  4. On a later visit, choose Recall saved location. Review the filled folder and filename, then choose Open board.
  5. Save and close the board before changing its remembered location. Closing a window with unsaved cards still requires the existing save or discard decision.

Embed the shared controls

Applications link Umicom::kanban_gtk4. Create a project window, then enable location controls using an existing private settings directory:

#include <umicom/ui/gtk4/kanban_binding.h>
GtkWindow *board = NULL;
UmiStatus status = UmiKanbanGtk4CreateProjectWindow(app, project_root, &board);
if (status == UMI_STATUS_OK)
    status = UmiKanbanGtk4EnableProjectStorage(board, private_settings_directory);
/* Handle status before presenting the window. */

The native adapter copies paths into a worker request. It does not let a worker use GTK widgets. A removed window cannot apply recalled fields. If the user edits either field during loading, recall refuses to overwrite that edit. Applications may instead use UmiKanbanGtk4EnableProjectStorageForApplication to resolve their normal configuration folder; the host remains responsible for creating that folder.

Use the C service without GTK

Link Umicom::kanban_storage and include umicom/kanban/binding_storage.h. Create a binding with UmiKanbanProjectBindingCreate, then call UmiKanbanBindingStorageSave or UmiKanbanBindingStorageLoad. Supply an existing absolute settings folder. These calls may block, so interactive hosts should run them on a worker.

The codec reuses Framework value archives, validates complete fields and checks the stored project identity on load. Neither decoding nor loading grants permission to open a board. A checksum detects accidental damage; it does not encrypt the record or authenticate its author.

Recovery and limits

  • If no location is saved, choose the folder manually and remember it. A missing record does not create a board.
  • If the settings directory is missing or read-only, create or choose a suitable private location. Existing board files are unaffected.
  • If a record is malformed or belongs to another project, loading refuses it. Re-enter the correct location and explicitly remember it.
  • Moved projects and path aliases can have different binding names. Reconfirm their location instead of assuming they identify the same project.
  • Location saves use atomic replacement and local last-writer-wins preference semantics. They are not collaborative board transactions.
  • The record contains local paths. Keep settings outside public repositories. Public board exports do not automatically include this record.
