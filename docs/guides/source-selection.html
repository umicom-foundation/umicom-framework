Select source words and lines

Selection commands highlight source text without changing it. They are useful before copying, replacing selected matches, commenting or applying a line edit. Read-only documents allow selection too.

  1. Open a document and place the caret in the text.
  2. Choose Select source word to select the word at the caret, or the word immediately before it when the caret is at its end.
  3. Choose Select line content to select the physical line without its newline. Use Select line with ending when copying or replacing the newline as well.
  4. Use an existing copy or edit action on that selection. Selection alone neither saves a file nor creates a text Undo step.

Exact boundaries

Source words contain ASCII letters, digits, underscores and contiguous non-ASCII characters. This is a programming convenience rather than a language-aware tokenizer or natural-language word breaker. A dot separates object.member. Emoji and punctuation outside ASCII may remain part of the same source word. If there is no eligible word at or immediately before the caret, the previous selection remains.

Lines recognize LF, CRLF and CR. Both bytes of a CRLF ending are selected together. The position after a final newline is an empty final line; selecting it succeeds with an empty range. UTF-8 characters cannot be split. Input is limited to eight MiB.

Framework use

UmiEditorSourceSelectionAt computes a byte range from a stable borrowed text view. It changes its output only on success. UmiDocumentCoordinatorSelectSourceUnit captures a named draft and publishes the range through existing source navigation; an inactive target becomes active on success. Its active-document counterpart is used by the native adapter.

UmiDocumentSourceSelectionCommandCount, At and FromId provide immutable labels and IDs for frontends. GTK hosts call UmiGtk4AdapterSelectSourceUnit to refresh their native selection and use the existing completion callback. Keep document calls on the owning thread.

Troubleshooting

A missing word is not an edit failure: move into a word or select a whole line. Invalid UTF-8 or a caret inside a character is rejected without changing the selection. A native application with no open document disables these commands. Display-dependent tests may be skipped when GTK cannot initialize; those skips do not validate the workflow.
