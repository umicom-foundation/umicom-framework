Save reusable form searches

A search preset is a named definition: a record namespace, optional metadata text and typed answer conditions. It contains no result list or page cursor. Reopening a preset starts a fresh search against the database you authorize.

Keep a search in local record history

  1. Link to Umicom::form_records and include umicom/data/structured_form_search_preset.h. Allocate the bounded preset and result models on the heap when composing larger application state.
  2. Fill a UmiStructuredFormSearchPreset with a title, a namespace ending in a dot, metadata text and a valid filter. The schema supplies the form ID and version. Validate the definition before presenting a Save action.
  3. Prepare ordinary record attribution. Set its entity ID to form.search. followed by a short key using letters, digits, underscores or hyphens. Keep this namespace separate from the answer records being searched.
  4. Call umi_structured_form_search_preset_save with expected revision zero to create a preset. To amend one, pass its last reviewed record revision. A conflicting update returns an error and retains the newer stored definition.
  5. Use umi_structured_form_search_preset_load with revision zero to load the latest definition, or a positive revision to inspect its history. Use open_reviewed when opening metadata already shown in a catalogue; it refuses a changed head.
  6. Authorize the reopened definition's namespace, then call umi_structured_form_query_from_preset with a page size from 1 to 16. It creates a first-page query. Pass that query to umi_structured_form_query_page with an appropriate registered schema catalogue.

What the format preserves

The portable filter snapshot records the exact form ID and version and each condition's field ID, value type, text format, unit, operation and operand. Integers retain their full range and decimals use the shared locale-independent text codec. Decoding refuses unknown framing, partial input, trailing bytes and noncanonical numeric spellings. It also refuses a changed unit, type or text format. Change the schema version whenever any other interpretation changes; the format is not a complete schema fingerprint.

The preset envelope adds the title, namespace and metadata text. It accepts at most eight conditions and fits within a bounded record document. The record layer supplies atomic revision checks and content hashes. Hashes detect accidental corruption; they do not authenticate an author or protect against deliberate replacement of the whole database.

Inspect the SDK example

The installed data_history/form_search_presets.c example creates fictional inventory records, saves a reusable condition, opens the exact saved definition and runs a fresh paged search. It uses only public headers and the memory data backend, so no bank account, clinical data or network connection is involved.

Recover from a refusal

If a preset has a newer revision, reload and review it before amending. If its schema version differs, use its original registered schema and make any migration a separate explicit action. A malformed or unrelated document in the preset namespace cannot be silently amended into a saved search. Preserve it for inspection and choose another key when creating a new definition.

Presets are unencrypted local records and may contain sensitive search text. The host controls storage selection, permissions, disclosure and UTF-8 presentation. This service provides the reusable model and persistence boundary; an application must add its own Save/Open preset controls. See native record search for applying conditions in an editor.
