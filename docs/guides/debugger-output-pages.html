Captured debugger output

A console report is an owned copy of the output records returned by a debugger console query. It keeps page boundaries stable while the live registry changes. It does not evaluate expressions or send commands to the program being debugged.

Use the native output browser

  1. Open an application that embeds UmiGtk4DebugConsoleCreate. The application supplies the callback that queries its debugger service.
  2. Leave the session and category fields empty to include all retained records, or enter an exact session ID or category. Text matching is bytewise case-insensitive; it is not a regular expression or Unicode case folding.
  3. Choose the minimum numeric severity and the ordering, then select Refresh output. The browser captures the matching records and displays up to 64 per page.
  4. Use Next and Previous to navigate the capture. Editing a filter does not change the capture until another Refresh succeeds.
  5. Use Copy page to put only the displayed page on the clipboard. Output can contain source paths and application data; review it before sharing.
  6. Select Clear view to discard this capture. This does not remove records from the debugger service.

Integrate the C23 services

Execute an UmiDebugConsoleQuery, pass it to UmiDebugConsoleReportCreate, then destroy the query when it is no longer needed. The report owns its record copies. Read its summary with UmiDebugConsoleReportRead and release it with UmiDebugConsoleReportDestroy.

UmiDebugConsoleReportFormat accepts an offset and a page limit from 1 to 128. Pass a null output buffer and zero capacity to obtain the required byte count, allocate that count plus one byte for the terminator, then format again. A short destination remains unchanged. An offset past the capture returns UMI_STATUS_NOT_FOUND.

The GTK widget owns its callback context only after successful construction and invokes the supplied destroy function once when the widget is finally released. Refresh is synchronous and intended for an in-memory query. Applications should not perform network access in that callback.

Limits and recovery

The underlying registry retains at most 2048 entries. A report is not a complete process transcript. If the query limits its results, the formatted heading identifies truncation. Invalid UTF-8 prevents capture; terminal control bytes are escaped for display. Body line breaks and tabs remain readable.

An invalid filter or failed refresh clears the previous displayed results. Correct the input and refresh again. An empty result can mean the filter matched nothing, the registry was cleared, or no debugger output has been received. The widget does not start a debugger or launch a program.
