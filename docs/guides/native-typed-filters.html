Build a typed record filter

A typed filter compares answers using their declared type and unit. For example, a parcel mass below 10 means 10 in the unit displayed beside the input. It never silently converts that number to another unit.

Add the editor to a GTK4 application

  1. Link your target to Umicom::structured_form_filter_gtk4 and include umicom/ui/gtk4/structured_form_filter.h.
  2. Keep an immutable, validated UmiStructuredFormSchema alive for the widget's entire lifetime. Create a widget with UmiStructuredFormFilterGtk4New and parent the returned floating widget in your GTK layout.
  3. Choose Add condition, select a field and an operation, then enter an operand when required. Every condition must match. With no conditions, every valid record matches.
  4. Call UmiStructuredFormFilterGtk4Read when the user chooses Search. Only use the returned filter and revision if the call succeeds. Read does not access storage or authorize a search.
  5. Supply the filter to umi_structured_form_query_page, together with the authorized namespace, exact form identity and schema version. That separate service checks persisted records before returning metadata.

Editing and revision checks

The filter-changed signal carries the editor revision. A revision identifies the current query inputs, including incomplete text. Store that value when preparing work. Add, Remove and Set require the expected revision and refuse stale edits. Reading during a change notification is supported; mutating through those three methods during a notification returns BUSY.

If a notification handler changes a native input control, the revision advances immediately and a later main-loop notification reports the new state. Keep the GTK main loop running and avoid repeatedly changing controls in every notification. An unfinished number such as a minus sign stays visible, but Read fails and leaves both outputs unchanged.

Operations and limits

Equals checks complete typed values. Contains performs a case-sensitive substring search on plain text fields. Numeric comparisons preserve integer precision and finite decimal values; their thresholds may lie outside the range accepted when saving the field. State conditions distinguish unanswered, known, unknown and not applicable. Switching to a state condition disables the value input while keeping its text available if the user switches back.

The editor accepts at most eight conditions. Boolean operands use true or false; numbers use a decimal point and no unit suffix. The schema supplies the displayed unit. Secret fields and labels or operands that GTK cannot display as UTF-8 are refused. Unsupported combinations, such as Contains on a date field, remain editable but cannot be read as a valid filter.

Lifetime and recovery

Use the widget only from its GTK owner thread. Retire, unroot or dispose permanently ends its editing lifetime. Create a new editor when reopening a closed page. Removed rows and separately retained buttons cannot mutate the remaining filter. A failed Set retains the previous query; fix the supplied filter and retry with the current revision.

This component provides query editing only. The host still owns authorization, asynchronous storage work, result presentation and cancellation of outdated search results. See typed record search for bounded storage searches and continuation rules.
