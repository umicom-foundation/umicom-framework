Captured call stacks

A call stack lists the functions recorded for a thread in a debugger. Framework can copy the selected stopped thread's retained frames into an independent observation. Capturing does not ask the adapter for more frames or execute the program.

Review in Studio

  1. Open your project and enable its trusted build tools.
  2. Start or attach the configured debugger. Pause it, and select a stopped thread in Run and Debug.
  3. Choose Review captured call stack. The review initially omits source paths.
  4. Choose source filenames or full source paths if needed. These choices reformat the same captured data.
  5. Read the text, then choose Copy reviewed text to copy it to the clipboard. Closing the review sends nothing anywhere.

The review is an observation, not a live view. It can remain open while the debugger continues. Capture again to see newer frames. Closing the Studio owner closes its review windows. An empty retained stack is reported as zero frames; that does not prove the target has no call stack.

Use the C23 service

Link to Umicom::debug. Keep workspace access on its owning thread. The capture itself owns its records and can be read after destroying the workspace.

#include <umicom/debug/backtrace.h>
#include <stdlib.h>

UmiDebugBacktrace *trace = NULL;
UmiStatus status = UmiDebugBacktraceCapture(workspace, &trace);
size_t bytes = 0;
char *text = NULL;
if (status == UMI_STATUS_OK)
    status = UmiDebugBacktraceFormat(trace, UMI_DEBUG_BACKTRACE_OMIT_PATHS,
                                    NULL, 0, &bytes);
if (status == UMI_STATUS_OK) {
    text = malloc(bytes + 1);
    if (text == NULL) status = UMI_STATUS_OUT_OF_MEMORY;
}
if (status == UMI_STATUS_OK)
    status = UmiDebugBacktraceFormat(trace, UMI_DEBUG_BACKTRACE_OMIT_PATHS,
                                    text, bytes + 1, &bytes);
/* Consume text only when status is OK. */
free(text);
UmiDebugBacktraceDestroy(trace);

UmiDebugBacktraceCheck compares the original workspace identity and registry generations. BUSY means the observation is older; it remains readable. A check is not a process-liveness guarantee. The owner-thread rule still applies.

Native hosts

Link to Umicom::ui_gtk4 and call UmiGtk4DebugBacktraceCreateWindow(owner, trace, &review). A successful window clones the capture. Present the returned borrowed window on the GTK thread. Retain a reference yourself if inspecting it after it closes. The constructor does not present automatically or copy anything.

Text and privacy

C0 control bytes, DEL and backslashes are escaped. UTF-8 is validated and markup remains plain text. Filename mode takes the last slash or backslash component. Neither filename mode nor omitting source paths guarantees redaction: function and thread names can contain sensitive information. Review before sharing. Variables, watch values, launch arguments and source-file contents are not included.

Troubleshooting

  • No selected thread: choose a thread and capture again.
  • Thread is running: pause through the normal debugger controls. A capture never pauses it automatically.
  • No frames: inspect the stopped thread in the debugger, then recapture. The capture does not fetch missing frames.
  • Text cannot be formatted: adapter metadata may contain invalid UTF-8. No partial text is made available for copying.
  • Path display changed during refresh: a native observer changed the dropdown while text was being published. Select another mode and then the desired mode again.
  • Copy does nothing: the review button must be visible in its live window. Retained controls from a closed window cannot copy.
