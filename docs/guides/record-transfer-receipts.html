Record an import receipt

A transfer receipt records a local import separately from the authorship in the imported history. It contains the reviewed bundle checksum, the original final revision and the import operator's attribution. The shared Data Server commits the original history and receipt together, or rolls both back.

Import with a receipt

  1. Link Umicom::data and include umicom/data/record_transfer.h. Decode and review a complete record bundle. A checksum identifies the bytes reviewed; it does not authenticate their sender.
  2. Choose a unique receipt ID containing 1 to 40 ASCII letters, digits, underscores or hyphens. This is an application identifier, not a path. The receipt is stored under transfer.receipt. followed by this ID.
  3. Fill UmiRecordTransferRequest with that ID and the import source, operator label, reason and positive recorded UTC time in nanoseconds. Keep any authentication decision in your host. Never copy the import operator from an untrusted file.
  4. After authorizing the destination and exact reviewed history, call umi_record_transfer_restore on a storage worker. Supply the bundle checksum you reviewed. Do not start an outer transaction.
  5. On success, retain the returned receipt identity. Original authorship remains unchanged. A record or receipt collision refuses the entire operation; do not silently choose another ID and retry.

Read and verify

Use umi_record_transfer_receipt_load to read the immutable receipt. Use umi_record_transfer_receipt_verify to check all originally imported revisions against its checksum in one transaction. Later edits to the imported record remain valid and are outside this historical receipt. An amended receipt is refused. Both functions leave their output unchanged on failure.

Recover from failure

An existing receipt, orphaned reserved row, changed checksum or invalid attribution causes refusal. A receipt-write or commit error rolls back the imported history too. A rollback error reports an I/O error: inspect the storage recovery state before retrying. Rejected attempts are not recorded by this service; a host may keep a separate attempt log with its own failure handling.

Limits

Reserve receipt records for this service; do not edit them through a generic record editor. The bounded record bundle limits still apply. This is ordinary unencrypted local storage, not a signed audit ledger, authentication system or whole-database backup. A writer capable of replacing the entire store can replace both history and receipt. Native products must explicitly adopt this API before claiming receipted imports.

Display a copied receipt

Link Umicom::record_transfer_receipt_gtk4 and call UmiRecordTransferReceiptGtk4New to show read-only literal labels, full-precision UTC timestamps and the bundle checksum. The widget owns a copy and performs no database access. Call the portable load or verify function separately to establish what was checked. Copied receipt validation detects inconsistent fields; it does not authenticate the event.
