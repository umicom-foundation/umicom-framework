Find and open saved records

A record catalogue is a list of current record identities and their amendment metadata. The shared C23 service lets a native window or another host find a record without knowing its exact key. It uses the same memory or SQLite Data Server as amendment history. No separate index needs rebuilding.

Find a note in a native application

  1. Open the application's local record editor and choose the database that contains your fictional notes.
  2. Expand Find saved records. Leave the search empty to browse the application's namespace, or enter part of an identifier, reviewer name, source or amendment reason. Search is case sensitive and does not inspect note content.
  3. Choose Find records. The status shows the number listed and total matches. Choose Next results for another page, up to 16 rows at a time.
  4. Select a result from the list, then choose Open selected. Save or explicitly discard current unsaved text first. Searching itself leaves that text alone.
  5. If the list has changed, choose Find records again and review the new results. Opening checks that the selected record still has the metadata shown in the list; it will not silently substitute a newer revision.

A list is a snapshot, meaning it describes the store at the moment the read transaction completed. It does not lock out future changes. The editor also checks the storage revision when saving. Namespace filtering organizes records; it does not provide sign-in or access control.

Use the shared service from C23

#include "umicom/data/record_catalogue.h"
#include "umicom/data/record_document.h"

UmiRecordCatalogueQuery query = {.entity_prefix = "notes.", .limit = 16};
UmiRecordCataloguePage page;
UmiStatus status = umi_record_catalogue_page(server, &query, &page);
if (status == UMI_STATUS_OK && page.count != 0) {
    /* The host explicitly selects this row before opening its content. */
    UmiRecordDocument document;
    status = umi_record_document_open_reviewed(server, &page.rows[0], &document);
}

For another page, copy page.snapshot to query.expected_snapshot and page.next_after_entity to query.after_entity, retaining the prefix and search text. Stop when next_after_entity is empty. An invalidated snapshot returns UMI_STATUS_INVALID_STATE; clear both continuation fields and explicitly restart. Never treat that error as an empty result.

Results are sorted by identifier bytes. A snapshot digest includes all current amendment metadata within the namespace and the search parameters. Changing a head, adding a record, or changing the query invalidates continuation. Unrelated namespaces do not invalidate it. The digest detects changes; it is not a signature or authorization token.

Build the installed example

Install a Framework SDK containing the data component. Copy its share/umicom-framework/examples/data_history directory into your example workspace. From the copied directory, run each command separately and stop on an error:

cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH="C:/umicom/installed/applications" -DCMAKE_C_COMPILER="C:/msys64/ucrt64/bin/gcc.exe"
cmake --build build --target umicom-record-catalogue-example --parallel 2
ctest --test-dir build -R "^consumer.record-catalogue$" --output-on-failure --no-tests=error

The example uses fictional records in memory and prints Opened notes.fictional: 12 verified content bytes. These commands describe the workflow; a successful local run is the evidence that your SDK supports it.

Limits and troubleshooting

ResultMeaning and next step
No matchesCheck the selected database, namespace and letter case. Content words are not searched.
Capacity exceededThe namespace contains more than 256 heads, or scanning the store exceeds 32,768 key/value rows including history and unrelated rows. Use a narrower namespace where appropriate or a separately designed indexed store. This service refuses a partial result; it never claims unseen records are absent.
Invalid state on continuation or openingThe reviewed metadata or query no longer matches. Refresh the list and review again.
BusyThe server already has a transaction or another operation owns it. Complete the existing operation before retrying; the catalogue never rolls back a transaction it did not acquire.
Not found or parse errorA required row may be missing or malformed. Metadata-only histories can appear in the catalogue but have no document content to open. Preserve the store and inspect its integrity rather than silently creating replacement records.

The catalogue validates the listed metadata, not every historical revision or payload. Opening verifies the selected content. Whole-chain integrity, permissions, encryption, full-text indexing and remote collaboration are separate concerns.
