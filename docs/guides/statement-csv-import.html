Import a statement CSV

Trader, Bank and TMS share a local transaction-review window. Choose Statement CSV when your file follows the format below. A bank's own download may use different columns, dates or amount signs. Convert a copy into this explicit format and check it against the original first. No bank-specific layout is guessed, and importing never posts transactions or contacts a bank.

If your file uses different headers, the custom column mapping workflow can interpret them without rearranging the original CSV. Choose date and amount conventions explicitly.

Try the included example

  1. Open Bank transaction reports in Trader, Bank or TMS.
  2. Select Statement CSV in the format selector. The default remains Open Banking JSON for existing response files.
  3. Choose C:\umicom\Umicom-Applications\framework\examples\bank_feed\statement.csv, then select Import for review. The installed example is under share/umicom/examples/bank_feed/statement.csv beneath your installation folder.
  4. Select practice-account | GBP. Expect booked credits of 12.50, booked debits of 2.25 and net movement of 10.25. The pending debit of 999.00 appears separately.
  5. Select Reconcile selected account. Use 2026-10-12 for both dates, 100.00 for opening and 110.25 for closing. The arithmetic should match. See Compare statement balances for interpreting the result.
  6. Export to a private folder you choose. Changing the path or input format clears the current report and retires its export. Each already-open comparison keeps its own snapshot.

Prepare the nine columns

Use this exact header and order. Every record must have all nine fields, including empty optional fields.

account,transaction,reference,information,booking_date,currency,amount,status,mutability
practice-account,credit-one,ref,Example credit,2026-10-12,GBP,12.50,BOOK,Immutable
practice-account,debit-one,,Example debit,2026-10-12,GBP,-2.25,BOOK,Immutable
ColumnMeaning and accepted values
accountRequired account identifier, at most 40 Unicode characters. Accounts are kept separate.
transactionOptional source transaction ID, at most 210 characters. Repeated nonempty IDs within one account are rejected, even across currencies. Missing IDs remain separate observations and are counted.
referenceOptional reference, at most 210 characters.
informationOptional description, at most 500 characters. Quoted descriptions may contain commas, quotes, tabs and line breaks.
booking_dateA valid YYYY-MM-DD date, years 1600 through 9999. This is the date as supplied; no time or timezone is invented.
currencyExactly three uppercase ASCII letters, such as GBP. This checks spelling, not whether a currency exists or a bank supports it.
amountPositive or unsigned means credit; a leading minus means debit. Use 1 to 13 integer digits and at most 5 fractional digits after a dot. Do not use plus signs, currency symbols, spaces, thousands separators or exponents. The value is parsed exactly, without rounding or currency conversion.
statusBOOK for booked or PDNG for pending. Only booked rows affect a statement balance comparison.
mutabilityImmutable or Mutable, reflecting your source. Pending rows remain mutable regardless of this field. An immutable flag is an imported assertion, not independent verification.

CSV text rules

Save as UTF-8 with commas as separators and LF or CRLF line endings. An initial UTF-8 byte-order mark is accepted. Double quotes enclose fields containing commas or line breaks; write a literal quote as two quotes inside a quoted field. Spaces are significant. Blank records and unexpected columns cause a statement import error. Header-only files are accepted as empty observations, not as proof of a zero balance. The file limit is 4 MiB and the transaction limit is 1,024.

practice-account,description-example,,"Payment, reference ""North""",2026-10-12,GBP,-2.25,BOOK,Immutable

Resolve an import error

  1. Check the selected format. The filename extension does not select a parser.
  2. Use the displayed logical record and column when supplied. The header is record 1. A quoted multiline description still belongs to one record. Column 0 means the whole record.
  3. Correct the source copy and import again. If any record is invalid, the entire new feed is refused; there is no partial balance calculation. The previous report is cleared before loading starts.

The CSV produced by Export is a review report with additional metadata and spreadsheet text protection. It is not this nine-column input format and is not intended as a lossless re-import file. Preserve your original statement separately.

For contributors

UmiCsvReader in umicom/base/csv_reader.h owns its input and yields borrowed, decoded text fields. Copy fields before the next read. It handles syntax and UTF-8 only. UmiBankFeedCsvCreate in umicom/bank_feed/csv_import.h applies the explicit financial schema and returns the same owned feed used by JSON imports. Reuse UmiBankFeedSum, UmiBankStatementReview and the existing CSV exporters afterwards. A future bank-specific adapter should translate documented source fields into validated observations, with its own fixtures; it should not change the generic parser or infer debit signs from a filename.

False pagination flags mean this format supplies no pagination evidence. Neither those flags nor an arithmetic match establishes completeness, authenticity, available funds or settlement.
