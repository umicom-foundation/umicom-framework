Review bank transaction reports

The bank transaction inspector reads a saved Open Banking JSON response. It helps you inspect cash movements without entering them into a ledger. A local import does not authenticate a bank connection.

Import and inspect

  1. In Umicom Trader, open Bank transaction reports from the workspace toolbar.
  2. Choose a file in a folder you control, then select Import for review. The complete file is checked before any new rows appear. Changing the path clears the old report.
  3. Select an account and currency. The view shows booked credits, booked debits and their net movement. Pending movements appear separately. A mutable entry may change in a later bank response.
  4. Check the previous-page and next-page indicators. Even when both are absent, the import does not prove that the bank returned your complete history. Missing transaction IDs are counted because they cannot safely be matched to a later import.
  5. Use the export control to choose a new private .csv file. The export includes every account in the imported page, not just the current selection. Existing files are not overwritten.

Amounts retain decimal precision. GBP, EUR and other currencies are never added together. Net movement is not an opening balance, closing balance, available funds or a permission to spend. Source rows are displayed in their original order.

Supported input

The response must contain a Data object and may contain a Transaction array. Each row needs an account ID, amount and currency, credit/debit direction, posting status and booking timestamp. The inspector understands BOOK/PDNG and the older Booked/Pending spellings. Transaction ID, reference, narrative and mutability are optional. This is a selected-field reader, not a validator for the whole Open Banking standard.

{
  "Data": {
    "Transaction": [{
      "AccountId": "practice-account",
      "TransactionId": "practice-credit",
      "CreditDebitIndicator": "Credit",
      "Status": "BOOK",
      "BookingDateTime": "2026-01-15T10:00:00Z",
      "Amount": {"Amount": "12.50", "Currency": "GBP"},
      "TransactionInformation": "Example receipt"
    }]
  }
}

This invented example has one booked credit of GBP 12.50. Save it as a JSON file to explore the workflow without private account data.

Limits and recovery

Imports accept at most 4 MiB and 1,024 rows. Amount text contains 1–13 integer digits and at most five decimal places. Malformed dates, incorrect field types, duplicate known keys and duplicate nonempty transaction IDs within one account are rejected. Booking timestamps must use years 1600–9999, valid calendar dates, a Z or numeric timezone, and at most nine fractional-second digits. Control characters in selected text fields are refused. Unknown optional fields are discarded. Imported links are never followed. Amounts too large to sum are reported as unavailable; individual rows remain inspectable.

If an import fails, check the source format and obtain a fresh export from your bank or authorised provider. Do not edit a real statement merely to make it pass. The reader does not accept PDF statements, arbitrary bank CSV layouts, or the proprietary Wise, Revolut Business and PayPal JSON formats. Those need separate mappings.

Loading does not save data automatically. Clearing or closing the window removes its retained report. An export already accepted may finish after closing; an I/O failure may leave a partial new file. Inspect that file and choose a different filename when retrying.

Import a prepared CSV statement

The same window also accepts an explicitly formatted CSV. Select Statement CSV before importing. Follow Import a statement CSV for its nine columns, signed amounts, invented example and error recovery. The JSON instructions above remain supported. Arbitrary provider CSV and PDF layouts still need a separate converter.

Save observations for reopening

The Reusable observation archive section saves the retained data in a versioned Umicom JSON format. Choose Umicom observation archive when importing it again. Unlike the CSV report, it preserves booking timestamps, missing identifiers and page hints. Follow Save and reopen bank observations for the complete workflow and its limits.

For contributors

Use Umicom::bank_feed for parsing, row copies, account/currency totals and owned CSV reports. The GTK window adds file selection and asynchronous loading. Keep provider authentication outside this importer: a future connector must establish consent, validate account scope and preserve pagination before handing a response to a reader. Reuse Framework’s exact decimal and file owners when adding adapters.

Reference: Open Banking transaction resource.

Compare two imports

Retain one accepted import, load a second and inspect exact-ID differences using Compare two imported bank reports. Missing identifiers remain unmatched, and an absent row is never treated as a deletion. Existing statement reconciliation and archive exports remain available.

Reopen a saved balance comparison

Select Umicom statement review archive to reopen saved dates and balances as well as imported rows. The report opens an independent comparison and recalculates its totals. See the statement review guide for saving, reopening and privacy limits.
