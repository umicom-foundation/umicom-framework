Sort selected source lines

Framework can prepare ascending or descending text order for selected complete lines. This is useful for plain lists, configuration entries and other text whose order you intend to change. It does not understand programming-language syntax or dependencies.

  1. Keep the original UTF-8 source available while calling UmiEditorLineSortPlanCreate. Give the source byte length, two selection byte offsets, direction (0 ascending, 1 descending), and an optional cancellation token.
  2. Inspect the plan with UmiEditorLineSortPlanInspect. The summary gives the selected block and whether the text changed.
  3. Read the complete proposed text through UmiEditorLineSortPlanRead. It belongs to the plan. Text outside the selected line block is preserved.
  4. Destroy the plan after use. Creating a plan does not modify a file, document, selection or Undo history.

For an open document, call UmiDocumentCoordinatorEditLinesForDocument with its document ID and UMI_EDITOR_EDIT_COMMAND_SORT_LINES_ASCENDING or UMI_EDITOR_EDIT_COMMAND_SORT_LINES_DESCENDING. The coordinator checks ownership and read-only state, then records a changed result as one reversible edit. Earlier unsynchronized typing remains a separate history step. The active tab need not be the target tab.

Ordering and line endings

Order compares UTF-8 bytes. It is case-sensitive, not numeric or language-specific. For example, “10” sorts before “2” and “A” before “a”. Equal lines keep their relative order. Each output position keeps its original LF or CRLF line separator, including mixed line endings. A missing final newline stays missing. Bare CR line endings are not supported by this command.

A selection expands to the complete lines it touches. Ending exactly at the beginning of the next line excludes that next line. An empty selection returns UMI_STATUS_NOT_FOUND; it never sorts the whole document implicitly. A changed result selects the reordered block. An unchanged result keeps the original selection and adds no Undo step.

Limits and recovery

The operation accepts at most eight MiB of UTF-8 text and 65,536 selected lines. Invalid UTF-8 returns a parse error; an offset inside a Unicode character is an invalid argument. Input with embedded NUL is refused. Cancellation, allocation failure and limit errors leave the source unchanged. Reduce the selection or fix malformed text before retrying. Destroy any successful plan even when you decide not to apply it.

Native Studio exposes the same commands in Code tools and command search. Select lines, search for “sort selected”, choose a direction, then review the result. Use Undo to restore the previous text and selection. Save writes the current draft through the normal document save workflow.
