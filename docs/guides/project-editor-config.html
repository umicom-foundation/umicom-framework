Review project editor settings

An .editorconfig file records a project's text conventions. Umicom can inspect matching rules and show where each final value came from. Inspection does not apply settings, reformat source, save files or execute project commands.

  1. Open a project in Studio, then choose Inspect EditorConfig in Explorer.
  2. Check the absolute project boundary and target file relative to it. An active saved file inside the project supplies a suggested name. For an unsaved or external file, enter the relative name yourself.
  3. Choose Inspect. Reads run in the background. The report shows the captured paths, configuration file digests, resolved values and their source line and section.
  4. Review unsupported or invalid values. Use the existing editor preferences form separately if you want to change this Studio session. Inspection has no Apply action.
  5. Choose Cancel inspection or Close when finished. Changing projects does not retarget an already opened inspector.

Inheritance and boundaries

Matching sections are processed in file order, and closer configuration files take precedence. A value of unset removes an earlier property. The explicit project boundary limits the directory search; a preamble root=true stops it earlier. This project-bounded search deliberately does not inspect directories above your chosen root.

Supported review

The reader keeps unknown properties and interprets indentation, line endings, character sets, trailing-space policy and final-newline policy for review. Invalid recognized values are counted. Current indentation controls have one width, from 1 to 16; differing indent sizes and tab widths cannot be silently converted into that pair.

Patterns support literal Unicode, stars, question marks, literal character classes, escaped characters, brace alternatives and ascending signed 32-bit integer ranges. Matching is case-sensitive. Configuration text must be UTF-8 with LF or CRLF lines. Inline hash and semicolon characters remain part of a value.

Limits and recovery

Each configuration is limited to 1 MiB, 256 sections and 1024 pairs. Keys and values may contain up to 1024 and 4096 bytes. Inspection visits at most 32 directory levels and reads at most 8 MiB total. Patterns are limited to 1024 bytes, 256 expanded alternatives and 8 expansion steps. Matching also limits scalar-row work to 16 million cells. These are bounded services, not a claim of upstream EditorConfig certification.

If a read is denied, a configuration is malformed, or a path traverses a link beneath the chosen boundary, inspection refuses the result. Correct the reported input and inspect again. Digests identify observed bytes; they are not signatures or locks, and several reads do not form a simultaneous filesystem snapshot.

Contributors can call UmiEditorConfigParse for memory-only parsing, UmiEditorConfigResolve for explicit ordered layers, or UmiEditorConfigInspectionLoad on a worker for bounded project reads. Destroy successful owners with their matching Destroy function. The native inspection window reuses those services.

Format reference: EditorConfig specification. Current limits and behaviour are described above; automatic per-document adoption and save-time formatting are not yet connected.
