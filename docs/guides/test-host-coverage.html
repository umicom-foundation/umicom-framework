Review test coverage across hosts

A test skipped on Windows may still need a passing Linux observation. A saved pass from older source must not close that gap. Framework's coverage review connects exact test names to required hosts, configurations and a requested source identity.

Prepare the observations

  1. Build the intended source on each required host. Record the source fingerprint, toolchain, configuration, command and exit status alongside the test evidence. A branch name such as main is not a stable fingerprint.
  2. Capture a complete CTest JUnit report and import it with UmiCtestReportImport or the existing saved-report file service. Keep runtime skips, disabled tests and missing executables separate.
  3. Describe each required test, host and configuration. The capability description explains why that host is required, such as a GTK display or a Linux filesystem operation.
  4. Create a coverage review. Inspect every outstanding row before deciding which environment or test needs attention.

Use the shared C23 service

The following fragment assumes report is an already imported report owned by the caller. The identity is illustrative; supply the real fingerprint captured with the run.

#include <umicom/testing/ctest_coverage.h>

UmiCtestCoverageRequirement required[] = {{
    .name = "application.editor.open",
    .host = "windows-desktop",
    .configuration = "Debug",
    .capability = "GTK display"
}};
UmiCtestCoverageHost hosts[] = {{
    .host = "windows-desktop",
    .configuration = "Debug",
    .source_identity = "source-fingerprint-from-the-run",
    .report = report
}};
UmiCtestCoverageReview *review = NULL;
UmiStatus status = UmiCtestCoverageReviewCreate(
    "source-fingerprint-from-the-run",
    required, 1, hosts, 1, &review);
if (status == UMI_STATUS_OK) {
    UmiCtestCoverageSummary summary;
    status = UmiCtestCoverageReviewRead(review, &summary);
    if (status == UMI_STATUS_OK) {
        for (size_t i = 0; i < summary.requirements; ++i) {
            const UmiCtestCoverageRow *row =
                UmiCtestCoverageReviewAt(review, i);
            /* Present the requirement and outcome as plain text.
             * Read observation only when has_observation is true. */
            (void)row;
        }
    }
    /* This gate covers only the explicitly required rows. */
    status = UmiCtestCoverageRequirePassed(review);
}
UmiCtestCoverageReviewDestroy(review);

The review copies its rows and the requested identity. After creation, it does not borrow the input arrays or reports. Rows remain valid until the review is destroyed. It keeps requirement order so a board or checklist can retain its planned ordering.

Interpret outstanding coverage

OutcomeNext step
Failed or timed outInspect the saved diagnostic and repair the failure. A timeout remains a failure even when some work completed.
Skipped or disabledIdentify the prerequisite or deliberate exclusion. Add and run the required host coverage explicitly; a pass elsewhere does not silently replace this row.
Not runCheck the executable, working directory, fixtures and completed build before rerunning.
Missing hostSupply the exact host/configuration observation. A Release result does not satisfy a Debug requirement.
Missing testCheck the discovered test inventory and exact decoded test name. A removed test is not a repaired test.
Source mismatchCompare the requested identity with the row's observed identity. Run the intended source instead of relabelling old evidence.

Duplicate host/configuration observations and duplicate test/host/configuration requirements are rejected. Choose the intended observation explicitly instead of relying on whichever report appears first. Empty requirements can be reviewed but never satisfy the passing gate.

Review a saved plan with the native command

  1. Keep the complete JUnit reports in one evidence directory, for example C:\umicom\_local\logs\testing. Save the source fingerprint and host configuration with each run. Do not rename old metadata to make it match a new build.
  2. Create coverage.csv in that directory. Use the exact header below. A host row identifies one report. A require row identifies one test that must pass on that host and configuration. This example uses illustrative names and fingerprints; replace them with values from your own runs.
kind,host,configuration,source_identity,test,capability,report
host,windows-desktop,Debug,source-fingerprint-from-the-run,,,windows.xml
host,linux-desktop,Debug,source-fingerprint-from-the-run,,,linux.xml
require,windows-desktop,Debug,,application.editor.open,GTK display,
require,linux-desktop,Debug,,filesystem.exchange,Linux filesystem operation,

Every record has seven fields. Empty fields still need their commas. Quote a field containing a comma, and double a quote inside a quoted field. Names are case-sensitive and whitespace is significant. UTF-8 with or without a byte-order mark, LF and CRLF are accepted. Blank records, extra columns, unknown row kinds, control characters and duplicate identities are rejected.

  1. Run the installed native command, or the executable from your Applications build:
& "C:\umicom\Umicom-Applications\build\windows-ucrt64-all-debug\bin\umicom.exe" test-report --coverage "source-fingerprint-from-the-run" "C:\umicom\_local\logs\testing\coverage.csv"
$LASTEXITCODE

Exit 0 means every listed requirement has a passing saved result for the exact host, configuration and requested source identity. Exit 1 means a requirement remains outstanding, or the plan has no requirements. Exit 2 means an input could not be admitted. The command prints each requirement and outcome; it does not run tests or write files.

Report paths are relative to the manifest directory, even when the command runs from another directory. Child folders are supported with either slash. Absolute paths, drive prefixes, empty path components, . and .. components are refused. A missing declared report is an input error. A requirement whose host has no declared report row produces missing host.

Reuse the manifest in an application

Include umicom/testing/ctest_coverage_manifest.h. Call UmiCtestCoverageManifestImport with the complete CSV byte span, then inspect its host and requirement accessors. Import copies input and performs no file reads. Call UmiCtestCoverageManifestReviewFiles with an explicit absolute evidence directory and requested source identity to obtain the same immutable review used by the CLI. Destroy the manifest and review separately.

CSV input is limited to 4 MiB, with up to 256 host reports and 100,000 requirements. The aggregate report input limit is 64 MiB; the existing XML parser limits also apply. Parsed records and copied review rows require additional memory. File reading can block, so native applications should perform it on a worker and present results as plain text.

Use a trusted evidence directory. Final report files must be ordinary local files; parent directory aliases may still be followed. This service is not filesystem confinement and does not authenticate a report. Resolve input errors before using its review to make a release decision.

Limits

This service compares supplied metadata and saved results. It does not execute tests, discover host capabilities, authenticate identities, verify timestamps, inspect logs or prove that a report was built from the claimed source. Keep that provenance in the calling application's evidence workflow. A passing coverage gate does not imply that unlisted tests passed; use UmiCtestReportRequirePassed when the complete report must pass.

Requirements and observations are bounded by the public capacity constants. Allocation, malformed text and capacity failures return an error with a null review. Summary reads leave their output unchanged on invalid arguments. Link consumers against Umicom::testing.
