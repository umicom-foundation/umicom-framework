Reviewing a local FX-forward transition

An FX forward records an agreement to exchange two currencies later at a specified rate. Framework's bounded forward book stores local observations about that agreement. A transition review shows the proposed lifecycle change before the caller chooses to apply it. It does not authorise a trade, reserve money or send settlement instructions.

1. Understand the lifecycle

Current stateAllowed next state
DraftConfirmed or Cancelled
ConfirmedSettlement pending or Cancelled
Settlement pendingSettled or Cancelled
Settled or CancelledNo further transition

Each transition needs a strictly newer trade version. Repeating a state, skipping a stage or changing a terminal record is refused. Imported records can start in any known state: importing a record does not prove that another system approved it. Applications must label that provenance.

2. Prepare and display the review

  1. Initialise UmiOpenTmsFxForwardBook and admit a complete record with umi_open_tms_fx_forward_book_add.
  2. Call umi_open_tms_fx_forward_review_create with the identity, next state and next version.
  3. Read the before/after copies with umi_open_tms_fx_forward_review_read. Display the trade identity, currencies, notional, proposed state and versions.
  4. After the user's decision and the application's current permission check, call umi_open_tms_fx_forward_review_apply. Check its status before displaying success.
  5. Destroy the review when no longer needed. Destroying it does not undo a successful transition.

The review owns its data. Changing a display snapshot cannot change the requested transition. Apply compares the complete active book, including unrelated records. A changed book returns UMI_STATUS_BUSY without writing anything. Refresh, create a new review and ask for a new decision; do not retry the old review automatically. Use one serial owner for all access.

Try the local TMS practice window

In Umicom TMS, select FX-forward practice. Enter a unique trade ID and check the practice account, counterparty, currencies, notional and rates. Select Capture local draft. Its ID appears in the review field. Choose the next state, select Prepare transition review, inspect all assumptions, tick I reviewed this local change, then select Apply reviewed local change.

Editing a field or changing the selected action invalidates the preview. A duplicate ID, an invalid decimal or a skipped lifecycle stage is refused. Decimal entries use a full stop and no grouping separator. Each window begins with its own empty book; closing it discards unsaved changes. The checkbox is a local acknowledgement, not a separate authorised approver. Older Framework SDKs show that the practice feature is unavailable.

3. Build the installed-SDK example

Install a Framework SDK containing the finance component first. The following PowerShell example uses C:\umicom\installed\applications; replace that prefix with your actual installation. The example explicitly rejects an accidental source-tree package. Run one command at a time and stop if a command fails.

Set-Location "C:\umicom\Umicom-Applications\framework"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake -S ".\examples\treasury_forward_review" -B ".\build\treasury-forward-review" -G Ninja -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe -DUMICOM_SDK_PREFIX=C:/umicom/installed/applications
cmake --build ".\build\treasury-forward-review"
ctest --test-dir ".\build\treasury-forward-review" --output-on-failure --no-tests=error
& ".\build\treasury-forward-review\treasury-forward-review-consumer.exe" apply
& ".\build\treasury-forward-review\treasury-forward-review-consumer.exe" stale

The apply scenario expects one local update and refuses replay. The stale scenario changes the quoted rate after preview and expects refusal with the trade still in draft. Both scenarios should print PASS: treasury_forward_review. These are expected results, not a qualification claim for your machine.

4. Keep unavailable prices separate from zero

umi_open_tms_fx_forward_mark_to_market_checked calculates notional × (market forward rate − contract forward rate). A zero market rate means unavailable and returns UMI_STATUS_UNAVAILABLE. An equal valid market and contract rate succeeds with a measured zero. Invalid or non-finite values are refused, overflow returns UMI_STATUS_CAPACITY_EXCEEDED, and failures leave the output unchanged.

This simple undiscounted observation is not a production valuation model. It has no discount curve, market-data freshness policy, collateral, currency conversion or accounting posting. The older scalar API remains available but returns zero on refusal; use the checked API for new displays.

Store portable draft values through the SDK

fx_forward_archive.h binds the existing Framework value archive to the active forward book. Its typed encode/decode functions retain exact finite numeric observations, record order, versions and revisions. They exclude padding, unused rows and unused string tails. The envelope checksum detects accidental damage; it does not authenticate the author or encrypt financial data.

Measure with a null output buffer, allocate the reported size, then encode. Decode into a separate draft and review its source before adoption. Small-stack hosts can supply separate heap-allocated scratch and destination books through archive_decode_with_workspace. Conditional decoding compares the current destination against an independent reviewed snapshot and refuses a changed destination without writing it. Revoke existing transition reviews whenever the hosting application replaces a book.

The installed example also accepts archive-roundtrip and archive-stale. CTest exercises these cases alongside apply and stale. These SDK examples operate on private memory buffers. The native practice window additionally supports explicit file saving and reviewed loading.

Save and open a private treasury archive

  1. In the practice window, enter an absolute ordinary path such as C:\umicom\_local\treasury\practice.umiv. Create the parent directory yourself first, in a location you control.
  2. Select Save captured records to new file. This saves the captured book, including its recorded versions and lifecycle labels. Later edits are not part of that save. An existing file is never overwritten: choose a new filename for another snapshot.
  3. To resume, enter the archive path and select Open archive for review. Opening runs on a worker and leaves the current book unchanged.
  4. Compare the CURRENT and LOADED — NOT APPLIED sections. They show all identities, financial assumptions, maturity values, versions and lifecycle labels. Check the archive's source yourself; its checksum is not authentication.
  5. Tick the replacement acknowledgement and select Replace with reviewed archive. A field edit or a different action invalidates the review. Open again after an edit. All old transition reviews are revoked when a book is replaced.

Closing discards unsaved local changes. A save already accepted by the worker finishes from its captured records even after the window closes. A late load cannot replace records in a closed window. Save refuses existing files, including incomplete outputs from an earlier failure; inspect retained partial files and choose a new filename to retry.

Archives contain private financial observations. They are not encrypted, signed, backed up automatically or a transaction journal. Imported “Confirmed” or “Settled” labels do not authorise an action or prove that cash moved. Invalid UTF-8 text is refused by the native viewer before display.

Use the file adapter from another application

Link Umicom::treasury_files and include umicom/open_tms/fx_forward_file.h. The separate library keeps portable finance independent of filesystem access. Call umi_open_tms_fx_forward_book_save_new on a worker with an owned, immutable book and inspect its output receipt. Call umi_open_tms_fx_forward_book_load into a separate book; failed loads preserve that destination. Review before replacement. These synchronous APIs follow the platform's ordinary absolute-path contract and are not a workspace confinement boundary.

Build the file example with an installed SDK

With a freshly installed SDK, run these commands from the Framework checkout. The example creates one synthetic archive and reopens it. It does not remove or overwrite files. Choose a new filename for each run and use a directory you control.

Set-Location "C:\umicom\Umicom-Applications\framework"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
cmake -S ".\examples\treasury_forward_files" -B ".\build\treasury-forward-files" -G Ninja -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe -DUMICOM_SDK_PREFIX=C:/umicom/installed/applications
cmake --build ".\build\treasury-forward-files"
New-Item -ItemType Directory -Force "C:\umicom\_local\treasury"
& ".\build\treasury-forward-files\treasury-forward-files.exe" "C:\umicom\_local\treasury\example-new.umiv"

Expected output is Saved and reopened one synthetic local record. No financial action occurred. Running the same filename again should refuse because it already exists. These are expected results for owner qualification, not a claim that this example has been executed.

5. Limits and recovery

  • The book holds at most 512 records. Identity fields must terminate inside their arrays and contain nonblank, control-free bytes. Currency codes are distinct uppercase three-letter codes.
  • Notional and contract rate must be finite and positive. Market rate may be zero for unavailable. Maturity zero remains unspecified; the book does not decide whether a date has expired.
  • An exhausted revision returns capacity exceeded. Do not wrap or manually reset a revision while reviews remain alive.
  • The portable finance API is in-memory; the optional treasury_files adapter adds explicit archives. Authentication, separate reviewer permissions, external confirmation and settlement exceptions remain hosting responsibilities. A local state called “Settled” does not prove that cash moved.
  • A configure failure about the package or missing symbol usually means the selected SDK lacks this interface. Rebuild and reinstall the intended SDK, then configure this separate consumer again.
