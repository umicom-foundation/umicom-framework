Own secure record operations across worker threads

The record host owns a Data Server, identity registry, session registry and policy engine. One mutex covers a security change or a complete protected storage operation. This gives background application workers a shared boundary without exposing raw storage or policy handles.

Create and configure a host

  1. Link Umicom::record_host and include umicom/data/record_host.h. Choose memory storage for temporary data or SQLite for a persistent record database. Supply a fixed source label and an entity prefix ending in a dot. Memory options use a NULL database path.
  2. Register identities through trusted application administration. A new host has no policy rules, so records are inaccessible until policy is configured.
  3. Replace the complete policy with umi_record_host_replace_policy. Every rule is copied and validated before the replacement becomes visible. A failed replacement retains the previous policy. Zero rules explicitly removes all grants. The last matching rule wins.
  4. Authenticate the user in the trusted host before calling umi_record_host_issue_session. Issuance requires a registered, enabled identity. Keep the returned session handle private. The service does not authenticate passwords or perform network login.

SQLite retains record content and amendment history. This host's identities, sessions and policy are in memory and must be bootstrapped again after reopening. Do not interpret reopening a database as restoring access credentials.

Use a worker

For queued work, use the current-time interface so session expiry is checked after admission. Its trusted clock callback is the only configured provider invoked while that lock is held; it must not reenter the host.

  1. Retain one host reference before scheduling a worker. Keep the schema, request and content buffers alive until its operation returns.
  2. Call a document or typed-form method. The host checks the current session, identity, operation and purpose while holding the same lock used by administrative mutations. The trusted host supplies clock values and binds each request to its authenticated session.
  3. Return a copied result to the interface and release the worker's host reference. Do not update GTK widgets from the worker. Reconcile the result with the interface's current draft before marking it saved.

Host methods can wait on storage or another operation. Use a worker for these calls when blocking the interface would be disruptive. Application notification callbacks do not run under the host lock. Current-time methods invoke only their configured trusted clock provider there.

Close and retire

umi_record_host_retire waits for an already admitted operation to finish, then permanently refuses later operations with CANCELLED. It does not undo a committed write or interrupt an active storage call. Retirement is idempotent, and state remains readable.

Every caller must own a live reference. The controller can release its reference after workers have retained theirs. Final release destroys the host. Retaining a dangling pointer cannot resurrect it. Join workers or transfer ownership correctly before freeing their request and result buffers.

Review failure

PERMISSION_DENIED preserves unsaved input; resolve login or policy through trusted administration. INVALID_STATE on a save means the reviewed revision or form schema no longer matches. A competing writer can succeed first. CANCELLED means the host has retired; create and configure a new host if a new workflow is intended. Do not bypass these checks with raw database writes.

Scope

This host is a reusable in-process service, not a process sandbox or complete product login. Its administrative APIs are trusted capabilities and must not be dispatched directly from untrusted client requests. It does not encrypt data, persist security policy, provide a durable purpose audit or make clinical/payment decisions. Other processes writing the same database must use compatible integrity and revision rules. Product editors require explicit adoption before these checks protect their workflows.
