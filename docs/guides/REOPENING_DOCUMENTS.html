Reopen a closed document

Closing a saved source tab does not delete its file. The document coordinator remembers its path so that a host can offer Reopen Closed Document. This history is shared by the document service and native adapter; an application does not need a second list of paths.

Try it in Studio

  1. Open a saved source file, such as notes.c, then close its tab.
  2. Choose File → Reopen Closed Document, search for that command, or press Ctrl+Shift+T. The saved source should become the active document again.
  3. Close two different saved files and repeat the command. The most recently closed file returns first.
  4. For a disposable practice file, change the text without saving and choose Discard and Close. Reopen it and compare the result with the saved file. Discarded text is not retained by this history.

If the same path is already open, Reopen selects that working copy. It preserves the current draft rather than reading over it. If it is closed, Reopen reads the provider's current content, including changes made by another program since the tab closed.

Understand the limits

The coordinator remembers up to 16 distinct absolute saved paths in memory. Closing the same path again moves it to the front of the reopening order. The oldest entry is evicted when a new path exceeds the limit. Untitled documents and relative paths are excluded. This avoids keeping discarded drafts and prevents a changed current folder from redirecting a reopen request.

History ends when its coordinator is destroyed. It is not a backup, session restore, recovery journal or durable recent-files list. Text, undo stacks, caret positions, pin settings and tab groups are not recorded. A new open follows the ordinary document loader's encoding and size limits.

Handle a missing file

  1. Read the failure message. A missing or unreadable file stays on the list, and no empty replacement document is created.
  2. Restore the file or its access permissions, then retry Reopen Closed Document.
  3. If you do not want to retry that path, choose File → Forget Last Closed Document. This removes only the newest history entry; it does not delete, rename or save a file. You can then reopen the next older entry.

Reopen and Forget are unavailable while the native binding is pasting asynchronously, saving all documents or waiting for a reviewed close decision. Finish or cancel that action before trying again.

Use the coordinator API

Include umicom/document/reopen.h and link Umicom::document. Use the coordinator that already owns the application's working copies. The following helper can be called from that coordinator's owner thread:

#include "umicom/document/reopen.h"

/* Read a history snapshot, then use its revision for this explicit request. */
UmiStatus ReopenSavedSource(UmiDocumentCoordinator *documents,
    UmiDocumentId *opened_document)
{
    UmiDocumentReopenSnapshot history;
    UmiStatus status = UmiDocumentCoordinatorReopenSnapshot(documents, &history);
    if (status != UMI_STATUS_OK) return status;
    if (history.busy) return UMI_STATUS_BUSY;
    return UmiDocumentCoordinatorReopenLast(documents,
        history.revision, opened_document);
}

A revision is a counter describing which history you observed. A later close, successful reopen or Forget changes it. A request using an older counter is rejected instead of acting on a different path. The output document ID remains unchanged on failure. The snapshot copies the next display name and count, without exposing paths or performing provider reads.

ResultHost response
OKUse the returned live document ID. The history entry has been consumed.
NOT_FOUNDInspect the history count to distinguish an empty list from a provider that could not find the file.
INVALID_STATEThe observed history changed. Refresh the command state before making a new request.
BUSYWait for the current operation to finish; do not force a second close or reopen from its provider callback.
Provider or capacity errorKeep the entry and explain the failure. Retry after correcting its cause, or let the user explicitly Forget it.

Connect a native host

  1. Bind the existing coordinator with UmiGtk4AdapterBindDocumentEditing.
  2. Use UmiGtk4AdapterReopenDocumentEnabled when refreshing Reopen and Forget controls. The same predicate applies to both.
  3. Dispatch user actions through UmiGtk4AdapterReopenDocument or UmiGtk4AdapterForgetClosedDocument. Framework refreshes the views and delivers one editing completion for a live binding.
  4. Detach the binding before destroying its coordinator or callback context. A completion callback may detach the host because notification is the final step. A provider callback may detach the UI binding, but must keep the coordinator alive and must not mutate its documents.

Extend the policy in Framework if another application needs it. Keep the bounded metadata history separate from unsaved-work recovery. Add a scenario to tests/document_closing/test_reopen.c for service behavior and test_reopen_gtk4.c for native lifetime or busy-state behavior. A new workflow should verify the document text and identity, not only that its command is present.
