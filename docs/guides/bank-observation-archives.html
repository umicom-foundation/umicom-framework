Save and reopen bank observations

An observation archive saves the transaction rows you imported so you can review them again later. It is a plain UTF-8 JSON file, suggested name bank-observations.umibank.json. Keep it in a private folder: it contains all account identifiers, descriptions and amounts in the import. It is not encrypted.

Save an import

  1. Open Bank transaction reports in an application that exposes the shared inspector. For a first attempt, use the invented JSON in Review bank transaction reports or the example in Import a statement CSV.
  2. Choose the input format, choose your saved file and select Import for review. Review the account/currency selection and page indicators. A successful import enables both the CSV report and observation archive controls.
  3. Scroll to Reusable observation archive (all accounts in this import) and expand its export control. Enter a new absolute filename in a private existing folder. The account selection does not narrow the saved archive.
  4. Select the export control’s save button and wait for its success message. Existing files are refused; use a new filename for each snapshot. If saving fails, read the message and inspect any partial new file before trying a different filename.

Reopen the saved archive

  1. In the same inspector or a new window, select Umicom observation archive. Choosing the format explicitly matters; the application does not guess it from the filename.
  2. Choose the archive you saved and select Import for review. Expected result: the same rows, account/currency totals, booking times, pending/mutable flags and page hints reappear. Source row order and amount spelling are retained.
  3. Review the original input SHA-256 displayed above the report. SHA-256 is a fingerprint of a sequence of bytes. On a new JSON or CSV import the inspector computes it from that file. On archive import it retains the fingerprint stored inside the archive.
  4. Use Reconcile selected account to open a separate comparison for that account, or save another archive. An archive does not include a previous comparison’s opening balance, period, matching decisions or ledger data.

A saved fingerprint can be changed by someone editing the archive. It does not authenticate a provider, prove consent or prove that the archive matches an original statement. Keep the original input separately when you need to compare it. Importing and saving never connect to a bank, place orders or post ledger entries.

What is retained

RetainedNot retained
Account and transaction identifiers, reference and information textProvider fields discarded by the original importer
Exact amount text, currency, credit/debit direction, booking date or timestampExchange rates, an account balance or a verified statement total
Booked/pending state, mutability, missing IDs and original row orderA deduplicated history across separate imports
Previous/next page indicators, original input format and its fingerprint when suppliedPage URLs, original filename, column mapping settings, credentials or consent

The archive keeps the imported observations only. Page indicators are hints, including when neither is present. They do not prove that you imported every transaction. A mutable observation can change in a later bank response.

Limits and recovery

  • The portable archive accepts at most 4 MiB and 1,024 rows. The native export control additionally accepts at most 2,097,152 characters. If an encoded archive exceeds a bound, it is unavailable for export; no partial snapshot is offered by the encoder.
  • Version 1 has an exact schema. Unknown versions, missing or duplicate keys, unknown fields, invalid dates, invalid amount syntax and duplicate nonempty transaction IDs within one account are refused. Missing IDs remain separate observations.
  • CSV date-only bookings and multiline information remain supported. Other selected text rejects ASCII control characters, including DEL. Do not modify a real statement to hide an import error; obtain a valid export or correct the source mapping.
  • Changing an input, clearing the report or closing its window retires the old export controls and pending import result. A save accepted before closing may still finish. There is no automatic save.
  • For “Import failed”, first check the selected format. A report CSV is not this archive and uses a different schema. A truncated or edited archive should be replaced from a separately kept original, not treated as reliable evidence.

Use the service from C

Include umicom/bank_feed/archive.h and link Umicom::bank_feed. Pass an owned feed to UmiBankFeedArchiveEncode; release its output with UmiBankFeedArchiveFree. UmiBankFeedArchiveDecode creates a new feed that you release with UmiBankFeedDestroy. It copies retained values, so input bytes can be released after decoding.

The optional metadata contains an input format and an empty or 64-character lowercase SHA-256 value. Unknown source is supported. The codec performs no file I/O. On failure, encoding clears its output pointer and length; decoding clears its feed pointer and leaves optional metadata unchanged. Keep file ownership and publication decisions in the host application, and serialise access to a feed with its destruction.
