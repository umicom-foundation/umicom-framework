Save reviewed public board fields

The Kanban board can keep the public fields you reviewed in a separate .umipublic plan. This lets you reopen a contributor-site selection without copying the private board description into a website.

The plan is private. It contains board and card identifiers and the reviewed fields. It is not encrypted. Keep it in your private local folder, outside public repositories. The generated HTML is the file intended for publication after you inspect it.

Save a selection

  1. Open a board and expand Review a public website snapshot.
  2. Select each card you want to publish. Enter a public title, optional summary and an approved developer display name, then select Include reviewed card. Private descriptions and internal developer identifiers are not filled into these fields automatically.
  3. Enter the public board title. Expand Save or reopen a private public-selection plan.
  4. Choose an existing private directory and a filename ending in .umipublic. Select Save current public selection. This replaces the selected plan file through the Framework rooted-file storage service. It does not save or replace the board document.

Load and review later

  1. Open the intended board, choose the saved plan’s private directory and filename, and select Load selection for review.
  2. Read the preview. It shows the saved board identity, revision, public board title and every selected card’s public fields. Loading does not change the current selection or generate HTML.
  3. Review the public fields for the current board. Check the approval box and select Adopt reviewed fields. The host requires the same board identifier and still-active selected cards. A stale view must be refreshed first.
  4. Select Generate website separately. Inspect the HTML output, then save it through the existing HTML export control. Upload only that reviewed HTML file to your chosen host.

Adoption preserves the saved public wording. It does not copy changed private titles, descriptions or assignments. Current card positions come from the current board when you generate the website. Adoption clears any previously generated HTML so it cannot be mistaken for the new selection.

Failures and limits

A different board, archived or missing card, invalid archive or stale view is refused. The previous live selection is retained. Discard loaded selection clears only the review. Plan files are bounded to 2 MiB and 1,024 selected cards. Their checksum detects accidental damage; it does not identify a trusted author.

Loading and saving run on a worker. Hiding or closing the controls prevents late review publication. A save already dispatched may finish writing its independently captured plan; closing the window does not undo that save. Host applications must retire the control before releasing a borrowed board.

Reuse in another application

The pure Umicom::kanban library owns immutable plans, validation and encoding. The optional Umicom::kanban_storage library reads and replaces private files. Umicom::kanban_gtk4 supplies the review controls. The host capture and adoption callbacks run on the GTK thread; workers own only copied paths and immutable plan values. The same services support Studio and other native applications.
