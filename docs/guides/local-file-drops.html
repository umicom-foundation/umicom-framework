Receiving local file drops

A file drop is a selection made in a desktop file manager and released over a native application. Framework converts the selection into copied local paths. Your application decides whether to open a document, import data or perform another reviewed operation.

  1. Include umicom/ui/gtk4/local_file_drop.h and link Umicom::ui_gtk4. Use GTK 4.10 or newer, matching the native application baseline.
  2. Implement a UmiLocalFileDropGtk4Receiver. Its widget, path array and strings are borrowed for the callback only. Copy the paths before scheduling work. Return UMI_STATUS_OK only after accepting the request; this does not mean that later asynchronous work has finished.
  3. Call UmiLocalFileDropGtk4Create with a selection limit between 1 and 128 and your receiver. Pass a context destructor when the controller should own the context. A failed creation leaves the context with you.
  4. Pass the returned controller to gtk_widget_add_controller. That transfers the controller reference to the widget. Select the propagation phase before attachment if your editor must receive files before a child text widget handles them.
  5. Keep the widget visible and sensitive in an open window. Report operation results using the application's existing document or import service.

Selection rules

The controller accepts GdkFileList copy drops. Every path must be absolute, local, valid UTF-8 and shorter than 4096 bytes including space for its terminating zero. An empty list, remote URI, excessive count or invalid item rejects the whole selection before your receiver runs. Order and duplicate paths remain available for your application's policy. The adapter does not test file existence, read files, follow project trust decisions, move files or delete anything.

Ownership and recovery

The receiver may close its window or remove the controller. Copied paths stay available until it returns. Recursive drops on the same controller are rejected. Hidden, detached or destroyed hosts do not receive a drop. Controller finalization calls the context destructor once; keep the GTK main thread as the owner of these objects.

If a selection is rejected, try a smaller local selection or use the application's file chooser. A drop accepted by a document queue may still contain a missing file or unsupported content; show those per-file outcomes rather than treating admission as a successful read.

GTK defines the drop-controller contract and the file-list transfer type.
