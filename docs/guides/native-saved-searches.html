Save and reopen form searches

A saved search keeps its title, text search and typed answer filters. It does not keep results: run the search again to see current saved records. This feature belongs to the shared GTK4 form record editor so applications use the same revision checks.

Create a search

  1. Connect the editor to the intended database. Expand the answer filters and choose the fields and comparisons you need.
  2. Enter any metadata text you want to match.
  3. Enter a new search key using 1 to 40 letters, digits, underscores or hyphens. Enter a descriptive title.
  4. Enter your actor name and a reason in the editor's attribution controls, then choose Save new search.
  5. Wait for the completion message. A matching key already in the database is refused; choose a new key or explicitly open the existing definition.

Reopen and change a definition

  1. Enter the saved key and choose Open saved search.
  2. Wait until the title and filters are loaded. The editor checks the form version and record namespace before applying them.
  3. Choose Search saved answers to run a new query. Opening the definition does not start the query or alter your current record draft.
  4. Edit the query and title, enter an attribution reason, then choose Save changes to opened search. This appends a revision only if the stored definition has not changed since it was opened or saved.

Host integration

Use UmiFormRecordEditorGtk4SaveSearch, UmiFormRecordEditorGtk4OpenSearch and UmiFormRecordEditorGtk4SavedSearch from umicom/ui/gtk4/form_record_editor.h. Calls return admission status; inspect Busy and LastStatus for completion. Supply a positive recorded timestamp to the save API. The visible buttons capture UTC time.

The editor borrows its immutable schema. Keep it alive while workers are active. A save owns a copy of the admitted query and finishes even if the window retires. Later edits remain visible. An incoming read is refused if its query controls have changed. Synchronous GTK observers can also change controls during installation; their changes remain visible and an altered query reports cancellation. There is no rollback over those edits.

Recovery and limits

If an update is stale, preserve your edits before explicitly reopening the definition. Opening replaces the query controls; it does not merge unsaved query edits. These controls do not yet provide automatic query recovery or a close prompt for an unsaved search. Record draft protections are separate.

Definitions use plaintext revisioned storage. The embedding application must authorize database access and any disclosure of filter values. A saved namespace is not an access-control grant. No connection to a provider or remote publication is performed.

See portable search definitions and typed record searches for storage formats, paging and supported comparisons.
