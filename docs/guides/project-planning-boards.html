Project planning boards

A project board is an independent planning document associated with one captured project folder. Opening another project does not redirect a board you already opened.

  1. In Studio, open a project folder, then choose Project board in Explorer or Open project board on Welcome.
  2. Check the project path in the new window title. Framework suggests a filename specific to that project path.
  3. Choose an existing private folder for the board. The field starts empty; no folder is created and no file is placed inside your source repository automatically.
  4. Choose Create board for a new archive or Open board to reopen the suggested file. Creation refuses an existing file.
  5. Create cards, assign developer names and move work between lists. Save explicitly. Close asks you to save or discard unsaved work.

Choosing Project board again returns to that project's existing window. The board remains open if Studio closes. Do not publish its archive as an accidental consequence of adding source files to Git. A public contributor view is a separate, explicitly reviewed export.

Filename identity

The suggested name uses SHA-256, a digest of the normalised project path. This makes names stable for the same path without embedding the path in the filename. It is not encryption or a guarantee that two paths refer to the same directory. Moving the project or changing path case can suggest a different name. Choose your existing archive explicitly if the project moved. The window's project association describes the captured project; choosing a different filename does not rewrite archive content.

Current limits

This version uses independent board windows. Storage folder preferences and a docked Studio board pane are not yet provided. The user selects the private folder on each newly created window. Opening a board does not register accounts, grant project execution trust, or upload a website. An untrusted project can have a planning window because this action does not execute project code.

Embedding in another native application

Call UmiKanbanGtk4CreateProjectWindow(application, project_root, &window) with a NULL output on the GTK owner thread. On success, present the application-owned window separately. No file operation starts at construction. Use UmiKanbanGtk4ProjectLocation to read the captured association. For toolkit-neutral naming, use UmiKanbanProjectLocationCreate. The document service repeats storage checks when the user opens or creates the archive.
