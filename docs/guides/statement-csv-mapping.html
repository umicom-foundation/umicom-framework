Match statement CSV columns

A mapping tells the importer which source column contains each value. Trader, Bank and TMS use this shared Framework tool. It reads a local file you select and keeps its observations separate from any ledger. It does not authenticate a bank or create an account connection.

Import the example with separate debit and credit columns

  1. Open Bank transaction reports and select CSV with custom columns. Expand Match your CSV columns if it is collapsed.
  2. Select C:\umicom\Umicom-Applications\framework\examples\bank_feed\mapped-statement.csv. An installed copy is under share/umicom/examples/bank_feed in your installation folder.
  3. Enter the settings in the table below. A blank header means that column is absent; it does not replace empty cells in a selected column.
  4. Select Import for review, then practice-account | GBP. Expect booked credits of 12.50, booked debits of 2.25, and booked net movement of 10.25. Both example rows are marked mutable.
  5. For a balance comparison, choose Reconcile selected account, both dates 2026-10-12, opening 100.00 and closing 110.25. The arithmetic should match. An arithmetic match does not establish statement completeness.

Choose meanings from your own statement

Open a copy of the source file in a text editor to inspect its first record. Header names are case-sensitive and spaces are significant. All headers must be nonempty, unique and shorter than 256 UTF-8 bytes. Extra source columns may remain unmapped. Each data record must have the same number of fields as the header; quoted commas and line breaks do not create extra fields.

  1. Map account and currency columns when the file contains several accounts or currencies. For a single-account file without those columns, clear each header and enter its constant. Supplying both a header and a constant is rejected. Empty mapped cells are errors.
  2. Choose the date convention from the source: YYYY-MM-DD, DD/MM/YYYY or MM/DD/YYYY. The importer never guesses whether 03/04/2026 is March 4 or April 3. All forms require leading zeros and four-digit years. No timezone is invented.
  3. For a signed amount column, map Signed amount header, clear both Debit and Credit headers, and choose the signed format. Negative means debit. For separate columns, clear Signed amount and map both Debit and Credit.
  4. Separate amounts must be nonnegative. One side may be empty or zero. Two nonzero sides are rejected rather than subtracted, and two empty sides are rejected. Two zeros represent a zero credit. Amounts use a dot, at most 13 integer digits and 5 fractional digits. Currency symbols, grouping separators, plus signs, rounding and automatic sign reversal are unsupported.
  5. If supplied, status cells must be BOOK or PDNG, and mutability cells Immutable or Mutable. Otherwise choose the absent-header settings deliberately. Pending and mutable are the initial defaults; pending rows always remain mutable. A mutable row is one whose source may still change.
  6. Leave absent transaction ID, reference and description headers blank. Missing IDs remain separate observations, so importing data without IDs cannot establish deduplication. Repeated nonempty IDs in one account are rejected.

Errors and changing settings

Errors identify the original logical record and column when possible. The header is record 1; a quoted multiline description counts as one record. Column 0 means the whole record, a missing header or a constant. Check spelling and duplicate names first for header errors. For a settings error, check account/currency sources and the selected amount columns. Correct the settings or a copy of the source file and import again.

Any invalid record rejects the whole import. Editing a mapping clears the report and disables its export; an older background result cannot repopulate it. Click Import again after changes. An already-open reconciliation keeps its own independent snapshot.

Mappings stay in memory for this window and are not saved as profiles. The source file is never rewritten. Export creates a review report, not a lossless copy of your bank's CSV. Store it privately and retain the original separately.

For contributors

UmiBankFeedCsvMapping in umicom/bank_feed/csv_mapping.h is a bounded value object. Initialise it with UmiBankFeedCsvMappingInit, replace header names and explicitly select interpretation rules, then pass it with input bytes to UmiBankFeedCsvMappedCreate. The call copies accepted observations; it borrows the mapping and input only until return. The result supports the same totals, export and statement-review APIs as JSON and normalised CSV.

The shared CSV reader handles syntax. The mapper resolves exact headers and translates dates and separate amounts. The common row validator enforces identity, decimal and publication rules. Extend these layers separately, with examples showing ambiguous and invalid input. No filename, bank brand or date locale is an implicit parser setting.

The input limit remains 4 MiB and 1,024 transactions. Only comma-separated UTF-8 files are supported. Files with introductory prose, semicolons, local decimal commas, balances used as amounts, or other status vocabularies need explicit conversion first. No built-in bank-specific profile is claimed.
