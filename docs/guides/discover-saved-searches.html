Discover saved form searches

The search catalogue lists named definitions stored in a Data Server. It searches their titles and keys, then opens the exact revision you reviewed. It does not run those definitions or return record answers.

Build a catalogue request

  1. Create an immutable UmiStructuredFormCatalogue containing the trusted schemas used by the saved definitions. Keep each schema and its referenced strings alive.
  2. Open the intended Data Server after your application authorizes access.
  3. Fill UmiStructuredFormSearchQuery with the exact form ID, schema version and searched-record namespace. Set limit between 1 and 16. Leave the cursor and snapshot empty for the first page.
  4. Call umi_structured_form_search_catalogue_page. Its text filter is a case-sensitive substring of the definition's title or entity key.
  5. For another page, copy next_after_entity and snapshot into the next request. Keep the form, version, namespace and text unchanged. Stop when the cursor is empty.
  6. Before using a row, call umi_structured_form_search_reader_open_reviewed with its revision metadata. A changed head is refused. Refresh explicitly instead of opening a different definition silently.

Historical definitions

umi_structured_form_search_reader_load accepts revision zero for the current head or an explicit earlier revision. The resolver reads a bounded form identity hint, selects its exact trusted schema, then validates the full definition. It never substitutes a newer version, downloads a schema or migrates a query automatically.

What a page proves

Every definition in form.search. is checked before filtering. Known definitions for other forms or namespaces are excluded. An unknown version, malformed definition or damaged document fails the whole scan, even if its title would not match. This prevents a partial list from looking complete.

The reader checks revision heads again after the individual document reads. Those reads do not form one global transaction. The snapshot detects changes; it is not a signature or an authorization token. Store-level permissions remain the host's responsibility.

Limits and recovery

A scan supports at most 256 definition heads and examines at most 32,768 storage rows through the shared catalogue. Capacity failures do not truncate results. Output arguments stay unchanged on failure.

If a page becomes stale, start a new first-page request. If a schema is unknown, register the actual historical schema before retrying; do not relabel the bytes as a newer version. If content is malformed, preserve the database for inspection and restore only through an explicit reviewed recovery workflow.

The installed SDK example examples/data_history/form_search_discovery.c creates a fictional inventory definition, finds it by title and reopens its reviewed revision. Link the consumer to Umicom::form_records.
