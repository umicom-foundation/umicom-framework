Choose related build presets

A project can give different names to its configure, build and test presets. The Framework Build Settings form can copy a matching set into the three stage fields for review. Nothing is executed by this action.

  1. Open Build Settings for the project and check its source folder.
  2. Read the project preset files. If they include other files or inherit preset values, use Read included presets for a project whose files you trust. Included files can be outside the project folder.
  3. Select a visible configure preset. The details show how many visible build and test choices refer to it.
  4. Choose Use matching configure, build and test presets. This requires exactly one eligible build choice and one test choice. Their names may differ from the configure name.
  5. Review all three stage fields and the remaining settings. Choose Apply Settings to save them. Starting configure, build or test is a separate action.

When no set can be selected

If either stage is missing, no names are copied. If several choices refer to the configure preset, choose the desired stage names individually with Use selected name. Hidden and literal-false presets are excluded. Conditions that need evaluation remain for CMake to evaluate when run; discovery does not guarantee that a preset will be available.

A direct read cannot prove that a set is unique when includes or inheritance remain unresolved. Use the expanded read, or select individual names. Clear the old shared preset field before choosing separate stage names. Changing the source folder retires the discovered list, even if you change it back: read the files again.

Only the three stage names change. The launch program, launch arguments, build target, tool directory, SDK definitions and other fields stay as entered. Build, test and configure presets own their CMake options. Review the separate build folder for operations that do not use a stage preset, such as target discovery or launching an executable.

Using the C23 service

Include umicom/developer_project/preset_set.h and link the developer library. Inspect an existing catalogue with UmiProjectPresetSetInspect, using a configure-row index. The summary reports related counts, unique indexes and incomplete discovery. Use UmiProjectPresetSetSelect to prepare a complete profile candidate. It preserves output on failure and supports updating a profile in place. Neither function reads files, saves settings, grants trust or starts a process.

Preset files can change after discovery. Refresh the list after editing them. See the CMake preset reference for the configurePreset relationship used by build and test presets.
