Export a captured journal review

A journal records matching debits and credits. A review captures the journal and the local rules that were inspected before someone chooses Apply. This guide exports that captured view as CSV using the finance SDK. The resulting report is useful for comparison and human review. It is not evidence that a payment settled or that a database transaction committed.

1. Establish the amount convention

The journal stores integer minor units. For example, with GBP and scale 2, 1250 means 12.50 pounds. Currency and scale are explicit inputs to the report. They are not inferred from an account name. All accounts in this review must use the same agreed convention; separate mixed-currency journals before creating a review.

A three-letter currency code is checked for uppercase syntax only. A valid code does not prove that an account supports it. The surrounding banking or accounting service remains responsible for account currencies, authorization and any conversion.

2. Create a complete review

Use umi_accounting_posting_batch_create as described in Review complete journal batches. A refused batch does not produce a review or post a prefix of its journals. Keep the returned review alive while preparing a report.

3. Build an independently owned report

#include "umicom/finance/accounting/posting_batch_report.h"

UmiCurrency currency = {{'G', 'B', 'P', '\0'}};
UmiCsvDocument *report = NULL;
UmiStatus status = umi_accounting_posting_batch_report(
    review, &currency, 2U, UMI_CSV_MAX_BYTES, &report);
if (status == UMI_STATUS_OK) {
    /* Borrow these bytes only until report is changed or destroyed. */
    const char *text = UmiCsvDocumentData(report);
    size_t length = UmiCsvDocumentBytes(report);
    /* Pass text and length to your existing export service. */
    (void)text;
    (void)length;
}
UmiCsvDocumentDestroy(report);

The report owns its text. Destroying the review afterwards does not invalidate the report. The maximum byte argument includes its terminating zero. A too-small limit, invalid UTF-8 or invalid arguments return a failure and leave the report pointer null; a partial journal report is never returned.

4. Read the columns

ColumnsMeaning
record, review_kindA line or journal total, always marked captured-eligibility.
journal_index, journal_id, accounting_date, period_idThe captured order, identifier, accounting date and matching period. Indices start at one.
line_index, line_id, account_idThe original line order and identifiers. These fields are empty on journal-total rows.
currency, scaleThe caller's stated convention, repeated so each row can be interpreted.
debit_minor, credit_minorExact signed 64-bit integer coefficients.
debit, creditExact decimal text at the requested scale. No floating-point calculation or rounding occurs.

Each journal's lines are followed by its total. There is no cross-journal or cross-currency grand total. Shared CSV handling quotes fields, doubles embedded quotes, validates UTF-8 and prefixes potentially executable spreadsheet text with an apostrophe. Spreadsheet import settings still matter: import identifier and decimal columns as text when exact preservation is required. The integer and decimal values in the CSV itself remain exact.

5. Try the installed example

Install the finance SDK and its learning examples first. Replace the two absolute example paths below with your installed SDK and a separate writable build directory. Stop if any command fails.

cmake -S "C:/umicom/installed/finance/share/umicom/examples/journal_batch" -B "C:/umicom-build/journal-batch" -G Ninja -DUMICOM_SDK_PREFIX="C:/umicom/installed/finance"
cmake --build "C:/umicom-build/journal-batch"
ctest --test-dir "C:/umicom-build/journal-batch" --output-on-failure --no-tests=error
& "C:/umicom-build/journal-batch/journal-batch.exe" report
& "C:/umicom-build/journal-batch/journal-batch.exe" report-stale
& "C:/umicom-build/journal-batch/journal-batch.exe" report-after-apply

Each report mode prints one header, four line rows and two journal totals. report-stale edits a live draft and confirms that Apply refuses it while the report retains the original captured amounts. report-after-apply applies to the example's local in-memory book; its report still says captured-eligibility. Neither mode produces an authoritative posting receipt.

Recover from a refusal

  1. For invalid currency or scale, check the explicit convention. Supported scales are 0 through 9; do not silently round to make a value fit.
  2. For a byte limit refusal, choose a larger bounded report capacity, no greater than UMI_CSV_MAX_BYTES. Do not publish an earlier partial copy.
  3. For malformed text, correct the original journal identifier before creating a new review. Do not remove arbitrary bytes from the exported identifier.
  4. For stale review inputs, create and display a new review before another Apply. Exporting the old review does not reauthorize it.
  5. If the installed package is not found, verify that the finance component was installed to the exact SDK prefix. Do not point the example at a source-tree build by accident.
