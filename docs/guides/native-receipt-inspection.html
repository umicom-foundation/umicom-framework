View saved import receipts

The shared native receipt inspector reopens provenance saved by an atomic record import. It uses an existing SQLite database through a read-only Data Server connection. It does not restore records, create a database or change the imported history.

Use the controls

  1. Select the existing database with Browse.
  2. Enter the receipt ID assigned during import. This is the short ID, without the transfer.receipt. storage prefix.
  3. Select View receipt to check and display the stored receipt itself. The original author and the import operator are shown separately.
  4. Select Verify imported history to additionally compare all originally imported revisions with the receipt's bundle checksum. Later legitimate amendments are allowed.

The feedback explicitly distinguishes viewing a receipt from verifying its referenced history. Neither operation authenticates the author or prevents a person with full store access from replacing the database. Editing either input removes the previous preview and invalidates a pending read result.

Embed in an application

Link to Umicom::record_transfer_inspector_gtk4. Provide an authorization callback that decides whether the selected local store and receipt may be read in your application. It runs on the GTK thread before I/O. The callback context is borrowed for the widget lifetime.

#include "umicom/ui/gtk4/record_transfer_inspector.h"

UmiRecordTransferInspectorGtk4Options options = {
    .authorize_read = authorize_receipt_access,
    .authorize_context = application_context
};
GtkWidget *inspector = NULL;
UmiStatus status = UmiRecordTransferInspectorGtk4New(&options, &inspector);
if (status == UMI_STATUS_OK)
    gtk_box_append(GTK_BOX(container), inspector);

All public widget methods run on the GTK owner thread. Read returns admission status. Observe operation-finished, carrying one status integer, or read the state after busy becomes false for completion. Rendering failure is reported separately in display_status; a successfully copied receipt remains available through the state.

Closing and errors

Use CanClose to detect pending work. Retirement is permanent and discards later read results. Keep the GTK main context running until completion so that the task can release its resources. The worker owns and closes its connection; application callbacks never receive that handle.

A missing database produces a storage error and is not created. A missing receipt, amended receipt head, malformed content or inconsistent history is refused. If View succeeds but Verify fails, the receipt itself was readable while its referenced history was unavailable or inconsistent. Do not treat that as a verified import. Paths must be explicit absolute local filenames; relative paths and URIs are refused.
