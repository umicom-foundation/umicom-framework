Review and transfer form records

A record bundle contains a bounded, complete history for one record. A form review adds meaning checks: every revision must use the expected form and an exact schema registered by your application. Link Umicom::form_records and include umicom/data/structured_form_bundle.h.

  1. Decode a bundle using the portable bundle codec or the explicit file adapter. This only reads bytes. It does not write to your database.
  2. Build a trusted schema catalogue containing all supported historical versions. Keep its schemas immutable and alive while reviewing the file.
  3. Call umi_structured_form_bundle_review with the expected form identifier and a namespace ending in a dot, such as notes.. Supply a pure key check if your product requires a stricter record identity. The review copies the bundle and checks every historical form. An unsupported old version blocks the entire import.
  4. Read the summary and inspect the revisions. Show the record identity, original author labels, timestamps, schema versions and digest to the person reviewing the operation. Required fields left unanswered remain drafts; import does not submit a form.
  5. After the user authorizes the destination and action, pass the reviewed summary digest to umi_structured_form_bundle_restore on a storage worker. The transaction refuses an existing record, including one created after the review. A successful operation retains all original revisions.

Expected result

The destination contains the original history and the existing source remains unchanged. The review can still be inspected after a failed restore. Selecting another file creates a different review; it must never reuse the previous confirmation automatically.

Recover from a refusal

An unknown schema requires a reviewed application update, not substitution of the latest schema. A namespace or form mismatch means the file belongs to another record type. For a collision, retain both histories and inspect them separately; this API cannot overwrite or merge them. A wrong review digest requires a new explicit review. A storage error requires checking the Data Server recovery state before retrying.

Boundaries

The bundle checksum detects corruption; it does not authenticate an author. Import does not grant permissions, encrypt content, authenticate labels, record a separate import audit event, migrate schemas or replace a whole database. The application owns authorization, destination selection and any separate audit trail. This service is shared so desktop, CLI and web hosts can enforce the same history checks.

Produce a reviewed history file

Link Umicom::record_bundle_files and pass the exact reviewed UmiRecordRevision to umi_record_bundle_export_reviewed with an explicit absolute destination. This captures the complete bounded history, compares canonical metadata against that reviewed head and only then creates a new file. A stale editor cannot export an unseen newer head. The caller authorizes disclosure; the service neither authenticates attribution nor encrypts output. After capture, later store changes do not alter the file. See the native editor guide for the visible workflow.

Preserve import provenance

umi_structured_form_bundle_restore_receipted applies the same exact typed review and additionally commits an import receipt in the same transaction. Supply host-owned attribution and a unique receipt ID. It does not change the original author labels. The older plain restore method remains available. See record an import receipt for reading, verification and failure recovery.
