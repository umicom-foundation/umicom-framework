Choose a local workspace library

A library is a SQLite database file: one file that stores related work. You choose its location. Opening Media, Music, LLM, RAG or Creator does not create a project database in a hidden folder.

Create your first library

  1. In Media or Music, expand Project library location. In LLM, RAG or Creator, open Library location.
  2. Select Choose new location.... Choose an existing folder you can write to and a new filename such as creative-work.sqlite3 or research.sqlite3. You can also type the full path.
  3. Select Create new. The active path appears when the database and workspace open successfully.
  4. For Media or Music, use the Project tab to create a Project ID. Choose Load starter into empty project to edit an example. Accepted project edits are saved to that library.
  5. For the AI applications, save a collection, add or import source passages, and prepare a job for review. A library choice alone does not contact a model.

Reopen saved work

  1. Select Browse existing... and choose your database.
  2. Select Open existing. This action reports a missing file instead of creating a blank replacement.
  3. In Media or Music, enter the saved Project ID and select Open project by ID. The scene, motion and notes reopen. Undo history starts with the new session.
  4. In the AI applications, the saved collections, passages and job history become available. LLM, RAG and Creator can open the same AI library.
Project libraries and AI libraries serve different purposes. A Media project library stores scenes, motion and notes. Asset-library files, audio arrangements, captions and provider settings keep their existing separate save workflows. Choosing a project library does not move those files or API credentials. Database contents are local and unencrypted.

Change libraries during a session

Choose another path, then confirm closing the current forms and undo history. Unsaved form text is not transferred. Saved records remain in their original library. The application opens the candidate first: if it fails, the current workspace remains available. Finish or cancel a model request or document import before switching an AI library.

Opening the active path again leaves the current workspace and form text unchanged. Use the existing reload action when you deliberately want to read newer saved records.

Existing installations

An existing default database may appear in the path field so you can open it deliberately. The UMICOM_AI_WORKSPACE_DB and UMICOM_CREATIVE_WORKSPACE_DB environment variables prefill a location; they do not automatically open or create a database. No existing database is moved or deleted.

If a library does not open

  • File already exists: use Open existing, or choose a different filename. Create never overwrites a database.
  • File or folder missing: check the absolute path. Parent folders are not created automatically.
  • Access denied: choose a writable local folder. Close another tool that may hold an exclusive lock.
  • SQLite unavailable: the application needs the Framework SQLite adapter enabled in its build.
  • Create failed after reserving a file: a newly created file may remain for inspection. Correct the reported configuration or permission issue, then try Open existing. Do not delete a file containing saved work.
  • Invalid or damaged database: keep the original for diagnosis. Opening another known library does not repair it.

Close the applications before copying a database for backup. Copy any SQLite sidecar files with it if they remain. Do not replace, rename or edit a database while an application is using it. For a library shared by several applications, explicitly reload after another writer changes its records.

Remember and reopen library locations

  1. After a library opens successfully, its path is added to Recent libraries on this computer. The history message reports whether that preference was saved.
  2. On the next launch, choose a recent path and select Use selected. This fills the path field without opening a database.
  3. Check the path, then select Open existing. A remembered path can still be missing, moved or inaccessible.
  4. Use Forget selected or Clear recent list to remove location records. Neither action deletes projects, changes the current library, nor signs out of a provider.

The list stores up to twelve recent locations for each application profile. Its full preferences filename is shown below the controls. Only that small metadata file normally lives in your user configuration directory; the project database stays where you chose. Paths are plaintext and may reveal folder or project names. Passwords and API keys are not included.

For a portable setup, set UMICOM_LIBRARY_HISTORY_FILE to an absolute preferences filename before launching an application. Use separate files for separate profiles unless you want them to share the same list. Reading a missing preferences file creates nothing. A successful open or an explicit history edit may create its preferences folder. It never creates the parent folder of your project database.

If saving the recent list fails, your open library remains usable. Check the displayed preferences path and its permissions, then select Remember current to retry. Damaged preferences are reported and preserved. Close applications using that file, keep a copy for inspection, and choose a new preferences filename to start a fresh list. Concurrent applications can replace each other's latest history changes; this convenience list is not a backup or a database lock.

Keep a report outside the library

Creative project summaries and AI draft reviews offer Save displayed text. This writes a separate report to a location you choose; it does not copy or change the library database. See saving displayed reports.
