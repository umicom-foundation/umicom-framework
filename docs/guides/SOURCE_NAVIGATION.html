Finding your place in a source file

A compiler message may point to line 12 of a file. A colleague may ask you to inspect a statement on line 40. Instead of scrolling and counting, you can ask the editor to move directly to that location.

In Umicom Studio, the toolbar, the Navigate menu and Ctrl+G use the same Framework navigation service. The service moves the caret—the point where new text would be inserted. It does not change the programme or save a file.

1. Move to a line in Umicom Notes

Open a disposable Umicom Notes project in Studio and open its C source file. The following small programme is useful for practising navigation. Its braces and indentation make it easy to recognise each line.

#include <stdio.h>
int main(void)
{
    puts("Umicom Notes");
    return 0;
}

Save the file once so that you have a known starting point. Choose Navigate → Go to Line…, or press Ctrl+G. Enter 4:5 and choose Go to location. The caret should move to the p in puts: line 4 begins with four spaces, so the next byte is column 5.

The editor toolbar also accepts 4:5 in its Line:column field. Entering only 4 moves to the beginning of line 4. The form's Enter key submits the location. Cancel closes the form without moving the caret or clearing a selection.

Now add an unsaved comment above puts. Request the line containing that statement again, using its new line number. Navigation reads the current editor draft, not an older saved copy. Your comment remains unsaved until you choose Save.

2. Understand a source position

InputMeaning
1The beginning of the first line.
4:5Line 4, UTF-8 byte column 5.
4:5 The same position. Spaces and tabs around the whole input are allowed.
0, -2, +2, 4:0Invalid: both numbers must be positive and contain digits only.
4 : 5 or 4:5:2Invalid: the separator must be one colon, without internal spaces.

Lines and columns start at 1. A line that does not exist is rejected, leaving the caret where it was. A column beyond a real line's end moves to that line's end. This makes a short line usable without inventing spaces. An empty line is still a line; a final newline also creates an empty last line.

A byte is not always a displayed character

Umicom's existing source-position contract counts UTF-8 bytes. The letters in ABC each use one byte. In A£B, however, £ uses two bytes: A starts at column 1, £ at column 2 and B at column 4. A request for column 3 is moved back to the beginning of £, so the caret cannot split its encoding.

A tab character occupies one byte even when it is displayed as several spaces. These columns therefore differ from screen-cell or grapheme columns. When another tool uses a different convention, its adapter must convert the position before calling this contract.

Keep the intended document

A location form records the identity of the active document when it opens. If application code selects another tab before the form is submitted, the old request is refused. It must not move the caret in that other file. Cancel the old form and open a new one for the intended document.

The form is modal during normal interaction. The identity check also covers changes made by other commands or application callbacks. It checks the active document's identity, not an immutable copy of its text: edits within the same document are resolved against its current draft. Closing the original document or replacing the editing binding also invalidates the request.

3. Use navigation in another Umicom application

A contract describes what a function accepts, what it promises and who owns its data. The public navigation header is umicom/document/navigation.h. Link a native C application to Umicom::document; the GTK form additionally uses Umicom::ui_gtk4.

ContractPurpose and example
UmiDocumentLocationContains the one-based line and column. The example parses 4:5 and prints both values.
UMI_DOCUMENT_LOCATION_TEXT_MAXLimits input to 96 bytes, checked before reading it. This bounds the request text, not the size of an open document.
UmiDocumentLocationParse(text, byteCount, outLocation)Reads exactly the supplied bytes. No allocation occurs, and a failed parse leaves the caller's output unchanged. A buffer need not end in a zero byte when its length is supplied correctly.
UmiDocumentCoordinatorNavigate(documents, expectedDocument, text, byteCount, outOffset)Parses the request, checks the active document ID and delegates to the existing UmiDocumentCoordinatorGoToPosition. The optional output is a zero-based byte offset in the complete draft.
UmiGtk4AdapterDocumentNavigate(adapter, location)Uses a zero-terminated location string for an immediate native request. It reports the result through the current document-edit completion binding.
UmiGtk4AdapterPromptDocumentLocation(adapter)Opens or presents the shared form. Returning OK means the form opened, not that the user navigated. Go reports a result; Cancel does not perform navigation.
UmiGtk4AdapterDocumentHasCompletion(adapter)Lets the host decide whether the current binding will display the command result. It is a read-only query, not a command or a guarantee that a later binding remains alive.

The registered command keeps its existing identifier, umicom.document.go-to-line, and accepts the same line or line:column syntax. Existing numeric-line callers do not need a new command ID. In Studio, invoking the menu without an argument opens the input form; a command with an argument navigates immediately.

Keep ownership explicit

The caller owns its input buffer and output structure. The parser does not retain either. The navigation function borrows the coordinator for the call. Capture the active document's nonzero ID before collecting input and keep the coordinator alive until that operation ends.

All document and GTK calls run on the document owner's thread. The GTK form retains an invalidatable binding token rather than owning the coordinator. Removing the binding closes the form and stops retained controls from applying an old request. No background worker, document registry or Undo stack is created for navigation.

Read the result before proceeding

ResultWhat to do
OKFor direct navigation, the position was applied. For form creation, wait for the user's action.
Invalid ArgumentCheck the syntax and use positive decimal numbers. Embedded zero bytes, signs and numeric overflow are rejected.
Capacity ExceededKeep the location request within 96 bytes.
Not FoundCheck that a document is open and that the requested line exists.
Invalid StateThe original document is no longer active. Ask for a fresh location in the correct tab.
UnavailableConnect the native adapter to the existing document coordinator before asking it to navigate.
Out of MemoryKeep the current draft intact and retry when resources are available.

Read-only documents allow navigation because moving a caret does not alter their text. Successful navigation clears the current selection; a rejected request leaves it unchanged.

4. Build the complete example

The following programme creates its own temporary Notes source file. It opens that file through Framework, requests 4:5, then proves that input captured for one document cannot navigate a different active tab. Finally, it checks both the complete draft and saved bytes. It removes only the temporary directory it created.

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/editor_workflow/navigation.c
 * PURPOSE:
 *   Find a line in an Umicom Notes draft, reject stale form input and verify
 *   that navigation changes neither the source text nor the saved file.
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "umicom/document/navigation.h"
#include "umicom/platform/filesystem.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#ifdef _WIN32
#include <process.h>
#define PROCESS_ID _getpid
#else
#include <unistd.h>
#define PROCESS_ID getpid
#endif

int main(void)
{
    const char *source = "#include <stdio.h>\nint main(void)\n{\n    puts(\"Umicom Notes\");\n    return 0;\n}\n";
    UmiCommandRegistry *commands = NULL;
    UmiUiWorkbench *workbench = NULL;
    UmiDocumentStore *store = NULL;
    UmiDocumentCoordinator *documents = NULL;
    UmiStatus status = UMI_STATUS_OK;
    char temp[UMI_PATH_CAPACITY], root[UMI_PATH_CAPACITY], path[UMI_PATH_CAPACITY];
    char leaf[100], viewId[UMI_UI_ID_CAPACITY], otherView[UMI_UI_ID_CAPACITY];
    char *saved = NULL, *draft = NULL;
    int ownsDirectory = 0;
#define TRY(call) do { status = (call); if (status != UMI_STATUS_OK) goto cleanup; } while (0)

    /* The example owns this temporary directory. Existing files are never used
     * as test fixtures, and only this directory is removed during cleanup. */
    (void)snprintf(leaf, sizeof leaf, "umicom-notes-navigation-%ld", (long)PROCESS_ID());
    TRY(umi_fs_temp_directory(temp, sizeof temp));
    TRY(umi_fs_join(root, sizeof root, temp, leaf));
    if (umi_fs_exists(root)) { status = UMI_STATUS_ALREADY_EXISTS; goto cleanup; }
    TRY(umi_fs_make_directories(root)); ownsDirectory = 1;
    TRY(umi_fs_join(path, sizeof path, root, "notes.c"));
    TRY(umi_fs_write_text(path, source));
    TRY(umi_command_registry_create(&commands));
    TRY(umi_ui_workbench_create("umicom.notes.navigation", commands, &workbench));
    TRY(umi_document_store_create(&store));
    TRY(umi_document_coordinator_create(store, workbench, NULL, &documents));
    TRY(umi_document_coordinator_open(documents, path, viewId, sizeof viewId));

    UmiDocumentWorkingCopySnapshot intended;
    TRY(umi_document_coordinator_active_snapshot(documents, &intended));
    UmiDocumentLocation location;
    TRY(UmiDocumentLocationParse("4:5", 3U, &location));
    printf("Requested line %zu, UTF-8 byte column %zu.\n", location.line, location.column);
    size_t offset = 0U;
    TRY(UmiDocumentCoordinatorNavigate(documents, intended.document_id, "4:5", 3U, &offset));
    if (source[offset] != 'p') { status = UMI_STATUS_INVALID_STATE; goto cleanup; }
    puts("The caret points to puts; navigation did not edit the source.");

    /* Model a form opened for notes.c, followed by a change of active tab.
     * Old input must not navigate the newly active review document. */
    TRY(umi_document_coordinator_new(documents, "Review notes", otherView, sizeof otherView));
    status = UmiDocumentCoordinatorNavigate(documents, intended.document_id, "2", 1U, &offset);
    if (status != UMI_STATUS_INVALID_STATE) { status = UMI_STATUS_INTERNAL_ERROR; goto cleanup; }
    status = UMI_STATUS_OK;
    UmiDocumentWorkingCopySnapshot active;
    TRY(umi_document_coordinator_active_snapshot(documents, &active));
    if (strcmp(active.view_id, otherView) != 0) { status = UMI_STATUS_INVALID_STATE; goto cleanup; }
    puts("A different active tab rejected the old request and remained active.");

    /* Check independent outcomes: both the complete draft and saved bytes. */
    size_t bytes = 0U;
    TRY(UmiUiDocumentViewModelCopyText(umi_ui_workbench_documents(workbench), viewId, &draft, &bytes));
    if (bytes != strlen(source) || memcmp(draft, source, bytes) != 0) {
        status = UMI_STATUS_INVALID_STATE; goto cleanup;
    }
    TRY(umi_fs_read_text(path, &saved, &bytes));
    if (bytes != strlen(source) || memcmp(saved, source, bytes) != 0) {
        status = UMI_STATUS_INVALID_STATE; goto cleanup;
    }
    puts("The Notes draft and saved file are unchanged.");
cleanup:
    UmiUiDocumentViewModelFreeText(draft);
    umi_fs_free_text(saved);
    umi_document_coordinator_destroy(documents);
    umi_document_store_destroy(store);
    umi_ui_workbench_destroy(workbench);
    umi_command_registry_destroy(commands);
    if (ownsDirectory) {
        UmiStatus removed = umi_fs_remove_tree(root);
        if (status == UMI_STATUS_OK) status = removed;
    }
    if (status != UMI_STATUS_OK) fprintf(stderr, "Notes navigation: %s\n", umi_status_text(status));
    return status == UMI_STATUS_OK ? EXIT_SUCCESS : EXIT_FAILURE;
}

Follow the code

commands, workbench, store and documents are separate owners with different responsibilities. The command registry names operations. The workbench contains the document views. The document store holds the working content, and the coordinator connects the existing services.

TRY checks each return value and sends a failure to the cleanup section. The cleanup section releases resources in reverse order. It is reached on both success and failure, so an early error does not skip the release steps.

intended.document_id records which document the first request belongs to. The second tab intentionally changes the active document. The next call returns Invalid State, and the example checks that the second tab remains active. It then reads the original draft and the saved file independently; the printed message alone is not the test.

Run it from an Applications development build

After configuring the Applications build, compile the example target. These commands use the existing Windows preset:

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& "C:\msys64\ucrt64\bin\cmake.exe" --build --preset windows-ucrt64-all-debug --target umicom-document-navigation-example --parallel 2
& ".\build\windows-ucrt64-all-debug\bin\umicom-document-navigation-example.exe"

On Linux, after configuring the existing headless development preset:

cmake --build build/headless-debug --target umicom-document-navigation-example --parallel 2
./build/headless-debug/bin/umicom-document-navigation-example

The expected output is:

Requested line 4, UTF-8 byte column 5.
The caret points to puts; navigation did not edit the source.
A different active tab rejected the old request and remained active.
The Notes draft and saved file are unchanged.

Use an installed Framework SDK

The same source directory includes a CMake project using find_package(UmicomFramework CONFIG REQUIRED). Set CMAKE_PREFIX_PATH to your Framework installation. For example, on Linux:

cmake -S framework/examples/editor_workflow -B build/notes-sdk -G Ninja -DCMAKE_PREFIX_PATH="$HOME/umicom/installed/framework-sdk"
cmake --build build/notes-sdk --parallel 2
ctest --test-dir build/notes-sdk --no-tests=error --output-on-failure

Its navigation executable is umicom-notes-navigation (with .exe on Windows). The other editor examples remain in this project, so the test command also checks them.

6. Check the operation in Studio

Use the same file through the toolbar, Navigate menu and Ctrl+G. Check the caret position and the full text after each request. Try an invalid number, a missing line, a long column and a read-only document. Open the form and cancel with a selection present: the selection should remain.

Keep a second draft open. Navigation must not save it or move its caret by mistake. Use the existing Report problem tools to record the exact starting document, request and result when something differs. Screenshots show where the caret appeared; a saved-file comparison checks that navigation did not write the file.

The form exposes the automation targets document.location.window, document.location.input, document.location.message, document.location.go and document.location.cancel. Tests should inspect the resulting document state, not just whether a control received a click.

Source navigation reads the complete supported draft synchronously. It is not a background search. On large files, copying and resolving that text can take time. The existing document size and ownership limits still apply.
