Native form transfer review

The shared GTK4 review widget shows the complete bounded history of one typed record before a host offers an import action. Link Umicom::form_bundle_review_gtk4 and include umicom/ui/gtk4/form_bundle_review.h.

  1. Create an immutable typed bundle review using the form transfer service. Do file reads and database work on a worker.
  2. On the GTK thread, call UmiFormBundleReviewGtk4New. Place the floating widget inside a scrolled window. It copies the summary, original metadata and read-only answers for every revision; the source review need not remain alive for display.
  3. Let the user inspect the revision pages. Historical units and labels come from the exact schema for that revision. Author labels are shown literally, without interpreting markup. Unsupported UTF-8 and secret fields are refused before publishing a widget.
  4. Keep the import button separate. When clicked, call UmiFormBundleReviewGtk4Confirmed. It refuses an unchecked confirmation box or a retired view and leaves the output unchanged.
  5. Authorize the selected database independently. Use the returned digest with the same retained immutable review in a storage worker. Never reread a newly selected file and apply the old confirmation.

Closing or changing the view

Removing a rooted widget, disposing it or calling UmiFormBundleReviewGtk4Retire permanently revokes future confirmation. Your host must also cancel any still-pending approval when the surrounding view closes. An accepted database write has its own lifetime and must report completion separately.

Expected behaviour

The latest revision is selected initially, every earlier revision remains available, and none of the record fields can be edited here. Selecting the confirmation box only expresses intent for the displayed history; it does not authenticate a person or grant access. Construction performs no database writes and no file access.
