Synthetic Healthcare profiles

Umicom Healthcare can compose a fictional administrative-profile editor from Framework. This page is separate from the access exercise and review notes. It is for invented training data, not real patient records or clinical care.

  1. Open Synthetic profiles in Healthcare. If the page is absent, the linked Framework SDK does not provide both Umicom::healthcare_forms and Umicom::form_record_editor_gtk4.
  2. Choose a local SQLite database by entering its full path. The directory must already exist. The database stores unencrypted answers.
  3. Enter a key such as SYN-000001. Keys must start with SYN- and contain exactly six digits after the hyphen.
  4. Choose New record. Enter a fictional display name and source description. Choose an explicit true or false fictional contact-permission answer. An unanswered value is different from false.
  5. Optionally add a valid calendar date, a preferred contact method and an administrative note. Unknown and not-applicable states are offered only where the schema permits them and require a reason.
  6. Enter a revision attribution and reason, then save. Reopen the same database and key to review the persisted answers. Saving an existing key as a new record is refused instead of overwriting it.

These labels and keys do not verify identity, legal consent or a relationship to the separate synthetic registry. No contact information is sent anywhere. No diagnosis, prescription, treatment, eligibility or funding decision is produced.

Reuse from another host

umi_healthcare_synthetic_profile_schema returns one process-lifetime immutable schema. Both native and browser form adapters can use it. Stored snapshots carry the schema identity and version. Changing interpretation requires a new semantic version and an explicit migration, rather than reinterpreting older answers silently.

The product places profile records under healthcare.profile.. Review notes retain their separate healthcare.review. namespace. A matching key across namespaces does not automatically link the records.

For storage behavior and failure recovery, see Save typed forms locally.
