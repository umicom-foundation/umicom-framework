Store editor indentation preferences

The editor library encodes a small, versioned record. The document library adds local file storage; neither operation changes a live document or application settings.

  1. Include umicom/editor/indentation_record.h for in-memory encoding and decoding. Link Umicom::editor.
  2. For file storage, include umicom/document/indentation_storage.h and link Umicom::document.
  3. Resolve a product path with UmiDocumentIndentationStoragePath. Passing an absolute base override isolates tests or portable hosts from the user's real data.
  4. Create the trusted parent directory when saving. Call UmiDocumentIndentationStorageSave with a validated width and spaces flag.
  5. Load with UmiDocumentIndentationStorageLoad. Apply the returned policy through the document owner only after checking that its current settings still match the user's review.
umicom.editor.indentation/1
width=4
spaces=1

The decoder accepts LF or CRLF and an optional final newline. Width is 1–16 and spaces is 0 or 1. Unknown versions, extra lines, reordered fields and malformed values are rejected. Failed decoding leaves the output policy unchanged.

Storage limits

Loads are capped at 128 bytes and require a regular absolute local file. Saves use exclusive staging and replacement; independent writers are last-writer-wins. Parent directories must be trusted and stable. This does not promise power-loss durability or preserve an arbitrary source file's permissions. Run file operations on a worker in interactive applications.

A missing file is a normal first-use condition. Keep the active policy on any load failure. Never silently rewrite a corrupt preference file during startup.
