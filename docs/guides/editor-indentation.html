Editor indentation

Indentation is the whitespace at the start of a source line. Studio uses its existing studio.editor.tab_width and studio.editor.insert_spaces settings to configure the shared document editor. The default is four columns with spaces. Widths from one through sixteen are supported.

Editing a document

  1. Open a writable source document and place the caret where indentation is needed.
  2. Press Tab. With spaces enabled, this inserts enough spaces to reach the next logical tab stop. For example, at column one with width four it inserts three spaces. With spaces disabled it inserts a literal tab.
  3. Select text and press Tab to indent the lines touched by the selection. The selected text is kept.
  4. Press Shift+Tab to remove one leading tab or up to the configured width of leading spaces from the selected lines or current line.
  5. Use Undo or Redo to reverse or repeat the edit. Save remains a separate action.

The Code Tools indent and outdent commands use the same preferences. Existing source is not reformatted when settings change. Ctrl+Tab keeps its normal navigation role.

For application authors

UmiDocumentCoordinatorSetIndentation copies a validated UmiEditorIndentation. The coordinator owns that policy; it does not read global settings or persist them. Studio applies its typed settings at UI creation and refresh through UmiStudioUiApplyEditorSettings.

UmiDocumentCoordinatorInsertIndentation acts on a particular open document and preserves its identity and Undo history. It does not activate an inactive tab. Canonical command clients can run umicom.document.insert-indentation without an argument.

Calling line-edit operations with a non-NULL UmiDocumentLineEditOptions retains their original explicit token behavior. With NULL options they use the coordinator policy. This lets a contributor implement a reviewed project-specific action without silently changing the user's preferences.

Native views and limits

Framework updates GtkSourceView's tab width, indent width and spaces setting, and supplies measured tab stops to the plain GtkTextView fallback. Both source views route Tab through the same document operation. Property refresh holds native view references and stops if its document binding is retired.

Logical tab stops count each Unicode scalar as one column and advance existing tabs to the next stop. They do not claim exact screen-cell width for combining marks, emoji sequences or wide characters. Only the affected UTF-8 prefix is examined by the standalone tab-stop helper; document edits validate the complete draft. This feature does not infer indentation from existing code or replace language-specific formatting.

Troubleshooting

  • A read-only document cannot be indented. Close an outstanding edit review before trying another edit.
  • Changing preferences does not modify source or create an Undo entry by itself.
  • Malformed settings are rejected instead of being silently truncated. Use a width between one and sixteen.
  • If a shared editor client changes the policy directly, refresh its native document views to update tab display.
