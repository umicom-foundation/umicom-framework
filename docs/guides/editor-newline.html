New lines in source documents

Framework source editors use the same document history for keyboard editing and commands. A line ending is the invisible character sequence separating lines: LF is one byte, while CRLF is two.

  1. Open a writable source document and place the caret after some indented text.
  2. Press Enter. The new line copies existing leading spaces and tabs before the caret. It does not add extra indentation after braces or interpret the programming language.
  3. Press Shift+Enter to insert a line ending without copying indentation.
  4. Use Undo to restore the previous text and selection. Save remains a separate action.

Selections and file formats

Enter replaces selected text, just like ordinary typing. It uses the ending of the line where that selection starts. A final line without an ending inherits the preceding line's ending. An empty or single-line document starts with LF. Mixed LF and CRLF files retain untouched endings. Malformed UTF-8, embedded zeros, bare CR endings and edits exceeding the 8 MiB working-copy limit are refused.

Using the service

Include umicom/document/newline.h and call UmiDocumentCoordinatorInsertNewline(documents, document_id, 1) on the document owner's thread. Pass zero as the last argument for a plain new line. This edits the named draft without activating another tab. The toolkit-neutral UmiEditorNewlineCreate returns an owned token; release it with UmiEditorNewlineFree.

When Enter cannot edit

Check that the document is writable and the editor still owns its window. Finish or cancel a pending replacement, completion review, clipboard read or save question, then retry. No fallback edit is applied after a refused managed command. Unmanaged text controls retain their normal toolkit behavior.
