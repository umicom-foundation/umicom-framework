Open several source documents

A selection of files can contain an unreadable item. Framework's opening plan records a separate outcome for each selected path, allowing a host to keep useful tabs open while explaining failures.

Use the document owner

  1. Include umicom/document/open_batch.h and link Umicom::document.
  2. Call UmiDocumentOpenBatchCreate with at most 32 absolute local paths. This copies the selection and performs no reads. Relative, missing or invalid paths are not interpreted as project commands.
  3. On the document owner's thread, call UmiDocumentOpenBatchStep once. An OK result means that one outcome was recorded. Inspect that item with UmiDocumentOpenBatchAt to determine whether it opened successfully.
  4. Yield to your event loop, then step again with the same coordinator. Keep the coordinator and its borrowed services alive. Never run steps concurrently or destroy the plan from a provider callback.
  5. Display the copied summary and individual results. NOT_FOUND from Step means no files remain. Destroy the plan when the report is no longer needed.

The existing coordinator resolves already-open paths. Opening the same source again selects its current tab; it does not reload over unsaved changes. Different spellings are compared through the coordinator's normal path rules. This does not establish that arbitrary symbolic links identify the same file.

Cancellation and partial results

Cancel marks pending files as cancelled and retains successful tabs. Cancellation cannot undo a read already running. A reentrant step or cancel during a provider callback returns BUSY. An invalid overall request, such as too many files, starts no work. Invalid individual members are recorded as failures while other members continue.

Opening files does not save documents, grant workspace trust or run a build. The host may yield between items; an individual synchronous provider read can still take time. Remote resource URIs are outside this local-path contract.

Studio workflow

  1. Choose File → Open and select several files using the native chooser.
  2. Wait for Studio to finish opening the selection. Successful sources appear as editor tabs.
  3. If any file fails, read the File opening results window. Fix permissions, select a supported text file or reduce the selection, then retry only the files that need attention.

Existing editor size and text encoding limits still apply. The results report describes opening, not compilation or project membership.
