Return to a source location

When you jump between source locations, the document coordinator remembers where you left and where you arrived. Studio presents this shared service as Navigate → Back and Navigate → Forward. It uses the working copies already open in the editor.

Try a return trip in Studio

  1. Open a source file containing several lines. Put the caret on its first line.
  2. Use Go to Line to visit another line. The document remains open and its text is unchanged.
  3. Choose Navigate → Back or press Alt+Left. The caret should return to the location you left.
  4. Choose Navigate → Forward or press Alt+Right. The caret should return to the later location.
  5. Open another file, use a Find in Files result, or cycle source tabs with Ctrl+Tab. Back can return across these jumps. A search result records one destination instead of adding a separate stop at the file's first line.

Command search also contains Navigate Back, Navigate Forward and Clear Navigation History. Back and Forward are available only when the corresponding history direction exists and the native editor is not waiting for a Paste, Save All or Close decision.

Understand what is remembered

History holds up to 64 locations in this coordinator's live documents. It stores document identity, line and byte column; it does not copy source text, save a file or change text undo/redo. A byte column counts UTF-8 bytes, which can differ from the number of visible characters. Landing inside a multi-byte character moves to that character's first byte.

Repeated adjacent positions coalesce. After moving Back, a new jump starts a new branch and replaces the old Forward path. A full history drops its oldest location. Moving the caret with the mouse does not add a history entry, but its latest position is captured when you leave using Back or Forward.

Locations follow the same open document through Save As. They resolve against its current draft, so later edits can change which text is on a recorded line. They are not permanent bookmarks, edit-aware anchors, a recent-files list or restart recovery. Clicking a tab directly is not itself recorded as a jump. Untitled and read-only documents can participate while they remain open.

Recover from an unavailable destination

  1. Read the reported status. A closed destination or a line removed by editing returns NOT_FOUND. The history cursor and active tab stay where they were.
  2. To open a closed saved file, use Reopen Closed Document separately. This reads its saved contents into a new working copy; it does not restore the old history identity.
  3. Use Clear Navigation History if old locations no longer help. This only clears location metadata. It does not close documents, discard text or clear text undo.
  4. If an action is busy, finish or cancel the existing editor decision. If a host reports a stale revision, read a fresh snapshot before making another explicit request.

Use the shared document owner

Include umicom/document/navigation_history.h and link Umicom::document. Use the coordinator already managing the application's sources. A revision is an observation token: it identifies the history state the caller saw, preventing an old UI request from navigating a changed timeline.

#include "umicom/document/navigation_history.h"

UmiStatus ReturnToPreviousSource(UmiDocumentCoordinator *documents)
{
    UmiDocumentNavigationHistorySnapshot history;
    UmiStatus status = UmiDocumentCoordinatorNavigationSnapshot(documents, &history);
    if (status != UMI_STATUS_OK) return status;
    if (history.busy) return UMI_STATUS_BUSY;
    return UmiDocumentCoordinatorTravel(documents, -1, history.revision, NULL);
}

The complete source example is examples/editor_workflow/location_history.c. Calls run on the coordinator's owning thread. The GTK adapter supplies matching availability, travel and clear functions through its existing editing binding. Applications need no additional history array.

Extend navigation safely

Framework's editor history also serves hosts outside the document coordinator. Use UmiEditorNavigationHistoryTravel with a callback that reaches the destination before returning success. If reaching it fails, leave the host unchanged and return that failure. History will keep its previous position and the caller's output untouched. Nested mutations are refused while the callback is active; the callback must not destroy its history owner.

Open, Go To, source cycling and successful search navigation collect optional location metadata. A capture failure, such as insufficient memory, does not turn a successful source operation into a failure. Hosts can inspect last_record_status to report that this jump was not recorded. Revision counters refuse exhaustion instead of reusing an earlier token. History is released with its coordinator and is not written to disk.
