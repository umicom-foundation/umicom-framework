Manage saved searches in a record workbench

Framework record workbenches can edit saved search definitions without mixing them with record answers. A managed search draft tracks unsaved edits, refuses a dirty close, and can be recovered from a private file. Temporary query controls remain available for trying conditions before deciding to save them.

Create a reusable search

  1. Open the workbench's local database. Set the temporary metadata query and answer conditions.
  2. Enter a saved-search key and title. Expand Edit a saved search with recovery.
  3. Select Start draft from current query. The managed editor copies those conditions. It is now an unsaved definition, independent of later temporary query changes.
  4. Edit its title, metadata text or conditions. Enter the attribution label and revision reason in the workbench, then select Save managed query draft.
  5. Wait for the completed save message. If you typed while saving, those later edits remain unsaved. Use the ordinary saved-search browser to open the published definition into the temporary query controls when you want to run it.

Edit an existing definition

  1. Enter the saved-search key and select Edit saved search by key.
  2. The workbench reads that definition on its storage worker. It refuses to overwrite a dirty managed draft. Edits made while the read runs also prevent replacement.
  3. Review and save the edited definition. If another writer changed its stored head, the save fails and your draft remains. There is no automatic overwrite or merge.

Keep and recover private work

  1. Enter an absolute path to a new recovery file, then select Keep a new query recovery copy. Its directory must already exist. Existing files are not replaced.
  2. The file contains the saved baseline and valid current definition in plaintext. Keeping it does not clear dirty state or save the definition into the database. Use a private location with appropriate access permissions.
  3. To recover, open the intended database, save or explicitly discard the current managed draft, enter the recovery path, and select Recover query draft.
  4. The workbench checks the historical baseline against the selected database and validates the exact form schema and record namespace. A later save still checks whether the stored head changed.

Closing and independent work

Save or explicitly discard both managed search edits and record-answer edits before closing. The managed editor's Discard button affects only the query draft. The record Discard action affects only answers. Invalid native text remains visible until corrected or explicitly discarded. Recovery captures valid typed values; it does not preserve incomplete numeric text.

Accepted writes finish even if the widget is retired. A host must keep processing the main context until UmiFormRecordEditorGtk4Busy becomes false, then release the workbench. A missing window does not cancel a database write already admitted.

Embedding and qualification

The shared Umicom::form_record_editor_gtk4 target includes the managed editor. Existing applications using this Framework component inherit its controls. Applications remain responsible for authorization, database selection, private-file policy and close confirmation. Saved queries are not permission rules.

cmake --build build/windows-ucrt64-debug --target umicom-managed-search-draft-test umicom-managed-search-recovery-test
ctest --test-dir build/windows-ucrt64-debug -R "^framework[.]structured_forms[.]editor[.]managed-search[.]" --output-on-failure --no-tests=error

These cases require SQLite and a GTK display. A missing display is a skip, not a pass. After automated qualification, exercise new, edit, save, reopen, recover and close through an application workbench.
