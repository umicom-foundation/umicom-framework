Browse saved searches in the native editor

The shared form record editor can list saved query definitions by title or key. The list belongs to the same connected database and the active form's exact namespace and version.

  1. Connect to your database. Enter a title fragment in Find saved search title or key, or leave it empty.
  2. Choose Find saved searches and wait for completion. Each row shows the title, key and stored revision.
  3. Choose Next saved searches when another page is available. Changing the title filter requires a new first-page search.
  4. Select a row and choose Open selected search. The stored head must still match the row you reviewed.
  5. Review the loaded conditions, then choose Search saved answers to run the query. Opening the definition does not search automatically or change your record draft.

When a selection is refused

A definition changed by another writer must be listed again before opening. A change to the title filter, selected row, result model or query controls during a read also refuses that incoming result. Keep your visible edits and explicitly retry when ready.

Unknown historical versions or damaged definitions fail discovery rather than producing an incomplete list. Hosts can register all trusted historical schemas with UmiFormRecordEditorGtk4SetHistoryCatalogue before connecting. Without that registration, discovery knows only the active schema.

Application integration

UmiFormRecordEditorGtk4FindSavedSearches starts an asynchronous read. UmiFormRecordEditorGtk4SavedSearchPage copies the completed page only while it still matches the visible result model and text filter. UmiFormRecordEditorGtk4OpenSavedSearchResult opens an index from that page. These calls share the editor's worker, busy state and close protection.

Use the GTK owner thread. Keep the registered schemas alive until every worker finishes. The selection is a reviewed data reference, not permission to access a database. Applications still own authorization and database-path decisions.

Discovery supports 16 rows per page and 256 saved definitions per bounded scan. Title matching is case-sensitive. There is no fuzzy search, remote synchronization, query migration or automatic refresh.
