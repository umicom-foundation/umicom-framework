Check session time when record work starts

A background job can wait before reaching storage. A timestamp captured when the user clicked Save may be stale by the time the job starts. The record host's current-time entry points read its trusted clock after acquiring the shared host lock, then check the current session and policy.

Use the current-time interface

  1. Include umicom/data/record_host_clock.h and link the existing Umicom::record_host library. Ordinary host creation uses the system monotonic clock for these methods.
  2. After authenticating a registered, enabled identity, call umi_record_host_issue_current_session with a lifetime in nanoseconds. This uses the same clock domain as later current-time record operations.
  3. Dispatch document methods ending in _current, such as umi_record_host_append_current, or their typed-form equivalents. Each method copies the request and replaces its time with a fresh reading under the host lock. The original request stays unchanged.
  4. Preserve unsaved edits when the result is PERMISSION_DENIED, CANCELLED or UNAVAILABLE. An expired session must be replaced through trusted authentication; do not retry with a captured earlier timestamp.

Clock domains

The default monotonic clock measures elapsed time within the running system. Its values are not UTC or calendar dates. Session issuance, expiry, access receipts and the recorded timestamp produced by these current-time operations use that same domain. Do not format those values as human dates. An optional observed timestamp remains caller-provided record content and does not control access.

The existing explicit-time host APIs remain available for trusted callers managing their own clock domain. Do not mix their sessions with current-time operations unless both use the same domain. Persistent UTC event times and cross-device clock reconciliation need a separately defined record-time contract.

Controlled clock providers

umi_record_host_create_with_clock copies a trusted UmiClock descriptor. Its state remains borrowed until the final host reference is released. The host does not dispose it. This supports controlled hosts and deterministic regression cases.

The monotonic callback runs while the shared host lock is held. It must be thread-safe, bounded and must never call back into the same host. A zero reading returns UNAVAILABLE. A backward reading is refused by session validation. Retired hosts refuse admission before invoking the clock.

Qualify the behavior

cmake --build build --target umicom-record-host-clock-test
ctest --test-dir build -R "^framework\.record_host\.clock\." --output-on-failure --no-tests=error

The regression sources use controlled clock readings to check stale requests, expiry, rollback, unavailable time, unchanged input and output, retirement and all document/form entry points. They are separate from product login and native interface qualification.
