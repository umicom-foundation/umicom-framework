Find and inspect typed records

The shared native form record editor can search saved record metadata and inspect earlier answers. Search and history never save a form or replace an unsaved draft.

Find a saved record

  1. Connect a local database. Enter a search phrase, or leave it empty to list the editor's configured record namespace.
  2. Choose Find records. Search is a case-sensitive substring of record key, source, actor label or revision reason. It does not search answer text.
  3. Select a row explicitly, then choose Open selected listed record. Resolve current unsaved edits first. The open rechecks the exact listed revision; if another writer changed it, refresh the search.
  4. Use Next matching records for another page. The catalogue binds pages to one metadata snapshot. Changed search text or stored heads require a fresh search.

A page has at most 16 rows. The bounded scan permits 256 heads in the namespace and 32,768 storage rows. Exceeding a bound reports a capacity refusal instead of presenting a partial list as complete. Namespace filters are not authorization.

Inspect an earlier revision

  1. Open an existing typed record and choose Refresh history.
  2. Select a revision, then choose Inspect selected revision. The editor verifies its stored content and matching schema before displaying copied labels.
  3. Read the stored revision number, source and actor label above the snapshot. Values retain their units; Unknown and Not applicable retain their reasons. Attribution labels are not proof of authenticated identity.
  4. Continue editing your current form if needed. Inspection does not replace it, mark it saved or approve a clinical or financial decision.
  5. Choose Older history to read older metadata. A changed head refuses continuation; refresh history to start again.

Corrupt, missing or incompatible historical content is refused. The editor does not silently migrate old schemas or restore an old revision over current data. Keep the original schema available when a product deliberately supports historical schema versions.

Use the installed example

After installing the Framework SDK, configure examples/form_records as an independent CMake project with CMAKE_PREFIX_PATH pointing to that installation. Its umicom-form-record-example target uses a memory store and prints:

Saved reviewed revision 3 at Shelf B; historical revision 1 remains Shelf A.

The optional umicom-form-record-native target uses the installed GTK editor. Enter an absolute private database path in an existing directory, create a fictional equipment record and try its search, history and review controls. Storage is ordinary plaintext; use fictional records.

Compose a read-only snapshot

Link Umicom::form_inspect_gtk4 and call UmiStructuredFormInspectGtk4New with a schema and captured form. The returned floating widget contains selectable labels, with no edit or save actions. It owns the displayed strings, so the input form and schema need remain valid only until the call returns. Required answers may be missing because inspection validates a draft, not a submission. Secret schemas and invalid UTF-8 are refused.
