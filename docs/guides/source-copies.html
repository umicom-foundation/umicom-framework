Save a separate source copy

A copy exports the draft visible in an editor. It does not rename the source, mark it saved, change the active tab or clear Undo. Use ordinary Save to update the source itself.

  1. Capture a named document with UmiDocumentCoordinatorCaptureCopy on its owner thread.
  2. Read UmiDocumentCopyInspect to describe the captured source to the user.
  3. Ask the user to choose a new absolute local filename in an existing directory.
  4. Call UmiDocumentCopyWriteNew and inspect both its status and result.
  5. Destroy the copy when finished. It owns its bytes independently of the editor.

What is captured

The visible draft and selected UTF-8, UTF-8 BOM or UTF-16 encoding are captured before any file dialog. Existing line endings and a missing final newline remain unchanged. Later typing is not included. Read-only sources may be copied. The copy is bounded by the existing document text limit.

Existing files and failures

Only a new file can be created. An existing filename, including a symbolic link, is refused without replacement. Choosing the original source path is refused even if that source file is currently missing. Relative paths and dot segments are rejected. Windows paths must be ordinary local drive paths; network UNC paths and device names are not supported by this writer.

If creation succeeds but writing fails, the new file remains for inspection. The result records creation and the byte count accepted. Choose a different name or inspect the failed file; the service never deletes it automatically. Parent-directory aliases can be followed, so select a directory you control. This operation does not enforce project-directory confinement.

Studio workflow

  1. Focus the source tab you want to copy.
  2. Choose File → Save Copy… or find Save Copy in the command palette.
  3. Choose a new filename. Studio suggests a name beginning with copy-.
  4. Read the result notification. Your original tab and its unsaved marker remain unchanged.

Native file selection is asynchronous; output writing is synchronous and can wait for storage. Native host retirement cancels a pending chooser's write. The snapshot itself can outlive the source document.
