Editing source files in Umicom Studio

You are updating Umicom Notes. The programme currently displays three saved notes, and you want it to display five. That small change is a useful way to practise selecting text, copying it, reversing an edit and saving the result.

An editor draft is the text you are working on in a tab. The saved file is the version stored on disk. Editing, Cut, Paste, Undo and Redo change the draft. Save is a separate operation that writes it to the file.

1. Practise with a Notes project

Create a disposable C23 Console Application with File → New Project, or open an existing practice project through Open Workspace Folder. Give it the application name Umicom Notes and open src/main.c. Do not replace an unrelated working project.

Enter the following programme and save it. The variable savedNotes holds an unsigned whole number. %u tells printf how to display that number, and \n starts a new output line.

#include <stdio.h>

int main(void)
{
    unsigned savedNotes = 3U;
    printf("Umicom Notes: %u saved notes\n", savedNotes);
    return 0;
}

Click inside the source editor before using the main Edit menu. Its commands operate on the active source document. Shortcuts used inside other text fields, such as a search box, retain those fields' normal editing behaviour.

CommandWhat it changesTry it in Notes
Undo · Ctrl+ZReturns to an earlier draft in the same document.Change 3U to 5U, then Undo. The source should show 3U again.
Redo · Ctrl+Y or Ctrl+Shift+ZReapplies the undone draft change.Redo the edit and check that 5U returns.
Copy · Ctrl+CCopies selected text; leaves the draft unchanged.Select savedNotes and Copy it.

The caret is the insertion point. A selection is a highlighted range. Copy and Cut need a nonempty selection; Delete Selection does nothing when no text is selected. Read-only source permits Copy and Select All but refuses changes and history traversal. A document can become read-only after a menu was opened, so the operation checks again when it runs.

Undo and Redo use the same document history as the editor bar. A new edit after Undo begins a new history path and removes the old Redo path. History is bounded to 32 entries and 16 MiB per stack; older entries are discarded as those limits are reached. Closing the document discards its in-memory history. Keep important versions in saved files and Git.

2. Understand a delayed Paste

The clipboard is shared with other applications. Its text may arrive after you request it. Umicom captures the destination document, its draft and the selected range before asking for the clipboard. It does not wait and then choose whichever tab happens to be active.

Switching to a second tab does not redirect the incoming text. Provided the original destination is still unchanged, Paste edits that original draft and leaves the second tab active. If you change the original draft, its saved revision, path, caret or selection before the text arrives, Umicom refuses the old request. Select the intended destination and Paste again. Closing the target or detaching the window also prevents a late reply from changing another document.

One clipboard read can be pending for each editor binding. Further Paste requests report Busy until it finishes. Unavailable clipboard text and unsupported input leave the draft unchanged. Plain UTF-8 text is supported, up to the document's 8 MiB limit. Images, file drops and rich-text formatting are not inserted by this command.

GTK receives the clipboard data before the document limit can be checked. This limit prevents an oversized edit, but it is not a bound on GTK's temporary transfer allocation. Clipboard contents are not automatically added to application logs.

3. Save and build the intended version

Return to src/main.c, confirm it contains 5U and Save. Then build and run the Notes project. Its output should read Umicom Notes: 5 saved notes. Undo without another Save changes only the open draft; the compiler still reads the saved file.

Keep a second document open with an unsaved comment while practising. Check that editing the source file never saves, replaces or discards that other draft. Use Report problem to collect a short interaction log and a screenshot when a control does not behave as expected. State which tab was active, what was selected, the exact action and the resulting file or draft.

4. Use the same editing contracts in another application

A contract describes what a function accepts, what it returns and who owns its data. The document coordinator is the single owner of edits, history and saved-file operations. A graphical adapter translates a menu choice or keyboard action into a call to that owner; it does not maintain a second document store.

All calls below run on the document owner's thread. A thread is one execution path through the programme. These calls do not make a background worker or lock the filesystem. GTK clipboard completion returns to the GTK thread before applying the captured edit.

UmiDocumentEditCommandFromIdRecognises the existing edit.* identifiers. Unknown names return Not Found without changing the output.The example maps edit.paste to UMI_DOCUMENT_EDIT_PASTE.
UmiDocumentEditState and UmiDocumentCoordinatorGetEditStateReturn copied text/selection lengths and read-only/Undo/Redo availability without selecting or saving.The example checks that Select All selected the entire source.
UmiDocumentCoordinatorSelectAllSelects a document by numeric identity; does not activate another tab.The example first selects all, then narrows its selection to the digit.
UmiDocumentCoordinatorPrepareEditCaptures a complete owned draft, its target and revisions. Preparation changes nothing.Prepare before starting a delayed clipboard request.

Count bytes carefully

The letter A occupies one UTF-8 byte, but £ occupies two and some symbols occupy four. The public selection offsets count bytes. GTK character offsets must be converted before they are placed in the view model. Selection endpoints must not divide a multi-byte character. The coordinator refuses malformed UTF-8 and embedded zero bytes instead of silently altering the replacement.

Connect a GTK application

UmiGtk4AdapterBindDocumentEditing borrows an existing coordinator and a completion callback. Call it after the adapter window has been prepared. Use UmiGtk4AdapterDocumentCommandEnabled to display availability, and UmiGtk4AdapterDocumentCommand to execute the chosen identifier. Keep the coordinator and callback context alive until the binding is removed.

/* adapter and documents are already created and remain owned by the host. */
UmiStatus status = UmiGtk4AdapterBindDocumentEditing(adapter, documents,
    OnEditingCompleted, applicationContext);
if (status == UMI_STATUS_OK &&
    UmiGtk4AdapterDocumentCommandEnabled(adapter, "edit.paste")) {
    status = UmiGtk4AdapterDocumentCommand(adapter, "edit.paste");
}
/* Before destroying documents or applicationContext: */
(void)UmiGtk4AdapterBindDocumentEditing(adapter, NULL, NULL, NULL);

This fragment belongs inside an existing host. The native test fixture supplies complete adapter/window setup and cleanup. Rebinding or window destruction cancels and invalidates outstanding reads. Native source-editor clipboard signals and Ctrl+Z/Ctrl+Y/Ctrl+Shift+Z use the same owner. Other entry fields are not replaced by the source-editor binding.

These commands cover the main Edit menu, editor-bar history buttons and standard source-editor shortcuts. Drag-and-drop, primary-selection/middle-button paste and toolkit context-menu enablement are separate interaction paths. Test them separately rather than assuming that one successful clipboard test covers them all.

5. Build the complete Notes exercise

The programme below uses the actual Framework document store, view model and coordinator. It creates its own temporary file, captures a selection, changes tabs, applies the edit to the original target and verifies Undo, Redo and an explicit Save. It supplies the delayed replacement directly so it can run from a terminal without reading your system clipboard.

Windows

Set-Location "C:\umicom\Umicom-Applications"
$env:Path = "C:\msys64\ucrt64\bin;$env:Path"
& "C:\msys64\ucrt64\bin\cmake.exe" --build --preset windows-ucrt64-all-debug --target umicom-document-editing-example --parallel 2
& ".\build\windows-ucrt64-all-debug\bin\umicom-document-editing-example.exe"

cd "$HOME/umicom/Umicom-Applications"
cmake --build --preset headless-debug --target umicom-document-editing-example --parallel 2
./build/headless-debug/bin/umicom-document-editing-example

Use an already configured Applications checkout. The build guide explains configuration. A nonzero exit code means a check failed. The expected output is:

The source changed from 3 to 5. The second draft stayed active and unchanged.
Undo and Redo used the same document history.
Explicit Save wrote the expected source; reading it back confirmed the result.

The complete source

File: framework/examples/editor_workflow/edit_commands.c

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/editor_workflow/edit_commands.c
 *
 * PURPOSE:
 *   Edit a Notes source document, keep a second draft intact, undo and redo the
 *   change, then explicitly save and read the intended file back.
 *
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "umicom/document/edit.h"
#include "umicom/platform/filesystem.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#ifdef _WIN32
#include <process.h>
#define PROCESS_ID _getpid
#else
#include <unistd.h>
#define PROCESS_ID getpid
#endif

/* A copied view string belongs to the caller until FreeText releases it. */
static UmiStatus CheckDraft(UmiUiDocumentViewModel *views, const char *viewId,
    const char *expected)
{
    char *text = NULL;
    size_t bytes = 0U;
    UmiStatus status = UmiUiDocumentViewModelCopyText(views, viewId, &text, &bytes);
    if (status == UMI_STATUS_OK &&
        (bytes != strlen(expected) || memcmp(text, expected, bytes) != 0))
        status = UMI_STATUS_INVALID_STATE;
    UmiUiDocumentViewModelFreeText(text);
    return status;
}

int main(void)
{
    const char *source = "#include <stdio.h>\nint main(void) { puts(\"Umicom Notes: 3 saved notes\"); return 0; }\n";
    const char *updated = "#include <stdio.h>\nint main(void) { puts(\"Umicom Notes: 5 saved notes\"); return 0; }\n";
    const char *otherDraft = "Review the note search before the next build.\n";
    UmiCommandRegistry *commands = NULL;
    UmiUiWorkbench *workbench = NULL;
    UmiDocumentStore *store = NULL;
    UmiDocumentCoordinator *documents = NULL;
    UmiDocumentEditPlan *plan = NULL;
    UmiStatus status = UMI_STATUS_OK;
    char temp[UMI_PATH_CAPACITY], root[UMI_PATH_CAPACITY] = {0};
    char path[UMI_PATH_CAPACITY], leaf[100];
    char sourceView[UMI_UI_ID_CAPACITY], otherView[UMI_UI_ID_CAPACITY];
    int ownsDirectory = 0;
    char *saved = NULL;

    /* TRY stops at the first failed contract and still visits cleanup. */
#define TRY(call) do { status = (call); if (status != UMI_STATUS_OK) goto cleanup; } while (0)
    (void)snprintf(leaf, sizeof leaf, "umicom-notes-edit-%ld", (long)PROCESS_ID());
    TRY(umi_fs_temp_directory(temp, sizeof temp));
    TRY(umi_fs_join(root, sizeof root, temp, leaf));
    if (umi_fs_exists(root)) { status = UMI_STATUS_ALREADY_EXISTS; goto cleanup; }
    TRY(umi_fs_make_directories(root));
    ownsDirectory = 1;
    TRY(umi_fs_join(path, sizeof path, root, "notes.c"));
    TRY(umi_fs_write_text(path, source));
    TRY(umi_command_registry_create(&commands));
    TRY(umi_ui_workbench_create("umicom.notes.editing", commands, &workbench));
    TRY(umi_document_store_create(&store));
    TRY(umi_document_coordinator_create(store, workbench, NULL, &documents));
    TRY(umi_document_coordinator_open(documents, path, sourceView, sizeof sourceView));

    UmiUiDocumentViewModel *views = umi_ui_workbench_documents(workbench);
    UmiDocumentWorkingCopySnapshot target, active;
    UmiUiDocumentViewSnapshot view;
    TRY(umi_document_coordinator_active_snapshot(documents, &target));
    UmiDocumentEditCommand command;
    TRY(UmiDocumentEditCommandFromId("edit.paste", &command));
    if (command != UMI_DOCUMENT_EDIT_PASTE) { status = UMI_STATUS_INVALID_STATE; goto cleanup; }
    TRY(UmiDocumentCoordinatorSelectAll(documents, target.document_id));
    UmiDocumentEditState editState;
    TRY(UmiDocumentCoordinatorGetEditState(documents, target.document_id, &editState));
    if (editState.selection_bytes != strlen(source)) { status = UMI_STATUS_INVALID_STATE; goto cleanup; }
    TRY(umi_ui_document_view_model_find(views, sourceView, &view));
    /* This ASCII digit occupies one byte. General UTF-8 selections must end
     * on complete characters, even when one character uses several bytes. */
    const char *digit = strstr(source, "3 saved");
    if (digit == NULL) { status = UMI_STATUS_INVALID_STATE; goto cleanup; }
    view.cursor_offset = (size_t)(digit - source);
    view.selection_length = 1U;
    TRY(umi_ui_document_view_model_upsert(views, &view));
    TRY(UmiDocumentCoordinatorPrepareEdit(documents, target.document_id, &plan));
    const char *selection = NULL;
    size_t selectedBytes = 0U;
    TRY(UmiDocumentEditPlanSelection(plan, &selection, &selectedBytes));
    if (selectedBytes != 1U || selection[0] != '3') {
        status = UMI_STATUS_INVALID_STATE; goto cleanup;
    }

    /* Model a user changing tabs while clipboard text is being delivered.
     * The example supplies that text directly; it does not read the clipboard. */
    TRY(umi_document_coordinator_new(documents, "Review notes", otherView, sizeof otherView));
    TRY(umi_ui_document_view_model_find(views, otherView, &view));
    view.dirty = 1;
    TRY(UmiUiDocumentViewModelUpsertText(views, &view, otherDraft, strlen(otherDraft)));
    TRY(umi_document_coordinator_active_snapshot(documents, &active));
    TRY(UmiDocumentCoordinatorSyncDocument(documents, active.document_id));
    TRY(UmiDocumentCoordinatorApplyEdit(documents, plan, "5", 1U));
    UmiDocumentEditPlanDestroy(plan);
    plan = NULL;
    TRY(CheckDraft(views, sourceView, updated));
    TRY(CheckDraft(views, otherView, otherDraft));
    TRY(umi_document_coordinator_active_snapshot(documents, &active));
    if (strcmp(active.view_id, otherView) != 0) { status = UMI_STATUS_INVALID_STATE; goto cleanup; }
    puts("The source changed from 3 to 5. The second draft stayed active and unchanged.");

    TRY(UmiDocumentCoordinatorUndo(documents, target.document_id));
    TRY(CheckDraft(views, sourceView, source));
    TRY(UmiDocumentCoordinatorRedo(documents, target.document_id));
    TRY(CheckDraft(views, sourceView, updated));
    puts("Undo and Redo used the same document history.");

    /* Draft operations do not write the file. Saving is an explicit step. */
    TRY(umi_fs_read_text(path, &saved, NULL));
    if (strcmp(saved, source) != 0) { status = UMI_STATUS_INVALID_STATE; goto cleanup; }
    umi_fs_free_text(saved);
    saved = NULL;
    TRY(UmiDocumentCoordinatorSaveAs(documents, target.document_id, path));
    TRY(umi_fs_read_text(path, &saved, NULL));
    if (strcmp(saved, updated) != 0) { status = UMI_STATUS_INVALID_STATE; goto cleanup; }
    TRY(CheckDraft(views, otherView, otherDraft));
    puts("Explicit Save wrote the expected source; reading it back confirmed the result.");

cleanup:
    umi_fs_free_text(saved);
    UmiDocumentEditPlanDestroy(plan);
    umi_document_coordinator_destroy(documents);
    umi_document_store_destroy(store);
    umi_ui_workbench_destroy(workbench);
    umi_command_registry_destroy(commands);
    if (ownsDirectory) {
        UmiStatus removed = umi_fs_remove_tree(root);
        if (status == UMI_STATUS_OK) status = removed;
    }
    if (status != UMI_STATUS_OK) fprintf(stderr, "Notes editing: %s\n", umi_status_text(status));
    return status == UMI_STATUS_OK ? EXIT_SUCCESS : EXIT_FAILURE;
}

Follow the programme in order

The first calls create the command registry, workbench, document store and coordinator. The file is opened through the existing local provider. Select All demonstrates the copied edit-state query, and the next update narrows the selection to the digit.

PrepareEdit creates a private capture. The selected pointer is borrowed from that capture; its explicit length prevents an accidental read past the selection. Opening a second draft models the delay between a clipboard request and its reply. ApplyEdit uses the captured numeric document identity, not the active tab.

The exercise checks both drafts and the active selection before traversing history. It then reads the file to confirm that editing has not saved anything. Only the explicit SaveAs call writes the intended file. A final read checks the bytes that were actually saved. Cleanup releases the plan before its owners and removes only the temporary directory created by this run.

7. Check the operation, not just the click

Repeat the Notes exercise through the Edit menu and the source-editor shortcuts. Check the entire draft, the saved file and the second document. Try a read-only document, an empty selection and a new edit after Undo. A build should use the version you explicitly saved.

The core tests can supply a delayed replacement deterministically. They prepare a capture, change the destination and then attempt completion. The native tests use real GTK controls and the system clipboard, so run them in a disposable desktop test session. They use toolkit signals, not operating-system mouse injection. An external test timeout is still needed if a native callback stops responding.

To understand a failure, retain the test output and record the starting document, selected range, exact action and expected result. Never include private clipboard text in a defect report unless it is necessary and you have permission to share it.
