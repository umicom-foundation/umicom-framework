Stable document tabs in GTK4 applications

A tab's identifier describes the document; its button is the live interaction target. Recreating a button during a routine refresh can interrupt a pointer gesture or lose keyboard focus even when the replacement looks identical. Framework's keyed tab strip keeps surviving buttons in place.

  1. Include umicom/ui/gtk4/workstation/tab_strip.h and link the existing Umicom::ui_gtk4 target.
  2. Create the strip with UmiGtk4TabStripCreate, a selection handler and application context. The returned GTK widget has a floating reference; parent it using normal GTK ownership. The optional context destructor runs at finalization.
  3. For each presentation update, provide ordered UmiGtk4TabStripItem records with stable unique IDs, titles, optional full-path tooltips and at most one selected item. Call UmiGtk4TabStripSync on the GTK owning thread. Input strings are copied before notification-capable changes.
  4. Keep document text and save policy in the application's document service. The strip selects an identity; it does not load files, save edits or enable execution.
  5. Call UmiGtk4TabStripInvalidate before releasing a borrowed application owner. A weak or generation-checked application binding remains appropriate: a retained native widget can outlive the window's functional lifetime.

Refresh and error behavior

The strip preserves buttons for unchanged IDs, updates changed titles and selection styles, reorders surviving buttons, and removes departed IDs. Horizontal scrolling handles overflow. Long captions are ellipsized; full tooltips remain available. Invalid snapshots are rejected before native mutation. Reentrant synchronization returns BUSY; retirement or external reparenting during a notification returns CANCELLED. Cancellation can leave a partial presentation, so the owner must resolve its current lifetime before retrying. Synchronization never activates a tab on the user's behalf.

Verify the interaction boundary

The framework.ui_workstation.tab_strip.* scenarios check stable identity, focus, selection styling, reordering, invalid input, retired controls, reentrant notifications, external child detachment and horizontal overflow. Studio's first-use journeys additionally exercise coordinator-owned text, repeated switching, saving and isolated PNG capture. Missing graphical access is reported as a skip. Native pointer input and visual review complement these widget-level checks.

Use UmiGtk4TabStripFind only while the strip is alive. It returns a borrowed current button, not permanent authority to dispatch actions. A retained removed button must remain inert.
