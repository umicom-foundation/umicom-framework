Saving several documents in Umicom Studio

A project often has several open source files. You might change a function in notes.c and write its declaration in a new notes.h tab. Save All lets you save both without moving between the tabs yourself.

A draft is the text currently open in the editor. A saved file is the copy stored at a particular path. A draft can exist before it has a filename. Save All therefore needs to know both which document you mean and where it should be written.

1. Save a Notes source file and a new header

Open a practice Umicom Notes project. Use a folder that contains no important work. Open a named source file and make a small change, such as changing the number returned by a note-count function. Keep the modified file open.

Choose File → New to create another draft. Enter the declaration int CountNotes(void);. This second draft has text but no destination yet.

Choose File → Save All. Named documents use their existing paths. When the sequence reaches the new header, a filename chooser identifies that document. Choose a suitable local destination, such as include/notes.h in an existing include directory, and accept it. Review any replacement question carefully when selecting an existing file.

Studio reports the number of completed saves. Open the files through the file manager or another reader and check their contents. Saving a header does not automatically add it to a build target, and saving source does not compile it. Build and Test remain separate commands.

2. Understand cancellation and partial saves

Save All processes one document at a time. If it saves notes.c and you then cancel the filename chooser for notes.h, the first file stays saved. The header stays open and unsaved. The remaining documents are not processed by that run.

This is why a report may say one saved, two remaining. It is not an all-or-nothing transaction. After correcting a problem, start a fresh Save All run; documents that are already clean do not need another write.

SituationWhat to expect
You select a different tab while input is being collected.The original document identity remains the target. The new active tab is not substituted.
The intended document is closed or given another path.The old request stops instead of writing to a different document or destination.
The same intended draft is edited before its turn.Its latest text is saved when its own step runs. The session captures document identities, not frozen text.
A new document is opened after Save All starts.That new document belongs to the next run. Completion describes the original captured list.
A saved file changed outside Studio.The existing conflict-aware saver checks it. Resolve the difference rather than forcing an overwrite.
A document is read-only or its destination cannot be written.The run stops with an explanation. The open draft is retained. A provider failure can leave the destination uncertain; inspect that file before retrying.
Another Save All or clipboard read is already pending.A new Save All request reports Busy instead of queuing a second competing sequence.

The interface returns to its event loop between documents. Each file write itself is synchronous: slow storage can still delay that step. Cancel cannot interrupt or reverse a write already executing. Closing or rebinding the editing host cancels later work and prevents callbacks from reaching its old application context.

3. Reuse Save All in another application

The document coordinator already owns document identity, drafts, history and saving. A save session only records a list of pending document identities and its progress. It does not create another document store, write files directly or select tabs to find its destination.

ContractPurposeUse in the example
UmiDocumentSaveSessionCreateCapture currently pending document identities and paths without writing. The caller owns the returned session; the coordinator is borrowed.Create the session after both Notes drafts are ready.
UmiDocumentSaveSessionProgressCopy the phase, saved/remaining counts and current document description.Inspect the phase before taking the next step.
UmiDocumentSaveSessionStepProcess at most one document or pause for a filename. An OK result alone is not whole-run completion.Save the named source, then reach NEEDS_PATH for the header.
UmiDocumentSaveSessionProvidePathSupply an explicitly chosen absolute filename for the waiting untitled document. Existing Save As checks and overwrite semantics apply.Supply a new header path inside the exercise directory.
UmiDocumentSaveSessionCancelPrevent remaining steps without discarding drafts or rolling back files already saved.Use during cleanup or when a user cancels a chooser.
UmiDocumentSaveSessionDestroyRelease the session and its copied metadata; do not destroy its borrowed coordinator.Release before destroying the document services.

Read the phase before continuing

PhaseNext action
READYCall Step once, then inspect progress again.
NEEDS_PATHAsk the user for a destination, or cancel. Do not repeatedly call Step while waiting.
COMPLETEReport the successful saves. The same session cannot acquire documents opened later.
FAILEDKeep the original status and current filename visible. Retain drafts and start a fresh run after resolving the cause.
CANCELLEDStop requesting filenames and saves. Earlier completed saves remain valid.

Run these functions on the document owner’s thread. Keep the coordinator alive for the session lifetime, and never destroy either object from a provider callback while a call is executing. A session is not a lock against another process editing the filesystem.

Connect a GTK host

The existing editing binding supplies the coordinator. The GTK adapter adds filename collection and scheduling; an application supplies a completion callback for its own status area.

/* The adapter and documents already belong to the application. */
UmiStatus status = UmiGtk4AdapterBindDocumentEditing(
    adapter, documents, OnEditCompleted, applicationContext);
if (status == UMI_STATUS_OK && !UmiGtk4AdapterDocumentSaveAllBusy(adapter)) {
    status = UmiGtk4AdapterDocumentSaveAll(
        adapter, OnSaveAllCompleted, applicationContext);
}
/* An explicit Cancel command may call this between owner-thread steps. */
(void)UmiGtk4AdapterCancelDocumentSaveAll(adapter);
/* Before releasing documents or applicationContext: */
(void)UmiGtk4AdapterBindDocumentEditing(adapter, NULL, NULL, NULL);

This fragment shows where an existing host connects the service. The runnable example below does not open a GTK window; it demonstrates the same document-saving sequence with its own temporary filenames. The native test fixture supplies complete adapter setup, scheduling and teardown.

4. Run the complete C example

The programme creates two temporary Notes source documents, saves them through a single session and reads both files back to verify the result. It also checks that the active document has not changed. The temporary folder is removed at the end; your existing projects are not used.

/*-----------------------------------------------------------------------------
 * Umicom Framework
 * File: examples/editor_workflow/save_all.c
 *
 * PURPOSE:
 *   Save the two source documents of an Umicom Notes exercise using the real
 *   Framework coordinator. A header starts untitled; the caller supplies its
 *   filename at the same boundary used by the graphical Save All workflow.
 *
 * AUTHOR AND ORGANISATION: Sammy Hegab, Umicom Foundation
 * LICENCE: MIT
 *---------------------------------------------------------------------------*/
#include "umicom/document/save_session.h"
#include "umicom/document/local_provider.h"
#include "umicom/platform/filesystem.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#ifdef _WIN32
#include <process.h>
#define PROCESS_ID _getpid
#else
#include <unistd.h>
#define PROCESS_ID getpid
#endif
#define REQUIRE(x) do { if (!(x)) { fprintf(stderr, "Line %d: %s\n", __LINE__, #x); goto cleanup; } } while (0)

/* The view contains the editor draft. Updating it is deliberately separate
 * from saving: a successful edit must not imply that a file was written. */
static UmiStatus SetDraft(UmiUiWorkbench *workbench, const char *viewId, const char *text)
{
    UmiUiDocumentViewSnapshot view;
    UmiUiDocumentViewModel *views = umi_ui_workbench_documents(workbench);
    UmiStatus status = umi_ui_document_view_model_find(views, viewId, &view);
    if (status != UMI_STATUS_OK) return status;
    view.dirty = 1;
    return UmiUiDocumentViewModelUpsertText(views, &view, text, strlen(text));
}

/* Read back independently. A Save request is not proof that the desired bytes
 * reached this file; the comparison below checks the observable result. */
static int FileEquals(const char *path, const char *expected)
{
    char *text = NULL; size_t length = 0U;
    UmiStatus status = umi_fs_read_text(path, &text, &length);
    int same = status == UMI_STATUS_OK && length == strlen(expected) &&
        memcmp(text, expected, length) == 0;
    free(text);
    return same;
}

int main(void)
{
    UmiCommandRegistry *commands = NULL;
    UmiUiWorkbench *workbench = NULL;
    UmiDocumentStore *store = NULL;
    UmiDocumentCoordinator *documents = NULL;
    UmiDocumentSaveSession *session = NULL;
    char temp[UMI_PATH_CAPACITY], root[UMI_PATH_CAPACITY], leaf[96];
    char sourcePath[UMI_PATH_CAPACITY], headerPath[UMI_PATH_CAPACITY];
    char sourceView[UMI_UI_ID_CAPACITY], headerView[UMI_UI_ID_CAPACITY];
    const char *sourceText = "/* Umicom Notes: count the stored notes. */\nint CountNotes(void) { return 2; }\n";
    const char *headerText = "/* Umicom Notes public declaration. */\nint CountNotes(void);\n";
    int created = 0, result = 1;

    /* Use an isolated practice directory. Never overwrite a real project. */
    REQUIRE(umi_fs_temp_directory(temp, sizeof(temp)) == UMI_STATUS_OK);
    REQUIRE(snprintf(leaf, sizeof(leaf), "umicom-notes-save-all-%ld", (long)PROCESS_ID()) > 0);
    REQUIRE(umi_fs_join(root, sizeof(root), temp, leaf) == UMI_STATUS_OK);
    REQUIRE(!umi_fs_exists(root));
    REQUIRE(umi_fs_make_directories(root) == UMI_STATUS_OK); created = 1;
    REQUIRE(umi_fs_join(sourcePath, sizeof(sourcePath), root, "notes.c") == UMI_STATUS_OK);
    REQUIRE(umi_fs_join(headerPath, sizeof(headerPath), root, "notes.h") == UMI_STATUS_OK);
    REQUIRE(umi_fs_write_text(sourcePath, "int CountNotes(void) { return 1; }\n") == UMI_STATUS_OK);

    REQUIRE(umi_command_registry_create(&commands) == UMI_STATUS_OK);
    REQUIRE(umi_ui_workbench_create("umicom.notes.save-all", commands, &workbench) == UMI_STATUS_OK);
    REQUIRE(umi_document_store_create(&store) == UMI_STATUS_OK);
    UmiDocumentProvider provider = umi_document_local_provider();
    REQUIRE(umi_document_coordinator_create(store, workbench, &provider, &documents) == UMI_STATUS_OK);
    REQUIRE(umi_document_coordinator_open(documents, sourcePath, sourceView, sizeof(sourceView)) == UMI_STATUS_OK);
    REQUIRE(SetDraft(workbench, sourceView, sourceText) == UMI_STATUS_OK);
    REQUIRE(umi_document_coordinator_new(documents, "notes.h", headerView, sizeof(headerView)) == UMI_STATUS_OK);
    REQUIRE(SetDraft(workbench, headerView, headerText) == UMI_STATUS_OK);

    REQUIRE(UmiDocumentSaveSessionCreate(documents, &session) == UMI_STATUS_OK);
    UmiDocumentSaveProgress progress;
    for (;;) {
        REQUIRE(UmiDocumentSaveSessionProgress(session, &progress) == UMI_STATUS_OK);
        if (progress.phase == UMI_DOCUMENT_SAVE_COMPLETE) break;
        if (progress.phase == UMI_DOCUMENT_SAVE_NEEDS_PATH) {
            /* A GUI shows a filename chooser here. This exercise deliberately
             * supplies its own new temporary header destination, not user data. */
            printf("Choose a filename for %s\n", progress.display_name);
            REQUIRE(UmiDocumentSaveSessionProvidePath(session, headerPath) == UMI_STATUS_OK);
        } else {
            REQUIRE(progress.phase == UMI_DOCUMENT_SAVE_READY);
            REQUIRE(UmiDocumentSaveSessionStep(session) == UMI_STATUS_OK);
        }
    }
    REQUIRE(progress.saved == 2U && progress.remaining == 0U);
    REQUIRE(FileEquals(sourcePath, sourceText));
    REQUIRE(FileEquals(headerPath, headerText));
    UmiDocumentWorkingCopySnapshot active;
    REQUIRE(umi_document_coordinator_active_snapshot(documents, &active) == UMI_STATUS_OK);
    REQUIRE(strcmp(active.view_id, headerView) == 0);
    printf("Verified %zu saved Notes source files. The active document did not change.\n", progress.saved);
    result = 0;
cleanup:
    /* Cancel before release. Earlier completed saves are not rolled back. The
     * exercise removes only the temporary directory that it created above. */
    if (session != NULL) (void)UmiDocumentSaveSessionCancel(session);
    UmiDocumentSaveSessionDestroy(session);
    umi_document_coordinator_destroy(documents);
    umi_document_store_destroy(store);
    umi_ui_workbench_destroy(workbench);
    umi_command_registry_destroy(commands);
    if (created) (void)umi_fs_remove_tree(root);
    return result;
}

Follow the main steps

SetDraft changes only the editor text. UmiDocumentSaveSessionCreate remembers the two pending document identities. The loop then checks the current phase: READY advances one file; NEEDS_PATH supplies the header’s new destination; COMPLETE ends the sequence. A failed call goes to cleanup instead of reporting success.

FileEquals performs a separate read. This matters because a request that returns without an obvious error is not sufficient proof that the expected bytes reached the correct file. The cleanup order releases the session before the coordinator and other borrowed services.

6. Check the whole operation

Repeat the two-document exercise in Studio. Record which tab was active, which files were modified and the filenames you selected. Verify the saved contents, not just the notification. Then repeat with cancellation, a read-only draft and a file that another editor changed.

Use Report problem to collect the shortest useful interaction sequence and a note of the expected and actual results. Review any screenshot before sharing it; source code and paths may contain private information.

For Undo/Redo, keep two documents with different edits open. Apply targeted Undo to the first while the second is active. Only the first history should change. This catches an incorrect implementation that substitutes the active tab for the document chosen by the caller.
