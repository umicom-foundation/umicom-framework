Building adaptable tool panels

A tool panel is an area containing controls for a task, such as building a project. When users make it narrower, its buttons should move onto another row instead of forcing the application wider. Framework provides this layout through UmiGtk4ActionGroupCreate.

Keep layout separate from execution

The group arranges existing buttons. It does not start builds, save documents, change workspace trust or hold application services. A button keeps the same command binding before and after a resize. Framework build sessions, document services and command admission remain responsible for what an action does.

  1. Include umicom/ui/gtk4/workstation/action_group.h and link Umicom::ui_gtk4.
  2. Create the group on the GTK owning thread.
  3. Create each button and attach its existing checked command binding. Add it with UmiGtk4ActionGroupAppend.
  4. Place the group inside the panel. If panel height is limited, use a vertically scrolling container so lower rows remain reachable.
  5. Keep bindings safe when the host closes. The group does not extend a borrowed service's lifetime or make a retained button authoritative.
#include "umicom/ui/gtk4/workstation/action_group.h"

GtkWidget *actions = UmiGtk4ActionGroupCreate();
GtkWidget *build = gtk_button_new_with_label("Build");
/* Bind build to the host's existing checked command before appending it. */
UmiStatus status = UmiGtk4ActionGroupAppend(actions, build);
if (status == UMI_STATUS_OK) {
    gtk_box_append(GTK_BOX(panel), actions);
} else {
    /* Both widgets are still unparented after failed admission. */
    g_object_ref_sink(build);
    g_object_unref(build);
    g_object_ref_sink(actions);
    g_object_unref(actions);
}

The group supports up to 64 unparented buttons, including toggle buttons. It rejects a button already owned by another container without moving it. Failed admission does not consume the button: the caller must retain or release it according to normal GTK ownership. Creating a button alone does not connect a feature; Studio's runtime_panel_add_commands shows the real integration with checked commands.

Check the result

  1. Open a panel with several actions and make it narrow. Its actions should occupy multiple rows.
  2. Move keyboard focus to a button, then resize the panel. Confirm the same control remains focused.
  3. Activate it once and confirm one operation starts.
  4. Close and reopen the host. Confirm old retained controls cannot bypass the host's command checks.

The framework.ui_workstation.action_group.* tests cover allocation, retained identity and focus, single dispatch, ownership admission and the capacity boundary. They require a graphical session; absence of one is a skip. Application workflows need their own tests because layout alone cannot establish that a build, trade or media operation succeeded.
