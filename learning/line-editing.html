Preparing and applying line edits

Framework separates a proposed source transformation from the document that owns it. This lets native editors and command-driven tools use the same line rules without creating competing Undo stacks.

Prepare a result without changing a draft

  1. Include umicom/editor/line_edit_plan.h. Initialize a UmiEditorEditCommandRequest with umi_editor_edit_command_request_initialize.
  2. Supply complete UTF-8 source and byte offsets for the caret and selection. Endpoints must lie between characters and must not split a CRLF separator.
  3. Call UmiEditorLineEditPlanCreate. Its source and output limit is 8 MiB. Check the returned status before using the plan.
  4. Use UmiEditorLineEditPlanInspect for the resulting caret and selection, and UmiEditorLineEditPlanRead for complete proposed text.
  5. The returned text is borrowed from the plan. Copy it if needed after UmiEditorLineEditPlanDestroy. Destroy the plan when finished.

Apply to the current document

  1. Include umicom/document/line_edit.h.
  2. On the document owner thread, call UmiDocumentCoordinatorEditLines with the coordinator, a supported line command and optional literal indentation/comment tokens.
  3. The coordinator captures current source and selection, prepares the full result and commits through its existing history only when the text changes.
  4. For a bound GTK editor, use UmiGtk4AdapterEditLines. It checks native operation state and delivers the result through the established document completion callback.
  5. Keep Save separate. These functions never write a source file or contact a provider.

Selection and token rules

Delete, duplicate, move and join use the caret line. Indent, outdent and comment use all selected lines, excluding a final line whose start exactly equals the selection end. Trim affects the whole draft. Changed prefix operations retain selected whole lines; without a selection they place the caret at the line start. Trim places it at document start. Unchanged operations retain the selection.

Defaults are four spaces and //. Indentation accepts up to 16 spaces or tabs. Comment tokens accept up to 32 printable non-space ASCII bytes. These are literal tokens, not language detection. LF and CRLF are accepted; bare CR returns UMI_STATUS_NOT_IMPLEMENTED. Conservative growth checks can reject near-limit input even when a comment removal would shrink it.

Extend the shared behavior

Add new transforms in the editor layer, validate their complete proposals, and keep history in the document coordinator. A plan has no mutable document or transaction stack. Native callbacks may detach or destroy their host, so retain the established lifetime token and reacquire its binding before notifying the application. Add regression cases for text, Unicode boundaries, no-change behavior, failures and Undo before exposing another command.

Canonical commands beginning with umicom.document.line-edit. are registered by umi_document_commands_register. They take no arguments and read the current active draft. Unexpected arguments are refused. Their text changes use the same coordinator service as the native buttons.

Cancellation is checked between bounded preparation phases. Undo restores captured command selections with their exact source; text-only states without a capture retain boundary-safe clamping. Native typing can use a pre-action edit capture with UmiDocumentCoordinatorCommitTyping to retain its departure selection too. Manual folding is a separate view-only operation that intentionally leaves source and Undo unchanged.
