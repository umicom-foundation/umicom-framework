# Native LLM Completion Benchmark — Framework Contracts

**Author and organisation:** Sammy Hegab · Umicom Foundation  
**Licence:** MIT · **Implementation:** native C23 · **Scope:** bounded research/education

## Purpose

The experimental byte-level decoder has growing training, checkpoint and
sampling support. We must now evaluate its actual output without pretending
that a predicted C23-looking byte sequence is correct programming.

The canonical Framework provides two complementary contracts:

- `umicom/ai/training/benchmark.h`: in-memory, failure-atomic, deterministic
  completion scoring using **the existing decoder generation service**.
- `umicom/ai/training/benchmark_suite.h`: a bounded read-only parser and
  ownership contract for explicitly reviewed benchmark case files.

No source code is executed, compiled, interpreted, imported into a runtime,
or written by these two services.

## Scoring and the meaning of results

For each case, the Framework generates **exactly as many bytes as the reference
completion** and reports:

- `exactMatch`: full byte-for-byte equality, including length;
- `matchingPositionBytes`: byte locations with the same value;
- `matchingPrefixBytes`: consecutive matches from byte zero until the first
  mismatch;
- `generatedBytes`: the number of emitted bytes.

The aggregate report includes the decoder's completed optimiser steps, total
expected/generated byte counts, matching positions/prefixes and the number of
exact cases. Results are copied to caller buffers **only after all cases
succeed**. Invalid inputs, unsupported vocabularies or failed generations
leave the caller's per-case and aggregate results unchanged.

Metrics are textual and cannot establish C23 compilation, correct application
behaviour, memory safety, security, financial domain correctness or suitability
for production use.

## Reviewed benchmark suite grammar

```text
UMICOM-AI-BENCHMARK-1
# A comment begins with # in column zero.
case my_case 616263 646566
case empty_prompt - 00
```

A row contains the keyword `case`, a unique identifier and two hexadecimal
fields. `616263` decodes to the byte sequence `abc`; `646566` decodes to `def`.
A lone `-` denotes an empty **prompt** only. Every expected completion must
have at least one byte. Empty lines, CRLF and spaces/tabs between fields are
supported. No shell interpolation, include directives or escaping are allowed.

Limits are enforced before publication:

| Constraint | Limit |
|---|---:|
| Cases | 1–64 |
| Prompt per case | 0–4,096 bytes |
| Reference per case | 1–256 bytes |
| Identifier | 1–63 ASCII characters in `[A-Za-z0-9_.-]` |
| Benchmark file | 600,000 bytes |

The file format does not provide a filesystem sandbox or authenticate content.
The reviewer must approve path, corpus licence, held-out independence and
source provenance. The parser never accesses any file named inside the suite;
all data is embedded as hex, eliminating path traversal within cases.

## Thin LLM application integration

`applications/llm/src/console/benchmark_main.c` provides only a presentation
layer. Its optional executable, `umicom-llm-benchmark`, takes an approved byte
checkpoint and optionally a reviewed suite file:

```powershell
Set-Location "C:\umicom\Umicom-Applications"

& ".\build\windows-ucrt64-all-debug\bin\umicom-llm-benchmark.exe" `
    "C:\path\to\approved-decoder-checkpoint.umi" `
    ".\framework\learning\native-llm\fixtures\benchmark-reviewed.txt"
```

The binary is opt-in (`UMICOM_LLM_BUILD_NATIVE_BENCHMARK=ON`) so current Umicom
Applications installations and builds are not silently changed. With only a
checkpoint argument, it runs three **public teaching examples**, not a hidden
competency benchmark.

## Correctness evidence

The training laboratory registers separate tests for byte scoring, full model
execution, rejection contracts, honest reporting, strict suite parsing,
rejections and the fixture loader. The model is encoded before and after a
benchmark in regression testing to verify that no weights or training step
counters changed. An equal model/checkpoint, suite and sampling seed produces
reproducible byte-completion results.

Only after this stage passes should the project explore independent C23 compile
and functional tests. Such an evaluator must execute generated code solely in
an explicitly authorised, strongly isolated environment; that is NOT included
in this milestone.
